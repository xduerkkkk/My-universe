# 基于 FUNSD 的表单字段抽取研究 —— OCR、布局信息与视觉语言模型对比实验

## 摘要

文档理解（Document Understanding）是智能办公、票据处理、金融审计与企业数字化中的重要研究方向。传统 OCR 方法虽然能够从扫描文档中提取文本内容，但通常忽略页面布局结构与视觉上下文，因此难以准确理解表单中的字段关系与语义结构。近年来，融合文本、空间布局与视觉信息的视觉语言模型（Vision-Language Model, VLM）在文档智能领域取得了显著进展。

本项目以 FUNSD（Form Understanding in Noisy Scanned Documents）数据集为基础，围绕“不同信息输入对表单字段抽取性能的影响”展开研究。项目首先实现了完整的数据处理流程，包括 OCR token 提取、BIO 标签转换、边界框归一化、数据清洗与训练集划分；随后构建并比较了三类模型：仅使用文本信息的 OCR-only 基线模型、融合文本与坐标信息的 Text+Layout 模型，以及同时利用文本、布局与页面图像的 LayoutLMv3 模型。

实验结果表明，LayoutLMv3 在实体级指标上显著优于纯文本方法，其 Entity F1 达到 0.7479，而 OCR-only 基线仅为 0.3352。实验说明：仅依赖 OCR 文本难以完成复杂表单理解任务，而视觉与布局信息对于字段关系建模具有关键作用。此外，项目还实现了预测结果可视化与错误案例分析，对不同模型的错误模式进行了对比研究。

关键词：文档理解；FUNSD；LayoutLMv3；OCR；视觉语言模型；表单字段抽取

# 第 1 章绪论

## 1.1 研究背景

随着企业数字化与智能办公的发展，大量业务流程开始依赖电子文档与扫描文档处理。例如发票识别、合同审核、银行表单录入、物流单据处理等场景，都需要计算机自动理解文档中的字段结构与语义关系。

传统文档处理流程通常采用 OCR（Optical Character Recognition）技术先将图像转换为文本，再通过规则系统或自然语言处理模型进行字段抽取。然而，仅使用 OCR 文本存在明显局限：

1. OCR 仅提供线性文本序列，缺乏页面空间结构信息；
    
2. 表单字段关系往往依赖页面布局；
    
3. 不同字段之间的相对位置对于语义理解非常重要；
    
4. 扫描噪声、表格结构与复杂排版会进一步增加理解难度。
    

例如，在表单中，“Name” 与 “John Smith” 的关系不仅依赖文本语义，更依赖二者在页面上的空间邻近关系。如果忽略布局结构，仅依赖文本顺序，模型很难正确建立字段对应关系。

近年来，随着 Transformer 与视觉语言模型的发展，研究者开始尝试联合建模：

- OCR 文本；
    
- 页面布局坐标；
    
- 原始页面图像。
    

其中，LayoutLM、LayoutLMv2 与 LayoutLMv3 等模型在文档智能任务上取得了显著成果。这类模型能够同时理解文本内容与页面结构，从而显著提升表单理解与信息抽取性能。

---

## 1.2 研究目标

本项目以 FUNSD 数据集为基础，围绕表单字段抽取任务展开研究，重点分析不同输入信息对模型性能的影响。

项目主要比较以下三类方法：

|模型|输入信息|
|---|---|
|OCR-only|OCR 文本 token|
|Text+Layout|token + bbox 坐标|
|LayoutLMv3|token + bbox + 页面图像|

其中：

- OCR-only 模型代表传统 NLP 文本方法；
    
- Text+Layout 模型用于研究显式位置信息的作用；
    
- LayoutLMv3 模型用于研究视觉语言联合建模能力。
    

通过实验比较不同模型在 FUNSD 数据集上的表现，分析：

1. 页面布局信息是否能够提升字段抽取性能；
    
2. 视觉特征在文档理解中的作用；
    
3. 不同模型的错误模式与适用场景。

# 第 2 章相关工作

## 2.1 基于 OCR 的传统文档理解方法

传统文档理解方法通常采用“OCR + 规则系统”的处理流程。首先利用 OCR 技术从文档图像中提取文本，再通过模板匹配、关键词规则或传统 NLP 方法进行字段抽取。

这种方法在固定模板场景下具有一定效果，但存在明显缺陷：

1. 对文档布局变化敏感；
    
2. 难以适应复杂表格结构；
    
3. 无法有效利用空间关系；
    
4. 泛化能力较差。
    

随着深度学习的发展，研究者开始使用 BERT、RoBERTa 等 Transformer 模型进行 token classification，但纯文本模型仍然无法充分理解页面布局结构。

---

## 2.2 Layout-aware 文档模型

为解决传统 NLP 模型缺乏空间理解能力的问题，研究者提出了 LayoutLM 系列模型。

LayoutLM 在 Transformer 中引入二维位置编码，将 OCR token 的 bbox 坐标与文本 embedding 联合输入模型，使模型能够学习页面结构信息。

随后：

- LayoutLMv2 引入视觉区域特征；
    
- LayoutLMv3 进一步统一文本与图像 Masked Modeling 任务，实现更强的多模态联合预训练。
    

LayoutLMv3 能够同时理解：

- token 文本；
    
- 页面布局；
    
- 图像 patch。
    

因此在文档分类、字段抽取、表单理解等任务中取得了较好效果。


---

## 2.3 视觉语言模型在文档理解中的应用

近年来，视觉语言模型（Vision-Language Model）逐渐成为 Document AI 研究热点。代表性方法包括：

- LayoutLMv3；
    
- Donut；
    
- DocFormer；
    
- Pix2Struct。
    

这类模型通常通过联合建模文本与视觉信息，提升模型对复杂版面结构与跨模态语义关系的理解能力。

相比传统 OCR-only 方法，多模态模型能够更准确地理解：

- 字段对齐关系；
    
- 表格结构；
    
- 标题区域；
    
- 页面视觉分组。
    

因此，本项目选择 LayoutLMv3 作为主要视觉语言模型进行实验。

## 3.3 BIO 标签转换

FUNSD 原始标注以 entity 为单位存储，而模型训练采用 token classification 方式，因此需要将实体转换为 BIO 标签序列。

例如：

|token|label|
|---|---|
|Name|B-QUESTION|
|:|I-QUESTION|
|John|B-ANSWER|
|Smith|I-ANSWER|

其中：

- B 表示实体开始；
    
- I 表示实体内部；
    
- O 表示非实体。
    

该转换方式有利于模型学习实体边界。

---

## 3.4 Bounding Box 坐标归一化

由于不同页面尺寸不同，因此需要对 bbox 坐标进行归一化。

设原始页面宽高分别为：

W, H

原始坐标为：

(x1, y1, x2, y2)

则归一化公式如下：

x_norm = x / W × 1000

y_norm = y / H × 1000

最终所有坐标统一映射至 [0, 1000] 区间。

该处理方式与 LayoutLM 系列模型保持一致。

---

# 第 4 章方法设计

## 4.1 任务定义

本项目采用 token classification 方式完成表单字段抽取任务。

输入包括：

- OCR token；
    
- bbox 坐标；
    
- 页面图像（部分模型）。
    

输出为每个 token 的 BIO 标签。

模型目标为学习：

f (token, bbox, image) → label

其中 label ∈ {QUESTION, ANSWER, HEADER, O}

---

## 4.2 OCR-only 文本基线模型

首先构建仅使用文本信息的 OCR-only baseline。

模型采用 DistilBERT 作为文本编码器，并在输出层进行 token classification。

其处理流程如下：

OCR token  
↓  
DistilBERT Encoder  
↓  
Linear Classifier  
↓  
BIO label prediction

该模型不使用任何布局与视觉信息，仅依赖 token 语义进行预测。




---

## 4.3 Text+Layout 布局增强模型

为研究显式位置信息的作用，项目进一步实现 Text+Layout baseline。

该模型在 OCR-only 基础上额外引入 bbox 坐标信息。

首先：

- 将 bbox 坐标输入 MLP；
    
- 生成 bbox embedding；
    
- 与文本 hidden state 进行拼接；
    
- 输入分类器预测标签。
    

其结构如下：

Text token → DistilBERT  
bbox → MLP Encoder  
↓  
Feature Fusion  
↓  
Classifier  
↓  
BIO Prediction

相比 OCR-only，该模型能够显式利用页面位置信息。

## 4.4 LayoutLMv3 多模态模型

LayoutLMv3 是微软提出的视觉语言文档理解模型。

其输入包括：

- OCR token；
    
- bbox 坐标；
    
- 页面图像 patch。
    

与传统 NLP 模型不同，LayoutLMv3 同时建模：

1. 文本语义；
    
2. 空间布局；
    
3. 页面视觉特征。
    

模型采用统一 Transformer 架构，通过：

- 2D Position Embedding；
    
- Patch Embedding；
    
- Spatial-aware Attention；
    
- Multi-modal Fusion；
    

实现跨模态联合建模。

相比仅使用文本的方法，LayoutLMv3 能够更准确地理解：

- 字段对齐关系；
    
- 表格结构；
    
- 标题区域；
    
- 页面视觉分组。
    

因此非常适合表单理解任务。

# 第 6 章实验分析与错误分析

## 6.1 整体性能分析

### （1）LayoutLMv3 显著领先

LayoutLMv3 的 Entity F1 达到 0.7479，是 OCR-only 基线（0.3352）的 2.2 倍。

这一结果说明：

- 文档理解任务不仅依赖文本语义；
    
- 页面布局与视觉结构具有关键作用；
    
- 多模态联合建模能够显著提升字段抽取性能。
    

相比纯文本模型，LayoutLMv3 能够“看到”：

- 字段对齐关系；
    
- 页面视觉分组；
    
- 表格边界；
    
- 标题区域。
    

因此能够更准确地建立 QUESTION 与 ANSWER 的对应关系。

---

### （2）Text+Layout 提升有限

Text+Layout 模型的 Entity F1 为 0.3317，略低于 OCR-only（0.3352）。

该结果表明：

- 单纯拼接 bbox embedding 难以充分建模复杂布局结构；
    
- DistilBERT 本身缺乏二维空间建模能力；
    
- 小规模数据集难以训练有效的空间表示。
    

此外，bbox MLP 的表达能力相对有限，仅能学习简单位置关系，无法像 LayoutLMv3 那样通过 spatial-aware attention 理解复杂页面结构。

因此，仅增加坐标特征并不能显著提升模型性能。

---

### （3）HEADER 类别最困难

所有模型在 HEADER 类别上的表现均明显低于 QUESTION 与 ANSWER。

主要原因包括：

1. HEADER 样本数量较少；
    
2. HEADER 视觉形式变化较大；
    
3. HEADER 通常更依赖版面结构而非文本语义；
    
4. 标题边界较模糊。
    

因此，HEADER 更依赖视觉上下文与全局布局理解能力。

---

## 6.2 错误类型分析

|Error Type|Text-Only|Text+Layout|LayoutLMv3|
|---|---|---|---|
|O → entity（误报）|768|704|462|
|entity → O（漏检）|1,093|1,066|542|
|QA 混淆|779|769|281|
|HEADER 混淆|219|229|104|
|BIO 边界错误|937|927|236|

实验发现：

### （1）漏检是主要错误来源

所有模型中，entity → O 错误均明显高于 O → entity。

说明模型倾向于：

“保守预测”。

即：

宁可不预测实体，也不愿错误预测实体。

这一现象与文档理解任务中的类别不均衡有关。

---

### （2）LayoutLMv3 大幅减少边界错误

相比文本基线，LayoutLMv3 的 BIO 边界错误减少约 75%。

说明：

- 页面结构信息有助于识别实体边界；
    
- 视觉上下文能够帮助模型区分字段区域。
    

尤其在 QUESTION 与 ANSWER 紧邻场景下，多模态模型能够更准确地判断字段范围。

---

### （3）Text+Layout 错误模式接近 OCR-only

Text+Layout 的错误分布与 OCR-only 基本一致。

进一步说明：

- 简单 bbox 拼接方式难以真正利用布局信息；
    
- 仅增加坐标特征并不足以建立复杂空间关系。
    

---

## 6.3 典型错误场景分析

### （1）QUESTION 与 ANSWER 边界混淆

当 QUESTION 与 ANSWER 在页面中紧密相邻时，模型容易将边界 token 错分。

例如：

Name : John Smith

模型可能将 “:” 同时预测为 QUESTION 或 ANSWER。

---

### （2）表格结构漏检

在多列表格区域中，靠近表格边界的 token 更容易被预测为 O。

原因包括：

- OCR token 排序混乱；
    
- 表格结构复杂；
    
- 文本顺序与视觉顺序不一致。
    

---

### （3）长页面截断

当页面 token 超过 512 时，尾部字段可能被截断。

导致：

- 模型无法看到完整页面；
    
- 部分实体无法预测。
    

---

### （4）OCR 噪声影响

部分勾选框符号（☐、☑）会被 OCR 识别为文本 token。

这些符号缺乏明确语义，容易增加模型预测噪声。

---

# 第 7 章总结与展望

## 7.1 工作总结

本项目围绕 FUNSD 表单字段抽取任务，系统研究了文本、布局与视觉信息对文档理解性能的影响。

项目首先实现了完整的数据处理流程，包括：

- OCR token 提取；
    
- BIO 标签构建；
    
- bbox 归一化；
    
- 数据清洗与统计分析。
    

随后实现并比较了三类模型：

1. OCR-only 文本基线；
    
2. Text+Layout 布局增强基线；
    
3. LayoutLMv3 多模态模型。
    

实验结果表明：

- 仅使用 OCR 文本难以完成复杂表单理解；
    
- 页面布局与视觉信息对字段抽取具有关键作用；
    
- LayoutLMv3 在 Entity F1 上显著优于文本基线；
    
- 简单 bbox 拼接方式难以充分利用布局信息。
    

此外，项目还实现了预测结果可视化与错误案例分析，对模型错误模式进行了深入研究。
