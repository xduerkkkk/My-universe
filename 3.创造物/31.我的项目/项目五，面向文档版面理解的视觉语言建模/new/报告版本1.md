# 面向文档版面理解的视觉语言建模实践



  

## 一、任务背景

  

在票据审核、表单录入、档案数字化和企业文档管理等场景中，文档不仅包含文字内容，还包含标题、表格、文本框位置、键值关系和页面布局等信息。仅使用 OCR 得到的纯文本，往往难以准确理解文档中的结构和关键信息。

  

本项目面向**表单字段抽取（Form Field Extraction）** 任务，基于 FUNSD 数据集，结合文本内容、页面图像和位置信息，完成一个较完整的文档理解模型训练与对比流程。项目重点放在数据预处理、版面信息利用、视觉语言模型训练、基线对比和错误分析上。

  

---

  

## 二、数据处理

  

### 2.1 数据集

  

选用 **FUNSD（Form Understanding in Noisy Scanned Documents）** 数据集。FUNSD 包含 199 张扫描表单图像，每张表单标注了 OCR 文本框、实体类别（question / answer / header / other）以及实体间的关系。

  

### 2.2 数据预处理

  

| 1 | 读取原始 FUNSD 标注 | 从 JSON 文件提取 form-level 标注 |
| 2 | BIO 标签转换 | question→QUESTION, answer→ANSWER, header→HEADER, other→O |
| 3 | 文本框排序 | 按 y 坐标优先排序，维持阅读顺序 |
| 4 | 坐标归一化 | bbox 统一映射到 [0, 1000] 空间 |
| 5 | 数据集划分 | train=127, val=22, test=50（原始 FUNSD 划分） |

  

### 2.3 数据统计

  

| 统计项          | 训练集    | 验证集   | 测试集   |
| ------------ | ------ | ----- | ----- |
| 样本数          | 127    | 22    | 50    |
| Token 总数     | 18,668 | 3,220 | 8,707 |
| 每页 Token 均值  | 147.0  | 146.4 | 174.1 |
| 每页 Token 中位数 | 139    | 137.5 | 177   |
| 超出 512 长度比例  | 0%     | 0%    | 0%    |

  

**类别分布（实体级）：**

  

| 类别            | 训练集   | 验证集   | 测试集   |
| ------------- | ----- | ----- | ----- |
| ANSWER        | 8,183 | 1,336 | 3,294 |
| QUESTION      | 6,231 | 1,030 | 2,654 |
| O (no entity) | 3,035 | 597   | 2,385 |
| HEADER        | 1,219 | 257   | 374   |

  

*注：数据集中 ANSWER 和 QUESTION 占比较高，HEADER 数量较少，存在类别不均衡现象。*

  

### 2.4 OCR 噪声情况

  

- 非打印字符比例：约 0.6%（如 ☐、☑ 等表单勾选框符号）

- 高符号比 tokens：如 `(s)`、`($)`、`+/` 等占位符和分隔符

- 总体 OCR 质量较好，未见明显长 token 异常

## 三、任务选择与建模

  

### 3.1 任务定义

  

选择 **表单字段抽取（Form Field Extraction）** 作为主要任务，将其建模为 **BIO 序列标注问题**：

  

- 输入：页面上所有 OCR 单词 token 序列

- 输出：每个 token 的 BIO 标签

  

**标签集合：**

  

| 标签 | 含义 |

|------|------|

| O | 非实体 token |

| B-QUESTION / I-QUESTION | 问题字段 |

| B-ANSWER / I-ANSWER | 答案字段 |

| B-HEADER / I-HEADER | 标题字段 |

  

### 3.2 评估指标

  

- **Token 级**：Accuracy、Macro F1

- **实体级**（seqeval）：Precision、Recall、F1（micro/macro/weighted）

- **类别级**：QUESTION、ANSWER、HEADER 的实体 F1

## 四、基线模型实现

  

实现了三类可比较方法，覆盖纯文本到完整 VLM 的信息利用梯度：

  

### 4.1 模型概览

  

| 模型 | 简称 | 输入 | 架构 |

|------|------|------|------|

| OCR-Only Baseline | Text-Only | tokens | distilbert-base-uncased → Linear classifier |

| Text + Layout Baseline | Text+Layout | tokens + bboxes_norm | distilbert-base-uncased + bbox MLP → concat → Linear |

| LayoutLMv3 | LayoutLMv3 | tokens + bboxes_norm + image | microsoft/layoutlmv3-base (full VLM) |

  

### 4.2 模型详情

  

**（1）OCR-Only Baseline (`text_only`)**

  

- 编码器：`distilbert-base-uncased`（~67M 参数）

- 输入：仅 OCR token 序列（`is_split_into_words=True`）

- 标签对齐：每个 word 的第一个 subword 获得原标签，后续 subword 设为 `-100`（忽略 loss）

- 分类头：`nn.Linear(hidden_size, 7)`

  

**（2）Text + Layout Baseline (`text_layout`)**

  

- 文本编码器：`distilbert-base-uncased`

- 位置编码器：小型 MLP

  ```

  Linear(4 → 128) → ReLU → Dropout(0.1) → Linear(128 → 128)

  ```

- 融合方式：`[text_hidden; bbox_features]` 拼接 → `Linear(hidden+128, 7)`

- bbox 归一化：输入除以 1000.0 映射到 [0, 1]

- bbox 对齐：每个 word 的所有 subword 共享同一归一化坐标

  

**（3）LayoutLMv3 (`layoutlmv3`)**

  

- 模型：`microsoft/layoutlmv3-base`（~125M 参数）

- 输入：页面图像（3×224×224）+ token + 归一化 bbox

- Processor：`AutoProcessor.from_pretrained(..., apply_ocr=False)`（复用 FUNSD OCR 结果）

- 直接使用 `LayoutLMv3ForTokenClassification`

  

### 4.3 训练配置

  

所有模型使用统一的训练参数：

  

| 参数 | Text-Only | Text+Layout | LayoutLMv3 |

|------|-----------|-------------|------------|

| Epochs | 5 | 5 | 5 |

| Batch Size | 4 | 4 | 2 |

| Learning Rate | 5e-5 | 5e-5 | 5e-5 |

| Weight Decay | 0.01 | 0.01 | 0.01 |

| Warmup Steps | 50 | 50 | 50 |

| Max Seq Length | 512 | 512 | 512 |

| Seed | 42 | 42 | 42 |

| Optimizer | AdamW | AdamW | AdamW |

## 六、结果分析

  

### 6.1 整体表现分析

  

1. **LayoutLMv3 大幅领先**：Entity F1 达到 0.7479，是纯文本基线（0.3352）的 2.2 倍。这表明页面图像特征对表单理解至关重要——模型可以"看到"字段的视觉分组和空间关系。

  

2. **Text+Layout 略低于 Text-Only**：加入 bbox 信息后 Entity F1 从 0.3352 微降至 0.3317（-1%）。这一结果表明：

   - 单纯将 bbox 坐标作为额外特征拼接到文本隐层，在小数据集（127 训练样本）上难以学到有效的位置表征；

   - distilbert-base 的文本编码能力有限，仅靠拼接方式融合位置信息无法充分利用版面结构；

   - 位置信息的有效利用需要更强的融合机制（如 LayoutLMv3 中的 spatial-aware attention）。

  

3. **HEADER 类别普遍困难**：所有模型在 HEADER 类别上表现最差。HEADER 在训练集中仅 1,219 个 token（占 6.5%），且 HEADER 的视觉特征（大字体、居中排版）与文本内容特征（通常是单行短文本）难以仅从 token 级建模中捕获。

  

### 6.2 错误类型分析

  

| Error Type | Text-Only | Text+Layout | LayoutLMv3 |

|------------|-----------|-------------|------------|

| O → entity（误报） | 768 | 704 | 462 |

| entity → O（漏检） | 1,093 | 1,066 | 542 |

| QA 混淆 | 779 | 769 | 281 |

| HEADER 混淆 | 219 | 229 | 104 |

| BIO 边界错误 | 937 | 927 | 236 |

  

**分析：**

  

- **漏检是主要错误来源**：所有模型的 `entity_to_O` 错误远多于 `O_to_entity`，说明模型更倾向于"保守"预测（宁可不标，也不标错）。

- **LayoutLMv3 在各类型错误上均显著优于文本基线**：总错误数从 ~3,800 降至 1,625（-57%），尤其在 QA 混淆（-64%）和边界错误（-75%）上改进最大。

- **Text+Layout 错误模式与 Text-Only 极为相似**：位置信息对纯文本模型的错误分布影响微弱，印证了 bbox MLP 拼接方式的局限性。

  

### 6.3 典型错误场景

  

（*详见 `funsd_experiment/outputs/visualization/` 下的可视化图像*）

  

1. **相邻字段混淆**：当 QUESTION 和 ANSWER 字段在页面上紧密相邻时，模型容易将边界 token 错分。

2. **表格结构漏检**：表单中的多列表格区域，位于表格边界附近的 token 容易被预测为 O。

3. **长页面截断**：超过 512 token 的页面的尾部字段被截断，无法预测。

4. **OCR 噪声影响**：表单中的勾选框符号（☐、☑）被 OCR 识别为文本 token，增加了预测噪声。

## 七、创新拓展

  

### 7.1 位置信息利用优化

  

比较了"无位置信息"和"拼接 bbox 特征"两种方式：

  

| 配置 | Entity F1 | 说明 |

|------|-----------|------|

| tokens only | 0.3352 | 纯文本 |

| tokens + bbox MLP (concat) | 0.3317 | bbox 作为额外特征拼接 |

  

**结论**：在当前小数据设置下，简单的 bbox 拼接未带来正面收益。更有效的位置信息利用方式应为：空间感知注意力（LayoutLMv3）、绝对位置编码 + 相对位置偏置（如 LiLT 中的 2D 位置编码）、或混合特征注入方式。消融实验表明，仅靠 token 级拼接不能充分捕获版面布局的复杂性。

  

### 7.2 多模态输入对比（消融实验）

  

| 输入组合 | 模型 | Entity F1 | △ vs Text-Only |

|----------|------|-----------|----------------|

| tokens | Text-Only (distilbert) | 0.3352 | —（基线） |

| tokens + bboxes | Text+Layout (distilbert + MLP) | 0.3317 | -1.0% |

| tokens + bboxes + image | LayoutLMv3 | 0.7479 | +123% |

  

**各模态贡献分析：**

  

| 贡献因素 | Δ Entity F1 | 归因 |

|----------|-------------|------|

| + 位置信息（纯拼接） | -0.0035 | 小数据下拼接方式未能有效利用位置 |

| + 图像 + 空间感知融合 | +0.4162 | LayoutLMv3 的 multimodal attention 带来主要增益 |

| + 更大预训练模型（125M vs 66M） | 不可分离 | 部分增益来自模型容量和预训练知识 |

  

**结论**：在表单字段抽取任务上，页面图像是最关键的额外信息来源；但图像的有效利用依赖于具备空间感知能力的模型架构（如 LayoutLMv3），而非简单的后拼接。

## 九、总结

  

本项目完成了 FUNSD 表单字段抽取的完整实验流程：

  

1. **数据层面**：完成 FUNSD 数据集加载、BIO 标签转换、坐标归一化、排序、统计和 OCR 噪声分析。

2. **模型层面**：实现了 OCR-only（text-only）、Text+Layout、LayoutLMv3 三类模型，覆盖了从纯文本到完整多模态 VLM 的信息利用梯度。

3. **评估层面**：使用 token 级 + 实体级（seqeval）双层指标，输出整体、类别级、错误类型三层分析。

4. **对比层面**：通过消融实验量化了文本、位置、图像三类信息对表单字段抽取的贡献。

5. **可视化层面**：生成了页面级预测标注和三模型对比图，便于定性分析。

  

**核心发现**：页面图像是表单理解的关键信息来源，但其有效利用需要空间感知模型架构（LayoutLMv3）。单纯将位置坐标作为额外特征拼接到文本隐层，在小数据集上未带来正向收益。
