
「发布即过时」这句我踩过实证：去年团队按一本静态教程搭 RAG Agent，教程里的工具调用协议半年后框架直接废弃，返工成本比从零学还高。现在我们内部选型就照你说的路子走——把 opencode 和 codex 的 releases 全量拉下来让 AI 梳理时间线，两周看一次 diff，比任何书都快。补充一个数据点：pi 的核心 Agent Loop 不到 300 行，但插件框架的接口设计迭代了 11 个版本，这种取舍只有读 commit history 才看得见。书适合建立心智模型，动手还得跟活仓库。


文中提到的“AI 得理解什么叫今时不同往日，否则就是拎不清”，我觉得其本质还是 Agent 缺乏真实业务场景中的上下文获取能力。最常见的情况就是某一个事情有 Deadline，在 Deadline 之前这个优先级最高的，过了某一个时间点之后就完全没有做的价值。或者说因为一些客观原因的变化（例如有新的项目出现或资源调配发生变化），导致一系列老的项目优先级都需要变化。这些判断多是保存在人类的大脑中，并不暴露给 Agent，所以和 Agent 对话时会觉得它有点笨，不懂得变通。我在工作场景中的体会就是，很多领导都不比手下的员工聪明，但是员工经常做无用功，浪费时间精力在不被认可的项目上，本质是领导拥有员工所不具备的信息渠道。
