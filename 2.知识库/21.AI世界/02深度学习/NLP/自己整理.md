# 绪论

## 押题 ：为什么自然语言处理很难？

**参考答案：**

自然语言处理困难主要因为自然语言本身具有复杂性和不确定性。首先，语言存在歧义，同一句话可能有多种理解；其次，语言依赖上下文，词语含义会随语境变化；第三，语音是连续信号，需要从声波中识别语言单位；第四，不同语言的结构差异很大，例如中文没有天然空格，部分语言词形变化复杂。因此，计算机处理自然语言比处理形式化语言更困难。

## 押题 ：语言模型的基本作用是什么？

**参考答案：**

语言模型用于估计一个词序列出现的概率，或者根据已有上下文预测后续词语。它可以帮助机器判断一句话是否自然，也可以用于文本生成、机器翻译、语音识别、问答系统和聊天机器人等任务。


**自然语言处理是让计算机处理人类语言的技术。自然语言既包括文本，也包括语音。由于语言存在歧义、上下文依赖、长距离关系和跨语言差异，因此 NLP 具有较大难度。本课程主要围绕语音识别、语音合成、语音转换、语言模型和文本生成等任务展开，本质上都是用深度学习模型完成不同形式语言信息之间的映射。现代 NLP 的发展趋势是模型越来越大、预训练越来越重要、模型能力越来越通用。**


# 语音识别
语音识别是把一段连续语音序列转换成一段离散文字序列

具体来说，声音-->声学特征
此时声音变成了一个二维矩阵：`[时间帧数 T, 特征维度 D]`（类似于图像)

声学特征-->模型处理-->输出 token



## token 类别

### 1 . Phoneme 音素
   音素是语音里的基本发音单位。
优点：

它和发音直接相关，适合语音识别。

缺点：

需要发音词典，也就是 lexicon。不同语言、不同口音、不同词的发音规则会比较麻烦。

### 2. Grapheme 字符 / 字母

英文可以是字母，比如 a、b、c。  
中文可以是汉字，比如 “一”“拳”“超”“人”。

优点：

词表小，不需要像 word 那样准备巨大词表。  
中文尤其适合用字作为 token，因为中文不天然依赖空格。

缺点：

字符本身语义不完整，序列会变长，模型需要自己学字符如何组合成词。



### 3. Word 词

Word 是以词为单位输出。

比如：

one punch man

输出就是：

one / punch / man

优点：

输出序列短，语义比较完整。

缺点：

词表非常大，会有 OOV，也就是没见过的新词。对于词形变化复杂的语言，word 级别会特别麻烦。



**Word token 语义强，但词表大；character/grapheme 词表小，但序列长。**

为什么 word token 不一定适合语音识别？

Word token 的优点是语义完整、输出序列较短，但它的问题是词表非常大，而且容易出现训练中没有见过的新词，也就是 OOV。对于词形变化复杂的语言，word 级别的词表会更大，训练和解码难度都会增加。因此，实际语音识别中常常使用字符、子词或音素等更灵活的 token。



### 4. Morpheme 语素

Morpheme 是最小的有意义单位。

比如：

unbreakable = un + break + able

它介于字符和词之间。

优点：

比字符更有意义，比词的词表小。

缺点：

如何切分 morpheme 不一定简单，可能需要语言学知识或统计方法。

---

### 5. Byte 字节

Byte 的特点是语言无关，词表大小固定，比如 UTF-8 中可以看成 256 种取值。

优点：

**language independent**，不太依赖具体语言。

缺点：

序列很长，模型学习难度更大。


### Token 类别的选择

token 决定了模型输出空间的大小、输出序列的长度以及是否需要词典等外部资源。比如 word token 语义完整但词表很大，容易出现未登录词；grapheme token 词表小但序列较长；phoneme token 接近发音但需要发音词典。因此 token 选择会影响模型训练难度、识别效果和系统复杂度。
## Acoustic Feature 声学特征

常见声学特征包括：

**spectrogram（声谱图）、MFCC、filter bank、waveform**

MFCC 和 Filter Bank 简单理解：
**MFCC** 是传统语音处理中常用的声学特征，它试图模拟人耳对声音频率的感知。  
**Filter Bank** 保留更多频谱信息，在深度学习语音识别中很常用。

### 为什么要用声学特征？

因为原始波形维度高、变化复杂，直接建模难度较大。声学特征可以把连续语音信号转换成更适合模型处理的时间序列表示，突出发音和频谱信息，降低建模难度，提高语音识别效果。

也就是：
**speech waveform → acoustic features → neural network**



## Sequence to Sequence
Seq2Seq 模型就是序列到序列的意思

**在早期的经典 Seq2Seq 模型**
就是Encoder-Decoder 架构

**在早期的经典 Seq2Seq 模型（比如 Google 经典的 Listen, Attend and Spell 架构）中，RNN 或 LSTM 就是用来直接当 Encoder（编码器）和 Decoder（解码器）的。**




### RNN 、LSTM

RNN 的作用是处理序列：

当前时刻的输入 + 上一个时刻的隐藏状态 → 当前隐藏状态

但普通 RNN 有长期依赖问题，所以引入 LSTM。  
LSTM 通过门控机制保留重要信息，遗忘不重要信息。



### Encoder-Decoder 


**Encoder 编码器**：把输入语音特征序列编码成隐藏表示。  
**Decoder 解码器**：根据编码结果一步步生成输出 token。


Encoder (RNN/LSTM)
* **输入形状**：`[B, T, D_in]`
  * `B`：Batch Size（批大小）。
  * `T`：输入的时间步长（语音帧数），在语音中通常很长，比如 1000 帧。
  * `D_in`：输入的声学特征维度（比如 80 维的 Mel 频谱）。
* **Encoder 处理**：每一帧 $x_t$ 按照时间顺序输入给 RNN/LSTM
* **输出形状**：`[B, T, D_hidden]`
  * 这里的输出它包含了每一帧的声学信息以及上下文的语义信息。

Decoder (RNN/LSTM)
* **任务**：根据 Encoder 提取的信息，一步一步（Autoregressive，自回归地）生成文本 Token ($y_1, y_2, ..., y_N$)。
* **输入形状（在生成第 $t$ 个 Token 时）**：
  * Decoder 的输入通常包含两部分：
    1. 上一个时间步输出的 Token（经过 Embedding 转成向量）。
    2. **Attention（注意力机制）**：因为 $T$（语音长度）远大于 $N$（文本长度），Decoder 不可能直接把 $T$ 个状态全部吃进去。它会通过 Attention 去动态寻找：“我现在要预测第 $t$ 个字了，我该重点关注 Encoder 的哪几帧？” 从而计算出一个**上下文向量（Context Vector）**。
  * 综合起来，Decoder 单步的输入形状大约是 `[B, 1, D_embed + D_context]`
* **输出形状（隐藏状态）**：`[B, 1, D_dec_hidden]`。

**预测最终 Token**：
  * 把 Decoder 的隐藏状态经过一个全连接层（Linear）加上 Softmax。
  * 最终输出形状：`[B, 1, Vocab_Size]`（Vocab_Size 就是词表大小，比如 5000 个汉字）。
  * 取概率最大的那个位置对应的词，就是当前预测出的 Token $y_t$。

流程是：

**x₁, x₂, ..., xT → Encoder → hidden representations → Decoder → y₁, y₂, ..., yN**

注意的点在于，每一步 decoder 都会读 encoder。decoder 是写作的，encoder 是理解的小抄。

**Encoder 负责理解输入序列，Decoder 负责生成输出序列。**

## Seq to Seq Model：LAS
把上小节的 encoder 和 decoder 架构，也可命名为 LAS

**LAS：Listen, Attend and Spell**

这个名字很好记：

**Listen = 听**  
**Attend = 注意**  
**Spell = 拼写输出**


### 1. Listen：编码语音

Listen 部分就是 Encoder。

它接收声学特征序列，把原始语音帧变成高层表示。

简单说：

**Listen 负责“听懂声音”。**

---

### 2. Attend：注意力机制

Attention 的作用是：

Decoder 在生成每个 token 时，不是只看一个固定向量，而是动态关注输入语音的不同部分。

比如输出第一个字时关注前面的语音帧；输出后面的字时关注后面的语音帧。

所以 attention 解决的是：

**输出 token 和输入语音帧之间的软对齐问题。**

这很容易考。

---

### 3. Spell：生成 token

Spell 就是 Decoder。

它根据 Encoder 表示和 Attention 结果，一个 token 一个 token 地生成文字。

例如：

输入语音：one punch man  
输出 token：o → n → e → ... 或 one → punch → man

取决于 token 设计。


## Beam Search 和 Teacher Forcing



### 1. Beam Search

Decoder 生成文本时，每一步都有很多可能 token。

如果每一步只选概率最大的一个，可能局部最优，整体不好。

Beam Search 的思路是：

**每一步保留多个候选序列，最后选择整体概率较高的结果。**

例如 beam size = 3，就保留当前最可能的 3 条路径。

考试答法：

**Beam Search 是一种解码策略，用于在生成序列时保留多个高概率候选，避免贪心搜索过早选择错误路径。**

---

### 2. Teacher Forcing

训练 Decoder 时，有两种做法：

一种是用模型上一步预测的 token 作为下一步输入。  
另一种是直接用真实答案中的上一个 token 作为下一步输入。

Teacher Forcing 指的是第二种：

**训练时把真实的上一个 token 喂给模型。**

好处：

训练更稳定，收敛更快。

问题：

训练时用真实历史，测试时只能用模型自己预测的历史，这会造成训练和测试不一致。


> Teacher Forcing 的优点和缺点是什么？

参考答案：

Teacher Forcing 的优点是训练时使用真实的上一个 token 作为输入，可以减少错误累积，使模型训练更稳定、收敛更快。缺点是训练阶段和推理阶段不一致，推理时模型只能使用自己预测出的 token，一旦前面预测错误，后续错误可能继续累积。




但在**语音识别（ASR）**中，有一个非常大的痛点：**$T \gg N$（输入远长于输出）**。
* 10 秒的语音，经过特征提取后，可能有 **1000 帧（T=1000）**。
* 但这句话可能只有 **20 个字（N=20）**。

因此，如果完全生硬地用 RNN 当 Encoder，要走 1000 步，RNN 会很容易遗忘。

所以会有后面的优化
# 语音识别--模型

本章了解语音识别具体的模型

## CTC：最重要，最可能考

CTC 全称是：

**Connectionist Temporal Classification**
联结主义时间分类

CTC

CTC 解决的问题是：

**只有整句语音和整句文本，没有每一帧对应哪个字的标注，模型仍然可以训练。**
（正常训练，是**获取逐帧标签**，强制对齐，到了一个长长的标签，比如 100 帧对应的标签真的是：  
`[d, d, d, d, d, e, e, e, e, e, p, p, p, p, p, ...]`，每一帧算 loss

 而CTC 的网络里，**训练数据只需要**一段 3 秒的语音音频输入，文本 "deep"。
 - 至于这 3 秒里，到底前多少毫秒是 d，中间多少毫秒是 e，模型**根本不需要人工提供逐帧的标签**
 - 模型靠自己在训练中用“所有可能的排列组合（路径）求概率和”的方式，**自己去寻找对齐关系**。

###  CTC 的基本思想

训练时，语音输入有 T 帧：

**x₁, x₂, ..., xT**

模型每一帧都输出一个 token 分布。

CTC输出时还会输出一个特殊符号：
**blank，记作 φ**
然后通过两步得到**最终结果**：
**第一步：合并连续重复 token**  
**第二步：删除 blank φ**

最终结果会和文本标签 "deep"对比。

但是，训练时的输出，有非常多的路径到达文本标签，如 `dφeφep, ddφeeφp` 结果都是 deep

CTC 会把所有能得到正确文本的路径概率加起来。
**CTC 不要求人工指定哪一帧对应哪个字，而是自动枚举可能对齐路径。**

因为模型要在**整个数据集**上降低 Loss，它发现那些错误的路径（比如把元音当成 h）会导致在别的词上疯狂出错。模型被迫去学习**真实的声学特征（听音辨字）**。一旦模型学会了听音辨字，那些**符合真实物理发音顺序的路径（如 h e e），它的概率就会自然而然地呈现出碾压式的优势，成为贡献最大的路径。**




---

### 建议看图：PPT 第 5 页、第 6 页

第 5 页看 CTC 的结构：  
输入声学特征 → Encoder → 每一帧输出 token distribution。

第 6 页一定要看，它是 CTC 最关键的图。里面展示了：

`φ φ d d φ e φ e φ p p → deep`

它的过程是：

先合并连续重复：

`φ d φ e φ e φ p`

再删除 blank：

`d e e p`

所以得到：

`deep`

> 为什么 CTC 需要 blank φ？直接合并重复字符不行吗？

参考答案：

不行。因为有些单词本身就有重复字母，比如 **deep** 里面有两个 e。如果只做“合并重复”，`d e e p` 会变成 `d e p`。CTC 引入 blank 后，可以用 blank 把两个相同字符隔开，比如 `d e φ e p`，这样删除 blank 后仍然得到 `deep`。



### CTC 的优点：
第一，训练不需要帧级别对齐标注。  
第二，结构相对简单。  
第三，可以用于语音识别这种输入长、输出短的任务。  
第四，如果 encoder 是单向的，也可以做流式识别。

### CTC 的缺点

CTC 的核心缺点是：
**输出之间相对独立，语言建模能力弱。**

也就是说，CTC 每一帧主要根据声学信息判断输出什么，它本身不太会强建模“前一个字影响后一个字”。
比如中文里，“我想吃苹”后面更可能是“果”，这个语言上下文关系 CTC 本身不强。
所以 CTC 经常需要外部语言模型帮助。


## RNN-T ：CTC + 语言上下文


RNN-T 全称：

**Recurrent Neural Network Transducer**

它可以理解为：
**在 CTC 的基础上，加入了对历史输出 token 的建模。**

CTC 主要看声学帧。  
RNN-T 不只看声学帧，还看前面已经输出过什么 token。

所以它更像：
**声学模型 + 语言模型 + 联合预测**

> RNN-T 相比 CTC 最大的改进是什么？

参考答案：

CTC 的输出之间相对独立，语言上下文建模能力较弱；RNN-T 加入了 prediction network，能够利用之前已经输出的 token，因此可以建模输出 token 之间的依赖关系，具有更强的语言建模能力。

RNN-T 通常有三个模块：

### 1. Encoder / Transcription Network

处理声学输入。

作用类似：

**听声音。**

### 2. Prediction Network

处理历史输出 token。

作用类似：

**根据前面已经识别出的字，预测后面可能是什么。**

### 3. Joint Network

把声学信息和历史文本信息结合起来，预测下一个 token。

作用类似：

**把“听到的声音”和“语言上下文”合起来判断。**


### 对比
- CTC 的推理，是输入声音->声学特征->直接输出 token 或 blank，1000 帧就必须输出 1000 个符号（哪怕里面有 980 个是 Blank）。
- RNN Encoder-Decoder (Seq2Seq)，是 ENcoder 读完，输出理解，**此时没有任何 Token 输出。** Decoder 再借助输出的理解（即对声学特征的理解）去输出 token。**它输出的步数，等于最终文本的字数，跟帧数毫无关系！**
	- 第 1 步：Decoder 利用 Attention 扫描那 1000 个向量，输出第 1 个字 d。
	- 第 2 步：Decoder 看着自己刚才输出的 d，再次扫描那 1000 个向量，输出第 2 个字 e。
	- ...
	- 第 5 步：Decoder 输出一个特殊的 **`<EOS>`（End of Sentence，句子结束符）**。
	    推理瞬间停止！  
	    总结 Seq2Seq 不是按“帧”输出的，而是按“字（自回归步数）”输出的。它不需要 Blank 符号，因为生成完 deep 后，它自己喊停了。
	

- RNN-T 
	- ENcoder 和 seq2seq 一样，提取当前时间帧的**声学特征**
	- Prediction Network 呢，输入“已经真实输出的历史 token”（比如已经输出了 d、e），输出一- 个**语言特征**（此时它还没算出最终是哪个字，只是给出一个“语境预判”）。
	- Joint Network 是它把【当前第 t帧的声学特征】和【历史输出带来的语言特征】**加在一起**然后经过一层网络和 Softmax，**输出最终的 Token 或 Blank**。


Seq2Seq 靠 Attention 对齐
Seq2Seq 里的 Attention 是“软对齐”。预测第 2 个字的时候，模型可以看第 10 帧，预测第 3 个字的时候，模型可以掉头回去看第 2 帧。
* 在**机器翻译**里这很棒，因为英语和中文的语序是颠倒的。
* 但在**语音识别**里，时间流逝是**单向（严格单调 monotonic）**的！说的话绝对是从左到右的，不可能倒退。Seq2Seq 的 Attention 经常会“看走眼”，导致语音识别出现**漏字、重复**的严重幻觉。


RNN-T 靠 Joint Network + Blank 严格单调对齐
RNN-T 和 CTC 一样，时间只能往前走。它也使用了 Blank（空白符）的概念：
* 如果 Joint Network 发现：当前这帧声音 $h_t$ 和过去的文本 $y_{u-1}$ 结合后，还不足以判断出下一个字，它就会输出一个 **Blank (`-`)**。
* 遇到 Blank 后，**文本不增加，时间往前走一帧**（吸收下一帧声音 $h_{t+1}$）。
* 遇到实体字后，**时间停留在原地，文本往下走一步**（更新 Prediction Network）。
这种机制完美契合了语音识别“严格从左到右”的物理规律，杜绝了 Seq2Seq 乱跳的问题。


### RNN-T 的优点

RNN-T 的优点：

第一，可以建模输出 token 之间的依赖。  
第二，适合流式语音识别。  
第三，不需要完整等待整句话说完，可以边听边输出。  
第四，在工业语音识别中很重要。


### RNN-T 的缺点

它比 CTC 更复杂，训练和解码难度更高。

**CTC 简单但语言建模弱；RNN-T 更复杂但能利用历史输出。**


## Neural Transducer：分块处理

Neural Transducer 可以理解为：

**把长语音切成一个个小块 chunk/window，再在每个块里做识别。**

它想解决的问题是：
如果模型总是看完整句语音，会不适合实时识别。 （前面的 CTC 可以随时间步推移输出，传统**Seq2Seq**不行）
所以它让模型分块处理，一边接收语音，一边生成输出。

模型**不再是一帧一帧地处理声音了**，而是把连续的声音切成一个个**固定长度的“块（Chunk / Block）”**。比如每 300 毫秒切一块（包含 10 帧）。

1. **收齐一个块**：系统先等待，直到收集满当前块的所有声音特征（$h^t$ 到 $h^{t+w}$）。
2. **块内 Attention（注意力）**：图中的交叉箭头表示，中间的橘色解码器（Decoder）在生成字的时候，是可以**同时看到这整个块**的信息的（Attention 机制）。
3. **输出多个 Token**：在这个块内，Decoder 开始生成字，比如图里输出了 `c` 和 `a`。
4. **输出块结束符（Blank）**：当 Decoder 觉得这个块里的声音信息已经翻译完了，它就会输出一个特殊的空白符（图中红色的空方块）。这个动作相当于向系统喊话：“**这段我翻译完了，把下一个声音块送进来吧！**”
5. **滑动到下一个块**：系统开始收集下一个时间段的 $W$ 帧，重复上述过程。

### 优缺点
优点：

**适合流式识别，延迟较低。**

既能不断往外蹦字（实现了流式），又能结合局部的上下文（提高了准确率）。

> 对比**CTC / RNN-T（严格流式）**在处理第 $t$ 帧时，它**绝对看不到**第 $t+1$ 帧的声音。这在有些时候很容易识别错（比如有些发音要连着后面几个音才能听出到底是什么字）。 Neural Transducer 在块内，它可以利用 Attention 机制看到这 300 毫秒内的“未来”信息，这让它的识别准确率比纯粹一帧帧猜的 RNN-T 要高。Seq2Seq要等**整句话（可能 10 秒钟）**全说完，才能开始 Attention。我等不了整句话，但我可以等 300 毫秒啊！我把长句子切成无数个 300 毫秒的短句，在每个短句里用 Seq2Seq 的 Attention。这样既保住了流式的特性（最多延迟 300 毫秒），又享受到了 Attention 带来的上下文理解能力！

缺点：

**窗口大小不好选。**
窗口太小：信息不足，容易识别错。  
窗口太大：延迟增加，实时性变差。


## MoChA：单调块注意力
MoChA 全称：

**Monotonic Chunkwise Attention**

它名字很长，但可以拆开理解：

**Monotonic = 单调**  
**Chunkwise = 分块**  
**Attention = 注意力**

对于单调的理解，
传统的 Attention，**没法流式（边听边写）**：因为它有全图视野，它要预测第一个字，必须得等你把最后一秒的音也录完，它整体看一遍才敢下结论。即使你录完了，它在预测时，注意力也有可能“看走眼”，明明已经翻译到第 20 帧了，预测下一个字时它的注意力又**倒退**跳回到了第 5 帧，导致屏幕上输出乱码或者重复的字。

而 Mocha，如果你在预测上一个字时，注意力已经走到了第 20 帧，那么当你预测下一个字时，**你的目光只能从第 20 帧开始往后看，绝对不允许回头看 1-19 帧！**  
这就强行把 Attention 的目光变成了和时间流逝一样的“单向箭头”。这就解决了“乱跳”的问题。


对于分块的理解，Mocha 是 windows 伸缩自如的 Neural Transducer

- 它本质上依然是一个边听边写、分块处理的**流式识别模型**（类似于 Neural Transducer）。
- 但它的 **Windows（接收声音的窗口）**不固定，语速快、音节短，窗口就小；语速慢、拖长音，窗口就拉长


加上了单向箭头后，MoChA 进一步规定：当你（巡逻兵）探测到当前这个字的信息足够了（确定了刚才聊的“伸缩自如的窗口”边界后），**你只允许在这个短小的窗口内部（比如第 20 帧到第 35 帧），进行 Attention 计算。**


# 语言模型

**语言模型就是预测序列概率 P (w₁, w₂, …, wN)，核心任务是根据上下文预测下一个词。**

> 为什么语音识别和文本生成都需要语言模型？

参考答案：

因为语音识别仅靠声学模型可能不够，模型可能把 “一拳超人”识别成 “一前超人”，语言模型可以用上下文概率纠正；文本生成本质也是预测下一个词，语言模型提供概率分布，使生成文本更自然。


最原始的语言模型就是给一个序列 w₁…wN 计算概率：


$$P (w_1, w_2, ..., w_N) = \prod_{t=1}^{N} P (w_t \mid w_1, ..., w_{t-1})$$ **一句话出现的概率，等于“在已知前面所有字的情况下，说出下一个字的概率”的连乘。**

比如你想预测句子：`“我 喜欢 吃 苹果”`
它的概率 = $P(我) \times P(喜欢 \mid 我) \times P(吃 \mid 我, 喜欢) \times \mathbf{P(苹果 \mid 我, 喜欢, 吃)}$

**问题出在哪里？**
假设我们要预测一篇长文章的第 100 个词。根据公式，我们要算：
$P(第100个词 \mid 前面99个词)$。
这意味着，为了求出这个概率，你必须去海量的语料库（比如全网所有的书和网页）里找，**“前面那 99 个词一模一样按顺序出现的情况下，第 100 个词是什么”**。
但是，世界上几乎找不到两段完全一模一样的 99 个词的组合！这就是 NLP 里著名的**“数据稀疏问题”**。条件太苛刻了，模型算出来的概率永远是 0。

## N-gram
为了解决这个问题，N-gram 提出了一个伟大的假设，叫做**马尔可夫假设（Markov Assumption）**：
**“下一个词出现的概率，只跟它前面最近的 $N-1$ 个词有关，再往前的历史统统不管了！”**

$$P (w_t \mid w_1, ..., w_{t-1}) \approx P (w_t \mid w_{t-N+1}, ..., w_{t-1})$$  
N-gram 究竟啥意思？
* **gram**：指的是文本里的基本单位（可以是一个字、一个词、甚至一个字母）。
* **N**：指的是把几个词捆绑在一起看。
* **N-gram 语言模型**：就是利用长度为 N 的切块，来估算单词出现的概率。

我们来看看 N 取不同值时的具体含义（以预测 `P(苹果 | 我, 喜欢, 吃)` 为例）：

**1. Unigram (一元模型，N=1)**
* **假设**：下一个词跟前面**0**个词有关（各个词是完全独立的）。
* **公式**：$P(苹果 \mid 我, 喜欢, 吃) \approx \mathbf{P(苹果)}$
* **解释**：模型根本不看前文，纯靠“苹果”这个词在整个语料库里出现的总频率来瞎猜。这就像个失忆症患者。

**2. Bigram (二元模型，N=2)**（最常用）
* **假设**：下一个词只跟前面 **1** 个词有关。
* **公式**：$P(苹果 \mid 我, 喜欢, 吃) \approx \mathbf{P(苹果 \mid 吃)}$
* **解释**：模型只记得上一个词是“吃”，于是去字典里查“吃”后面跟着“苹果”的概率。把“我、喜欢”全都抛在脑后了。

**3. Trigram (三元模型，N=3)**
* **假设**：下一个词只跟前面 **2** 个词有关。
* **公式**：$P(苹果 \mid 我, 喜欢, 吃) \approx \mathbf{P(苹果 \mid 喜欢, 吃)}$
* **解释**：模型记得前两个词是“喜欢吃”，去查这两个词后面跟着“苹果”的概率。


深度学习时代的模型存的是“神经元权重矩阵”，**而 N-gram 模型里存的内容极其简单粗暴——就是“查字典的频率统计表（Count）”！**

这就是极大似然估计（MLE）。比如我们要算 Bigram 模型里的 $P(苹果 \mid 吃)$，它是怎么算的呢？
非常简单，做除法：

$$P(苹果 \mid 吃) = \frac{\text{语料库中“吃 苹果”同时出现的次数}}{\text{语料库中“吃”出现的总次数}}$$

所以，一个训练好的 N-gram 模型，**它的内容就是一个巨大的 Hash 表（字典）**。
比如一个 Bigram 模型的内容长这样：
* `{"吃": 10000次}`
* `{"吃 苹果": 2000次} -> P(苹果|吃) = 0.2`
* `{"吃 米饭": 3000次} -> P(米饭|吃) = 0.3`
* `{"吃 键盘": 0次} -> P(键盘|吃) = 0.0`


正因为 N-gram 只能看眼前 $N-1$ 个词，记不住远处的上下文，后来人们才发明了 **RNN/LSTM**（把前面所有的历史信息压缩成一个 Hidden State 一代代传下去），再后来觉得 RNN 传太久会遗忘，于是又发明了 **Transformer（Attention 机制）**，让模型不仅能看到前面所有的词，还能直接跳过去抓取最关键的词（彻底解决了长距离依赖问题）！


### 神经网络语言模型 NNLM / RNN LM



### 1. NNLM（前馈神经网络）

- 输入：前 N-1 个词，维度拼接起来！所以输入维度是固定设置的
    
- 输出：下一个词的概率
    
- 优点：词嵌入（word embedding）+ softmax
    
- 缺点：上下文长度有限


（这就是加一个神经网络转换和 softmax 吗？）

### 2. RNN LM

- 输入：词向量序列
    
- RNN 更新 hidden state：$$h_t = f (h_{t-1}, x_t)$$
    
- 输出：softmax 得到 $P (w_t|h_t)$
    
- 优点：可以处理任意长度上下文
    
- 缺点：训练慢，长期依赖可能受梯度消失影响

RNN LM 通过隐藏状态 h_t 记住之前所有词的上下文信息，每一步输出依赖 h_t，因此能够捕捉比 N-gram 更长的依赖关系。


## 连续空间语言模型 Continuous LM

现代语言模型不是用离散词表，而是用 **词向量 / 子词 / token embedding** 表示。

优点：

- 捕捉语义相似性
- 处理 OOV 问题
- 支持大模型


核心思想：词被映射到向量空间，模型预测下一个词的 embedding，然后解码成 token。
