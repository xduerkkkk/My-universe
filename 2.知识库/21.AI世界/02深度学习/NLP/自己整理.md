# 绪论

## 押题 ：为什么自然语言处理很难？

**参考答案：**

自然语言处理困难主要因为自然语言本身具有复杂性和不确定性。首先，语言存在歧义，同一句话可能有多种理解；其次，语言依赖上下文，词语含义会随语境变化；第三，语音是连续信号，需要从声波中识别语言单位；第四，不同语言的结构差异很大，例如中文没有天然空格，部分语言词形变化复杂。因此，计算机处理自然语言比处理形式化语言更困难。

## 押题 ：语言模型的基本作用是什么？

**参考答案：**

语言模型用于估计一个词序列出现的概率，或者根据已有上下文预测后续词语。它可以帮助机器判断一句话是否自然，也可以用于文本生成、机器翻译、语音识别、问答系统和聊天机器人等任务。


**自然语言处理是让计算机处理人类语言的技术。自然语言既包括文本，也包括语音。由于语言存在歧义、上下文依赖、长距离关系和跨语言差异，因此 NLP 具有较大难度。本课程主要围绕语音识别、语音合成、语音转换、语言模型和文本生成等任务展开，本质上都是用深度学习模型完成不同形式语言信息之间的映射。现代 NLP 的发展趋势是模型越来越大、预训练越来越重要、模型能力越来越通用。**


# 语音识别
语音识别是把一段连续语音序列转换成一段离散文字序列

具体来说，声音-->声学特征
此时声音变成了一个二维矩阵：`[时间帧数 T, 特征维度 D]`（类似于图像)

声学特征-->模型处理-->输出 token



## token 类别

### 1 . Phoneme 音素
   音素是语音里的基本发音单位。
优点：

它和发音直接相关，适合语音识别。

缺点：

需要发音词典，也就是 lexicon。不同语言、不同口音、不同词的发音规则会比较麻烦。

### 2. Grapheme 字符 / 字母

英文可以是字母，比如 a、b、c。  
中文可以是汉字，比如 “一”“拳”“超”“人”。

优点：

词表小，不需要像 word 那样准备巨大词表。  
中文尤其适合用字作为 token，因为中文不天然依赖空格。

缺点：

字符本身语义不完整，序列会变长，模型需要自己学字符如何组合成词。



### 3. Word 词

Word 是以词为单位输出。

比如：

one punch man

输出就是：

one / punch / man

优点：

输出序列短，语义比较完整。

缺点：

词表非常大，会有 OOV，也就是没见过的新词。对于词形变化复杂的语言，word 级别会特别麻烦。



**Word token 语义强，但词表大；character/grapheme 词表小，但序列长。**

为什么 word token 不一定适合语音识别？

Word token 的优点是语义完整、输出序列较短，但它的问题是词表非常大，而且容易出现训练中没有见过的新词，也就是 OOV。对于词形变化复杂的语言，word 级别的词表会更大，训练和解码难度都会增加。因此，实际语音识别中常常使用字符、子词或音素等更灵活的 token。



### 4. Morpheme 语素

Morpheme 是最小的有意义单位。

比如：

unbreakable = un + break + able

它介于字符和词之间。

优点：

比字符更有意义，比词的词表小。

缺点：

如何切分 morpheme 不一定简单，可能需要语言学知识或统计方法。

---

### 5. Byte 字节

Byte 的特点是语言无关，词表大小固定，比如 UTF-8 中可以看成 256 种取值。

优点：

**language independent**，不太依赖具体语言。

缺点：

序列很长，模型学习难度更大。


### Token 类别的选择

token 决定了模型输出空间的大小、输出序列的长度以及是否需要词典等外部资源。比如 word token 语义完整但词表很大，容易出现未登录词；grapheme token 词表小但序列较长；phoneme token 接近发音但需要发音词典。因此 token 选择会影响模型训练难度、识别效果和系统复杂度。
## Acoustic Feature 声学特征

常见声学特征包括：

**spectrogram（声谱图）、MFCC、filter bank、waveform**

MFCC 和 Filter Bank 简单理解：
**MFCC** 是传统语音处理中常用的声学特征，它试图模拟人耳对声音频率的感知。  
**Filter Bank** 保留更多频谱信息，在深度学习语音识别中很常用。

### 为什么要用声学特征？

因为原始波形维度高、变化复杂，直接建模难度较大。声学特征可以把连续语音信号转换成更适合模型处理的时间序列表示，突出发音和频谱信息，降低建模难度，提高语音识别效果。

也就是：
**speech waveform → acoustic features → neural network**



## Sequence to Sequence
Seq2Seq 模型就是序列到序列的意思

**在早期的经典 Seq2Seq 模型**
就是Encoder-Decoder 架构

**在早期的经典 Seq2Seq 模型（比如 Google 经典的 Listen, Attend and Spell 架构）中，RNN 或 LSTM 就是用来直接当 Encoder（编码器）和 Decoder（解码器）的。**




### RNN 、LSTM

RNN 的作用是处理序列：

当前时刻的输入 + 上一个时刻的隐藏状态 → 当前隐藏状态

但普通 RNN 有长期依赖问题，所以引入 LSTM。  
LSTM 通过门控机制保留重要信息，遗忘不重要信息。



### Encoder-Decoder 


**Encoder 编码器**：把输入语音特征序列编码成隐藏表示。  
**Decoder 解码器**：根据编码结果一步步生成输出 token。


Encoder (RNN/LSTM)
* **输入形状**：`[B, T, D_in]`
  * `B`：Batch Size（批大小）。
  * `T`：输入的时间步长（语音帧数），在语音中通常很长，比如 1000 帧。
  * `D_in`：输入的声学特征维度（比如 80 维的 Mel 频谱）。
* **Encoder 处理**：每一帧 $x_t$ 按照时间顺序输入给 RNN/LSTM
* **输出形状**：`[B, T, D_hidden]`
  * 这里的输出它包含了每一帧的声学信息以及上下文的语义信息。

Decoder (RNN/LSTM)
* **任务**：根据 Encoder 提取的信息，一步一步（Autoregressive，自回归地）生成文本 Token ($y_1, y_2, ..., y_N$)。
* **输入形状（在生成第 $t$ 个 Token 时）**：
  * Decoder 的输入通常包含两部分：
    1. 上一个时间步输出的 Token（经过 Embedding 转成向量）。
    2. **Attention（注意力机制）**：因为 $T$（语音长度）远大于 $N$（文本长度），Decoder 不可能直接把 $T$ 个状态全部吃进去。它会通过 Attention 去动态寻找：“我现在要预测第 $t$ 个字了，我该重点关注 Encoder 的哪几帧？” 从而计算出一个**上下文向量（Context Vector）**。
  * 综合起来，Decoder 单步的输入形状大约是 `[B, 1, D_embed + D_context]`
* **输出形状（隐藏状态）**：`[B, 1, D_dec_hidden]`。

**预测最终 Token**：
  * 把 Decoder 的隐藏状态经过一个全连接层（Linear）加上 Softmax。
  * 最终输出形状：`[B, 1, Vocab_Size]`（Vocab_Size 就是词表大小，比如 5000 个汉字）。
  * 取概率最大的那个位置对应的词，就是当前预测出的 Token $y_t$。

流程是：

**x₁, x₂, ..., xT → Encoder → hidden representations → Decoder → y₁, y₂, ..., yN**

注意的点在于，每一步 decoder 都会读 encoder。decoder 是写作的，encoder 是理解的小抄。

**Encoder 负责理解输入序列，Decoder 负责生成输出序列。**

## Seq to Seq Model：LAS
把上小节的 encoder 和 decoder 架构，也可命名为 LAS

**LAS：Listen, Attend and Spell**

这个名字很好记：

**Listen = 听**  
**Attend = 注意**  
**Spell = 拼写输出**


### 1. Listen：编码语音

Listen 部分就是 Encoder。

它接收声学特征序列，把原始语音帧变成高层表示。

简单说：

**Listen 负责“听懂声音”。**

---

### 2. Attend：注意力机制

Attention 的作用是：

Decoder 在生成每个 token 时，不是只看一个固定向量，而是动态关注输入语音的不同部分。

比如输出第一个字时关注前面的语音帧；输出后面的字时关注后面的语音帧。

所以 attention 解决的是：

**输出 token 和输入语音帧之间的软对齐问题。**

这很容易考。

---

### 3. Spell：生成 token

Spell 就是 Decoder。

它根据 Encoder 表示和 Attention 结果，一个 token 一个 token 地生成文字。

例如：

输入语音：one punch man  
输出 token：o → n → e → ... 或 one → punch → man

取决于 token 设计。


## Beam Search 和 Teacher Forcing



### 1. Beam Search

Decoder 生成文本时，每一步都有很多可能 token。

如果每一步只选概率最大的一个，可能局部最优，整体不好。

Beam Search 的思路是：

**每一步保留多个候选序列，最后选择整体概率较高的结果。**

例如 beam size = 3，就保留当前最可能的 3 条路径。

考试答法：

**Beam Search 是一种解码策略，用于在生成序列时保留多个高概率候选，避免贪心搜索过早选择错误路径。**

---

### 2. Teacher Forcing

训练 Decoder 时，有两种做法：

一种是用模型上一步预测的 token 作为下一步输入。  
另一种是直接用真实答案中的上一个 token 作为下一步输入。

Teacher Forcing 指的是第二种：

**训练时把真实的上一个 token 喂给模型。**

好处：

训练更稳定，收敛更快。

问题：

训练时用真实历史，测试时只能用模型自己预测的历史，这会造成训练和测试不一致。


> Teacher Forcing 的优点和缺点是什么？

参考答案：

Teacher Forcing 的优点是训练时使用真实的上一个 token 作为输入，可以减少错误累积，使模型训练更稳定、收敛更快。缺点是训练阶段和推理阶段不一致，推理时模型只能使用自己预测出的 token，一旦前面预测错误，后续错误可能继续累积。




但在**语音识别（ASR）**中，有一个非常大的痛点：**$T \gg N$（输入远长于输出）**。
* 10 秒的语音，经过特征提取后，可能有 **1000 帧（T=1000）**。
* 但这句话可能只有 **20 个字（N=20）**。

因此，如果完全生硬地用 RNN 当 Encoder，要走 1000 步，RNN 会很容易遗忘。

所以会有后面的优化
# 语音识别--模型

本章了解语音识别具体的模型

## CTC：最重要，最可能考

CTC 全称是：

**Connectionist Temporal Classification**
联结主义时间分类

CTC 解决的问题是：

**只有整句语音和整句文本，没有每一帧对应哪个字的标注，模型仍然可以训练。**
（正常训练，是**获取逐帧标签**，强制对齐，到了一个长长的标签，比如 100 帧对应的标签真的是：  
`[d, d, d, d, d, e, e, e, e, e, p, p, p, p, p, ...]`，每一帧算 loss）
 CTC 的网络里，**训练数据只需要**一段 3 秒的语音音频输入，文本 "deep"。
 - 至于这 3 秒里，到底前多少毫秒是 d，中间多少毫秒是 e，模型**根本不需要人工提供逐帧的标签**。
 - 模型靠自己在训练中用“所有可能的排列组合（路径）求概率和”的方式，**自己去寻找对齐关系**。

### 1. CTC 的基本思想

语音输入有 T 帧：

**x₁, x₂, ..., xT**

模型每一帧都输出一个 token 分布。

但是输出时多了一个特殊符号：

**blank，记作 φ**

然后最终结果通过两步得到：

**第一步：合并连续重复 token**  
**第二步：删除 blank φ**

---

## 建议看图：PPT 第 5 页、第 6 页

第 5 页看 CTC 的结构：  
输入声学特征 → Encoder → 每一帧输出 token distribution。

第 6 页一定要看，它是 CTC 最关键的图。里面展示了：

`φ φ d d φ e φ e φ p p → deep`

它的过程是：

先合并连续重复：

`φ d φ e φ e φ p`

再删除 blank：

`d e e p`

所以得到：

`deep`

> 为什么 CTC 需要 blank φ？直接合并重复字符不行吗？

参考答案：

不行。因为有些单词本身就有重复字母，比如 **deep** 里面有两个 e。如果只做“合并重复”，`d e e p` 会变成 `d e p`。CTC 引入 blank 后，可以用 blank 把两个相同字符隔开，比如 `d e φ e p`，这样删除 blank 后仍然得到 `deep`。

### 2. CTC 的训练思想

CTC 训练时不是只使用一种对齐方式，而是考虑所有可能对齐。

比如目标文本是：

**好棒**

语音有很多帧。那它可能对应：

`好 好 棒 棒`  
`好 φ 棒 φ`  
`φ 好 棒 φ`  
`好 φ φ 棒`

这些都是可能对齐。

CTC 会把所有能得到正确文本的路径概率加起来。

**CTC 不要求人工指定哪一帧对应哪个字，而是自动枚举可能对齐路径。**
