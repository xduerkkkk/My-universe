# 绪论

## 押题 ：为什么自然语言处理很难？

**参考答案：**

自然语言处理困难主要因为自然语言本身具有复杂性和不确定性。首先，语言存在歧义，同一句话可能有多种理解；其次，语言依赖上下文，词语含义会随语境变化；第三，语音是连续信号，需要从声波中识别语言单位；第四，不同语言的结构差异很大，例如中文没有天然空格，部分语言词形变化复杂。因此，计算机处理自然语言比处理形式化语言更困难。

## 押题 ：语言模型的基本作用是什么？

**参考答案：**

语言模型用于估计一个词序列出现的概率，或者根据已有上下文预测后续词语。它可以帮助机器判断一句话是否自然，也可以用于文本生成、机器翻译、语音识别、问答系统和聊天机器人等任务。


**自然语言处理是让计算机处理人类语言的技术。自然语言既包括文本，也包括语音。由于语言存在歧义、上下文依赖、长距离关系和跨语言差异，因此 NLP 具有较大难度。本课程主要围绕语音识别、语音合成、语音转换、语言模型和文本生成等任务展开，本质上都是用深度学习模型完成不同形式语言信息之间的映射。现代 NLP 的发展趋势是模型越来越大、预训练越来越重要、模型能力越来越通用。**


# 语音识别
语音识别是把一段连续语音序列转换成一段离散文字序列

具体来说，声音-->声学特征
此时声音变成了一个二维矩阵：`[时间帧数 T, 特征维度 D]`（类似于图像)

声学特征-->模型处理-->输出 token



## token 类别

### 1 . Phoneme 音素
   音素是语音里的基本发音单位。
优点：

它和发音直接相关，适合语音识别。

缺点：

需要发音词典，也就是 lexicon。不同语言、不同口音、不同词的发音规则会比较麻烦。

### 2. Grapheme 字符 / 字母

英文可以是字母，比如 a、b、c。  
中文可以是汉字，比如 “一”“拳”“超”“人”。

优点：

词表小，不需要像 word 那样准备巨大词表。  
中文尤其适合用字作为 token，因为中文不天然依赖空格。

缺点：

字符本身语义不完整，序列会变长，模型需要自己学字符如何组合成词。



### 3. Word 词

Word 是以词为单位输出。

比如：

one punch man

输出就是：

one / punch / man

优点：

输出序列短，语义比较完整。

缺点：

词表非常大，会有 OOV，也就是没见过的新词。对于词形变化复杂的语言，word 级别会特别麻烦。



**Word token 语义强，但词表大；character/grapheme 词表小，但序列长。**

为什么 word token 不一定适合语音识别？

Word token 的优点是语义完整、输出序列较短，但它的问题是词表非常大，而且容易出现训练中没有见过的新词，也就是 OOV。对于词形变化复杂的语言，word 级别的词表会更大，训练和解码难度都会增加。因此，实际语音识别中常常使用字符、子词或音素等更灵活的 token。



### 4. Morpheme 语素

Morpheme 是最小的有意义单位。

比如：

unbreakable = un + break + able

它介于字符和词之间。

优点：

比字符更有意义，比词的词表小。

缺点：

如何切分 morpheme 不一定简单，可能需要语言学知识或统计方法。

---

### 5. Byte 字节

Byte 的特点是语言无关，词表大小固定，比如 UTF-8 中可以看成 256 种取值。

优点：

**language independent**，不太依赖具体语言。

缺点：

序列很长，模型学习难度更大。


### Token 类别的选择

token 决定了模型输出空间的大小、输出序列的长度以及是否需要词典等外部资源。比如 word token 语义完整但词表很大，容易出现未登录词；grapheme token 词表小但序列较长；phoneme token 接近发音但需要发音词典。因此 token 选择会影响模型训练难度、识别效果和系统复杂度。
## Acoustic Feature 声学特征

常见声学特征包括：

**spectrogram（声谱图）、MFCC、filter bank、waveform**

MFCC 和 Filter Bank 简单理解：
**MFCC** 是传统语音处理中常用的声学特征，它试图模拟人耳对声音频率的感知。  
**Filter Bank** 保留更多频谱信息，在深度学习语音识别中很常用。

### 为什么要用声学特征？

因为原始波形维度高、变化复杂，直接建模难度较大。声学特征可以把连续语音信号转换成更适合模型处理的时间序列表示，突出发音和频谱信息，降低建模难度，提高语音识别效果。

也就是：
**speech waveform → acoustic features → neural network**



## Sequence to Sequence
Seq2Seq 模型就是序列到序列的意思

**在早期的经典 Seq2Seq 模型**
就是Encoder-Decoder 架构

**在早期的经典 Seq2Seq 模型（比如 Google 经典的 Listen, Attend and Spell 架构）中，RNN 或 LSTM 就是用来直接当 Encoder（编码器）和 Decoder（解码器）的。**




### RNN 、LSTM

RNN 的作用是处理序列：

当前时刻的输入 + 上一个时刻的隐藏状态 → 当前隐藏状态

但普通 RNN 有长期依赖问题，所以引入 LSTM。  
LSTM 通过门控机制保留重要信息，遗忘不重要信息。



### Encoder-Decoder 


**Encoder 编码器**：把输入语音特征序列编码成隐藏表示。  
**Decoder 解码器**：根据编码结果一步步生成输出 token。


Encoder (RNN/LSTM)
* **输入形状**：`[B, T, D_in]`
  * `B`：Batch Size（批大小）。
  * `T`：输入的时间步长（语音帧数），在语音中通常很长，比如 1000 帧。
  * `D_in`：输入的声学特征维度（比如 80 维的 Mel 频谱）。
* **Encoder 处理**：每一帧 $x_t$ 按照时间顺序输入给 RNN/LSTM
* **输出形状**：`[B, T, D_hidden]`
  * 这里的输出它包含了每一帧的声学信息以及上下文的语义信息。

Decoder (RNN/LSTM)
* **任务**：根据 Encoder 提取的信息，一步一步（Autoregressive，自回归地）生成文本 Token ($y_1, y_2, ..., y_N$)。
* **输入形状（在生成第 $t$ 个 Token 时）**：
  * Decoder 的输入通常包含两部分：
    1. 上一个时间步输出的 Token（经过 Embedding 转成向量）。
    2. **Attention（注意力机制）**：因为 $T$（语音长度）远大于 $N$（文本长度），Decoder 不可能直接把 $T$ 个状态全部吃进去。它会通过 Attention 去动态寻找：“我现在要预测第 $t$ 个字了，我该重点关注 Encoder 的哪几帧？” 从而计算出一个**上下文向量（Context Vector）**。
  * 综合起来，Decoder 单步的输入形状大约是 `[B, 1, D_embed + D_context]`
* **输出形状（隐藏状态）**：`[B, 1, D_dec_hidden]`。

**预测最终 Token**：
  * 把 Decoder 的隐藏状态经过一个全连接层（Linear）加上 Softmax。
  * 最终输出形状：`[B, 1, Vocab_Size]`（Vocab_Size 就是词表大小，比如 5000 个汉字）。
  * 取概率最大的那个位置对应的词，就是当前预测出的 Token $y_t$。

流程是：

**x₁, x₂, ..., xT → Encoder → hidden representations → Decoder → y₁, y₂, ..., yN**

注意的点在于，每一步 decoder 都会读 encoder。decoder 是写作的，encoder 是理解的小抄。

**Encoder 负责理解输入序列，Decoder 负责生成输出序列。**

## Seq to Seq Model：LAS
把上小节的 encoder 和 decoder 架构，也可命名为 LAS

**LAS：Listen, Attend and Spell**

这个名字很好记：

**Listen = 听**  
**Attend = 注意**  
**Spell = 拼写输出**


### 1. Listen：编码语音

Listen 部分就是 Encoder。

它接收声学特征序列，把原始语音帧变成高层表示。

简单说：

**Listen 负责“听懂声音”。**

---

### 2. Attend：注意力机制

Attention 的作用是：

Decoder 在生成每个 token 时，不是只看一个固定向量，而是动态关注输入语音的不同部分。

比如输出第一个字时关注前面的语音帧；输出后面的字时关注后面的语音帧。

所以 attention 解决的是：

**输出 token 和输入语音帧之间的软对齐问题。**

这很容易考。

---

### 3. Spell：生成 token

Spell 就是 Decoder。

它根据 Encoder 表示和 Attention 结果，一个 token 一个 token 地生成文字。

例如：

输入语音：one punch man  
输出 token：o → n → e → ... 或 one → punch → man

取决于 token 设计。


## Beam Search 和 Teacher Forcing



### 1. Beam Search

Decoder 生成文本时，每一步都有很多可能 token。

如果每一步只选概率最大的一个，可能局部最优，整体不好。

Beam Search 的思路是：

**每一步保留多个候选序列，最后选择整体概率较高的结果。**

例如 beam size = 3，就保留当前最可能的 3 条路径。

考试答法：

**Beam Search 是一种解码策略，用于在生成序列时保留多个高概率候选，避免贪心搜索过早选择错误路径。**

---

### 2. Teacher Forcing

训练 Decoder 时，有两种做法：

一种是用模型上一步预测的 token 作为下一步输入。  
另一种是直接用真实答案中的上一个 token 作为下一步输入。

Teacher Forcing 指的是第二种：

**训练时把真实的上一个 token 喂给模型。**

好处：

训练更稳定，收敛更快。

问题：

训练时用真实历史，测试时只能用模型自己预测的历史，这会造成训练和测试不一致。


> Teacher Forcing 的优点和缺点是什么？

参考答案：

Teacher Forcing 的优点是训练时使用真实的上一个 token 作为输入，可以减少错误累积，使模型训练更稳定、收敛更快。缺点是训练阶段和推理阶段不一致，推理时模型只能使用自己预测出的 token，一旦前面预测错误，后续错误可能继续累积。




但在**语音识别（ASR）**中，有一个非常大的痛点：**$T \gg N$（输入远长于输出）**。
* 10 秒的语音，经过特征提取后，可能有 **1000 帧（T=1000）**。
* 但这句话可能只有 **20 个字（N=20）**。

因此，如果完全生硬地用 RNN 当 Encoder，要走 1000 步，RNN 会很容易遗忘。

所以会有后面的优化
# 语音识别--模型

本章了解语音识别具体的模型

## CTC：最重要，最可能考

CTC 全称是：

**Connectionist Temporal Classification**
联结主义时间分类

CTC

CTC 解决的问题是：

**只有整句语音和整句文本，没有每一帧对应哪个字的标注，模型仍然可以训练。**
（正常训练，是**获取逐帧标签**，强制对齐，到了一个长长的标签，比如 100 帧对应的标签真的是：  
`[d, d, d, d, d, e, e, e, e, e, p, p, p, p, p, ...]`，每一帧算 loss

 而CTC 的网络里，**训练数据只需要**一段 3 秒的语音音频输入，文本 "deep"。
 - 至于这 3 秒里，到底前多少毫秒是 d，中间多少毫秒是 e，模型**根本不需要人工提供逐帧的标签**
 - 模型靠自己在训练中用“所有可能的排列组合（路径）求概率和”的方式，**自己去寻找对齐关系**。

###  CTC 的基本思想

训练时，语音输入有 T 帧：

**x₁, x₂, ..., xT**

模型每一帧都输出一个 token 分布。

CTC输出时还会输出一个特殊符号：
**blank，记作 φ**
然后通过两步得到**最终结果**：
**第一步：合并连续重复 token**  
**第二步：删除 blank φ**

最终结果会和文本标签 "deep"对比。

但是，训练时的输出，有非常多的路径到达文本标签，如 `dφeφep, ddφeeφp` 结果都是 deep

CTC 会把所有能得到正确文本的路径概率加起来。
**CTC 不要求人工指定哪一帧对应哪个字，而是自动枚举可能对齐路径。**

因为模型要在**整个数据集**上降低 Loss，它发现那些错误的路径（比如把元音当成 h）会导致在别的词上疯狂出错。模型被迫去学习**真实的声学特征（听音辨字）**。一旦模型学会了听音辨字，那些**符合真实物理发音顺序的路径（如 h e e），它的概率就会自然而然地呈现出碾压式的优势，成为贡献最大的路径。**




---

### 建议看图：PPT 第 5 页、第 6 页

第 5 页看 CTC 的结构：  
输入声学特征 → Encoder → 每一帧输出 token distribution。

第 6 页一定要看，它是 CTC 最关键的图。里面展示了：

`φ φ d d φ e φ e φ p p → deep`

它的过程是：

先合并连续重复：

`φ d φ e φ e φ p`

再删除 blank：

`d e e p`

所以得到：

`deep`

> 为什么 CTC 需要 blank φ？直接合并重复字符不行吗？

参考答案：

不行。因为有些单词本身就有重复字母，比如 **deep** 里面有两个 e。如果只做“合并重复”，`d e e p` 会变成 `d e p`。CTC 引入 blank 后，可以用 blank 把两个相同字符隔开，比如 `d e φ e p`，这样删除 blank 后仍然得到 `deep`。



### CTC 的优点：
第一，训练不需要帧级别对齐标注。  
第二，结构相对简单。  
第三，可以用于语音识别这种输入长、输出短的任务。  
第四，如果 encoder 是单向的，也可以做流式识别。

### CTC 的缺点

CTC 的核心缺点是：
**输出之间相对独立，语言建模能力弱。**

也就是说，CTC 每一帧主要根据声学信息判断输出什么，它本身不太会强建模“前一个字影响后一个字”。
比如中文里，“我想吃苹”后面更可能是“果”，这个语言上下文关系 CTC 本身不强。
所以 CTC 经常需要外部语言模型帮助。


## RNN-T ：CTC + 语言上下文


RNN-T 全称：

**Recurrent Neural Network Transducer**

它可以理解为：
**在 CTC 的基础上，加入了对历史输出 token 的建模。**

CTC 主要看声学帧。  
RNN-T 不只看声学帧，还看前面已经输出过什么 token。

所以它更像：
**声学模型 + 语言模型 + 联合预测**

> RNN-T 相比 CTC 最大的改进是什么？

参考答案：

CTC 的输出之间相对独立，语言上下文建模能力较弱；RNN-T 加入了 prediction network，能够利用之前已经输出的 token，因此可以建模输出 token 之间的依赖关系，具有更强的语言建模能力。

RNN-T 通常有三个模块：

### 1. Encoder / Transcription Network

处理声学输入。

作用类似：

**听声音。**

### 2. Prediction Network

处理历史输出 token。

作用类似：

**根据前面已经识别出的字，预测后面可能是什么。**

### 3. Joint Network

把声学信息和历史文本信息结合起来，预测下一个 token。

作用类似：

**把“听到的声音”和“语言上下文”合起来判断。**


### 对比
- CTC 的推理，是输入声音->声学特征->直接输出 token 或 blank，1000 帧就必须输出 1000 个符号（哪怕里面有 980 个是 Blank）。
- RNN Encoder-Decoder (Seq2Seq)，是 ENcoder 读完，输出理解，**此时没有任何 Token 输出。** Decoder 再借助输出的理解（即对声学特征的理解）去输出 token。**它输出的步数，等于最终文本的字数，跟帧数毫无关系！**
	- 第 1 步：Decoder 利用 Attention 扫描那 1000 个向量，输出第 1 个字 d。
	- 第 2 步：Decoder 看着自己刚才输出的 d，再次扫描那 1000 个向量，输出第 2 个字 e。
	- ...
	- 第 5 步：Decoder 输出一个特殊的 **`<EOS>`（End of Sentence，句子结束符）**。
	    推理瞬间停止！  
	    总结 Seq2Seq 不是按“帧”输出的，而是按“字（自回归步数）”输出的。它不需要 Blank 符号，因为生成完 deep 后，它自己喊停了。
	

- RNN-T 
	- ENcoder 和 seq2seq 一样，提取当前时间帧的**声学特征**
	- Prediction Network 呢，输入“已经真实输出的历史 token”（比如已经输出了 d、e），输出一- 个**语言特征**（此时它还没算出最终是哪个字，只是给出一个“语境预判”）。
	- Joint Network 是它把【当前第 t帧的声学特征】和【历史输出带来的语言特征】**加在一起**然后经过一层网络和 Softmax，**输出最终的 Token 或 Blank**。


Seq2Seq 靠 Attention 对齐
Seq2Seq 里的 Attention 是“软对齐”。预测第 2 个字的时候，模型可以看第 10 帧，预测第 3 个字的时候，模型可以掉头回去看第 2 帧。
* 在**机器翻译**里这很棒，因为英语和中文的语序是颠倒的。
* 但在**语音识别**里，时间流逝是**单向（严格单调 monotonic）**的！说的话绝对是从左到右的，不可能倒退。Seq2Seq 的 Attention 经常会“看走眼”，导致语音识别出现**漏字、重复**的严重幻觉。


RNN-T 靠 Joint Network + Blank 严格单调对齐
RNN-T 和 CTC 一样，时间只能往前走。它也使用了 Blank（空白符）的概念：
* 如果 Joint Network 发现：当前这帧声音 $h_t$ 和过去的文本 $y_{u-1}$ 结合后，还不足以判断出下一个字，它就会输出一个 **Blank (`-`)**。
* 遇到 Blank 后，**文本不增加，时间往前走一帧**（吸收下一帧声音 $h_{t+1}$）。
* 遇到实体字后，**时间停留在原地，文本往下走一步**（更新 Prediction Network）。
这种机制完美契合了语音识别“严格从左到右”的物理规律，杜绝了 Seq2Seq 乱跳的问题。


### RNN-T 的优点

RNN-T 的优点：

第一，可以建模输出 token 之间的依赖。  
第二，适合流式语音识别。  
第三，不需要完整等待整句话说完，可以边听边输出。  
第四，在工业语音识别中很重要。


### RNN-T 的缺点

它比 CTC 更复杂，训练和解码难度更高。

**CTC 简单但语言建模弱；RNN-T 更复杂但能利用历史输出。**


## Neural Transducer：分块处理

Neural Transducer 可以理解为：

**把长语音切成一个个小块 chunk/window，再在每个块里做识别。**

它想解决的问题是：
如果模型总是看完整句语音，会不适合实时识别。 （前面的 CTC 可以随时间步推移输出，传统**Seq2Seq**不行）
所以它让模型分块处理，一边接收语音，一边生成输出。

模型**不再是一帧一帧地处理声音了**，而是把连续的声音切成一个个**固定长度的“块（Chunk / Block）”**。比如每 300 毫秒切一块（包含 10 帧）。

1. **收齐一个块**：系统先等待，直到收集满当前块的所有声音特征（$h^t$ 到 $h^{t+w}$）。
2. **块内 Attention（注意力）**：图中的交叉箭头表示，中间的橘色解码器（Decoder）在生成字的时候，是可以**同时看到这整个块**的信息的（Attention 机制）。
3. **输出多个 Token**：在这个块内，Decoder 开始生成字，比如图里输出了 `c` 和 `a`。
4. **输出块结束符（Blank）**：当 Decoder 觉得这个块里的声音信息已经翻译完了，它就会输出一个特殊的空白符（图中红色的空方块）。这个动作相当于向系统喊话：“**这段我翻译完了，把下一个声音块送进来吧！**”
5. **滑动到下一个块**：系统开始收集下一个时间段的 $W$ 帧，重复上述过程。

### 优缺点
优点：

**适合流式识别，延迟较低。**

既能不断往外蹦字（实现了流式），又能结合局部的上下文（提高了准确率）。

> 对比**CTC / RNN-T（严格流式）**在处理第 $t$ 帧时，它**绝对看不到**第 $t+1$ 帧的声音。这在有些时候很容易识别错（比如有些发音要连着后面几个音才能听出到底是什么字）。 Neural Transducer 在块内，它可以利用 Attention 机制看到这 300 毫秒内的“未来”信息，这让它的识别准确率比纯粹一帧帧猜的 RNN-T 要高。Seq2Seq要等**整句话（可能 10 秒钟）**全说完，才能开始 Attention。我等不了整句话，但我可以等 300 毫秒啊！我把长句子切成无数个 300 毫秒的短句，在每个短句里用 Seq2Seq 的 Attention。这样既保住了流式的特性（最多延迟 300 毫秒），又享受到了 Attention 带来的上下文理解能力！

缺点：

**窗口大小不好选。**
窗口太小：信息不足，容易识别错。  
窗口太大：延迟增加，实时性变差。


## MoChA：单调块注意力
MoChA 全称：

**Monotonic Chunkwise Attention**

它名字很长，但可以拆开理解：

**Monotonic = 单调**  
**Chunkwise = 分块**  
**Attention = 注意力**

对于单调的理解，
传统的 Attention，**没法流式（边听边写）**：因为它有全图视野，它要预测第一个字，必须得等你把最后一秒的音也录完，它整体看一遍才敢下结论。即使你录完了，它在预测时，注意力也有可能“看走眼”，明明已经翻译到第 20 帧了，预测下一个字时它的注意力又**倒退**跳回到了第 5 帧，导致屏幕上输出乱码或者重复的字。

而 Mocha，如果你在预测上一个字时，注意力已经走到了第 20 帧，那么当你预测下一个字时，**你的目光只能从第 20 帧开始往后看，绝对不允许回头看 1-19 帧！**  
这就强行把 Attention 的目光变成了和时间流逝一样的“单向箭头”。这就解决了“乱跳”的问题。


对于分块的理解，Mocha 是 windows 伸缩自如的 Neural Transducer

- 它本质上依然是一个边听边写、分块处理的**流式识别模型**（类似于 Neural Transducer）。
- 但它的 **Windows（接收声音的窗口）**不固定，语速快、音节短，窗口就小；语速慢、拖长音，窗口就拉长


加上了单向箭头后，MoChA 进一步规定：当你（巡逻兵）探测到当前这个字的信息足够了（确定了刚才聊的“伸缩自如的窗口”边界后），**你只允许在这个短小的窗口内部（比如第 20 帧到第 35 帧），进行 Attention 计算。**


# 语言模型

**语言模型就是预测序列概率 P (w₁, w₂, …, wN)，核心任务是根据上下文预测下一个词。**

> 为什么语音识别和文本生成都需要语言模型？

参考答案：

因为语音识别仅靠声学模型可能不够，模型可能把 “一拳超人”识别成 “一前超人”，语言模型可以用上下文概率纠正；文本生成本质也是预测下一个词，语言模型提供概率分布，使生成文本更自然。


最原始的语言模型就是给一个序列 w₁…wN 计算概率：


$$P (w_1, w_2, ..., w_N) = \prod_{t=1}^{N} P (w_t \mid w_1, ..., w_{t-1})$$ **一句话出现的概率，等于“在已知前面所有字的情况下，说出下一个字的概率”的连乘。**

比如你想预测句子：`“我 喜欢 吃 苹果”`
它的概率 = $P(我) \times P(喜欢 \mid 我) \times P(吃 \mid 我, 喜欢) \times \mathbf{P(苹果 \mid 我, 喜欢, 吃)}$

**问题出在哪里？**
假设我们要预测一篇长文章的第 100 个词。根据公式，我们要算：
$P(第100个词 \mid 前面99个词)$。
这意味着，为了求出这个概率，你必须去海量的语料库（比如全网所有的书和网页）里找，**“前面那 99 个词一模一样按顺序出现的情况下，第 100 个词是什么”**。
但是，世界上几乎找不到两段完全一模一样的 99 个词的组合！这就是 NLP 里著名的**“数据稀疏问题”**。条件太苛刻了，模型算出来的概率永远是 0。

## N-gram
为了解决这个问题，N-gram 提出了一个伟大的假设，叫做**马尔可夫假设（Markov Assumption）**：
**“下一个词出现的概率，只跟它前面最近的 $N-1$ 个词有关，再往前的历史统统不管了！”**

$$P (w_t \mid w_1, ..., w_{t-1}) \approx P (w_t \mid w_{t-N+1}, ..., w_{t-1})$$  
N-gram 究竟啥意思？
* **gram**：指的是文本里的基本单位（可以是一个字、一个词、甚至一个字母）。
* **N**：指的是把几个词捆绑在一起看。
* **N-gram 语言模型**：就是利用长度为 N 的切块，来估算单词出现的概率。

我们来看看 N 取不同值时的具体含义（以预测 `P(苹果 | 我, 喜欢, 吃)` 为例）：

**1. Unigram (一元模型，N=1)**
* **假设**：下一个词跟前面**0**个词有关（各个词是完全独立的）。
* **公式**：$P(苹果 \mid 我, 喜欢, 吃) \approx \mathbf{P(苹果)}$
* **解释**：模型根本不看前文，纯靠“苹果”这个词在整个语料库里出现的总频率来瞎猜。这就像个失忆症患者。

**2. Bigram (二元模型，N=2)**（最常用）
* **假设**：下一个词只跟前面 **1** 个词有关。
* **公式**：$P(苹果 \mid 我, 喜欢, 吃) \approx \mathbf{P(苹果 \mid 吃)}$
* **解释**：模型只记得上一个词是“吃”，于是去字典里查“吃”后面跟着“苹果”的概率。把“我、喜欢”全都抛在脑后了。

**3. Trigram (三元模型，N=3)**
* **假设**：下一个词只跟前面 **2** 个词有关。
* **公式**：$P(苹果 \mid 我, 喜欢, 吃) \approx \mathbf{P(苹果 \mid 喜欢, 吃)}$
* **解释**：模型记得前两个词是“喜欢吃”，去查这两个词后面跟着“苹果”的概率。


深度学习时代的模型存的是“神经元权重矩阵”，**而 N-gram 模型里存的内容极其简单粗暴——就是“查字典的频率统计表（Count）”！**

这就是极大似然估计（MLE）。比如我们要算 Bigram 模型里的 $P(苹果 \mid 吃)$，它是怎么算的呢？
非常简单，做除法：

$$P(苹果 \mid 吃) = \frac{\text{语料库中“吃 苹果”同时出现的次数}}{\text{语料库中“吃”出现的总次数}}$$

所以，一个训练好的 N-gram 模型，**它的内容就是一个巨大的 Hash 表（字典）**。
比如一个 Bigram 模型的内容长这样：
* `{"吃": 10000次}`
* `{"吃 苹果": 2000次} -> P(苹果|吃) = 0.2`
* `{"吃 米饭": 3000次} -> P(米饭|吃) = 0.3`
* `{"吃 键盘": 0次} -> P(键盘|吃) = 0.0`


正因为 N-gram 只能看眼前 $N-1$ 个词，记不住远处的上下文，后来人们才发明了 **RNN/LSTM**（把前面所有的历史信息压缩成一个 Hidden State 一代代传下去），再后来觉得 RNN 传太久会遗忘，于是又发明了 **Transformer（Attention 机制）**，让模型不仅能看到前面所有的词，还能直接跳过去抓取最关键的词（彻底解决了长距离依赖问题）！



同时，
- N-gram 是典型的**离散型（Discrete）**模型。
- 它的世界里**没有“空间、距离、向量”的概念**。它真的就只有一个大词表（字典）。
- 对于 N-gram 来说，“狗”就是词表里的第 54 号元素，“猫”就是第 99 号元素，“挖掘机”是第 800 号元素。
- 在它眼里，54 号和 99 号的关系，跟 54 号和 800 号的关系是一模一样的（都是毫无关系）。



## 连续空间语言模型 Continuous LM

现代语言模型不是用离散词表，而是用 **词向量 / 子词 / token embedding** 表示。

优点：

- 捕捉语义相似性
- 处理 OOV 问题 **（Out-Of-Vocabulary，未登录词 / 词表外词.当模型在测试推理或者实际应用时，遇到了一个**不在那 5 万个词表里的词**,)**
- 支持大模型


核心思想：词被映射到向量空间，模型预测下一个词的 embedding，然后解码成 token。


### 神经网络语言模型 NNLM / RNN LM

只要是基于神经网络的语言模型，**第一步绝对是做 Embedding（词嵌入）！**

NNLM / RNN LM 是两个例子

### 1. NNLM（前馈神经网络）

- 输入：前 N-1 个词，维度拼接起来！所以输入维度是固定设置的
- 输出：下一个词的概率

- 优点：词嵌入（word embedding）+ softmax
- 缺点：上下文长度有限


### 2. RNN LM

- 输入：词向量序列
- RNN 更新 hidden state：$$h_t = f (h_{t-1}, x_t)$$
    
- 输出：softmax 得到 $P (w_t|h_t)$
- 优点：可以处理任意长度上下文
- 缺点：训练慢，长期依赖可能受梯度消失影响

RNN LM 通过隐藏状态 h_t 记住之前所有词的上下文信息，每一步输出依赖 h_t，因此能够捕捉比 N-gram 更长的依赖关系。



## Fusion
 **ASR（听觉大脑，比如 LAS 模型）** 和 **LM（语言大脑，比如 RNN LM）** 分别拆解透了。但在实际的工业界中，光靠听觉大脑是不够的。

**为什么要融合（Fusion）？**  
因为有些音太像了！比如你发音 [r aɪ t]，ASR 可能会纠结到底是 right 还是 write。这时候，如果你前面说的是 "You are completely..."，**语言大脑（LM）** 就会跳出来说：“别猜了！根据我读过几十亿句话的经验，这里 99% 是 right！


判断一种融合方法，主要看两个维度：

1. **在哪融合（How to integrate）**：是在最后一刻的**输出层（Output）**合并，还是在网络中途的**隐藏层（Hidden）**合并？
    
2. **何时融合（When to integrate）**：是在**模型训练完之后（After Training）**硬凑，还是在**模型训练之前（Before Training）**就让它们一起成长？
    

由此，诞生了三大门派：**Shallow Fusion（浅融合）、Deep Fusion（深融合）、Cold Fusion（冷融合）**。



### 1. Shallow Fusion（浅层融合，第 24 页）
**【通俗比喻】：两个专家各自独立工作，最后把写着答案的纸条递交上去，按权重投票。**

* **前提条件**：ASR（图中的 LAS Decoder）是单独训练好的，LM 也是单独训练好的。两者互不干涉。
* **怎么融合**：看图中的公式 $y^* = \arg\max (\log P_{LAS}(y) + \lambda \log P_{LM}(y))$
  * 在推理时，ASR 说下一个词是 `right` 的概率是 0.6，LM 说下一个词是 `right` 的概率是 0.8。
  * 把这两个得分直接**相加**（中间有个 $\lambda$ 是用来调参的权重，比如我觉得 LM 更靠谱，我就给 LM 乘个 1.2）。
  * 选取得分最高的词输出。
* **优点**：**极其简单、插拔自如！** 你的 ASR 模型一行代码都不用改，想换什么 LM 随时换（甚至可以换成巨大的 BERT）。
* **缺点**：太表面了。两个专家没有交流，只是机械地加分数，遇到复杂情况容易翻车。

---

### 2. Deep Fusion（深层融合，第 25-26 页）
**【通俗比喻】：两个独立的专家在出结果之前，坐在一起开个短会，商量一下再给出唯一的最终答案。**

* **前提条件**：ASR 和 LM 依然是**事先分别单独训练好**的。
* **怎么融合（在哪融合）**：
  * 我们不在最后一步（Output 概率）加和了。
  * 我们在两者输出概率的**前一步**，把 ASR 的 **隐藏层向量（Hidden）** 和 LM 的 **隐藏层向量（Hidden）** 提取出来。
  * 我们引入一个**新的小网络（图中的 Network）**，把这两个向量拼接在一起喂给它，让它来输出最终的预测。
* **怎么训练**：ASR 和 LM 的参数都被**冻结（锁死）**了，我们拿一堆数据，**只训练中间这个新加的“小会议室（Network）”**。
* **优点**：比浅层融合聪明，因为网络可以看到更深层的“语义特征”，而不只是最后干瘪的概率数字。
* **缺点**：依然是个“半路夫妻”，小会议室的作用有限。

---

### 3. Cold Fusion（冷融合，第 27 页）
**【通俗比喻】：语言专家（LM）是一个德高望重的老教授，听觉专家（LAS）还是个白纸一样的婴儿。婴儿从第一天起，就在老教授的贴身指导下学习听音辨字。**

* **怎么融合（何时融合）**：**Before Training（在 ASR 训练之前就开始融合）！**
* **训练过程**：
  * 先单独训练好一个强大的 LM（老教授）。
  * 然后，**从零开始（From scratch）训练 LAS 模型**。
  * 在 LAS 训练的每一次循环中，都把 LM 算出来的隐藏状态（Hidden），作为**额外的知识**输入给 LAS 的 Decoder。
* **优点**：
  * 这种融合是最彻底的，LAS 会极其信任且深刻地利用 LM 的知识。
  * PPT 原话：**"LAS converges faster"（LAS 训练收敛得更快）**，因为有老教授带路，婴儿学得快。
* **致命缺点**：
  * PPT 原话：**"LAS has to be trained again if you have a new LM"**。
  * 也就是说，因为 LAS 是伴随这个特定的 LM 长大的，它对这个 LM 产生了严重依赖。**如果你明天想换一个更聪明的 LM，对不起，这个 LAS 就废了，你必须带着新的 LM 把 LAS 从头再训练一遍！**（这在工业界是很痛的，因为训练一遍语音大模型要花几百万的电费）。



### 第 28 页：终极总结（Concluding Remarks）

这就是本章最后的收尾。
在实际应用中，工程师们是怎么选的呢？
* **Shallow Fusion** 至今仍然是工业界**最流行、最常用**的方法。因为它太方便了！我们可以把手机本地的小 LM，随时通过网络接口换成云端的超级 LM（不需要重新训练 ASR）。
* **Cold/Deep Fusion** 性能虽然可能更好，但因为训练成本高、耦合太深，通常只在打比赛或者特定的封闭系统里用。


# 语音合成
语音合成，也就是 **Text-to-Speech, TTS**，目标是把一段文本变成自然语音。
但中间并不是直接“文字 → 波形”这么简单。传统系统通常会分成很多模块，例如：

文本分析 → 语言特征/音素 → 声学特征 → 声码器 → 语音波形

##  第一类：拼接式语音合成 Concatenative Approach
先录很多真人语音，建立一个大语音库；  
合成时，从语音库中挑出合适的片段；  
然后把这些片段拼接成完整语音。
PPT 里用的是 **speeches from a large database** 来描述这种方法，也就是依赖大型语音数据库中的真实语音片段

它的优势是：

1. **自然度高**：因为很多声音片段本身就是真人录的。
2. **音质好**：不需要复杂声码器重建波形。
3. **在固定领域效果稳定**：比如导航、客服、车站播报等场景。

缺点是：

1. 数据库要求很大你想合成越多内容，就要提前录越多语音。  . 如果数据库里没有合适片段，合成结果就会不自然。
2. 灵活性差，如果想换说话人、换情感、换语速、换风格，就要重新录很多数据。
3. 拼接处不自然，两个片段虽然单独听都自然，但拼在一起时可能出现：

## 第二类：参数式语音合成 Parametric Approach

文本
↓
文本分析/语言特征
↓
声学模型，例如 HMM 或 DNN
↓
预测声学参数：频谱、基频 F0、时长等
↓
声码器 vocoder
↓
语音波形

这里的“参数”不是神经网络参数，而是描述语音声音特征的声学参数，比如：

| 参数                   | 含义        |     |
| -------------------- | --------- | --- |
| 频谱 spectral envelope | 决定音色、发音内容 |     |
| 基频 F0                | 决定音高      |     |
| 时长 duration          | 决定每个音发多久  |     |
| 能量 energy            | 决定声音强弱    |     |

也就是说，参数式方法不是存储大量语音片段，而是学习：

> 给定文本和语言特征，应该生成什么样的声学参数。

然后再由声码器把这些参数转成语音。

### HMM-based TTS 是什么？

HMM-based speech synthesis 是早期参数式语音合成的代表。  
它会把语音看成一连串状态，每个状态对应某种声学分布，然后根据文本预测状态序列和声学参数。

优点是：

1. **模型小**
2. **可控性比拼接式更强**
3. **不需要庞大语音库**
4. **可以较容易调整语速、音高等参数**

缺点也明显：

1. 声音容易过平滑，听起来“闷”。
2. 自然度通常不如高质量拼接式语音。
3. 需要复杂的特征工程和前端处理。

### DNN-based TTS 改进了什么？
后来 DNN 替代 HMM 中的一些统计建模部分，用深度神经网络预测声学参数。

相比 HMM，DNN 的表达能力更强，可以更好地建模文本和声学特征之间的复杂关系。  
但它仍然属于参数式方法，因为它通常还是：

文本特征 → 声学参数 → 声码器 → 波形

也就是说，它还没有完全端到端。
## 第三类：端到端 TTS：以 Tacotron 为代表

传统 TTS 系统的问题是模块太多，
每个模块都可能出错，而且前一个模块的错误会传到后一个模块。

端到端 TTS 的目标是：

> 尽量减少人工设计模块，让神经网络直接学习从文本到语音表示的映射。

PPT 中将 Tacotron 标为 **Tacotron: End-to-End TTS**，并强调它是 towards end-to-end speech synthesis 的代表。

Tacotron 的重要特点是：

输入：character 字符
输出：linear spectrogram 线性频谱



这说明 Tacotron 已经不再强依赖人工音素标注，而是直接从字符序列学习到声学表示。

不过注意：Tacotron 本身通常不是直接输出最终波形，而是输出频谱；最终还需要 Griffin-Lim 或 WaveNet 等方法把频谱变成语音波形。

文本序列和语音频谱序列长度完全不同。  
例如一句话只有 10 个字，但对应的频谱可能有几百帧。
所以模型需要学习：

> 当前生成的语音帧对应输入文本中的哪个字符？
这就是 Attention 的作用。

##  TTS 里的 Attention 有什么特殊要求？


语音合成里的对齐通常应该是**单调的**。
也就是说，文本从前往后读，语音也应该从前往后生成。  
你不会先读最后一个字，再读第一个字。
也就是输出音频和输入文本必须满足单调对齐关系。

这也是 TTS 与机器翻译等任务不同的地方。机器翻译中词序可能变化，但 TTS 里文本和语音大体必须按顺序对应。

## Duration
在语音合成中，它表示：

> 每个字、音素或音节应该持续多久。

例如：


“啊——” 可以拖长
“的” 通常很短

重读词可能更长

如果 duration 错了，会出现：

1. 某个字被跳过
2. 某个字重复读
3. 语速忽快忽慢
4. 韵律不自然
5. 长句合成崩溃

这也是后来 FastSpeech 等模型要显式建模 duration 的原因。PPT 中提到 FastSpeech 在 50 个句子的测试中 repeats、skips、error sentences 都为 0，而 Tacotron 2 和 Transformer TTS 仍有一定错误率


## 三类对比
| 方法                | 核心思想               | 优点         | 缺点                   |
| ----------------- | ------------------ | ---------- | -------------------- |
| 拼接式 Concatenative | 从大语音库中选片段并拼接       | 音质自然，真实录音  | 数据库大，灵活性差，拼接不连续      |
| 参数式 Parametric    | 预测声学参数，再用声码器合成     | 模型小，可控，灵活  | 声音容易过平滑，不够自然         |
| 端到端 TTS           | 神经网络直接从文本生成频谱/语音表示 | 流程简化，自然度提升 | 需要大量数据，可能有跳词/重复/对齐错误 |



如果考试问：**Tacotron 为什么需要 Attention？**

可以答：

> Tacotron 输入是字符序列，输出是线性频谱序列，二者长度不同，且一个字符通常对应多个语音帧，因此解码器在生成每一帧时需要知道应该关注输入文本中的哪个字符。Attention 机制用于学习输入字符和输出频谱帧之间的对齐关系。在 TTS 中，语音是按文本顺序朗读的，所以这种对齐通常应满足单调性，即输出音频和输入文本要单调对齐。12

如果考试问：**Attention、Duration、单调对齐的关系？**

可以答：

> Attention 是一种动态学习文本和语音帧对应关系的机制；Duration 表示每个字符或音素持续的时间，本质上也是一种显式对齐信息；单调对齐是 TTS 任务对这种对应关系的要求，即语音帧对应的文本位置应随时间从前往后移动，不能乱序。若对齐失败，可能出现重复、跳词等问题，FastSpeech 等方法通过显式 duration 建模减少这类错误。


### 1. 优点

Tacotron 的优点主要有三个。

第一，它简化了传统 TTS 系统，把很多手工设计模块合并到一个神经网络框架里。26

第二，它直接以 character 作为输入，不像一些传统系统那样强依赖复杂的音素、时长、声学特征工程。2

第三，它的效果已经超过传统参数式方法，PPT 中 Tacotron 的 MOS 是 3.82，而 Parametric 是 3.69。4

---

### 2. 问题

Tacotron 的问题也主要有三个。

第一，Attention 对齐可能不稳定，尤其是长句子里容易出现跳词、重复、停不下来等问题；这和 PPT 里强调 output audio 和 input text 必须 monotonic aligned 有关。4

第二，它输出的是频谱，还需要 audio synthesis 阶段才能得到最终语音。24

第三，早期版本的整体自然度还低于高质量拼接式方法，PPT 中 Concatenative 的 MOS 是 4.09，高于 Tacotron 的 3.82。


##  Beyond Tacotron
Tacotron 的问题：

1. 可能发音错误 mispronunciation

2. attention 对齐不稳定

3. 长句可能重复 repeat

4. 可能跳词 skip

5. 可能出现 error sentence

6. 自回归生成速度慢

Beyond Tacotron 的改进方向：

1. 用 phoneme / lexicon / character+phoneme hybrid input 减少发音错误

2. 给 encoder 加更多信息，比如 syntactic information

3. 改进 attention，比如 monotonic attention、location-aware attention，让 attention 更稳定。

4. 用 duration 显式建模对齐

5. FastSpeech 用更稳定的 duration-based / non-autoregressive 框架减少重复跳词，并提升速度

| 项目     | Beyond Tacotron                                    | FastSpeech                                       |
| ------ | -------------------------------------------------- | ------------------------------------------------ |
| 层级     | 大方向 / PPT 第三部分                                     | 具体模型                                             |
| 含义     | Tacotron 之后的各种改进                                   | 一种改进 Tacotron 类 TTS 的方法                          |
| 关注问题   | 发音错误、OOV、输入表示、encoder 信息、attention/duration 等      | 主要解决重复、跳词、错句，并提高稳定性                              |
| PPT 证据 | “03 Beyond Tacotron” 是大纲中的一章                       | 表格单独比较 FastSpeech 和 Tacotron 2 / Transformer TTS |
| 例子     | phoneme input、hybrid input、syntactic information 等 | FastSpeech 在 50 句测试中 error rate 为 0%             |

# 语音转换

**语音转换就是：输入一段语音，尽量保留它的语言内容，但改变某些语音属性，比如说话人、情感、口音、唱法等**

## 2. 语音转换中“保留”和“改变”的东西


### 2.1 保留什么？

一般来说，VC 最核心要保留的是：

1. **语言内容 Content**
2. **语义信息**
3. **音素序列或发音内容**
4. 某些任务中也希望保留节奏或韵律

PPT 里明确写到 “What is preserved? Content”，所以“内容保持不变”是语音转换的基本目标。

也就是说，如果输入语音说的是“天气真好”，转换后仍然应该说“天气真好”，而不是变成“How are you?” 或者其他句子。

### 2.2 改变什么？

可以改变的属性很多，PPT 里说 “What is Changed? Many different aspects”，其中最典型的是 **speaker，说话人身份**。

此外，PPT 后面还列出了很多语音转换的应用方向，包括 singing、speaking style、emotion、Normal-to-Lombard、Whisper-to-Normal、singers vocal technique conversion、improving intelligibility 和 accent conversion 等。

所以语音转换不只是“换声”，更广义地说，它可以做：

|转换类型|例子|
|---|---|
|说话人转换|A 的声音变成 B 的声音|
|情感转换|平静语音变成开心/愤怒语音|
|歌声转换|一个歌手的音色变成另一个歌手|
|口音转换|非母语口音变成更接近母语者发音|
|说话风格转换|耳语变正常语音，普通语音变 Lombard speech|
|清晰度增强|帮助发音受损者提高语音可懂度|

PPT 中提到 accent conversion 可以结合非母语者的 voice quality 和母语者的 pronunciation patterns，也就是说它可以用于语言学习场景。


## 3. 语音转换和 TTS 有什么关系？

这点也值得理解，因为语音转换和语音合成容易混淆。

**TTS，Text-to-Speech，是文本到语音；VC，Voice Conversion，是语音到语音。**

PPT 中把 VC 放在 Speech-to-Speech Model 的语境下介绍，也就是输入和输出都是语音。

对比一下：

|任务|输入|输出|核心目标|
|---|---|---|---|
|TTS|文本|语音|根据文字生成声音|
|VC|源语音|目标风格语音|保留内容，改变语音属性|

举例：

- TTS：输入文字 “How are you?”，系统生成一段语音。
- VC：输入 A 说的 “How are you?”，系统输出 B 声音版本的 “How are you?”。

PPT 中还提到 voice conversion 可以作为实现 personalized TTS 的一种简单方式，也就是先有普通 TTS，再通过语音转换把声音转成目标人的个性化声音



## 4. 语音转换的应用场景

PPT 中列出的应用其实很多，我们可以按照考试常见分类整理。

### 4.1 Deepfake 与身份伪装

PPT 提到了 Deep Fake，并且说它可以 fool humans 或 speaker verification system，也就是可能欺骗人类听者或说话人验证系统。1

所以 VC 有正向用途，也有安全风险。

正向用途比如影视配音、个性化语音助手、隐私保护；负向用途包括伪造声音、攻击声纹识别系统等。

### 4.2 Personalized TTS

语音转换可以用来做个性化 TTS，即先合成普通语音，再把它转换成某个目标说话人的声音。4

这个思路的好处是：如果目标说话人的训练数据不多，可以通过 VC 方式实现个性化声音迁移。

### 4.3 Singing Voice Conversion

PPT 中列出了 singing 相关工作，例如 Unsupervised Singing Voice Conversion 和 Pitch-Net 等。

歌声转换通常更难，因为歌声里除了音色，还有音高、旋律、颤音、唱法技巧等因素。

### 4.4 Speaking Style Conversion

PPT 提到 speaking style 包括 emotion、Normal-to-Lombard、Whisper-to-Normal、singers vocal technique conversion 等。

这里的关键不是换说话人，而是换“说话方式”。

比如：

- 普通语音 → 带情绪语音
- 耳语 → 正常说话
- 普通发声 → Lombard speech
- 普通唱法 → vibrato 或 lip trill 等特殊技巧

### 4.5 Improving Intelligibility

PPT 中还提到可以改善 speech intelligibility，尤其是帮助因手术失去部分发音器官的患者提高语音可懂度。

这类应用更偏医疗辅助，不是为了让声音“像某个人”，而是让语音更容易被听懂。

### 4.6 Accent Conversion

PPT 中提到 accent conversion 可以结合非母语者的 voice quality 和母语者的 pronunciation patterns，并且可以用于 language learning。

也就是说，口音转换不是简单换音色，而是希望保留说话人自身音质，同时让发音模式更接近目标口音或母语者发音。

## 5. Categories：语音转换的数据类别

PPT 中有一个重点是 **Categories**，尤其是 parallel data 和 unparallel data。

这部分可以理解为：训练 VC 模型时，源说话人和目标说话人的语音数据是否“一一对应”。

---

### 5.1 Parallel Data：平行数据

**Parallel data** 指的是源说话人和目标说话人说了相同的内容。

例如：

- 源说话人 A：How are you?
- 目标说话人 B：How are you?

PPT 中在 parallel data 部分展示了 “How are you?” 对应 “How are you?” 的例子，说明源和目标语音内容一致。

这种数据最容易训练，因为模型可以直接学习：

> 同一句话在 A 声音和 B 声音之间如何映射。

但是它的问题是收集成本高，因为需要不同说话人录制相同文本。

---

### 5.2 Unparallel Data：非平行数据

**Unparallel data** 指的是源说话人和目标说话人的语音内容不一样。

例如：

- 源说话人 A：天气真好
- 目标说话人 B：How are you?

PPT 中在 unparallel data 的例子里出现了“天气真好”和“How are you?”，说明两边内容并不对应。2

这种情况更贴近真实世界，因为我们通常很难要求不同说话人录完全相同的句子。

但是训练难度更高，因为模型不能简单地做帧级别对齐，也不能直接知道“源语音的这一段应该对应目标语音的哪一段”。



### 5.3 平行数据 vs 非平行数据

| 类别              | 是否同一句话 | 优点        | 难点          |
| --------------- | ------ | --------- | ----------- |
| Parallel data   | 是      | 容易对齐，训练简单 | 数据采集成本高     |
| Unparallel data | 否      | 数据更容易获得   | 难以对齐，需要更强模型 |

PPT 把非平行数据类比为 “audio style transfer”，并且提到可以借鉴 image style transfer 的技术。

这句话很关键，因为它说明：非平行 VC 的思路往往不是直接学习一句话到另一句话的对应关系，而是学习如何把“内容”和“风格/说话人特征”分开。

这也自然引出下一部分：**Feature Disentangle，特征解耦**。

## Feature Disentangle 特征解耦

它的目标可以概括成一句话：

> 把一段语音拆成“内容信息”和“说话人信息”，再重新组合生成目标声音。

PPT 中在非平行数据后面直接引出了 **Feature Disentangle**，说明特征解耦主要是为了解决 unparallel data 下内容和风格难以直接对齐的问题


在 parallel data 里，A 和 B 说的是同一句话，比如两边都是 “How are you?”，模型比较容易学习 A 的声音如何变成 B 的声音。2

但在 unparallel data 里，A 说“天气真好”，B 说 “How are you?”，源语音和目标语音内容不同，不能直接建立逐帧对应关系。2

这时我们就不能简单地让模型学习：

> A 的这段语音 → B 的这段语音

因为它们连内容都不一样。  
所以更合理的思路是：

> 先从 A 的语音里抽出 content，再从 B 的语音里抽出 speaker/style，然后把 A 的 content 和 B 的 speaker/style 合成起来。

这就是 **Feature Disentangle** 的动机

### 2. Feature Disentangle 的基本结构

PPT 里出现了两个关键模块：**Content Encoder** 和 **Speaker Encoder**。1

可以把整个模型想象成这样：

Text

输入语音

  ↓

Content Encoder 提取内容：说了什么

Speaker Encoder 提取说话人：谁在说

  ↓

Decoder 根据 content + speaker 生成语音

PPT 中的图示展示了 Content Encoder 处理 “How are you?”，Speaker Encoder 判断 “Which Speaker?”，然后 Decoder 生成对应语音的结构。1

---

### 3. Content Encoder：负责“说了什么”

**Content Encoder** 的任务是提取语音中的语言内容，也就是类似音素、发音序列、文字内容的信息。

比如输入 A 的语音：

> “How are you?”

Content Encoder 希望得到的是和 “How are you?” 相关的内容表示，而不是 A 的音色、年龄、性别、身份等 speaker 信息。

理想情况下，不管是 A 说 “How are you?”，还是 B 说 “How are you?”，Content Encoder 输出的 content representation 应该比较接近。

也就是说，Content Encoder 要尽量做到：

> same content → similar content embedding  
> different speakers → 不要影响 content embedding

这一步非常关键，因为如果 content encoder 里混进了太多 speaker 信息，后面就很难把声音真正转换成目标说话人。

---

### 4. Speaker Encoder：负责“谁在说”

**Speaker Encoder** 的任务是提取说话人的身份、音色、声纹等信息。

比如输入 B 的语音，Speaker Encoder 希望得到一个表示 B 声音特点的向量。  
这个向量不应该太关心 B 具体说了什么，而应该关心：

- 音色
- 声道特征
- 性别/年龄相关声学特点
- 说话人身份
- 可能还包括部分韵律风格

PPT 里的 Speaker Encoder 后面对应的问题是 **“Which Speaker?”**，也就是它要帮助模型知道目标说话人是谁。1

---

### 5. Decoder：把 content 和 speaker 重新合成

Decoder 的任务是把两个信息组合起来：

Text

Content = 源语音说了什么

Speaker = 目标语音是谁的声音

然后生成：

Text

目标说话人声音版本的源语音内容

举例来说：

Text

A 说：“天气真好”

B 提供 speaker embedding

Decoder 输出：B 的声音说“天气真好”

所以 Feature Disentangle 的核心不是直接把整段 A 音频映射到整段 B 音频，而是先拆开再重组。

---

## 6. L1 / L2 距离：用来约束“像不像”

PPT 里后面会涉及“as close as possible”这类思想，通常在语音转换中会用 **L1/L2 distance** 来衡量两个特征或两段语音表示之间有多接近。6

这里我们先理解它的作用。

---

### 6.1 L1 距离是什么？

**L1 distance** 可以理解为绝对值差距：

Text

L1 = |预测值 - 真实值|

如果是向量，就是每一维差的绝对值加起来：

Text

L1 = Σ |x_i - y_i|

在语音转换中，L1 loss 常用于让生成的声学特征尽量接近目标声学特征。

它的特点是比较稳，不太容易被少数特别大的误差主导。

---

### 6.2 L2 距离是什么？

**L2 distance** 可以理解为平方误差：

Text

L2 = (预测值 - 真实值)^2

向量形式就是：

Text

L2 = Σ (x_i - y_i)^2

L2 对大的误差更敏感，因为差距会被平方放大。

在训练中，L2 loss 可以强迫模型尽量减少较大的偏差，但有时也可能导致生成结果过于平滑。

---

### 6.3 在 Feature Disentangle 里，L1/L2 用在哪里？

L1/L2 可以用在几个地方：

### 第一，用来做 reconstruction loss

输入一段语音，模型先编码再解码，希望输出能重建原始语音：

Text

输入语音 X

→ Content Encoder + Speaker Encoder

→ Decoder

→ 重建语音 X'

然后用 L1 或 L2 约束：

Text

X' 和 X 尽量接近

这个过程让模型学会基本的语音编码与生成能力。

---

### 第二，用来约束 content representation 接近

如果两段语音内容相同，即使说话人不同，它们的 content embedding 也应该接近。

比如：

Text

A: How are you?

B: How are you?

理想情况下：

Text

Content (A) ≈ Content (B)

这时可以用 L1/L2 让它们的 content 表示尽量接近。

---

### 第三，用来约束转换结果和目标分布接近

生成语音不仅要保留内容，还要听起来像目标说话人。  
因此模型可能会在声学特征层面、频谱层面或隐变量层面使用距离约束。

不过要注意：在 **unparallel data** 中，因为源和目标不是同一句话，所以不能简单地直接让输出和某一句目标语音做逐帧 L1/L2 对齐。  
这也是为什么需要额外机制，比如 speaker classifier 和 discriminator。

## Extra Criterion for Training：额外训练准则

PPT 中明确出现了 **EXTRA CRITERION FOR TRAINING**，并且包括两个问题：一个是 **real or generated?**，另一个是 **which speaker?**。6

这说明训练 VC 模型时，除了普通重建损失，还可以加入额外约束：

1. **Discriminator 判断真假**
   训练目标是：

- Discriminator 尽量分辨真实语音和生成语音；
- Generator / Decoder 尽量骗过 Discriminator，让生成语音听起来像真实语音。

所以 Discriminator 主要提升的是：

> 生成语音的自然度和真实感。
