# 语音识别

声音-->声学特征-->模型处理-->token

声学特征（ acoustic features）有：
- 频谱
- 能量
- MFCC、filter bank？他们两个怎么记住
![[_attachments/image/自己总结-1779241757390.jpeg]]
使用声学特征的好处，是将复杂的声音降维为简单，易处理的声学特征。将连续语音信号，转化为时间序列的声学特征，便于模型处理，提升模型效果。

token 的分类
- Phoneme 音素，与发音直接有关，便于语音识别。需要额外的 **Lexicon（词典）** 把 word 映射成 phoneme 序列
- Grapheme 字符，词表小，以一个字母/字为单位。但是没有语义
- Word 词，语义比较完成，但词表非常大，容易出现 OOV 问题。
- Morpheme ，语素，是最小的有意义单位。介于字符与词之间
- Byte 字节，和语言无关，固定序列长度

常用的语音识别模型架构是，seq2seq。
以其中处理序列模型为 RNN/LSTM 为例，他们都是输入上一个 token，输出下一个 token。模型设计使得上一个 token 也包含历史 token
- Encoder，**一次性输入完整的声学特征序列**，声学特征，然后模型输出对其的理解。具体的“理解”含义是① 提取内容信息；② **去除说话人差异**；③ **去除噪声**
- Decoder，结合上一个 token，与 Encoder 给出的理解，用 attention 机制，经过一个 softmax输出下一个 token

这种 seq2seq 模型可命名为 LAS
**LAS：Listen, Attend and Spell**
- Listen，就是 Encoder
- Attend，就是 attention 注意力机制
- Spell，就是 Decoder

训练时的小点
- Beam Search，每步保留概率最高的 B 条路径，最后选总分最高的
- Teacher forcing，训练时用真实标签 token 作为输入，而不是模型自己上一步输出的 token。这样做训练较为稳定，缺点是推理与训练不一致

## 押题参考答案

### 【题 1 答案】

**流程**：Waveform → DFT → Spectrogram → 通过 Mel Filter Bank → log → **Filter Bank 特征**；再做 DCT → **MFCC**。

**区别**：

- MFCC 比 Fbank 多一步 DCT，做了去相关，维度更低（典型 39 维）
- Fbank 维度更高、保留更多信息、相邻维度相关性强，更适合深度学习模型
- MFCC 适用于传统 GMM-HMM 系统；现代 DNN 系统更常用 Fbank

### 【题 2 答案】

- **Phoneme**：发音最小单位，需 Lexicon 映射；声学相关性强但需要专家知识 1
- **Grapheme**：字母/汉字；词表小、无 OOV，但单个字符无语义
- **Word**：词表大（英文可达数十万），语义完整，但易 OOV
- **Morpheme**：词素，介于 Grapheme 和 Word 之间，兼顾粒度和语义
- **Byte**：固定 256 词表，**与语言无关**，可处理多语言混合

**Word 有 OOV**：词表是固定的，新词/罕见词无法表示；**Byte 无 OOV**：任何 UTF-8 文本都能用 256 个字节表示。

### 【题 3 答案】

**LAS = Listen, Attend, and Spell**

- **Listen**（Encoder）：输入声学特征，输出高层表示  3
    - 三个作用：① 提取内容信息；② **去除说话人差异**；③ **去除噪声** 3
- **Attend**（Attention）：在每个解码步对 Encoder 输出加权，得到上下文向量 c
- **Spell**（Decoder）：结合 c 和上一步输出，通过 softmax 预测下一个 token

### 【题 6 答案】

|模型|输入-输出关系|
|---|---|
|LAS|T 输入 → N 输出，全局 attention|
|CTC|T 输入 → T 输出（含 Φ）2|
|RNA|1 输入 → 1 输出 6|
|RNN-T|1 输入 → 多输出 6|
|Neural Transducer|1 个 window → 多输出 6|
|MoChA|可伸缩 window → 多输出 6|

**MoChA 改进**：Neural Transducer 的 window 大小固定且按固定步长移动；MoChA 让 window **位置可学习、伸缩自如**，更灵活地对齐输入输出 6。

### 【题 7 答案】

**Teacher Forcing**：训练 Decoder 时，每一步输入用**真实的上一个 token**而不是模型预测的 token。

**为何稳定**：训练初期模型预测很差，若用模型自身输出会导致错误累积、梯度难以收敛；用真实 token 保证每一步输入正确，loss 更稳定。

**Exposure Bias 问题**：训练时输入永远是正确 token，推理时却必须用模型自身（可能错误）的输出 → 训练和推理分布不一致，一旦预测错就可能越错越离谱。缓解方法：Scheduled Sampling（按概率混合使用真实/预测 token）。
# 语音识别模型
- LAS = seq2seq 老大哥
- CTC = LAS 把 Decoder 简化成 linear + 加 Φ
- RNA = CTC 的进化（输入 1 出 1，但有依赖）
- RNN-T = RNA 的进化（输入 1 可出多）
- Neural Transducer = RNN-T + window
- MoChA = Neural Transducer + 可移动 window

LAS：以 RNN 为例，RNN 模型本身是，每个时间步输入一个向量+上一时间步模型的**隐状态**
在 Encoder 中，输入向量是当前时间步的声学特征。（这与我们会把整个时间的声学特征送给 encoder 不矛盾）
在 Decoder 中，每个时间步输入一个向量是上一步 token。此时与上一步隐状态结合，产生当前状态。然后呢！利用 Encoder
此时 Encoder 已经有了所有帧数的输出，Decoder 会拿当前自己的隐状态，问 Attention 机制，现在该去看音频哪部分。Attention 算出 10-30 帧权重大，吐出了属于当前步的 **上下文向量**。Decoder 会把隐状态和上下文向量拼接一起。

- Decoder 每一步的流程更精确的描述是：  
    **上一步隐状态 zₜ₋₁ → Attention 查询 Encoder 输出 → 得到上下文 cₜ → (zₜ₋₁, 上一步 token embedding, cₜ) 一起算出 zₜ → 经 softmax 得到当前 token 分布**。




CTC：不要 Decoder 了，直接 Encoder 每一帧输出理解后接一个 linear+softmax，所以每一帧都会输出 token，不过会输出 Blank 占位符。
训练比较难，因为不知道每帧对应哪个 token，需要**穷举所有合法对齐路径并求和**（前向-后向算法）

**RNA:
= Recurrent Neural Aligner**它的定位是：

- **CTC** 的 decoder 每一帧独立输出 → **没有上下文依赖**
- **RNA** 在 CTC 基础上**加入了输出之间的依赖**（即当前输出会依赖前一个输出），但仍然 **一个输入向量 → 一个输出 token**21。
- 所以 RNA 是 CTC 的进化（添加依赖性），而不是直接进化到 RNN-T。

RNN-T：
- ENcoder 和 seq2seq 一样，提取所有时间的**声学特征**
- Prediction Network 呢，输入“已经真实输出的历史 token”（比如已经输出了 d、e），输出一 个**语言特征**。
- Joint Network 是它把【当前第 t 帧的声学特征】和【历史输出带来的语言特征】把两者**联合编码**（一般是相加或拼接后过非线性层）然后经过一层网络和 Softmax，**输出最终的 Token 或 Blank**。
- RNN-T 没有传统的 Attention Decoder。Prediction Network + Joint Network 共同承担"解码"角色，但严格来说**没有 LAS 那样的 Decoder**。

和 LAS 的区别是，是逐帧对齐，不是靠 Attention 软对齐。




Neural Transducer ：
RNN-T + window，RNN-T 在处理第 $t$ 帧时，它**看不到**第 $t+1$ 帧的声音。块内就比较均衡。块内 ENcoder 有理解，所以兼顾了流式处理与上下文理解


MoChA：
Neural Transducer + 可移动 window
**window 大小是固定的，但 window 的位置（起始点）是模型动态决定的**（"伸缩自如"指的是移动位置，而不是窗口尺寸可变）


| 模型                | 输入输出对应关系           | 是否流式 | 输出依赖  |
| ----------------- | ------------------ | ---- | ----- |
| LAS               | 多对多（attention 全局）  | ❌    | ✅     |
| CTC               | T → T（含 Φ）         | ✅    | ❌（独立） |
| RNA               | T → T（含 Φ）         | ✅    | ✅     |
| RNN-T             | 1 输入可出多输出          | ✅    | ✅     |
| Neural Transducer | window 内 attention | ✅    | ✅     |
| MoChA             | window 位置可移动       | ✅    | ✅     |

## 押题答案

**1. LAS 三阶段**：

- **Listen**：Encoder（通常金字塔 BLSTM）将声学特征编码为高层表示，提取内容信息、去除说话人变化和噪声 6。
- **Attend**：每个解码步用当前 Decoder 隐状态查询 Encoder 输出，得到上下文向量 cₜ。
- **Spell**：Decoder 结合上一步 token、隐状态、上下文，自回归生成下一个 token。

**2. CTC 的输出独立问题**：CTC Decoder 是 linear classifier，每帧输出仅由该帧 Encoder 输出决定，不依赖上下文输出 2。后果：相邻帧之间可能不一致 → 出现**重复、结巴**或拼写错误，需要外接语言模型修正。

**3. CTC 解码规则**：先把连续相同的 token 合并为一个，再删除所有 Φ。例如 `ΦddΦeΦeΦpp → d e e p → deep`；`ddΦeeeΦpp → d e p → dep`（注意 Φ 把两段相同 token 隔开就不合并）3。

**4. RNA / RNN-T 的进化**：

- RNA 相比 CTC：让当前输出**依赖于前一个输出 token**（引入循环依赖）2。
- RNN-T 相比 RNA：允许**一个输入向量产生多个 token**（通过反复决策直到输出 ∅ 才前进到下一帧）1。

**5. Neural Transducer 的动机**：LAS 的 attention 必须看到整段序列才能解码 → 不能流式。Neural Transducer 把序列分成固定 **window (chunk)**，attention 只在 window 内部计算 → **既保留 attention 的上下文能力，又支持流式**15。

**6. MoChA vs Neural Transducer**：Neural Transducer 的 window 是**固定切分**的；MoChA 的 window **大小固定但位置由模型动态决定**，可以"滑动"到合适位置 → 对齐更灵活 1。

**7. CTC 解码 `ΦccΦaaΦtt`**：合并重复 → `ΦcΦaΦt` → 去 Φ → **`cat`**。

**8. RNN-T 结构**（文字描述）：

- Encoder：输入，输出声学表示。
- Prediction Network：输入历史已生成 token（不含 ∅），输出语言表示。
- Joint Network： → softmax → 输出下一个 token 或 ∅。若输出 ∅ 则 t+1，否则 u+11。

**9. 三模型对比**：

|维度|LAS|CTC|RNN-T|
|---|---|---|---|
|流式|❌|✅|✅|
|输出依赖|✅|❌|✅|
|对齐方式|全局 soft attention|帧级独立分类|单调对齐 + ∅ 推进|

**10. 实时字幕系统选择**：应选 **RNN-T** 或 **MoChA**。

- **RNN-T**：天然单调流式、输出有依赖、工业界主流（Google 上线）。
- **MoChA**：保留 attention 的精度，且可流式。
- **不选 LAS**：必须看完整段，延迟太大。
- **不选 CTC**：输出独立易出错，需外挂 LM。



# 语言模型

最原始的语言模型就是给一个序列 w₁…wN 计算概率：


$$P (w_1, w_2, ..., w_N) = \prod_{t=1}^{N} P (w_t \mid w_1, ..., w_{t-1})$$

为了解决这个问题，N-gram 提出马尔可夫假设
**“下一个词出现的概率，只跟它前面最近的 $N-1$ 个词有关，再往前的历史统统不管了！”**

$$P (w_t \mid w_1, ..., w_{t-1}) \approx P (w_t \mid w_{t-N+1}, ..., w_{t-1})$$  

 N-gram 模型里存的内容，是**N 元组的统计计数表**（count table），通过最大似然估计（MLE）计算条件概率，算出当前推理所需要的 P。

问题，一是词与词之间无关，二是没有上下文记忆（只有 N 个词 ），三是 OOV 问题，词表很稀疏。



现代语言模型不是用离散词表，而是用 **词向量 / 子词 / token embedding** 表示

把这种先把词，转换为向量的模型，叫Continuous LM

两个例子
- NNLM，词嵌入+linear+softmax。输入仍是固定的 N-1 个词的 embedding，拼接后过线性层+softmax，所以**窗口固定**，无记忆
- RNN LM，词转化为向量后，经过 RNN 模型。

有了听觉模型，语言模型，
我们把他们融合一下，效果更好。

比如你发音 [r aɪ t]，ASR 可能会纠结到底是 right 还是 write。这时候，如果你前面说的是 "You are completely..."，**语言大脑（LM）** 就会跳出来说：“别猜了！根据我读过几十亿句话的经验，这里 99% 是 right！

- Shallow Fusion：两个模型各自训练好，ASR 模型先正常输出下一个词的概率，然后 LM 跳出来，给出他的意见。结果 $y^* = \arg\max (\log P_{LAS}(y) + \lambda \log P_{LM}(y))$，选取得分最高的词输出。
- Deep Fusion，两者输出概率的**前一步**，把 ASR 的 **隐藏层向量（Hidden）** 和 LM 的 **隐藏层向量（Hidden）** 提取出来。喂给新模型，让专家判别
- Cold Fusion：在 ASR 训练之前，先训练好 LM，在 LAS 训练的每一次循环中，都把 LM 算出来的隐藏状态（Hidden），作为**额外的知识**输入给 LAS 的 Decoder

| 维度              | 选项                  |
| --------------- | ------------------- |
| **何时融合（when）**  | 训练时 / 推理时           |
| **在哪融合（where）** | Output 层 / Hidden 层 |

- Shallow Fusion = 推理时 + Output 层
- Deep Fusion = 训练时 + Hidden 层（LM 已预训练）
- Cold Fusion = 训练时 + Hidden 层（LM 预训练 + LAS 从零训）

**A1.**

- 拼接式：数据库巨大、自然度最高（MOS 4.09）但拼接处不自然，灵活性差，难以迁移 。
- 参数式：基于 HMM/DNN，数据需求中等，自然度偏机械（MOS 3.69），灵活性中等 。
- 端到端：训练数据较大，自然度高（MOS 3.82），多说话人/情感迁移最灵活 。

**A2.** `文本 → 文本分析 → 语言特征/音素 → 声学模型(HMM/DNN) → 声学特征(频谱/F0/时长/能量) → 声码器(Vocoder) → 语音波形` 。

**A3.** 输入是 **character（字符序列）**；输出在 **Tacotron V1 是 linear spectrogram**，再用 Griffin-Lim 合成波形；**Tacotron V2 输出 mel-spectrogram**，再用 WaveNet 合成波形 36。

**A4.** TTS 中输入文本与输出音频满足**严格单调对齐**：音素的发音顺序就是音频的时间顺序，不能倒序 。而机器翻译中源语言和目标语言的语序可能不同（如中英），允许重排，因此**不适用**单调对齐约束。

**A5.**
- 典型错误：**skip（漏字）**、**repeat（重复念）**、**attention collapse / drift（注意力漂移到无关位置）**。
- 原因：attention 是软对齐，在长序列上容易学到错误分布，无显式约束保证顺序。
- 解决：用一个 **Duration Predictor** 直接预测每个 phoneme 的帧数 d_i，然后将 phoneme 表征沿时间轴复制 d_i 次，硬性保证顺序与对齐（FastSpeech 系列）。训练时 duration 的 ground-truth 可由已训练 Tacotron 的 attention 矩阵抽取。

**A6.**

- 拼接式直接拼真人语音片段，**音质天然真实**；
- 当时的端到端 vocoder（Griffin-Lim）相位还原差，听感受损；
- 端到端在长句、未登录词、对齐不稳上偶有错误；
- 但端到端在**灵活性、可控性、迁移性**上完胜，因此后续被持续改进（V2 引入 WaveNet 后已超过拼接式）3。

**A7.** 推荐**端到端 + 迁移学习/预训练**路线。理由：

- 拼接式需要数十小时高质量录音库，小语种几乎不可能；
- 参数式需要语言学家做发音词典、上下文相关 HMM 树，工程成本高；
- 端到端只需 (text, audio) 对，且可通过多说话人/跨语言预训练（如 Meta-TTS、XPhoneBERT）显著降低数据需求。
# 语音转换

语音转换的目的是，保留 content，语义，音素，改变**speaker，说话人身份**，或情感，口音等
- **Speaker 转换** → Deep Fake、个性化 TTS
- **Singing Voice Conversion**（歌声转换）
- **Speaking Style**：Emotion、Normal-to-Lombard、**Whisper-to-Normal**（耳语转正常）、歌唱技巧转换（如颤音 vibrato）
- **Improving Intelligibility**：帮助做过发声器官手术的患者恢复语音清晰度
- **Accent Conversion**：用于语言学习


**TTS，Text-to-Speech，是文本到语音；VC，Voice Conversion，是语音到语音。**

训练数据：
- 平行数据：模型可以直接学习同一句话在 A 声音和 B 声音之间如何映射。
- 非平行数据：数据集源说话人和目标说话人的语音内容不一样，难以对齐，需要“特征解耦”

特征解耦的结构是**Content Encoder** ， **Speaker Encoder**，Decoder：把 content 和 speaker 重新合成

**Content Encoder** ，用instance Normalization因为 speaker 信息可能藏在特征分布的均值、方差、能量等统计量里，IN 把这些统计量抹掉，从而让 content representation 更少携带 speaker identity

 L1 / L2 距离：用来约束“像不像”
 L1 = Σ |x_i - y_i|
 L2 = Σ (x_i - y_i)^2
用于算 Loss？

还可以引入Extra Criterion for Training：额外训练准则，使得效果更好

或者说对抗训练？
Extra Criterion 至少包括两类：

1. **Discriminator**：判断生成语音是真实的还是生成的，即 real or generated 1。
2. **Speaker Classifier**：判断语音属于哪个 speaker，即 which speaker 1。

所以 Extra Criterion 可以包括 adversarial loss，也可以包括 speaker classification loss。

更准确地说：

> Discriminator 负责约束生成语音“像真实语音”；Speaker Classifier 负责约束生成语音“像目标说话人”。



Decoder / Generator 生成语音
Discriminator 判断真假
Generator 试图骗过 Discriminator

Content Encoder 生成 content representation
Speaker Classifier 尝试判断 speaker
Content Encoder 尝试让 Speaker Classifier 判断失败


除了特征解耦，对于非平行数据还可以使用**Direct Transformation** 
CycleGAN 就是一个模型。


A → B
生成器 G_AB 输入 A 的语音，输出伪 B 语音：

X_A → G_AB (X_A) = X_B'
然后 B 域判别器判断：
X_B' 到底是真 B 语音，还是生成的假 B 语音？

接着再加入**cycle consistency**：
X_A → G_AB (X_A) → G_BA (G_AB (X_A)) ≈ X_A


A → B → A 后要接近原始 A
B → A → B 后要接近原始 B
这个“接近”通常可以用 L1 loss 或 L2 loss 度量。

## 题 1 答案：什么是 VC？它和 TTS 有什么区别？

Voice Conversion 是一种 speech-to-speech 任务，输入是源语音，输出是转换后的语音，目标是保留语言内容，同时改变说话人身份或其他语音属性 3。

TTS，即 Text-to-Speech，输入是文本，输出是语音；VC，即 Voice Conversion，输入是语音，输出也是语音，因此课件将其归为 Speech-to-Speech Model class 3。

---

## 题 2 答案：VC 中保留什么，改变什么？

VC 中通常保留的是 linguistic content，也就是这句话说了什么、音素内容是什么 3。

VC 可以改变 speaker identity、speaking style、emotion、accent、singing voice、whisper / normal speaking style 等语音属性 34。

例如，把 A 说的“Hello”转换成 B 的声音，但内容仍然是“Hello”，这就是 speaker conversion。

---

## 题 3 答案：平行数据和非平行数据有什么区别？

平行数据指源说话人和目标说话人说的是同一句话或相同文本，因此模型可以直接学习从 A 的语音特征到 B 的语音特征的映射。

非平行数据指源说话人和目标说话人的语音内容不同，无法逐帧或逐句直接对齐，因此不能简单地用 paired reconstruction loss 训练。

非平行数据更困难，因为模型既要保留 source content，又要替换成 target speaker，而没有对应的 ground truth target speech。为了解决这个问题，可以使用 Feature Disentangle 或 Direct Transformation，课件中也把这两部分作为本章重点 3。

## 题 5 答案：Speaker Classifier 的两种作用

第一种作用是在 content disentanglement 中作为 adversarial classifier。它接收 Content Encoder 的输出，并尝试判断该 content representation 来自哪个 speaker；而 Content Encoder 则尝试去除 speaker 信息，让 Speaker Classifier 判断失败。课件中提到 Speaker Classifier 和 encoder 可以迭代学习 5。

第二种作用是在 generated speech constraint 中作为辅助分类器。它接收生成语音或生成声学特征，并判断其属于哪个 speaker；此时 Generator / Decoder 的目标是让 Speaker Classifier 判断为目标说话人，而不是让它失败 1。

所以关键区别是：

- 接在 content representation 上时，classifier 用来逼迫 content 去 speaker。
- 接在 generated speech 上时，classifier 用来逼迫输出像目标 speaker。

## 题 7 答案：什么是 IN？为什么能去 speaker information？

Instance Normalization，简称 IN，是对每个样本、每个 channel 的特征做归一化，使每个 channel 具有 zero mean 和 unit variance 5。

其基本思想是：speaker information 往往与特征的统计量有关，例如均值、方差、能量分布等；IN 把这些统计量标准化，因此可以削弱 speaker identity。课件中明确写到 IN 可以 remove speaker information 5。

课件实验中，使用 IN 时 Speaker Classifier 的准确率为 0.375，不使用 IN 时准确率为 0.658，这说明使用 IN 后 speaker information 更少，分类器更难判断说话人 6。

## 题 10 答案：VC 的应用场景

Voice Conversion 的应用包括：

1. Speaker conversion / voice cloning：把一个人的声音转换成另一个人的声音。
2. Personalized TTS：帮助构建个性化语音合成系统 4。
3. Singing voice conversion：转换歌唱声音 4。
4. Emotion conversion：改变语音中的情感表达 4。
5. Normal-to-Lombard conversion：把正常语音转换为 Lombard style speech 4。
6. Whisper-to-normal conversion：把耳语转换为正常说话风格 4。
7. Improving intelligibility：提高语音清晰度，例如帮助发音器官受损的病人改善可懂度 4。
8. Accent conversion：转换口音，可用于语言学习 4。
