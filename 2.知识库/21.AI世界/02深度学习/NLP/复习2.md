# 一、这一章的主线

这一章只要抓住一句话：

**语音识别不是简单分类，而是把一段连续语音序列转换成一段离散文字序列。**

也就是：

**Speech sequence → Model → Text / Token sequence**

PPT 第 5 页讲得很核心：  
语音输入是一串长度为 **T** 的向量序列，每一帧有维度 **d**；文本输出是一串长度为 **N** 的 token 序列，词表大小为 **V**，而且通常 **T > N**。

你可以这么理解：

人说一句“one punch man”，机器听到的不是三个清楚的单词，而是一长串声波帧。模型要从这些连续信号里判断：哪些声音对应哪些文字。

---

## 先想一个问题

> 为什么语音识别不能简单看成“输入一段音频，分类成一句话”？
 
参考答案：

因为一句话不是一个固定类别。语言可以无限组合，不能把每一句话都当成一个类别。语音识别的输出是一个长度不固定的 token 序列，所以它本质上是一个**序列到序列**问题，而不是普通分类问题。

这个问题非常重要，考试很可能变形考。

---

# 二、第一部分：Token

Token 就是模型输出的基本单位。

语音识别最后不是直接输出“声音”，而是输出一串 token。问题是：**token 选什么？**

PPT 里讲了几类：

## 1. Phoneme 音素

音素是语音里的基本发音单位。

比如英文里：

cat → K AE T  
good → G UH D  
man → M AE N

优点：

它和发音直接相关，适合语音识别。

缺点：

需要发音词典，也就是 lexicon。不同语言、不同口音、不同词的发音规则会比较麻烦。

考试可以这样答：

**Phoneme 是语音层面的基本单位，适合描述发音，但通常需要发音词典支持。**

---

## 2. Grapheme 字符 / 字母

Grapheme 是书写系统里的最小单位。

英文可以是字母，比如 a、b、c。  
中文可以是汉字，比如 “一”“拳”“超”“人”。

优点：

词表小，不需要像 word 那样准备巨大词表。  
中文尤其适合用字作为 token，因为中文不天然依赖空格。

缺点：

字符本身语义不完整，序列会变长，模型需要自己学字符如何组合成词。

---

## 3. Word 词

Word 是以词为单位输出。

比如：

one punch man

输出就是：

one / punch / man

优点：

输出序列短，语义比较完整。

缺点：

词表非常大，会有 OOV，也就是没见过的新词。对于词形变化复杂的语言，word 级别会特别麻烦。

你记住一句：

**Word token 语义强，但词表大；character/grapheme 词表小，但序列长。**

---

## 4. Morpheme 语素

Morpheme 是最小的有意义单位。

比如：

unbreakable = un + break + able

它介于字符和词之间。

优点：

比字符更有意义，比词的词表小。

缺点：

如何切分 morpheme 不一定简单，可能需要语言学知识或统计方法。

---

## 5. Byte 字节

Byte 的特点是语言无关，词表大小固定，比如 UTF-8 中可以看成 256 种取值。

优点：

**language independent**，不太依赖具体语言。

缺点：

序列很长，模型学习难度更大。

---

## 这里再想一个问题

> 如果老师问：“为什么语音识别中 token 的选择很重要？”你怎么答？

参考答案：

因为 token 决定了模型输出空间的大小、输出序列的长度以及是否需要词典等外部资源。比如 word token 语义完整但词表很大，容易出现未登录词；grapheme token 词表小但序列较长；phoneme token 接近发音但需要发音词典。因此 token 选择会影响模型训练难度、识别效果和系统复杂度。

---

# 三、第二部分：Acoustic Feature 声学特征

语音本质上是波形，也就是连续信号。

但模型一般不直接处理原始波形，而是先把语音切成一帧一帧，再提取声学特征。

常见声学特征包括：

**spectrogram、MFCC、filter bank、waveform**

PPT 里也展示了 waveform 到频谱特征的过程。

你可以把它理解为：

原始语音波形太细、太杂，模型不好直接学。  
所以我们先把声音转换成更容易表示发音信息的特征。

也就是：

**speech waveform → acoustic features → neural network**

---

## MFCC 和 Filter Bank 简单理解

不用深挖公式，只要会说：

**MFCC** 是传统语音处理中常用的声学特征，它试图模拟人耳对声音频率的感知。  
**Filter Bank** 保留更多频谱信息，在深度学习语音识别中很常用。

如果考试简单，一般不会让你推公式，重点是知道：

**声学特征是语音信号输入模型前的表示方式。**

---

## 再想一个问题

> 为什么不直接把原始语音波形输入模型，而要提取 acoustic feature？

参考答案：

因为原始波形维度高、变化复杂，直接建模难度较大。声学特征可以把连续语音信号转换成更适合模型处理的时间序列表示，突出发音和频谱信息，降低建模难度，提高语音识别效果。

---

# 四、第三部分：Sequence to Sequence

这一部分是本章主线。

语音识别的问题是：

输入：一长串声学特征  
输出：一串 token

输入和输出长度不同，而且不知道哪几帧声音对应哪个字。

比如：

输入可能有几百帧声学特征。  
输出可能只有几个字：

“one punch man”

这就是典型的：

**sequence to sequence 问题**

---

## RNN / LSTM 的作用

PPT 里讲了 RNN、LSTM、Encoder-Decoder。

RNN 的作用是处理序列：

当前时刻的输入 + 上一个时刻的隐藏状态 → 当前隐藏状态

也就是说，它能记住前面的信息。

但普通 RNN 有长期依赖问题，所以引入 LSTM。  
LSTM 通过门控机制保留重要信息，遗忘不重要信息。

你不用背复杂结构图，只要会说：

**RNN/LSTM 用来处理时间序列，适合语音这种连续帧输入。LSTM 比普通 RNN 更适合建模长距离依赖。**

---

## Encoder-Decoder

Encoder-Decoder 是 Seq2Seq 的经典结构。

**Encoder 编码器**：把输入语音特征序列编码成隐藏表示。  
**Decoder 解码器**：根据编码结果一步步生成输出 token。

流程是：

**x₁, x₂, ..., xT → Encoder → hidden representations → Decoder → y₁, y₂, ..., yN**

考试中你要能说出一句：

**Encoder 负责理解输入序列，Decoder 负责生成输出序列。**

---

## 再想一个问题

> 为什么语音识别需要 Seq2Seq，而不是普通 RNN 分类？

参考答案：

普通分类通常输出一个类别，而语音识别需要输出一个长度可变的 token 序列。同时，语音输入帧数 T 和文本输出长度 N 不相等，也没有明确的一一对齐关系。因此需要 Seq2Seq 模型把变长输入序列映射到变长输出序列。

---

# 五、第四部分：Seq to Seq Model：LAS

PPT 后面重点讲了一个模型：

**LAS：Listen, Attend and Spell**

这个名字很好记：

**Listen = 听**  
**Attend = 注意**  
**Spell = 拼写输出**

---

## 1. Listen：编码语音

Listen 部分就是 Encoder。

它接收声学特征序列，把原始语音帧变成高层表示。

简单说：

**Listen 负责“听懂声音”。**

---

## 2. Attend：注意力机制

Attention 的作用是：

Decoder 在生成每个 token 时，不是只看一个固定向量，而是动态关注输入语音的不同部分。

比如输出第一个字时关注前面的语音帧；输出后面的字时关注后面的语音帧。

所以 attention 解决的是：

**输出 token 和输入语音帧之间的软对齐问题。**

这很容易考。

---

## 3. Spell：生成 token

Spell 就是 Decoder。

它根据 Encoder 表示和 Attention 结果，一个 token 一个 token 地生成文字。

例如：

输入语音：one punch man  
输出 token：o → n → e → ... 或 one → punch → man

取决于 token 设计。

---

## 再想一个问题

> LAS 中 Listen、Attend、Spell 分别对应什么功能？

参考答案：

Listen 对应编码器，用来把声学特征序列编码成高层语音表示；Attend 对应注意力机制，用来在生成每个输出 token 时选择关注输入序列的相关部分；Spell 对应解码器，用来逐步生成最终的文字或 token 序列。

---

# 六、Beam Search 和 Teacher Forcing

这两个点很可能简单考概念。

## 1. Beam Search

Decoder 生成文本时，每一步都有很多可能 token。

如果每一步只选概率最大的一个，可能局部最优，整体不好。

Beam Search 的思路是：

**每一步保留多个候选序列，最后选择整体概率较高的结果。**

例如 beam size = 3，就保留当前最可能的 3 条路径。

考试答法：

**Beam Search 是一种解码策略，用于在生成序列时保留多个高概率候选，避免贪心搜索过早选择错误路径。**

---

## 2. Teacher Forcing

训练 Decoder 时，有两种做法：

一种是用模型上一步预测的 token 作为下一步输入。  
另一种是直接用真实答案中的上一个 token 作为下一步输入。

Teacher Forcing 指的是第二种：

**训练时把真实的上一个 token 喂给模型。**

好处：

训练更稳定，收敛更快。

问题：

训练时用真实历史，测试时只能用模型自己预测的历史，这会造成训练和测试不一致。

---

## 再想一个问题

> Teacher Forcing 的优点和缺点是什么？

参考答案：

Teacher Forcing 的优点是训练时使用真实的上一个 token 作为输入，可以减少错误累积，使模型训练更稳定、收敛更快。缺点是训练阶段和推理阶段不一致，推理时模型只能使用自己预测出的 token，一旦前面预测错误，后续错误可能继续累积。

---

# 七、这一章你必须抓住的重点

这章不用记太多图，重点是这条线：

**语音是连续信号 → 先提取 acoustic feature → 选择 token 作为输出单位 → 因为输入输出长度不同且对齐未知，所以用 Seq2Seq → LAS 用 Listen 编码语音、Attend 对齐信息、Spell 生成文字。**

你把这句话背下来，这章主线就稳了。

# 八、押题与参考答案

## 押题 1：什么是语音识别？

**参考答案：**

语音识别是将语音信号自动转换为文本或 token 序列的技术。它的输入是连续的语音特征序列，输出是离散的文字或 token 序列。由于输入和输出长度通常不同，且二者之间不存在显式对齐关系，因此语音识别通常被建模为序列到序列问题。

---

## 押题 2：为什么语音识别是一个 Sequence to Sequence 问题？

**参考答案：**

语音识别的输入是一串声学特征序列，长度为 T；输出是一串 token 序列，长度为 N。通常 T 大于 N，而且语音帧和文字 token 之间没有明确的一一对应关系。因此，语音识别需要把变长输入序列映射为变长输出序列，所以是 Sequence to Sequence 问题。

---

## 押题 3：语音识别中的 token 有哪些类型？各有什么特点？

**参考答案：**

语音识别中的 token 可以是 phoneme、grapheme、word、morpheme 或 byte。Phoneme 接近发音，但通常需要发音词典；grapheme 词表较小，不需要复杂词典，但序列较长；word 语义完整、输出序列短，但词表很大，容易出现未登录词；morpheme 介于字符和词之间，能够表达一定语义；byte 语言无关，词表固定，但序列更长、建模难度更大。

---

## 押题 4：为什么 word token 不一定适合语音识别？

**参考答案：**

Word token 的优点是语义完整、输出序列较短，但它的问题是词表非常大，而且容易出现训练中没有见过的新词，也就是 OOV。对于词形变化复杂的语言，word 级别的词表会更大，训练和解码难度都会增加。因此，实际语音识别中常常使用字符、子词或音素等更灵活的 token。

---

## 押题 5：什么是 acoustic feature？为什么需要它？

**参考答案：**

Acoustic feature 是从原始语音波形中提取出的声学表示，如 spectrogram、MFCC、filter bank 等。原始波形维度高、变化复杂，直接输入模型会增加学习难度。声学特征能够突出语音中的频谱和发音信息，使模型更容易学习语音和文字之间的关系。

---

## 押题 6：Encoder-Decoder 在语音识别中分别起什么作用？

**参考答案：**

Encoder 用来处理输入的语音特征序列，并将其编码成高层隐藏表示；Decoder 根据 Encoder 的表示逐步生成输出 token 序列。Encoder 主要负责理解输入语音，Decoder 主要负责生成文本结果。

---

## 押题 7：LAS 模型中的 Listen、Attend、Spell 分别是什么意思？

**参考答案：**

LAS 是 Listen, Attend and Spell 的缩写。Listen 表示编码器部分，用来接收并编码声学特征；Attend 表示注意力机制，用来在生成每个 token 时关注输入语音中的相关部分；Spell 表示解码器部分，用来逐步生成文字或 token 序列。

---

## 押题 8：Attention 在语音识别中的作用是什么？

**参考答案：**

Attention 的作用是在解码生成每个 token 时，动态关注输入语音序列中最相关的部分。由于语音帧和输出文字之间没有明确的一一对齐关系，Attention 可以帮助模型学习输入和输出之间的软对齐关系，从而提高序列生成效果。

---

## 押题 9：什么是 Beam Search？

**参考答案：**

Beam Search 是一种序列解码方法。在生成每个 token 时，它不是只保留概率最大的一个结果，而是保留多个高概率候选序列，并在后续步骤中继续扩展这些候选。这样可以减少贪心搜索带来的局部最优问题，提高最终生成序列的质量。

---

## 押题 10：什么是 Teacher Forcing？

**参考答案：**

Teacher Forcing 是序列模型训练中的一种方法。训练 Decoder 时，不使用模型上一步预测出的 token 作为下一步输入，而是使用真实答案中的上一个 token。它可以让训练更稳定、收敛更快，但会造成训练阶段和推理阶段不一致，推理时如果前面预测错误，后续结果可能受到影响。

---

# 九、这一章背诵版

**语音识别是将连续语音信号转换为离散文字或 token 序列的任务。语音输入通常表示为长度为 T 的声学特征序列，输出是长度为 N 的 token 序列，且通常 T 大于 N，二者没有明确对齐关系，因此语音识别是典型的序列到序列问题。语音识别首先需要选择输出 token，如 phoneme、grapheme、word、morpheme 或 byte；然后将原始语音转换成 acoustic feature，如 MFCC、filter bank 或 spectrogram；最后通过 Seq2Seq 模型完成识别。LAS 模型由 Listen、Attend、Spell 三部分组成，分别负责语音编码、注意力对齐和文本生成。**
