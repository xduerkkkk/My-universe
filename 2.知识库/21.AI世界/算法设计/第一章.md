### 🚀 第一批：基础查找与“傻瓜式”排序

这一部分的特点是：逻辑简单，且**选择排序**的性能非常“稳定”（稳定地差，不管给什么数据都一样慢）。

#### 1. 二分查找 (Binary Search)
**覆盖 PPT 页码：** p.10 - p.15

*   **核心前提 (Key Condition):** 输入数组必须是**有序的 (Sorted)**。如果没排序，二分法无效。
*   **算法流程 (Process):**
    1.  定界：`low = 1`, `high = n`。
    2.  循环：只要 `low <= high`，算出中间位置 `mid = floor((low + high) / 2)`。
    3.  比较：
        *   如果 `x == A[mid]`：找到了！返回 `j = mid`。
        *   如果 `x < A[mid]`：说明 `x` 在左半边，`high = mid - 1`。
        *   如果 `x > A[mid]`：说明 `x` 在右半边，`low = mid + 1`。
*   **复杂度分析 (Analysis):**
    *   **比较次数 (Comparisons):** 最多 $\lfloor \log n \rfloor + 1$ 次。
    *   **时间复杂度 (Time Complexity):** $O(\log n)$。这是非常快的。

> **💡 记忆点：** 哪怕有 100 万个数据，二分查找最多也只需要找 20 次左右 ($\log_2{10^6} \approx 20$)。

#### 2. 选择排序 (Selection Sort)
**覆盖 PPT 页码：** p.24 - p.28

*   **核心思想 (Idea):** 每次从剩下的乱序堆里挑一个**最小的**，把它放到已排序部分的末尾。
*   **算法流程 (Process):**
    *   **第 1 轮：** 扫描 $A[1 \dots n]$，找到最小值的下标，把它和 $A[1]$ 交换。
    *   **第 2 轮：** 扫描 $A[2 \dots n]$，找到最小值的下标，把它和 $A[2]$ 交换。
    *   ...
    *   **第 $i$ 轮：** 扫描 $A[i \dots n]$，找到最小值，和 $A[i]$ 交换。
    *   **结束：** 直到 $n-1$ 轮结束。

*   **最好 vs 最坏情况 (Best vs Worst Case):**
    *   **这是考点！** 选择排序是一个“死脑筋”算法。
    *   无论输入数组是已经排好序的（最好），还是逆序的（最坏），还是乱序的，它**都要做完全一样多的比较运算**。它无法利用“已有的顺序”来偷懒。

*   **复杂度硬指标 (Metrics):**
    *   **比较次数 (Comparisons):** 固定是 $\frac{n(n-1)}{2}$。
        *   为什么？第1次比 $n-1$ 次，第2次比 $n-2$ 次... 等差数列求和。
        *   **时间复杂度:** 永远是 **$\Theta(n^2)$** (Quadratic)。
    *   **移动/赋值次数 (Assignments):**
        *   **最好情况 (Best Case):** 数组本来就是有序的。交换 0 次（虽然比较了但没动位置）。赋值次数为 **0**。
        *   **最坏情况 (Worst Case):** 每次都要交换。每次交换需要 3 次赋值 (temp = A[i]; A[i] = A[k]; A[k] = temp)。总共约 **$3(n-1)$** 次。
    *   **空间复杂度 (Space Complexity):** $O(1)$。只需要一个 `temp` 变量，不需要额外数组。

### 🚀 第二批：插入排序 & 归并排序

这一部分的重点在于：**插入排序的“敏感性”**（看人下菜碟）和 **归并排序的“稳定性”**（雷打不动的快）。

#### 3. 插入排序 (Insertion Sort)
**覆盖 PPT 页码：** p.29 - p.35

*   **形象理解：** 就像**打扑克牌抓牌**。
    *   左手里拿着已经排好序的牌（初始时只有1张）。
    *   右手抓一张新牌，从后往前看，插到左手牌里合适的位置。

*   **算法流程 (Process):**
    *   从第 2 个元素开始 ($i=2$ 到 $n$)。
    *   把它存到 `x`。
    *   和前面的元素比较 ($A[i-1] \dots A[1]$)。如果前面的比 `x` 大，就往后挪一位。
    *   直到找到比 `x` 小的位置，把 `x` 插进去。

*   **🔥 核心考点：最好 vs 最坏 (Best vs Worst Case)**
    *   **最好情况 (Best Case):** 数组**已经是升序**的。
        *   **发生什么：** 每次拿新牌，跟前一张一比，“咦，我正好比你大”，直接放在最后。**不用移动，只比较 1 次**。
        *   **比较次数：** $n-1$ 次（就是 $O(n)$）。
        *   **时间复杂度：** **$O(n)$**。
    *   **最坏情况 (Worst Case):** 数组是**降序（逆序）**的。
        *   **发生什么：** 每次拿新牌，发现前面的都比我大，全部都要往后挪，我要插到最前面去。
        *   **比较次数：** $1+2+3+\dots+(n-1) = \frac{n(n-1)}{2}$。
        *   **时间复杂度：** **$O(n^2)$**。
    *   **平均情况 (Average Case):** $O(n^2)$。

> **💡 对比总结：** 如果考题问“给定一个**基本有序**的数组，用哪个排序最快？”，选**插入排序**！(比快排、归并都快，因为它是 $O(n)$)。

#### 4. 自底向上归并排序 (Bottom-Up Merge Sort)
**覆盖 PPT 页码：** p.36 - p.43

*   **注意：** PPT 讲的不是通常的递归法 (Recursive)，而是**自底向上 (Bottom-Up/Iterative)**。这在写代码时不需要递归栈，但逻辑是一样的。

*   **核心思想 (Idea):** **分治法 (Divide and Conquer)** 的变体。
    *   先把相邻的每 **2** 个元素合并成有序组。
    *   再把相邻的每 **4** 个元素合并。
    *   再 **8** 个... 直到整个数组合并完成。

*   **算法流程 (Process):**
    *   设置步长 $t = 1, 2, 4, 8 \dots$
    *   当 $t < n$ 时：
        *   把数组切成一段一段，每段长度 $2t$。
        *   对每一段里的两个子序列（长度为 $t$）进行 **Merge** 操作。

*   **复杂度分析 (Analysis):**
    *   **最好/最坏/平均：** 统统都是 **$O(n \log n)$**。
        *   不管数组多乱，它都要一层一层合并，雷打不动。
    *   **比较次数 (Comparisons):** 介于 $(n \log n)/2$ 和 $n \log n$ 之间。
    *   **赋值次数 (Assignments) (PPT p.43 考点):** **$2n \log n$**。
        *   *解释：* 每一层合并都需要把 $n$ 个元素搬到辅助数组 $B$，再搬回 $A$，所以是 $2n$。一共有 $\log n$ 层。
    *   **空间复杂度 (Space Complexity) (PPT p.58):** **$O(n)$**。
        *   *解释：* 归并排序最大的缺点！它需要一个和原数组一样大的辅助数组 $B$ 来暂存数据。而选择和插入排序只需要 $O(1)$。


你的两个回答都非常准确！💯
1.  **场景题：** **插入排序**最快。因为它能利用“基本有序”这个特性，接近 $O(n)$。而归并/选择都很死板。
2.  **判断题：** **False**。$n \log n$ 远小于 $n^2$。

下面为你**硬核推导** Bottom-Up Merge Sort (自底向上归并排序) 的所有复杂度。
我们要用到 **PPT p.36-43** 的内容。

### 核心逻辑架构：层级 (Passes)

要算复杂度，首先得知道这个算法“跑了几轮”。
Bottom-Up 的逻辑是：步长 $t$ 每次翻倍 ($1, 2, 4, 8, \dots, n$)。
*   第 1 轮：$t=1$ (2个一组归并)
*   第 2 轮：$t=2$ (4个一组归并)
*   第 3 轮：$t=4$ (8个一组归并)
*   ...
*   第 $k$ 轮：$t=n/2$ (整个数组归并)

**结论：** 总共有 **$\log_2 n$** 轮 (Passes)。
*(比如 $n=8$，需要 $t=1, 2, 4$ 共 3 轮，$\log_2 8 = 3$)*

---

### 推导 1：赋值次数 (Assignments) —— 精确推导
**PPT p.43 结论：Exactly $2n \log n$**

让我们看 **PPT p.19** 的代码 `MERGE` 函数，这是每一轮里发生的具体操作：

1.  **一轮里面发生了什么？**
    在一轮（Pass）中，我们需要把整个数组 $A$ 的 $n$ 个元素都过一遍。
    *   **动作 A：** 比较大小后，把元素从数组 $A$ 搬家到辅助数组 $B$ (代码第4行或第7行)。
        *   这里每个元素都要搬一次。共 **$n$** 次赋值。
    *   **动作 B：** 归并完这一段后，把元素从辅助数组 $B$ 搬回家到 $A$ (代码第15行)。
        *   这里每个元素又要搬一次。共 **$n$** 次赋值。

2.  **汇总：**
    *   每一轮的赋值次数 = $n (\text{搬去} B) + n (\text{搬回} A) = \mathbf{2n}$。
    *   总轮数 = $\log_2 n$。
    *   **总赋值次数** = (每轮次数) $\times$ (轮数) = $2n \times \log_2 n = \mathbf{2n \log n}$。

---

### 推导 2：比较次数 (Comparisons) —— 范围推导
**PPT p.42 结论：Between $(n \log n)/2$ and $n \log n$**

这里的关键在于：**合并两个有序数组时，到底要比几次？**
假设我们要合并两个长度为 $L$ 的有序数组（总长度 $2L$）：

*   **最坏情况 (Worst Case):**
    *   比如 `[1, 3, 5]` 和 `[2, 4, 6]`。
    *   我们要比到其中一个数组**只剩最后一个元素**为止。
    *   比较次数 $\approx$ 总元素个数 $2L$。
    *   **推导到整轮：** 这一轮要把 $n$ 个元素都归并完，所以最坏比较次数是 **$n$** 次。
    *   **总最坏比较：** $n \times \text{轮数} = \mathbf{n \log n}$。

*   **最好情况 (Best Case):**
    *   比如 `[1, 2, 3]` 和 `[4, 5, 6]`。
    *   1比4(取1), 2比4(取2), 3比4(取3)。左边空了，右边直接接上去，不用比了。
    *   比较次数 = 左边数组长度 = $L$。也就是总长度的一半。
    *   **推导到整轮：** 这一轮虽然处理了 $n$ 个元素，但只需要比 **$n/2$** 次。
    *   **总最好比较：** $(n/2) \times \text{轮数} = \mathbf{\frac{1}{2} n \log n}$。

---

### 推导 3：空间复杂度 (Space Complexity)
**PPT p.58 结论：$\Theta(n)$**

*   **原因：**
    *   你需要一个辅助数组 $B$ (代码里叫 `B`)。
    *   为了能装下所有元素，$B$ 的大小必须和 $A$ 一样大，也就是 $n$。
    *   除此之外只需要几个变量 `s, t, k` ($O(1)$)。
    *   **结论：** 主要开销是数组 $B$，所以是 $O(n)$。

| 维度                   | 推导核心                              | 结果 (复杂度)            |     |
| :------------------- | :-------------------------------- | :------------------ | --- |
| **轮数 (Passes)**      | $t$ 每次翻倍                          | $\log n$            |     |
| **赋值 (Assignments)** | 搬去 $B$ 再搬回 $A$ ($2n$) $\times$ 轮数 | **$2n \log n$**     |     |

| **时间 (Time)**        | 比较次数是主导                           | **$O(n \log n)$**   |     |
|                      |                                   |                     |     |

### 🏰 堡垒一：复杂度符号 ($O, \Omega, \Theta$)
**覆盖 PPT 页码：** p.48 - p.55

别被数学符号吓到，你只需要记住三个“代号”：

1.  **$O$ (Big-O) —— 上界 (Upper Bound)**
    *   **代号：** $\le$ (小于等于)
    *   **含义：** 算法运行时间**最坏**也就是这样了，不会更差。
    *   *例子：* $100n = O(n^2)$ 是对的（因为 $n$ 比 $n^2$ 小），$100n = O(n)$ 也是对的。

2.  **$\Omega$ (Omega) —— 下界 (Lower Bound)**
    *   **代号：** $\ge$ (大于等于)
    *   **含义：** 算法运行时间**最少**也要这么多，不可能更快。
    *   *例子：* $n^2 = \Omega(n)$ 是对的。

3.  **$\Theta$ (Theta) —— 确界 (Tight/Exact Bound)**
    *   **代号：** $=$ (等于，或者叫“同阶”)
    *   **含义：** 既是上界又是下界，卡得死死的。
    *   *例子：* $2n^2 + 100 = \Theta(n^2)$。

> **🌟 必考定理 (PPT p.52):**
> $f(n) = \Theta(g(n))$ **当且仅当 (if and only if)** $f(n) = O(g(n))$ **且** $f(n) = \Omega(g(n))$。
> *(人话：如果一个人既不比你高，也不比你矮，那他肯定和你一样高。)*

### 🏰 堡垒二：空间复杂度 (Space Complexity)
**覆盖 PPT 页码：** p.56 - p.58

*   **定义：** 算法运行过程中，**除了存输入数据以外**，还需要额外借多少内存空间 (Extra Space)。

*   **对比 (重点背诵 PPT p.58):**
    *   **Selection Sort (选择排序):** $\Theta(1)$。
        *   *原因：* 只需要一个 `temp` 变量来交换，不用借新数组。
    *   **Insertion Sort (插入排序):** $\Theta(1)$。
        *   *原因：* 同上，在原数组上腾挪，不需要新地盘。
    *   **Merge Sort (归并排序):** $\Theta(n)$。
        *   *原因：* 必须借一个和原数组一样大的 `B` 数组来暂存合并后的结果。**这是归并排序最大的缺点。**

### 🏰 堡垒三：摊还分析 (Amortized Analysis)
**覆盖 PPT 页码：** p.63 - p.65

这玩意儿听着高级，其实就是**“拉平了算账”**。
有些操作偶尔很慢（比如扩容、大清理），但平时很快。如果只看最坏情况（很慢的那一次），太悲观了。我们要算**平均每次**花多少时间。

**🔥 PPT p.65 经典案例 (必看!)**
考试如果考摊还分析，大概率直接用这个例子（双向链表操作）：

*   **规则：**
    *   输入一串数字。
    *   如果是**奇数 (Odd)**：追加到链表末尾。（操作耗时 1）
    *   如果是**偶数 (Even)**：追加到末尾，**然后删除链表里所有的奇数**。（操作耗时 1 + 删除数量）

*   **分析：**
    *   乍一看，碰到偶数时，可能要删除前面 10000 个奇数，最坏情况是 $O(n)$？
    *   **摊还视角：**
        *   每个奇数，**进**链表 1 次。
        *   每个奇数，最多被**删**出链表 1 次（删了就没了，不会诈尸）。
        *   所以，不管中间怎么折腾，总的操作次数 $\le$ 进的次数 + 出的次数 $\le 2n$。
    *   **结论：** 平均摊还到每一步，时间复杂度是 **$O(1)$**。

我们还是利用 **PPT (Chapter 1)** 里的原版伪代码，把这 4 个核心算法的“逻辑骨架”拆解一遍。请务必把**变量名的含义**和**循环边界**记熟！

### 1. 二分查找 (Binary Search)
**📍 PPT Page 12**
**考点预警：** `mid` 的计算、循环条件 `low <= high`、以及左右边界的移动 (`mid+1` / `mid-1`)。

```text
1. low <- 1; high <- n; j <- 0;
2. while (low <= high) and (j = 0)   <-- 考点：为什么是 <=？因为只剩一个元素也要检查。
3.    mid <- floor((low + high) / 2);
4.    if x = A[mid] then j <- mid;   <-- 找到了，记录位置
5.    else if x < A[mid] then high <- mid - 1;  <-- 在左半边，砍掉右边
6.    else low <- mid + 1;           <-- 在右半边，砍掉左边
7. end while;
8. return j;
```
*   **一定要背：** 更新边界时，**一定要加 1 或减 1**。如果不加减（写成 `high <- mid`），当剩两个数时会死循环！

---

### 2. 选择排序 (Selection Sort)
**📍 PPT Page 25**
**考点预警：** 双重循环的边界，交换发生的时机。

```text
1. for i <- 1 to n-1          <-- 外层：决定当前要确定第几个位置（只需做到 n-1，最后一个自动归位）
2.    k <- i;                 <-- 假设当前位置 i 就是最小的，记下标为 k
3.    for j <- i+1 to n       <-- 内层：从后面找有没有比 A[k] 更小的
4.       if A[j] < A[k] then k <- j;  <-- 发现了更小的！更新 k，注意只记录下标，不交换
5.    end for;
6.    if k != i then interchange A[i] and A[k]; <-- 考点：找到一圈后，才做一次交换
7. end for;
```
*   **一定要背：** 交换动作 (`interchange`) 是在**内层循环结束之后**才做的，不是发现一个换一个（那样就变成冒泡了）。

---

### 3. 插入排序 (Insertion Sort)
**📍 PPT Page 32**
**考点预警：** `while` 循环的两个条件（还没到头 且 前面的数太大）。

```text
1. for i <- 2 to n            <-- 从第2张牌开始摸（第1张默认有序）
2.    x <- A[i];              <-- 把这张牌拿在手里 (x)
3.    j <- i - 1;             <-- 准备和左手里的牌比较
4.    while (j > 0) and (A[j] > x)  <-- 考点：只要没比到头，且前面的牌比 x 大
5.       A[j+1] <- A[j];      <-- 把大牌往后挪一格 (Shift)
6.       j <- j - 1;          <-- 继续往前看
7.    end while;
8.    A[j+1] <- x;            <-- 考点：挪出空位了，把 x 插进去
9. end for;
```
*   **一定要背：** 它是**移位 (Shift)** 而不是交换 (Swap)。第 8 行填空很容易错填成 `A[j]`，记得是 `j+1`，因为第 6 行多减了一次。

---

### 4. 自底向上归并排序 (Bottom-Up Merge Sort) —— 🔥 最难代码
**📍 PPT Page 40**
**考点预警：** 变量 `s` 和 `t` 的含义，以及复杂的下标计算。

```text
1. t <- 1;                    <-- t 的含义：当前已经排好序的子序列长度 (初始为1)
2. while t < n                <-- 只要子序列长度还没覆盖整个数组
3.    s <- t; t <- 2*s; i <- 0; <-- 考点：s是旧长度，t翻倍变成新合并后的长度
4.    while i + t <= n        <-- 只要还能凑出一对完整的 (长度s + 长度s)
5.       MERGE(A, i+1, i+s, i+t); <-- 合并前一半和后一半
6.       i <- i + t;          <-- 跳到下一对
7.    end while;
8.    if i + s < n then MERGE(A, i+1, i+s, n); <-- 考点：处理“落单”的尾巴
9. end while;
```
*   **一定要背：** 
    *   **Loop 2:** 外层循环控制步长翻倍 (`t <- 2*s`)。
    *   **Loop 4:** 内层循环横向扫描数组，成对合并。
    *   **Line 8:** **尾巴处理**。比如数组长 10，步长 4。合并了 `[1..4]` 和 `[5..8]`，还剩 `9, 10`。这时候 `i+s` (8+4=12) 越界了，进不了 `while`，需要 Line 8 来把最后这点剩饭处理一下。
