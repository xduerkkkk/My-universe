### 第一阶段：基数排序与递归生成排列

#### 1. 基数排序 (Radix Sort) —— 考点：LSD 顺序
**覆盖 PPT：** p.5 - p.11

*   **核心逻辑：** 这种排序不是基于比较的，而是基于**“分发” (Distribute)**。
*   **关键英文术语：**
    *   **Least Significant Digit (LSD):** 最低有效位（即个位）。PPT 强调必须先从 LSD 开始分发 (p.6)。
    *   **Lexicographically:** 词典序。
    *   **Coalesced:** 合并。分发到 10 个桶（0-9）后，按顺序把它们收回来连在一起 (p.7)。
*   **流程：**
    1.  按**个位**分桶，按 0-9 顺序收回。
    2.  按**十位**分桶，按 0-9 顺序收回。 
    3.  ...直到最高位 $k$。
*   **复杂度 (p.11)：**
    *   时间：$\Theta(n)$ (准确说是 $\Theta(k \cdot n)$，$k$ 是位数)。
    *   空间：$\Theta(n)$。
*   **押题点：** 可能会给你 5 个数字（如 p.8），让你画出**第一轮（个位排序后）**或第二轮的结果。



#### 2. 生成排列 (Generating Permutations) —— 考点：递归形式
**覆盖 PPT：** p.12 - p.16

老师强调要记住这个递归形式，这个算法非常经典（**交换 -> 递归 -> 换回来**）。

*   **关键英文术语：**
    *   **Permutations:** 排列。
    *   **Interchange / Swap:** 交换。
*   **算法核心逻辑 (p.14)：**
    为了生成所有排列，我们让每一个元素都有机会站在“第一位”，然后递归去搞定剩下的 $n-1$ 个。

**必须要背下的代码逻辑（伪代码翻译）：**
```text
perm(m) 
  if m = n:  // 递归出口
    output P[1...n]
  else:
    for j <- m to n:
      interchange P[j] and P[m] // 把第 j 个元素换到当前“第一位” (m位置)
      perm(m + 1)               // 递归生成后面部分的排列
      interchange P[j] and P[m] // 【重要】Backtracking 换回来，恢复现场
```
*   **复杂度 (p.16)：**
    *   时间：$\Theta(n \cdot n!)$ (因为有 $n!$ 种排列，每种输出耗时 $n$)。
    *   空间：$\Theta(n)$ (递归栈深度)。
*   **押题点：** 填空题。最喜欢挖空的地方是 `perm(m+1)` 和第二个 `interchange`。



好，我们进入第二阶段！这一块有**两个绝对的必考点**：一个是寻找多数元素的“检查步骤”，另一个是线性时间选择（寻找第 $k$ 小）的“神奇数字 5”。

### 第一部分：寻找多数元素 (Finding Majority Element)
**覆盖 PPT：** p.17 - p.21

#### 1. 什么是多数元素？
*   **定义：** 在一个长度为 $n$ 的数组中，出现次数 **超过 $\lfloor n/2 \rfloor$**（即超过一半）的那个数。
*   **注意：** 有时候数组里根本没有多数元素（比如 `1, 2, 3`）。

#### 2. 核心算法：摩尔投票法 (Moore's Voting Algorithm)
PPT 讲得比较学术，我给你换个**“打擂台”**或者**“极限一换一”**的讲法，秒懂：

*   **逻辑：**
    *   我们把不同的数字看作不同的帮派。
    *   **规则：** 只要两个**不一样的数字**碰面，它俩就**同归于尽**（抵消）。
    *   **结局：** 因为多数元素的人数超过了一半，所以就算它跟所有其他帮派的人一换一地死磕，**最后活在擂台上的，肯定还是多数元素**（如果有的话）。

*   **算法流程 (Candidate 过程)：**
    1.  `count = 0`，`candidate = 无`。
    2.  遍历数组：
        *   如果 `count == 0`：当前没人站擂台，我站上去！(`candidate = me`, `count = 1`)
        *   如果 `count > 0`：
            *   如果是友军（和我一样）：`count++` (声势壮大)。
            *   如果是敌军（和我不同）：`count--` (同归于尽，一个换一个)。

#### 3. 🔥 考试陷阱：为什么需要“检查步骤”？(PPT p.20)
这是老师强调的重点！

**问题：** 摩尔投票法第一轮跑完，留在 `candidate` 里的那个数，**一定是多数元素吗？**
**答案：不一定！它只是一个“候选人”！**

**反例 (PPT p.20)：**
数组：`4 4 4 1 2 3 5` ($n=7$，一半是 3.5)
1.  前三个 4：`count` 涨到 3。
2.  遇到 1, 2, 3：`count` 减减减，变成 0。
3.  遇到 5：`count` 为 0，5 上台。`candidate` 变成 5。
4.  **结局：** 算法告诉你候选人是 5。但 5 只出现 1 次，根本不是多数元素（真正的多数元素其实是 4，但在前面的内耗中死光了）。

**✅ 必背解法：检查步骤 (Verify)**
在第一轮找出 `candidate` 之后，**必须**再遍历一次数组：
1.  专门数一下这个 `candidate` 到底出现了几次。
2.  **判断：** 如果 `次数 > n/2`，Return 它。否则，Return None (不存在)。

> **考试怎么考？**
> 1.  给你一个数组，让你模拟 `count` 的变化过程。
> 2.  问你：这个算法的时间复杂度是多少？
>     *   **答案：** $\Theta(n)$ (扫两遍，还是线性)。
> 3.  问你：为什么要扫第二遍？
>     *   **答案：** Because the first pass only guarantees finding a **candidate**. If no majority element exists, the candidate might be a false positive. (第一遍只能找候选，如果不存在多数元素，候选是假的)。

### 第二部分：分治法 (Divide and Conquer)

这里有两个算法：**Select (找第 k 小)** 和 **Quicksort (快排)**。

#### 1. 线性时间选择 (Selection / Finding kth Smallest)
**覆盖 PPT：** p.29 - p.36

*   **问题：** 在乱序数组里找第 $k$ 小的数（比如找中位数）。
*   **笨办法：** 先排序 $O(n \log n)$，再取第 $k$ 个。太慢。
*   **牛办法 (Select 算法)：** 即使最坏情况也能做到 **$\Theta(n)$**。

**关键考点：神奇的“5” (Median of Medians)**
PPT p.33 展示了这个复杂的步骤，考试一般问**流程逻辑**或**复杂度**：

1.  **分组：** 把数组每 **5** 个元素分一组 (Divide into groups of 5)。
2.  **找中位数：** 每组找中位数。
3.  **找中位数的中位数：** 把上面那堆中位数拿出来，再找它们的中位数，叫 $mm$ (median of medians)。
4.  **划分 (Partition)：** 用这个 $mm$ 作为基准 (Pivot)，把数组分成三份：$<mm$, $=mm$, $>mm$。
5.  **递归：** 看 $k$ 落在哪个区间，就去哪个区间递归找。

**押题点：**
*   **Q:** 为什么要“5个一组”找中位数的中位数？直接随便选一个不行吗？
*   **A:** 为了保证划分的平衡性 (Guarantees a good split)。即使在最坏情况下，也能扔掉至少 30% 的数据。这保证了时间复杂度是 **$\Theta(n)$**。
*   **对比：** 如果随机选基准（Randomized Select），平均是 $O(n)$，但最坏是 $O(n^2)$。PPT 讲的这个“5个一组”的方法是**确定性 $\Theta(n)$** (PPT p.36)。

---

#### 2. 快速排序 (Quicksort)
**覆盖 PPT：** p.37 - p.42

*   **核心逻辑：**
    *   选一个 **Pivot** (基准，PPT里选的是第一个元素 `A[low]`)。
    *   **Partition (划分):** 也就是 PPT 里的 `SPLIT` 算法。把比它小的放左边，比它大的放右边。
    *   递归处理左右两边。

*   **复杂度 (必考背诵):**
    *   **Best Case:** $\Theta(n \log n)$ (每次都切得很均匀)。
    *   **Average Case:** $\Theta(n \log n)$。
    *   **Worst Case:** **$\Theta(n^2)$**。
        *   *什么时候最坏？* 数组已经**有序**（或逆序），且每次总是选第一个元素当基准。这样每次只能切掉 1 个元素。
    *   **Space Complexity (PPT p.40 特别点):**
        *   PPT 写的是 **$\Theta(1)$**。
        *   *注：* 这是指 `SPLIT` 函数本身的辅助空间。虽然递归需要栈空间($\log n$ 到 $n$)，但既然 PPT p.40 明确写了 "The only extra space used is ... local variables. Therefore $\Theta(1)$"，**考试请按 PPT 写 $\Theta(1)$**。

### 先补课：为什么快排选第一个元素遇到有序数组是 $O(n^2)$？

这里我给你一个极简的解释，帮你扫清障碍：

*   **快排的理想情况：** 像切西瓜，一刀下去，左右两半**均匀**。每次数据量减半，深度是 $\log n$。
*   **快排的最坏情况：** 像削铅笔，每次只切下来一点点。
    *   数组：`[1, 2, 3, 4, 5]`。
    *   **第1刀**：选 `1` 做基准。比它小的没人的，比它大的有 `[2, 3, 4, 5]`。你只排好了一个 `1`，还剩 4 个。
    *   **第2刀**：选 `2` 做基准。剩 `[3, 4, 5]`。
    *   **后果**：你本来想分治（Divide），结果没分掉，每次只减少一个问题规模。$n + (n-1) + \dots + 1$，这就是典型的 **$O(n^2)$**。

### 1. 最长公共子序列 (LCS)
**覆盖 PPT：** p.46 - p.53

*   **问题：** 找两个字符串最长的公共部分（顺序要一致，但可以不连续）。比如 `zxyxyz` 和 `xyyzx`。
*   **必背公式 (Recurrence) - PPT p.48**
    这个公式必须能默写，填表全靠它：
    $$
    L[i, j] = 
    \begin{cases} 
    0 & \text{if } i=0 \text{ or } j=0 \\
    L[i-1, j-1] + 1 & \text{if } a_i = b_j \text{(字符相等)} \\
    \max(L[i-1, j], L[i, j-1]) & \text{if } a_i \neq b_j \text{(字符不等)}
    \end{cases}
    $$

*   **填表口诀 (怎么做题)：**
    画一个表格，行是字符串 A，列是字符串 B。
    1.  **撞衫了（字符相等 $a_i == b_j$）：**
        *   看**左上角**的格子，数值 **+1**。
        *   *含义：* 既然这一位大家都有，那就把这一位续在之前的最长序列后面。
    2.  **撞车了（字符不等 $a_i \neq b_j$）：**
        *   看**左边**和**上面**的格子，谁大选谁。
        *   *含义：* 这一位配不上，那就继承之前最好的结果。

*   **复杂度 (PPT p.53)：**
    *   时间：$\Theta(nm)$ (填满 $n \times m$ 的格子)。
    *   空间：$\Theta(\min\{n, m\})$ (如果只求长度，可以优化空间；如果不优化就是 $\Theta(nm)$)。

### 2. Floyd 算法 (全对全最短路径)
**覆盖 PPT：** p.56 - p.64

*   **问题：** 图里所有点到所有点的最短路径。
*   **核心逻辑 (矩阵更新)：**
    *   我们有 $n$ 个点。
    *   我们要做 $n$ 轮迭代。第 $k$ 轮的意思是：**“如果我们允许经过节点 $k$ 中转，路会不会变短？”**

*   **必背公式 (PPT p.60)：**
    $$D_k[i, j] = \min \{ D_{k-1}[i, j], \quad D_{k-1}[i, k] + D_{k-1}[k, j] \}$$
    *   **$D_{k-1}[i, j]$**: 老路（不经过 $k$）。
    *   **$D_{k-1}[i, k] + D_{k-1}[k, j]$**: 新路（从 $i$ 走到 $k$，再从 $k$ 走到 $j$）。

*   **填表/计算题押题：**
    老师可能会给你一个 $3 \times 3$ 的矩阵（如 PPT p.61），让你求更新后的矩阵。
    *   **技巧：**
        *   在第 $k$ 轮迭代时，**第 $k$ 行** 和 **第 $k$ 列** 的数值是**永远不会变**的（因为从 $k$ 到 $k$ 距离为 0）。
        *   你只需要检查其他格子：$D[i,j]$ 能不能被 $D[i,k] + D[k,j]$ 变小？

*   **复杂度 (PPT p.64)：**
    *   时间：$\Theta(n^3)$ (三层循环：$k, i, j$)。
    *   空间：$\Theta(n^2)$ (存矩阵)。

### 3. 0/1 背包问题 (The Knapsack Problem)
**覆盖 PPT：** p.65 - p.73

*   **问题：** 包容量 $C$，一堆东西有重量 $s_i$ 和价值 $v_i$，怎么装价值最大？
*   **注意：** 每个东西要么装(1)，要么不装(0)，不能切开装。

*   **必背公式 (PPT p.69)：**
    $$
    V[i, j] = 
    \begin{cases} 
    V[i-1, j] & \text{if } j < s_i \text{ (装不下)} \\
    \max \{ V[i-1, j], \quad V[i-1, j-s_i] + v_i \} & \text{if } j \ge s_i \text{ (能装下，选还是不选？)}
    \end{cases}
    $$
    *   $V[i, j]$ 意思是：只考虑前 $i$ 个物品，包容量为 $j$ 时的最大价值。

*   **填表逻辑 (必考大题)：**
    1.  表头：列是容量 $0 \dots C$，行是物品 $1 \dots n$。
    2.  第一行（没有物品）：全是 0。
    3.  第一列（容量为 0）：全是 0。
    4.  **填格子 $V[i, j]$：**
        *   看看上面的格子 $V[i-1, j]$ （不拿 $i$ 的价值）。
        *   看看“回头”的格子 $V[i-1, j-s_i] + v_i$ （拿了 $i$，剩下容量去上面找最大值，再加上 $i$ 的价值）。
        *   两个比一下，填大的。

*   **复杂度 (PPT p.73)：**
    *   时间：$\Theta(nC)$。
    *   空间：$\Theta(C)$ (可以优化成一行) 或 $\Theta(nC)$。
