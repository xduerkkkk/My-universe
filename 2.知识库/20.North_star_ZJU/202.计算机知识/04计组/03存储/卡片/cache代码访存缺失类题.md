# 1 ![[_attachments/image/cache代码访存类题-1788340753535.jpeg]]

做这种题，**第一步永远是先提炼出硬件参数和访存特征**。
在考场上，**“逻辑块号映射法（图表法）”是速度最快、最不易出错的标准解法**；而**“地址切分法”是底层的原理验证法**。下面为你完整展示这两种方法。

---

### 第一步：统一提炼硬件参数与访存特征（两法通用）

#### 1. 硬件参数拆解
* **块大小** $= 8\text{ B}$。
* **Cache 组数**：
  $$\text{总行数} = \frac{64\text{ B}}{8\text{ B}} = 8\text{ 行}$$
  $$\text{Cache 组数} = \frac{8\text{ 行}}{2\text{ 路}} = 4\text{ 组} \quad (\text{组号为 } 0, 1, 2, 3)$$
* **每个 Cache 块能装几个元素**：
  每个 `int` 占 $4\text{ B}$，故 **$1\text{ 块} = 8\text{ B} / 4\text{ B} = 2\text{ 个 } \texttt{int}$**。

#### 2. 数组在主存中的分布
数组 `a[18]` 共 18 个元素，占用 $18 \times 4\text{ B} = 72\text{ B}$，共划分占用 **9 个主存块（块 0 ~ 块 8）**：
* 块 0：`a[0], a[1]` $\to$ 映射到组号 $0 \pmod 4 = \mathbf{0}$
* 块 1：`a[2], a[3]` $\to$ 映射到组号 $1 \pmod 4 = \mathbf{1}$
* 块 2：`a[4], a[5]` $\to$ 映射到组号 $2 \pmod 4 = \mathbf{2}$
* 块 3：`a[6], a[7]` $\to$ 映射到组号 $3 \pmod 4 = \mathbf{3}$
* 块 4：`a[8], a[9]` $\to$ 映射到组号 $4 \pmod 4 = \mathbf{0}$
* 块 5：`a[10], a[11]` $\to$ 映射到组号 $5 \pmod 4 = \mathbf{1}$
* 块 6：`a[12], a[13]` $\to$ 映射到组号 $6 \pmod 4 = \mathbf{2}$
* 块 7：`a[14], a[15]` $\to$ 映射到组号 $7 \pmod 4 = \mathbf{3}$
* 块 8：`a[16], a[17]` $\to$ 映射到组号 $8 \pmod 4 = \mathbf{0}$

#### 3. 访存次数特征
代码行：`a[j] = a[j] + 3;`
* 每个元素经历 **1 次读（Read）+ 1 次写（Write）**。
* 单轮内层循环访存：$18 \times 2 = 36\text{ 次}$。
* 外层循环 4 轮，**总访存次数** $= 4 \times 36 = \mathbf{144\text{ 次}}$。
* **写命中规律**：由于读和写紧接着发生，读操作将块调入 Cache 后，紧接着的写操作**必定是写命中（Write Hit）**。

---

### 方法一：逻辑块号映射法（推荐考场使用）

这种方法的核心是**按“组”观察容量竞争**：
每组只有 **2 个槽位（2 路）**：
* **组 1、2、3**：各自只映射了 **2 个主存块**（组 1 映射块 1, 5；组 2 映射块 2, 6；组 3 映射块 3, 7）。
  $\Rightarrow$ **容量足够，装满后永远不会发生替换冲突！**
* **组 0**：映射了 **3 个主存块（块 0, 4, 8）**。
  $\Rightarrow$ **容量不足（3 个块抢 2 个槽位），会不断触发 LRU 替换淘汰！**

#### 跟踪每轮循环的 Miss 情况：

#### 【第 1 轮循环 ($i=0$)】（冷启动阶段）
* 组 1、2、3：首次访问块 1, 2, 3, 5, 6, 7 时各发生 1 次 Miss（共 **6 次 Miss**），随后全部常驻 Cache。
* 组 0 的演变过程：
  1. 读 `a[0]` (块 0) $\to$ **Miss** $\to$ 组 0: `[块0]`
  2. 读 `a[8]` (块 4) $\to$ **Miss** $\to$ 组 0: `[块0, 块4]`（已满）
  3. 读 `a[16]` (块 8) $\to$ **Miss** $\to$ LRU 淘汰最久未用的**块 0** $\to$ 组 0: `[块4, 块8]`
* **第 1 轮总 Miss 次数** $= 6 + 3 = \mathbf{9\text{ 次}}$。
* 第 1 轮结束时组 0 状态：`[块4(老), 块8(新)]`。

#### 【第 2 轮循环 ($i=1$)】
* 组 1、2、3：所有块都在 Cache 中，**0 次 Miss**。
* 组 0 的演变过程：
  1. 读 `a[0]` (块 0) $\to$ **Miss**（块 0 不在） $\to$ 淘汰最老的**块 4** $\to$ 组 0: `[块8(老), 块0(新)]`
  2. 读 `a[8]` (块 4) $\to$ **Miss**（块 4 不在） $\to$ 淘汰最老的**块 8** $\to$ 组 0: `[块0(老), 块4(新)]`
  3. 读 `a[16]` (块 8) $\to$ **Miss**（块 8 不在） $\to$ 淘汰最老的**块 0** $\to$ 组 0: `[块4(老), 块8(新)]`
* **第 2 轮总 Miss 次数** $= \mathbf{3\text{ 次}}$。
* 第 2 轮结束时组 0 状态：`[块4(老), 块8(新)]`（状态与第 1 轮结束完全相同，形成周期）。

#### 【第 3、4 轮循环 ($i=2, 3$)】
* 进入稳定循环周期，每轮都是组 1、2、3 全命中，组 0 发生 **3 次 Miss**。
* 第 3 轮：**3 次 Miss**；第 4 轮：**3 次 Miss**。

### 方法二：严格物理地址二进制切分法（原理验证）

#### 1. 地址字段划分
* 主存容量 $= 64\text{ B} \times 256 = 16384\text{ B} = 2^{14}\text{ B} \implies$ **主存地址共 14 位**。
* 块大小 $= 8\text{ B} = 2^3\text{ B} \implies$ **块内偏移（Offset）占 3 位**（低 0~2 位）。
* 组数 $= 4 = 2^2 \implies$ **组号（Set Index）占 2 位**（第 3~4 位）。
* **主存标记（Tag）** $= 14 - 3 - 2 = \mathbf{9\text{ 位}}$（高 5~13 位）。

```
+---------------------+-------------------+---------------------+
|      Tag (9位)      |   组号 Set (2位)   |  块内偏移 Off (3位) |
+---------------------+-------------------+---------------------+
```

#### 2. 数组元素的物理地址与字段分解表
数组从 `00000000H` 开始：

| 元素 | 字节起始地址 | 二进制地址（低 8 位） | 组号 (Set) | 主存块号 |
| :--- | :--- | :--- | :--- | :--- |
| `a[0], a[1]` | `0B ~ 4B` | `... 000 00 000` | **00B (组 0)** | 块 0 |
| `a[2], a[3]` | `8B ~ 12B` | `... 000 01 000` | **01B (组 1)** | 块 1 |
| `a[4], a[5]` | `16B ~ 20B` | `... 000 10 000` | **10B (组 2)** | 块 2 |
| `a[6], a[7]` | `24B ~ 28B` | `... 000 11 000` | **11B (组 3)** | 块 3 |
| `a[8], a[9]` | `32B ~ 36B` | `... 001 00 000` | **00B (组 0)** | 块 4 |
| `a[10], a[11]` | `40B ~ 44B` | `... 001 01 000` | **01B (组 1)** | 块 5 |
| `a[12], a[13]` | `48B ~ 52B` | `... 001 10 000` | **10B (组 2)** | 块 6 |
| `a[14], a[15]` | `56B ~ 60B` | `... 001 11 000` | **11B (组 3)** | 块 7 |
| `a[16], a[17]` | `64B ~ 68B` | `... 010 00 000` | **00B (组 0)** | 块 8 |

#### 3. 硬件查询追踪
硬件依据地址第 3~4 位的 `Set` 索引到对应的 Cache 组：
- 当访问 `a[8]` 时，`Set = 00B`，直接去组 0 的 2 个路中并行比对 Tag；
- 由于组 0 只有 2 路，当依次处理 `Tag=000` (块 0)、`Tag=001` (块 4)、`Tag=010` (块 8) 时，发生冲突替换。
结论与方法一完全一致。

### 最终结果计算

1. **总 Miss 次数**：
   $$\text{Miss 总数} = 9\text{ (第1轮)} + 3\text{ (第2轮)} + 3\text{ (第3轮)} + 3\text{ (第4轮)} = 18\text{ 次}$$
2. **总访存次数**：
   $$\text{访存总数} = 4 \times 18 \times 2 = 144\text{ 次}$$
3. **Cache 缺失率**：
   $$\text{缺失率} = \frac{18}{144} = \frac{1}{8} = \mathbf{12.5\%}$$

### 一、第 (2) 问：求指定元素的 Cache 行号（考场标准 3 步法）

**核心公式（直接映射）**：
$$\text{Cache 行号} = \text{主存块号} \bmod \text{Cache 总行数}$$

#### 基础参数准备（草稿纸上秒列出）
* 元素大小：32 位补码 = **4B**。
* 数组行大小：256 个元素 $\times$ 4B = **1024B**。
* Cache 块大小（行大小）：**64B**。
* Cache 总行数：**8 行**。
* 数组首地址：**320**。

---

#### 求解元素 $a[0][31]$：
* **Step 1（算字节地址）**：
  $a[0][31]$ 是数组的第 $0 \times 256 + 31 = 31$ 个元素。
  $$\text{地址} = 320 + 31 \times 4\text{B} = 320 + 124 = \mathbf{444}$$
* **Step 2（算主存块号）**：
  $$\text{主存块号} = \lfloor 444 \div 64 \rfloor = \mathbf{6}\quad(6 \times 64 = 384 < 444 < 448)$$
* **Step 3（求模得行号）**：
  $$\text{Cache 行号} = 6 \bmod 8 = \mathbf{6}$$

---

#### 求解元素 $a[1][1]$：
* **Step 1（算字节地址）**：
  $a[1][1]$ 是第 $1 \times 256 + 1 = 257$ 个元素。
  $$\text{地址} = 320 + 257 \times 4\text{B} = 320 + 1028 = \mathbf{1348}$$
* **Step 2（算主存块号）**：
  $$\text{主存块号} = \lfloor 1348 \div 64 \rfloor = \mathbf{21}\quad(21 \times 64 = 1344)$$
* **Step 3（求模得行号）**：
  $$\text{Cache 行号} = 21 \bmod 8 = \mathbf{5}$$

---

### 二、第 (3) 问：求命中率及比较执行时间（考场分析模板）

分析命中率，考场上直接看**访存步长与 Cache 块大小的关系**：
* 1 个 Cache 块容量：$64\text{B} \div 4\text{B} = \mathbf{16\text{ 个连续的 int 元素}}$。
* 首地址检查：$320 \div 64 = 5$（整除，说明**数组开头完美对齐在主存块的边界上**，没有任何错位偏移）。

---

#### 1. 程序 A（行优先访问：`a[i][j]`，内层是 `j`）
* **访存规律**：按内存物理地址顺序连续读：`a[0][0]`, `a[0][1]`, `a[0][2]`...
* **行为分析**：
  * 访问 `a[0][0]` 时：发生**冷缺失（Miss）**，硬件自动把包含该元素的**一整块（连续 16 个 int）**调入 Cache；
  * 接下来的 `a[0][1]` 到 `a[0][15]` 这 15 个元素：全部**命中（Hit）**；
  * 访问 `a[0][16]` 时：跨入下一个主存块，再次 Miss，调入后续 16 个元素……
* **命中率计算**：
  $$\text{命中率} = \frac{16 - 1}{16} = \frac{15}{16} = \mathbf{93.75\%}$$

---

#### 2. 程序 B（列优先访问：`a[i][j]`，内层是 `i`）
* **访存规律**：每次跳一整行读数据：`a[0][0]` $\to$ `a[1][0]` $\to$ `a[2][0]`...
* **跨度分析（关键陷阱）**：
  * 相邻两次访问的物理跨度：一整行 = $256 \times 4\text{B} = 1024\text{B}$。
  * 跨越的主存块数：$1024\text{B} \div 64\text{B} = \mathbf{16\text{ 个主存块}}$。
* **映射冲突推导（直接映射）**：
  * `a[0][0]` 落在主存块 $5$，对应 Cache 行号：$5 \bmod 8 = \mathbf{5}$；
  * `a[1][0]` 落在主存块 $5 + 16 = 21$，对应 Cache 行号：$21 \bmod 8 = \mathbf{5}$；
  * `a[2][0]` 落在主存块 $21 + 16 = 37$，对应 Cache 行号：$37 \bmod 8 = \mathbf{5}$；
  * 依此类推，每次内层循环访问的元素**全都被直接映射到 Cache 的第 5 行！**
* **行为分析**：
  * 每次访问都会把上一次调入第 5 行的块强制替换冲刷出去（发生**抖动 / 冲突缺失**），导致下一次依然找不到数据。
* **命中率计算**：
  $$\text{命中率} = \mathbf{0\%}$$

#### 3. 结论与作答
* 程序 A 命中率为 **$93.75\%$**，程序 B 命中率为 **$0\%$**。
* **执行时间**：**程序 A 的执行时间更短**。
  * **理由**：程序 A 的 Cache 命中率远高于程序 B，访存缺失次数极少，CPU 等待内存调块的停顿惩罚时间显著短于程序 B。

我们针对题目的三问，结合你的手写草稿逐题进行**原理解析、错误订正与考点拓展**。

你的草稿中出现了两处**致命的底层错误**（结构体大小判断错误、写操作次数算术错误），导致后续的块数计算和缺失率完全偏离。下面逐一拆解。

---

### 第一问：分析并比较程序段 A、B、C 的时间局部性和空间局部性

#### 1. 考点拆解
* **空间局部性**：若一个存储单元被访问，其**物理相邻**的存储单元不久也将被访问。评价标准是**访存地址是否连续、跨度有多大**。
* **时间局部性**：若一个存储单元被访问，**同一个存储单元**在不久的将来会被再次访问。评价标准是**是否存在短周期内的重复读/写**。

#### 2. 三个程序段深入分析
* **程序段 A**：
  * **访问模式**：按行优先顺序访问 `square[0][0]` 到 `square[7][7]`，与 C 语言数组在主存中的连续存放次序**完全吻合**。每个元素内部的 4 个字段也是连续紧邻存放并顺次赋值。
  * **空间局部性：最好**。访存严格沿主存地址连续递增，每个被调入 Cache 的数据块都被充分用满。
  * **时间局部性：差**。每个字段写完后，整个程序再也没有回头访问过同一个地址。
* **程序段 B**：
  * **访问模式**：内层循环变化的是行下标 $j$（访问 `square[j][i]`），这是**按列优先访问**。由于每行占 128B（4 个主存块），内层循环每前进一步，主存地址就跳跃 128B。
  * **空间局部性：最差**。步长大，完全破坏了跨元素间的空间局部性（仅在元素内部 4 个字段赋值时有极短暂的局部性）。
  * **时间局部性：差**。同样没有任何单元被重复访问。
* **程序段 C**：
  * **访问模式**：拆成了两个独立的双重循环。循环 1 线性遍历所有元素的 `y` 字段；循环 2 线性遍历所有元素的 `c, m, k` 字段。
  * **空间局部性：较好（介于 A 和 B 之间）**。虽然在单个循环内是跳着访问结构体内部字段（每次步长 16B），但总体仍是单向线性递增。
  * **时间局部性**：从代码结构上看，所有数组元素在第一个循环被访问后，在第二个循环**再次被访问**，具备一定的时间局部性意图。但由于数组总大小（1024B）超过了 Cache 总容量（512B），直接映射下循环 1 的后半部分会把前半部分全部冲刷出 Cache，导致循环 2 无法利用这个时间局部性。

> **草稿订正**：草稿中写“C 相当于两倍的 A 的复杂度”不属于体系结构的局部性分析语言。考研阅卷必须使用“访存步长与主存存储次序一致/不一致”、“Cache 块内数据利用率”、“同一单元未重复访问”等专业术语描述。

---


### 第一步：建立“物理标尺”（把题目参数压缩为最简整数）
先不管代码怎么写，先把硬件和数据的对应关系算死：

1. **算元素与块的大小**：
   * 1 个元素 = 16B。
   * 1 个 Cache 块 = 32B $\to$ **1 个块 = 2 个元素**。
2. **算数组的总块数**：
   * 数组共 $8 \times 8 = 64$ 个元素。
   * 总块数 $= 64 / 2 = \mathbf{32} \text{ 个主存块}$（记为：块 0 $\sim$ 块 31）。
3. **算 Cache 的总容量（看会不会装满冲突）**：
   * Cache 共有 $512\text{B} / 32\text{B} = \mathbf{16} \text{ 行}$。
   * **核心冲突结论**：数组（32 块）是 Cache（16 行）的 **2 倍**。主存中相差 16 的块会映射到同一个 Cache 行（即块 $k$ 与块 $k+16$ 发生映射冲突）。

> **标尺基准**：
> 设 64 个元素按内存顺序编号为 $E_0, E_1, E_2, \dots, E_{63}$。
> * 块 0 包含：$E_0, E_1$
> * 块 1 包含：$E_2, E_3$
> * 块 $b$ 包含：$E_{2b}, E_{2b+1}$

---

### 第二步：分析“微观操作”（每个元素被碰时发生什么）
观察三个程序段的内层赋值：
* 无论是写 `square[i][j]` 还是 `square[j][i]`，一旦开始处理某个元素，都是连续执行 4 条写语句（`c=0; m=0; y=1; k=0;`）。
* **微观铁律**：如果当前元素所在的块**不在 Cache 中**，写第 1 个字段触发**缺失**并调入该块；随后的 3 个字段**必定命中**。
  $\to$ **因此，每个元素如果缺失，只会贡献 1 次缺失，带来 3 次命中**。

---

### 第三步：分析“宏观轨迹”（写出块访问序列，排查冲突）
这一步是最容易乱的，按以下方法画出**块的访问轨迹**：

#### 1. 程序段 A（行优先：$E_0, E_1, E_2, E_3 \dots$）
* **访问顺序**：顺序扫描 $E_0 \to E_{63}$。
* **块的轨迹**：`块0 -> 块1 -> 块2 -> ... -> 块31`。
* **推导**：
  * 每个块只进去一次。
  * 访问 $E_0$ 时调入块 0（缺失 1 次），接着访问 $E_1$（全命中）。
  * 32 个块依次载入，**缺失次数 $= 32 \times 1 = 32$ 次**。

#### 2. 程序段 B（列优先：跨步跳跃访问）
* **访问顺序**：内层循环是 `j`（行号改变），外层是 `i`（列号固定）。
  * 先访问第 0 列：`square[0][0]` ($E_0$), `square[1][0]` ($E_8$), `square[2][0]` ($E_{16}$), `square[3][0]` ($E_{24}$), `square[4][0]` ($E_{32}$) $\dots$
* **块的轨迹**：
  * $E_0 \to$ **块 0**（映射到 Cache 第 4 行）
  * $E_8 \to$ **块 4**（映射到 Cache 第 8 行）
  * $E_{16} \to$ **块 8**（映射到 Cache 第 12 行）
  * $E_{24} \to$ **块 12**（映射到 Cache 第 0 行）
  * $E_{32} \to$ **块 16**（$16 \bmod 16 = 0$，**映射到 Cache 第 4 行，把块 0 踢了出去！**）
* **推导（致命冲突点）**：
  * 块 0 里的另一个元素是谁？是 $E_1$（即 `square[0][1]`）。
  * $E_1$ 要等到什么时候才被访问？要等外层循环走到第 1 列（$i=1$）！
  * 但在访问 $E_1$ 之前，内层循环早就访问了 $E_{32}$（块 16），**块 0 已经被踢出 Cache 了**。
  * **结论**：任何一个块内的 2 个元素，都**无法**享受空间局部性带来的“块共享”！
  * 每一个元素（共 64 个）在第一次被触碰时，其所在块都必须重新从内存载入。
  * **缺失次数 $= 64 \times 1 = 64$ 次**。

#### 3. 程序段 C（两个独立循环）
* **访问顺序**：
  * 循环 1：只写 `y`，顺序访问 $E_0 \to E_{63}$。
  * 循环 2：写 `c, m, k`，再次顺序访问 $E_0 \to E_{63}$。
* **推导**：
  * **循环 1**：顺序访问 32 个块。
    * 访 $E_0$ 缺失调入块 0，访 $E_1$ 命中。
    * 32 个块各缺失 1 次，**循环 1 产生 32 次缺失**。
    * *注意状态*：循环 1 结束时，由于数组占 32 块而 Cache 只有 16 行，后 16 块把前 16 块全部冲掉了（Cache 里只剩下块 16 $\sim$ 31）。
  * **循环 2**：从头重新访问 $E_0 \to E_{63}$。
    * 访问 $E_0$ 时，块 0 早已不在 Cache 中（发生容量/冲突缺失）。
    * 32 个块必须全部重新调入一遍，每个块首个元素缺失 1 次，第二个元素命中。
    * **循环 2 产生 32 次缺失**。
  * **总缺失次数 $= 32 + 32 = 64$ 次**。

---

### 第四步：汇总收尾
* 总写操作数统一为：$8 \times 8 \times 4 = 256$ 次。
* **程序 A**：写缺失率 $= \frac{32}{256} = 12.5\%$
* **程序 B**：写缺失率 $= \frac{64}{256} = 25\%$
* **程序 C**：写缺失率 $= \frac{64}{256} = 25\%$

### 总结公式模型
遇到二维数组 Cache 大题，只抓两个核心：
1. **一个块装 $k$ 个元素**；
2. **下一个用到同块元素的时刻到来前，这个块有没有被挤出去？**
   * **没被挤出（如 A）**：每个块只需调入 1 次，缺失次数 = 块数。
   * **全被挤出（如 B）**：同块元素吃不到红利，缺失次数 = 元素总数。
   * **拆成两轮且超容（如 C）**：每轮各调入一次，缺失次数 = 轮数 $\times$ 块数。
