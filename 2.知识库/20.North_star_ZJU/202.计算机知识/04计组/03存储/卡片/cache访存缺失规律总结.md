# Cache 访存缺失规律总结 — 考场快速判断框架

> 本卡片提炼三类典型题的底层规律，帮助你在考场上 **30 秒内判断是否会冲突、命中率大致范围**，无需完整模拟。

---

## 一、核心判断三步法

### Step 1：容量冲突判断（决定性因素）

**铁律**：映射到同一组/行的主存块数 > 该组的路数 → **必发生替换冲突**

```
判断公式：
- 组相联/直接映射：同一Cache行号 = 主存块号 mod Cache行数
- 计算：有多少个主存块会争抢同一个Cache位置？
```

**快速判断表**：

| Cache类型   | 映射关系            | 容量阈值           | 典型场景                    |
| :-------- | :-------------- | :------------- | :---------------------- |
| **直接映射**  | 每个主存块固定映射到1行    | 映射到同行的块数 > 1   | 例2/例3：数组跨度大，后半覆盖前半      |
| **2路组相联** | 每个主存块映射到1组的2个槽位 | 映射到同组的块数 > 2   | 例1：组0映射3个块→冲突，其他组≤2→不冲突 |
| **全相联**   | 可放任意位置          | 总块数 > Cache总行数 | 极少冲突，除非数据集巨大            |
|           |                 |                |                         |

**例1关键洞察**：
- 18个元素 → 9个主存块 → 映射到4个组
- 组0映射块0/4/8（3个块抢2路）→ **冲突源**
- 组1/2/3各映射2个块 → 容量刚好 → **第一轮后永不冲突**

**例3关键洞察**：
- 数组占32个主存块，Cache只有16行（直接映射）
- 块100-115映射到行4-15/0-3，块116-131也映射到行4-15/0-3
- **数组大小 > Cache容量 → 必有冲突**

---

### Step 2：访存模式判断（决定块内利用率）

**块内利用率 = 实际命中次数 / 块调入次数**

| 访存模式 | 步长特征 | 块内利用率 | 命中率估算 |
|:---|:---|:---|:---|
| **连续访问**（行优先） | 每次+1个元素 | **最高**：$\frac{块大小/元素大小 - 1}{块大小/元素大小}$ | 例2-A：15/16 = 93.75% |
| **跨行访问**（列优先） | 每次+整行宽度 | **最低**：只用块内1个元素 | 例2-B：0%（完全抖动） |
| **分段扫描**（两轮循环） | 先扫一遍，再扫一遍 | 中等：取决于是否缓存留存 | 例3-C：25%（两轮各冷启动） |

**快速判断**：
- **内层循环变量是列下标 `j`** → 连续访问 → 高命中率
- **内层循环变量是行下标 `i`** → 跨行访问 → 低命中率（可能抖动）

**例2的致命差异**：
```c
// 程序A：行优先，内层j连续递增
for (i=0; i<256; i++)
    for (j=0; j<256; j++)  // ✓ 地址连续
        a[i][j] = ...
        
// 程序B：列优先，每次跨1024B
for (i=0; i<256; i++)
    for (j=0; j<256; j++)  // ✗ 每次跨一整行
        a[j][i] = ...      // 地址步长 = 256*4B = 1024B
```

---

### Step 3：循环轮次判断（区分冷启动vs稳态）

**第一轮：冷启动阶段**
- 所有块首次访问必Miss
- Miss次数 = 访问的不同主存块数

**后续轮次分类**：

| 情况 | 判断依据 | Miss行为 | 典型例子 |
|:---|:---|:---|:---|
| **容量充足** | 数据集 ≤ Cache容量 | 第2轮起全命中 | 例1的组1/2/3 |
| **稳态冲突** | 容量不足但访问有序 | 每轮固定Miss次数 | 例1的组0：每轮3次Miss |
| **完全抖动** | 步长导致同行竞争 | 每次访问都Miss | 例2-B：列优先0%命中 |

**例1的周期性**：
- 第1轮：9次Miss（冷启动）
- 第2轮：3次Miss（组0的块0/4/8互相踢）
- 第3/4轮：重复第2轮的3次Miss
- **进入稳态后Miss次数恒定**

## 二、考场30秒决策树

```
┌─ 开始分析 ─┐
│ 提取参数   │ → 块大小、Cache行数/路数、数组大小、访问模式
└────┬───────┘
     ↓
┌────────────────────────────────────┐
│ 1. 数组总块数 vs Cache容量？       │
├────────────────────────────────────┤
│ • 数组块数 ≤ Cache行数             │ → 可能全命中（看访问模式）
│ • 数组块数 > Cache行数             │ → 必有冲突（继续判断严重程度）
└────┬───────────────────────────────┘
     ↓
┌────────────────────────────────────┐
│ 2. 访存是否连续？                  │
├────────────────────────────────────┤
│ • 内层循环列下标（行优先）         │ → 高块内利用率
│ • 内层循环行下标（列优先）         │ → 计算步长→判断是否同行冲突
└────┬───────────────────────────────┘
     ↓
┌────────────────────────────────────┐
│ 3. 映射冲突检查                    │
├────────────────────────────────────┤
│ • 计算关键元素的Cache行号          │
│ • 检查是否多个块映射到同一行       │
│ • 路数够不够容纳？                 │
└────┬───────────────────────────────┘
     ↓
   得出结论
```

## 三、三题对比表（规律提炼）

| 题目 | Cache配置 | 数组特征 | 冲突原因 | 缺失率 | 核心规律 |
|:---|:---|:---|:---|:---|:---|
| **例1** | 2路组相联<br>4组×8B | 18元素<br>9块→4组 | 组0容量不足<br>(3块抢2路) | 18/144<br>=12.5% | **容量不均**：只有组0冲突 |
| **例2-A** | 直接映射<br>8行×64B | 256×256<br>行优先 | 无冲突<br>连续流式访问 | 1/16<br>=6.25% | **空间局部性**：块内利用率15/16 |
| **例2-B** | 同上 | 256×256<br>列优先 | 步长1024B=16块<br>全映射到同行 | 1/1<br>=100% | **抖动陷阱**：步长mod行数=0 |
| **例3-A** | 直接映射<br>16行×32B | 8×8结构体<br>32块线性 | 数组2×Cache<br>后半覆盖前半 | 32/256<br>=12.5% | **容量不足**：单向流过无重用 |
| **例3-C** | 同上 | 两轮扫描<br>先y后cmk | 两轮各冷启动<br>无时间局部性 | 64/256<br>=25% | **轮次独立**：间隔太长已失效 |

## 四、常见陷阱与反直觉点

### 陷阱1：数组对齐与块边界
- **地址不从0开始时**：必须老实算 `地址 ÷ 块大小` 得主存块号
- **例2的地址320**：刚好整除64，数组完美对齐块边界 → 简化计算
- **若地址324**：首元素占块的后半部分 → 块内利用率下降

### 陷阱2：结构体大小计算
- **例3的致命错误**：认为元素4B，实际16B（4个int）
- **通用公式**：
  ```
  结构体大小 = Σ(各字段大小) + 对齐填充
  元素数/块 = 块大小 ÷ 结构体大小（向下取整）
  ```

### 陷阱3：写命中的"免费午餐"
- **读后立即写（RMW）**：读操作已将块调入，写操作必命中
- **例1的144次访存**：72次读Miss + 72次写Hit

### 陷阱4：15/16与0的分水岭
- **例2为何A是15/16，B是0？**
  - A的步长 = 4B（元素大小）< 64B（块大小）→ 块内有15个伙伴
  - B的步长 = 1024B = 16×64B → 恰好跳回同一Cache行 → 每次踢掉上次的
- **判断公式**：
  ```
  若 步长 mod (块大小 × Cache行数) = 0
  → 访问序列会周期性映射到同一行 → 抖动
  ```

## 五、考场作答模板

### 模板A：直接映射 + 连续访问
```
1. 块参数：块大小XB，Cache共Y行
2. 元素/块 = X ÷ sizeof(元素)
3. 首次访问Miss，后续(元素/块-1)次Hit
4. 命中率 = (元素/块 - 1) / 元素/块
```

### 模板B：跨步访问 + 冲突检查
```
1. 计算访存步长 = 数组行宽 × sizeof(元素)
2. 步长跨越的块数 = 步长 ÷ 块大小
3. 检查：(当前块号 + 跨越块数) mod Cache行数
   若等于当前块号 → 发生冲突
4. 若冲突 → 命中率≈0；若不冲突 → 按模板A计算
```

### 模板C：组相联 + 分组分析
```
1. 列出所有主存块号
2. 按"块号 mod 组数"分组
3. 逐组判断：
   - 该组映射的块数 ≤ 路数 → 第一轮后全命中
   - 该组映射的块数 > 路数 → 持续替换
4. 总Miss = Σ(各组Miss)
```
