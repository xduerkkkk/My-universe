## 一、接口边界与信息通路

### 卡 1｜接口-12｜接口—外设与接口—CPU 分别传什么？

**自测**
- 中断请求信号通常位于哪一侧？
- 外设状态、控制、数据经过哪些部件到达 CPU？

> [!faq]- 核对
> - **结构链**：CPU/主存 ↔ 系统总线 ↔ I/O 接口（控制器/适配器）↔ 设备电缆/设备总线 ↔ 外设。
> - **中断请求**：通常由接口/控制器向 CPU 或中断控制器提出，不是打印机本体跨过接口直接和 CPU 交换普通信息。
> - **接口—外设侧**：设备数据、状态、控制/握手信号。
> - **接口—主机侧**：数据、端口/寄存器访问、命令、状态以及中断/DMA 相关请求。
> - **下次检查**：先圈题目问的是哪两端，不能看到“中断”就默认所有链路相同。

### 卡 2｜接口-18｜控制器、适配器、驱动器怎样辨认？

**自测**
- “磁盘驱动器”和“磁盘控制器”哪个通常是接口？
- 可编程中断控制器是否属于外设本体？

> [!faq]- 核对
> - **接口关键词**：控制器、适配器、接口卡、网卡等，负责协议、寄存器、缓冲、控制与主机连接。
> - **外设关键词**：键盘、打印机本体、显示器、磁盘驱动器等被控制的设备。
> - **边界**：真实产品可能把控制器集成在设备内部；408 分类按功能位置判断，而不是按机箱中物理位置判断。
> - **易错点**：英文 drive 是驱动设备，不等于软件“驱动程序”，也不等于 controller。

### 卡 3｜接口-2、10、13｜串并行与格式转换

**自测**
- 接口的“数据格式转换”具体转换什么？
- 磁盘在磁道上读写为什么是串行？串行/并行只看线的根数吗？

> [!faq]- 核对
> - **格式转换**：可包括串并转换、字长/编码/电平/时序适配，由接口的数据缓冲和控制逻辑配合完成。
> - **磁道读写**：单磁头沿磁道经过磁性单元，位按时间顺序通过磁头，属于串行位流。
> - **判断核心**：看一次传送中有多少位并行通道及协议时序，不宜简化成“物理上只要一根线就是串行”。差分串行链路可能有多根导线，多 lane 串行链路也能并行提高带宽。
> - **拓扑**：CPU—I/O 总线—接口—设备侧链路—外设。

### 卡 4｜接口-6｜I/O 指令、机器指令与系统调用

**自测**
- I/O 指令是否属于机器指令？应用程序能否直接执行？

> [!faq]- 核对
> - **机器指令**：处理器指令集直接编码、由 CPU 执行的指令。
> - **I/O 指令**：若体系结构采用独立 I/O 编址，可有专门 IN/OUT 等机器指令；通常是特权指令，由内核/驱动执行。
> - **统一编址**：也可能用普通 load/store 访问内存映射 I/O 寄存器，没有专门 I/O 指令。
> - **系统调用**：应用程序请求 OS 提供 I/O 服务的软件接口，不等于一条具体 I/O 机器指令。

### 卡 5｜接口-11｜逻辑设备名、物理设备与设备号

**自测**
- 逻辑设备名的作用是什么？主/次设备号能否当成所有 OS 的通用定义？

> [!faq]- 核对
> - **逻辑设备名**：向程序提供稳定抽象，支持设备独立性。
> - **物理设备**：具体硬件及其系统标识，由 OS 映射与管理。
> - **主/次设备号**：是 Unix/Linux 等系统常见的具体实现，用于关联驱动类别和设备实例；不是所有操作系统、所有教材语境的普遍定义。
> - **易错点**：先辨认题目在考抽象层次还是某个 OS 的设备管理实现。

## 二、中断响应与现场保护

### 卡 6｜方式-15｜硬件保护 PC 的主要目的

**自测**
- 为什么响应中断时保护/更新 PC 必须由硬件先完成？
- 主要目的是“更快”吗？

> [!faq]- 核对
> - **主要目的**：保存返回断点，并把控制转入中断处理入口，使 ISR 能开始且结束后能正确返回原程序。
> - **为何先由硬件做**：执行任何软件指令前，CPU 必须已经保存必要断点并取得入口；否则原 PC 可能被覆盖。
> - **边界**：具体保存 PC、PSW 的位置和多少状态由体系结构决定；硬件实现较快只是附带效果。

### 卡 7｜方式-16｜中断请求触发器为什么存在？

**自测**
- 它解决“请求太短”还是“多个请求排序”？
- 屏蔽寄存器、允许中断位、判优电路各做什么？

> [!faq]- 核对
> - **请求触发器**：锁存某个中断源已经提出请求，避免 CPU 尚未检查时短脉冲消失。
> - **允许中断位/IF**：CPU 的全局可屏蔽中断开关。
> - **屏蔽寄存器/屏蔽字**：决定哪些中断源当前被允许或被屏蔽。
> - **判优电路**：多个未屏蔽请求同时存在时决定先响应谁。
> - **易错点**：保存单个请求与多请求优先级是不同层次。

### 卡 8｜方式-17｜关中断发生在何时？

**自测**
- CPU 刚响应中断时，谁负责关中断？ISR 中的软件关中断又是什么？

> [!faq]- 核对
> - **进入中断**：教材模型中，中断隐指令/硬件响应阶段可自动关闭可屏蔽中断，防止尚未保存现场就被再次打断。
> - **ISR 软件**：可通过特权指令修改中断允许状态；是否需要显式关/开以及时机依体系结构和操作系统约定。
> - **返回**：中断返回指令通常恢复 PC 与 PSW，其中可能包括先前的中断允许状态。
> - **易错点**：不要把 x86 的 CLI/IRET 细节当成所有 CPU 的唯一定义。

### 卡 9｜方式-2、13｜中断向量、向量地址与中断响应周期

**自测**
- 中断向量地址与中断服务程序入口地址是否一定相同？
- “中断响应周期”包含什么？

> [!faq]- 核对
> - **中断向量**：用于确定 ISR 入口的信息；它可能直接是入口地址，也可能指向保存入口地址/跳转指令的表项，取决于体系结构。
> - **向量地址**：中断向量表中相应表项的位置，不应无条件等同于 ISR 入口。
> - **中断响应周期**：通常指 CPU 接受请求后执行中断隐指令的硬件阶段，包括关中断、保存断点/状态、形成入口等；具体动作依教材模型。

### 卡 10｜方式-19｜响应优先级与处理优先级

**自测**
- “硬件管谁先开始，软件管谁先结束”是否总成立？
- 屏蔽字如何改变嵌套次序？

> [!faq]- 核对
> - **响应优先级**：多个请求同时等待时，硬件判优决定 CPU 先接受哪个。
> - **处理优先级**：进入某 ISR 后，屏蔽字/中断允许策略决定哪些中断可嵌套，从而影响实际完成顺序。
> - **边界**：可编程中断控制器也可由软件配置硬件优先级，因此“硬件/软件”不是绝对割裂；考试重点是区分“首次响应顺序”和“嵌套执行顺序”。

## 三、程序查询、中断与 DMA

### 卡 11｜方式-22｜程序查询是否等于 CPU 一直死循环？

**自测**
- 独占查询与定时查询有什么区别？
- 地址加 1、计数减 1 由谁完成？

> [!faq]- 核对
> - **独占查询**：CPU 持续轮询，等待期间不能做其他有效工作。
> - **定时查询**：CPU 周期性检查设备，其间可执行其他程序，但仍由 CPU 指令完成状态检查和每次数据搬运。
> - **程序控制传送**：地址更新、计数和数据搬运由 CPU 执行的软件指令完成。
> - **DMA**：块内的地址递增、字数递减和总线传送由 DMA 控制器硬件完成。
> - **易错点**：“程序查询方式必然一直查询”只描述独占查询。

### 卡 12｜方式-23、24｜DMA 总线请求与 DMA 完成中断

**自测**
- DMA 控制器什么时候向 CPU 要总线？什么时候发中断？
- 为什么 DMA 占有总线时 CPU 可能暂时不能响应普通中断？

> [!faq]- 核对
> - **DMA 总线请求**：为搬运一个传送单位申请系统总线，通常在机器/总线周期边界响应；经典教材也表述为两个存取周期之间。
> - **DMA 完成中断**：整个数据块结束或异常后通知 CPU，按普通中断响应时点处理，通常在指令结束后检查。
> - **占总线期间**：CPU 若需要访问主存来保存断点、取中断向量或取指，就必须等待总线归还；是否完全不能响应还取决于 CPU 内部资源和体系结构，408 题通常按“响应需要总线”处理。
> - **下次检查**：看到“DMA 请求”立即问是 HRQ/HOLD 还是 INTR。

### 卡 13｜方式-28、29｜DMA 与 CPU/中断的优先级能否说“永远最高”？

**自测**
- 为什么教材常让 DMA 总线请求优先于 CPU 访存？
- 它是否真的高于任何非屏蔽中断、在所有系统中都永远最高？

> [!faq]- 核对
> - **教材理由**：高速设备缓冲有限，若不能及时取走数据可能丢失，因此 DMA 请求总线时常优先于 CPU 的普通访存需求。
> - **层次区分**：DMA 总线仲裁优先级与 CPU 中断响应优先级不是同一条排名表，不能直接说“DMA 比非屏蔽中断都高”。
> - **系统边界**：真实机器的仲裁、实时性与非屏蔽异常机制由具体体系结构规定；“永远”是高风险绝对词。
> - **408 答法**：若题目比较 DMA 与 CPU 对总线的使用，通常 DMA 优先；若比较异常/中断，先确认是否在谈总线请求还是中断请求。

### 卡 14｜方式-30｜“程序控制方式”包含哪些方式？

**自测**
- 程序查询、中断、DMA、通道中，哪些传送单位由 CPU 指令亲自搬运？

> [!faq]- 核对
> - **直接程序控制/程序查询**：CPU 执行 I/O 指令并检查状态，每个数据单位由 CPU 搬运。
> - **中断驱动 I/O**：设备就绪时中断 CPU，但进入 ISR 后仍由 CPU 指令搬运该数据单位，因此仍属于程序控制的数据传送。
> - **DMA**：CPU 初始化，DMA 控制器搬整个块；块内数据不经 CPU 寄存器逐字搬运。
> - **通道**：通道执行通道程序，独立性比 DMA 更强。
> - **术语边界**：不同教材对“程序控制方式”口径可能不同，答题以教材分类树为准，但判断抓手始终是“每次数据搬运由谁执行”。

### 卡 15｜方式-32｜DMA 是否“完全不破坏现场”？

**自测**
- DMA 传送是否需要保存 CPU 的 PC、PSW 和通用寄存器？
- Cache 一致性问题是否等于“破坏 CPU 现场”？

> [!faq]- 核对
> - **408 现场概念**：DMA 不通过 CPU 执行数据搬运，不改变当前程序的 PC、PSW、通用寄存器，因此无需像中断那样保护执行现场。
> - **总线影响**：周期挪用会让 CPU 暂停一次访存，影响性能但不等于破坏寄存器现场。
> - **一致性边界**：DMA 写主存可能使 Cache 副本陈旧，需要硬件一致性或软件维护；这是存储一致性问题，不应混入“是否保存中断现场”的题目层次。

### 卡 16｜方式-35、57｜DMA 的块、字与数据通路

**自测**
- DMA 一次任务传块，还是一次总线传送就传整块？
- “设备接口 ↔ 主存”是专用物理线吗？

> [!faq]- 核对
> - **任务粒度**：一次 DMA 初始化通常负责一个数据块；实际总线事务按字、总线宽度或突发长度分多次完成。
> - **逻辑数据通路**：数据源/终点是设备接口与主存，正常数据不需要逐字经过 CPU 通用寄存器。
> - **物理实现**：双方通常通过共享系统总线或互连传送，不代表存在一根专用的“设备—主存私线”。
> - **DMA 控制器角色**：控制地址、计数和握手；数据是否经过其内部缓冲寄存器取决于控制器结构。

### 卡 17｜方式-54｜中断请求、DMA 完成通知与 EOI

**自测**
- 外设发“中断结束信号”这句话哪里容易错？
- DMA 完成中断与 EOI 是否是一回事？

> [!faq]- 核对
> - **设备/控制器 → CPU**：提出中断请求；DMA 完成后也可用中断请求通知“本块已结束”。
> - **CPU/ISR → 中断控制器**：某些控制器需要 EOI（End Of Interrupt）命令，表示本次服务已完成，可清除在服务状态并继续仲裁。
> - **区别**：DMA“传输结束中断请求”描述请求原因；EOI 描述 CPU 完成中断服务后的控制动作。
> - **边界**：EOI 的存在与发送方式依中断控制器，不应说所有设备系统都必须显式发送同一种信号。

## 四、计算题模板

### 卡 18｜大题｜中断频率与 CPU 是否来得及

**自测**
- 已知设备频率 $f_d$、每次中断总周期 $C_i$、CPU 频率 $f_c$，怎样判断可行？

> [!faq]- 核对
> - **设备间隔**：$T_d=1/f_d$，或折算为 CPU 周期数 $N_d=f_c/f_d$。
> - **CPU 服务成本**：把中断响应、现场保护恢复、ISR 指令周期全部相加得到 $C_i$。
> - **判据**：若 $C_i\le  N_d$，理想条件下 CPU 能跟上；否则请求会积压或数据丢失。
> - **占用率**：$U=f_d\times C_i/f_c$。
> - **易错点**：明确题目是否把设备传输时间与 CPU 服务时间重叠。

### 卡 19｜大题｜轮询、中断、DMA 的 CPU 占用率

**自测**
- 哪些时间计入“任务总耗时”，哪些计入“CPU 为 I/O 工作的时间”？

> [!faq]- 核对
> - **墙钟时间**：从任务开始到全部数据完成，包含设备传输、等待与 CPU 处理。
> - **CPU 占用时间**：只计 CPU 实际执行轮询、初始化、ISR、收尾等工作的周期；设备自主传输期间通常不计。
> - **轮询**：独占轮询时等待几乎全部占用 CPU。
> - **中断**：每个数据单位付一次响应与 ISR 开销。
> - **DMA**：通常每块付初始化与完成中断开销，块内传送只造成总线争用。

### 卡 20｜大题｜异步串行帧位数

**自测**
- 已知 7 数据位、1 校验位、1 停止位，为什么常不是 9 位？

> [!faq]- 核对
> - **异步帧**：通常还包含 1 个起始位，因此总位数 = 起始位 + 数据位 + 可选校验位 + 停止位。
> - **本例**：$1+7+1+1=10$ bit/字符。
> - **边界**：停止位数、校验位、数据位均以题设为准；不要把“默认 1 起始位”漏掉，也不要自行添加同步字符。

### 卡 21｜大题｜“每次输出/缓冲区满”题的读题动作

**自测**
- 看到“每秒产生 R 字节、缓冲区 B 字节、每满一次处理”，第一步算什么？

> [!faq]- 核对
> - **事件频率**：$f=R/B$ 次/秒；事件间隔 $T=B/R$。
> - **再问动作成本**：每次输出/中断/DMA 启动需要多少 CPU 周期或总线周期。
> - **最后算占比**：事件频率 × 单次成本 ÷ CPU 每秒总周期。
> - **易错点**：$1/f$ 是两次事件的墙钟间隔，不自动等于 CPU 每次“查看/处理”所花时间。
