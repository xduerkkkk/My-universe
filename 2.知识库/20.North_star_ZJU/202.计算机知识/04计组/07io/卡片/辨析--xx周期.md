- **时钟周期（节拍 T）：** 最小的套娃。CPU 的心跳，比如 3GHz 的 CPU，一个时钟周期就是 1/3G 秒。
    
- **机器周期 / 总线周期：** 中等套娃。通常规定为**“去主存读写一次数据所需的时间”**。它包含若干个时钟周期。
    
- **指令周期：** 最大的套娃。执行一条完整指令（取指、译码、执行）的时间。它包含若干个机器周期。
    
- **存取周期（Memory Cycle Time）：** 这是主存芯片自己的物理属性！它表示主存进行一次完整读写，并**恢复内部电容状态**，直到能迎接下一次读写所需的总时间。（存取周期 > 真正读出数据的时间）。

最小时间单位 ──> 最大时间单位

[ 时钟周期 (T) ]  <-- 晶振频率决定，CPU 最小工作步长
       ↓
[ 机器周期 (CPU 周期) ] <-- 执行一个基本操作（如一次访存），包含 M 个时钟周期
       ↓  (理想状态下，两者的长度相互设计和适配)
[ 存取周期 ] <-- 存储器硬件限制，连续两次独立读写所需的最小间隔
       ↓
[ 指令周期 ] <-- 执行一条完整指令，包含 N 个机器周期

### 机器周期 vs 总线周期：真的没区别吗？
- **机器周期（Machine Cycle）** 是一个 **CPU 内部的状态控制概念**。它是 CPU 完成一个基本微操作（如取指、译码、内部运算、写回）所需要的时间。
    
- **总线周期（Bus Cycle）** 是一个 **外部总线传输概念**。它是 CPU 通过总线对外部存储器或 I/O 端口进行一次完整的读/写操作所需的时间[
    

它们不完全等同，原因在于：**并不是每一个机器周期都需要使用总线**。

- **当机器周期需要访存时**：比如“取指机器周期”，CPU 需要去内存拿指令，此时该机器周期在时间上就等同于一个总线周期[
    
- **当机器周期不需要访存时**：比如“执行机器周期”，如果 CPU 正在进行一些复杂的内部寄存器运算（如乘法、除法或逻辑运算），此时 CPU **完全不占用外部总线在这种情况下：
    
    - 此时**没有总线周期**在运行。
        
    - 但它依然是一个完整的**机器周期**。
        
    - 因为 CPU 此时不用总线，所以它可以在这个机器周期结束时，非常安全地把总线控制权让给 DMA 接口

**结论：**  
如果选“总线周期执行完”，那就无法解释“在 CPU 进行内部运算（不产生总线周期）时，为什么也能响应 DMA 请求”。CPU 的控制单元（CU）是在**每个机器周期结束时**去检测并响应 DMA 请求信号（如 HOLD 引脚）的。
