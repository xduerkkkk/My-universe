## 一、I/O 接口

### 1.1 数据格式转换（接口-2）
数据格式转换发生在数据寄存器这一环：接口把 CPU 的数据组织方式与外设的对接。

### 1.2 串行 vs 并行（接口-10）
磁头划过盘片时只能按位顺序写入，这是**串行（Serial）**。

**并行（多根数据线同时传）：** CPU 内部总线（32/64 位）、老式 LPT 打印口（并口）、PATA/IDE 硬盘排线。
**串行（单根数据线逐位传）：** USB、SATA 硬盘线、网线/光纤。

现代高速计算机中串行反超并行：并行线时钟高时产生串扰，且多线无法保证比特同时到达；串行线无干扰，频率可达极高（如 PCIe）。

**本质：看数据线是一根还是多根。**

### 1.3 🔴 设备地址的四种名称（接口-11）
- **逻辑设备名（程序员用）：** `/dev/printer`、`C盘` 这类统一代号，不关心底层具体设备。这叫**设备独立性**。
- **物理设备名（系统底层用）：** 硬件的真实名字，OS 通过 LUT 把逻辑名映射到物理名。
- **主设备号 (Major) / 从设备号 (Minor)（Linux）：** Major 标识驱动程序类别，Minor 标识同类别中的具体设备。

### 1.4 ⚠️ 中断请求信号在「接口↔CPU」之间（接口-12 · !!）
**没审题。** 打印控制接口=I/O 接口，打印机=外设。中断请求信号是**I/O 接口与 CPU 之间**交换的信息，不是接口与外设之间。

### 1.5 🔴 数据传输的物理链路（接口-13）
**CPU — IO 总线 — IO 接口 — 通信总线/电缆 — 外设**

### 1.6 ⚠️ 谁属于 I/O 接口（接口-18 · !!）
- 磁盘驱动器 = 外设本身（drive），**不属于 I/O 接口**。
- 打印机适配器 = 接口（adapter）。
- 网络控制器 = 网卡，接口。
- 可编程中断控制器（8259A）= 接口的控制功能部件。

**判断信号：** "适配器/控制器/接口卡"→接口；"驱动器/显示器/键盘/鼠标本体"→外设。

## 二、中断机制

### 2.1 中断向量地址（方式-2）
中断向量地址由**向量地址形成部件**产生。该地址从主存取出的是一条 `JMP` 指令（或服务程序入口地址），即**中断向量**。

### 2.2 🔴 哪些情况触发中断（方式-3）
- Cache：**不涉及中断**（纯硬件）。
- 缺页：需要访问硬盘，**触发中断**，挂起进程。
- **上溢**：触发中断（异常）——结果超出格式容量，硬件无法处理，OS 通常终止程序。
- **下溢**：**不触发中断**——结果趋近于 0，硬件直接当机器零(0)处理。

### 2.3 🔴 中断检查时机 + 周期名词辨析（方式-5）
- **中断请求（INTR）：每条指令结束时** 检查。
- **DMA 请求（HRQ）：每个机器周期（总线周期）结束时** 检查（因为 DMA 每传 1 字都要借用总线，频率高）。
- **机器周期/总线周期：** 主存读写一次所需时间，含若干时钟周期。
- **指令周期：** 执行一条完整指令（取指—译码—执行）的时间，含若干机器周期。
- **存取周期：** 主存芯片物理属性——完成一次完整读写并恢复电容状态所需总时间。存取周期 > 读出时间。

**JMP vs IRET：**
- JMP：只改 PC（目标地址→PC）。
- IRET：恢复 PC（从栈弹回）+ 恢复 PSW（标志寄存器 + 中断允许位）。目标地址从栈中取出、运行时确定，不是固定地址。**IRET 本质是"恢复断点现场"，不能等同于无条件转移。**

### 2.4 CPU 响应中断的条件（方式-8）
中断信号、开中断、一条指令执行完毕。

### 2.5 🔴 通道（方式-10）
启动 I/O 前：**访管中断**（软件）；I/O 完成后：**I/O 中断**（硬件）。通道 = 能独立执行通道程序（存放在主存中）的专用处理器，比 DMA 更强。

### 2.6 🔴 中断响应周期（方式-13）
"中断响应周期"就是执行中断隐指令的过程。

### 2.7 ⚠️ 硬件保护 PC 的目的（方式-15 · !!）
采用硬件（而非软件）保护并更新 PC，主要目的是**能进入中断处理程序并正确返回源程序**。"提速"只是附带效果。保护断点必须在执行任何指令之前完成，软件指令无法做到（执行软件指令的前提是 PC 已被改写、断点已丢）。

### 2.8 ⚠️ 中断触发器（方式-16 · !!）
外设中断请求是瞬时脉冲，CPU 可能正忙（长指令、关中断）。中断触发器的作用是**锁存该请求信号**，保持到 CPU 能查询的时候。

**相关部件：**
- 中断屏蔽寄存器（IMR）：在 8259A 中，决定哪些中断请求能送到 CPU。
- 允许中断触发器（EINT/IF）：在 CPU 的 PSW 中，是总开关。

**为什么不选"协调多个中断"？** 多中断协调靠判优逻辑和屏蔽字，每个中断源各自一个触发器，触发器只管锁存自己的请求。

### 2.9 ⚠️ 关中断指令写在哪（方式-17 · !!）
中断隐指令（硬件）在最开始关中断；**恢复现场时的关中断指令（如 `CLI`）由程序员/OS 写在 ISR 代码里**。

### 2.10 🔴 优先级与执行次序辨析（方式-19）
**口诀：硬件管"谁先开始"，软件管"谁先结束"。**
- 中断响应优先级：硬件排队电路决定，映射了请求优先级，决定**谁先开始执行**。
- 中断屏蔽标志：软件（OS）设置，决定执行中能否被插队。
- 执行完的次序：看屏蔽字（软件），不看响应优先级。

### 2.11 开中断指令的位置（方式-38）
如果"开中断"放在"中断返回"**之后**，CPU 已回到用户程序，永远执行不到该指令→系统永久关中断。

### 2.12 中断服务程序在内核态执行（方式-52）
ISR 在内核态执行。优先级低的中断请求在检测阶段就被拦截，CPU 只有在检测到中断请求信号后才进入中断响应周期。

### 2.13 🔴 中断 I/O 数据传送实质是"程序控制"（方式-53）
中断 I/O 方式下，数据传送由 ISR 中的 **`IN`/`OUT` 汇编指令（软件）** 驱动硬件完成，实质是**程序（软件）控制的**，不是纯硬件。外设准备数据时间必须 > 中断处理时间，否则覆盖缓冲区。

### 2.14 ⚠️ 中断结束信号 EOI 的方向（方式-54 · !!）
当 `IF=1` 时，CPU 在**当前指令执行结束时**检测到中断请求，**紧接着**进入中断响应周期——这一条对。

**三种"信号"的区分：**
- 普通外设发 `INTR`：含义是"有数据需要取"（请求服务开始）。
- DMA 发 `INTR`：物理上与普通外设一样，但含义是"数据块传输完毕"。
- **CPU 发 EOI 给 8259A**：告诉中断控制器"这个中断处理完了，清零排队标志，允许同级下一个中断进入"。这才是真正的"中断结束命令"。

**结论：设备只发"请求"，不发"结束信号"。EOI 是 CPU→8259A 的复位命令。** "外部设备向 CPU 发中断结束信号"是方向性错误。

## 三、DMA 方式

### 3.1 🔴 DMA 中断的时机与善后（方式-4）
- DMA 在**整个数据块全部传完后**才发中断。
- 发完中断后 DMA 闲置，等待 CPU 下达新任务。
- CPU 进入"DMA 传输结束 ISR"：检查 DMA 状态寄存器，唤醒之前等数据的阻塞进程，如有新数据需传则重新初始化 DMA。
- DMA 中断开销小，所以优先级比程序中断高。

### 3.2 🔴 谁能产生 DMA 请求（方式-6）
只有具备 DMA 接口的设备才能产生 DMA 请求。

### 3.3 ⚡ DMA 占总线时 CPU 不能响应中断（方式-23 · !）
CPU 响应中断的第一步是中断隐指令——要把 PC 和 PSW 压入主存栈、从主存读中断向量。压栈和读向量都需要**占用系统总线**。DMA 占着总线时，CPU 无法完成中断隐指令，因此不能响应中断。

### 3.4 🔴 DMA 响应时机（方式-24）
**"两个存取周期之间" = "一个机器周期（总线周期）结束时"**（408 语境下同义）。
- DMA 请求（HRQ）：在每个机器周期结束时响应。
- DMA 传送结束中断（INTR）：在指令周期结束后响应。

### 3.5 🔴 DMA 请求 = 总线请求 HRQ（方式-27）
题目写"**DMA 请求**"就是 HRQ（总线请求），不是中断请求。流水线 CPU 中每个流水段（IF/ID/EX）长度 = 1 个机器周期（通常 = 1 个时钟周期）。

### 3.6 ⚠️ DMA 优先级 > NMI（方式-28 · !!）
**DMA 优先级高于非屏蔽中断。**

### 3.7 ⚠️ DMA 优先级永远 > CPU（方式-29 · !!）
外设（磁盘、网卡）的硬件 FIFO 缓冲区极其有限，如果 CPU 占着总线不放，外设缓冲区会在几微秒内溢出→丢包/读写错误。所以 DMA 优先级必须最高。

**磁盘读写各阶段归属：** 寻道→中断；旋转→中断；旋转后→DMA 请求；读写磁盘块→DMA 传输（无中断）；结束/校验→DMA 结束中断。

### 3.8 ⚠️ DMA 不破坏现场，但引发 Cache 一致性问题（方式-32 · !!）
DMA 不破坏 CPU 程序现场（PC、PSW、通用寄存器完全无损）。但 DMA 直接写主存时，如果 CPU Cache 中存有该地址的旧副本，Cache 数据失效——这是 **Cache 一致性问题**。

### 3.9 ⚠️ DMA 传输单位：块 vs 字（方式-35）
一次 DMA 传送的目标是**一个数据块**，但每一次总线占用只传**一个字**。块是目标，字是每次搬的单位。

### 3.10 🔴 DMA 初始化信息与数据流（方式-36）
DMA 初始化信息中**没有通用寄存器**——DMA 直接跟主存打交道，不经过 CPU 寄存器。
**数据流：设备 → 数据缓冲寄存器 → 数据线 → 主存。**

### 3.11 🔴 中断与 DMA 的并行性（方式-21）
中断与 DMA 的**传送**都与主程序并行，区别是：中断方式下 CPU 与外设**串行**（CPU 亲自执行 IN/OUT），DMA 方式下**并行**（DMA 和 CPU 同时工作，交替占用总线）。

### 3.12 DMA 初始化是谁干的（方式-48）
- 硬件视角：**CPU** 执行指令写 DMA 寄存器。
- 软件视角：**设备驱动程序**（OS 代码）指挥 CPU 完成。
- "CPU 负责初始化" 和 "OS/驱动程序负责初始化" 都正确，视角不同。

### 3.13 🔴 周期挪用 + 缓冲区（方式-51）
周期挪用方式下，DMA 在 512B 数据块传输过程中分 128 次（512/4）借走总线，**两次借取之间 CPU 可以自由访问主存**。只有"停止 CPU 访存（独占总线）"方式下 CPU 才被全程封锁。

**知识漏洞：** 普通中断和 DMA 都有缓冲区——外设攒够 32 位（4 字节）后发信号通知系统取数。两者在这一点上机制相同，只是"谁来取"不同（CPU vs DMA）。

### 3.14 ⚡ DMA 数据传输通路（方式-57 · !）
**数据通路：设备接口 ↔ 主存**（不是设备接口 ↔ DMA 控制器）。
- 控制通路：DMA 控制器 ↔ 设备/主存/CPU（传握手信号）。
- 数据通路：数据本身从设备接口直接到主存，不经过 DMA 控制器。

### 3.15 机器周期 vs 总线周期（方式-26）
**机器周期不一定是总线周期，总线周期一定是机器周期。**（总线周期 = 访存的那一个机器周期。）

## 四、程序查询 / 程序控制方式

### 4.1 ⚠️ 程序查询的分类（方式-22 · !!）
程序查询分**独占查询**（一直循环查状态）和**定时查询**（定期查）。每次传送后主存地址 +1、计数值 -1。
- 程序查询方式下：CPU 执行加减指令（**软件**）完成。
- DMA 方式下：DMA 控制器内**硬件计数器**自动完成。

"CPU 需一直查询外设状态"→只符合独占查询，不符合定时查询，不能作为程序查询方式的总特征。

### 4.2 ⚠️ 程序控制方式分类（方式-30 · !!）
"直接程序传送"（直接程序控制方式）包含：
- **程序查询方式（条件传送）：** 循环查状态寄存器，条件满足才传。
- **无条件传送：** 外设永远就绪（如 LED），直接传，不查状态。

**程序控制方式 vs DMA：**
- 程序控制方式（含查询和中断）：每搬一个数据，CPU 必须执行一条指令（`IN`/`OUT`），是**软件**在工作。
- DMA 方式：CPU 只在首尾参与，中间数据传送由 DMA 控制器硬件完成。**DMA 不属于程序控制方式。**

### 4.3 多重中断的检测（方式-45）
CPU 在每条指令周期结束时都检测中断信号线。**ISR 的每一条指令执行完，同样会检测**——所以多重中断的嵌套检测与普通中断机制一致。

### 4.4 🔴 非屏蔽中断 NMI（方式-46）
- 常规外设（键盘/鼠标/磁盘/网卡）→ 全部**可屏蔽中断 INTR**。
- NMI 来源：**电源掉电警告、主存奇偶校验错误、总线严重故障**。
- **DMA 请求是总线请求（HRQ），不需要开中断。**

## 五、I/O 编址方式

### 5.1 🔴 独立编址 vs 统一编址（方式-44）
- **独立编址（x86）：** 端口有专用的 `IN`/`OUT` 指令，端口地址与主存地址完全分离。
- **统一编址（ARM）：** 端口占用主存地址空间的一部分，用标准访存指令（`LOAD`/`STORE`）访问端口，发的是主存地址。

## 六、I/O 性能计算

### 6.1 🔴 中断占比计算（方式-43）
"最长延迟时间 50ns"——这段时间 CPU 在做自己的事，不算 I/O 时间。**计算 I/O 占比时直接忽略。**
周期总时间 = 400ns，中断处理 = 100ns，占比 = 100/400 = **25%**（不是 100/500）。

### 6.2 🔴 高频中断计算（方式-47）
先算每秒中断次数，再算 CPU 占用。
数据缓冲寄存器 32 位→每攒 4 字节发一次中断。用数据传输速率 ÷ 4 得到每秒中断次数，再乘以每次中断的处理时间。

## 七、大题

### 7.1 大题1 · 能否用中断方式
**结论：** 不能。CPU 处理一次中断 40μs > 两次中断间隔 25μs（1/40000），中断积压→数据丢失（中断风暴）。必须用 DMA。

### 7.2 大题2 · 多重中断堆栈与空档期
t=0 主程序跑，1 先响应→主程序断点压栈。1 被 3 打断→1 断点压栈。栈：`1断点(顶)` / `主断点(底)`。

3 完→IRET 弹栈，回 1，栈剩主断点。
1 完→IRET 弹栈，**必须回到主程序**（栈只剩主断点），形成折线底部的空档。

CPU 回主程序后执行一条指令→指令结束时检测中断→2 优先级高于 4→立即响应 2→主断点再次压栈。

**总结：** 空档期是因为 CPU 无法在两个非嵌套中断间横向跳转，必须先弹栈回主程序，再被新中断压栈带走。

### 7.3 大题3 · DMA 两级请求计算
**两级请求：**
- 字节级（周期窃取）：每攒 1 字节申请一次总线，每次占用 1 个存取周期（0.2μs）。
- 块级（中断）：整块 400B 传完才发 1 次中断（5μs 开销）。

**计算（9600 b/s）：**
- 每秒字节数 = 9600/8 = 1200 B/s
- 周期窃取 = 1200 × 0.2μs = 240μs
- 结束中断 = 1200/400 × 5μs = 15μs
- DMA 总占用 = **255μs**
- 纯中断方式对比 = 1200 × 5μs = **6000μs**

DMA 占用仅纯中断的 4%。

### 7.4 大题4 · 注意单位换算和小数点

### 7.5 大题5 · 异步通信 + 两个"时间"
**起始位漏掉是致命错误。** 异步串行通信无统一时钟，每个字符帧前必须加 **1 位起始位**。总位数 = 1起始 + 7数据 + 1校验 + 1停止 = **10 位**。

两个"时间"的区别：
- **第一小问（墙上时间）：** 外设传 1 字符 = 0.5ms = 25000 周期；循环 = 25000（传数）+ 10（响应）+ 60（指令1-15）= 25070 周期；1000 字符 ≈ 25,070,000 周期。
- **第二小问（CPU 真正投入 I/O 的时间）：** 外设传输时 CPU 空闲。CPU 只花 10（响应）+ 20×4（完整 ISR）= 90 周期/字符；1000 字符 = 90,000 周期。

CPU 占用仅占总时间的 ~0.4%，其余时间可跑其他任务。这就是中断 vs 轮询的本质差距。

## 八、🔗 OS ↔ 计组 对应关系

> 计组 = 硬件电路 + 时序 + 信号；OS = 软件层次 + 进程状态 + 调度。
> 对应 OS 整理：[[2.知识库/20.North_star_ZJU/202.计算机知识/03操作系统/04IO/02王道题-知识点整理|OS-IO 知识点整理]]

| 主题 | 计组视角（本文） | OS 视角 |
|------|----------------|---------|
| I/O 接口 | 适配器/控制器=硬件部件，含数据/状态/控制寄存器 | 控制器提供命令集，CPU 写控制寄存器 |
| 设备地址 | 逻辑名/物理名/主从设备号 | 绝对号 vs 相对号；设备名→fd→驱动 |
| 通道 | 执行通道程序的专用处理器 | 硬件技术；通道→控制器→设备层级 |
| DMA | 总线请求 HRQ、周期窃取、块/字、Cache 一致性 | 进程：运行→阻塞→中断仍阻塞→就绪 |
| 中断 | 隐指令、保护断点、向量、关/开中断位置 | ISR 把控制器缓冲→内存缓冲 |
| 中断 vs 进程 | 硬件在指令结束时检测；多重中断靠栈 | 进程阻塞≠CPU空转；不一定回原进程 |
| 传送本质 | 中断 I/O 实质是 ISR 的 IN/OUT 指令 | 驱动程序把标准命令译成寄存器操作 |
| 缓冲区 | DMA 和中断都有硬件 FIFO，攒够再发 | 内存缓冲 vs SPOOLing 井；临界资源 |
| 数据流 | 设备→数据缓冲寄存器→数据线→主存 | 键盘→控制器寄存器→CPU寄存器→内核缓冲→用户区 |

**主线串联：**
1. **中断 I/O 是软件还是硬件？** ISR 中的 `IN`/`OUT` 指令→调用驱动程序→驱动硬件寄存器。计组讲指令层，OS 讲驱动层，同一件事的不同切片。
2. **DMA 时进程和 CPU 各在干嘛？** 计组管总线/信号怎么走（数据通路），OS 管进程状态怎么变（运行→阻塞→就绪），拼成 DMA 完整生命周期。
3. **中断为什么不一定返回原进程？** 计组保证"能正确返回断点"（机制），OS 决定"要不要返回"（调度策略）。
4. **缓冲三级放大：** 硬件 FIFO（计组）→ 内存缓冲 → 磁盘 SPOOLing 井（OS），微观到宏观。
