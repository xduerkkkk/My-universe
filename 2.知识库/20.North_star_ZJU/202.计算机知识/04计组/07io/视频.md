# 中断
- INTR = Interrupt Request (中断请求)
- INTA = Interrupt Acknowledge (中断响应/中断确认)

中断系统为每个中断源设置一个中断请求标记触发器
INTR 信号线发出可屏蔽中断，NMI 信号线是不可屏蔽中断


CPU 怎么知道要有中断的？
如果是轮询就是自己检查状态端口，这不叫中断
中断方式，CPU 在每条指令执行结束时检查的是 **INTR 信号线的电平**(确切说是检查中断请求触发器的状态), 不是去读 IO 的状态端口。
CPU 在每条指令的最后一个时钟周期 (指令执行结束、取下条指令之前) 会去查询中断请求触发器
- 第一步, 请求阶段: IO 设备把 INTR 线拉高 (置 1)。这根线上传的不是数据, 就是一个电平信号, 含义只是"有设备请求中断"。

- 第二步,响应阶段 (中断响应周期): CPU 决定响应后, 发出 INTA (中断响应) 信号回给设备。这时设备才把 **中断类型号 (中断向量号)** 放到数据总线上, CPU 读进来。


中断请求触发器在 **每个设备的接口里**(中断源侧), 它被设备的完成信号置位后, 拉高 **INTR 信号线**, 这条线接到 **CPU 的 INTR 引脚**; CPU 在每条指令末尾用硬件顺带看一眼这个引脚 (不花指令周期, 所以比轮询端口高效), 发现有请求且允许中断时, 就从 **INTA 引脚** 发确认信号, 设备随即把中断类型号送上数据总线。

#### 1. 响应优先级（由硬件电路决定，无法改变）

- **决定者**：中断控制器里的**排队判优器（PR）**或主板上的**菊花链（Daisy Chain）硬件电路**。
    
- **作用**：当多个外设在**同一时刻**一起发送中断请求时，硬件电路决定 CPU **先跟谁握手（先响应谁）**。
    
- **特点**：这是出厂时硬件电路焊死的，程序员无法通过写代码改变。
    

#### 2. 处理优先级（由 MASK/中断屏蔽字决定，可动态改变）

- **决定者**：CPU 写入中断控制器的 **MASK（中断屏蔽字）**。
    
- **作用**：在多重中断中，当 CPU **正在处理** A 中断时，B 中断来了，CPU 查一下当前的 MASK，决定 **“B 到底能不能打断 A 搞嵌套”**。
    
- **特点**：程序员可以通过在中断服务程序里修改 MASK，**动态地改变处理优先级**。

	- 硬件向量法：中断判优后，输出当前是哪个 IO 部件，比如 0010，是鼠标的，然后经过中断向量地址形成部件，产出一个向量地址，从主存里找这个向量地址，地址里存的是，JMP xxx，这个 xxx 就是中断程序的地址！不直接指向中断程序，直觉上就是两级指针便于管理




- 中断服务程序 ：

	- 执行中断：各有各的过程

**为什么要搞两级指针？** 因为硬件（向量地址形成部件）是焊死在主板上的，算出来的地址（如 `0x0008`）是无法更改的。但操作系统经常要升级，鼠标的驱动程序（中断服务程序）在内存里的位置是会变的！有了这层“向量表（指针数组）”，操作系统每次加载驱动时，只需要把新的入口地址填到 `0x0008` 这个格子里就行了。底层硬件完全不需要改动。完美！

- 响应优先级: 决定"谁先被理睬", 硬件定, 不可变。
- 处理优先级: 决定"谁能打断谁", 屏蔽字定, 软件可调。
- 如果所有中断服务程序都不改屏蔽字 (只屏蔽自己或开全部), 那处理优先级就等于响应优先级。正是因为可以设屏蔽字, 两者才可能被拉开。
- MASK(屏蔽寄存器)物理上在 IO 接口/中断控制器侧,只是它的内容由 CPU 软件写入。
- 响应优先级:同时请求时谁先被响应,由硬件排队电路固定决定。
- 处理优先级:中断嵌套时谁能打断谁,由可被软件修改的屏蔽字决定。
- 通过给每个服务程序设计不同屏蔽字,可以让处理优先级不同于固定的响应优先级,这就是屏蔽技术的意义所在。


# DMA
![[视频-1773130996026.jpeg]]


历经 AR、WC、控制寄存器
1. **步骤 1：CPU 初始化 DMA（布置仓库）**
    
    - 包工头（CPU）先把起始地址(AR)、传输字数写进 DMA (WC) 的寄存器里。
        
    - 大白话：CPU 对 DMA 管家说：“一会儿有砖头送来，你按这个清单放进 A 仓库。现在你在门口等着。”
        
2. **步骤 2：CPU 启动外设（打响发令枪！）**
    
    - CPU 在安顿好 DMA 之后，会紧接着执行一条专用的 `OUT` 指令。
        
    - 这条指令是直接发给**外设的 I/O 接口（如磁盘控制器）**的控制寄存器的！
        
    - 大白话：CPU 亲自给砖厂（外设）打电话：“现在，立刻，马上给我生产 1000 块砖！”
        
    - **打完这个电话，CPU 才算真正交接完任务，可以去干别的程序了。**
        
3. **步骤 3：外设苦逼地“备货”**
    
    - 磁盘接到 CPU 的命令，开始寻道、旋转，把磁头对准扇区。这是一个极其漫长的机械动作（几毫秒）。
        
    - 此时，DMA 管家在干嘛？他在旁边翘着二郎腿发呆，因为货还没造出来。
        
4. **步骤 4：外设请求 DMA（DREQ）**
    
    - 磁盘终于把第 1 块砖（数据）读出并放在了自己的数据缓冲寄存器里。
        
    - 此时，外设通过一根物理导线，向 DMA 发出请求：“货备好了，快来搬！”（这就回到了咱们上一节聊的第二阶段）。

### 💡 核心避坑点

在 408 考研中，如果你遇到了这样的判断题：

- **“DMA 传输过程完全不需要 CPU 的干预。”** $\rightarrow$ **错！** CPU 必须在传输**前**进行初始化并启动外设，在传输**后**处理 DMA 发来的中断。只是在**传输中**不需要 CPU 参与。
    
- **“外设是由 DMA 控制器启动的。”** $\rightarrow$ **错！** 绝大多数情况下，外设是由 CPU 执行 I/O 输出指令启动的。DMA 只负责在数据准备好之后抢总线、搬数据。



DMA 请求（DREQ）—— 不是中断 
设备准备好了一批数据要传，它向 DMA 控制器发出 DREQ（DMA Request）。DMA 控制器收到后，再向 CPU 发出 HOLD（总线请求）信号，意思是"把总线让给我用一下"。CPU 在当前总线周期结束后回应 HLDA（总线响应），交出总线控制权。

传输完成中断 —— 这才是真中断


一条指令可能包含取指、取操作数、存结果好几个总线周期
CPU 在每条指令执行的最后，会有一个固定的"中断查询"动作——检查有没有待处理的中断请求。如果有，才转去响应。
DMA 的响应粒度细得多：它的插入点是**存取周期之间**，也就是一个总线周期（机器周期）结束、下一个总线周期开始的间隙。这意味着 DMA 可以在一条指令执行的中途插进去。
