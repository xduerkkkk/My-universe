### 第 29 题：有符号转无符号

- **已知：** `si = -32767`

### 第 31 题：无符号转有符号

- **已知：** `usi = 65535`
    
- **目标：** 求对应的有符号数 `si`
    
- **秒杀法 1（用模算）：** 无符号大数转有符号负数，直接**减去模**。
    
    $65535 - 65536 = -1$
    
- **答案：** 直接选 **A**！
    
- **秒杀法 2（凭直觉）：** `65535` 是 16 位无符号数能表示的最大值，它的二进制必然是**全 1**（`1111...1111`）。而在补码世界里，**全 1 永远代表 -1**（你可以用我们刚才学的位权法算一下：$-32768 + 16384 + ... + 1 = -1$）。看到无符号最大值转有符号，闭眼选 -1。

只要遇到同位数的 signed 和 unsigned 强转：

1. 找出它们的模（8 位是 256，16 位是 65536，32 位是 $2^{32}$）。
    
2. **负数 $\rightarrow$ 无符号：加模**
    
3. **大的无符号 $\rightarrow$ 负数：减模**

### 一、 符号扩展的魔法：为什么补 `1` 值不变？

假设我们有一个 4 位的有符号负数 **-3**。

它的二进制补码是 `1101`。

用我们学过的“负权法”验证一下：$-8 + 4 + 0 + 1 = -3$。

现在，计算机要把这个 4 位的盒子，换成 8 位的盒子。规则说“前面全部补 `1`”。

于是变成了：`1111 1101`。

**见证奇迹的时刻到了，我们再用“负权法”算一遍这个 8 位数：**

|**位数**|**第7位**|**第6位**|**第5位**|**第4位**|**第3位**|**第2位**|**第1位**|**第0位**|
|---|---|---|---|---|---|---|---|---|
|**权重**|**-128**|64|32|16|**8**|4|2|1|
|**数值**|**1**|**1**|**1**|**1**|**1**|1|0|1|

- 后面三位 `101` 没变，依然贡献了 $4 + 0 + 1 = 5$。
    
- **核心看前面这些 `1`**：
    
    原本在 4 位系统里，第 3 位的权重是 **-8**。
    
    现在到了 8 位系统，第 3 位变成了普通正数，权重是 **+8**。而新的最高位变成了 **-128**。
    

我们把前面新补的 `1` 和原来变成正数的符号位加起来：

$-128 + 64 + 32 + 16 + 8 = \mathbf{-8}$

**看懂了吗？！**

神奇的二进制数学规律就在这里：$-2^n = -2^{m-1} + \sum_{i=n}^{m-2} 2^i$。

用人话说就是：**把一个负权重的位置往左边无限延伸补 `1`，这串新补的 `1` 加上原来那个位置变成的正权重，总和永远等于最初的那个负权重！**

所以，$-128 + 64 + 32 + 16 + 8$ 完美地还原了最初的那个 **-8**。整体数值 $-8 + 5 = -3$，依然分毫不差！

### 二、 “加减模”大法的底层逻辑：同一串数字的两种眼光

搞懂了负权重，我们再来看为什么同一串二进制，无符号和有符号之间刚好差了一个“模”。

还是用 4 位的 `1101` 为例。我们看看计算机用两种不同的“眼光”看它时，到底发生了什么变化：

|**眼光**|**第3位 (最高位)**|**第2位**|**第1位**|**第0位**|**最终计算结果**|
|---|---|---|---|---|---|
|**无符号 (Unsigned)**|权重是 **+8**|4|2|1|$\mathbf{+8} + 4 + 0 + 1 = \mathbf{13}$|
|**有符号 (Signed)**|权重是 **-8**|4|2|1|$\mathbf{-8} + 4 + 0 + 1 = \mathbf{-3}$|

仔细对比这两行计算，你会发现：

后面三位的计算（$4 + 0 + 1$）**完全一模一样**。

**唯一的区别，仅仅在于最高位那一个 `1` 的权重！**

- 无符号把它看成了 **+8**
    
- 有符号把它看成了 **-8**
    

那么，从 -8 变成 +8，中间差了多少？

$+8 - (-8) = \mathbf{16}$！

这不就是我们 4 位系统的 **“模” ($2^4 = 16$)** 吗？！

**结论呼之欲出：**

因为除了最高位，其他所有位的权重完全相同。而最高位在无符号下是正的 $2^{n-1}$，在有符号下是负的 $-2^{n-1}$。

它们俩的差值永远是 $2^{n-1} - (-2^{n-1}) = 2^n$。

**而 $2^n$ 就是这个系统的“模”！**

所以，当底层二进制位保持不变（比如都是 `1101`）时，你有符号（-3）转无符号（13），直接加上模（16）就可以了；反过来，无符号转有符号，直接减去模。

# 类型转换
你在上面看到的“全变成 `int`”，是因为所有运算都必须经过**第一阶段（整型提升）**。

在 408 计算机系统中，表达式中不同类型操作数混合运算时，硬件与编译器遵循一套**严格的两阶段规则**：

```
操作数 A, B 
   │
   ▼
【阶段 1：整型提升 (Integer Promotion)】
   凡是位宽 < int 的整型 (char, short, bool)，无条件提升为 int 或更高
   │
   ▼
【阶段 2：寻常算术转换 (Usual Arithmetic Conversions)】
   若提升后 A 和 B 的类型仍不一致，按照「类型优先级梯队」向高等级对齐
   │
   ▼
进入 ALU 执行相同位宽、相同符号属性的运算
```

---

### 阶段 1：整型提升（为什么小类型全变成 `int`）

* **硬件原因**：现代 CPU 的通用寄存器和 ALU 运算通路基本以 **32 位（或 64 位）** 为基本单位。CPU 不会为 8 位、16 位单独开辟独立的运算流水线，而是将它们先扩展到 32 位再送入 ALU。
* **规则**：
  * `char`（8 位）、`short`（16 位）在进入运算前，**无条件符号扩展**为 32 位的 `int`。
  * `unsigned char`、`unsigned short` 的取值范围（$[0, 65535]$）完全能被 32 位 `int`（$[-2^{31}, 2^{31}-1]$）容纳，因此**无条件零扩展**为 32 位的 `int`。
  * **结论**：只要类型小于 `int`，进 ALU 前第一步**必定全变成 `int`**。

---

### 阶段 2：寻常算术转换（类型对齐的完整梯队）

当两个操作数都达到 32 位及以上，但类型依然不同时，按以下**优先级从低到高**对齐：

$$\text{int} < \text{unsigned int} < \text{long} < \text{unsigned long} < \text{long long} < \text{float} < \text{double}$$

对齐的具体判定逻辑如下（从上到下匹配）：

#### 1. 包含浮点数
* 只要有一个操作数是浮点数，整型全部转换为浮点数，低精度浮点转高精度浮点（如 `int + double` $\rightarrow$ 全部转 `double`）。

#### 2. 全为整型（32 位及以上）
* **情况 A：符号相同**
  * 低等级转高等级（如 32 位 `int` + 64 位 `long long` $\rightarrow$ 转 64 位 `long long`）。
* **情况 B：位宽相同，一有符号、一无符号**
  * **带符号无条件转为无符号**（如 32 位 `int` + 32 位 `unsigned int` $\rightarrow$ 全部转 **`unsigned int`**）。
* **情况 C：位宽不同，一有符号（长）、一无符号（短）**
  * 若长的有符号类型能完全容纳短的无符号类型的所有值（例如 64 位 `long long` 容纳 32 位 `unsigned int`），则全部转为 **长有符号类型**（转 `long long`）。
  * 若容纳不下，则两者全部转为 **长类型的无符号版本**。
