### 一、传输层接收时也在做检验吗？

**是的，传输层接收方首先执行的就是校验和检验。**

- **验证算法**：接收方在内存中临时提取 IP 首部信息拼装成 **12 字节伪首部**，然后对 `伪首部 + 传输层首部 + 数据部分` 进行 16 位二进制反码求和。
- **校验失败的处理动作**：
  - **UDP**：直接**丢弃**该用户数据报（无确认，不重传）。
  - **TCP**：直接**丢弃**该报文段，**不发送 ACK 确认**，迫使发送方的超时重传定时器（RTO）到期后重传该报文段。

### 二、 发送方流水线：传输层 $\rightarrow$ 网络层（IP 层）

当应用层（如 HTTP 客户端）发起请求时，发送方的自顶向下封装与计算流程如下：

#### 1. 传输层（TCP / UDP）发送动作
1. **端口封装（多路复用 Multiplexing）**：
   - 提取应用进程绑定的本地动态端口（**源端口**）与服务器服务端口（**目的端口**，HTTP 为 80，HTTPS 为 443）。
2. **连接与流控控制（若为 TCP）**：
   - 将应用层数据流切分为大小不超过 **MSS（最大报文段长度）** 的数据块。
   - 填入本次发送的 **序号（Seq）**、期望对端回复的 **确认号（Ack）**、标志位（ACK、PSH 等）、接收窗口大小（`rwnd`）。
3. **计算校验和**：
   - 临时构造 12 字节伪首部（源 IP、目的 IP、全 0、协议号 6 或 17、TCP/UDP 长度）。
   - 将传输层首部的「校验和」字段置 0，计算 `伪首部 + 传输层首部 + 载荷` 的反码和并取反，写入「校验和」字段。
4. **下发**：将构造好的段（Segment）交付给网络层。

#### 2. 网络层（IPv4）发送动作
1. **首部封装**：
   - 填入 **源 IP 地址**、**目的 IP 地址**。
   - 填入 **协议号（Protocol）**（TCP 填 `6`，UDP 填 `17`）。
   - 设定初始 **TTL**（如 64 或 128）。
   - 设定 **标识（Identification）** 和标志位（DF、MF）。
2. **计算 IP 首部校验和**：
   - 将 IP「首部校验和」置 0，对 20~60 字节的 **IP 首部** 进行反码求和取反，填入字段。
3. **分片判断（源端分片）**：
   - 若 IP 数据报总长大于本端接口 MTU，且 $\text{DF}=0$，由源端网络层拆分成多个分片（计算各自的片偏移）。
4. **寻径下发**：查路由表确定下一跳，查 ARP 表获取下一跳 MAC，交付给数据链路层。

### 三、 接收方流水线：网络层（IP 层）$\rightarrow$ 传输层

当物理层和数据链路层确认 CRC 无误并剥离 MAC 头尾后，接收方的自底向上解封装与校验流程如下：

#### 1. 网络层（IPv4）接收动作
1. **IP 首部校验**：
   - 对整个 IP 首部进行 16 位反码求和，若结果不等于 `0xFFFF`，判定首部损坏，**立即丢弃**。
2. **目的地址匹配**：
   - 检查目的 IP 是否为本机接口 IP。若是则接收；若不是且本机未开启路由器转发功能，直接丢弃。
3. **分片重组（Reassembly）**：
   - **408 核心考点**：**IP 数据报的分片重组只在最终目的主机的网络层进行，中间路由器绝不重组。**
   - 检查标志位（MF）和片偏移（Offset）：若属于分片，按「标识（ID）」放入重组队列。当所有分片到齐后拼装成完整 IP 数据报；若重组定时器超时仍有分片未到，丢弃全部已到分片并向源端发送 ICMP 分片重组超时报文。
4. **协议分发（解复用）**：
   - 检查 IP 首部中的 **协议号（Protocol）** 字段：
     - 若为 `6` $\rightarrow$ 剥离 IP 首部，将载荷送给 **TCP 模块**；
     - 若为 `17` $\rightarrow$ 剥离 IP 首部，将载荷送给 **UDP 模块**。

#### 2. 传输层（TCP / UDP）接收动作
1. **校验和检验**：
   - 提取上层传递过来的 IP 首部参数，在内存拼凑 12 字节伪首部，对 `伪首部 + 传输层首部 + 载荷` 进行反码求和。
   - 结果不为 `0xFFFF` 则**直接丢弃**。
2. **多路分解（Demultiplexing，分发到套接字）**：
   - **UDP（二元组定位）**：根据 `(目的 IP, 目的端口号)` 找到对应的 UDP Socket，将数据推入其缓冲区。
   - **TCP（四元组定位）**：根据 **`(源 IP, 源端口, 目的 IP, 目的端口)`** 四元组，精确定位已经建立好连接的那个具体套接字（Connected Socket）。
3. **TCP 状态机与可靠性维护（若为 TCP）**：
   - **序号检查与乱序重排**：检查 `Seq`，若按序到达则移入接收缓冲区；若乱序到达则暂存并等待空缺报文（选择确认 SACK）。
   - **滑动窗口更新**：根据接收缓冲区剩余空间计算新的 `rwnd`（接收窗口）。
   - **发送确认（ACK）**：生成包含期望接收的下一序号 `ack = seq + payload_len` 的 ACK 报文返回给发送方。
4. **交付应用层**：
   - 剥离传输层首部，操作系统唤醒阻塞在 `read()` / `recv()` 系统调用上的应用进程（如 Web 服务器的 Nginx/Apache），进程从 Socket 接收缓冲区读取纯净的 HTTP 请求文本。

### 四、 发送/接收全流程 408 考点速记矩阵

| 层次                | 发送方核心动作                             | 接收方核心动作                                                         | 错误/异常处理                        |
| :---------------- | :---------------------------------- | :-------------------------------------------------------------- | :----------------------------- |
| **网络层 (IP)**      | 填首部、算 **IP 首部校验和**、定 TTL、查路由/ARP    | 验证 **IP 首部校验和**、匹配目的 IP、**目的端分片重组**、按 Protocol 字段分发             | 校验和错直接丢弃；重组超时丢弃发 ICMP          |
| **传输层 (TCP/UDP)** | 填端口、算 **伪首部+首部+数据校验和**、切分 MSS (TCP) | 验证 **伪首部+首部+数据校验和**、按 **四元组/二元组** 多路分解到 Socket、乱序重排与回 ACK (TCP) | 校验和错丢弃；TCP 丢弃后不回 ACK 触发发送端超时重传 |
