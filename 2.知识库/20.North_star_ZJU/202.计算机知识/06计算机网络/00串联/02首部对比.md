以下从 **嵌套关系、关键数值规律、横向维度对比、各层特征总结** 四个方面进行结构化梳理：

---

### 一、 报文的自顶向下嵌套关系

每一层都在上一层数据的前面（或后面）加装本层的首部：

```text
[ 以太网 MAC 帧头 (14B) ] ──┬──────────────────────────────────────────────────────────┬── [ FCS (4B) ]
                             │  [ IP 首部 (20~60B) ] ──┬────────────────────────────┐  │
                             │                          │ [ TCP (20~60B) / UDP (8B) ]│  │
                             │                          │ [ 应用层数据 (Payload)    ]│  │
                             │                          └────────────────────────────┘  │
                             └──────────────────────────────────────────────────────────┘
```

---

### 二、 408 核心数字与计算单位对比（极高频考点）

这是做选择题和计算题最容易混淆的地方，总结为**“三个乘数法则”**：

| 计算单位                      | 涉及的字段                                  | 字段位宽   | 实际字节数换算                        | 考点数值范围                                                  |
| :------------------------ | :------------------------------------- | :----- | :----------------------------- | :------------------------------------------------------ |
| **$\times \text{ 4 字节}$** | • **IP 首部长度**<br>• **TCP 数据偏移**（即首部长度） | 4 bit  | $\text{字段值} \times 4\text{ B}$ | 字段取值 $5 \sim 15$ $\implies$ 首部长度 $20 \sim 60\text{ 字节}$ |
| **$\times \text{ 8 字节}$** | • **IP 片偏移** (Fragment Offset)         | 13 bit | $\text{字段值} \times 8\text{ B}$ | 除了最后一个分片，每个分片的数据长度必须是 **8B 的整数倍**                       |
| **$\times \text{ 1 字节}$** | • **IP 总长度**<br>• **UDP 长度**           | 16 bit | $\text{字段值} \times 1\text{ B}$ | 最大理论长度均为 $2^{16}-1 = 65535\text{ 字节}$                   |

### 三、 四大关键功能横向对比

#### 1. 寻址字段（Address）
* **MAC 帧**：**48 bit（6 字节）**（源 MAC + 目的 MAC） $\to$ 用于**局域网相邻节点逐跳寻址**。
* **IP 首部**：**32 bit（4 字节）**（源 IP + 目的 IP） $\to$ 用于**跨网络端到端主机寻址**。
* **TCP / UDP 首部**：**16 bit（2 字节）**（源端口 + 目的端口） $\to$ 用于**主机内具体进程寻址**。

#### 2. 分用标识（指出上一层把数据交由谁处理）
每层首部都有一个字段，负责告诉上一层协议栈“里面装的是什么协议”：
* **MAC 帧中的「类型」字段（2B）**：指出网络层协议（如 `0x0800` 代表 IPv4，`0x0806` 代表 ARP）。
* **IP 首部中的「协议」字段（8bit）**：指出传输层协议（如 `6` 代表 TCP，`17` 代表 UDP，`1` 代表 ICMP）。
* **TCP/UDP 首部中的「目的端口」字段（16bit）**：指出应用层服务（如 `80` 代表 HTTP，`53` 代表 DNS）。

#### 3. 差错检验机制对比
* **MAC 帧（FCS 字段）**：**CRC 算法**，校验范围是**整个 MAC 帧**。
* **IP 首部（首部检验和）**：**反码求和**，校验范围**仅包含 IP 首部**（不校验数据）。
* **UDP / TCP（检验和）**：**反码求和**，校验范围是**伪首部 + 首部 + 数据**（端到端全覆盖）。

### 四、 四类报文的本质特征与记忆口诀

#### 1. 以太网 V2 MAC 帧（14B 首部 + 4B 尾部）
* **组成**：目的 MAC(6B) + 源 MAC(6B) + 类型(2B) + 数据(46~1500B) + FCS(4B)。
* **边界条件**：
  * **MTU（最大传输单元）** $= 1500\text{ 字节}$。
  * **最小有效数据** $= 46\text{ 字节}$（因为 CSMA/CD 要求以太网最小帧长为 $64\text{ 字节}$，$64 - 18 = 46$）。

#### 2. IPv4 数据报（20B 固定 + 0~40B 可选）
* **核心功能**：**路由转发与分片**。
* **分片三大件**：
  * **标识（16bit）**：属于同一个原始数据报的分片拥有相同标识。
  * **标志（3bit）**：`DF=1`（不允许分片）；`MF=1`（后面还有分片），`MF=0`（最后一个分片）。
  * **片偏移（13bit）**：该分片在原报文中的位置（以 8B 为单位）。
* **转发三大件**：`TTL`（每跳减 1）、`协议号`、`首部检验和`。

#### 3. TCP 报文段（20B 固定 + 0~40B 可选）
* **核心功能**：**可靠传输、流量控制与拥塞控制**。
* **字段全服务于机制**：
  * 可靠传输 $\to$ `序号 seq` (32bit)、`确认号 ack` (32bit)。
  * 控制连接状态 $\to$ `6 位标志位`（URG, **ACK**, PSH, RST, **SYN**, **FIN**）。
  * 流量控制 $\to$ `接收窗口 rwnd` (16bit)。
  * 变长首部指示 $\to$ `数据偏移` (4bit, 单位 4B)。

#### 4. UDP 数据报（固定 8 字节）
* **核心特征**：**极简无连接**。
* **结构仅 4 字段（每个 2 字节）**：
  $$\text{源端口 (2B)} + \text{目的端口 (2B)} + \text{UDP 长度 (2B)} + \text{UDP 检验和 (2B)} = 8\text{ 字节}$$
* **注意点**：UDP 检验和是**可选的**（不想算可以全填 0，但如果算出来刚好为 0 则必须填全 1）。
