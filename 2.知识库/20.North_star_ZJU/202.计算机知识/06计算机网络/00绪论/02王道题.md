B 选项（计算机网络）：
定义：将地理位置不同、功能自治的独立计算机系统通过通信线路连接起来。

定义：建立在网络之上的分布式软件系统。
关键词“协同与透明”：分布式系统中的多台物理计算机通过网络连接，但对用户而言是透明的（用户感知不到背后有多台机器），它们被调度来共同完成同一个大任务（例如分布式计算 MapReduce、分布式数据库）。

   你在备考 408 时觉得乱，是因为**题目选项中的“口语化表达”**和**教材中“官方严谨学术术语”**混在了一起。

必须为你明确区分**两种完全不同的概念**：

---

### 1. 官方严格学术术语：“发送时延”（Transmission Delay）

*   **标准命名**：**发送时延**（旧教材或部分翻译曾写为“传输时延”）。
*   **精确公式**：
    $$t_{\text{发送}} = \frac{\text{分组长度 } L}{\text{信道带宽 } R}$$
*   **物理含义**：指网卡或路由器**把数据比特推入信道**所花费的时间，只发生在设备内部。
*   **特性**：只要分组大小 $L$ 和带宽 $R$ 固定，这 1 个分组的发送时延就是**固定**的。

---

### 2. 题目选项中的口语表达：“传输数据的总耗时”（Total Delay / Transfer Time）

*   **俗称/题干用词**：“传输时延”或“传输期间的时延”。
*   **精确术语**：应该叫**端到端总时延（Total End-to-End Delay）**。
*   **构成**：$\text{总时延} = \text{发送时延} + \text{传播时延} + \text{处理时延} + \text{排队时延}$。
*   **物理含义**：从源端**开始发第一比特**，到目的端**完整接收完最后一个比特**所经历的**整体总耗时**。

---

### 还原 06 题中的真实含义

王道这道题中的“传输时延”**全都是指【概念 2：传输数据的总耗时】**，而不是【概念 1：发送时延 $L/R$ 】。

#### 1. 第 ① 空：“为了使数据在传输期间的时延最小，首选电路交换”
*   **这里的“时延”**：指从 A 送到 B 的**总耗时（概念 2）**。
*   **原因**：电路交换建立通路后，数据直达，**排队时延为 0、处理时延为 0、中间节点的二次发送时延为 0**。因此**总耗时最小**。

#### 2. 第 ④ 空：“分组交换对报文交换的改进产生的直接结果是：减少传输时延”
*   **这里的“传输时延”**：依然指整份文件传完的**总耗时（概念 2）**。
*   **为什么绝对不是指概念 1（发送时延 $L/R$）？**
    *   分组交换切包后，每个分组都**增加了首部控制字节**。
    *   如果看单包发送时延 $L/R$，因为总比特数变多，**发送时延（概念 1）反而变大了**！
    *   但因为**流水线并行（Pipelining）**机制，中间路由器不需要等待完整文件即可边收边发，**整份数据的端到端总耗时（概念 2）大幅减少了**。选项 C 说的就是这个“总耗时减少”。

---

### 解题避坑规则

*   当题目问**“计算发送时延”**或给出公式 $\frac{L}{R}$ 时，指严格的**发送时延（Transmission Delay）**。
*   当题目在做交换方式对比（如电路、报文、分组交换对比）并出现“**传输时延最小 / 减少传输时延**”时，指**整份数据传输完成的端到端总耗时（Total Delay）**。
  
  因此，分组交换相比报文交换，**直接结果是“减少了传输时延（端到端总时延）**
7. A
   #### 分组交换内部的两种服务模式（数据报 vs 虚电路）

当你决定采用**分组交换**（即把长数据切成小包）之后，网络层（Network Layer）在传输这些小包时，又有**两种不同的设计路线**：

- **路线 A：数据报方式（Datagram）**
    
    - **描述对象**：分组交换网络。
        
    - **设计思想**：**网状分散、无连接**。把包发出去就不管了，每个包独立寻址，谁先到谁后到、走哪条路都不保证。
        
    - **现实落地**：我们今天使用的**整个 Internet（互联网 / IP 协议）**，用的就是分组交换里的数据报方式。
        
- **路线 B：虚电路方式（Virtual Circuit）**
    
    - **描述对象**：分组交换网络。
        
    - **设计思想**：**借用电路交换思想的面向连接分组传输**。虽然数据依然是切成小包转发，但发包前必须先建立一条逻辑上的“虚电路”，所有包必须严格沿着这条虚电路按顺序传送。
        
    - **现实落地**：早期的电信网（如 X.25、ATM、帧中继）以及广域网流量工程（MPLS）。


这道题的**正确答案是 A**。

很多初学者觉得难懂，是因为没有搞懂**数据报（Datagram）**最根本的底层工作机制。以下为你逐项拆解这道题的每一个选项：

---

### 一、核心机制拆解（为什么选 A）

*   **A 选项（正确）**：同一报文的不同分组可以经过不同的传输路径通过通信子网。
    *   **底层机制**：数据报方式是**无连接（Connectionless）**的。
    *   源主机把长报文切分成多个分组后，**每个分组都独立写上了完整的源 IP 和目的 IP**。
    *   当分组到达路由器时，路由器对**每一个分组独立查找转发表、独立选择路径**。
    *   因为不同时刻网络拥塞情况不同，**分组 1 可能走路径甲，分组 2 可能走路径乙**。这是数据报方式最根本的物理特征。

---

### 二、错误选项排查

*   **B 选项（错误）**：同一报文的不同分组到达目的节点时顺序是确定的。
    *   **错在哪**：因为各个分组走的路径不同、沿途路由器的排队时间不同，后发出的分组完全可能先到达，即产生**乱序（Out-of-order）**或**丢失**。到达顺序是**不确定**的。
    *   *注：能够“保证按序到达”的是**虚电路（Virtual Circuit）**方式。*

*   **C 选项（不准确/非核心特征）**：适合于短报文的通信。
    *   **错在哪**：虽然数据报没有建连开销，对突发短数据很方便，但**长报文切包后同样广泛采用数据报传输**（整个互联网的 IP 协议都是数据报方式）。因此这不能作为区分数据报的核心特征。

*   **D 选项（错误）**：同一报文的不同分组在路由选择时只需要进行一次。
    *   **错在哪**：这是**虚电路（Virtual Circuit）**的特点！
    *   虚电路只在“呼叫建立”阶段进行**一次路由选择**，确定一条固定路径。
    *   而在数据报方式中，如果有 $N$ 个分组，路由器就要对这 $N$ 个分组分别独立查找转发表，**进行 $N$ 次路由选择**。

---

### 三、一表总结（408 秒杀此类题目）

| 对比维度     | **数据报方式（Datagram）**    | **虚电路方式（Virtual Circuit）** |
| :------- | :--------------------- | :------------------------- |
| **连接建立** | **无需建立连接**             | **必须先建立虚电路连接**             |
| **路由选择** | **每个分组独立路由（进行 $N$ 次）** | **建连时仅进行一次路由选择**           |
| **传输路径** | 各分组路径**可能不同**          | 所有分组路径**完全相同**             |
| **到达顺序** | **可能乱序、重复、丢失**         | **严格按序到达**                 |
| **分组首部** | 包含**完整源/目的 IP**        | 仅包含**虚电路号（VCID）**          |

	现在我们把**发送（挤）**和**传播（滑行）**结合起来，依然只看文件里**最末尾的那一个比特**。
	
	**第一步：H1 把所有数据挤出门（H1 的发送时延）**
	
	- 文件大小 $x = 1\text{ MB} = 1 \times 10^6\text{ B} = 8 \times 10^6\text{ bit}$。
	    
	- H1 埋头苦干，挤完所有数据耗时：$\frac{8 \times 10^6\text{ b}}{100 \times 10^6\text{ b/s}} = 0.08\text{ s} = 80\text{ ms}$。
	    
	- **此时状态（$80\text{ ms}$ 时刻）：** 最后一个比特刚刚离开了 H1 的网卡，进入了第一段网线。
	    
	
	**第二步：最后一个比特在第一段网线上飞驰（第 1 段传播时延）**
	
	- 它需要花时间飞到路由器。
	    
	- 耗时：就是我们刚算的单向传播时延 **$0.01\text{ ms}$**。
	    
	- **此时状态（$80.01\text{ ms}$ 时刻）：** 最后一个比特抵达路由器。此时整个“最后一个分组”都被路由器完整接收了。
	    
	
	**第三步：路由器把最后一个分组挤出门（路由器的发送时延）**
	
	- 路由器现在要把这最后的 $1000\text{ B}$ 分组发往 H2。
	    
	- 分组大小 $p = 1000\text{ B} = 8000\text{ bit}$。
	    
	- 路由器挤出这个分组耗时：$\frac{8000\text{ b}}{100 \times 10^6\text{ b/s}} = 0.00008\text{ s} = 0.08\text{ ms}$。
	    
	- **此时状态（$80.09\text{ ms}$ 时刻）：** 最后一个比特离开了路由器，进入了第二段网线。
	    
	
	**第四步：最后一个比特在第二段网线上飞驰（第 2 段传播时延）**
	
	- 它需要花时间从路由器飞到 H2。
	    
	- 耗时：又是 **$0.01\text{ ms}$**。
	    
	- **此时状态（$80.10\text{ ms}$ 时刻）：** 最后一个比特终于抵达 H2！大功告成！
	    
	
	### 3. 总结
	
	总时间 = H1 发送时延 ($80$) + 第 1 段传播 ($0.01$) + 路由器发送最后分组 ($0.08$) + 第 2 段传播 ($0.01$) = **$80.10\text{ ms}$**。
	
	所以，本题正确答案是 **D**。

    网络层（第 3 层）接收来自上一层（传输层）的数据，将其封装成**“分组（Packet / 数据报）”**，并在头部增加第 3 层的逻辑地址（IP 地址）和控制信息
    传输层确实负责增加可靠性和流控制信息，但它封装出来的数据单元叫做**“数据段（Segment / 报文段）”**，而不是“数据帧（Frame）”。“数据帧”是数据链路层的专有名词。
    源和目的的**端口信息**（用于区分不同应用程序）是由**传输层**添加的。表示层的功能是数据的格式转换、加密解密和压缩，不负责分割数据和加端口。

	*   **核心知识点**：服务访问点（SAP，Service Access Point）。
	*   **一句话定义**：**第 N 层提供给第 N+1 层调用的“逻辑接口”或“地址标识”。** 
	*   **解题逻辑**：
	    我们需要清楚网络体系结构中每一层往上提供的 SAP 到底是什么（这是 408 选择题的固定对应关系）：
	    1.  **数据链路层的 SAP** $\rightarrow$ **MAC 地址**（网络层通过 MAC 地址调用链路层服务）。所以 D 错。
	    2.  **网络层的 SAP** $\rightarrow$ **IP 地址**（传输层通过 IP 地址调用网络层服务）。所以 C 错。
	    3.  **传输层的 SAP** $\rightarrow$ **端口号（Port）**（应用层通过端口号区分不同的网络进程）。
	    4.  **应用层的 SAP** $\rightarrow$ **用户接口（User Interface）**。应用层已经是体系结构的最高层，它的“上一层”就是实际使用网络的人或者外部应用程序。因此，应用层提供给用户的调用接口就是“用户接口”（A 选项）。
	*   **干扰项**：B 选项“网卡接口”是物理层面的硬件接口，而 SAP 是体系结构中的逻辑抽象概念，直接排除。
	
	**记忆矩阵：**
	*   链路层 SAP = MAC 地址
	*   网络层 SAP = IP 地址
	*   传输层 SAP = 端口号
	*   应用层 SAP = 用户接口
