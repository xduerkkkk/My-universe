## 章节主线

```text
应用进程协作模型
  ├─ C/S 与 P2P
  ├─ DNS：名字 → 地址/服务记录
  ├─ FTP：控制连接 + 数据连接
  ├─ 电子邮件：SMTP + POP3/IMAP + MIME
  └─ Web：URL、HTTP、连接模式、缓存与 RTT
```

应用层定义应用进程之间交换的报文格式、字段语义、交互顺序和错误处理。它通常借助传输层 socket 通信，但“应用层的持续/非持续”不能与“传输层的面向连接/无连接”混为一谈。

## 1. 网络应用模型

| 模型 | 核心结构 | 优点 | 代价 |
|---|---|---|---|
| C/S | 客户端主动请求，服务器提供稳定服务 | 易管理、易控制、服务集中 | 服务器可能成为瓶颈与单点 |
| P2P | 对等方既请求也提供资源 | 自扩展、利用边缘资源 | 管理、安全、发现与稳定性更复杂 |

模型是**逻辑进程关系**，与底层物理拓扑没有一一对应关系。同一设备可在不同会话中扮演不同角色。

## 2. DNS

### 2.1 名称空间与资源记录

DNS 是层次化分布式数据库。域名由标签组成，越靠右层次越高。常见记录：

| 类型 | 作用 |
|---|---|
| A | 域名→IPv4 |
| AAAA | 域名→IPv6 |
| NS | 区域的权威 DNS |
| MX | 邮件交换服务器 |
| CNAME | 别名→规范名 |
| PTR | 反向解析 |

域名、IP、主机、MAC 均非一一对应。DNS 管名称与资源记录，不负责私网/公网地址转换。

### 2.2 服务器角色

- **本地/递归 DNS**：主机第一查询点，代查并缓存。
- **根服务器**：返回 TLD 服务器线索。
- **TLD 服务器**：返回目标区域权威服务器线索。
- **权威服务器**：对本区域记录给出权威答案。
- **转发器**：把查询转交上游，是部署角色而不是名称层级。

### 2.3 递归、迭代与缓存

- **递归**：被查询者负责得到最终答案或错误。
- **迭代**：被查询者返回当前知道的最佳线索，查询方继续问下一台服务器。
- **缓存**：按 TTL 保存结果，降低时延与上级负载；TTL 到期后需要重新查询。

### 2.4 UDP/TCP 边界

常规查询常用 UDP 53；区域传送以及 UDP 截断后的重试使用 TCP 53。传统 512B 限制只适用于未扩展 UDP DNS；现代部署还有 EDNS(0)、DoT、DoH 等。408 默认按经典 UDP/TCP 规则作答。

## 3. FTP

### 3.1 两条连接

| 连接 | 用途 | 典型持续时间 | 端口 |
|---|---|---|---|
| 控制连接 | 命令、状态码、登录与目录操作 | 会话期间保持 | 服务器 TCP 21 |
| 数据连接 | 文件或目录列表 | 每次传输建立/释放 | 主动模式服务器 TCP 20；被动模式服务器临时端口 |

FTP 的“带外控制”指控制和数据分离到不同连接，不是 TCP URG/OOB。

### 3.2 主动与被动模式

- **主动**：客户端告知数据端口，服务器从 20 端口主动连接客户端；可能被客户端防火墙拦截。
- **被动**：服务器开放临时端口，客户端主动连接，更适合 NAT/防火墙环境。

## 4. 电子邮件

### 4.1 架构

```text
发送方用户代理
   ↓ SMTP 提交
发送方邮件服务器
   ↓ SMTP 中转
接收方邮件服务器
   ↓ POP3 / IMAP / Webmail
接收方用户代理
```

### 4.2 协议对比

| 协议 | 方向/用途 | 经典端口 | 关键词 |
|---|---|---:|---|
| SMTP | 提交、服务器间中转 | 25 | 推送 |
| POP3 | 下载邮件 | 110 | 简单拉取 |
| IMAP | 服务器端同步管理 | 143 | 多端同步 |
| MIME | 内容格式与编码扩展 | — | 附件、非 ASCII、多媒体 |

MIME 不负责把邮件从一台服务器送到另一台；它扩展邮件报文可表达的内容。

## 5. 万维网与 HTTP

### 5.1 基本对象

- **URL**：协议、主机、端口、路径等资源定位信息。
- **Web 页面**：基础 HTML 加若干引用对象。
- **HTTP**：请求/响应协议；经典模型为无状态，状态可借 Cookie/Session 等机制维持。

### 5.2 非持续与持续连接

| 模式 | TCP 复用 | 典型代价 |
|---|---|---|
| 非持续 | 每个对象新建连接 | 握手多、慢启动反复 |
| 持续非流水线 | 单连接复用，逐个请求 | 少握手，但仍串行等待 |
| 持续流水线 | 单连接连续发多个请求 | RTT 更少，但有队头阻塞等问题 |
| 并行非持续 | 多条 TCP 同时传对象 | 时延折叠，但连接多 |

HTTP/1.x 经典题通常基于 TCP；HTTP/2 也基于 TCP并采用多路复用；HTTP/3 基于 QUIC/UDP。做题要按版本和题设判断。

### 5.3 RTT 公式（经典小对象模型）

假设 1 个 HTML + N 个内嵌小对象，忽略 DNS 与发送时延：

| 模式 | RTT |
|---|---:|
| 非持续串行 | `2 + 2N` |
| 非持续完全并行 | `4` |
| 持续非流水线 | `N + 2` |
| 持续流水线 | `3` |

这里 1RTT 用于 TCP 建连，1RTT 用于请求与首字节响应。第三次握手 ACK 可捎带 HTTP 请求。

### 5.4 时间题扩展条件

- DNS 查询是否计时、缓存是否命中。
- TCP 是否已建立、计时从何时开始。
- 对象大小、链路带宽和发送时延是否可忽略。
- 初始 cwnd、MSS、接收窗口和慢开始需要几轮。
- 图片是否可并行、并行连接数量是否受限。
- FIN 是否与最后数据/ACK 合并，是否计 TIME_WAIT。

## 6. NAT/NAPT 的应用层题背景

NAT 虽常在 Web 题中出现，但机制属于网络边界转发：

- 内网新连接无映射时动态分配公网端口并建表。
- 回包按公网目的端口反查内网地址与端口。
- 无映射的外部主动连接通常不能进入，静态映射/端口转发是例外。
- NAPT 修改 TCP/UDP 端口，破坏严格分层透明性。

## 7. PDU 名称与封装

| 层 | 常用 PDU 名称 |
|---|---|
| 应用层 | 报文 Message |
| TCP | 报文段 Segment |
| UDP | 用户数据报 Datagram |
| IP | 数据报/分组 Packet |
| 数据链路层 | 帧 Frame |
| 物理层 | 比特 Bit |

帧通常既有首部又有尾部/FCS；IP Total Length 不包含以太网首尾；传输层首部也不包含 IP 首部。

## 8. 校正与条件

> [!warning] “客户端面向用户，服务器面向任务”
> **校正**：定义应看谁主动请求、谁提供服务；面向用户/任务只是一种类比。

> [!warning] “根服务器管顶级域、顶级服务器管二级域”
> **校正**：这是考试记忆近似。真实 DNS 依据区域委派，权威边界不必严格每个标签一级一台服务器。

> [!warning] “DNS 客户端与服务器根本不用 TCP”
> **校正**：常规短查询常用 UDP，但 DNS 标准支持 TCP；区域传送、截断重试等使用 TCP。

> [!warning] “HTTP 必定基于 TCP”
> **校正**：HTTP/1.x 与 HTTP/2 经典实现基于 TCP；HTTP/3 基于 QUIC/UDP。408 传统题按题设版本作答。

> [!warning] “FTP 数据连接使用服务器 20 端口”
> **校正**：只对主动模式的经典数据连接成立；被动模式使用服务器临时端口。

> [!warning] “POP3 一定下载后删除”
> **校正**：下载并删除是经典工作方式之一，客户端也可选择在服务器保留副本；不能写成协议绝对要求。

## 9. 绝对词检查

- **“一个域名只有一个 IP”**：CDN、负载均衡和容灾会返回多个地址。
- **“本地 DNS 就是权威 DNS”**：角色可以重合，但通常不同。
- **“非持续就是无连接”**：非持续 HTTP 仍可在每个对象前建立 TCP。
- **“并行 N 个对象耗时乘 N”**：理想完全并行按关键路径计时，不直接相加。
- **“NAT 无表项一定丢弃”**：出站新连接会动态建表；无映射的入站才通常丢弃。
