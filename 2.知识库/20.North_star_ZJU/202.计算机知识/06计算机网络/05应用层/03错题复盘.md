## 主动回忆卡

### 网络应用模型

#### 来源：网络模型 4—5｜客户端/服务器与 P2P 是逻辑关系

**自测**
- C/S 模型中的客户端和服务器如何区分？
- 应用层模型与物理网络拓扑是否一一对应？

> [!faq]- 核对
> - **客户端**：主动发起请求的一方；**服务器**：长期或按需提供服务、响应请求的一方。
> - **角色可变化**：同一主机在不同应用或不同时刻可以既是客户端又是服务器。
> - **P2P**：节点之间可直接提供和请求服务，通常具有更强的自扩展性，但管理、安全和可用性控制更复杂。
> - **逻辑模型**：C/S、P2P 描述应用进程的协作方式，不由底层物理拓扑是星形、树形还是网状直接决定。
> - **校正**：“客户端面向用户、服务器面向任务”只能作粗略记忆，不是定义。

### DNS

#### 来源：DNS 1—2｜域名、IP、主机与 MAC 的对应关系

**自测**
- 一个域名能否对应多个 IP？多个域名能否对应同一 IP？
- 域名层次与物理子网是否必须一致？

> [!faq]- 核对
> - **一域名→多 IP**：负载均衡、CDN、容灾、就近访问。
> - **多域名→一 IP**：虚拟主机、反向代理；HTTP Host 或 TLS SNI 帮助服务器区分站点。
> - **域名与主机**：都不是一一对应；一台主机可承载多个域名，一个域名也可指向集群。
> - **域名与子网**：域名是应用层管理层次，IP 子网是网络层编址结构，二者没有必然同构关系。
> - **MAC**：链路层接口标识，不参与全球 DNS 名称层次。

#### 来源：DNS 4｜DNS 系统由哪些角色构成？

**自测**
- 域名空间、域名服务器、解析器分别做什么？

> [!faq]- 核对
> - **域名空间与资源记录**：定义层次化名称树以及 A、AAAA、NS、MX、CNAME 等数据。
> - **域名服务器**：保存某些区域的数据并回答查询；权威服务器对所管理区域给出权威答案。
> - **解析器 resolver**：代表应用发起查询，可能调用本地递归 DNS 并利用缓存。
> - **整体性质**：DNS 是层次化、分布式数据库，不是“私网 IP 与公网 IP 的转换器”；后者是 NAT/NAPT。

#### 来源：DNS 5、9｜本地、递归、代理、权威、根与顶级服务器

**自测**
- 本地域名服务器一定权威吗？“代理 DNS”又是什么角色？
- 根、TLD、权威服务器分别能回答到什么层次？

> [!faq]- 核对
> - **本地 DNS**：主机配置的第一查询点，通常提供递归查询与缓存；不一定对用户查询的域名权威。
> - **代理/转发 DNS**：把请求转发给上游解析器，是一种工作方式，不是固定层级名称。
> - **根服务器**：给出顶级域服务器线索；**TLD 服务器**：给出目标域的权威服务器线索；**权威服务器**：保存该区域的正式资源记录。
> - **易错点**：“根管顶级域、顶级管二级域”是记忆近似；DNS 实际按委派和区域边界工作，不保证每一级都严格对应域名标签层数。

#### 来源：DNS 批注、万维网 1｜DNS 为什么常用 UDP，何时用 TCP？

**自测**
- 常规 DNS 查询默认使用什么传输层协议？
- 哪些经典场景会转用 TCP？

> [!faq]- 核对
> - **408 经典模型**：常规短查询/响应通常使用 UDP 53，避免连接建立开销。
> - **TCP 经典场景**：区域传送；UDP 响应被截断（TC=1）后重新用 TCP 查询。
> - **512B 边界**：是未使用 EDNS(0) 时的传统 UDP DNS 报文限制，不能写成现代 DNS 永久固定上限。
> - **现代边界**：DNS 本身同时定义 UDP/TCP 传输，另有 DoT/DoH 等部署方式；做 408 题按题设和经典模型判断。

### FTP

#### 来源：FTP 2｜控制连接与数据连接

**自测**
- FTP 为什么要两条 TCP 连接？21 和 20 分别在什么条件下使用？

> [!faq]- 核对
> - **控制连接**：客户端临时端口→服务器 TCP 21，传命令和响应，通常贯穿整个会话。
> - **数据连接**：传目录或文件，每次传输可重新建立。
> - **主动模式**：服务器通常从 TCP 20 主动连到客户端指定端口。
> - **被动模式**：服务器返回一个临时端口，由客户端主动连接；此时服务器数据端口不固定为 20。
> - **校正**：“FTP 数据连接永远使用服务器 20 端口”只适用于经典主动模式。

#### 来源：FTP 全组｜带外控制与有状态会话

**自测**
- “带外控制”在 FTP 中是什么意思？
- 数据连接断开后控制连接是否必须断开？

> [!faq]- 核对
> - **带外控制**：控制命令与文件数据走不同 TCP 连接，不是 TCP 紧急数据 OOB 的含义。
> - **控制连接**：可持续保持登录状态和当前目录等会话信息。
> - **数据连接**：按一次目录列表或文件传输建立/关闭，不要求控制连接同步关闭。
> - **易错点**：两条连接都使用 TCP；不能因为“数据连接临时”就说 FTP 面向无连接。

### 电子邮件

#### 来源：电子邮件全组、视频批注｜SMTP、POP3、IMAP、MIME

**自测**
- 发件、服务器中转、收件分别使用什么协议？
- MIME 是传输协议吗？

> [!faq]- 核对
> - **SMTP**：用于用户代理提交邮件及邮件服务器之间推送/中转，经典端口 25；提交服务常见 587，但 408 主要记 25。
> - **POP3**：客户端从服务器拉取邮件，经典端口 110；功能较简单。
> - **IMAP**：在服务器端管理邮件和文件夹，适合多端同步，经典端口 143。
> - **MIME**：扩展邮件内容格式和编码，使非 ASCII 文本、附件、图片等可封装进邮件；它不是替代 SMTP 的独立传输协议。
> - **方向记忆**：SMTP 推，POP3/IMAP 拉或同步。

#### 来源：电子邮件视频｜SMTP 对话与邮件路径

**自测**
- 一封跨域邮件从发送者到接收者经历哪些节点？
- SMTP 常见命令顺序是什么？

> [!faq]- 核对
> - **路径**：发送方用户代理→发送方邮件服务器→接收方邮件服务器→接收方用户代理。
> - **中转**：邮件服务器之间用 SMTP；接收方读取通常用 POP3/IMAP 或 Webmail 的 HTTP/HTTPS。
> - **命令骨架**：HELO/EHLO → MAIL FROM → RCPT TO → DATA → QUIT。
> - **易错点**：邮件正文中的 From/To 首部与 SMTP 信封命令 MAIL FROM/RCPT TO 属于不同层次。

### 万维网与 HTTP

#### 来源：万维网 1｜“非持续连接”不等于“面向无连接”

**自测**
- HTTP 非持续连接为什么仍然是面向连接？
- 哪些 HTTP 版本使用 TCP，HTTP/3 呢？

> [!faq]- 核对
> - **非持续连接**：每传完一个或少量对象就关闭 TCP，下一对象需重新建连接；它描述应用层连接复用策略。
> - **面向连接**：描述承载协议是否先建立传输状态。经典 HTTP/1.0、HTTP/1.1 和 HTTP/2 基于 TCP，所以仍面向连接。
> - **现代边界**：HTTP/3 基于 QUIC，而 QUIC 运行在 UDP 上；因此“所有 HTTP 永远基于 TCP”已不成立。
> - **408 语境**：若题目只讨论非持续/持续 HTTP 和 RTT，通常按 HTTP/1.x over TCP 模型。

#### 来源：万维网 11｜非持续 HTTP + 并行连接 RTT

**自测**
- 获取 1 个 HTML 和 7 个小图，非持续 HTTP 且图片可完全并行，至少多少 RTT？

> [!faq]- 核对
> - **HTML 阶段**：1RTT 建 TCP + 1RTT 请求并收到 HTML，共 2RTT。
> - **依赖**：浏览器先拿到并解析 HTML，才能知道 7 个图片 URL。
> - **图片阶段**：7 条连接并行建立 1RTT，并行请求/接收 1RTT，共 2RTT。
> - **总计**：`2+2=4RTT`，忽略对象传输时延与 DNS 时延。
> - **易错点**：HTML 与内嵌对象不能从 t=0 就并行。

#### 来源：万维网 11｜四种经典 HTTP RTT 公式

**自测**
- 获取 1 个 HTML + N 个小对象时，四种经典模式的 RTT 公式是什么？

> [!faq]- 核对
> - **非持续、串行**：`2 + 2N`。
> - **非持续、完全并行**：`2 + 2`，前提是 N 条连接可同时建立与传输。
> - **持续、非流水线**：`1 TCP握手 + 1 HTML + N = N+2`。
> - **持续、流水线**：`1 TCP握手 + 1 HTML + 1 批量对象 = 3`。
> - **条件**：均忽略 DNS、对象发送时延、连接并发上限和拥塞控制；实际题目给了这些条件时必须另算。

#### 来源：万维网 14、18｜HTTP + TCP 慢开始时间线

**自测**
- 从“主机请求建立 TCP 连接”开始计时，与从“连接建立成功”开始计时差几个阶段？
- 第三次握手能否捎带 HTTP 请求？

> [!faq]- 核对
> - **从发 SYN 开始**：首先计入 1RTT 完成前两次握手；第三次 ACK 可捎带 HTTP 请求。
> - **从连接建立成功开始**：不再重复计算握手 RTT。
> - **数据传输**：服务器能在每轮发送多少数据，取决于题设的初始 cwnd、MSS、接收窗口和 ACK 时机。
> - **关闭**：FIN 可与最后数据或 ACK 合并，必须按题图时间线判断。
> - **易错点**：不先圈出题目计时起点，就会稳定多算或少算 1RTT。

#### 来源：万维网 15｜NAT/NAPT 动态建表

**自测**
- 内网新四元组没有 NAT 表项时，路由器应做什么？
- 外网主动入站没有映射时是否都能转发？

> [!faq]- 核对
> - **新出站连接**：分配未占用的公网转换端口，新增映射，修改源 IP/源端口并转发。
> - **已有映射**：复用对应表项，不与其他内网连接产生端口冲突。
> - **入站响应**：按公网目的端口命中映射后还原内网目的地址。
> - **无映射入站**：通常丢弃；若配置静态 NAT、端口转发或 PCP/UPnP 等映射，则可例外。
> - **跨层性**：NAPT 修改 IP 和 TCP/UDP 端口，需要重算相关校验和。

### 协议数据单元

#### 来源：王道视频万维网｜报文、报文段、数据报、分组、帧

**自测**
- HTTP、TCP、UDP、IP、以太网各自的 PDU 常叫什么？

> [!faq]- 核对
> - **应用层**：报文 message，如 HTTP 请求报文、SMTP 邮件报文。
> - **TCP**：报文段 segment；**UDP**：用户数据报/datagram。
> - **IP**：IP 数据报或分组 packet。
> - **数据链路层**：帧 frame，通常包含首部和尾部/FCS。
> - **物理层**：比特 bit。
> - **边界**：术语在不同教材中偶有泛化用法，答题优先服从题目所在层次。

## 大题通用模板

### DNS 解析路径

1. **识别**：问递归/迭代、缓存、服务器角色还是耗时。
2. **已知与目标**：列本地 DNS、根、TLD、权威服务器以及缓存是否命中。
3. **步骤**：主机→本地 DNS；本地 DNS 依次获得委派线索，最终取权威记录并缓存。
4. **条件分支**：递归查询由被问服务器继续代查；迭代查询返回下一步线索。
5. **自检**：本地 DNS 不等于权威服务器，根通常不直接给最终主机 IP。
6. **常见失分**：把 DNS 与 NAT 混淆、把域名层次机械等同物理网络层次。

### HTTP RTT

1. **识别**：持续/非持续、并行/串行、流水线、对象数量、DNS、传输时延。
2. **已知与目标**：圈出计时起点，是发 SYN 还是已建立连接。
3. **步骤**：先获取 HTML，再按模式处理内嵌对象；并行任务按最大路径耗时而不是求和。
4. **条件分支**：第三次握手可捎带请求；TCP 慢开始、带宽和对象大小可能增加额外 RTT/发送时延。
5. **自检**：HTML 依赖不能提前并行，总耗时单位统一。
6. **常见失分**：把非持续当 UDP、把 N 条并行连接仍乘 N、漏算 DNS 或重复算握手。
