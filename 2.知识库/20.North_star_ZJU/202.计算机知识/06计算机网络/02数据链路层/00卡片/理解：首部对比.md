![[_attachments/image/首部对比-1786605142478.jpeg]] ![[_attachments/image/首部对比-1786605162633.jpeg]] 死记硬背这三个首部的字段是毫无意义的，也是极易混淆的。在 408 考试中，记忆这三个首部最好的方法是**基于“封装与解封装”的自顶向下/自底向上逻辑，以及它们各自要解决的核心问题来进行横向对比**。

你可以把首部字段拆解为以下 **6 个功能维度**进行关联记忆：

### 1. 寻址机制（Who to Who?）
每一层都要解决“从哪来，到哪去”的问题，寻址字段占据了大量空间。
*   **以太网（链路层）：目的 MAC 地址 (6B) + 源 MAC 地址 (6B)**
    *   **记忆点：** 以太网是**唯一一个把目的地址放在最前面的协议**。这是因为交换机在硬件转发时，只要读到前 6 字节的目的 MAC，就可以立刻查表并开始转发（直通交换），能极大地降低延迟。
*   **IPv4（网络层）：源 IP 地址 (4B) + 目的 IP 地址 (4B)**
    *   **记忆点：** 位于固定首部的最底部（第 13-20 字节）。先源后目的。
*   **TCP（传输层）：源端口号 (2B) + 目的端口号 (2B)**
    *   **记忆点：** 位于首部的最顶部（第 1-4 字节）。先源后目的。

### 2. 向上交付/多路复用（What is inside?）
接收端拆开本层首部后，需要知道里面的数据该交给上层的哪一个协议，这就是多路复用/分解。
*   **以太网：类型 (2B)**。例如 `0x0800` 代表里面装的是 IP 数据报，`0x0806` 代表 ARP。
*   **PPP：协议 (2B)**。作用同上，例如 `0x0021` 代表 IP。
*   **IPv4：协议 (1B)**。例如 `6` 代表交由 TCP 处理，`17` 代表 UDP。
*   **TCP：无此字段**。因为 TCP 靠**目的端口号**直接把数据交给特定的应用层进程了。

### 3. 差错检测（Did it break?）
网络传输不可靠，每一层对错误的处理范围不同。
*   **以太网/PPP：帧校验序列 FCS (4B/2B)**。
    *   **记忆点：** 位于帧的**尾部**（因为是边发边计算 CRC，算完直接追加在最后）。校验范围是**整个帧**（首部+数据载荷）。
*   **IPv4：首部检验和 (2B)**。
    *   **记忆点：** 仅校验 **IP首部**，不校验数据。原因：IP 每经过一个路由器，TTL 都要减 1，首部必须重新计算校验和。如果连带长达几千字节的数据一起校验，路由器计算压力太大，严重拖慢转发速度。
*   **TCP：检验和 (2B)**。
    *   **记忆点：** 校验范围是 **伪首部 + TCP首部 + TCP数据载荷**。它是端到端的可靠性保障。

### 4. 长度与边界（How big?）
由于数据长短不一，必须告诉接收方“首部有多长”、“总数据有多长”。**（注意：这三个字段的单位是 408 必考死穴）**
*   **以太网：无长度字段**。因为物理层有帧间距机制（以太网）或帧定界符（PPP 的标志字段 `0x7E`），硬件可以直接识别帧的结束。只需要记住数据载荷的限制：**MTU = 46B ~ 1500B**。
*   **IPv4：**
    *   **首部长度 (4 bit)：** 单位是 **4B (32位字)**。因为首部最小 20B，所以该字段最小值是 5。
    *   **总长度 (16 bit)：** 单位是 **1B**。最大表示 65535 字节。
*   **TCP：**
    *   **数据偏移 (4 bit)：** 本质就是 TCP 首部长度。单位也是 **4B (32位字)**。最小值也是 5（对应 20B 固定首部）。

### 5. 分片与分段（Too big to send?）
当 IP 报文大于以太网的 1500B MTU 时，必须切开。
*   **IPv4（网络层分片）：** 独占一行（第 5-8 字节）。
    *   **标识 (16 bit)：** 同一个大报文切出来的所有小片，标识号相同。
    *   **标志 (3 bit)：** DF位（Don't Fragment，是否允许分片），MF位（More Fragment，后面还有没有分片）。
    *   **片偏移 (13 bit)：** 当前分片在原报文中的位置。单位是 **8B**。
*   **TCP（传输层分段）：** 不依赖 IP 首部的字段，而是通过 **序号 (Seq, 32 bit)** 来标识当前 TCP 段的数据第一个字节的编号。

### 6. 各层独有核心机制（Why does this layer exist?）
剩下的字段，就是该层协议之所以存在的独有灵魂，也是该层最复杂的机制：
*   **IPv4 独有 —— 路由防环：生存时间 TTL (1B)**。每经过一个路由器减 1，为 0 则丢弃并发送 ICMP，防止报文在网络里无限循环死锁。
*   **TCP 独有 —— 可靠与控速：**（占了 TCP 首部极大的空间）
    *   **确认号 Ack (32 bit)：** 期望收到对方下一个报文段的第一个数据字节的序号。
    *   **6个控制位 (URG, ACK, PSH, RST, SYN, FIN)：** 决定 TCP 的状态机流转（建连、断连、强制重置等）。
    *   **窗口 Window (16 bit)：** 流量控制的核心，告诉对方“我现在的接收缓存还能装多少字节”。

---
**总结你的记忆流：**
拿到一个报文，先看最外层以太网（找 MAC，查 MTU，尾部查全帧 CRC）；扒掉外皮看到 IP 层（查源/目IP，减 TTL，看是否分片，只校验 IP 头部）；再扒掉 IP 皮看到 TCP 层（查源/目端口，看 Seq/Ack 保证可靠，看 Window 控制速度）。 把它们的共性（地址、校验、长度单位）横向对比，就能精准记住所有的细节。
