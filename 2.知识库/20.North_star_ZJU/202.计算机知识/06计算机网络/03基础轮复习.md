# 访问一个网页的全流程考研版知识树

核心主线：

```text
主机接入网络
→ DHCP 获取配置
→ DNS 解析域名
→ 判断目标是否同网段
→ ARP 获取下一跳 MAC
→ 封装数据
→ TCP 三次握手
→ HTTP/HTTPS 请求
→ 路由器逐跳转发 / NAT
→ 服务器解封装并响应
→ 响应数据返回主机
```

你要把它看成一棵树：

```text
访问网页总流程
├── 主机如何获得网络身份
├── 主机如何找到服务器 IP
├── 主机如何找到下一跳
├── 数据如何封装
├── 数据如何跨网络转发
├── TCP 如何保证可靠通信
├── HTTP 如何请求网页
└── 返回数据如何找到原主机和原进程
```

---

# 0. 总抓手：先区分两条线

这一点最重要。

## 线 1：端到端逻辑线

```text
浏览器进程  →  Google Web 服务器进程
```

这条线关心：

```text
域名、IP、端口、TCP、HTTP/HTTPS
```

比如：

```text
你的浏览器 192.168.1.10:50000
→
Google 服务器 142.xxx.xxx.xxx:443
```

---

## 线 2：逐跳转发线

```text
你的主机
→ 默认网关
→ 运营商路由器
→ 骨干网路由器
→ Google 网络
→ Google Web 服务器
```

这条线关心：

```text
MAC 地址、帧、ARP、路由器、路由表、NAT
```

一句话记：

```text
IP + 端口：服务于端到端通信
MAC + 帧：服务于逐跳转发
```

# 1. 主机刚接入网络：先获得网络配置

## 发生了什么？

你的电脑 / 手机刚连上网，还没有可用的 IP 地址。  
它需要通过 DHCP 获取网络配置。

---

## 涉及协议

```text
DHCP = Dynamic Host Configuration Protocol
动态主机配置协议
```

DHCP 属于应用层协议，通常使用 UDP。

```text
DHCP 客户端端口：UDP 68
DHCP 服务器端口：UDP 67
```

---

## DHCP 给主机什么？

通常给：

```text
IP 地址
子网掩码
默认网关
DNS 服务器地址
租期
```

不是只给 IP。

---

## DHCP 四步：DORA

```text
Discover
Offer
Request
ACK
```

时间轴：

```text
主机                     DHCP服务器
 | ---- Discover ------> |   我需要一个 IP
 | <---- Offer --------- |   我可以给你 192.168.1.10
 | ---- Request -------> |   我选这个地址
 | <---- ACK ----------- |   确认分配成功
```

---

## 重点细节

主机一开始没有 IP，所以 Discover 通常这样封装：

```text
源 IP：0.0.0.0
目的 IP：255.255.255.255
源端口：UDP 68
目的端口：UDP 67
目的 MAC：FF:FF:FF:FF:FF:FF
```

这是广播。

---

## 常见陷阱

### 陷阱 1：DHCP 服务器不一定是路由器

家庭网络中常常是家用路由器兼任 DHCP 服务器。  
但学校、公司网络中，可能是专门的 DHCP 服务器，也可能经过 DHCP 中继。

### 陷阱 2：默认网关不是“整个路由器”

默认网关更准确是：

```text
主机所在局域网中，路由器那个接口的 IP 地址
```

例如：

```text
主机 IP：192.168.1.10
默认网关：192.168.1.1
```

这个 `192.168.1.1` 是路由器 LAN 口的 IP。

---

## 这里该复习的下级知识点

```text
【DHCP DORA 流程】
【UDP 67/68】
【广播地址 255.255.255.255】
【DHCP 租期与续租】
【DHCP 中继】
【默认网关】
```

# 2. 用户输入域名：主机要先做 DNS 解析

## 发生了什么？

用户输入：

```text
https://www.google.com
```

主机不能直接根据域名发 IP 数据报。  
它要先把域名转换为 IP 地址。

---

## 涉及协议

```text
DNS = Domain Name System
域名系统
```

普通 DNS 查询通常使用：

```text
UDP 53
```

也可能使用 TCP 53。

---

## DNS 的作用

DNS 主要做：

```text
域名 → IP 地址
```

例如：

```text
www.google.com → 142.xxx.xxx.xxx
```

---

## 重点纠错

目的端口 443 不是 DNS 给的。

```text
目的 IP：DNS 解析得到
目的端口：应用协议决定
```

例如：

```text
http://example.com      → 默认端口 80
https://example.com     → 默认端口 443
https://example.com:8443 → 端口 8443
```

---

## DNS 查询前可能先查缓存

顺序大致是：

```text
浏览器缓存
→ 操作系统缓存
→ 本地 DNS 服务器缓存
→ 根域名服务器
→ 顶级域服务器
→ 权威域名服务器
```

考研中常考：

```text
递归查询
迭代查询
```

---

## 常见陷阱

### 陷阱 1：DNS 不是只用 UDP

常规查询多用 UDP 53。  
但响应太长、区域传送等场景可能用 TCP 53。

### 陷阱 2：DNS 解析的是 IP，不是 MAC

DNS 不会告诉你 Google 的 MAC 地址。  
MAC 地址只在本地链路内有意义。

---

## 这里该复习的下级知识点

```text
【DNS 递归查询】
【DNS 迭代查询】
【DNS 缓存】
【A、AAAA、CNAME、MX 记录】
【根域名服务器、顶级域服务器、权威域名服务器】
【DNS 使用 UDP/TCP 的区别】
```

# 3. 主机判断目的 IP 是否在同一网段

## 发生了什么？

DNS 返回目标 IP 后，主机要判断：

```text
目标 IP 和我是不是同一个局域网？
```

例如：

```text
本机 IP：192.168.1.10
子网掩码：255.255.255.0
目标 IP：142.xxx.xxx.xxx
```

发现不在同一个网段。

于是主机决定：

```text
把数据交给默认网关
```

---

## 判断规则

主机用：

```text
本机 IP 与子网掩码按位与
目标 IP 与子网掩码按位与
```

如果结果一样，说明同网段。  
如果结果不同，说明不同网段。

---

## 两种情况

### 情况 1：目的主机在同一网段

```text
直接 ARP 查询目的主机的 MAC
```

例如：

```text
192.168.1.10 → 192.168.1.20
```

主机问：

```text
谁是 192.168.1.20？
```

---

### 情况 2：目的主机不在同一网段

```text
ARP 查询默认网关的 MAC
```

例如访问 Google：

```text
192.168.1.10 → 142.xxx.xxx.xxx
```

主机问的不是 Google 的 MAC，而是：

```text
谁是 192.168.1.1？
```

也就是默认网关的 MAC。

---

## 常见陷阱

### 陷阱 1：访问外网时，目的 MAC 不是外网服务器 MAC

主机发出的第一跳帧是：

```text
目的 IP：Google 服务器 IP
目的 MAC：默认网关 MAC
```

这一点非常重要。

### 陷阱 2：主机也有路由表

不是只有路由器有路由表。  
主机也要根据自己的路由表判断：

```text
直连网络怎么走
默认路由怎么走
```

---

## 这里该复习的下级知识点

```text
【子网掩码】
【CIDR】
【网络号与主机号】
【同网段判断】
【默认路由】
【主机路由表】
```

---

# 4. ARP：根据 IP 找下一跳 MAC

## 发生了什么？

主机已经知道：

```text
目标 IP 是 Google
下一跳是默认网关
默认网关 IP 是 192.168.1.1
```

但发链路层帧必须知道目的 MAC。  
所以要通过 ARP 查询网关 MAC。

---

## 涉及协议

```text
ARP = Address Resolution Protocol
地址解析协议
```

作用：

```text
已知同一局域网内某个 IP，查询它的 MAC 地址
```

---

## ARP 流程

```text
主机广播：
谁是 192.168.1.1？请告诉 192.168.1.10。

路由器单播回复：
192.168.1.1 的 MAC 是 aa:bb:cc:dd:ee:ff。
```

---

## ARP 请求和应答

ARP 请求：

```text
广播
目的 MAC：FF:FF:FF:FF:FF:FF
```

ARP 应答：

```text
单播
目的 MAC：请求者的 MAC
```

---

## 常见陷阱

### 陷阱 1：ARP 只在同一链路内工作

ARP 不跨路由器。

所以访问 Google 时，主机不会 ARP 查询 Google 的 MAC。

### 陷阱 2：ARP 是 IP 到 MAC，不是域名到 IP

```text
DNS：域名 → IP
ARP：IP → MAC
```

两个不要混。

---

## 这里该复习的下级知识点

```text
【ARP 请求广播】
【ARP 应答单播】
【ARP 缓存】
【ARP 表】
【同网段 ARP 目标主机】
【不同网段 ARP 默认网关】
```

---

# 5. 浏览器准备发送数据：操作系统开始封装

## 发生了什么？

浏览器要访问网页，先构造应用层数据。  
如果是 HTTP：

```text
HTTP 请求报文
```

如果是 HTTPS：

```text
HTTP 数据先经过 TLS 加密
```

---

## 谁负责封装？

不是“端口负责封装”，也不是“网卡独自封装全部”。

大致是：

```text
浏览器 / 应用程序
→ 操作系统协议栈
→ 网卡驱动
→ 网卡发送
```

---

## 不考虑 HTTPS 时的封装

```text
HTTP 报文
↓
TCP 段
↓
IP 数据报
↓
链路层帧
↓
物理信号
```

---

## 考虑 HTTPS 时的封装

```text
HTTP 报文
↓
TLS 记录
↓
TCP 段
↓
IP 数据报
↓
链路层帧
↓
物理信号
```

---

## 每层主要加什么？

### TCP 层

加 TCP 首部：

```text
源端口
目的端口
序号 seq
确认号 ack
窗口大小
标志位 SYN/ACK/FIN
校验和
```

形成：

```text
TCP 段
```

---

### IP 层

加 IP 首部：

```text
源 IP
目的 IP
TTL
协议字段
首部校验和
分片相关字段
```

形成：

```text
IP 数据报
```

---

### 数据链路层

如果是以太网，加以太网首部和尾部：

```text
源 MAC
目的 MAC
类型字段
FCS
```

形成：

```text
以太网帧
```

如果是 Wi-Fi，则封装成 802.11 帧。

---

## 一次请求中的地址大概是这样

假设：

```text
本机 IP：192.168.1.10
本机临时端口：50000
Google IP：142.xxx.xxx.xxx
Google HTTPS 端口：443
默认网关 MAC：aa:bb:cc:dd:ee:ff
本机 MAC：11:22:33:44:55:66
```

第一跳发出的帧：

```text
链路层：
源 MAC：11:22:33:44:55:66
目的 MAC：aa:bb:cc:dd:ee:ff

网络层：
源 IP：192.168.1.10
目的 IP：142.xxx.xxx.xxx

传输层：
源端口：50000
目的端口：443
```

重点：

```text
目的 MAC 是默认网关
目的 IP 是 Google
```

---

## 常见陷阱

### 陷阱 1：源端口不是 443

客户端源端口通常是临时端口，例如：

```text
50000、49152、53001
```

服务器端口才通常是：

```text
HTTP：80
HTTPS：443
DNS：53
```

### 陷阱 2：链路层帧不是端到端的

链路层帧只负责一跳。  
到了路由器，原来的帧会被拆掉，重新封装下一跳的帧。

---

## 这里该复习的下级知识点

```text
【封装与解封装】
【TCP 首部】
【IP 首部】
【以太网帧格式】
【五元组】
【Socket】
【临时端口】
【HTTP 与 HTTPS 封装区别】
```

# 6. TCP 三次握手：建立端到端连接

## 发生了什么？

在发送 HTTP 请求前，浏览器要先和 Google 服务器建立 TCP 连接。

通信双方是：

```text
本机 TCP 端：192.168.1.10:50000
Google TCP 端：142.xxx.xxx.xxx:443
```

---

## 三次握手

```text
客户端                          服务器
  | -------- SYN ------------> |
  | <----- SYN + ACK --------- |
  | -------- ACK ------------> |
```

---

## 每一次握手都要封装吗？

要。

每一个 TCP 段都要封装成：

```text
TCP 段
↓
IP 数据报
↓
链路层帧
```

而且每经过一个路由器，链路层帧都会换。

---

## 三次握手建立的是和谁的连接？

不是和默认网关建立 TCP 连接。  
默认网关只是转发。

TCP 连接是：

```text
你的主机 ↔ Google Web 服务器
```

也就是端到端逻辑连接。

---

## 常见陷阱

### 陷阱 1：路由器通常不参与 TCP 连接本身

路由器只看 IP 层，负责转发 IP 数据报。  
它不会和你一起完成 TCP 三次握手。

当然，NAT 路由器会修改地址和端口，但它不是 TCP 连接的最终端。

### 陷阱 2：TCP 连接建立后，HTTP 才发送

HTTP 依赖 TCP。  
HTTPS 还要在 TCP 后进行 TLS 握手。

---

## 这里该复习的下级知识点

```text
【TCP 三次握手】
【seq 和 ack】
【SYN、ACK 标志位】
【为什么不是两次握手】
【TCP 状态转换】
【HTTPS 中的 TLS 握手】
```

# 7. 第一跳：主机把帧交给默认网关

## 发生了什么？

主机已经封装好了适合本地链路的帧，然后发给默认网关。

---

## 有线和无线不同

### 如果主机通过网线连接路由器

使用以太网相关技术：

```text
IEEE 802.3
```

可能封装成以太网帧。

---

### 如果主机通过 Wi-Fi 连接路由器

使用无线局域网：

```text
IEEE 802.11
```

封装成 802.11 帧，不是普通以太网帧。

---

## CSMA/CD 和 CSMA/CA

### CSMA/CD

```text
Carrier Sense Multiple Access with Collision Detection
载波监听多路访问 / 冲突检测
```

传统共享式有线以太网使用。  
现代交换式全双工以太网中，基本不再真正需要它。

---

### CSMA/CA

```text
Carrier Sense Multiple Access with Collision Avoidance
载波监听多路访问 / 冲突避免
```

无线局域网使用。

因为无线设备一般难以一边发送一边检测冲突，所以主要是避免冲突。

---

## 常见陷阱

### 陷阱 1：不是所有链路都用以太网帧

从你家到 Google 服务器，中间可能经过：

```text
Wi-Fi
以太网
光纤链路
运营商内部链路
数据中心网络
```

每一段链路都可能有自己的链路层协议。

### 陷阱 2：我们学以太网，是因为它是最典型的局域网技术

不是因为整个互联网都只跑以太网帧。

---

## 这里该复习的下级知识点

```text
【IEEE 802.3】
【IEEE 802.11】
【以太网帧】
【无线局域网帧】
【CSMA/CD】
【CSMA/CA】
【冲突域】
【广播域】
【交换机和集线器区别】
```

# 8. 路由器收到帧：拆帧、查 IP、转发

## 发生了什么？

默认网关收到主机发来的帧后：

```text
拆掉链路层帧
取出 IP 数据报
查看目的 IP
查路由表
决定下一跳
重新封装新的链路层帧
发出去
```

---

## 路由器的核心动作

```text
拆帧
↓
看 IP 目的地址
↓
TTL 减 1
↓
查路由表
↓
最长前缀匹配
↓
确定下一跳
↓
重新封装帧
↓
转发
```

---

## TTL

```text
TTL = Time To Live
生存时间
```

每经过一个路由器，TTL 减 1。  
如果减到 0，丢弃，并可能返回 ICMP 差错报文。

作用：

```text
防止分组在网络中无限循环
```

---

## 路由表和最长前缀匹配

路由器根据目的 IP 查路由表。  
如果多条路由都匹配，选前缀最长的。

这叫：

```text
Longest Prefix Matching
最长前缀匹配
```

---

## 常见陷阱

### 陷阱 1：路由器不关心 HTTP 内容

路由器通常不看 HTTP 请求内容。  
它主要看 IP 首部。

### 陷阱 2：路由器每一跳都重新封装帧

IP 数据报跨越多个网络。  
链路层帧只在当前链路有效。

---

## 这里该复习的下级知识点

```text
【路由器工作层次】
【路由表】
【最长前缀匹配】
【TTL】
【ICMP】
【IP 数据报格式】
【逐跳转发】
```

---

# 9. NAT：家用路由器把私有地址改成公网地址

## 发生了什么？

家庭网络中，你的主机通常使用私有地址：

```text
192.168.x.x
10.x.x.x
172.16.x.x ~ 172.31.x.x
```

这些地址不能直接在公网路由。

所以家用路由器会做 NAT。

---

## NAT 全称

```text
NAT = Network Address Translation
网络地址转换
```

更具体地，家庭网络常用的是：

```text
NAPT = Network Address and Port Translation
网络地址与端口转换

PAT = Port Address Translation
端口地址转换
```

---

## NAT 做了什么？

修改前：

```text
源 IP：192.168.1.10
源端口：50000
目的 IP：142.xxx.xxx.xxx
目的端口：443
```

修改后：

```text
源 IP：路由器公网 IP
源端口：NAT 分配的转换端口
目的 IP：142.xxx.xxx.xxx
目的端口：443
```

同时建立 NAT 表：

```text
公网 IP:转换端口  ↔  内网 IP:内网端口
```

例如：

```text
205.56.79.35:2056 ↔ 192.168.1.10:50000
```

---

## 返回数据怎么回来？

Google 服务器返回：

```text
源 IP：142.xxx.xxx.xxx
源端口：443
目的 IP：205.56.79.35
目的端口：2056
```

NAT 路由器查表，发现：

```text
2056 ↔ 192.168.1.10:50000
```

于是改成：

```text
目的 IP：192.168.1.10
目的端口：50000
```

再发回内网主机。

---

## 常见陷阱

### 陷阱 1：NAT 表不是提前给所有主机规划好的

通常是连接产生时临时建立。

### 陷阱 2：源端口是 80 时，要警惕它可能是服务器响应

客户端访问 Web 服务器通常是：

```text
客户端临时端口 → 服务器 80/443
```

服务器响应通常是：

```text
服务器 80/443 → 客户端临时端口
```

所以看到：

```text
源端口 = 80
```

往往说明这是 Web 服务器发出的响应，而不是普通客户端请求。

# 10. 中间多个路由器：逐跳转发直到 Google 网络

## 发生了什么？

数据不会一根线直接连到 Google。

它会经过很多网络：

```text
家庭网络
→ 运营商接入网
→ 城域网
→ 骨干网
→ Google 边缘网络
→ Google 数据中心
```

每一跳都做类似操作：

```text
收帧
拆帧
看 IP
查路由表
TTL 减 1
重新封装
发给下一跳
```

---

## 中间可能涉及的路由协议

考研中网络层会讲：

```text
RIP
OSPF
BGP
```

它们不是主机访问网页时每个分组都携带的东西，而是路由器之间用来维护路由表的协议。

---

## 三个协议定位

```text
RIP：基于距离向量，适合小型网络
OSPF：基于链路状态，自治系统内部使用
BGP：自治系统之间使用，互联网核心路由协议
```

---

## 常见陷阱

### 陷阱 1：路由协议和被转发的数据报不是一回事

普通数据报只是被路由表转发。  
路由协议是路由器之间用来生成和维护路由表的。

### 陷阱 2：IP 源地址和目的地址一般不变

除 NAT 等特殊情况外，中间路由器转发时，IP 源地址和目的地址通常不变。

变化的是：

```text
每一跳的源 MAC、目的 MAC
TTL
链路层帧
```

```text
【分组交换】
【逐跳转发】
【RIP】
【OSPF】
【BGP】
【自治系统 AS】

```

# 11. Google Web 服务器收到数据：逐层解封装

## 发生了什么？

数据到达 Google 服务器所在网络后，最终被服务器网卡接收。

服务器开始解封装：

```text
链路层帧
↓
IP 数据报
↓
TCP 段
↓
TLS 记录
↓
HTTP 请求
```

---

## 服务器如何知道交给哪个进程？

靠目的端口。

例如：

```text
目的端口 443
```

操作系统把数据交给监听 443 端口的服务器进程。

---

## 这就是“分用”

传输层有两个方向：

### 发送时：复用

多个进程的数据都交给 TCP/UDP，统一往下传。

```text
多个应用进程 → TCP/UDP → IP
```

### 接收时：分用

收到数据后，根据端口号交给对应进程。

```text
IP → TCP/UDP → 对应应用进程
```

---

## 常见陷阱

### 陷阱 1：服务器是主机，真正处理请求的是进程

更准确说：

```text
Google Web 服务器进程处理 HTTP/HTTPS 请求
```

### 陷阱 2：目的端口定位的是进程，不是主机

主机由 IP 定位。  
进程由端口定位。

---

```text

【进程与端口】
【复用与分用】
【Socket】
【五元组】
【HTTP 请求报文】
【HTTP 响应报文】
```


# 15. 最后给你一版“考试级口述答案”

你可以练到能顺口说出这段：

```text
主机接入网络后，首先通过 DHCP 获取 IP 地址、子网掩码、默认网关、DNS 服务器等配置。用户在浏览器输入域名后，主机通过 DNS 将域名解析为目的 IP 地址。随后主机根据自己的 IP 地址、子网掩码和目的 IP 地址判断目的主机是否在同一网段。如果不在同一网段，则将数据交给默认网关。

为了把数据交给默认网关，主机需要通过 ARP 获取默认网关的 MAC 地址。之后浏览器产生 HTTP 请求，操作系统协议栈依次封装为 TCP 段、IP 数据报和链路层帧。TCP 连接建立时需要三次握手，握手报文同样会经过封装和逐跳转发。

链路层帧只在一跳内有效。路由器收到帧后拆掉链路层首部，查看 IP 数据报的目的 IP，TTL 减 1，查路由表并根据最长前缀匹配选择下一跳，然后重新封装为适合下一跳链路的帧继续转发。若主机使用私有地址访问公网，家庭路由器还会进行 NAT/NAPT，将内网 IP 和端口映射为公网 IP 和转换端口。

数据最终到达 Web 服务器后，服务器逐层解封装，根据目的端口将数据交给对应的 Web 服务进程。服务器生成 HTTP 响应后，再经过相反方向的封装、转发和 NAT 映射返回客户端，客户端最终将响应交给浏览器进行解析和渲染。
```

这一段你背熟后，计网的很多碎知识点就能挂上去了。
