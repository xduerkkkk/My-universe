## 一、数制与编码

### 1.1 🔴 "当且仅当"与0的陷阱（数制-13）
题目说"当且仅当"——要特别注意 **0 也是偶数**这一情况。审题时"当且仅当"意味着充要条件，漏掉 0 就错了。

### 1.2 ⚠️ 移码的偏置值（数制-22 · !!）
**核心：Bias（偏置值）不是固定的！可设为 128 或 127。**

- 移码计算：实际数值 = 二进制无符号整数值 − 偏置值
- 给定 2 个 `0` 和 6 个 `1`（共 8 位）：
  - **最小无符号数**（小数字放高位）：`00111111` = 63
  - **最大无符号数**（1 放高位）：`11111100` = 252
  - 偏置值 127 时：最小值 = 63−127 = **−64** ✓（验证选项 A）
  - 偏置值 128 时：最大值 = 252−128 = 124（不是 123），所以 B 错
- **补码最小值**（2 个 0、6 个 1）：`10011111` = −128+31 = **−97**（不是 −96）
- **补码最大值**：`01111110` = **126**（不是 252）

### 1.3 🔴 有符号↔无符号转换规则（数制-34）
**短有符号 → 长无符号，分两步：**
1. 先做大小提升（如 16位→32位），因为原类型是有符号数，**必须符号扩展**。此步真值不变。
2. 再做类型重新解释（有符号→无符号），**二进制机器码完全不变**，直接按无符号数读。

## 二、运算方法和电路

### 2.1 ⚠️ 算术左移（运算-7 · !!）
**算术左移：最高位不管是什么，直接丢弃。** 没有补位操作（与逻辑左移不同）。

### 2.2 🔴 溢出判断电路（运算-8）
ALU 中溢出判断用**异或门（XOR）**实现：
- 单符号位：$C_s \oplus C_1$（符号位进位 ⊕ 最高数值位进位）
- 双符号位：$S_{f1} \oplus S_{f2}$（两个符号位不同说明溢出）
- 译码/编码电路 → 指令系统或 I/O 的活，不是运算器必需品。
- 移位电路 → 通常用 MUX 或桶形移位器实现，不由基本门决定。

### 2.3 🔴 模 2 补码 vs 模 4 补码（运算-11）
- **模 2 补码**：单符号位。模 = $2^1 = 2$，符号位 1 位（0=正，1=负）。
- **模 4 补码**：双符号位（变形补码）。模 = $2^2 = 4$，符号位 2 位（00=正，11=负）。
- **存储与运算的区别**：存储时只保留 1 个符号位（节省空间）；送入 ALU 运算时，将单符号位**复制一份**扩展为双符号位。

### 2.4 双符号位法与进位看法的等价性（运算-13）
双符号位法和"符号位进位、最高位进位一起看"道理相同——本质都是检测 $C_s \oplus C_1$。

### 2.5 🔴 逻辑左移与溢出（运算-17）
**逻辑左移时，最高位移出的是 1，则溢出。**（逻辑移位不保留符号意义。）

### 2.6 🔴 有符号/无符号混用（运算-22）
**有符号和无符号混用时，全部强制当成无符号数处理！**

C 语言类型转换规则：
1. 先做整型提升（小于 int → int），对齐硬件。
2. 同为有符号/无符号 → 转到宽度更高的。
3. 一个有符号、一个无符号，且无符号宽度 ≥ 有符号 → **有符号数被转成无符号类型**。

**比较大小的底层：** 无符号→看 **CF（借位标志）**，有符号→看 **OF（溢出标志）+ SF（符号位）**。

### 2.7 ⚠️ CF 和 OF 的底层计算（运算-31 · !!）
给定 $R1 = \text{FFFF FFFFH}, R2 = \text{FFFF FFF0H}$，执行 $R1 - R2$：

**CF（借位标志）——无符号视角：**
- $R1$ 是无符号最大值 (2³²−1)，$R2$ 比它小 15。够减 → **CF = 0**。
- 口诀：「小减大」→需要借位 ↔ 大的减小的 → 够减。

**OF（溢出标志）——有符号视角：**
- 两者最高位都是 1 → 都是负数。$R1 = -1$，$R2 = -16$。
- $(-1) - (-16) = 15$，在 32 位安全范围 [−2³¹, 2³¹−1] 内 → **OF = 0**。
 
**加法器视角验证：**
- 减法 = $A + \sim B + 1$，$C_{out}=1$。
- $CF = C_{out} \oplus 1 = 0$。
- $OF = C_s \oplus C_1 = 1 \oplus 1 = 0$（最高位进位=向外的进位）。

### 2.8 🔴 CF/OF 例题二（运算-32）
$x=10, y=-20$，执行 $x - y$：

**OF（有符号）：** $10 - (-20) = 30$，远在 32 位 int 的安全范围内 → **OF = 0**。

**CF（无符号）：** $x=10$（极小正数），$y=-20$ 的补码是 `0xFFFFFFEC`（≈42.9亿的无符号天文数）。$10$ 减 42.9 亿肯定不够减 → **CF = 1**。

**出题陷阱：** 第一组数据 $(x=100, y=200)$ 给了 OF=0, CF=1 的结果，暗示"小减大借位"。到第二组 $(10, -20)$，很多人被 −20 的负号骗了，以为 $10-(-20)$ 是加法不会借位——忘记 **CF 眼里没有负数，只看无符号物理权值**。

## 三、浮点数

### 3.1 ⚠️ C 语言类型转换全规则（浮点-1 · !!）
**隐式转换优先级不是由位宽决定，而是由数据表示范围和编码机制决定。整型遇浮点型 → 永远向浮点型转换。**

**隐式转换链：** `char, short → int → unsigned → long → float → double`（单向向右）。
有符号遇无符号 → **有符号被当成无符号处理**（原位宽读二进制，可能导致负数变巨大正数）。

**显式转换（强转）：**
- 长字节→短字节：**直接截断高位**，保留低位。可能改变正负号。
- `int → float`：范围不会溢出，但 `int` 有 31 位数值位、`float` 尾数只有 23 位 → **可能精度丢失**（低位被丢弃）。
- `float → int`：**丢弃小数部分**（向零取整）。若整数部分超过 21 亿 → 严重溢出，结果不可预知。

### 3.3 ⚠️ 规格化的意义（浮点-8 · !!）
**常见错误：把"浮点数的优点"和"规格化的优点"搞混。**

- **表示范围**：完全由**阶码位数**决定。规格化只是调整尾数形式，没有增加阶码物理位宽 → **不能增加表示范围**。
- **表示精度**：规格化保证尾数寄存器里最高位始终是有效数字（不浪费位数），**能增加精度**。
- 规格化在硬件底层**使浮点运算变复杂**（需要额外的对阶、规格化步骤），不是变简单。

### 3.4 ⚠️ 浮点数表示范围在正负区间对称（浮点-9 · !!）
浮点数的表示范围在正数区间和负数区间**对称**（不像补码整数负数比正数多一个）。

### 3.5 ⚠️ 浮点溢出看阶码（浮点-11 · !!）
**浮点数运算是否溢出，看的是阶码是否上溢！**
- 阶码上溢 → 真正溢出。
- 阶码下溢 → 可以由非规格化数过渡（gradual underflow）。
- 尾数上溢/下溢 → 通过改阶码（右规/左规）消化，最终体现为阶码的上溢或下溢。

### 3.6 ⚠️ 负浮点数的二进制写法（浮点-13 · !!）
 遇到**浮点数**转机器码：最高位直接填 `1`（负数）或 `0`（正数），后面的尾数全部填**正数绝对值的二进制**。绝不要去求什么反码补码。

### 3.7 尾数舍入（浮点-14）
不仅是加减完要舍入——像 0.1 这种小数在**转化成浮点数时，尾数就已经需要遵循舍入规则**。

### 3.8 🔴 阶码差与对阶（浮点-17）
**两数阶码差 ≥ 25 时，阶码较小的操作数对结果无影响。**（尾数右移超过所有有效位数→全变0。）

### 3.9 🔴 机器字长的决定因素（浮点-18）
机器字长决定：通用寄存器位数、定点数的表示范围和精度。不决定浮点数范围（浮点范围由阶码决定）。

### 3.10 ⚠️ 表示边界 + 结合律（浮点-20 · !!）
**核心考点：不同数据类型的表示边界 + 运算执行先后顺序。**

**I. `dx + dy == (double)(x + y)` —— 错，考查溢出时间点**
- 右边：先运行 `x + y`（32 位 int 加法），可能**提前溢出**→ 负数。然后强转 double，结果已经是错的。
- 左边：先各自转 double（53 位精度），再加，绝对不会溢出。
- 例：`x = 2147483647, y = 1` → 右边溢出成 −2147483648.0，左边是 2147483648.0。

**II. `(dx + dy) + dz == dx + (dy + dz)` —— 对，考查结合律**
- 正常浮点数不满足结合律（大数吃小数）。
- 但 `dx, dy, dz` 全部从 32 位 int 转来 → 三数累加至多 6×10⁹ → 至多需要 33 位尾数。
- `double` 有 53 位有效精度（1 隐藏 + 52 尾数）→ 53 >> 33 → 整个过程**绝对无损** → 结合律成立。

**备考直觉：**
- 先加减后强转（如命题 I）→ 第一反应查越界/溢出。
- 浮点结合律问题 → 正常不成立；但如果**有效位数碾压所需位数**，则无损→成立。

### 3.12 不同类型运算的自动提升（浮点-25）
不同类型数据算术运算时，硬件 ALU 无法直接处理。编译器强制将低精度类型**提升（Promotion）**为高精度类型，再进行运算。

### 3.13 🔴 分母为 2ⁿ 的小数转二进制（浮点-26）
遇到分母是 2 的幂次（32、8、4）的十进制分数，**不用乘 2 取整法（太慢）**，用**整数平移法**：
1. 分子当成普通十进制→转二进制。
2. 分母 = 2ⁿ，小数点左移 n 位。

例：29/32 → 29=11101₂，32=2⁵ → 左移 5 位 = 0.11101₂。
例：5/8 → 5=101₂，8=2³ → 左移 3 位 = 0.101₂，补齐 = 00.10100₂。

**关键判断：** 这道题阶码和尾数均采用**补码**表示（不是 IEEE 754），**不能隐含 1！** 只有 IEEE 754 浮点数（明确写了 float/double/754）才有隐含最高位 1。

### 3.14 🔴 浮点尾数的隐含位 1（浮点-31）
做题时容易忽略**规格化浮点数隐含的最高位 1**。遇到 IEEE 754 题记得：23 位物理尾数 + 1 隐藏位 = **24 位有效精度**；double 是 52+1=**53 位**。

### 3.15 🔴 边界对齐（浮点-37）
又是边界对齐的问题——结构体/联合体的存储边界要对齐到最大成员的对齐要求。

### 3.16 🔴 十进制小数转二进制（浮点-40）
十进制小数转二进制，老老实实用**乘 2 取整法**，复杂度高的不要投机。

### 3.17 🔴 阶码全 0 = 非规格化数（浮点-42）
阶码全 0 是**非规格化数**的标志（IEEE 754），此时隐藏位是 0 而不是 1。

### 3.18 🔴 浮点精度 ≠ 阶码（浮点-43）
**float 阶码最大 127，不代表它能精确表示 127 位整数。** 整数精度看**尾数**：单精度 24 位有效（1 隐藏 + 23 尾数）→ 只能精确表示 [−2²⁴, 2²⁴] 范围内的连续整数。双精度 53 位 → 可精确表示 [−2⁴⁰, 2⁴⁰] 内的整数（53 > 40）。

**选 32 位整数还是单精度浮点？**（给定 α ≤ 2²⁰）
- 精度：两者在 2²⁰ 范围内都能绝对精确。
- 速度：整数 ALU 直接算，浮点数要经过对阶/求和/规格化/舍入/溢出判断五步 → 整数快得多。
- 结论：精度够的前提下**优先选整数**。

### 3.19 `int` vs `float` vs `double` 有效位宽总结

| 类型 | 物理位宽 | 有效精度 | 精确整数范围 |
|------|:--:|:--:|------|
| int (32位) | 32 bit | 31 位（1 位符号） | [−2³¹, 2³¹−1] |
| float | 32 bit | **24 位**（1隐藏+23尾数） | [−2²⁴, 2²⁴] |
| double | 64 bit | **53 位**（1隐藏+52尾数） | [−2⁵³, 2⁵³] |

### 3.20 类型强转的三步判断法

**第 1 步：查"小数截断"**
- 链条中出现 `float/double → int` → 检查原数有无小数 → 有则必丢。

**第 2 步：查"精度丢失"**
- 出现 `int → float` → 31 位塞进 24 位。问具体值还是恒成立？恒成立则不选（有风险）；给了具体值则估算二进制位数是否 ≤ 24 位。

**第 3 步：查"大容器装小容器"**（绝对安全）
- `int(31位) → double(53位)` ✓
- `float(24位) → double(53位)` ✓

**铁律：**
- `int → float`：可能丢精度（低位截断），但**绝不溢出**（float 阶码范围大）。
- `float → int`：丢小数 + 若整数部分超 21 亿则**溢出**成无意义负数。
