# 乘除法

![[笔记-1774354731359.jpeg]]
无符号乘法：
乘积寄存器和乘数寄存器相接，被乘数寄存器为 ALU 的一端，
乘数寄存器的最右端决定了是加乘数还是啥也不干。 
然后个操作（加或不干）完成后，乘积+乘数寄存器整体逻辑右移一位，
一箭双雕，既实现了判断下一个操作（从右往左看乘数的下一个数），又实现了“累加”在乘积要往左移一位，

![[_attachments/image/笔记-1782721698479.jpeg]]
关于**有符号乘法（Booth 算法）**，它依然沿用你总结的“操作后整体右移一箭双雕”的框架，但判断规则的背后原理是：**把乘数看作多个连续的 1 组成的区块，利用“一段连续的 1 可以转换为一次减法和一次加法”的数学规律来计算。**

在二进制中，一段连续的 1，例如二进制的 `001110`（十进制 14），可以等价表示为 `010000 - 000010`（即 $16 - 2 = 14$）。
这意味着，当我们从右向左依次检查乘数时，不需要遇到 1 就加被乘数，而是可以**在连续 1 的开头减去被乘数，在连续 1 的结尾加上被乘数。**

图中引入一个**辅助位（$Y_{-1}$，初始值为 0）**，与乘数最低位（$Y_0$）组合起来，就是为了在从右向左移动的过程中，**探测“连续 1”的边界**。

原理具体拆解如下（设从右向左扫描，当前位为 $Y_0$，右侧移出的上一位为辅助位 $Y_{-1}$）：

*   **当 $Y_0 Y_{-1} = 10$ 时（遇到 1，上一位是 0）**：
    说明从右往左看，你**刚进入**一段连续的 1 的最右端（例如 `0111[1]0` 的括号处）。
    根据原理，在连续 1 的低位端应该执行减法。所以操作是：**乘积 P 减去被乘数 X（即 P + [-x]补）**。
*   **当 $Y_0 Y_{-1} = 11$ 时（遇到 1，上一位也是 1）**：
    说明你正处于一段连续的 1 的**内部**。
    由于刚进入这段 1 的时候已经做过减法了，内部的 1 不需要额外操作。所以操作是：**+0**。
*   **当 $Y_0 Y_{-1} = 01$ 时（遇到 0，上一位是 1）**：
    说明从右往左看，你**刚离开**一段连续的 1，进入了 0 的区域。
    根据原理，连续 1 结束的高位端应该执行加法（对应前面提到的 `+ 010000`）。所以操作是：**乘积 P 加上被乘数 X（即 P + [x]补）**。
*   **当 $Y_0 Y_{-1} = 00$ 时（遇到 0，上一位也是 0）**：
    说明你正处于一段连续的 0 的内部，没有遇到 1 的边界。所以操作是：**+0**。

**这就是图片左下角记忆技巧 `辅助位 - Y最低位` 的底层逻辑**：
$Y_{-1} - Y_0 = -1$（即 0 - 1），代表从 0 变 1，进入连续 1 区间，减 X。
$Y_{-1} - Y_0 = 1$（即 1 - 0），代表从 1 变 0，离开连续 1 区间，加 X。
$Y_{-1} - Y_0 = 0$（即 0-0 或 1-1），代表区间内部状态无变化，加 0。

**有符号乘法操作上的关键不同点（必须注意的前提）：**
在完成上述加减操作后，乘积寄存器 P 和乘数寄存器 Y 及辅助位整体向右移一位时，必须使用**算术右移**。因为当前寄存器 P 里存储的是带符号的部分积补码，右移时最高位必须复制自身的符号位（如果是负数最高位必须补 1），不能像无符号乘法那样无脑补 0，否则正负号就乱了。



![[笔记-1774422830017.jpeg]]

- **除数寄存器 B**：4bit，存放除数。
    
- **余数寄存器 R**：4bit，初始全为 0000。
    
- **商寄存器 Q**：4bit，初始存放**被除数**（例如 1011）。
    
- **拼接移位**：硬件上将 R 和 Q 拼接成一个 8bit 的整体 [R, Q]，并且只支持**逻辑左移**。
    

除法运算的“一箭双雕”，就是 **[R, Q] 整体向左移一位** 时同时完成的两件事：

1. **作用一（往前送数据）：将“被除数”的最高位，送入“余数寄存器 R”参与计算。**  
    当 [R, Q] 左移时，Q 的最高位会被挤入 R 的最低位。这在底层等价于你在纸上手算长除法时，**“把被除数的下一位数字拉下来”**。此时 R 里的数据就是当前需要和除数 B 进行大小比较的被除数部分。
    
2. **作用二（往后腾位置）：为新算出来的“商”，腾出存放空间。**  
    由于 Q 整体左移了一位，Q 的最低位必然空了出来。这个空位，**正好被用来直接写入当前这一步算出的商值（1 或 0）**。
    

之所以你会觉得除法“绕”，是因为乘法是“先算再移”，而**除法必须是“先移再算”**。

下面以**恢复余数法**为例，拆解一次完整的循环（4bit 除法严格执行 4 轮）：

**第 1 步：先移位（一箭双雕发力）**  
[R, Q] 整体逻辑左移一位。此时待计算的位进入了 R，同时 Q 的最低位空出（暂时为 0）。

**第 2 步：ALU 试探性减法**  
将余数寄存器 R 减去除数 B（底层是 R + [-B]补），结果写回 R。

**第 3 步：根据 ALU 结果的符号位，上商并决定是否恢复**

- **如果 R 结果的最高位（符号位）是 0**：  
    说明得到的余数是正数，**够减**。  
    硬件直接把刚才 Q 左移空出来的最低位改为 1（这就是“上商 1”）。
    
- **如果 R 结果的最高位（符号位）是 1**：  
    说明得到的余数是负数，**不够减**。  
    硬件把 Q 的最低位保持为 0（这就是“上商 0”）。  
    由于刚才把 R 减成了负数（破坏了原来的数据），必须立刻执行一次**恢复操作**：将 R 加上除数 B（即 R + B），把 R 变回减法之前的值。
    

**为什么这个机制极度精妙？**  
这是一个完美的**空间置换**过程。初始时，Q 里面塞满了 4bit 的被除数，没有地方放商。但在 4 轮循环中，被除数的数据一位一位地向左送进了 R 被消耗掉；同时，Q 的右侧一位一位地空出来，正好吃进了 4 轮产生出的 4bit 商。  
执行 4 轮结束后：Q 里原本的被除数全部消失，完全被新产生的“商”取代；而最后剩下的无法再减的数值，就稳稳地停在 R 里，成为最终的“余数”。

# 浮点数

$符号，尾数×基数^{阶码}$

![[笔记-1774509484952.jpeg]]
阶码加偏置，以及阶码后拼尾数，都是为了方便比较。



当发现存储的 8bit 阶码中，全是 1 或全是 0 时，是特殊的浮点数
![[笔记-1774513731735.jpeg]]

### 危机一：隐藏的 `1.` 导致永远无法表示“0”

**代数困境：** 既然尾数默认是 $1.f$，那不管阶码多小，算出来永远是 $1.x \times 2^{-126}$，它无限接近于 0，但**绝对不可能等于 0**！计算机如果没有绝对的 `0`，加减法系统直接崩溃。

**硬件补丁（阶码全 0，尾数全 0）：**

设计师规定：当阶码是**全 0**，且尾数也是**全 0** 时，硬件直接无视那个隐藏的 `1.`，强制把它定义为**绝对的 `0`**。

- _符号位为 0，就是 $+0$；符号位为 1，就是 $-0$。在极限运算里（比如 $1 / -0 = -\infty$），区分正负零在数学上是极其必要的。_
    

### 危机二：极小值附近的“断崖式下溢”

**代数困境：** 正常的单精度浮点数，最小的正数是多少？

阶码能用的最小值是 $1$（因为全 0 被抢走了），减去偏置 127，实际指数是 $-126$。尾数全 0 时，加上隐藏的 1，结果是：**$1.0 \times 2^{-126}$**。

那么，比 $1.0 \times 2^{-126}$ 还要小的数字怎么办？如果直接掉到 0，会在数轴上形成一个巨大的“真空断崖”，这会导致 $A - B = 0$ 成立，但 $A$ 居然不等于 $B$（极其可怕的代数错误）！

**硬件补丁（阶码全 0，尾数非 0 —— 非规格化数）：**

设计师再次利用**阶码全 0** 这个状态。规定：如果阶码全 0，但尾数不是 0，说明数字已经小到了极限。

此时，**强行把隐藏的 `1.` 降级为 `0.`**！

真实数值变成了：**$0.f \times 2^{-126}$**。

你看，因为头部变成了 `0.`，随着尾数 $f$ 慢慢变小，这个数字可以像下楼梯一样，平滑、线性地一路走到绝对的 0。这就叫**“渐进式下溢（Gradual Underflow）”**。

### 危机三：除以 0 和数学悖论导致 CPU 停机

**代数困境：** 整数运算除以 0 或者溢出，CPU 会直接抛出异常甚至死机。但是在科学计算中（比如算气象数据、物理模拟），不能因为中间某一步算出了无穷大（$1.0 / 0.0$）或者无意义的数（$\sqrt{-1}$），就让运行了三个月的超级计算机直接崩溃停机！必须用物理电平把这些错误“记录”下来，让程序继续跑。

**硬件补丁（阶码全 1，尾数全 0/非 0）：**

设计师征用了阶码的另一个极端：**全 1**（即 255）。

- **正/负无穷大（$\pm\infty$）：** 如果发生了溢出，或者正数除以 0。硬件把阶码强行置为**全 1**，尾数干干净净置为**全 0**。这就是纯粹的极限——**无穷大**。它甚至可以继续参与运算，比如 $\infty + 5 = \infty$。
    
- **非数 NaN（Not a Number）：** 如果发生了非法的数学悖论运算（比如 $0.0 / 0.0$ 或者 $\infty - \infty$），硬件把阶码置为**全 1**，但尾数随便填一个**非 0** 的乱码。这个非 0 的尾数就像是一个“错误日志（Payload）”，告诉后续程序：“这里产出了一坨没有数学意义的垃圾数据”。任何数字与 NaN 运算，结果都是 NaN（它具有传染性）。
