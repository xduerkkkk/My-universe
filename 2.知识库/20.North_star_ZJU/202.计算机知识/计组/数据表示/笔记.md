当发现存储的 8bit 阶码中，全是 1 或全是 0 时，是特殊的浮点数
![[笔记-1774513731735.jpeg]]

### 危机一：隐藏的 `1.` 导致永远无法表示“0”

**代数困境：** 既然尾数默认是 $1.f$，那不管阶码多小，算出来永远是 $1.x \times 2^{-126}$，它无限接近于 0，但**绝对不可能等于 0**！计算机如果没有绝对的 `0`，加减法系统直接崩溃。

**硬件补丁（阶码全 0，尾数全 0）：**

设计师规定：当阶码是**全 0**，且尾数也是**全 0** 时，硬件直接无视那个隐藏的 `1.`，强制把它定义为**绝对的 `0`**。

- _符号位为 0，就是 $+0$；符号位为 1，就是 $-0$。在极限运算里（比如 $1 / -0 = -\infty$），区分正负零在数学上是极其必要的。_
    

### 危机二：极小值附近的“断崖式下溢”

**代数困境：** 正常的单精度浮点数，最小的正数是多少？

阶码能用的最小值是 $1$（因为全 0 被抢走了），减去偏置 127，实际指数是 $-126$。尾数全 0 时，加上隐藏的 1，结果是：**$1.0 \times 2^{-126}$**。

那么，比 $1.0 \times 2^{-126}$ 还要小的数字怎么办？如果直接掉到 0，会在数轴上形成一个巨大的“真空断崖”，这会导致 $A - B = 0$ 成立，但 $A$ 居然不等于 $B$（极其可怕的代数错误）！

**硬件补丁（阶码全 0，尾数非 0 —— 非规格化数）：**

设计师再次利用**阶码全 0** 这个状态。规定：如果阶码全 0，但尾数不是 0，说明数字已经小到了极限。

此时，**强行把隐藏的 `1.` 降级为 `0.`**！

真实数值变成了：**$0.f \times 2^{-126}$**。

你看，因为头部变成了 `0.`，随着尾数 $f$ 慢慢变小，这个数字可以像下楼梯一样，平滑、线性地一路走到绝对的 0。这就叫**“渐进式下溢（Gradual Underflow）”**。

### 危机三：除以 0 和数学悖论导致 CPU 停机

**代数困境：** 整数运算除以 0 或者溢出，CPU 会直接抛出异常甚至死机。但是在科学计算中（比如算气象数据、物理模拟），不能因为中间某一步算出了无穷大（$1.0 / 0.0$）或者无意义的数（$\sqrt{-1}$），就让运行了三个月的超级计算机直接崩溃停机！必须用物理电平把这些错误“记录”下来，让程序继续跑。

**硬件补丁（阶码全 1，尾数全 0/非 0）：**

设计师征用了阶码的另一个极端：**全 1**（即 255）。

- **正/负无穷大（$\pm\infty$）：** 如果发生了溢出，或者正数除以 0。硬件把阶码强行置为**全 1**，尾数干干净净置为**全 0**。这就是纯粹的极限——**无穷大**。它甚至可以继续参与运算，比如 $\infty + 5 = \infty$。
    
- **非数 NaN（Not a Number）：** 如果发生了非法的数学悖论运算（比如 $0.0 / 0.0$ 或者 $\infty - \infty$），硬件把阶码置为**全 1**，但尾数随便填一个**非 0** 的乱码。这个非 0 的尾数就像是一个“错误日志（Payload）”，告诉后续程序：“这里产出了一坨没有数学意义的垃圾数据”。任何数字与 NaN 运算，结果都是 NaN（它具有传染性）。
