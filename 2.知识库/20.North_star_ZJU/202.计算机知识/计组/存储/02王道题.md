5. B 为啥<span style="background:#b1ffff">集成度</span> dram 高呢
	- **SRAM（静态）**：存储一位（1 bit）需要 **6 个晶体管**（6T，双稳态触发器结构）。占地面积大，像个大别墅。
    
	- **DRAM（动态）**：存储一位（1 bit）只需要 **1 个晶体管 + 1 个电容**（1T1C）。占地面积极小，像个单间胶囊房。
	**结论**：因为 1T1C 远小于 6T，所以 DRAM 可以做得特别密，容量大，便宜，适合做主存。 当然，他比 SRAM 慢

15. <font color="#ff0000">B, A 哪不对</font>!!
	“工作中”等同于“通电状态下”，不是说“被访存状态下”。DRAM 是易失性存储器，如果不通电（非工作状态），数据瞬间全部消失，根本谈不上漏电。所以“工作中”是讨论漏电现象的先决条件。
	
	存取时间是对 CPU 而已， CPU 发出读命令开始，到数据稳定出现在数据总线上为止，就是指主存芯片把数据“吐”到了这根共享的数据总线上，并且电信号达到了稳定状态的那一瞬间。此时，CPU 的寄存器（如 MDR）刚好可以把数据捕获（Latch）进去。
	
	- **恢复（Recovery / 预充电）：** 这是**伴随在每一次正常读写操作之后**的“收尾动作”。因为 DRAM 读一次电容就空了（破坏性读出），所以只要你读了这一行，硬件就必须立刻把电平重新充满。这个动作是**强制捆绑**在每次访存操作里的。
    
	- **刷新（Refresh）：** 这是**系统定时器发起的保命动作**。如果某一行数据很久没被 CPU 读写过，电容自己慢慢漏电快漏光了，内存控制器就会专门发一个指令，强行把这一行读出来再充回去。
	  “恢复”是为了弥补刚才被读空的电容；“刷新”是为了弥补随时间自然漏电的电容。
	  
	  存取周期是对芯片而言，存储器进行**两次独立的、连续的**读/写操作之间，所必须间隔的**最小时间**。
	  在 408 考研的常规语境中，**“访存周期”就是“存取周期”的同义词**。
	- 正常读写一次，需要耗费 1 个存取周期（读出数据发给 CPU + 恢复电平）。
    
	- 执行一次刷新，**也需要耗费 1 个存取周期**（读出数据不发给 CPU + 恢复电平）。
- **刷新周期（宏观死线）：** 它是电容自然漏电到达临界值的时间。系统规定，比如 **2ms（毫秒）**。意思是：不管你用什么方法，每隔 2ms，你必须把整个内存里所有的行都挨个刷新一遍，否则数据就蒸发了。
  - **恢复时间：** 就是“行缓冲器把电平灌回整行电容”这一步所花的时间。比如花了 **20ns**。

刷新一行的时间和存取周期相同，恢复时间是存取周期后半段的时间，刷新周期和这俩微观的玩意无关！

16. ？!!<span style="background:#b1ffff">DRAM 刷新知识点</span>
    采用异步刷新，每单元刷新间隔不超过 2ms，则生成的刷新信号的间隔？什么是每单元？什么是刷新信号？
    “每单元刷新间隔不超过 2ms”，大白话就是：**这块内存里所有的存储电容（单元），都必须在 2ms 内被刷新一次，否则就会漏电丢失数据。**  
	但在物理硬件上，我们知道 DRAM 绝对不可能一个一个单元去刷，而是**按行刷新**。所以，这句话在计算时的等价含义是：**“整个芯片的所有行，必须在 2ms（刷新周期）内全部被刷新一遍。”**
	刷新操作是由每一块 DRAM 芯片**内部**的电路独立且同时完成的。因此，算行数**只能看单块芯片的容量**，绝对不能看拼装后的总容量。
	   **规则：** 刷新操作是由每一块 DRAM 芯片**内部**的电路独立且同时完成的。因此，算行数**只能看单块芯片的容量**，绝对不能看拼装后的总容量。
*   **计算：** 单块芯片是 $64K \times 1$ 位。
    1. 总地址空间是 $64K = 2^{16}$，这意味着芯片有 16 根逻辑地址线。
    2. DRAM 采用**地址复用技术**。在 408 默认情况下，存储矩阵是正方形，16 根地址线平分给行和列。
    3. 行地址线 = $16 \div 2 = 8$ 根。
    4. **芯片的总行数 $N = 2^8 = 256$ 行。**
*   *推论：既然有 256 行，第二空的答案肯定是 256，直接排除 C 和 D。*

**第二空（集中刷新）：刷新一遍最少用多少周期？**
*   根据我们在上一个问题得出的死定律：**刷新 1 行严格耗费 1 个读/写周期（存取周期）。**
*   现在芯片有 256 行，要一口气集中把它全刷完，显然需要 **256 个周期**。

**第一空（异步刷新）：生成的刷新信号间隔时间是多少？**
*   **规则：** 异步刷新是把 256 行平摊到 2ms 内。
*   **公式：** 刷新信号间隔 = 最大刷新周期 $\div$ 总行数。
*   **计算：** $2ms \div 256 = 2000\mu s \div 256 = 7.8125 \mu s \approx 7.8 \mu s$。
*   这意味着内存控制器每隔 $7.8\mu s$ 就发一次命令，花 1 个存取周期的时间去刷 1 行。

25. ?<span style="background:#b1ffff">单体多字</span>？!! 知识点.. 不知道哪来的。单体多字为什么没有解决主存容量过小的问题，因为没扩容？
    单体多字的做法：把存储器的数据总线宽度从1个字加宽到m个字，一次访存取出m个字，再依次送给CPU。

	它解决的问题：带宽不足（CPU等待主存的时间过长），因为一次访存周期能提供更多数据。
	
	它没解决的问题：主存容量没有增大。因为它只是加宽了数据通路，存储单元的总数没有增加——地址空间不变，能存的信息总量不变。
	
	本质上，容量 = 存储单元数 × 每个单元的位数。单体多字是把相邻m个字并为一个宽存储单元一起读出，存储单元数反而变成了原来的 1/m，每个单元位数变成原来的 m 倍，总容量不变。要增大容量，必须增加可寻址的存储单元数量（即字扩展），单体多字不涉及这一点。
	
	- **B 选项：单体多字存储器中，每个存储单元存储多个字。**  
    **正确。** 这是它的物理定义。为了能一口气吐出 4 个字，它的一个物理存储单元的位宽必须是普通机器字长的倍数。
    
	- **C 选项：指令与数据的连续存放有利于提高读写速度。**  
	    **正确。** 设想一下，CPU 一口气拿回了地址 0, 1, 2, 3 的四个字。如果你的代码是顺序执行的（具有良好的**空间局部性**），这 4 个字刚好都会被用上，速度当然快。
	    
	- **D 选项：过多的跳转指令会严重影响工作效率。**  
	    **正确（这是它的致命弱点）。** 如果 CPU 拿到 0, 1, 2, 3，刚执行完地址 0 的指令，遇到一个 Jump 100（跳转指令）。那么刚刚费力读出来的 1, 2, 3 全变成了废纸。CPU 必须再去向内存发地址 100，重新死等一个漫长的周期 
	    
	    ```
	    TT
	    ```
	    
	    。跳转指令完全破坏了它的提速逻辑。
	    
	- **A 选项：主要解决主存容量大小的问题。**  
	    **错误（所以选它）。** 从头到尾，这种加宽数据线、一口气多拿几个字的设计，**唯一目的就是为了解决“速度不匹配（提高带宽）”的问题**。想要解决容量问题，需要增加地址线或增加内存芯片数量，单体多字完全无助于增加总字节数。

 **总线 64 位**（CPU 一次必须吃 8 个字节）。

为了让这 8 个“每次只能吐 1 字节”的小芯片，能在 1 个周期内共同凑齐 64 位（8 字节）喂给 CPU，硬件工程师**只能有一种连线排布方式**：

    - 地址 0 放在第 0 个芯片；
        
    - 地址 1 放在第 1 个芯片；
        
    - ...
        
    - 地址 7 放在第 7 个芯片；
        
    - 地址 8 又回到第 0 个芯片...
看到“总线宽度大于芯片宽度”，并且注明了“按字节编址”时，这就是标准的**多模块交叉编址（同时启动）**模型
