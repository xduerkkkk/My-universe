# 存储王道高危错题复盘卡

> 来源：[[2.知识库/20.North_star_ZJU/202.计算机知识/计组/存储/02王道题]] 中的 `!!` 题。
> 这里不是抄题本，而是“下次遇到同类题时的触发器”。
> 复盘方法：先只看标题和“秒杀句”，能讲出解法就过；讲不出再看“下次做题动作”。

## 存储器概述 12：Cache 命中率“至少”

- 状态：!! 二刷仍错
- 考点：命中率、临界值、至少/至多
- 原错因：算出 98.33% 后直接选 98，没有处理“至少”的向上取整。
- 复盘抓手：计算题不是算完就结束，最后一步一定回到问法。
- 秒杀句：**“至少为 x”遇到 98.33%，答案要选不小于它的最小选项，即 99%。**
- 下次做题动作：
  1. 先算临界值。
  2. 圈出“至少/至多/不超过/不少于”。
  3. 再决定向上还是向下取整。

## 主存 13：主存、内存、RAM、ROM、BIOS

- 状态：!! 二刷仍错
- 考点：内存储器和外存储器边界
- 原错因：把“操作系统在硬盘”和“CPU 可直接访问的内存”混在一起。
- 复盘抓手：408 语境下，主存/内存看 CPU 能不能直接寻址。
- 秒杀句：**主存 = RAM 为主 + 少量 ROM；OS 平时在硬盘，启动后核心进入 RAM，BIOS/Bootloader 在 ROM。**
- 下次做题动作：
  1. 题目问“内存/主存”时，先按 CPU 直接访问判断。
  2. RAM 是主体，ROM 是固化启动程序的少量部分。
  3. 不要因为 OS 存在硬盘，就把 OS 运行时位置也判成外存。

## 主存 15：DRAM 恢复、刷新、存取时间/存取周期

- 状态：!! 二刷仍错
- 考点：DRAM 漏电、恢复、刷新、存取时间、存取周期
- 原错因：把“工作中/被访问中”、恢复和刷新、存取时间和存取周期混在一起。
- 复盘抓手：
  - 存取时间：CPU 发读命令到数据稳定出现。
  - 存取周期：两次独立访存之间的最小间隔。
  - 恢复：一次读写后的收尾。
  - 刷新：定时防漏电的保命动作。
- 秒杀句：**恢复跟着读写走，刷新跟着时间走；刷新一行也占一个存取周期。**
- 下次做题动作：
  1. 题干如果问 CPU 视角，看“存取时间”。
  2. 题干如果问芯片连续操作，看“存取周期”。
  3. 题干如果问漏电保数据，看“刷新周期”。

## 主存 16：DRAM 异步刷新计算

- 状态：!! 二刷仍错
- 考点：刷新周期、异步刷新、单芯片行数
- 原错因：不清楚“每单元刷新间隔”“刷新信号间隔”到底对应什么；容易按总容量算行数。
- 复盘抓手：DRAM 物理上按行刷新；刷新由每块芯片内部并行完成，所以行数只看单块芯片。
- 秒杀句：**异步刷新间隔 = 最大刷新周期 / 单块芯片行数。**
- 下次做题动作：
  1. 找单块芯片容量，例如 `64K×1`。
  2. 算逻辑地址位数，例如 `64K = 2^16`。
  3. 默认正方形矩阵 + 地址复用，行地址位 = 16/2 = 8。
  4. 行数 = `2^8 = 256`。
  5. 异步刷新信号间隔 = `2ms / 256`。

## 主存 18：SDRAM 与同步/异步

- 状态：!! 二刷仍错
- 考点：传统 DRAM 和 SDRAM 的同步异步
- 原错因：不知道同步异步到底在描述谁和谁的关系。
- 复盘抓手：同步/异步说的是存储器和系统/CPU 时钟的配合方式。
- 秒杀句：**传统 DRAM 异步：CPU 不知道它什么时候完成；SDRAM 同步：按系统时钟节拍交换数据。**
- 下次做题动作：
  1. 看到 SDRAM，先展开为 Synchronous DRAM。
  2. 问“同步”就答时钟节拍；问“异步”就答等待/握手/不固定完成时刻。

## 主存 19：地址线增加与容量倍数

- 状态：!! 二刷仍错
- 考点：地址线、容量、地址复用
- 原错因：看到“至少”或地址复用后，没有回到地址空间倍数。
- 复盘抓手：地址线每增加 1 根，可表示地址数翻倍。
- 秒杀句：**n 根地址线对应 `2^n` 个地址，增加 1 根就是容量 ×2。**
- 下次做题动作：
  1. 先判断题目问逻辑地址线还是芯片外部地址引脚。
  2. 若问容量变化，优先用 `2^n`。
  3. 若问 DRAM 引脚，注意行列地址复用。

## 主存 23：流水线/周期性访存题

- 状态：!! 二刷仍错
- 考点：连续传送、流水线节拍、低位交叉/多模块
- 原错因：没有主动识别“周期性/流水线”题型。
- 复盘抓手：这种题不能只看单次访存，要看稳定输出节拍。
- 秒杀句：**连续读写看流水线，第一拍启动，之后按总线周期/模块节拍稳定吐数据。**
- 下次做题动作：
  1. 画时间轴。
  2. 标出每个模块何时开始访问、何时可再次访问。
  3. 区分首个数据延迟和稳定吞吐率。

## 主存 24：低位交叉与十六进制末位

- 状态：!! 二刷仍错
- 考点：低位交叉编址
- 原错因：计算粗心，尤其十六进制 F 的位置判断。
- 复盘抓手：低位交叉只看地址低位决定芯片/模块。
- 秒杀句：**四体低位交叉看最后 2 位；00/01/10/11 分别对应 4 个模块。**
- 下次做题动作：
  1. 先把地址低位写成二进制。
  2. 四体取低 2 位，八体取低 3 位。
  3. 十六进制 F 表示二进制 1111，是 0~F 的第 16 个状态。

## 主存 25：单体多字

- 状态：!! 二刷仍错
- 考点：单体多字存储器
- 原错因：不知道该结构解决什么问题。
- 复盘抓手：单体多字是一次取多个连续字，提高带宽，不增加容量。
- 秒杀句：**单体多字解决速度/带宽，不解决容量；跳转会破坏连续取多字优势。**
- 下次做题动作：
  1. 题目问容量：看地址线/芯片数量。
  2. 题目问速度：看带宽、一次取几字、是否连续访问。
  3. 遇到跳转，警惕单体多字优势下降。

## 主存 33：需要画图的存储题

- 状态：!! 二刷仍错
- 考点：地址、模块、时间轴建模
- 原错因：感觉该画图但仍试图心算。
- 复盘抓手：存储题一旦出现地址分配/模块/周期，图比文字可靠。
- 秒杀句：**凡是“模块 + 地址 + 周期”的题，先画图再计算。**
- 下次做题动作：
  1. 画地址位划分。
  2. 画模块编号。
  3. 画时间轴。
  4. 最后再代公式。

## 主存 34：DRAM 行列复用与地址引脚

- 状态：!! 二刷仍错
- 考点：DRAM 地址复用、行列矩阵
- 原错因：把“保证地址引脚少”和“保证刷新快”混在一起。
- 复盘抓手：DRAM 行列复用的直接目的，是减少地址引脚数量。
- 秒杀句：**行列复用先服务于引脚复用；刷新快慢是相关影响，不是这个设计的最核心表述。**
- 下次做题动作：
  1. 先算逻辑地址总位数。
  2. 再按行列复用分成行地址和列地址。
  3. 选项若问“引脚少”，优先对应地址复用。

## 存储器与 CPU 连接 7：片选与片内地址线

- 状态：!! 二刷仍错
- 考点：存储芯片扩展、片选信号、高低位地址
- 原错因：按扩展后容量算片内地址位，导致片选线判断错。
- 复盘抓手：片内地址位由基础芯片容量决定；剩余高位才用于片选。
- 秒杀句：**先算基础芯片片内地址，再看 CPU 地址线剩下哪些做片选。**
- 下次做题动作：
  1. 看单片容量，算片内地址线。
  2. 看目标容量，算需要多少片/组。
  3. 用高位地址做片选，低位地址进芯片内部。

## Cache 9：指令 Cache 局部性

- 状态：!! 二刷仍错
- 考点：指令 Cache 与数据 Cache 的局部性
- 原错因：对“空间局部性”的对象判断不稳。
- 复盘抓手：指令通常顺序执行，天然连续；数据访问模式更不确定。
- 秒杀句：**指令 Cache 通常比数据 Cache 有更好的空间局部性。**
- 下次做题动作：
  1. 问指令流，先想到顺序执行。
  2. 问数据流，想到数组是好局部性，指针/随机访问较差。

## Cache 14：地址映射表容量

- 状态：!! 二刷仍错
- 考点：Cache 地址映射表、Tag、Valid、Dirty
- 原错因：漏算有效位；不清楚脏位是否属于地址映射表。
- 复盘抓手：映射表项按 Cache 行算，每行保存用于判断命中的元数据。
- 秒杀句：**映射表至少是 Cache 行数 ×（Tag + Valid）；写回法还要 Dirty；替换位看替换算法。**
- 下次做题动作：
  1. 算 Cache 行数。
  2. 拆主存地址：Tag / Index / Offset。
  3. 表项加 Tag + 有效位。
  4. 若写回，加修改位；若 LRU/FIFO，加替换控制位。

## Cache 18：逻辑地址和物理地址有效位

- 状态：!! 二刷仍错
- 考点：页式存储地址结构
- 原错因：不理解“有效位”就是表示该地址需要的二进制位数。
- 复盘抓手：逻辑地址 = 页号 + 页内偏移；物理地址 = 物理块号 + 块内偏移。
- 秒杀句：**页大小 = 块大小，所以地址转换只替换高位，低位偏移保持不变。**
- 下次做题动作：
  1. 页数取 log₂ 得页号位数。
  2. 页大小取 log₂ 得页内偏移。
  3. 物理块数取 log₂ 得块号位数。
  4. 物理地址偏移位 = 页内偏移位。

## Cache 21：Cache 容量、数据位与替换控制位

- 状态：!! 二刷仍错
- 考点：Cache 总容量、数据位、控制位
- 原错因：把字节编址的 offset 位数当成数据位；不清楚替换位何时需要。
- 复盘抓手：数据位是块里真实存的数据大小，控制位另算。
- 秒杀句：**4B 数据块的数据位是 32bit，不是因为 offset 有 2 位就写 2bit。**
- 下次做题动作：
  1. 先算 Cache 行数 = 数据容量 / 块大小。
  2. 每行数据位 = 块大小 × 8。
  3. 每行元数据 = Tag + Valid + Dirty/替换位等。
  4. 总容量 = 行数 × 每行总位数。

## Cache 31：数组访问缺失率

- 状态：!! 二刷仍错
- 考点：数组访问、访存序列、缺失率
- 原错因：没读出 `a[k]=a[k]+1` 包含读和写；没有先建立访问序列。
- 复盘抓手：缺失率题先数访存次数，再看一个块能覆盖几个元素。
- 秒杀句：**`a[k]=a[k]+1` 是 1 次读 + 1 次写；16B 块装 4 个 int。**
- 下次做题动作：
  1. 写出每轮循环的读/写次数。
  2. 根据块大小算一次调入几个数组元素。
  3. 判断写命中/写不命中策略。
  4. 再算总缺失次数 / 总访存次数。

## Cache 33：按字节编址、块大小、Offset

- 状态：!! 二刷仍错
- 考点：地址位与数据容量
- 原错因：把“按字节编址”理解成数据位大小；把 32B 和 32bit 混淆。
- 复盘抓手：按字节编址只说明 1 个地址对应 1 字节，因此块内偏移按字节数取 log₂。
- 秒杀句：**32B 块需要 5 位 offset；32B 数据是 256bit，不是 32bit。**
- 下次做题动作：
  1. 看到 B，先转换为 bit 时乘 8。
  2. 算 offset 时，对块大小的字节数取 log₂。
  3. 算数据位时，用块大小 × 8。
