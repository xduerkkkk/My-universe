我们跟着指令走一遍这 5 个阶段：

- **① IF (取指 Fetch)：** 根据 PC 寄存器的地址，去指令 Cache（缓存）里把这条加法指令取出来，放到 IF 段的锁存器里。
    
- **② ID (译码&取数 Decode)：** 翻译这条指令，发现是加法。同时，去寄存器堆（Registers）里把需要的两个数（Rs 和 Rd 的当前值）给读出来，放到 ID 段的锁存器里。
    
- **③ EX (执行 EXecute)：** ALU（算术逻辑单元）开始疯狂干活，把刚才取出来的两个数加在一起，算出结果，放到 EX 段的锁存器里。
    

**(划重点！下面是这张图最核心的考点，也是你在图上画了红圈的地方)**

- **④ M (访存 Memory)：这是一个“空段”！**
    
    - **为什么是空段？** 因为这是一条**运算类指令**（加减乘除、移位等）。它的数据都来源于寄存器，结果最终也要写回寄存器。它**根本不需要去读写主存（Data Cache）**！
        
    - **那这个阶段它在干嘛？** 既然不能让流水线停下来，它在这个时钟周期里就只能“发呆”。图上 ALU 后面的那根线，直接越过了 Data Cache，把运算结果**原封不动地传递**给了下一个锁存器。这也是你画红圈的那个多路选择器和旁路导线的作用。
        
- **⑤ WB (写回 Writeback)：** 终于熬到了最后一步，把在 EX 段算好、在 M 段闲逛了一圈的那个加法结果，正式写回到寄存器堆里的目的寄存器（$R_d$）中。





#### 1. LOAD 指令（把数据从内存取到寄存器）

_图 1_

LOAD 是最“充实”的指令，它 5 个阶段一个都不落，全勤打卡：

- **IF (取指):** 取出指令。
    
- **ID (译码):** 从寄存器堆里读出基址寄存器的值（比如 $R_s$），并提取指令里的偏移量（Imm）。
    
- **EX (执行):** ALU 把基址和偏移量相加，**算出真正要访问的内存地址（有效地址）**。
    
- **M (访存):** 拿着算好的地址，去 Data Cache 里**把数据读出来**，放到锁存器里。
    
- **WB (写回):** 把刚才读出来的数据，**写回到目的寄存器（$R_d$）中**。
    
- **结论：** LOAD 指令没有空段。
    

#### 2. STORE 指令（把寄存器的数据存入内存）

_图 2_

STORE 的任务是“往外泼水”，不需要往自己兜里揣东西：

- **IF & ID:** 和 LOAD 类似，取指令，读基址。但注意，ID 段还要**把准备存入内存的数据（图中的锁存器 B）也一起读出来**。
    
- **EX:** ALU 计算目标内存地址。同时，把要存的数据顺着绿线（旁路）传给下一个锁存器。
    
- **M:** 把数据**写入** Data Cache 的对应地址中。
    
- **WB (重点！):** **空段！** 因为数据已经安全送进内存了，STORE 指令不需要修改任何通用寄存器，所以它在 WB 段发呆。


#### 3. 条件转移指令（如 beq：相等则跳转）

_图 3_

这就是咱们前面讲“控制冲突”时，那个害得流水线猛踩刹车的主角：

- **IF:** 取指令。
    
- **ID:** 把要比较的两个数读出来，同时提取偏移量。
    
- **EX:** ALU 把两个数相减，判断是否相等。同时计算跳转的目标地址（$PC + \text{偏移量}$）。
    
- **M (特殊操作):** 很多教材把这一段直接改叫 **“WrPC 段”**。如果条件成立，就在这个阶段**把算好的目标地址强行塞进 PC 里**。这也解释了为什么控制冲突要等到晚期才发现走错了路。
    
- **WB (重点！):** **空段！** 跳转指令只改 PC，不改通用寄存器，所以写回段它也发呆。




| **指令类型**       | **M 段 (访存) 在干嘛？** | **WB 段 (写回) 在干嘛？** |
| -------------- | ----------------- | ------------------ |
| **LOAD (取数)**  | **读** Data Cache  | 写通用寄存器             |
| **STORE (存数)** | **写** Data Cache  | **发呆 (空段)**        |
| **运算类 (加减乘除)** | **发呆 (空段)**       | 写通用寄存器             |
| **条件跳转 (beq)** | 修改 PC (WrPC)      | **发呆 (空段)**        |
