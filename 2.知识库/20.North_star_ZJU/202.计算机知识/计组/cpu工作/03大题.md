
# 1 当没有自增
![[_attachments/image/03大题-1784019863380.jpeg]] ![[_attachments/image/03大题-1784019864896.jpeg]]

这道题的核心在于理解**指令周期的时间先后顺序**以及**单总线结构下更新寄存器值的硬件限制**。

答案图中非常清晰地分成了两个阶段来体现“先取地址，后加 1”。具体拆解如下：

### 1. “先取地址” 在图中的体现

**体现位置：** 图中的 `(R2) -> MAR` 以及后续的读主存和写回主存操作。

**原理解释：**
*   当执行到 `(R2) -> MAR` 时，R2 寄存器里装的是**原始的、未被修改的地址**。
*   把这个原始地址送入 MAR 后，CPU 依据这个原始地址去主存中取出了目的操作数（`M -> MDR -> D`）。
*   更关键的是，直到执行加法 `(C)+(D) -> MDR` 并将结果写回主存 `MDR -> M(MAR)` 为止，**MAR 中始终保持着最初从 R2 传过来的那个原始地址**，完全没有被改变。
*   这就实现了“先取（用）地址”：**读取数据和写回结果，用的全都是加 1 之前的旧地址。**

### 2. “后加 1” 在图中的体现

**体现位置：** 图中最下方的最后两个微操作：
1. `(R2) -> D`
2. `(D) + 1 -> R2`

**原理解释：**
*   **为什么不直接写 (R2) + 1 -> R2？**
    因为在题目给定的硬件图中，R2 只是一个通用寄存器，它自己**没有内置的自增硬件逻辑**（不同于通常带有独立 +1 逻辑的 PC）。
*   **如何实现加 1？**
    既然 R2 自己不能加，就必须**借助算术逻辑单元 (ALU)** 来完成加法。
*   **具体数据通路：**
    为了让 ALU 算 `R2 + 1`，必须把 R2 的值送到 ALU 的输入端。由于单总线的限制和 ALU 的缓冲需求，控制器先将 R2 的值送入暂存器 D（即 `(R2) -> D`，此时暂存器 D 原来的操作数使命已经结束，可以被覆盖）。然后，ALU 执行 `D 的内容 + 1`，并将结果通过总线重新打入 R2 寄存器（即 `(D) + 1 -> R2`）。
*   **时间顺序：**
    注意这两个操作处于整个指令周期的**最末尾**。此时，真正的运算结果已经安全地写回到了主存的原地址。这时再修改 R2 的值，既完成了“后加 1”的要求，又绝对不会破坏之前的访存地址。

**总结：**
图中的流程严格遵守了串行逻辑：
上半部分用 **未改变的 R2** 送入 MAR 去干活（先用）；
下半部分活干完后，把 **R2 送进 ALU 加 1** 再存回 R2（后加）。


# 2 题里有寄存器的话，还是尽量用
针对你的两个疑惑，直接给出结论：
1. **直接写 `(MDR) + (ACC)` 是错的**，因为硬件连线上不支持。
2. **`=` 和 `+` 是特定部件的操作控制信号**，表示让计算部件执行加法。

下面根据你提供的硬件结构图，为你详细拆解原因。

### 疑惑一：为什么不能直接 `(MDR) + (ACC)`？

在 408 的数据通路题中，**所有的微操作必须严格遵循图中画出的物理连线，不能凭空跳跃。**

1. **观察 ALU 的输入端：**
   - **左输入端**：接收来自 `ACC` 或 `MO` 的数据。
   - **右输入端**：**唯一**接收来自暂存器 `X` 的数据。（注意看图，从 X 底部有一条线直接连入 ALU 的右侧）。
2. **观察 MDR 的输出端：**
   - `MDR` 的输出箭头指向上方，连入**公共总线**。它并没有直接连到 ALU 的输入端。
3. **结论：**
   当你想把主存里取出的数据（此时在 MDR 中）与 ACC 相加时，由于 ALU 右侧只能吃 `X` 里的数据，你必须先让 MDR 的数据上总线，并打入寄存器 `X` 中。
   因此，**必须经过 `(MDR) -> X` 这一步作为缓冲**。对应的控制信号就是让 MDR 输出（`MDRo`），让 X 接收（`Xi`）。

### 疑惑二：控制信号里的 = 和 + 是怎么回事？

这些符号代表的是发给**运算部件的功能选择信号**。

在解答表中，出现了两种带有 `+` 的控制信号，分别对应图中的两个不同的计算部件：

**1. 独立出现的 `+` （例如取指周期和计算 EAR 时）**
- **对应部件**：图中的 **“地址加法器”**。
- **解析**：在计算变址寻址的有效地址 `(XR) + Ad(IR) -> EAR` 时，看图可知 `XR` 和 `IR` 的下端连入了一个叫“地址加法器”的梯形部件。旁边标注了一个小的 `+` 号。表里的 `+` 就是发给这个专用部件的控制信号，命令它执行加法。

**2. 带有等号的 `Ki = +` （例如执行周期的最后）**
- **对应部件**：图中的主 **ALU**。
- **解析**：看图，主 ALU 的右下角有一个控制信号输入端标注为 **`Ki`**。`Ki` 是一组控制线的统称，用于告诉 ALU 当前要做什么运算（加、减、与、或等）。
- **= 的含义**：这里的 = 就是赋值/指定的含义。
- **综合含义**：Ki = + 明确表示“向 ALU 的 Ki 控制端口发送**加法 (+)**指令”。同理，如果指令是减法，控制信号就会写成 Ki = -。


**总结备考要点：**
看单总线结构图时，运算器（ALU）的输入端往往会带有**暂存器**（如本题的 `X`，或者上一题的 `Y`）。单总线在一个时钟周期内只能传一个数，运算器需要两个数同时到达才能算，所以**“先取一个数放进暂存器，再连同总线上的另一个数一起算”**是这类题的固定物理约束，千万不能省略。

rs，rd  
一个是 source，一个是 destination

- **rd 是用来“写”的（Destination 目的寄存器）**：
    
    - **机制**：你要向 16 个寄存器中的某**一个**写入数据，必须且只能打开那**一个**寄存器的“写使能（Write Enable）”开关。怎么把 4 位的编号转换成 16 根独立的开关线？必须使用**地址译码器**（输入 4 位，输出 16 位，同一时刻只有 1 根输出有效）。
        
    - **结论**：rd 应连接**地址译码器**。
        
- **扩展：rs 是用来“读”的（Source 源寄存器）**：
    
    - **机制**：16 个寄存器内部都有数据，你要把其中**某一个**的数据挑出来送到公共输出端。这是一个“多选一”的过程，必须使用**多路选择器（MUX）**。rs 的 4 位信号就是 MUX 的控制端，决定导通哪一路。

### 正确的满分答案及机制推导

要做到“最少节拍”，核心物理法则就是：**在不发生总线冲突（同一时间只有一个人往内部总线发数据）的前提下，把能并行做的动作塞进同一个时钟周期。**

**T1 节拍： `PC -> MAR`, `1 -> R`, `PC + 1 -> R2`**
*   *物理动作*：打开 PC 的输出门，PC 的值送到内部总线上。
*   *并行机制*：
    1. MAR 的输入门打开，把总线上的 PC 值锁存（完成了发地址）。
    2. 控制器向主存发出读信号 `1 -> R`。
    3. **关键优化**：因为 PC 的值此时就在总线上，ALU 的左端口直接截获这个值，执行 `+1` 运算，随后将结果锁存进 R2 的输入门。
*   *总线占用*：内部总线被 PC 占用。合法。

**T2 节拍： `M(MAR) -> MDR`, `R2 -> PC`**
*   *物理动作*：主存根据 MAR 的地址找到指令，顺着**系统数据总线（外部）**送到 MDR 中。
*   *并行机制*：主存读数据非常慢，而且它走的是外部总线。此时 CPU 的**内部总线是空闲的**！所以我们抓紧这个周期，打开 R2 的输出门和 PC 的输入门，把刚才算好的新地址写回 PC。
*   *总线占用*：内部总线被 R2 占用。合法。

**T3 节拍： `MDR -> IR`**
*   *物理动作*：指令已经成功到达 MDR。打开 MDR 输出门，送上内部总线，打开 IR 的输入门，指令正式进入控制器。
*   *总线占用*：内部总线被 MDR 占用。合法。

**总结：**
你原本光算一个 PC+1 就要花 3 个节拍。而在利用了“ALU 直连总线”的物理特性，并利用“内外总线并行”的机制后，**整个完整的取指周期 + PC 自增**，总共只需要 3 个节拍。这就是 408 考查“最少节拍”的真正用意。你写的这段微操作，如果在真正的 408 考场上，几乎拿不到分。你的答案犯了两个致命错误。

    * *   **对应的控制信号**： `PCout=1, MARin=1, R=1, ALUop=INC, R2in=1`
    *     *   *拆解说明*：
    *         *   `PC -> MAR` 被拆解成了两个开关：打开 PC 朝向内部总线的输出门（`PCout=1`），同时打开 MAR 接收内部总线数据的输入门（`MARin=1`）。
    *         *   `1 -> R` 直接对应主存读命令信号（`R=1`）。
    *         *   `PC + 1 -> R2` 被拆解为：命令 ALU 执行自增操作（`ALUop=INC`，因为 PC 的值已经在总线上了，ALU 左端自动接收），同时打开 R2 的输入门接收 ALU 算出的结果（`R2in=1`）。
    * 
    * #### T2 节拍
    * *   **微操作描述**： `M(MAR) -> MDR`, `R2 -> PC`
    * *   **对应的控制信号**： `MDRinE=1, R2out=1, PCin=1`
    *     *   *拆解说明*：
    *         *   `M(MAR) -> MDR` 对应打开 MDR 朝向外部系统数据总线的输入门（`MDRinE=1`，E 代表 External，专门接收外部主存送来的数据）。
    *         *   `R2 -> PC` 对应打开 R2 的输出门（`R2out=1`）和 PC 的输入门（`PCin=1`），内部总线被 R2 到 PC 的数据流占据。由于主存数据走外部总线，这两件事在物理上不冲突。
    * 
    * #### T3 节拍
    * *   **微操作描述**： `MDR -> IR`
    * *   **对应的控制信号**： `MDRout=1, IRin=1`
    *     *   *拆解说明*：
    *         *   主存的数据已经安稳待在 MDR 里了。此时打开 MDR 朝向内部总线的输出门（`MDRout=1`），并打开指令寄存器的输入门（`IRin=1`），指令真正进入控制器。

![[_attachments/image/03大题-1784195476495.jpeg]] ## 为什么不需要额外等一个周期

你的困惑可能在于：「ADD 在周期 3 做运算，SUB 也在周期 3 做译码取数，SUB 怎么在同一周期就拿到了 ADD 的结果？」

实际上 SUB 并不是在周期 3 的"取数"阶段就用到了 ADD 的结果。时序拆开看：

|周期|ADD 在做什么|SUB 在做什么|
|---|---|---|
|3|运算 → 周期3末ALU输出结果，锁存到流水线寄存器|译码取数（从寄存器堆读R1，可能读到旧值，没关系）|
|4|写回|**运算** → 此时才真正需要R1的值作为ALU输入|

关键点：SUB 真正需要 R1 的值是在周期 4 它自己进入运算阶段、要把数送进 ALU 输入端的那一刻。而 ADD 的结果在周期 3 末尾已经产生并锁存好了。

旁路硬件做的事情是：在周期 4 开始时，用一个多路选择器（MUX）检测到「SUB 要用的源寄存器 = ADD 刚写出的目标寄存器」，于是 MUX 选择从上一级流水线寄存器（存着 ADD 的运算结果）直接送到 SUB 的 ALU 输入端，而不是用 SUB 在周期 3 从寄存器堆读出的那个（可能过时的）值。

所以本质是：

- **不用旁路时**：SUB 的"取数"阶段必须从寄存器堆读到正确值 → ADD 必须先写回（周期4）→ SUB 最早周期5才能译码取数 → 停顿2拍。
- **用旁路时**：SUB 的"取数"阶段读到什么无所谓，因为到运算阶段时硬件会用旁路通路把正确值"截获替换"到 ALU 输入端 → SUB 正常流动，无需停顿。

文中说的"将结果送入 ALU 的一端"就是指这个 MUX 选择旁路数据的动作。它发生在 SUB 运算阶段的起始时刻，不是在取数阶段。表格里 SUB 周期3写的"指令译码并取数"那一步读寄存器堆读到的值，最终会被旁路来的值覆盖掉（在硬件层面是 MUX 没选它）。
