# CPU 工作｜知识点整理

> [!info] 使用定位
> 本笔记把 [[002王道题]] 与 [[2.知识库/20.North_star_ZJU/202.计算机知识/计组/cpu工作/03大题]] 中零散的疑问整理成一套可推导的框架。错题回忆与大题模板见 [[04错题复盘]]。

# 一、总框架

CPU 执行指令可以压缩成三件事：

1. **保存状态**：PC、IR、通用寄存器、标志寄存器、段间寄存器保存当前机器状态。
2. **搬运与运算**：数据沿总线、MUX、扩展器、ALU、移位器和存储器接口流动。
3. **产生控制**：控制器根据指令、时序和条件，决定这一拍谁输出、谁接收、做什么运算。

关系链：

**机器指令 → IR → 控制器译码/定序 → 控制信号 → 数据通路动作 → 状态更新**

> [!summary] 一句话
> **CPU = 数据通路 + 控制部件。** 数据通路负责“数据怎么走、怎么算”，控制部件负责“这一拍让谁动”。

# 二、寄存器与位宽

## 2.1 常见寄存器

| 部件 | 核心职责 | 易错点 |
|---|---|---|
| PC | 保存下一次取指所使用的地址 | 转移/中断只是改写 PC，不是绕过 PC 取指 |
| IR | 保存当前正在译码/执行的指令 | 直接连接译码控制逻辑，GPR 不能随意替代 |
| MAR | 保存本次访存地址 | 位数与可表示的地址数量相关 |
| MDR | 暂存主存读出或待写入的数据 | 常与存储字长、数据通路宽度相关，但不是无条件相等 |
| GPR | 保存操作数、地址或中间结果 | 程序可见，可由指令字段编号 |
| PSW/标志寄存器 | 保存 Z、C、V、N 等状态 | 常被指令隐式读写，不等于完全不可访问 |
| 段间寄存器 | 保存流水级之间的数据和控制位 | 既传数据，也传后续阶段控制信号 |

## 2.2 四种位宽

| 名称 | 回答的问题 | 典型对应 |
|---|---|---|
| 机器字长 | CPU 一次整数运算主要处理多少位 | ALU、GPR 宽度 |
| 数据总线宽度 | 一次总线传输能搬多少位 | 常与 MDR 宽度相关 |
| 地址总线宽度 | 一次能给出多少位地址 | 常与 MAR 宽度相关 |
| 存储字长 | 一个存储字包含多少位 | 常与一次访存数据量相关 |

> [!danger] 纠偏：n 位 CPU
> 32 位/64 位 CPU 通常首先指**机器字长或体系结构整数寄存器宽度**，不是定义为数据总线线数。机器字长、数据总线、地址总线可以相同，也可以不同。

## 2.3 PC 位数

### PC 保存完整字节地址

若指令地址空间需要 $a$ 位字节地址，常见关系是：

$$
PC\text{位数}\approx MAR\text{位数}\approx\text{地址总线宽度}
$$

这是常见设计关系，不是跨所有体系结构的恒等式。

### PC 保存定长指令字地址

若每条指令固定占 $L$ 字节、按 $L$ 字节边界对齐，且题目允许 PC 省略恒为 0 的低位：

$$
PC\text{有效位数}=\text{字节地址位数}-\log_2L
$$

使用前提：**定长、对齐、题目明确采用字地址或省略低位。**

## 2.4 PC 更新

- 顺序执行：取指后形成下一条顺序地址。
- 条件转移成立：写入目标地址；不成立：继续使用顺序地址。
- CALL：保存返回地址，再把子程序入口写入 PC。
- RET：把返回地址恢复到 PC。
- 中断/异常：硬件形成处理入口并改写 PC。

# 三、指令周期、时钟与实现方式

## 3.1 时间概念

| 概念 | 含义 |
|---|---|
| 时钟周期 | 状态元件更新的基本节拍，主频为其倒数 |
| 机器周期/CPU 周期 | 完成一个相对独立子任务的时间，可能含多个时钟周期 |
| 存储周期/总线周期 | 完成一次存储器或总线事务的时间 |
| 指令周期 | 从取出一条指令到完成它的全部时间 |

> [!warning] 不要死背严格不等式
> 这些概念存在层级关系，但不同机器划分不同，不能把“时钟周期 < 存取周期 < 机器周期 < 指令周期”当成普遍严格定律。以题目定义和时序为准。

## 3.2 指令周期阶段

1. **取指周期**：PC → MAR，发读命令，MDR → IR，PC 顺序更新。
2. **间址周期**：需要间接寻址时，再访存取得有效地址。
3. **执行周期**：完成运算、访存、转移或写回。
4. **中断周期**：检测并响应中断，保存断点，形成处理入口。

不是每条指令都有间址周期或中断周期。

## 3.3 单周期、多周期、流水线 CPU

| 对比 | 单周期 | 多周期 | 流水线 |
|---|---|---|---|
| 指令占用 | 固定 1 拍 | 多拍 | 单条跨多级，多条重叠 |
| 时钟周期约束 | 最慢指令的完整路径 | 最慢阶段/微操作路径 | 最慢流水段 + 段间寄存器开销 |
| CPI | 1 | 大于 1，随指令变化 | 理想稳定状态接近 1 |
| 部件复用 | 一条指令内受限 | 可跨拍复用 | 多条指令分级并行 |
| 主要问题 | 周期长、短指令浪费 | 控制复杂、CPI 大 | 冒险与冲刷开销 |

> [!danger] 纠偏：多周期时钟周期
> 多周期 CPU 的时钟周期不是按“最快步骤”设置，而要保证**最慢阶段也能在一拍内完成**。它比单周期短，是因为只容纳一个阶段，而不是整条最慢指令。

## 3.4 DMA 两件事

- **周期窃取**：DMA 在总线/存储周期边界请求总线，CPU 可能暂停一个存取周期；这是总线仲裁，不是中断处理。
- **传送完成中断**：整块数据传完后发出外部中断请求，CPU 通常在当前指令结束后响应。

# 四、数据通路

## 4.1 元件分类

### 状态元件/时序元件

能跨周期保存信息：PC、IR、MAR、MDR、GPR、暂存寄存器、段间寄存器、存储单元。

### 组合逻辑/操作元件

输出由当前输入决定：ALU、加法器、移位器、MUX、扩展器、译码器、硬布线控制器的组合逻辑部分。

CPU 的基本节奏是：

$$
\text{寄存器输出}\rightarrow\text{组合逻辑传播}\rightarrow\text{下一组寄存器锁存}
$$

## 4.2 单总线约束

1. 同一拍，内部单总线通常只能有**一个输出源**。
2. 同一个总线值可以同时被多个接收端锁存。
3. ALU 需要两个输入时，常把一个操作数先放入暂存器，另一个由总线提供。
4. 微操作必须沿题图真实连线，不能越过 MUX、暂存器或移位器。
5. 主存—MDR 的外部通路与内部总线若独立，题目可能允许并行工作。

## 4.3 最少节拍

对每个微操作检查：

- 谁驱动内部总线？
- 谁接收？
- 是否占用 ALU/移位器/专用加法器？
- 数据是否已经产生？
- 是否走外部存储器通路？

没有资源冲突、数据已可用、时序允许，就可以合并到同一节拍。

## 4.4 微操作与控制信号

| 层次 | 示例 | 含义 |
|---|---|---|
| 微操作/RTL | PC → MAR | 描述数据流与基本运算 |
| 控制信号 | PCout=1，MARin=1 | 打开真实输出门和输入门 |

一个微操作通常由一组控制信号实现；一条微指令可以同时激活多组互不冲突的微操作。

# 五、控制器与微程序

## 5.1 控制器组成

教材常写：

$$
\text{控制器}=PC+IR+\text{操作控制器}
$$

操作控制器有两种典型实现：

- **硬布线**：逻辑门网络直接根据指令、时序和条件产生控制信号。
- **微程序**：从控制存储器读取微指令，由微指令产生控制信号。

不要把机器级 PC/IR 与微程序控制器内部的 μPC/μIR 混为一谈。

## 5.2 五个层次

**机器指令 → 对应微程序 → 若干微指令 → 一个或多个微操作 → 具体控制信号**

- 微程序：实现一条机器指令的一串微指令。
- 微指令：一个微周期内的控制信息和定序信息。
- 微操作：寄存器传送或基本运算。
- 控制信号：最终驱动硬件的电平。

## 5.3 微程序控制器部件

| 部件 | 作用 |
|---|---|
| 控制存储器 CM/CS | 保存微程序 |
| μPC/CMAR | 保存下一条微指令地址 |
| μIR/CMDR | 保存当前微指令 |
| 微地址形成部件 | 用增量、条件、操作码映射等形成下地址 |

408 默认模型中 CM 常用 ROM 表示；工程上也存在可写控制存储器，因此不要把 ROM 当作所有现实 CPU 的绝对规定。

## 5.4 微指令字段

- **操作控制字段**：本拍做什么。
- **判别测试字段**：本拍检查哪个条件。
- **顺序/下地址字段**：下一条微指令从控制存储器哪里取。

> [!warning] 两种“地址”
> 寄存器选择字段可以指定源/目的寄存器；下地址字段指定的是**下一条微指令地址**，两者不要混淆。

## 5.5 编码方式

### 直接编码

一位对应一根控制线：速度快、并行性高、微指令较长。

### 字段直接编码

互斥微命令放在同一字段，经译码后选出一个。若一组有 $n$ 个命令并保留“无操作”，通常需要：

$$
\left\lceil\log_2(n+1)\right\rceil
$$

### 字段间接编码

一个字段参与解释另一个字段，字长更短，但译码层次更多、速度更慢。

## 5.6 水平型与垂直型

| 对比 | 水平型 | 垂直型 |
|---|---|---|
| 编码程度 | 低，接近控制线 | 高，类似机器指令 |
| 字长 | 长 | 短 |
| 并行性 | 高 | 低 |
| 速度 | 快 | 译码较多，较慢 |

直接编码、字段直接/间接编码主要是在讨论水平型微指令操作控制字段的组织。

## 5.7 计算模板

- 控制存储器有 $2^a$ 个字，下地址至少 $a$ 位。
- 微指令字长为 $w$ 位，共有 $2^a$ 个字，容量为 $2^a\times w$ bit。
- 操作字段按直接编码或各互斥组编码求和。
- 判别字段根据条件数以及是否需要“不测试”状态确定。
- 公共取指微程序会占空间，不能把所有微指令字平均分给机器指令。

# 六、异常与中断

## 6.1 分类

| 类型 | 来源/性质 | 典型返回位置 |
|---|---|---|
| 外部中断 | I/O、时钟、DMA 完成等外部事件 | 下一条尚未执行的指令 |
| Fault 故障 | 当前指令执行中、原因可修复，如缺页 | 修复后重做当前指令 |
| Trap 陷阱 | 有意触发或执行完成后报告，如系统调用 | 下一条指令 |
| Abort 终止 | 严重且难恢复的硬件/一致性错误 | 通常无可靠返回地址 |

## 6.2 缺页为什么重做当前指令

当前指令尚未正常完成；OS 调页并更新页表后，重新执行才能产生正确的体系结构结果。

## 6.3 校验错误为什么常归入终止

机器校验可能来自硬件失效，CPU 状态或返回点可能不可靠；重新执行同一条指令未必能消除原因。

## 6.4 响应与处理程序

- **异常/中断响应**：硬件保存必要状态、切换特权级、形成入口并改写 PC。
- **处理程序执行**：响应完成后，CPU 才开始执行 OS/内核代码。
- 上下文切换通常由内核调度程序实现，可能由中断触发，但不等于硬件响应本身。

# 七、流水线

## 7.1 五级流水线

| 阶段 | 功能 |
|---|---|
| IF | 取指 |
| ID | 译码、读寄存器、产生控制信号 |
| EX | ALU 运算或有效地址计算 |
| MEM | 数据存储器读写 |
| WB | 写回寄存器堆 |

某条指令不需要某一级时，通常仍按统一节拍经过该级，只是相应控制信号无效。

## 7.2 性能公式

同步 $k$ 段、统一时钟为 $\Delta t$：

$$
T=(k+n-1)\Delta t
$$

若题目按第一条真实经过各段时间、后续按瓶颈间隔完成：

$$
T=\sum t_i+(n-1)\max(t_i)
$$

工程上常有：

$$
T_{clk}=\max(t_i)+t_{latch}
$$

其中 $t_{latch}$ 是段间寄存器开销。

## 7.3 段数不是越多越好

细分流水段可缩短组合逻辑路径、提高主频，但会增加段间寄存器开销、冒险处理难度、分支冲刷代价、功耗和控制复杂度。

## 7.4 控制信号也要流水

ID 产生的控制位与数据一起进入 ID/EX、EX/MEM、MEM/WB。每一级消费本级所需控制位，并把后续阶段的控制位继续传递。

## 7.5 三类冒险

### 结构冒险

同一拍，多条指令竞争同一个不能并行服务的资源。

解决：资源分离/复制、固定资源使用阶段、插入停顿。例如 I-Cache 与 D-Cache 分开可避免 IF 与 MEM 争同一存储端口。

### 数据冒险

经典顺序流水线主要关注 RAW。判断顺序：

1. 前指令何时产生值？
2. 后指令何时真正需要值？
3. 能否旁路到使用端？
4. 不能旁路则停几拍？

- ALU → ALU：前条 EX 末产生结果，常可转发给后条 EX，通常无需停顿。
- LOAD → 立即使用：数据到前条 MEM 末才产生，后条 EX 来不及，经典五级流水线通常至少停 1 拍。

### 控制冒险

分支、跳转、中断、异常改变 PC。在新 PC 确定前可能已取入错误指令，需要停顿、预测或冲刷。流水线越深，预测失败代价通常越大。

## 7.6 旁路的本质

旁路把**已经产生但尚未写回**的结果，从流水线寄存器经 MUX 直接送给后继指令的 ALU 输入。它绕过写回等待，但不能让尚未产生的数据“提前出现”。

## 7.7 RISC 与 Load/Store

- 只有 LOAD/STORE 访问数据存储器。
- ALU 指令只对寄存器操作。
- LOAD 的 EX 计算地址，MEM 才读到数据。
- 高级语言结果若要更新内存，最后不能漏 STORE。
- 操作数按边界对齐可避免一次数据跨多个存储字，减少多次访存和阻塞。

## 7.8 超流水线、超标量、VLIW

| 技术 | 核心做法 | 调度责任 |
|---|---|---|
| 超流水线 | 继续细分流水段，提高时钟频率 | 硬件流水控制 |
| 超标量 | 每拍动态发射多条普通指令 | 硬件动态检测/调度 |
| VLIW | 长指令显式包含多个并行操作 | 编译器静态调度为主 |

VLIW 省掉大量动态调度硬件，但仍需要多个执行部件、宽取指通路和多端口寄存器堆。

# 八、多处理器、多核与硬件多线程

## 8.1 概念

| 概念 | 含义 |
|---|---|
| 多处理器系统 | 多个处理器/处理单元协同工作 |
| 多核 CPU | 一个芯片集成多个完整物理核心 |
| 硬件多线程/SMT | 一个物理核维护多套线程状态，共享核心执行资源 |

超线程不会把 4 个物理核变成 8 个物理核。

## 8.2 共享程度

- SMT 线程共享同一物理核的流水线、执行单元和部分缓存，竞争最直接。
- 多核有独立核心执行资源，但仍可能共享末级 Cache、内存控制器、总线与内存带宽。
- 因此“多核绝不冲突”和“超线程资源完全独立”都不成立。

## 8.3 Cache

常见但非唯一的组织：L1 每核私有；L2 可私有或共享；末级 Cache 常由多个核心共享。不同私有 Cache 之间要靠一致性协议维护共享数据视图。

## 8.4 UMA 与 NUMA

| 对比 | UMA | NUMA |
|---|---|---|
| 访问延迟 | 各处理器大体一致 | 本地快、远端慢 |
| 结构 | 共享内存/统一访问 | 节点有本地内存，经互连访问远端 |
| 扩展性 | 共享带宽易成瓶颈 | 通常更易扩展，但管理更复杂 |
| 重点 | Cache 一致性、共享带宽 | 数据放置、远端访问、一致性 |

> [!danger] 纠偏：处理器数量
> 处理器、插槽和核心数量取决于具体系统，不能推出“必须是偶数”，也不能推出“必须是 2 的幂”。选择题遇到这种绝对数量规律要优先检查。

# 九、最容易混淆的概念

| A | B | 最小区分句 |
|---|---|---|
| PC | MAR | PC 保存下一取指地址；MAR 保存当前访存地址 |
| MDR | 数据总线 | MDR 是状态寄存器；数据总线是传输通路 |
| 机器字长 | 存储字长 | 前者看 CPU 运算；后者看存储字组织 |
| IR | μIR | IR 存机器指令；μIR 存微指令 |
| PC | μPC | PC 指向机器指令；μPC 指向控制存储器中的微指令 |
| 微程序 | 微指令 | 前者是一串；后者是一拍的控制字 |
| 微操作 | 控制信号 | 前者描述逻辑动作；后者是实现动作的硬件开关 |
| 中断响应 | 中断服务程序 | 前者是硬件进入入口；后者是之后执行的软件代码 |
| DMA 周期窃取 | DMA 完成中断 | 前者是总线仲裁；后者是外部中断请求 |
| 延迟 | 吞吐率 | 延迟看单个任务；吞吐看单位时间完成量 |
| 转发 | 写回 | 转发直接送给使用者；写回更新体系结构寄存器 |
| 多核 | 超线程 | 多核复制完整核心；超线程共享一个核心的执行资源 |

# 十、选择题绝对词检查

看到以下词，先寻找反例或限定：

- **总是/一定**：条件转移是否不成立？异常是否不可恢复？
- **所有/任何**：不同 ISA、不同 Cache 层级、不同存储时序是否有例外？
- **完全独立/互不干扰**：是否共享 Cache、总线、内存带宽？
- **只能/不能**：是体系结构规定，还是仅仅不能作为普通显式操作数？
- **位数相等**：是定义、典型实现关系，还是题设条件下近似？
- **每拍完成一条**：说的是单条延迟，还是流水线稳定吞吐率？
