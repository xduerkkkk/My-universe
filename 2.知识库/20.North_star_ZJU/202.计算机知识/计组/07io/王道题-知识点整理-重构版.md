> [!abstract] 章节主线
> CPU 不直接适配每种外设：I/O 接口完成缓冲、格式/时序适配与控制；程序查询、中断、DMA、通道的本质区别，是“谁等待、谁搬每个数据单位、谁管理整个块、CPU 何时介入”。

## 1. I/O 接口的边界

### 1.1 连接链路

$CPU/主存 \leftrightarrow 系统总线 \leftrightarrow I/O接口 \leftrightarrow 设备侧链路 \leftrightarrow 外设$

| 位置 | 典型信息/功能 |
|---|---|
| CPU ↔ 接口 | 端口/寄存器地址、读写命令、数据、状态、中断/DMA 请求 |
| 接口内部 | 数据缓冲、状态/控制寄存器、地址译码、格式与时序适配、握手 |
| 接口 ↔ 外设 | 设备数据、控制、状态和协议时序 |

### 1.2 接口还是外设

- **接口/控制部件**：适配器、控制器、接口卡、网卡、中断控制器。
- **外设本体**：打印机、键盘、显示器、磁盘驱动器。
- 真实系统可能高度集成，考试按功能层次判断：是否承担主机与设备之间的适配和控制。

### 1.3 格式转换

- 串/并转换；
- 字长、编码与电平适配；
- 异步/同步时序与速度匹配；
- 通过数据缓冲寄存器隔离 CPU 与慢速外设。

> [!warning] 旧版表述：并行/串行老老实实看数据线是一根还是多根。
> **校正**：核心是数据位在协议上按时间串行还是通过多个并行通道同时传送。差分对、多 lane 串行链路不能只按导线根数判断。  
> **适用条件**：磁盘单磁头沿磁道的位流是典型串行。

## 2. 名称与抽象层次

| 名称 | 含义 | 边界 |
|---|---|---|
| 逻辑设备名 | 程序使用的设备抽象 | 支持设备独立性 |
| 物理设备 | 具体硬件实例 | 由 OS/驱动管理 |
| 主/次设备号 | Unix/Linux 常见设备标识 | 不是所有 OS 的普遍定义 |
| 驱动程序 | OS 中控制设备的软件 | 不等于 drive（驱动器） |
| 控制器/适配器 | 连接与控制硬件 | 通常属于接口 |

## 3. 指令与 I/O 软件栈

- **机器指令**：CPU 指令集直接执行的编码。
- **专用 I/O 指令**：独立编址体系中的 IN/OUT 等，通常为特权指令。
- **存储器映射 I/O**：用普通 load/store 访问设备寄存器。
- **系统调用**：用户程序进入内核请求 I/O 服务；不是某一条 I/O 机器指令。
- **设备驱动**：内核中把通用 I/O 请求翻译为设备寄存器操作。

## 4. 中断机制

### 4.1 中断从请求到返回

1. 中断源提出请求，请求触发器锁存。
2. 屏蔽与判优逻辑筛选可响应请求。
3. CPU 在规定时点检查请求；普通外部中断通常在当前指令结束后响应。
4. 执行中断隐指令：关中断、保存断点/必要状态、形成 ISR 入口。
5. ISR 软件保护通用寄存器、处理中断、恢复现场。
6. 中断返回指令恢复 PC/PSW，回到被中断程序。

### 4.2 关键部件

| 部件 | 作用 |
|---|---|
| 中断请求触发器 | 锁存单个中断源的请求 |
| IF/EINT | CPU 全局可屏蔽中断允许位 |
| 屏蔽寄存器/屏蔽字 | 按中断源选择允许或屏蔽 |
| 判优电路 | 多个请求并存时决定响应顺序 |
| 中断向量表 | 提供 ISR 入口相关信息 |

### 4.3 向量相关术语

- **中断向量**：用于找到 ISR 的信息，可能直接是入口，也可能是表项内容。
- **中断向量地址**：向量表项本身的地址。
- **ISR 入口地址**：CPU 最终转入执行的位置。
- 三者是否相等依体系结构，不能机械画等号。

### 4.4 响应优先级与处理优先级

- 响应优先级解决“多个等待请求先接受谁”。
- 处理优先级/屏蔽策略解决“某 ISR 执行时谁能嵌套”，影响完成顺序。
- 硬件优先级可由软件配置；不要把“硬件管开始、软件管结束”当作无条件定义。

### 4.5 中断请求与 EOI

- 外设/控制器向 CPU 提出的是中断请求。
- DMA 传完一块后可提出“传输完成中断请求”。
- 某些中断控制器需要 CPU 在 ISR 尾部发送 EOI，表示服务已完成。
- 完成原因与 EOI 控制动作不是同一个信号。

## 5. 周期与检测时点

| 名称 | 含义 | 关系/提醒 |
|---|---|---|
| 时钟周期 | CPU 最小节拍 | 多个节拍组成更大操作 |
| 总线周期 | 完成一次总线事务 | 可含多个时钟周期 |
| 机器周期 | 完成一个基本机器操作 | 教材中常与一次访存/总线周期接近，但不必然等同 |
| 指令周期 | 完成一条指令 | 含一个或多个机器周期 |
| 存取时间 | 从发出读命令到数据可用 | 存储器响应延迟 |
| 存取周期 | 两次独立存取可连续开始的最小间隔 | 通常不小于存取时间 |

- **普通中断请求**：常在指令结束处检测/响应。
- **DMA 总线请求**：常在机器/总线周期结束、两个存取周期之间让出总线。
- **DMA 完成中断**：回到普通中断的响应时点。

> [!warning] 旧版表述：机器周期/总线周期就是一次主存读写；流水线每段一定等于一个机器周期且一个时钟周期。
> **校正**：这些相等关系只在特定教材模型或特定处理器设计中成立。  
> **答题动作**：优先使用题目明示的层级关系，不跨题套用。

## 6. 四类 I/O 控制方式

| 方式 | CPU 等待 | 每个数据单位由谁搬 | 块级管理 | 典型开销 |
|---|---|---|---|---|
| 独占程序查询 | 忙等 | CPU 指令 | CPU | CPU 占用最高 |
| 定时程序查询 | 间歇查询 | CPU 指令 | CPU | 可做其他工作但有轮询开销 |
| 中断驱动 | 设备工作时 CPU 可并行 | ISR 中 CPU 指令 | CPU/驱动 | 每个单位或小批次有中断开销 |
| DMA | CPU 只初始化/收尾 | DMA 控制器 | DMA 控制器 | 总线争用 + 每块一次管理开销 |
| 通道 | CPU 参与更少 | 通道执行通道程序 | 通道 | 适合复杂/大量 I/O |

### 6.1 程序查询的边界

- “CPU 一直查”只描述独占查询。
- 定时查询期间 CPU 可做其他工作，但数据搬运仍由 CPU 指令完成。
- 地址递增与计数递减在程序控制方式下由软件完成。

### 6.2 中断驱动仍是程序搬运

- 中断只让 CPU 不必忙等。
- 设备就绪后，ISR 执行 I/O 指令，把数据在接口寄存器与 CPU/主存之间搬运。
- 数据总线的电信号由硬件完成，不等于“整个数据传送方式不是软件控制”。判断主体要看谁发起并逐次控制搬运。

### 6.3 DMA 的两个阶段

**初始化**：CPU 设置主存起始地址、传送方向、字数、设备等。  
**块内传送**：DMA 反复申请总线，更新地址与计数，传送一个字/一个突发。  
**结束**：DMA 在整块完成或异常时中断 CPU，驱动检查状态并唤醒等待进程。

## 7. DMA 请求、优先级与通路

### 7.1 两种“请求”

| 名称 | 目的 | 响应时点 |
|---|---|---|
| HRQ/HOLD 等总线请求 | 为一次 DMA 总线事务借总线 | 机器/总线周期边界 |
| DMA 完成中断请求 | 通知整块完成或异常 | 指令结束后的中断响应 |

### 7.2 DMA 与 CPU 谁优先

- 经典 408 模型中，高速设备 DMA 总线请求常优先于 CPU 普通访存，以免设备缓冲溢出。
- 这是**总线仲裁层次**，不能直接推出“DMA 高于任何非屏蔽中断”。
- 周期挪用方式下，CPU 仅在 DMA 占用的那些总线周期不能访存；两次挪用之间仍可运行。
- 停止 CPU 访存、周期挪用、交替分时等方式必须按题设区分。

### 7.3 DMA 是否破坏现场

- 不改变 PC、PSW、通用寄存器，因此无需中断式现场保护。
- 会造成总线停顿；这影响执行时间，不是现场破坏。
- DMA 与 Cache 不一致属于更高层存储一致性问题，需要一致性硬件或缓存维护。

### 7.4 数据通路

- 逻辑源/终点：设备接口 ↔ 主存。
- 控制者：DMA 控制器。
- 物理承载：共享系统总线/互连，而不是必然存在专用私线。
- 一次任务通常搬一块；一次总线事务搬一个字、若干字节或一个突发。

## 8. 通道

- 通道是专门执行 I/O 的处理部件，可执行存放在主存中的通道程序。
- CPU 通常通过访管/系统调用发起 I/O；通道完成后通过 I/O 中断通知 CPU。
- 与 DMA 相比，通道可解释更复杂的 I/O 指令序列，管理多个设备和多步操作。

## 9. 异常与中断的边界

| 事件 | 典型处理 |
|---|---|
| Cache 未命中 | 硬件补块，通常不作为程序可见中断 |
| 缺页 | 同步异常/缺页异常，由 OS 处理 |
| 浮点异常 | 设置异常标志；是否陷阱取决于标准、体系结构与屏蔽配置 |
| 外设就绪 | 外部异步中断 |
| DMA 块完成 | 外部中断通知 |

> [!warning] 旧版表述：浮点上溢一定中断，下溢通常直接当 0 且不中断。
> **校正**：IEEE 754 定义异常标志和默认结果；是否触发软件可见陷阱取决于体系结构与异常屏蔽。下溢还可能产生非规格化结果，不必直接变 0。

## 10. 计算题模板

### 10.1 中断可行性与占用率

- 设备事件间隔：$T_d=1/f_d$。
- 每次可用 CPU 周期：$N_d=f_c/f_d$。
- 单次服务成本：响应 + 现场保护恢复 + ISR 指令。
- 可行条件：$C_i\le  N_d$。
- CPU 占用率：$U=f_dC_i/f_c$。

### 10.2 DMA 占用率

- 每块次数：$f_{block}=R/B$，其中 R 为字节率，B 为块大小。
- CPU 成本：初始化周期 + 完成中断周期。
- 总线成本：传送字节数 ÷ 每次总线传送字节数 × 单次总线周期。
- 分清题目问 CPU 时间还是系统总线占用时间。

### 10.3 异步串行通信

$每字符位数=起始位+数据位+校验位+停止位$

- 字符率 = 波特率 ÷ 每字符位数（每个符号承载 1 bit 时）。
- 起始位是最常漏项；停止位数量按题设。

### 10.4 缓冲区事件

- 缓冲区填满频率：$f=R/B$。
- 填满间隔：$T=B/R$。
- CPU 占比：$f\times 单次CPU成本/CPU每秒总周期$。

## 11. 易混概念

- **设备驱动器 vs 设备驱动程序**：硬件 drive vs 软件 driver。
- **中断向量地址 vs ISR 入口地址**：表项位置 vs 最终入口。
- **中断请求 vs EOI**：设备请求服务 vs CPU 表示服务完成。
- **DMA 总线请求 vs DMA 完成中断**：借总线 vs 报告整块结束。
- **总线优先级 vs 中断优先级**：两个仲裁层次。
- **数据由硬件线上传输 vs 传送方式由软件控制**：物理实现与控制主体不同。
- **任务总耗时 vs CPU 占用时间**：设备等待可延长前者但不一定占用后者。

## 12. 绝对词检查

- “DMA 永远比 CPU/所有中断优先” → 先问比较的是总线还是中断。
- “程序查询一定一直忙等” → 区分独占与定时查询。
- “中断响应周期动作固定” → 检查教材模型和体系结构。
- “设备从来不发结束信息” → 可发“完成原因的中断请求”，但不等于 EOI。
- “DMA 数据完全不经过 DMA 控制器” → 区分逻辑源终点与内部缓冲实现。
- “机器周期等于总线周期等于时钟周期” → 仅在特定题设成立。
