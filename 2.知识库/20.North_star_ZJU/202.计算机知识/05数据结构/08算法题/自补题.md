### 一、深度拆解：判断有向图中是否存在“长度为 $k$ 的简单路径”

#### 1. 先抠字眼（408 的概念陷阱）
在考场上看到这道题，第一步不是写代码，而是翻译那两个专有名词：
* **“长度为 $k$”**：路径的长度是指路径上**边的条数**（不是顶点数！）。从 $u$ 到 $v$ 长度为 $k$，意味着从 $u$ 出发，要跨过 $k$ 条边才能到达 $v$。每往下走一步，剩余需要走的步数就变成 `k - 1`。
* **“简单路径”**：教材定义——**顶点不重复出现的路径**叫做简单路径！
  * 这意味着什么？意味着我们需要一个 `visited[]` 数组，走过的顶点标记为 `1`，不能再踩第二次（防止在环里原地打转凑步数）！

---

#### 2. 为什么普通 DFS 是错的？必须加一句 `visited[u] = 0`？（全题最核心痛点！）

我们先看一张极简的有向图，假设我们要找从 **1 到 4**，长度为 **$k = 3$**（走 3 步）的简单路径：

```text
   1 ——(第1步)——> 2 ——(第2步)——> 4  (提前到了！只走了2步，不对！)
   |              ^
 (第1步)        (第2步)
   v              |
   3 —————————————+
```
图中有两条路：
* 第一条：`1 -> 2 -> 4`（长度是 **2**，不符合 $k=3$ 的要求）。
* 第二条：`1 -> 3 -> 2 -> 4`（长度是 **3**，符合要求！）。

现在，假设我们站在起点 `1`，邻接表里 `1` 的第一个邻居是 `2`，第二个邻居是 `3`：
1. 我们先顺着 `1 -> 2` 走：此时把顶点 `2` 标记为已访问（**`visited[2] = 1`**），接着走到 `4`。结果发现：哎呀，只走了 2 步就到终点 `4` 了（或者 `2` 是个死胡同），这条路凑不够 3 步，**失败返回**！
2. 重点来了！从 `2` 退回到 `1` 之后，顶点 `1` 准备去尝试它的第二个邻居 `3`（走 `1 -> 3 -> 2 -> 4` 这条正确的路）。
3. **如果你在顶点 `2` 失败退回之前，没有把 `visited[2]` 重新擦除成 `0`**：那么当你从 `3` 想要迈向 `2` 的时候，一看 `visited[2] == 1`（以为 `2` 已经在当前路径里了），直接不敢往 `2` 走！那条唯一正确的路径 `1 -> 3 -> 2 -> 4` 就被你活活堵死了！

**一句话总结：**
* **普通判断连通性（有没有路径）：** 不需要回溯 `visited[u] = 0`。因为只要从 `2` 走不到终点，以后从 `3` 绕到 `2` 也肯定走不到终点，标记死就标记死了。
* **限制步数 $k$ 的简单路径：** 必须回溯 `visited[u] = 0`！因为**“带着剩余 2 步经过顶点 `2` 失败了，不代表我从别的路绕过来、带着剩余 1 步经过顶点 `2` 也会失败！”** 退栈时必须擦掉脚印，把顶点 `2` 让给别的分支去用！

#### 3. 用你的“我是中间结点”思维，手把手写出这 30 行代码

现在，请你闭上眼睛，**想象你就是图中间的一个顶点 `u`**。
函数名叫：`int DFS(ALGraph G, int u, int v, int k, int visited[])`
意思是：**“我现在站在 `u`，手里还剩 `k` 步必须要走，能不能走到终点 `v`？”**

##### 第一步：先补退出入口（我一上来先看自己是不是已经结束了？）
我站在 `u`，低头看一眼：
1. **完美结局：** 我脚下就是终点 `v`（`u == v`），而且我手里的步数刚好用光了（`k == 0`）！太棒了，直接大喊一声找到了：
   ```cpp
   if (u == v && k == 0) return 1;
   ```
2. **悲剧结局（两个剪枝）：**
   * **情况 A（早产）：** 我脚下已经是终点 `v` 了（`u == v`），但手里居然还剩步数没走完（`k > 0`）！因为题目要求**简单路径（顶点不能重复）**，我已经踩在终点 `v` 上了，绝对不能从 `v` 溜达出去兜一圈再踩回 `v`（那样 `v` 就出现两次了！）。所以提前到达终点也是死路一条！
   * **情况 B（步数耗尽）：** 我脚下不是 `v`，但我手里的步数已经用光了（`k == 0`），不能再往前迈步了。
   把这两种悲剧合并成一句话：
   ```cpp
   if (u == v || k <= 0) return 0;
   ```

##### 第二步：我当前结点要做什么操作？
既然还没结束，我要继续往后走。为了防止我的子孙结点绕一圈又踩回我头上（违反简单路径），我先把我自己锁死（打上标记）：
```cpp
visited[u] = 1;
```

##### 第三步：拿现成的函数去使唤我的所有邻居！（遍历邻接表）
在二叉树里，你是使唤 `root->lchild` 和 `root->rchild`；
在邻接表里，你的“孩子们”全都串在 `G.vertices[u].firstarc` 这条单链表上！
我们就顺着单链表挨个问邻居 `w`：
```cpp
ArcNode *p = G.vertices[u].firstarc; // 拿到我的第一个邻居边结点
while (p != NULL) {
    int w = p->adjvex;               // 取出邻居顶点的下标 w
    
    // 如果邻居 w 还没被当前路径踩过，我就派它去走剩下的 k - 1 步！
    if (visited[w] == 0) {
        if (DFS(G, w, v, k - 1, visited) == 1) {
            return 1; // 只要有一个邻居汇报成功了，我直接向上级汇报成功！（短路截断）
        }
    }
    p = p->nextarc;                  // 这个邻居不行，问链表里的下一个邻居
}
```

##### 第四步：善后工作（擦掉脚印，退回上一层）
如果 `while` 循环走完了，说明我所有的邻居都试过了，全都没法在 `k - 1` 步内走到 `v`。
说明我当前这次探索失败了，我要退回给我的父结点了。
**临走前，必须把我脚下的标记擦掉，好让别的分支以后还能经过我：**
```cpp
visited[u] = 0; // 恢复现场（显式回溯）
return 0;       // 向上级汇报失败
```

你看！把这四步拼起来，是不是逻辑极其顺畅、没有任何一行多余的废话？这就是 408 的满分标准答案！

```cpp
#define MAXV 100 // 最大顶点数

typedef struct ArcNode {
    int adjvex;              // 该弧所指向的顶点的位置（数组下标）
    struct ArcNode *nextarc; // 指向下一条弧的指针
} ArcNode;

typedef struct VNode {
    int data;                // 顶点信息
    ArcNode *firstarc;       // 指向第一条依附该顶点的弧的指针
} VNode, AdjList[MAXV];

typedef struct {
    AdjList vertices;        // 邻接表数组
    int vexnum, arcnum;      // 图的当前顶点数和弧数
} ALGraph;
```

### 第一题：判断有向图中是否存在从 $u$ 到 $v$ 长度为 $k$ 的简单路径

#### 1. 算法基本思想
采用**深度优先搜索（DFS）结合回溯**的思想。
设辅助递归函数 `DFS(G, u, v, k, visited)`，表示当前到达顶点 `u`，还需向前走 `k` 条边到达终点 `v`。
每到达一个顶点 `u`，若 `u == v` 且 `k == 0`，说明找到目标路径，返回 1；若提前到达终点（`u == v` 但 `k > 0`，因简单路径顶点不可重复，不能再从 `v` 出发绕圈）或步数耗尽仍未到达（`k <= 0`），则返回 0。
否则，将 `u` 标记为已访问（`visited[u] = 1`），遍历 `u` 的边表链表，对每个未访问的邻接点 `w` 递归调用 `DFS(G, w, v, k - 1, visited)`。若某分支返回 1，则直接向上层返回 1；若所有邻接点均无法到达，则在函数退栈前**将 `visited[u]` 恢复为 0（显式回溯）**，以便其他路径分支仍可使用顶点 `u`，最后返回 0。

#### 2. 完整算法代码
```cpp
// 辅助递归函数：在邻接表G中寻找从u到v长度为k的简单路径
int DFS_PathK(ALGraph G, int u, int v, int k, int visited[]) {
    // 1. 递归出口：恰好到达终点v，且步数k刚好用完
    if (u == v && k == 0) {
        return 1;
    }
    // 2. 剪枝条件：提前踩到终点v（简单路径不能重复经过v）或步数已用尽
    if (u == v || k <= 0) {
        return 0;
    }
    
    // 3. 标记当前顶点u已访问，防止当前路径成环
    visited[u] = 1;
    
    // 4. 遍历顶点u的所有出边（单链表遍历）
    ArcNode *p = G.vertices[u].firstarc;
    while (p != NULL) {
        int w = p->adjvex; // 取出邻接点下标
        if (visited[w] == 0) {
            // 派邻接点w去走剩下的 k-1 步，若找到则直接短路返回 1
            if (DFS_PathK(G, w, v, k - 1, visited) == 1) {
                return 1;
            }
        }
        p = p->nextarc;
    }
    
    // 5. 【核心回溯】当前分支走不通，退栈前擦除脚印，允许其他分支经过u
    visited[u] = 0;
    return 0;
}

// 主接口函数
int ExistPathLenK(ALGraph G, int u, int v, int k) {
    // 合法性防御检查
    if (u < 0 || u >= G.vexnum || v < 0 || v >= G.vexnum || k <= 0) {
        return 0;
    }
    int visited[MAXV] = {0}; // 初始化访问标记数组全为0
    return DFS_PathK(G, u, v, k, visited);
}
```

#### 3. 复杂度分析
* **时间复杂度：** 最坏情况下为 $O(V!)$（或写指数级 $O(d^k)$，其中 $d$ 为最大出度）。因为需要枚举所有长度不超过 $k$ 的简单路径，同一个顶点可能在不同路径分支中被重复访问和回溯。
* **空间复杂度：** $O(V)$（或 $O(k)$），其中 $V$ 为顶点数。主要开销为 `visited` 数组的 $O(V)$ 空间以及深度不超过 $k$ 的递归调用栈空间。

### 第二题：判断给定的顶点序列是否为“合法的拓扑序列”

#### 1. 算法基本思想
利用**拓扑排序的入度定义**进行模拟验证。
1. 首先创建一个入度数组 `indegree[]` 并初始化为 0，遍历邻接表 $G$ 的所有边链表，统计每个顶点的初始入度。
2. 按给定序列 `seq[]` 的顺序，依次取出顶点 `u = seq[i]`（$0 \le i < \text{vexnum}$）：
   * 检查当前顶点 `u` 的入度 `indegree[u]` 是否为 0。若不为 0（说明 `u` 还有前驱顶点未出现在它前面），则该序列非法，直接返回 0。
   * 若 `indegree[u] == 0`，则模拟将该顶点从图中删除：遍历顶点 `u` 的边链表，将其所有邻接点的入度减 1。
3. 若序列中所有顶点均顺利通过检查，说明是合法拓扑序列，返回 1。（注：为防止传入序列包含重复顶点或越界下标，可配合 `visited[]` 数组做严谨性校验）。




#### 2. 完整算法代码
```cpp
// 判断长度为 G.vexnum 的顶点下标序列 seq[] 是否为合法拓扑序列
int IsTopologicalSeq(ALGraph G, int seq[]) {
    int indegree[MAXV] = {0}; // 记录各顶点的入度
    int visited[MAXV] = {0};  // 防止 seq[] 中出现重复顶点（满分防坑细节！）
    
    // 1. 遍历整个邻接表，统计所有顶点的初始入度
    for (int i = 0; i < G.vexnum; i++) {
        ArcNode *p = G.vertices[i].firstarc;
        while (p != NULL) {
            indegree[p->adjvex]++; // p->adjvex 是弧头，其入度加 1
            p = p->nextarc;
        }
    }
    
    // 2. 依次验证序列 seq[] 中的每一个顶点
    for (int i = 0; i < G.vexnum; i++) {
        int u = seq[i]; // 当前取出的顶点下标
        
        // 防御检查：下标越界、重复出现、或者【核心条件：当前入度不为 0】
        if (u < 0 || u >= G.vexnum || visited[u] == 1 || indegree[u] != 0) {
            return 0; // 违反拓扑序列定义，直接返回 0
        }
        
        visited[u] = 1; // 标记顶点 u 已输出
        
        // 3. 抹去顶点 u 发出的所有边，将其邻接点的入度减 1
        ArcNode *p = G.vertices[u].firstarc;
        while (p != NULL) {
            int w = p->adjvex;
            indegree[w]--;
            p = p->nextarc;
        }
    }
    
    // 4. 所有顶点均合法输出，返回 1
    return 1;
}
```

#### 3. 复杂度分析
* **时间复杂度：** $O(V + E)$，其中 $V$ 为顶点数，$E$ 为边数。统计初始入度需遍历所有顶点和边，耗时 $O(V + E)$；验证序列时每个顶点及其出边也至多被扫描一次，耗时 $O(V + E)$。达到理论最优解。
* **空间复杂度：** $O(V)$，主要开销为辅助数组 `indegree` 和 `visited` 所占用的空间。

### 第三题：判断给定的顶点序列是否为图的一条“哈密顿回路”

#### 1. 算法基本思想
根据**哈密顿回路（Hamiltonian Cycle）的定义**，一条包含 $n+1$ 个顶点的序列 `path[0...n]`（其中 $n = \text{G.vexnum}$）构成哈密顿回路，当且仅当同时满足以下三个条件：
1. **首尾相接且长度合法：** 图中顶点数 $n \ge 1$，且起点与终点相同，即 `path[0] == path[n]`。
2. **顶点不重不漏（简单性与遍历性）：** 序列的前 $n$ 个顶点 `path[0...n-1]` 必须恰好包含图中的所有 $n$ 个顶点且互不重复（使用 `visited[]` 数组查重）。
3. **相邻顶点间有边（路径连通性）：** 对于序列中的每一步转移 `path[i]` $\rightarrow$ `path[i+1]`（$0 \le i < n$），在邻接表中顶点 `path[i]` 的单链表里，必须存在指向 `path[i+1]` 的边结点。若任意一步无边相连，则返回 0。

#### 2. 完整算法代码
```cpp
// 判断长度为 n+1 (n = G.vexnum) 的序列 path[] 是否为图G的哈密顿回路
int IsHamiltonianCycle(ALGraph G, int path[], int len) {
    int n = G.vexnum;
    
    // 1. 基础条件检查：序列长度必须为 n+1，且首尾顶点必须相同
    if (n <= 0 || len != n + 1 || path[0] != path[n]) {
        return 0;
    }
    
    int visited[MAXV] = {0}; // 记录前 n 个顶点是否重复出现
    
    // 2. 逐步检查 path[0] 到 path[n-1] 的每一个顶点及每一步边
    for (int i = 0; i < n; i++) {
        int u = path[i];     // 当前步的起点
        int v = path[i + 1]; // 当前步的终点（下一步要去的点）
        
        // 2.1 检查顶点下标是否合法，以及顶点 u 是否在前面已经出现过
        if (u < 0 || u >= n || v < 0 || v >= n || visited[u] == 1) {
            return 0; // 若越界或出现重复顶点，则不是哈密顿回路
        }
        visited[u] = 1; // 标记顶点 u 已访问
        
        // 2.2 在顶点 u 的邻接表（单链表）中查找是否存在指向 v 的边 <u, v>
        int hasEdge = 0; // 标志位：记录 <u, v> 是否存在
        ArcNode *p = G.vertices[u].firstarc;
        while (p != NULL) {
            if (p->adjvex == v) {
                hasEdge = 1; // 找到了从 u 指向 v 的边！
                break;       // 跳出单链表循环
            }
            p = p->nextarc;
        }
        
        // 若遍历完 u 的单链表都没找到指向 v 的边，说明路径断开，返回 0
        if (hasEdge == 0) {
            return 0;
        }
    }
    
    // 3. 闯过所有关卡（首尾相接、n个点互不重复、每一步均有边），返回 1
    return 1;
}
```

#### 3. 复杂度分析
* **时间复杂度：** $O(V + E)$，其中 $V$ 为顶点数，$E$ 为边数。外层循环执行 $V$ 次，由于前 $V$ 个顶点 `u = path[i]` 互不相同（若相同会提前终止返回 0），因此内层 `while` 循环对每个顶点的单链表至多完整扫描一次，所有单链表扫描的总次数不超过图的总边数 $E$。
* **空间复杂度：** $O(V)$，主要开销为用于顶点查重的辅助数组 `visited` 所占用的空间。

3. **复杂度降维打击：** 第三题看起来是个双重循环（`for` 套 `while`），很多考生会误写成 $O(V^2)$ 或 $O(V \cdot E)$。但在算法分析里写出 **“因为 `u` 互不重复，每条边至多访问一次，所以总时间复杂度为 $O(V + E)$”**，阅卷老师看到直接给你打满分！
