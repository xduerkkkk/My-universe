### 几个词先翻译成人话

| 原来的说法 | 现在先这样理解 |
| --- | --- |
| 状态 | 为了继续往下做，我手里需要记住什么 |
| 不变量 | 每轮做完后，仍然保证正确的一件事 |
| 前缀 | 数组最左边的一段，如 `A[0]` 到 `A[2]` |
| 稳定 | 保留下来的元素之间，原来的先后顺序不变 |
| 原地 | 主要在原数组或原结点上修改，不另造一整份结果 |
| 汇总／摘要 | 不记住过去的每个细节，只留下后面够用的信息 |
| 单调 | 向某个方向操作时，一个量不会忽大忽小地反复改变方向 |
| 松弛 | 发现更便宜的走法，就把当前记录的费用改小 |

## A 数组：先把循环看成逐个处理小格子

### A1 基础例题：删掉数组里的0

**小题目**：把 `[2,0,5,0,3]` 里的0删掉，其他数保持先后顺序。不新建另一个数组，返回新长度。

**先手算**：答案是长度3，有效内容 `[2,5,3]`。不是把0换成别的数，而是把要留下来的数挤到左边。

**先不想指针，只想两件事**：一根手指逐格检查原数组；另一根手指指着“下一个保留数该放的位置”。

| 刚读到的数 | 做什么 | 左边已经放好的有效结果 | 下一写位置w |
| --- | --- | --- | --- |
| 2 | 留下，写到0号格 | `[2]` | 1 |
| 0 | 跳过 | `[2]` | 1 |
| 5 | 留下，写到1号格 | `[2,5]` | 2 |
| 0 | 跳过 | `[2,5]` | 2 |
| 3 | 留下，写到2号格 | `[2,5,3]` | 3 |

```cpp
int RemoveZeros(int A[], int n) {
    int w = 0;                     // 下一个保留数的放置位置
    for (int r = 0; r < n; r++) {   // r负责把原数组读一遍
        if (A[r] != 0) {
            A[w] = A[r];            // 只把要留下来的数写过去
            w++;
        }
    }
    return w;                      // 写入了几个，就是新长度
}
```

**为什么不会覆盖还没读到的数？** 写入位置w总在读取位置r的左边或与它重合。被跳过的0只会让w落后，不会让w跑到r前面。

**最容易误会**：函数结束后物理数组可能是 `[2,5,3,0,3]`，没有关系。返回3已经声明“只看前三格”；不必把后两格清零。全是0或空数组时返回0。

**翻译回原模板**：“读写前缀”就是**一边读原数据，一边把结果放到最左侧的一段**。后面删除区间、有序去重，只是在改变“什么值得留下”。时间O(n)，额外空间O(1)。

**看懂后再回去**：[[03算法题模板#A1 读写前缀|A1 原模板与正式练习]]。

### A2 基础例题：把两小队有序的数排成一队&多出的尾巴怎么拼

**小题目**：A是 `[1,4]`，B是 `[2,3]`，各自已经升序。把它们合成 `[1,2,3,4]`，写进容量至少为 `n+m` 的独立数组out，返回写入长度。

**笨办法**：全部混在一起再排序。**这里不用重排**：两队都已排好，每次只比较两队最前面的数，取较小的。

**手算**：比1和2，取1；比4和2，取2；比4和3，取3；B空了，把A剩下的4接上。

```cpp
int MergeSorted(const int A[], int n, const int B[], int m, int out[]) {
    int i = 0, j = 0, k = 0;        // A队首、B队首、结果下一格
    while (i < n && j < m) {
        if (A[i] <= B[j]) {
            out[k++] = A[i++];
        } else {
            out[k++] = B[j++];
        }
    }
    while (i < n) out[k++] = A[i++]; // 可能只剩A还有人
    while (j < m) out[k++] = B[j++]; // 也可能只剩B还有人
    return k;
}
```

**关键语句拆开看**：`out[k++] = A[i++]` 在这里等价于先做 `out[k] = A[i]`，再分别让k、i加1；不是神秘语法。

**为什么只看队首就够？** 每队后面的数不会比自己的队首小。两个队首里较小的那个，也是所有剩余数里最小的。

**最容易误会**：不是两个游标每轮都动，而是**取了谁，谁前进**。任一队用完，另一队的剩余部分仍要复制。重复数也保留。

**翻译回原模板**：“有序同步推进”就是**利用原有顺序，每次只推进已确定可以处理的那一侧**。交集题同样比较队首，但相等时的动作不同。时间O(n+m)，工作空间O(1)，输出数组另占O(n+m)。

**看懂后再回去**：[[03算法题模板#A2 有序同步推进|A2 原模板与正式练习]]。

### A3 基础例题：数一数每个数字出现几次

**小题目**：输入只含0到4的整数，例如 `[3,1,3,0]`。统计0、1、2、3、4各出现几次，写入长度至少5的freq。

**先手算**：0出现1次，1出现1次，2没有，3出现2次，4没有，所以freq是 `[1,1,0,2,0]`。

**做法**：放五个贴有0到4标签的小盒子。读到3，就给“3号盒子”加1；不是给原数组的第3个位置加1。

```cpp
void CountDigits(const int A[], int n, int freq[]) {
    for (int v = 0; v <= 4; v++) freq[v] = 0;
    for (int i = 0; i < n; i++) {
        int x = A[i];               // x是数值，不是原位置
        freq[x]++;
    }
}
```

**手推变化**：读3后，`freq[3]=1`；读1后，`freq[1]=1`；再读3，`freq[3]=2`；读0，`freq[0]=1`。

**为什么要先清零？** 次数要从0开始累计，不能把内存里的旧内容当次数。`freq[3]` 的含义始终是“数字3出现的次数”，而不是“第三个元素”。

**最容易误会**：本例能直接这样写，是题目保证了 `0 <= x <= 4`。如果x是负数或十亿，就不能照搬五格数组。

**翻译回原模板**：“按值标记计数”就是**拿数值当盒子编号，记录这个值来过没有、来了几次**。只想知道有没有时，可用 `seen[x]=1`。本例时间O(n+5)，额外存储是5个计数槽。

**看懂后再回去**：[[03算法题模板#A3 按值标记计数|A3 原模板与正式练习]]。

### A4 基础例题：找第一个不小于3的位置

**小题目**：升序数组 `[1,3,3,5]`，找第一个 `>= x` 的位置，x=3时返回1；一个都没有时返回n。

**先手算**：把每一格是否满足条件写出来：`否、是、是、是`。我们要找“否变成是”的分界，不是随便找到一个3。

**做法**：用 `[low,high)` 表示还没排除的区间，左端算在内，右端不算。开始是 `[0,4)`。

```cpp
int FirstGE(const int A[], int n, int x) {
    int low = 0, high = n;          // high是右边界，不是最后下标
    while (low < high) {
        int mid = low + (high - low) / 2;
        if (A[mid] >= x) {
            high = mid;            // mid可能是第一个，不能丢掉
        } else {
            low = mid + 1;         // mid及其左侧都太小，排除
        }
    }
    return low;                    // 也可能等于n，表示不存在
}
```

**手推**：`[0,4)` 看2号格3，缩到 `[0,2)`；看1号格3，缩到 `[0,1)`；看0号格1，缩到 `[1,1)`，停，返回1。

**为什么能扔掉半边？** 数组有序。如果中间都小于x，左边更不可能满足；如果中间已满足，第一个满足者只可能在它左边或就是它。

**最容易误会**：`high=n` 不是访问 `A[n]`；循环不会取到那个位置。不要与原速查卡的闭区间版本混写：本例是另一套完整自洽的边界约定。空数组返回0，即n。

**翻译回原模板**：“二分边界”就是**反复缩小分界可能存在的位置**。不是见到“查找”就能用，先要有这里的有序／真假分界。时间O(log(n+1))，额外空间O(1)。

**看懂后再回去**：[[03算法题模板#A4 二分边界|A4 原模板与正式练习]]。

### A5 基础例题：随时报告“到目前为止的最大值”

**小题目**：从左向右读 `[3,1,4,2]`，每读一个数，就输出“从开头到当前的最大值”。答案 `[3,3,4,4]`。

**笨办法**：读到第3个数时，把前三个数重新比较一遍。**其实只要记住此前冠军**：新来的挑战它，赢了才换人。

```cpp
void PrefixMax(const int A[], int n, int out[]) {
    if (n == 0) return;             // 空数组没有第一个元素
    int best = A[0];
    for (int i = 0; i < n; i++) {
        if (A[i] > best) best = A[i];
        out[i] = best;             // 此时已经把当前元素算进去了
    }
}
```

**手推**：初始冠军3；读3，还是3；读1，不变；读4，换成4；读2，不变。

**为什么一个变量就够？** 新数能否成为冠军，只取决于旧冠军，不需要知道旧冠军之前击败过谁。这就是“扫描时保留摘要”。

**最容易误会**：本例要求“包含当前元素”，所以先更新再输出。如果题目要求 `i左边` 的最大值，就要先使用旧best，再将当前值纳入；顺序不能不加区分地照抄。不要把best随手初始化成0，否则全负数会错。

**翻译回原模板**：“扫描汇总与历史最优”就是**走过的部分不用每次重看，留下后面真正需要的一点信息**。信息也可能是累计和、最小值或连续段起点，不一定是最大值。时间O(n)，工作空间O(1)，out另占O(n)。

**看懂后再回去**：[[03算法题模板#A5 扫描汇总与历史最优|A5 原模板与正式练习]]。

### A6 基础例题：只把小数移到左边，不排序

**小题目**：把 `[4,1,3,2]` 按x=3分成两段：左边都 `<3`，右边都 `>=3`。两段内部不要求排序，也不要求保持原顺序。返回左段长度。

**先手算**：`[1,2,3,4]` 可以，`[2,1,4,3]` 也可以。我们只要分组，不需要得到唯一的有序答案。

```cpp
int PartitionLess(int A[], int n, int x) {
    int k = 0;                     // 左边已收集了k个小于x的数
    for (int i = 0; i < n; i++) {
        if (A[i] < x) {
            int temp = A[k];       // 与左段后面的第一个位置交换
            A[k] = A[i];
            A[i] = temp;
            k++;
        }
    }
    return k;
}
```

**手推**：读4，不动；读1，交换得 `[1,4,3,2]`，k=1；读3，不动；读2，交换得 `[1,2,3,4]`，k=2。

**为什么与A1不一样？** A1可以不要被删除的值，直接覆盖；这里**所有值都要保留**，所以要交换。最终前k格小于x，其余格大于等于x。

**最容易误会**：本例碰巧得到升序，不代表算法在排序。`[4,2,5,1]` 会得到 `[2,1,5,4]`；它满足分组要求，但既没全局有序，也没保住右组原顺序。

**翻译回原模板**：“划分而非全排序”就是**只做到题目要求的分界，不多做内部排序**。第k小还要进一步缩小目标区间，本例先学会最基本的一次分组。时间O(n)，额外空间O(1)。

**看懂后再回去**：[[03算法题模板#A6 划分而非全排序|A6 原模板与正式练习]]。

### A7 基础例题：和不超过4的最长连续一段

**小题目**：数组非负，`[1,2,1,3]`，K=4。找总和不超过K的最长连续段，返回长度；没有非空合法段时返回0。K保证非负。

**先手算**：`[1,2,1]` 的和为4，长度3；四个全取时和为7，超了。答案3。不能跳过中间元素拼一段。

**做法**：像拉动一扇窗。右边每次多包进一个数；太重了，就从左边逐个移出去。

```cpp
int LongestAtMost(const int A[], int n, long long K) {
    int left = 0, best = 0;
    long long sum = 0;
    for (int right = 0; right < n; right++) {
        sum += A[right];           // 把右边这个数包进来
        while (sum > K) {          // 不是只移一次，直到合法
            sum -= A[left];
            left++;
        }
        int length = right - left + 1;
        if (length > best) best = length;
    }
    return best;
}
```

| 新加入的数 | 超标前的和 | 从左边移出什么 | 剩余窗口 | 目前最长 |
| --- | --- | --- | --- | --- |
| 1 | 1 | 不移 | `[1]` | 1 |
| 2 | 3 | 不移 | `[1,2]` | 2 |
| 1 | 4 | 不移 | `[1,2,1]` | 3 |
| 3 | 7 | 先移1仍为6，再移2变4 | `[1,3]` | 3 |

**为什么左边不用退回去？** 所有数非负，向右扩展不会使和变小。一旦某个左端点导致超标，以后再加入非负数也不会重新合法；因此可以永久排除它。

**最容易误会**：任意负数会破坏这个理由。例如 `[5,-4]`、K=1，算法会过早扔掉5而漏掉长度2。原正式练习“最短达标段”是另一种收缩目标，不能直接照搬本例的答案更新位置。

**翻译回原模板**：“条件单调的窗口”就是**用连续的左右边界维护一段，并有充分理由让边界只往前走**。两层循环不等于O(n²)：每个数至多进窗、出窗各一次，总时间O(n)，额外空间O(1)。

**看懂后再回去**：[[03算法题模板#A7 条件单调的窗口|A7 原模板与正式练习]]。

## L 链表：先画出修改前后的箭头

本组用带头结点的单链表。`头 → 1 → 2 → NULL` 里，“头”不是数据1，而是额外的入口结点L。先把这张图画出来，再看 `next` 的赋值。移动局部游标p不会自动移动入口L。

### L1 基础例题：把三个结点反过来

**小题目**：`头 → 1 → 2 → 3 → NULL`，不交换data，只改箭头，变成 `头 → 3 → 2 → 1 → NULL`。

**先想危险在哪里**：如果直接把1的next改成NULL，却没记住2在哪里，后面的2、3就找不到了。因此每次都要**先记住原后继，再反转当前箭头**。

```cpp
void ReverseList(LinkList L) {
    LNode *pre = NULL;              // 已反转部分的第一个结点
    LNode *p = L->next;             // 接下来要处理的结点
    while (p != NULL) {
        LNode *next = p->next;      // 先记住未处理部分的入口
        p->next = pre;             // 当前结点转而指向前面
        pre = p;                   // 更新已反转部分的入口
        p = next;                  // 去原来的下一个结点
    }
    L->next = pre;                 // 头结点接上新的第一个数据结点
}
```

| 处理完谁 | 已反转部分pre | 还没处理的p |
| --- | --- | --- |
| 尚未处理 | NULL | `1 → 2 → 3` |
| 1 | `1 → NULL` | `2 → 3` |
| 2 | `2 → 1 → NULL` | `3` |
| 3 | `3 → 2 → 1 → NULL` | NULL |

**为什么最后还要改L->next？** pre只是函数里的局部变量；它知道新开头是3，但头结点原来还指向1。必须显式把入口接过去。

**最容易误会**：这里的变量名next不等于 `p->next` 永远不变；next保存的是**修改前**的地址。空表也能处理，最终仍为空表。

**翻译回原模板**：“保存后继再改边”就是**动箭头前先留好回到未处理部分的路**。这是后续链表回文、重排中的逆置积木。时间O(n)，额外空间O(1)。

**看懂后再回去**：[[03算法题模板#L1 保存后继再改边|L1 原模板与正式练习]]。

### L2 基础例题：把结点逐个搬到另一条链的尾巴

**小题目**：L是 `头L → 1 → 2 → 3`，R是只有头结点的空表。逐个把L的数据结点搬到R，最终L空，R是 `头R → 1 → 2 → 3`。不新建数据结点。

**为什么故意做这么简单？** 先只学会“摘一个结点，放到尾巴”。稳定分组只是后来多准备几个接收队伍，并决定往哪队放。

```cpp
void MoveToTail(LinkList L, LinkList R) {
    // 前提：L、R是不同头结点，R为空，两表不共享结点。
    LNode *p = L->next;
    L->next = NULL;                // 原入口置空，剩余部分由p接管
    LNode *tail = R;               // R为空时，尾巴就是头结点
    while (p != NULL) {
        LNode *next = p->next;     // 暂存剩余链
        p->next = NULL;            // 把当前结点摘成一个单独的结点
        tail->next = p;            // 旧尾巴接住它
        tail = p;                 // 它成为新尾巴
        p = next;
    }
}
```

**手推**：起初tail是头R；搬1，R变 `头R → 1`，tail指1；搬2，R变 `头R → 1 → 2`，tail指2；再搬3，顺序不变。

**为什么叫尾插？** 新来的永远排在已经到达的人后面，所以原来1、2、3的次序不会反过来。若每次插在头结点之后，就会变成3、2、1。

**最容易误会**：`tail->next = p` 是接线，`tail = p` 是移动“尾巴标记”；两句都需要。本例不能把带数据的R当作空表来用，也不是复制出另一份共享结点的链。

**翻译回原模板**：“摘点分流与尾插”就是**摘下原结点，根据条件选队伍，再接到那队的最后**。本例只有一个队伍，先把“摘”和“接”看清。时间O(n)，额外空间O(1)。

**看懂后再回去**：[[03算法题模板#L2 摘点分流与尾插|L2 原模板与正式练习]]。

### L3 基础例题：删除链表里所有的0

**小题目**：`头 → 0 → 0 → 2 → 0`，删除并释放所有数据为0的结点，剩下 `头 → 2`。结点由new创建，归这条链独占。

**先画一次删除**：`pre → p → 后面`，要变成 `pre → 后面`。单链表没有后退按钮，所以必须事先保留p前面的pre。

```cpp
void DeleteZeros(LinkList L) {
    LNode *pre = L;
    LNode *p = L->next;
    while (p != NULL) {
        if (p->data == 0) {
            pre->next = p->next;   // 前驱绕过待删结点
            delete p;             // 这以后不准再读旧p的内容
            p = pre->next;        // 从安全的前驱重新取得待处理点
        } else {
            pre = p;              // 留下当前结点，它成为新前驱
            p = p->next;
        }
    }
}
```

**手推连续两个0**：删第一个0时，pre仍是头；第二个0现在也紧跟在头后，所以继续由同一个pre删除。见到2才让pre前进到2。

**为什么删除分支不能让pre前进？** 被删结点不是保留结果的一部分；前驱必须留在最后一个保留结点上，否则会跳过连续的待删结点。

**最容易误会**：`delete p` 后再写 `p = p->next` 是访问已释放内存。本例删除标准固定是“等于0”；正式题若用**原链平均值**作标准，得先完整统计一次，再删除，不能边删边改平均值。

**翻译回原模板**：“前驱删除与原始统计”先拆成两件事：**前驱负责安全绕过结点；若标准来自原表，先把标准算好再动表**。本例只练第一件。时间O(n)，额外空间O(1)。

**看懂后再回去**：[[03算法题模板#L3 前驱删除与原始统计|L3 原模板与正式练习]]。

### L4 基础例题：只找中间结点，先不重排

**小题目**：`头 → 1 → 2 → 3 → 4 → 5`，返回指向3的指针。偶数长度时约定返回后一个中点，如 `[1,2,3,4]` 返回3；空表返回NULL。

**做法**：两个人从首数据结点一起出发，slow每次走一步，fast每次走两步。快的人走到尽头，慢的人大致走了一半。

```cpp
LNode *MiddleNode(LinkList L) {
    LNode *slow = L->next;
    LNode *fast = L->next;
    while (fast != NULL && fast->next != NULL) {
        slow = slow->next;
        fast = fast->next->next;
    }
    return slow;
}
```

**手推五个结点**：`slow=1, fast=1`；一次后是2和3；再一次后是3和5；5没有后继，停，返回3。

**为什么循环条件检查两件事？** fast自己要存在，而且它的后继也要存在，才能安全读取 `fast->next->next`。C++的 `&&` 先检查左侧，不满足时不会再读右侧。

**最容易误会**：这段程序**只定位，没有改任何箭头**。它也没有自动完成回文判断或首尾重排。那些题还需要明确分哪两段、哪里断开、如何接回；偶数时选哪个中点也要与后续操作一致。

**翻译回原模板**：“先定位再组合”就是**先找到要操作的位置，之后再拼接已经会的小动作**。快慢指针只是定位工具，不是一整套复杂链表解法。时间O(n)，额外空间O(1)。

**看懂后再回去**：[[03算法题模板#L4 先定位再组合|L4 原模板与正式练习]]。

## T 树：每次函数调用只管自己这棵小树

本组使用普通二叉树BTNode，不是孩子兄弟表示法。先记住：一个结点的左孩子、右孩子本身也可以看成两棵更小的树。递归函数要说清“这一趟调用负责什么”。

### T1 基础例题：数出一棵树有几个结点

**小题目**：根1的左右孩子分别为2、3，2和3没有孩子。返回结点总数3。空树返回0。

```text
    1
   / \
  2   3
```

**不用先想遍历名称**：整棵树的结点数 = 左边那棵的结点数 + 右边那棵的结点数 + 根自己1个。

```cpp
int CountNodes(BTNode *p) {
    if (p == NULL) return 0;       // 没有结点，就贡献0
    int left = CountNodes(p->lchild);
    int right = CountNodes(p->rchild);
    return left + right + 1;       // 两个孩子的结果到齐，再算自己
}
```

**手推返回过程**：2的左右都是空，返回 `0+0+1=1`；3也返回1；回到1时，它拿到left=1、right=1，于是返回3。

**为什么要等孩子返回？** 当前结点只知道左右孩子在哪里，不直接知道左右各有多少结点。让子调用负责自己的小树，再把答案交回来。

**最容易误会**：`left` 不是左孩子的data，而是“以左孩子为根的整棵子树结点数”。每一层调用都有自己的一份left、right，不会全部挤在同一对变量里。

**翻译回原模板**：“后序向上汇总”就是**小树先交结果，大树再合起来；信息从孩子往父亲走**。求高度时，把组合公式换成 `max(左高,右高)+1`，但仍要重新说明返回值。时间O(n)，递归栈O(h)，h是树高。

**看懂后再回去**：[[03算法题模板#T1 后序向上汇总|T1 原模板与正式练习]]。

### T2 基础例题：打印每条根到叶子的数字和

**小题目**：还是根1、左右叶子2和3。打印两条根叶路径的和：`1+2=3`、`1+3=4`。不要求保存路径本身，也不查找指定目标。

**与T1的区别**：到2时，2还需要知道“从根走到它之前已经累加了多少”。这份信息来自上面，不是来自孩子。

```cpp
void PrintLeafSums(BTNode *p, long long sum) {
    if (p == NULL) return;
    sum += p->data;                // 把当前结点加入当前路径
    if (p->lchild == NULL && p->rchild == NULL) {
        printf("%lld ", sum);      // 到叶子，这条根叶路径才完成
        return;
    }
    PrintLeafSums(p->lchild, sum);
    PrintLeafSums(p->rchild, sum);
}
// 入口调用：PrintLeafSums(root, 0);
```

**手推**：到1，sum变1；去2时，子调用拿到一份1，变成3并输出；回到1，再去3时，拿到的仍是1，不是3，输出4。

**为什么不用在返回前减回去？** 参数 `long long sum` 是**按值传递**。子调用拿到副本，子调用里的加法不会改父调用的sum。

**最容易误会**：如果以后用同一份共享数组记录路径，并用 `int &length` 共享长度，那么进入时长度加1，退出这条分支时就要减1。**共享记录要撤销；本例的按值参数不用撤销**，不能不分情况背“递归后减回来”。空树不输出任何路径。

**翻译回原模板**：“祖先状态与路径回退”就是**把上一路的信息带给下一层；若多条分支共用同一本记录本，离开时要擦掉本分支的记录**。本例先理解“往下传”，再学共享路径。时间O(n)，递归栈O(h)。

**看懂后再回去**：[[03算法题模板#T2 祖先状态与路径回退|T2 原模板与正式练习]]。

### T3 基础例题：只删除原来就是叶子的结点

**小题目**：删除原树的所有叶子，只删一轮。`1 →左孩子2 →左孩子3` 中原叶子只有3，所以删除后留下1和2；不能继续把新变成叶子的2也删掉。树结点由new创建且独占。

**先想入口会不会变**：若整棵树只有一个结点，它也是叶子，删除后新根应该是NULL。函数必须能把“新入口”交给调用者。

```cpp
BTNode *RemoveOriginalLeaves(BTNode *p) {
    if (p == NULL) return NULL;
    // 先判断，保证这里认的是原来的叶子。
    if (p->lchild == NULL && p->rchild == NULL) {
        delete p;
        return NULL;              // 这棵小树的新入口是空
    }
    p->lchild = RemoveOriginalLeaves(p->lchild);
    p->rchild = RemoveOriginalLeaves(p->rchild);
    return p;                     // 当前根没删除，入口仍是它
}
// 入口调用必须接住返回值：root = RemoveOriginalLeaves(root);
```

**手推三结点链**：1不是原叶子，递归去2；2不是原叶子，递归去3；3删除并返回NULL，2把自己的左孩子改成NULL，然后直接返回2；1再接住2。

**为什么写 `p->lchild = ...`？** 子函数只说“处理后，这棵小树的新根是它”；父结点必须真的修改指向这棵小树的箭头。只调用函数却不接返回值，可能留下指向已删除结点的地址。

**最容易误会**：把叶子判断挪到递归后，会把刚变成叶子的祖先也继续删除，变成另一道题。单结点树删除后，外层root也必须更新为NULL。

**翻译回原模板**：“返回并接回新根”就是**改完一棵小树，把它现在的入口交回来，上一级接好**。不是只有整棵树的根需要接，左右子树也需要。时间O(n)，递归栈O(h)。

**看懂后再回去**：[[03算法题模板#T3 返回并接回新根|T3 原模板与正式练习]]。

### T4 基础例题：在BST里查找3

**小题目**：严格二叉搜索树BST如下，找到值为x的结点并返回地址；不存在返回NULL。

```text
      4
     / \
    2   6
   / \
  1   3
```

**这里额外给了什么？** 每个结点的左子树都比它小，右子树都比它大。所以找3时，在4处不必看右子树6。

```cpp
BTNode *FindBST(BTNode *p, int x) {
    while (p != NULL) {
        if (x == p->data) return p;
        if (x < p->data) {
            p = p->lchild;         // 太小的目标只能去左边找
        } else {
            p = p->rchild;
        }
    }
    return NULL;
}
```

**手推x=3**：比4小，去2；比2大，去3；相等，返回这个结点。x=5时，路径是4→6→空，返回NULL。

**为什么能只走一条路？** BST的大小约束排除了另一整棵子树，不是因为普通二叉树天生就能二分。普通树里3完全可能藏在任意一侧。

**最容易误会**：BST不一定平衡；如果长成一条链，仍可能逐个查看n个结点。本例没有递归，额外空间O(1)，时间O(h)。

**翻译回原模板**：“BST有序性”就是**把左小右大当作省略检查的理由**。还有另一种用法：按左→根→右读整个BST，会读出升序序列，之后可比较相邻数。正式边界查找还要保存候选，本例先学会最简单的单路查找。

**看懂后再回去**：[[03算法题模板#T4 BST有序性|T4 原模板与正式练习]]。

### T5 基础例题：一层一行打印树

**小题目**：根1的孩子是2、3，2的左孩子是4，其余为空。打印三行：第一行1，第二行2 3，第三行4。总节点数不超过MAXSIZE。

**做法**：用队列，先到的人先处理。根先入队，处理某个结点时，把它的孩子排到队尾。为了知道哪里换行，要先记住本层的队尾位置。

```cpp
void PrintLevels(BTNode *root) {
    if (root == NULL) return;
    BTNode *q[MAXSIZE];
    int front = 0, rear = 0;       // 下一出队位置、下一入队位置
    q[rear++] = root;
    while (front < rear) {
        int end = rear;            // 固定下来：本层到这里为止
        while (front < end) {
            BTNode *p = q[front++];
            printf("%d ", p->data);
            if (p->lchild != NULL) q[rear++] = p->lchild;
            if (p->rchild != NULL) q[rear++] = p->rchild;
        }
        printf("\n");            // 本层处理完才换行
    }
}
```

**手推队列**：先 `[1]`，固定end=1；处理1后队列后面多了2、3，但本层到1就结束。下一层固定end=3，处理2、3；新加入的4留到再下一层。

**为什么不能把内层条件写成 `front < rear`？** rear会随着孩子入队不断增大，当前层就会连着下一层一起处理，丢掉换行边界。end是“本轮开始时的rear快照”。

**最容易误会**：本例只学层序，没有检查完全二叉树。以后判完全性时，还要记住“按层从左往右已经出现过空位”，这个记号不能换个父结点就清除。

**翻译回原模板**：“层序与跨层空位”里的“层序”就是**先处理完近的一层，再处理远的一层**；“跨层空位”是完全性题再增加的规则。时间O(n)，本例固定队列占O(MAXSIZE)空间；按容量随n增长的通常分析记O(n)。

**看懂后再回去**：[[03算法题模板#T5 层序与跨层空位|T5 原模板与正式练习]]。

### T6 基础例题：判断两棵小树完全相同

**小题目**：A和B都由根1、左孩子2组成，返回true；若B把2放在右边，虽然数字一样，也返回false。

**先不要想整棵树**：每次只比较一对位置对应的结点：是不是都空？是不是只空一个？值是否相等？再把同侧孩子交给子调用。

```cpp
bool SameTree(BTNode *a, BTNode *b) {
    if (a == NULL && b == NULL) return true;
    if (a == NULL || b == NULL) return false;
    if (a->data != b->data) return false;
    return SameTree(a->lchild, b->lchild)
        && SameTree(a->rchild, b->rchild);
}
```

**手推相同情况**：根1和根1相等；左边2和2相等，它们的空孩子也一一对应；右边都空，成立。

**手推位置不同**：比较左边时，A的2对上B的NULL，“只空一个”立即失败。不能只分别遍历出数值集合再比较。

**为什么先判断空，再读data？** NULL没有可读取的结点内容。两空代表这个位置形状吻合；只有一个空代表结构不符。

**翻译回原模板**：“双树同步”就是**两棵树一起往下走，每次明确比较的是哪一对位置**。相同树同向配对；镜像题才改成交叉配对，即左对右、右对左。两树各n个结点时最坏时间O(n)，递归栈O(h)。

**看懂后再回去**：[[03算法题模板#T6 双树同步|T6 原模板与正式练习]]。

## G 图：先把“有哪些边”和“要记什么”分开

为了先看清动作，本页G1、G2、G3用最直观的0/1邻接矩阵：顶点编号 `0..n-1`，`G[u][v]=1` 表示有边从u到v。无向边要把两个方向都置1。n不超过MAXSIZE。正式练习有的用邻接表；改的是“怎样枚举邻点”，不是算法的核心职责。

### G1 基础例题：从0出发，能摸到几个点

**小题目**：无向图有4个点，边只有0—1、1—2，3孤立。从0出发，沿边走，能到几个点？答案3，包括起点自己。

```text
0 — 1 — 2       3
```

**做法**：到一个新点就贴“来过”的标签，然后继续去没来过的邻居。贴过标签就不再重复进入，否则无向边会让你从0到1再回0，无休止绕圈。

```cpp
int DFSCount(const int G[][MAXSIZE], int n, int v, bool visited[]) {
    visited[v] = true;             // 进入时立刻贴标签
    int count = 1;                // 当前点自己算一个
    for (int w = 0; w < n; w++) {
        if (G[v][w] != 0 && !visited[w]) {
            count += DFSCount(G, n, w, visited);
        }
    }
    return count;
}

int ReachCount(const int G[][MAXSIZE], int n, int start) {
    // 前提：1 <= n <= MAXSIZE，start是合法编号。
    bool visited[MAXSIZE] = {false};
    return DFSCount(G, n, start, visited);
}
```

**手推**：进0标记，找1；进1标记，看到0已访问跳过，继续到2；进2标记，1已访问；返回时总数为3。整个过程根本碰不到孤立点3。

**为什么visited要共用？** 它是这次探索的一张总签到表，不是每次递归各自新建一张。数组参数指向同一份表，子调用贴过的标签，父调用和其他分支都看得到。

**最容易误会**：从0走一次只覆盖0所在的连通块，不代表遍历了全图。若题目问全图有几个块，要从每个仍未访问的点再启动一次，并共享整张访问表。

**翻译回原模板**：“遍历范围与分量汇总”就是**先说清从哪里出发、允许走哪些边，再把实际走到的范围统计出来**。本例矩阵扫描时间O(n²)上界，工作空间含访问表与递归栈；若用邻接表，全图DFS是O(n+m)。

**看懂后再回去**：[[03算法题模板#G1 遍历范围与分量汇总|G1 原模板与正式练习]]。

### G2 基础例题：最少经过几条边到各个点

**小题目**：无向图有边0—1、0—2、1—3、2—3。从0到每点最少经过几条边？答案 `dist=[0,1,1,2]`。

**先手算层次**：0是起点，距离0；迈一步能到1和2；再迈一步能到3。这里每条边都只算一步，不比较不同费用。

```cpp
void BFSDist(const int G[][MAXSIZE], int n, int start, int dist[]) {
    // start合法，dist容量至少n，-1表示还没发现。
    for (int i = 0; i < n; i++) dist[i] = -1;
    int q[MAXSIZE], front = 0, rear = 0;
    dist[start] = 0;
    q[rear++] = start;
    while (front < rear) {
        int v = q[front++];
        for (int w = 0; w < n; w++) {
            if (G[v][w] != 0 && dist[w] == -1) {
                dist[w] = dist[v] + 1; // 比发现它的点远一步
                q[rear++] = w;        // 标完再入队，不重复排队
            }
        }
    }
}
```

**手推队列**：0出队，发现1、2，距离都设1，队列为1、2；1出队，发现3，设2；2出队时也看到3，但3不是-1了，不再入队。

**为什么第一次发现就是最短？** 队列先处理距离小的点，后处理距离大的点；若存在更短走法，终点早就会被更前的一层发现。这一理由建立在每条边代价相同之上。

**最容易误会**：距离数组同时承担“是否发现”的标记，所以**入队时就设距离**。不要等出队才标，否则同一个点可能被不同前驱重复加入。不可达点保留-1。

**翻译回原模板**：“BFS标号与邻边约束”先理解成**按一圈一圈的距离给点写数字**。若改成二染色，标号从距离换成两种颜色，还需检查已染色邻点是否冲突。时间O(n²)，队列容量与距离输出均需容纳n个点。

**看懂后再回去**：[[03算法题模板#G2 BFS标号与邻边约束|G2 原模板与正式练习]]。

### G3 基础例题：先做完两个准备工作，才能做最后一步

**小题目**：三个任务0、1、2，有依赖0→2、1→2。箭头表示前者必须先完成。输出一个可行顺序，例如0、1、2；如果有环，返回false。

**先手算**：0和1没有前置任务，都能先做；2有两个前置任务，完成0还不够，完成1后才可以开始2。

```cpp
bool TopoSort(const int G[][MAXSIZE], int n, int out[]) {
    int indegree[MAXSIZE] = {0};    // 还没完成的前置任务数
    int q[MAXSIZE], front = 0, rear = 0, count = 0;
    for (int u = 0; u < n; u++)
        for (int v = 0; v < n; v++)
            if (G[u][v] != 0) indegree[v]++;
    for (int v = 0; v < n; v++)
        if (indegree[v] == 0) q[rear++] = v;
    while (front < rear) {
        int v = q[front++];
        out[count++] = v;          // 把v视为已经完成
        for (int w = 0; w < n; w++) {
            if (G[v][w] != 0) {
                indegree[w]--;
                if (indegree[w] == 0) q[rear++] = w;
            }
        }
    }
    return count == n;            // 没处理完：剩下的互相卡住了
}
```

**手推**：初始入度 `[0,0,2]`，队列0、1；做0，2的入度降到1，不能入队；做1，2降到0，才能入队；最后做2。

**为什么不只是“遇见邻居就入队”？** 这里的边是先后依赖，不是普通走路。要等一个点的**全部**前驱完成，不是一个前驱完成就够。

**最容易误会**：有环时out可能已经写了部分任务，但不构成全部任务的合法顺序；只有返回true才使用整个out。求最少学期还要按可并行的一批批任务分轮，本例暂时不算轮数。

**翻译回原模板**：“拓扑消除依赖”就是**每做完一项，就替后面的任务划掉一条未完成前置条件；划到0才能开始**。本例时间O(n²)，工作空间O(MAXSIZE)，输出另计；邻接表可做到O(n+m)。

**看懂后再回去**：[[03算法题模板#G3 拓扑消除依赖|G3 原模板与正式练习]]。

### G4 基础例题：两次牵线后，0和2是不是一组

**小题目**：4个点起初各自一组。先连接0—1，再连接1—2。问0和2是否已经连在同一组；再加0—2是否会合并两个原本不同的组？答案是“已连通”“不会”。

**做法**：每组推一个代表。`parent[x]` 表示x往代表方向认的上级，根结点满足 `parent[root]=root`。同组不要求每个成员立刻直接指向根。

```cpp
void InitSets(int parent[], int n) {
    for (int i = 0; i < n; i++) parent[i] = i;
}

int FindRoot(int parent[], int x) {
    if (parent[x] != x) {
        parent[x] = FindRoot(parent, parent[x]); // 顺便直接认最终代表
    }
    return parent[x];
}

bool JoinSets(int parent[], int u, int v) {
    int a = FindRoot(parent, u);
    int b = FindRoot(parent, v);
    if (a == b) return false;      // 本来就是一组，没有发生合并
    parent[b] = a;                // 必须让一个组的根认另一个根
    return true;
}
```

**手推**：初始parent为 `[0,1,2,3]`；合并0、1后为 `[0,0,2,3]`；合并1、2时，1的代表是0，所以让2认0，变 `[0,0,0,3]`。此时 `FindRoot(0)==FindRoot(2)`，再合并0、2返回false。

**为什么不是直接比较 `parent[u] == parent[v]`？** 两个成员可能离代表的层数不同。要一直沿上级找到根，再比较最终代表。

**最容易误会**：这里的parent是**集合组织关系**，不是原图里真实的边。不能从parent读出0到2的最短路线，也不能用它表示有向图的单向可达性。

**翻译回原模板**：“并查集合并”就是**先查代表，再合并两个代表所在的组**。本例为少一个状态，省略按规模合并；正式模板再加size优化。初始化O(n)，单次查找保守最坏O(n)，不能把优化版的复杂度直接套给本例；parent占O(n)，递归最深O(n)。

**看懂后再回去**：[[03算法题模板#G4 并查集合并|G4 原模板与正式练习]]。

### G5 基础例题：有直达路，也可能绕一下更便宜

**小题目**：有向带权图：0→1费用6，0→2费用1，2→1费用2。从0出发到各点的最低费用是什么？答案 `[0,3,1]`；去1应走0→2→1，不是选直达的6。

```text
0 ──6──→ 1
 \        ↑
  1       2
   ↘      │
      2 ──┘
```

这里用**另一种矩阵约定**：`W[u][v]` 是费用；无边填INF，自己到自己填0。0费用边也是真的边。所有费用非负，且本页小例子的有限路径和小于INF，运算可用long long表示。

```cpp
const long long INF = (1LL << 60);

void DijkstraTiny(const long long W[][MAXSIZE], int n,
                  int start, long long dist[]) {
    bool done[MAXSIZE] = {false};  // 哪些点的最短费用已最终确定
    for (int v = 0; v < n; v++) dist[v] = INF;
    dist[start] = 0;
    for (int step = 0; step < n; step++) {
        int u = -1;
        for (int v = 0; v < n; v++) {
            if (!done[v] && (u == -1 || dist[v] < dist[u])) u = v;
        }
        if (u == -1 || dist[u] == INF) break;
        done[u] = true;            // 选中未确定点里当前报价最小的
        for (int v = 0; v < n; v++) {
            if (!done[v] && W[u][v] != INF) {
                long long candidate = dist[u] + W[u][v];
                if (candidate < dist[v]) dist[v] = candidate;
            }
        }
    }
}
```

| 刚确定的点 | 更新了什么 | dist变成 |
| --- | --- | --- |
| 起始尚未确定 | 只知道到自己免费 | `[0,INF,INF]` |
| 0 | 直达到1要6，到2要1 | `[0,6,1]` |
| 2 | 经2到1只要1+2=3，比6便宜 | `[0,3,1]` |
| 1 | 没有更便宜的更新 | `[0,3,1]` |

**“选最小”和“松弛”分别是什么？** 选最小是从未确定点里挑当前总费用最低的；松弛是尝试“已经走到u，再走u→v”会不会比原报价便宜，便宜就改写。

**为什么可以确定它？** 边权非负，从更贵的未确定点再绕路，不会反而以更低的总费用到达当前最便宜点。出现负权时，这个理由就可能失效。

**最容易误会**：这不是BFS，边数少不代表费用低；也不是每次只选费用最小的一条边。Dijkstra比较的是**从源点走来的总费用**。

**翻译回原模板**：“选最小再松弛”在本例指Dijkstra的**先确定最近点，再改善其他点的路径报价**。Prim虽然也选小值，但更新的是接入当前树的一条边 `W[u][v]`，不是 `dist[u]+W[u][v]`；先不要把它们混背。时间O(n²)，done固定缓冲区占O(MAXSIZE)，dist输出容量O(n)。

**看懂后再回去**：[[03算法题模板#G5 选最小再松弛（备查）|G5 原模板与正式练习]]。

### S1 基础例题：用栈把三个数倒着输出

**小题目**：输入 `[3,5,7]`，用栈输出 `7 5 3`。n不超过MAXSIZE。

**把栈想成一摞盘子**：3先放，5叠上去，7最后放在最上面；取的时候只能先取最上面的7。

```cpp
void PrintReverseByStack(const int A[], int n) {
    int stack[MAXSIZE];
    int top = -1;                 // 没有盘子，栈空
    for (int i = 0; i < n; i++) {
        top++;
        stack[top] = A[i];        // 入栈：先腾一个新位置，再放
    }
    while (top >= 0) {
        int x = stack[top];       // 出栈：先取当前栈顶
        top--;
        printf("%d ", x);
    }
}
```

**手推**：入3后top=0，入5后top=1，入7后top=2；出栈依次读取2、1、0号格，输出7、5、3，最后top=-1。

**为什么能倒过来？** 新数据一直堆在旧数据上面，后来的先被拿走。这就是“后进先出”，不是“自动排序”。

**最容易误会**：top是最后一项的下标，不是元素个数。空栈不能再读 `stack[top]`；先判 `top>=0`。本例当然也能用倒序循环完成，用栈只是为了单独观察入栈、出栈动作。

**翻译回原模板**：“后进先出”就是**最后留下的待处理项，先拿出来处理**。括号题把“待配对的左括号”入栈；表达式题把“已经算出的子结果”入栈，存的东西不同，但出入规则相同。时间O(n)，本例固定栈占O(MAXSIZE)，按输入规模配容量时记O(n)。

**看懂后再回去**：[[03算法题模板#S1 后进先出（基础）|S1 原模板与正式练习]]。

### H1 基础例题：只修好根结点，不重排整棵树

**小题目**：数组 `[1,5,3]` 表示根1、左孩子5、右孩子3。两个孩子本身都是合法大根堆（叶子），但根太小。用一次下滤修成大根堆，得到 `[5,1,3]`。

**先画树**：

```text
修复前：     1          修复后：     5
           / \                    / \
          5   3                  1   3
```

**做法**：先把根的值x拿在手里，根位置暂当“洞”。选两个孩子中较大的那个向上补洞；洞移到那个孩子原来的位置，继续检查，最后把x放进去。

```cpp
void SiftDownMax(int A[], int n, int root) {
    // 前提：0 <= root < n，root的两棵孩子子树已经各自成堆。
    int x = A[root];
    int hole = root;
    int child = 2 * hole + 1;      // 0下标数组的左孩子
    while (child < n) {
        if (child + 1 < n && A[child + 1] > A[child]) child++;
        if (x >= A[child]) break;  // x放在这里就能压住两个孩子
        A[hole] = A[child];        // 较大的孩子上移，补当前洞
        hole = child;             // 洞往下走
        child = 2 * hole + 1;
    }
    A[hole] = x;
}
// 本例调用：SiftDownMax(A, 3, 0);
```

**手推**：x拿着1；孩子是5和3，选5；5补到根；洞落到左孩子位置，那里没有孩子了，把1放进去，结束。

**为什么必须选较大孩子？** 若提升3，根3的下面仍有5，大根堆条件还不满足。提升5后，5既不小于另一个孩子3，也不小于向下安置的1。

**最容易误会**：堆只保证父亲不小于孩子，不保证左右或全数组有序。`[5,1,3]` 是大根堆，但不是降序数组。若孩子子树本来就乱，一次修根不能保证整棵树成堆。

**翻译回原模板**：“堆的局部修复”就是**其余部分已经合规，只把可能过小的根值向下放到合适位置**。建堆要从后往前修多个非叶子；堆排序还要反复把堆顶移到末尾，本例先不叠加这两步。单次下滤时间O(log n)，额外空间O(1)。

**看懂后再回去**：[[03算法题模板#H1 堆的局部修复（基础）|H1 原模板与正式练习]]。

## 看完后，不背名称也可以这样自测

先只选一道已经读过的例题，回答下面四句：

1. **输入到输出变了什么？** 比如“把0删掉，其他数顺序不变”。
2. **我需要记住什么？** 比如“读到哪里，下一个保留数写哪里”。
3. **哪一行最不能写错？为什么？** 比如“改next前先存后继，不然丢链”。
4. **去掉什么条件就会出错？** 比如“有负数时，不能照搬这个按和收缩窗口”。

能把这四句说成人话，再去读原模板的“识别信号”“先问自己”，它们才会变成对已有经验的提示，而不是一串需要硬猜的暗号。

> [!tip] 从基础例题到正式练习，先找多出来的那一层
> - A1删0 → 删一个值域区间：只改保留条件。
> - A3计次数 → 查询缺失值：在计数之后再检查哪些槽是0。
> - L2单队尾插 → 按阈值分成多队：增加几套头尾指针与分队条件。
> - T1数结点 → 求树高／平衡：明确子树返回什么，再换组合规则。
> - T2只传路径和 → 保存某条目标路径：增加路径记录，并处理共享状态回退。
> - G2单次距离 → 两侧距离筛选：分别算两次距离，再检查题目要求的等式。
> 一时不会组合，就退回其中一个基本动作；不需要因此重新背整张表。
