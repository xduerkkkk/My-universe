### 1.$a, b, c$ 的作用范围

你说“在 $d$ 之后的出栈序列，$a,b,c$ 必须保持相对逆序 $c,b,a$”。

* **偏差之处**：$a, b, c$ **不一定都会出现在 $d$ 的后面**。

  * 如果 $a, b, c$ 在 $d$ 出栈**前**就已经全部或部分出栈了，它们就不受 $d$ 的约束。
  * **只有在 $d$ 出栈的那一刻，依然留存在栈中的元素**，在 $d$ 之后弹出时才必须严格保持相对逆序（即自顶向下的 LIFO 顺序）。

#### 示例验证：
假设输入序列为 $a, b, c, d, e$。
* **情况 1（$a,b,c$ 全在 $d$ 之后弹出）**：
  入栈 $a, b, c, d$ $\to$ 弹出 $d$。此时栈内留有 `[Bottom: a, Middle: b, Top: c]`。
  $d$ 弹出后，剩余的 $a, b, c$ 必须按 $c \to b \to a$ 相对逆序弹出。
* **情况 2（只有部分在 $d$ 之后弹出）**：
  入栈 $a, b$ $\to$ 弹出 $b$（$b$ 在 $d$ 之前就出了）。
  入栈 $c, d$ $\to$ 弹出 $d$。
  此时在 $d$ 后面出栈的只有 $c$ 和 $a$，它们之间的相对顺序只需保证 **$c$ 在 $a$ 前面**（即保持 $c \dots a$ 相对逆序）即可。出栈序列如 $b, d, c, a, e$ 是合法的。

**上溢（Overflow）**
    
- **定义**：当栈已经**满**了（Full），程序却依然试图执行**入栈（Push）**操作。
	
- **后果**：数据越出了预分配的数组边界，造成内存越界或数据覆盖。
        
 **下溢（Underflow）**
    
- **定义**：当栈已经是**空**的（Empty），程序却试图执行**出栈（Pop）**操作。
	
- **后果**：试图读取无效数据，属于逻辑控制错误。![[02王道题-1775026701803.jpeg]]
下溢”是由**程序控制逻辑**决定的（即栈空了你还强行 Pop）。不论你用普通栈还是共享栈，只要代码逻辑写错（在栈空时调用 Pop），就会发生下溢。共享栈改变的是**内存空间分配方式**，无法防止控制逻辑上的下溢。
- **共享栈的机制**：  
    将两个栈的栈底分别设在一维数组的两端，栈顶相向生长。  
    只要两个栈的**元素总量**不超过数组总容量，栈 A 就可以动态占用栈 B 暂未使用的空间（例如栈 A 用 150 单元，栈 B 用 30 单元）。
    
- **效果**：
    
    1. **节省存储空间**：不需要为每个栈都过量预留最大空间。
        
    2. **降低上溢概率**：只有当两个栈的元素总和超过总空间时才会发生上溢（即栈顶指针相遇 top2 - top1 == 1）。

---

### 一、两种指针定义的严格对比

假设数组长度为 `MaxSize`，且均采用“**牺牲一个存储单元**”的方法来区分队空与队满。

| 指针定义类型 | 方案 A（王道教材常用） | 方案 B（本题第 08 题） |
| :--- | :--- | :--- |
| **`front` 含义** | 指向**队首元素** | 指向**队首元素的前一位置** |
| **`rear` 含义** | 指向**队尾元素的下一个位置** | 指向**队尾元素** |
| **队空条件** | **`rear == front`** | **`rear == front`** |
| **队满条件** | **`(rear + 1) % MaxSize == front`** | **`(rear + 1) % MaxSize == front`** |
| **队列长度公式** | `(rear - front + MaxSize) % MaxSize` | `(rear - front + MaxSize) % MaxSize` |

---

### 二、为什么公式会一模一样？

本质原因是：**方案 B 将 `front` 和 `rear` 两个指针的位置，相对于方案 A 整体向左平移了 1 个单位。**

1. **方案 A**：`front` 准确踩在队首上，`rear` 往前多跨了 1 位（踩在队尾后方空位）。
2. **方案 B**：`rear` 准确踩在队尾上，`front` 往后多退了 1 位（踩在队首前方空位）。

两个指针在逻辑环形空间中的**相对距离（间隔关系）完全没有改变**。因此，判断“重合（队空）”和“相差 1 单元（队满）”的代数表达式完全一样。

---

### 三、两种方案真正的区别是什么？

两者的区别**不在于判空/判满公式**，而在于**代码执行顺序**与**元素访问下标**：

#### 1. 入队与出队的代码顺序反转
* **方案 A**（`front` 指队首，`rear` 指队尾后一位置）：
  * 入队：先存数据，再移动指针 $\to$ `Q[rear] = x; rear = (rear + 1) % MaxSize;`
  * 出队：先取数据，再移动指针 $\to$ `x = Q[front]; front = (front + 1) % MaxSize;`
* **方案 B**（`front` 指队首前一位置，`rear` 指队尾）：
  * 入队：先移动指针，再存数据 $\to$ `rear = (rear + 1) % MaxSize; Q[rear] = x;`
  * 出队：先移动指针，再取数据 $\to$ `front = (front + 1) % MaxSize; x = Q[front];`

#### 2. 元素物理下标取值不同
* **方案 A**：队首元素物理下标为 `front`，队尾元素物理下标为 `(rear - 1 + MaxSize) % MaxSize`。
* **方案 B**：队首元素物理下标为 `(front + 1) % MaxSize`，队尾元素物理下标为 `rear`。

#### 法则 1：输出受限（ORD）—— “中间不能有山峰”法则

**适用场景：** 允许两端入队，一端出队（第 20 题）。

**底层逻辑：** 因为只能从一端出队，所以留在队列里的元素，最终出队的顺序必定是它们在队列里从左到右的死顺序。而在排队时，新来的元素只能插在队伍的最前面或最后面，**绝对插不到中间**。所以，如果几个元素被困在队列里，**最后进去的那个（最大的那个）绝不可能在中间**。

**秒杀规律：**

1. 随便盯住输出序列中的一个大数 $X$。
    
2. 找出在 $X$ 后面输出、且比 $X$ 小的所有数，把它们单独拿出来看。
    
3. 在这些数中，**绝对不能出现“小-大-小”的格局（即最大的数不能夹在中间）**。
    

**我们用这个法则秒杀第 20 题：**

已知入队顺序是 $a, b, c, d, e$（当成 1, 2, 3, 4, 5）。

- **看 A 选项 (2, 1, 3, 4, 5)：** 找大数 2，后面比 2 小的只有 1，没问题。找 3，后面没有比 3 小的。全部合法。

- **看 C 选项 (4, 2, 3, 1, 5)：** 找大数 4。后面比 4 小的数组成的序列是 **`2, 3, 1`**。

#### 法则 2：输入受限（IRD）—— “必须是最大或最小”法则

**适用场景：** 允许一端入队，两端出队。

**底层逻辑：** 元素只能从一端进去，所以在队列里永远是严格按顺序排成一列（比如 `4, 3, 2, 1`）。出队时，你可以从队头拿，也可以从队尾拿。这意味着，你每次拿出来的元素，**必须是当前困在队列里的元素中最大的，或者是最小的！**

**秒杀规律：**

1. 盯住输出序列中的一个大数 $X$。
    
2. 找出在 $X$ 后面输出、且比 $X$ 小的所有数组成的集合。
    
3. 这些数在输出时，**第一个输出的数，绝对不能是“夹在中间大小”的数。它必须是这堆数里最大的，或者是最小的。**
    

**验证前面背的口诀：为什么 4, 2, 3, 1 是输入受限的死局？**

1. 找到大数 4。后面比 4 小的集合是 `{1, 2, 3}`。
    
2. 4 出来之后，接着出来的是 **2**。
    
3. 但是在 `{1, 2, 3}` 里面，2 既不是最大（3），也不是最小（1），它是夹在中间的数！
    
4. 你想象一下队列里是 `4, 3, 2, 1`，你拿走了 4（剩下 `3, 2, 1`），你想拿 2？抱歉，3 堵在左边，1 堵在右边，2 根本出不来！

这意味着 1, 2, 3 必须在 4 入队前，已经全部入队完毕，并且 4 是通过“左端入队”加入的。
那么问题转化为：**仅通过两端入队，1, 2, 3 这三个元素能形成哪些相对物理顺序？**

这就回到了你那句非常精准的判断：“**3 必须在 12 这一坨的最左边或最右边**”。
我们用严谨的状态转换来验证：
1.  **入队 1**：当前状态 `[1]`
2.  **入队 2**（可在左或右）：状态变为 `[2, 1]` 或 `[1, 2]`
3.  **入队 3**（可在当前状态的左或右）：
    *   若基于 `[2, 1]`，可得 `[3, 2, 1]` 或 `[2, 1, 3]`
    *   若基于 `[1, 2]`，可得 `[3, 1, 2]` 或 `[1, 2, 3]`
4.  **最后入队 4**（必须在最左）：对应得到的最终队列物理状态分别为：
    *   `[4, 3, 2, 1]` -> 对应输出 4, 3, 2, 1
    *   `[4, 2, 1, 3]` -> 对应输出 4, 2, 1, 3 **（选项 D 可得）**
    *   `[4, 3, 1, 2]` -> 对应输出 4, 3, 1, 2
    *   `[4, 1, 2, 3]` -> 对应输出 4, 1, 2, 3

### 3. 结论

观察选项 C 的序列：`4, 2, 3, 1`。
若要输出此序列，队列内部的物理排列必须是 `[4, 2, 3, 1]`。
刨去最左边的 4，说明 1, 2, 3 入队后形成的物理状态是 `[2, 3, 1]`。
在这个状态中，**最后入队的 3 夹在了 2 和 1 的中间**。这违背了“只能从两端入队”的前提条件，3 根本无法直接插到 1 和 2 之间。

因此：
*   选项 D（4, 2, 1, 3）可以通过输出受限队列得到（不能由输入受限得到）。
*   选项 C（4, 2, 3, 1）**既不能**由输入受限得到，**也不能**由输出受限得到。

正确答案是 **C**。

**A. 消除递归不一定需要使用栈 （正确）**
*   **原理解释：** 递归的本质是保存当前函数的状态（如局部变量、返回地址），以便后续调用结束后能恢复执行。只有当调用结束后**还有剩余操作未执行**时，才必须用栈来保存这些状态。
*   **反例（不需要栈的情况）：** 
    1.  **尾递归（Tail Recursion）：** 递归调用是函数体内的最后一个操作。因为调用返回后当前层已经没有需要继续执行的代码，所以根本不需要保存当前层的状态。编译器可以直接将其优化为普通循环（迭代）。
    2.  **简单的单向递归：** 例如用递归求斐波那契数列或阶乘，完全可以通过设置几个普通变量，用 `for` 或 `while` 循环直接自底向上推导，只需要常数级别的空间，不需要显式声明或使用栈。

**B. 对同一输入序列进行两组不同的合法入栈和出栈组合操作，所得的输出序列也一定相同 （错误）**
*   **原理解释：** 栈的特性是后进先出（LIFO），入栈和出栈的交替时机不同，会导致完全不同的输出序列。这就是经典的“栈的合法输出序列”问题（种类数由卡特兰数决定）。
*   **具体反例：** 输入序列为 `1, 2`。
    *   操作组合 1：入栈 1 -> 出栈 (输出 1) -> 入栈 2 -> 出栈 (输出 2)。输出序列：`1, 2`。
    *   操作组合 2：入栈 1 -> 入栈 2 -> 出栈 (输出 2) -> 出栈 (输出 1)。输出序列：`2, 1`。

**C. 通常使用队列来处理函数或过程调用 （错误）**
*   **原理解释：** 函数调用的执行逻辑是：A 调用 B，B 调用 C，必须等 C 执行完返回，B 才能继续执行；B 执行完返回，A 才能继续执行。
*   **核心机制：** 这是一种严格的**后进先出（LIFO）**关系（最后被调用的函数最先执行完毕）。因此，处理函数调用使用的是**栈（Stack）**，即“函数调用栈”。队列是先进先出（FIFO），通常用于缓冲区、任务调度或广度优先搜索等。

**D. 队列和栈都是运算受限的线性表，只允许在表的两端进行运算 （错误）**
*   **错误点：** 错在“只允许在表的两端”这句话。
*   **精确定义拆解：**
    *   **队列（Queue）：** 允许在一端（队尾）插入，在另一端（队头）删除。确实在**两端**进行运算。
    *   **栈（Stack）：** 插入（压栈）和删除（弹栈）操作被严格限制在**同一端**，即栈顶（Top）。栈底是固定的，不能进行任何运算。因此，说栈在“两端”进行运算是错误的。

### 1. 核心大前提：什么是“稀疏矩阵的压缩存储”？
稀疏矩阵是指绝大多数元素为 0 的矩阵。
**压缩机制的本质：只存储非零元素。**
但因为没存 0，原先二维数组的物理位置被打乱了，所以**必须额外记录该非零元素的逻辑行号和列号**。

### 2. 逐一拆解四个关键数据结构

*   **三元组表（稀疏矩阵的顺序存储）：**
    顾名思义，把每个非零元素打包成一个包含三个字段的结构体：`(行号, 列号, 元素值)`。然后把这些结构体依次存入一个一维数组中。
    **机制特点：** 极大地节省了空间，但因为底层是一维连续数组，如果需要在原矩阵中插入或删除一个非零元素，就要大规模移动数组元素，时间复杂度极高。

*   **十字链表（稀疏矩阵的链式存储）：**
    为了解决三元组表插入删除慢的问题，采用了链表。
    **机制特点：** 每个非零元素是一个链表节点，包含 5 个字段：`(行号, 列号, 元素值, right指针, down指针)`。
    *   `right` 指针：将同一行的非零元素串成一个单链表。
    *   `down` 指针：将同一列的非零元素串成一个单链表。
    整个结构纵横交错，形成一个“十字”网状，既实现了“只存非零元素”的压缩，又保证了动态修改的效率。

*   **邻接矩阵（极度反向考点）：**
    这是图论中的存储结构，本质就是一个**完整的二维数组**。
    **机制特点：** 哪怕图中只有 1 条边（极度稀疏），如果有 $N$ 个顶点，邻接矩阵也会雷打不动地开辟 $N \times N$ 的连续内存，里面填满 0。
    **结论：** 邻接矩阵**毫无压缩可言**，它是“稀疏矩阵压缩”的绝对反面。看到它直接排除 B 和 D。

*   **二叉链表：**
    每个节点包含数据域和两个指针域（左孩子、右孩子）。这是专门用于存储**二叉树**的结构。它无法表达二维矩阵中行列正交的逻辑关系。直接排除 C。
