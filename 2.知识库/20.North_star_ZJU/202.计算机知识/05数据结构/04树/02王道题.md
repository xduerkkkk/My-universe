# 二叉树遍历与线索二叉树

1. 感觉很考验理解![[02王道题-1775221568283.jpeg]]![[02王道题-1775221609440.jpeg]]
这类题的思考核心是：把"某序列的最后一个结点"翻译成**沿树往下走的确定路径**，而不是去枚举例子碰运气。

先建立两个关键结论：

**中序遍历的最后一个结点** 中序 = 左、根、右。要找最后被访问的，从根开始：只要有右孩子就往右走，直到某个结点没有右孩子。所以中序最后一个结点 = **从根一路走右孩子能到的那个结点**（它没有右孩子，但可能有左孩子，不一定是叶子）。

**先序遍历的最后一个结点** 先序 = 根、左、右。最后被访问的：每个结点处优先进右子树，右子树空才进左子树，一直递归下去。终点必然是一个**没有孩子的结点**，即**先序的最后一个结点一定是叶子**。它的定位规则是"每步优先向右，否则向左，直到叶子"。

有了这两条，逐项判断：

**A**：中序最后结点不一定是叶子（它可能有左孩子），而先序最后结点必是叶子，两者可以不同。反例：根 A 只有左孩子 B。中序 B, A，最后是 A；先序 A, B，最后是 B。错。

**B**：先序最后结点是叶子，中序最后结点可能不是叶子。反例：

Text

    A

   /

  B

 /

C

先序 A, B, C 最后是 C；中序 C, B, A 最后是 A。错。

**C**：设叶子 L 是某子树中序的最后一个结点。由中序结论，L 是"从根一路向右"到达的结点；又因为 L 是叶子，它既无右孩子也无左孩子。关键在于：从根到 L 这条路径上**每个结点的右孩子都是路径上的下一个结点**。而先序找最后结点的规则是"每步优先向右"，于是先序的下降路径会和这条右链完全重合，最终停在叶子 L。所以 L 也是先序的最后一个结点。**正确**。

**D**：设叶子 L 是先序最后结点。先序下降是"优先右，否则左"，可能走了左分支。反例：根 A 只有左孩子 B（叶子）。先序 A, B 最后是 B（叶子）；中序 B, A 最后是 A。L≠A。错。

一句话概括这类题的思考方式：把"最后一个结点"化成一条**下降路径的规则**（中序=纯右链终点；先序=优先右否则左直到叶子），再看两条规则在给定前提（是否叶子）下是否必然汇合到同一点。C 之所以成立，正是因为"叶子 + 中序最后"这个前提，逼出了一条纯右链，使先序规则无从分岔。
**对比就一句话**: 两者右子树都排在最后没错, 但当右子树为空时, 谁来"顶上"最后一个位置不同——

- 中序: 根在右的**前一位**, 右空了, 根自己就是最后 → 停在原地 (可能非叶子)。
- 先序: 根在**最前**, 右空了, 根顶不上, 只能退到左子树里找 → 必须继续下降 (终点必是叶子)。

你之前只看"右在最后"是对的, 但漏了根的位置这一层。正是根的位置差异, 让中序停在"最后一个没有右孩子的结点", 而先序必须一路走到叶子。

	2. 写出后序：$C, B, A$
	    
	3. **找对子：** 在先序中找相邻的两个字母，看看在后序中它们是不是也相邻，且顺序反过来。

	4. **算总数：** 把所有歧义的可能性乘起来。$2 \times 2 = 4$。

### 1. 题干分析：推导“某种操作”的实质
- $T$ 采用二叉链表存储，中序遍历（左-根-右）为升序序列，说明 $T$ 是一棵**二叉排序树 (BST)**，满足“左子树的值 < 根的值 < 右子树的值”。
- 目标是得到新树 $T'$，使得它的中序遍历（新的左-根-新的右）变为**降序序列**。
- 要实现从升序到降序的转变，唯一的操作就是**“将整棵树镜像翻转”**，即：**交换二叉树中所有结点的左右孩子指针**。

### 2. 分析选项 A 和 B：为什么后序合适、中序不合适？
要交换所有结点的左右指针，核心逻辑是对每个访问到的结点执行 `swap(root->left, root->right)`。我们把这个操作代入遍历模板中：

- **B 选项（后序遍历 - 合适）**
  后序遍历的顺序是“左子树 -> 右子树 -> 根结点”。
  如果套用后序，算法会先递归翻转左子树，再递归翻转右子树，最后回到当前根结点交换它的左右指针。这完全符合标准的后序模板，逻辑自然，不会产生任何冲突。前序遍历（根-左-右）同样合适，但选项没有。

- **A 选项（中序遍历 - 不合适）**
  中序遍历的顺序是“左子树 -> 根结点 -> 右子树”。
  如果你套用标准中序模板：先递归处理完左子树，然后访问根结点执行 `swap`，**此时，原本的右子树已经被换到了当前结点的左指针上**，原本已经处理过的左子树换到了右指针上。
  紧接着，按照模板你要去递归处理“右子树”——但此时右指针指向的是原本的左子树。这会导致**原本的左子树被二次处理，而原本的右子树被直接遗漏**。因此，中序遍历在实现这个操作时会破坏标准模板逻辑，最不合适。

### 通法：如何用先序和后序锁定树的结构？

- **后序模板**：`左子树 -> 右子树 -> 根`

**【核心判定定理】**
如果在先序序列中，结点 $X$ 紧挨着 $Y$（即 `..., X, Y, ...`）；
同时在后序序列中，结点 $Y$ 紧挨着 $X$（即 `..., Y, X, ...`）；
**那么必定说明：$X$ 只有 $Y$ 这一个孩子（即 $X$ 的度为 1），$Y$ 可能是左孩子也可能是右孩子。**

**为什么？**
假设 $X$ 有两个孩子 $L$ 和 $R$。
先序必然是：`X, L的根, ...` （紧跟在 $X$ 后面的是左孩子）
后序必然是：`..., R的根, X` （紧挨在 $X$ 前面的是右孩子）
因为有两个不同的孩子，紧挨着 $X$ 的结点必定不同。只有当其中一个子树为空（度为 1）时，紧挨着 $X$ 的才会是同一个结点。

### 1. 拆解“后根序列”
在普通的二叉树里，我们常说“后序遍历”（左-右-根）。但在多叉树（有序树）中，一个结点可能有 3 个、5 个甚至更多孩子，没有严格的“左右”之分。
因此，统一称为**“后根遍历”**，规则非常死板：
**先从左到右依次完全遍历当前结点的所有子树，最后访问当前结点自身。**
即：`子树1 -> 子树2 -> ... -> 子树n -> 根结点`。

### 2. 为什么转换后变成了二叉树的“中序”？
我们用“左孩子，右兄弟”的转换机制，严格对比两者的遍历逻辑：

在转换后的二叉树 $T_1$ 中，任何一个结点 $X$ 的指针含义是：
- `X.left`：指向 $X$ 在原树 $T$ 中的**第一个孩子**。
- `X.right`：指向 $X$ 在原树 $T$ 中的**紧挨着的右兄弟**。

现在我们对 $T_1$ 执行**中序遍历（左-根-右）**，宏观步骤如下：
1. **先走“左”**：也就是访问 `X.left` 及其连带的结构。在原树 $T$ 中，这就等于把 $X$ 的**所有孩子**全部访问完毕。
2. **再访“根”**：也就是访问 $X$ 自己。
3. **后走“右”**：也就是访问 `X.right` 及其连带的结构。在原树 $T$ 中，这就等于去访问 $X$ 的**所有右兄弟**。

**结论完美对齐：**

 为何“森林先序 = 二叉树先序”？

我们可以从递归定义的角度来看：

- **森林** 
    
    **`FF`**
    
     **的先序遍历**：
    
    1. 访问第一棵树的根节点。
        
    2. 先序遍历第一棵树中根节点的**子树森林**。
        
    3. 先序遍历森林中**剩余的树**。
        
- **二叉树** 
    
    **`TT`**
    
     **的先序遍历**：
    
    1. 访问根节点。
        
    2. 先序遍历**左子树**（对应原根节点的子树森林）。
        
    3. 先序遍历**右子树**（对应原根节点的后续兄弟，即剩余的树）。
        

你会发现，这两者的步骤逻辑是完全一致的，所以它们的先序序列相同。

---

为何“森林后序 = 二叉树中序”？

这是最容易产生困惑的地方。注意，森林的后序遍历有时也叫“后根遍历”。

- **森林** 
    
    **`FF`**
    
     **的后序遍历**：
    
    1. 后序遍历第一棵树中根节点的**子树森林**。
        
    2. 访问第一棵树的根节点。
        
    3. 后序遍历森林中**剩余的树**。
        
- **二叉树** 
    
    **`TT`**
    
     **的中序遍历**：
    
    1. 中序遍历**左子树**（对应原根节点的子树森林）。
        
    2. 访问根节点。
        
    3. 中序遍历**右子树**（对应原根节点的后续兄弟，即剩余的树）。
        

可以看到，由于“右兄弟”变成了“右子树”，在二叉树中序遍历（左-根-右）时，右兄弟是在根节点之后访问的。这恰好对应了森林后序遍历中“先处理完当前树的所有子孙，再处理根，最后处理后续树”的逻辑。

*   **从边的数量看**：

    $$m \times n_{非叶} = n + n_{非叶} - 1$$
*   **整理公式**：
    $$(m - 1) \times n_{非叶} = n - 1$$

*   **A 选项（错误）：并查集的环路检测**
    并查集**非常适合**检测无向图中的环路。
    **机制**：遍历图的所有边。对于每一条边 `(u, v)`，执行 `Find(u)` 和 `Find(v)`。如果两者返回的根结点相同，说明 `u` 和 `v` 已经在同一个连通分量（集合）中。此时若强行加入边 `(u, v)`，必定会在该连通分量中构成环路。
*   **B 选项（错误）：高度与优化**
    这里涉及到复杂度的边界。如果没有“按规模/秩合并（Union by Rank/Size）”，仅凭“路径压缩（Path Compression）”，在极端情况下（即只执行合并，不执行查找），树的高度在某一瞬间确实可能达到 $O(n)$。
    但该选项的表述带有误导性，在 408 语境下，它被判定为错误是因为：路径压缩的**核心目的**就是在 `Find` 过程中将路径上的所有结点直接挂载到根结点上，从而将树的高度**极大地扁平化**。如果同时使用路径压缩和按规模合并，树的高度将被严格控制在 $O(\alpha(n))$（几乎可以视作 $O(1)$ 常数），绝对不可能“仍是 $O(n)$”。
*   **C 选项（错误）：Find 的返回值与代表元**
    **严格区分函数返回值与数组存储值**：
    为了优化，并查集的底层数组 `S[root]` 常常用来存放该集合元素个数的**相反数**（例如 `-3` 表示有 3 个元素）。
    但是，`Find(x)` 操作的代码逻辑是顺着父指针向上找，最后返回的是**根结点的下标（索引）**。集合的标志（代表元）是这个**下标**，绝不是那个表示大小的相反数值。
*   **D 选项（正确）：按规模合并（Union by Size）**
    这是并查集的标准优化机制之一。
    **机制**：在执行 `Union(u, v)` 时，比较两个集合的大小（通过查看它们根结点存储的相反数）。强制将结点数量**较少**的树，其根结点的父指针指向结点数量**较多**的树的根结点。
    **效果**：这样可以保证合并后的树，高度增长极其缓慢，严格从数学上保证了最坏情况下的树高被限制在 **$O(\log_2 n)$**。

    *   **A 选项（正确）：双亲表示法**
    这是并查集的物理基础。所谓“双亲表示法”，就是使用一个一维数组 `parent[]`。数组的索引代表具体的结点，数组内存放的值 `parent[i]` 代表该结点的父结点的索引。如果是根结点，通常存放 `-1` 或自身的索引。这是一种极为紧凑的树形结构存储方式。
*   **B 选项（正确）：克鲁斯卡尔 (Kruskal) 算法**
    Kruskal 算法的核心是“贪心选边，且不能成环”。每次从剩下的边中挑出权值最小的一条边 `(u, v)`，如何判断这条边加进去会不会成环？完全依赖并查集：执行 `Find(u)` 和 `Find(v)`，若属于不同集合则合并（选边），若属于同一集合则跳过（防止成环）。
*   **C 选项（正确）：无向图连通性**
    将无向图的所有边执行 `Union` 操作后，最后统计底层数组中值为负数（或值为 `-1` / 指向自己）的根结点个数。如果有且仅有 1 个根，说明全图连通；如果有 $k$ 个根，说明图有 $k$ 个独立的连通分量。
*   **D 选项（错误）：查找操作的时间复杂度**
    这个选项错在**没有给出前提条件，直接定死了时间复杂度**。
    在精确的算法分析中：
    1.  **最原始（未优化）的并查集**：如果在 Union 时总是将一条链挂在另一条链的末端，树会退化成单链表，此时 `Find` 操作的最坏时间复杂度是 **$O(n)$**。
    2.  **仅采用按规模合并（Union by Size/Rank）**：树高被严格限制，`Find` 操作最坏复杂度才是 **$O(\log_2 n)$**。
    3.  **同时采用路径压缩和按规模合并**：`Find` 操作的均摊复杂度会降到极低的 **$O(\alpha(n))$**。
    因此，泛泛而谈“长度为 $n$ 的并查集查找复杂度就是 $O(\log_2 n)$”不仅忽略了原始 $O(n)$ 的可能，也忽略了彻底优化后更低复杂度的可能。

    ### 2. 分析 D 选项（正确）
题干中 $T_2$ 是**定长编码集**的二叉树。
- **定长**的物理含义：所有字符的二进制编码长度绝对相等（例如 ASCII 码统统是 8 位，不管字母出现多少次）。
- **映射到树结构**：既然每个字符的编码长度都相等，说明从根结点走到每个字符叶结点的路径长度完全一致。
- **结论**：在 $T_2$ 中，所有的字符（叶结点）必定处于树的**同一层**。这与字符出现的频次毫无关系，频次机制在定长编码中根本不生效。因此 D 正确。

### 3. 分析 C 选项（错误）
题干中 $T_1$ 是**哈夫曼编码集**的二叉树。
- 哈夫曼树的合并机制中，频次越高的字符倾向于离根越近（层数越浅），但这**绝对不意味着**频次不同就一定在不同层。
- **直接拿你上一题（第 18 题）的推导打脸**：
  在上一题中，字符 `a` 的频次是 6，字符 `e` 的频次是 10，频次完全不同。
  但经过哈夫曼树构建后，`a` 的编码是 `00`（长度 2），`e` 的编码是 `11`（长度 2）。它们处在哈夫曼树的**同一层**。因此 C 错误。
### 4. 分析 A 和 B 选项（错误：用极限边界反证）
我们直接构造一个极简的反例：假设字符集 $S$ 只有 3 个字符（即 $n=3$）。

*   **看 $T_1$（哈夫曼树）**：
    包含 $n$ 个叶结点的哈夫曼树，每次合并减少 1 棵树新增 1 个结点，其结点总数严格固定为 **$2n - 1$**。
    当 $n=3$ 时，$T_1$ 结点总数为 $2 \times 3 - 1 = 5$ 个。
    它的结构是：根连着 1 个叶子和 1 个分支，分支再连 2 个叶子。**树的高度为 2**。

*   **看 $T_2$（定长编码树）**：
    要对 3 个字符进行定长编码，至少需要 2 个比特位（因为 1 位只能编 2 个，2 位能编 4 个，满足 $2^{L-1} < 3 \le 2^L$）。
    所以所有叶结点的深度必须是 2（**树的高度为 2**）。
    为了达到深度 2，树的结构是：根 (1) -> 第一层分支 (2) -> 第二层叶子 (3)。结点总数为 $1 + 2 + 3 = 6$ 个。

*   **结论**：
    对比发现，A 选项说结点数相同（$5 \neq 6$，A 错）。
    B 选项说 $T_1$ 高度大于 $T_2$（$2 = 2$，并没有大于，B 错）。
    *(注：当 $n$ 较大且频次极其极端时，$T_1$ 确实会比 $T_2$ 深得多，但 B 选项的说法太过绝对，没有满足任意 $n$ 的条件)*
