**为什么不需要特殊处理？（代码模拟推演）：**

- **当插入第 1 个结点时：** 此时 `L` 是 `NULL`。执行 `s->next = L;`，也就是 `s->next = NULL;`。这刚好符合第一个结点（也就是未来的尾结点）的特征！然后 `L = s;`，头指针指向了这唯一的结点。完美！
    
- **当插入第 2 个结点时：** 此时 `L` 指向第 1 个结点。执行 `s->next = L;`，新结点的后面连上了第 1 个结点。然后 `L = s;`，头指针转移到了新的第 1 个结点。依然完美！

### 1. 初始化与判空（最基础的区别）

这是最直观的物理结构差异，也是写代码的第一步。

- **【不带头结点】**
    
    - **初始化：** 什么都不用分配，直接让头指针指空。
        
        `LinkList L = NULL;`
        
    - **判空条件：** 头指针本身是不是空。
        
        `if (L == NULL)`
        
- **【带头结点】**
    
    - **初始化：** 必须用 `malloc` 给“第 0 号”兵分配一块真金白银的内存，但里面不存有用数据。
        
        `L = (LNode *)malloc(sizeof(LNode));`
        
        `L->next = NULL;`
        
    - **判空条件：** 头结点的下一个是不是空。
        
        `if (L->next == NULL)`

### 2. 按位置插入（例如在第 $i$ 个位置插入新结点）

假设你要在第 $i$ 个位置插入。核心逻辑都是“找到第 $i-1$ 个结点”。

- **【带头结点】（代码统一，不用分类讨论）**
    
    无论 $i$ 是 1 还是 100，逻辑完全一样。如果 $i=1$，那么 $i-1=0$，正好就是头结点！
    
    C
    
    ```
    // 找第 i-1 个结点 p，哪怕 i=1，p 也是头结点，代码完美运行
    LNode *p = GetElem(L, i-1); 
    s->next = p->next;
    p->next = s;
    ```
    
- **【不带头结点】（必须为 $i=1$ 单独写 if）**
    
    如果不带头结点，且 $i=1$，根本不存在所谓的“第 0 个结点”给你当垫脚石。你必须直接修改头指针 `L` 本身。
    
    C
    
    ```
    if (i == 1) {       // 必须单独处理插在表头的情况！
        s->next = L;    // 新结点的尾巴连上原来的第一个结点
        L = s;          // 头指针 L 改变朝向，指向新结点
        return true;
    }
    // 如果 i != 1，再去按常规逻辑找第 i-1 个结点...
    LNode *p = GetElem(L, i-1);
    // ...
    ```

### 3. 按位置删除（例如删除第 $i$ 个结点）

和插入同理，区别依然爆发在“删除第 1 个元素”时。

- **【带头结点】（干净利落）**
    
    找到第 $i-1$ 个结点 `p`，把 `p` 的后面那个结点删掉就行，哪怕删的是第 1 个，`p` 依然是稳如泰山的头结点。
    
    C
    
    ```
    LNode *p = GetElem(L, i-1);
    LNode *q = p->next;
    p->next = q->next;
    free(q);
    ```
    
- **【不带头结点】（头指针会移位）**
    
    如果删除的是第 1 个结点，头指针 `L` 必须向后退一步，指向原来的第 2 个结点。
    
    C
    
    ```
    if (i == 1) {       // 必须单独处理删除表头的情况！
        LNode *q = L;   // 暂存原来第一个结点的地址，为了后面 free
        L = L->next;    // 头指针 L 直接指向第二个结点
        free(q);
        return true;
    }
    // 如果 i != 1，再去找第 i-1 个结点...
    ```

### 4. 遍历起点的区别

这个区别极小，但写代码时容易手滑写错。我们要用指针 `p` 扫过所有实际存数据的结点：

- **【不带头结点】：** 头指针直接指着第一个数据。
    
    `LNode *p = L;`
    
    `while(p != NULL) { ... p = p->next; }`
    
- **【带头结点】：** 头指针指着废弃的“第 0 号”，我们要从它的下一个开始。
    
    `LNode *p = L->next;`
    
    `while(p != NULL) { ... p = p->next; }`

### 🔥 终极底层考点：函数参数的传递（C++ 引用 `&` 的使用）

这是 408 大题和面试中最容易死得不明不白的地方！

如果你看懂了上面的 2 和 3，你会发现：**不带头结点的链表，在插入和删除第 1 个元素时，头指针 `L` 本身的值（也就是它指向的内存地址）被改变了！**

- **如果不带头结点：** 你的插入/删除函数的参数**必须**带上引用符 `&`（即 `LinkList &L`），或者在 C 语言中用二级指针 `LNode **L`。否则，你在函数内部把 `L` 指向了新结点，函数一结束，外面的 `L` 依然指向老地方，链表直接废掉。
    
- **如果带头结点：** 因为无论怎么增删，头指针 `L` 永远死死指着那个 `malloc` 出来的“第 0 号”头结点，`L` 自身的地址值永远不变，只是它内部的 `L->next` 在变。所以就算你忘了写引用符号 `&`（写成了 `LinkList L`），代码通常也能苟活下来（虽然规范写法还是建议加 `&`）。
