
| 森林遍历            | 对应树的遍历 | 对应二叉树的遍历             | 口诀记忆                  |
| --------------- | ------ | -------------------- | --------------------- |
| **先根遍历 / 先序遍历** | 先根遍历   | **先序遍历 (Pre-order)** | **先对先**（森林先序 = 二叉树先序） |
| **后根遍历 / 后序遍历** | 后根遍历   | **中序遍历 (In-order)**  | **后对中**（森林后序 = 二叉树中序） |


> **思考小测验（你可以尝试在心中回答）：**  
> 为什么森林的**后序**对应二叉树的**中序**，而不是二叉树的后序？  
> (提示：二叉树的中序是“左根右”，左是孩子，根是自己，右是兄弟；处理完所有孩子后才访问根，再访问兄弟，恰好符合森林后序遍历！)





| 写命中     | 写不命中     | 为什么这样配                                    |
| ------- | -------- | ----------------------------------------- |
| **写直达** | **非写分配** | 反正每次写都要写主存，调入 Cache 并不能省下这次写，还白占一行        |
| **写回**  | **写分配**  | 写回靠"多次写合并成一次写回"获益，那就应该让数据先进 Cache，才有合并的机会 |
两种搭配各自内部自洽：**同步得勤就别费劲调块，要靠推迟同步获益就得先把块拿进来**
