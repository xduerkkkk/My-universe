缓冲区技巧：
<span style="background:rgba(173, 239, 239, 0.55)">PV</span>：
第一层：P (empty / full) --> 准入判定：整个系统流水线是否允许我执行？不允许就空手去睡觉，不霸占任何资源。第二层：P (car) --> 工具分配：既然允许执行，分配给我硬件/设备去跑腿。第三层：P (S1 / S2) --> 极短互斥：操作共享存储区/临界区的最后一把保护锁，进门即上锁，出门即开锁。
 先申请专用配额，再申请通用空位

- **规则**：**特化约束优先于泛化约束（物理容量 empty），互斥锁 mutex 永远垫后。**

# 概念易错

## 进程相关概念

<span style="background:rgba(173, 239, 239, 0.55)">内核</span>需要加以保护的操作
1. **绝对属于特权指令的操作**：
    - **关中断**指令（CLI 等，防止抢占）。
    - **修改/设置时钟定时器计数值**（修改定时器寄存器）。
    - **修改控制寄存器 / 页表基址寄存器**（如 x86 的 CR0、CR3，ARM 的 TTBR）。
    - **停机指令**（HLT）。
2. **绝对属于用户态（非特权）的操作**：
    - **读系统时钟**（如读取当前日历时间、RDTSC 读时间戳计数器）。
    - **访管指令 / 陷入指令 / 系统调用指令**（如 INT n、SYSCALL、TRAP）。
3. **关于内存保护的标准定论**：
    - 用户态<font color="#ff0000">访问内核空间（**无论读还是写**）</font>，均受硬件 MMU 的特权级检查保护，非法访问必报异常。


<span style="background:rgba(173, 239, 239, 0.55)">PCB</span>
凡是「撤销这个进程时必须一并回收或关闭」的东西，都要在 PCB 里留有登记，否则进程一没就成了无主资源。打开文件表正是这类登记，所以它属于 PCB。
信号量是**全系统共享**的同步机构，自带一个整型值和一个等待队列，由内核统一维护，多个进程共用同一个。PCB 里至多记录「本进程当前在等哪个信号量」的指针，信号量本身不属于任何一个进程的私有数据。

<span style="background:rgba(173, 239, 239, 0.55)">进程通信：</span>
匿名管道半双工，双向通信要两根
send/receive 是系统调用，数据经内核缓冲区两次拷贝


<span style="background:rgba(173, 239, 239, 0.55)">信号量：</span>
$$\text{要想能唤醒别人} \implies \text{此前必定有人在队列里排队} \implies \text{执行 V 之前 } S.value \text{ 必定 } \le -1$$

既然执行前是一个负数（$\le -1$），**执行 V 操作仅仅是做了一次加 1（$+1$）**：
$$\text{执行后的值} = (\le -1) + 1 \ \implies \ \mathbf{\le 0}$$

因此，不论是互斥信号量还是资源信号量，**只要题目出现了“唤醒”两个字，执行 V 操作后的值 $\le 0$** 

调度，调用，IO，中断
 - 进程 P 是在**内核代码的中间**（系统调用路径内检查到队满）被置为阻塞态并让出 CPU 的。
    - 现场保存在 P 的**内核栈**中。
    - 唤醒并被调度后，CPU 直接在**内核态**恢复执行，从当时挂起的那一行代码接着往下跑，把字符写入刚腾出的空位，随后返回用户态。**不需要、也不会让 P 先回用户态重新发起一次系统调用。**

## 段页
cache 完全硬件，
但段页是硬件+OS，OS 体现在缺页时，要切换进程
但 cache 和段页对程序员都是透明的


**四类页表项标志位的"主体 × 时机 × 用途" 全表**：

| 标志位              | 由谁置位 / 何时置位                             | 由谁读取 / 何时读取                               | 经典用途             |
| ---------------- | --------------------------------------- | ----------------------------------------- | ---------------- |
| **有效位 V**        | OS：装入页时置 1、换出时清 0                       | MMU：每次地址翻译先检查 V；V = 0 触发缺页中断              | 区分"在内存" vs "在外存" |
| **修改位 M（dirty）** | **硬件**：写操作完成时自动置 1                      | OS：换出该页时读 M——若 M = 1 必须回写外存，M = 0 可直接丢弃   | **节省回写 I/O**     |
| **引用位 R**        | **硬件**：任何成功访问（读或写）该页时自动置 1              | OS：置换算法（Clock / 二次机会 / LRU 近似）周期性扫描 + 清 0 | 提供"近期是否使用" 的衰减信号 |
| **保护位 P**        | OS：建立页表时按段属性写入（如代码段 → 只读+可执行，数据段 → 可读写） | MMU：每次访问按访问类型核对；不匹配触发保护异常                 | 防止越权写代码段、跨越内核空间  |



## 文件



* **目录的本质**：目录是一种特殊的文件。它同样由一个 inode 管理（例如根目录固定为 inode 2），它的 inode 指向数据区中的几个簇。
* **目录的内容**：目录的数据簇里存的不是 inode，而是**目录项（Directory Entry）列表**。
* 每个目录项只有最核心的两个字段：
  $$\text{目录项} = (\text{文件名},\ \text{对应文件的 inode 编号})$$
* **查找机制**：
  如果主目录下有一个文件 `a.txt`，主目录的数据簇里只记录：`("a.txt", 1024)`。操作系统拿着编号 `1024`，直接通过数学公式计算偏移量：
  $\text{磁盘物理地址} = \text{inode区基址} + 1024 \times 64\text{ B}$
  从而到磁盘 inode 区直接抓取对应的 inode。




超级块（文件系统元数据）、根目录的 inode 会常驻内存。

内存是有内存的 inode 区、系统打开表、进程打开表

从未打开过文件也能修改引用计数器，
- **内存 Inode** 维护的是“文件的静态元数据”。凡是需要查看、修改文件属性（如硬链接数、文件权限、大小）的操作，都会把 Inode 调入内存，这些操作与“打开文件”无关。

**只要物理簇是连续的，任何文件分配方式在磁头寻道上都能获得巨大的速度提升**
因为簇是在物理磁盘上的，要寻道的！

### 访盘次数

访问路径 /A/b 的访盘次数
1. **第 1 次访盘**：根据已在内存的根目录 inode，从磁盘数据区读取**根目录的数据块**（拿到 A 的 inode 编号）。
    
2. **第 2 次访盘**：从磁盘 inode 区读取 **A 的 inode**（拿到 A 的数据块地址）。
    
3. **第 3 次访盘**：从磁盘数据区读取 **A 的数据块**（拿到 b 的 inode 编号）。
    
4. **第 4 次访盘**：从磁盘 inode 区读取 **b 的 inode**（拿到 b 的数据块地址）。
    
5. **第 5 次访盘**：根据 b 的直接地址项，从磁盘数据区读取 **b 的第 1 个数据块**（读到文件内容）。

- **形式 1（考察最基础机制，如本题背景）**：
    
    - **题干描述**：“假设文件系统的根目录索引节点已调入内存，其余信息均在磁盘上”。
        
    - **解法**：严格按照你刚才推导的 5 步走，**读根目录的数据块必须算 1 次访盘**。
        
- **形式 2（考察引入了“当前工作目录”机制）**：
    
    - **题干描述**：“若当前工作目录为 /A，且其索引节点和目录文件已在内存中，访问文件 b 需要几次访盘？”
        
    - **解法**：此时查找 b 的 inode 编号直接在内存进行（0 次访盘），只需读 b 的 inode（1 次）+ 读 b 的数据块（1 次），共 **2 次访盘**。
        
- **形式 3（考察文件打开操作）**：
    
    - **题干描述**：“进程已经成功执行了 open ("/A/b", ...)，随后执行 read () 读取第 1 个块，需要几次访盘？”
        
    - **解法**：open 成功意味着文件 b 的 inode 已经在内存的“系统打开文件表”中了。此时执行 read () **只需 1 次访盘**（直接读数据块）。



### 打开表

“本质上读写指针就在系统表项里，只是独立 open 会产生多个系统表项，而 fork 共享同一个系统表项；但如果题目只让你背概念，它问的是恐龙书抽象出来的‘逻辑归属’，此时要答在进程表。”


 场景 1：两个独立进程分别 open () 打开同一个文件 test. txt

6. 进程 1 调用 open ()：内核在系统表创建【表项 A】，offset = 0；
    
7. 进程 2 调用 open ()：内核在系统表**再创建【表项 B】**，offset = 0；
    
8. 【表项 A】和【表项 B】各自维护独立的 offset，但它们底层的 inode 指针指向同一个内存 inode；
    
9. **现象**：两个进程**各自拥有独立的读写偏移量**，互不干扰；对应 B 选项前半句“共享同一个表项”是错误的。
    

场景 2：进程 1 调用 open () 后，执行 fork () 创建子进程（本题 C 选项）

1. 父进程调用 open ()，系统表中生成【表项 A】（引用计数 = 1）；
    
2. 父进程调用 fork ()，子进程复制父进程的 PCB（复制了“进程打开文件表”）；
    
3. 此时，父进程的 fd=3 和子进程的 fd=3 **指向系统表里的同一个【表项 A】**（引用计数变成 2）；
    
4. **现象**：父进程读写移动了【表项 A】中的 offset，子进程下一次读写时直接看到被移动后的 offset。**父子进程共享同一个系统表项，因而共享读写偏移量**。这就是 C 选项完全正确的原因。
