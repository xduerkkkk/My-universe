# 概念易错

## 进程相关概念

凡是「撤销这个进程时必须一并回收或关闭」的东西，都要在 PCB 里留有登记，否则进程一没就成了无主资源。打开文件表正是这类登记，所以它属于 PCB。
信号量是**全系统共享**的同步机构，自带一个整型值和一个等待队列，由内核统一维护，多个进程共用同一个。PCB 里至多记录「本进程当前在等哪个信号量」的指针，信号量本身不属于任何一个进程的私有数据。

<span style="background:rgba(173, 239, 239, 0.55)">进程通信：</span>
匿名管道半双工，双向通信要两根
send/receive 是系统调用，数据经内核缓冲区两次拷贝


<span style="background:rgba(173, 239, 239, 0.55)">信号量：</span>
$$\text{要想能唤醒别人} \implies \text{此前必定有人在队列里排队} \implies \text{执行 V 之前 } S.value \text{ 必定 } \le -1$$

既然执行前是一个负数（$\le -1$），**执行 V 操作仅仅是做了一次加 1（$+1$）**：
$$\text{执行后的值} = (\le -1) + 1 \ \implies \ \mathbf{\le 0}$$

因此，不论是互斥信号量还是资源信号量，**只要题目出现了“唤醒”两个字，执行 V 操作后的值 $\le 0$** 


## 段页


**四类页表项标志位的"主体 × 时机 × 用途" 全表**：

| 标志位              | 由谁置位 / 何时置位                             | 由谁读取 / 何时读取                               | 经典用途             |
| ---------------- | --------------------------------------- | ----------------------------------------- | ---------------- |
| **有效位 V**        | OS：装入页时置 1、换出时清 0                       | MMU：每次地址翻译先检查 V；V = 0 触发缺页中断              | 区分"在内存" vs "在外存" |
| **修改位 M（dirty）** | **硬件**：写操作完成时自动置 1                      | OS：换出该页时读 M——若 M = 1 必须回写外存，M = 0 可直接丢弃   | **节省回写 I/O**     |
| **引用位 R**        | **硬件**：任何成功访问（读或写）该页时自动置 1              | OS：置换算法（Clock / 二次机会 / LRU 近似）周期性扫描 + 清 0 | 提供"近期是否使用" 的衰减信号 |
| **保护位 P**        | OS：建立页表时按段属性写入（如代码段 → 只读+可执行，数据段 → 可读写） | MMU：每次访问按访问类型核对；不匹配触发保护异常                 | 防止越权写代码段、跨越内核空间  |



## 文件
内存是有内存的 inode 区、系统打开表、进程打开表
从未打开过文件也能修改引用计数器，
- **内存 Inode** 维护的是“文件的静态元数据”。凡是需要查看、修改文件属性（如硬链接数、文件权限、大小）的操作，都会把 Inode 调入内存，这些操作与“打开文件”无关。
