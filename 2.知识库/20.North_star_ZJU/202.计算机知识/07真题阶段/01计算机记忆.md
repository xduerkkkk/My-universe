## 图
「没有顶点」的结构不在图的定义域内。

**图的定义里，「顶点必须有、边可以没有」是一条硬规定**；而「稀疏 / 稠密」「大图 / 小图」这类词全是相对描述，凡是给它们编出一条精确阈值的选项，基本都可以直接划掉。


1. **有向图保证强连通的最小边数**：
   先让 $n-1$ 个顶点构成完全有向图，再让第 $n$ 个点提供 $n-1$ 条单向出边（最坏情况非强连通），最后加 1 条边：
   $$\begin{aligned}
   E_{\min} &= (n-1)(n-2) + (n-1) + 1 \\
   &= (n-1)^2 + 1
   \end{aligned}$$
   代入 $n = 4$：
   $E_{\min} = (4 - 1)^2 + 1 = 3^2 + 1 = \mathbf{10}$

2. **对比：无向图保证连通的最小边数**：
   先让 $n-1$ 个顶点构成完全无向图，第 $n$ 个点完全不连（最坏情况不连通），最后加 1 条边：
   $E_{\min} = C_{n-1}^2 + 1 = \frac{(n-1)(n-2)}{2} + 1$

## 数

计算机底层的 ALU 加法器在完成一次运算（以 32 位为例，产生 32 位结果 $R$）后，会**无条件同时生成**以下 4 个标志位。ALU 不知道程序员看作有符号数还是无符号数，如何解读完全取决于后续的跳转指令（如 `ja` / `jb` 看无符号，`jg` / `jl` 看有符号）。

|  标志位   |         英文全称         |     适用数据类型     | 核心判定规则                                                                                                                                                                                     |
| :----: | :------------------: | :------------: | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ZF** |   Zero Flag (零标志)    |  有符号 / 无符号通用   | **当结果所有位全为 0 时，$\text{ZF} = 1$；否则 $\text{ZF} = 0$**。                                                                                                                                       |
| **SF** |   Sign Flag (符号标志)   | **仅对有符号整数有意义** | **直接等于结果的最高位（MSB/符号位）**：$\text{SF} = R_{31}$。最高位为 1 则 $\text{SF}=1$（负数），最高位为 0 则 $\text{SF}=0$（正数）。                                                                                        |
| **OF** | Overflow Flag (溢出标志) | **仅对有符号整数有意义** | 结果超出了补码能表示的范围（$-2^{31} \sim 2^{31}-1$）。<br>1. **逻辑判断**：同号相加产生异号结果，即“正+正=负”或“负+负=正”。<br>2. **硬件判断**：最高位进位与次高位进位异或：$\text{OF} = C_{31} \oplus C_{30}$。                                       |
| **CF** | Carry Flag (进位/借位标志) | **仅对无符号整数有意义** | 针对无符号整数溢出：<br>1. **加法（产生进位）**：$\text{CF} = 1 \iff$ 两个无符号数相加和超过 $2^{32}-1$（即 $C_{\text{out}}=1$）。<br>2. **减法（产生借位）**：$\text{CF} = 1 \iff$ 被减数 $<$ 减数（小数减大数不够减，向更高位借位，即 $C_{\text{out}}=0$）。 |
$$\text{减法时的 } \text{CF} = \overline{C_{\text{out}}} \quad (\text{或者写为 } \text{CF} = \text{Sub} \oplus C_{\text{out}})$$
* 当小减大时，加法器产生 $C_{\text{out}} = 0$，经过一个非门取反，得到 **$\text{CF} = 1$（产生借位）**。
* 当大减小时，加法器产生 $C_{\text{out}} = 1$，取反得到 **$\text{CF} = 0$（无借位）**。


|   加数符号    | 次高位进位 $C_{\text{in}}$ | 最高位进位 $C_{\text{out}}$ | 符号位最终结果 |         实际含义          | $OF = C_{\text{in}} \oplus C_{\text{out}}$ |
| :-------: | :-------------------: | :--------------------: | :-----: | :-------------------: | :----------------------------------------: |
| **正 + 正** |           0           |           0            |    0    |     正 + 正 = 正，正常      |                 **0（无溢出）**                 |
| **正 + 正** |           1           |           0            |    1    |  正 + 正 = 负，数值位顶破符号位   |                 **1（正溢出）**                 |
| **负 + 负** |           1           |           1            |    1    |     负 + 负 = 负，正常      |                 **0（无溢出）**                 |
| **负 + 负** |           0           |           1            |    0    | 负 + 负 = 正，数值位太小未抵消符号位 |                 **1（负溢出）**                 |

浮点数舍入：
- 移出的最高位为 0：直接截断（舍去）。
- 移出的最高位为 1，且后面还有非 0 位（大于一半）：最低位加 1（进位）
- 移出的最高位为 1，后面全是 0（正好等于一半）：
    - 若保留部分的最低位是 0（偶数）：舍去。
    - 若保留部分的最低位是 1（奇数）：最低位加 1（向偶数靠拢，使得最低位变 0）。

**Cache-主存系统的效率（$e$）** 定义为：**访问 Cache 的时间与整个系统的平均访问时间之比**。

$$e = \frac{t_c}{t_a} \times 100\%$$

其中：
* $t_c$：Cache 的存取周期（即系统处于最理想状态、命中率 100% 时的访问时间）。
* $t_a$：系统的平均访问时间（Average Access Time）。
* 效率 $e$ 的取值范围为 $(0, 1]$，越接近 1，说明存储系统的性能越接近 Cache 的速度。

加速比（Speedup, $S$）
* **公式**：
  $$S = \frac{t_m}{t_a}$$
* **物理意义**：引入 Cache 后的平均访问时间，相比**完全没有 Cache 纯靠主存**时的加速倍数。因为主存单次访问时间是 $t_m$，所以是以 $t_m$ 为基准比较。

| :--- | :--- | :--- | :--- |

| **`jl` / `jnge`** | Jump if Less | 小于（$<$） | $\mathbf{SF \neq OF}$ |
| **`jle` / `jng`** | Jump if Less or Equal | 小于等于（$\le$） | $\text{ZF} = 1 \text{ 或 } \mathbf{SF \neq OF}$ |

> **关键机制硬核拆解（SF 与 OF 的关系）**：
> 做减法 $\text{dest} - \text{src}$ 时：
> * 若没有发生溢出（$\text{OF} = 0$），结果为负（$\text{SF}=1$）代表确实小于，$\text{SF} \neq \text{OF}$ 成立。
> * 若发生正溢出（两负数相减得到负极大超界变为正，$\text{OF} = 1$ 且 $\text{SF} = 0$），本质仍然是小于，$\text{SF} \neq \text{OF}$ 依然成立。
> * **结论**：只要 $\mathbf{SF \neq OF}$，有符号数的大小关系就必定是**小于**。这是 408 计组考题中最容易涉及硬件逻辑设计的考点。

## 中断

陷入指令，进入内核态，进入的是“进程的内核态”，所以此不能说此进程因为进入内核态阻塞

中断服务程序的最后一条指令必须是**中断返回指令（如 IRET / RTI）**，绝不能是普通的无条件转移指令（如 JMP）


| 策略组合            | 含义与机制                                                                                                    |
| --------------- | -------------------------------------------------------------------------------------------------------- |
| **固定分配 + 局部置换** | 每个进程在运行前分配固定数量的页框（固定分配），缺页时只能从**自己已有的页框**中挑一个淘汰出去换入新页（局部置换），进程拥有的物理页框总数自始至终不变。                           |
| **可变分配 + 全局置换** | 进程分到的页框数可动态改变。缺页时，OS 从**系统的空闲物理页框队列**中直接拿一个分配给它；若空闲队列没了，OS 会在**全系统的其他进程**中随意挑一个页框抢过来（全局置换）。              |
| **可变分配 + 局部置换** | 缺页时**只能淘汰该进程自己内部的页框**。但 OS 会根据该进程近期的**缺页率（PFF）或工作集（Working Set）**动态调整其拥有的页框配额（缺页率高则多分几个页框，缺页率极低则回收多余页框）。 |

1. **TCP 的处理机制（传输层切片）**：
   - TCP 是**面向字节流**的。
   - TCP 在传输层就会把这 10MB 的应用层数据切成一块块不超过 **MSS（通常 1460 字节）** 的 TCP 报文段分别发送。
   - 到达 IP 层时，每个 IP 数据报大小都在 1500 字节以内，**IP 层不需要分片**。
2. **UDP 的处理机制（网络层分片）**：
   - UDP 是**面向报文**的，应用层给多大，UDP 就原封不动加上 8 字节首部扔给 IP 层。
   - 如果应用层塞给 UDP 一个 4000 字节的数据，加上 UDP 首部共 4008 字节。
   - IP 层发现 $4008 > 1500$（超过 MTU），**必须在网络层进行 IP 分片（Fragmentation）**，拆分成 3 个 IP 分片在链路上传输。

- **机制**：TCP 首部中，“源端口号”和“目的端口号”字段的位宽均为 **16 位（16 bit）**。
- **数值边界**：16 位二进制能表示的数值范围是 $0 \sim 2^{16}-1$，即 $0 \sim 65535$。因此，一台主机上的 TCP 端口号总数最多只有 **65536 个**（其中 0 号通常保留，1 到 1023 为熟知端口，1024 到 49151 为登记端口，49152 到 65535 为客户端动态/临时端口）。
一台主机能同时存活的理论 TCP 连接数取决于不同 IP 和端口的组合排列，理论上限极其庞大，实际仅受限于操作系统的**内存大小、文件描述符（File Descriptor）上限和内核缓冲区**等系统资源，**远远不止 65536 条**。

网卡编码调制传输介质所需的物理信号，接收端通过以太网帧头部的 8 字节前导码（7 字节同步码 10101010... + 1 字节帧开始定界符 SFD 10101011），锁定发送方的时钟频率与相位，实现**位同步**。，

**退避窗口（CW, Contention Window）**：
   - 节点随机从区间 $[0, \text{CW}-1]$ 中选取一个整数 $r$，退避时间 $= r \times \text{SlotTime}$（时隙时间）。
   - 初始时 $\text{CW} = \text{CW}_{\min}$（例如 16 或 32）。
   - 如果发送失败（未在超时时间内收到 ACK），认为发生冲突，CW 翻倍（$\text{CW} = 2 \times \text{CW}$），直到上限 $\text{CW}_{\max}$（通常为 1024）。
   - 发送成功并收到 ACK 后，CW 立即重置为 $\text{CW}_{\min}$。
