**全篇统一约定**：按字节编址，`int=4B`，数组按行优先连续存放；每个方案／小问独立从空数据 Cache 开始，除非题目明确两遍之间不清空。只统计题中数组访问，循环变量、sum 等在寄存器中；读缺失装整块，组相联采用标准 LRU，命中更新次序。写策略以各题为准；不计预取、编译器消除或合并访存，也不把写回／直写产生的主存流量当作额外的 CPU Cache 访问。

## 一、每题固定写这四步

```text
① 定硬件：C=__B，B=2^__B，L=C/B=__，E=__路，S=L/E=__。
           校验 S×E×B=C；每块 __ 个 int；同组地址步长 S×B=__B。
② 翻代码：每轮按顺序 R/W=__，总访问数 N=__。
           元素地址=__，真实主存块号 q=⌊地址/B⌋，组号 g=q mod S。
③ 接状态：首轮缺 __；轮末各关键组 [最旧,…,最新]=__。
           下次用它前，谁会把它换掉？换段那一轮的 H/M=__。
④ 按问法收口：M=__；缺失率 M/N=__，或命中率 1−M/N=__。
```

`C` 只取数据区容量，`L` 是总行数，`E` 是路数，`S` 是组数，`N` 专门留给访问次数。直接映射按 `E=1` 算。问地址位宽时，再写：块内偏移 `log₂B`、组号 `log₂S`、Tag＝地址位数减去前两项。

### 第二步具体怎么落笔

- `a[i]+=1`：写成 `R(a[i]) → W(a[i])`，不是一次访问。`sum+=a[i]` 中的 `sum` 若在寄存器，只算一次数组读。
- 二维数组 `a[R][D]`：`地址=A+4(rD+c)`，**先代入行列，再除块大小**。不要把数组一行天然看成一个块。
- 结构体：先写 `sizeof` 和字段偏移；字段地址＝`A+k×sizeof+字段偏移`。
- 连续访问整段字节时，不同块数＝`⌊末字节地址/B⌋−⌊首字节地址/B⌋+1`。跳步访问或只取字段，要数真正访问到的块，不能把中间没碰的块算进去。

### 第三步只问这三个问题

1. **是否真的装进来了？** 读缺失装块；写缺失要看写分配策略。空 Cache 起步的纯写＋不写分配，才可直接判每笔写都缺失。前面若已有读装块，后面的写仍可能命中。
2. **回来前，同组发生了什么？** 标准 LRU 下，从某块上一次访问之后开始，若访问了至少 `E` 个同组的其他不同块，而且这些访问会装块或更新 LRU，它就被挤走了。只命中别的组，不影响它；不写分配的写缺失也不会把它挤走。
3. **能不能乘？** 先看各组是否相同，再看每轮的块序列是否相同。首轮单算；换段轮接上旧状态单算；确认进入重复状态后才乘。**轮初在，不等于轮到它时还在。**

> [!warning] 保留原模式，但不套过头
> - “同组块数大于路数，所以全缺”只适用于相应组里反复同序循环、满足 LRU 条件的情形；不能据此断言整题全缺。
> - 数组总容量大于 Cache，不等于每次都缺；小于 Cache，也不保证没有同组冲突。
> - 冷启动时，若统计全部访问，`不同访问块数≤M≤N`。若只问读或只问写，分子、分母一起筛选，不能直接套这个下限。

## 二、带提示练起手

### 01｜非块对齐的一维读改写&

32 位字节地址；Cache 数据区 `2KiB`、块 `32B`、2 路、写分配。`int a[90]` 首址 `0x0010000C`。

```c
for (int i=0; i<90; i++) a[i] += 1;
```

求地址的 Tag／组号／块内偏移位数、总访问次数、缺失次数和**命中率**。

**落笔要求**：① 写出幂次与闭环；② 写 `R→W`，算首、末字节块号；③ 说明同一块内为什么不用逐元素模拟；④ 最后回答命中率。

> [!faq]- 01 核对｜先查第一处与你草稿不同的步骤
> 1. **定硬件**：`C=2¹¹B，B=2⁵B，L=64，E=2，S=32=2⁵`；`32×2×32=2048B`。每块 8 个 int，同组步长 `1024B`。位数为 **Tag 22、组号 5、偏移 5**。
> 2. **翻代码**：每轮一读一写，`N=180`。首址块内偏移 `12B`，末字节相对首块起点的偏移为 `12+90×4−1=371`。因此涉及 `⌊371/32⌋+1=12` 个块；真实块号从 `32768` 到 `32779`。
> 3. **接状态**：每块第一次读缺失后装入，紧接着的写及同块后续读写都命中；用完一块才向后走，没有别的数组插队。故 `M=12`，不是 90，也不是 24。
> 4. **收口**：命中率 `1−12/180=14/15`。检查 `12≤M≤180`；这题问的不是缺失率。

### 02｜代码改成纯写，流程哪一步改变

沿用 01 的硬件、数组长度和首址。以下三问**各自从空 Cache 开始**：

- A：代码为 `a[i]=0`，写分配。
- B：代码为 `a[i]=0`，不写分配。
- C：代码为 `a[i]+=1`，不写分配；每轮仍按先读、后写执行。

分别求全部数组访问的**缺失次数和缺失率**。

**落笔要求**：每问都写出 `N`；第三步说清“第一笔缺失是否装块，第二笔来时块在不在”。

> [!faq]- 02 核对｜不写分配不是“所有写都缺失”
> 1. **定硬件**：仍是 `L=64，E=2，S=32`，实际涉及 12 个块。
> 2. **翻代码**：A、B 每元素只写一次，`N=90`；C 每元素读写各一次，`N=180`。
> 3. **接状态**：A 每块首写缺失并装块，后续同块写命中；B 没有读来装块，写缺失也不装块，Cache 始终为空；C 每块首读缺失装块，后面的写已经命中，不会触发“不写分配”。
> 4. **收口**：A **12 次，`2/15`**；B **90 次，`1`**；C **12 次，`1/15`**。A、C 缺失数相同，分母不同。

### 03｜按列纯写：只改行数、行长或写策略

Cache 数据区 `128B`、块 `16B`、2 路。数组首址 `0x0`，只访问每行前 4 列：

```c
// 数组声明为 int m[n][D]
for (int c=0; c<4; c++)
    for (int r=0; r<n; r++) m[r][c] = 0;
```

分别求缺失次数：A `n=2,D=16`、写分配；B `n=3,D=16`、写分配；C `n=3,D=16`、不写分配；D `n=3,D=20`、写分配。

**落笔要求**：不能只写 `K`。先列首列真实块号与组号，再留下首列结束的组内状态；D 不能沿用 B 的组号。

> [!faq]- 03 核对｜同组还是不同组，取决于行长除以块大小
> 1. **定硬件**：`B=2⁴B，L=8，E=2，S=4`，同组步长 `64B`，每块 4 个 int。
> 2. **翻代码**：每轮纯写，A 的 `N=8`，其余 `N=12`。`D=16` 时行长 `64B=4` 块，前 4 列每列的块序列为 `0,4` 或 `0,4,8`，组号全为 0。D 的行长为 `80B=5` 块，块序列为 `0,5,10`，组号为 `0,1,2`。
> 3. **接状态**：A 首列组 0 留下 `[0,4]`，后面全中；B 留下 `[4,8]`，下一列的 `0,4,8` 依次缺失并回到 `[4,8]`；C 写缺失不装块，组 0 一直 `[]`；D 三块分到三个组，各组只放一块，首列后都留得住。
> 4. **收口**：A **2**；B **12**；C **12**；D **3**。B 和 C 答案相同，但 B 是反复换掉，C 是从未装入。

## 三、减少提示，但四步一行也不能省

### 04｜同一个数组，按行与按列

Cache 数据区 `128B`、块 `16B`、2 路。`int a[10][4]` 首址 `0x0`。

```c
// A
for (int c=0; c<4; c++)
    for (int r=0; r<10; r++) sum += a[r][c];
// B
for (int r=0; r<10; r++)
    for (int c=0; c<4; c++) sum += a[r][c];
```

分别求缺失率。**必须留下：四个组各自包含哪些块、A 的首列末状态、A 后续每列缺几次。**

> [!faq]- 04 核对｜不要拿最拥挤的一组代表全体
> 1. **定硬件**：`L=8，E=2，S=4`，一块 4 个 int。
> 2. **翻代码**：两问均 `N=40`。每行正好一块，行 `r` 对应块 `r`。A 每列访问 `0…9`；B 连续读同块的 4 个元素后才换块。
> 3. **接状态**：A 的四组分别是 `0,4,8｜1,5,9｜2,6｜3,7`。首列缺 10 次，轮末为 `[4,8]｜[5,9]｜[2,6]｜[3,7]`。前两组各有 3 块抢 2 路，后续每列各缺 3 次；后两组都能留住，后续全中。因此后续每列只缺 **6 次**，不是 10 次。B 每块只在第一次访问时缺失。
> 4. **收口**：A `M=10+3×6=28`，缺失率 **`7/10`**；B `M=10`，缺失率 **`1/4`**。

### 05｜两遍读改写：第二遍正向或反向

Cache 数据区 `128B`、块 `16B`、2 路。`int a[40]` 首址 `0x0`，采用写分配。

两方案的第一遍都从 `i=0` 到 `39` 执行 `a[i]+=2`；第二遍执行同一句，A 仍从 `0` 到 `39`，B 从 `39` 倒到 `0`。两遍之间不清 Cache。

分别求两方案全部数组访问的缺失率。**必须留下：第一遍末各组的 LRU 顺序；第二遍组 0 的块访问顺序和 H/M。**

> [!faq]- 05 核对｜块集合一样，不代表下一遍缺失数一样
> 1. **定硬件**：`L=8，E=2，S=4`，每块 4 个 int。
> 2. **翻代码**：两遍、40 元素、每元素一读一写，`N=2×40×2=160`。第一遍依次用完块 `0…9`。
> 3. **接状态**：第一遍缺 10 次，轮末 `[4,8]｜[5,9]｜[2,6]｜[3,7]`。A 第二遍组 0 按 `0,4,8` 访问，块的首次读为 `MMM`；组 1 同样缺 3 次，其余组全中，第二遍共缺 6 次。B 组 0 改为 `8,4,0`，首次读为 `HHM`；先命中 4 会把它挪为最新，装入 0 时换掉的是 8。组 1 也只缺 1 次，其他组全中，第二遍共缺 2 次。块内的后续读写都命中。
> 4. **收口**：A `M=16`，缺失率 **`1/10`**；B `M=12`，缺失率 **`3/40`**。反向没有减少访问次数，只改变了复用顺序。

### 06｜跨数组：每轮三笔，组号重新算

Cache 数据区 `128B`、块 `16B`，写分配。`int a[12],b[12],c[12]` 的首址分别是 `0x00,0x80,0x110`。

```c
// 明确按 R(a[i]) → R(b[i]) → W(c[i]) 执行
for (int i=0; i<12; i++) c[i] = a[i] + b[i];
```

A：直接映射；B：2 路；C：2 路，且仅把 `c` 首址改成 `0x100`。

分别求**全部访问的缺失次数**，以及**只统计写访问时的缺失率**。必须留下 `i=0、4、8` 的块号与组号。

> [!faq]- 06 核对｜映射方式一改，组数也跟着改
> 1. **定硬件**：`L=8`。A `E=1,S=8`；B、C `E=2,S=4`。不能保留旧组数只改路数。
> 2. **翻代码**：全部访问 `N=12×3=36`；只看写则 `N_W=12`。A、B 的三段块号为 `(0,8,17)、(1,9,18)、(2,10,19)`，组号均依次为 `(0,0,1)、(1,1,2)、(2,2,3)`。C 的第三块分别改为 `16、17、18`，于是每段三块全部同组。
> 3. **接状态**：A 每段 a、b 互踢，4 轮共缺 `4×2` 次；c 在另一行，每段仅首写缺 1 次，因此每段 9 次。虽然前一段 c 可能被下一段挤走，但它已经不用了。B 每段 a、b 同组共存，c 在另一组，每段只缺 3 次。C 每段三块循环抢两路，LRU 下 4 轮的三笔全缺。
> 4. **收口**：全部缺失 A **27**、B **9**、C **36**；其中写缺失分别为 **3、3、12**，故只统计写的缺失率为 **`1/4、1/4、1`**。不能把 27 除以 12，也不能把写缺失 3 除以全部访问 36。

### 07｜结构体与循环合并：先算字段地址

Cache 数据区 `128B`、块 `16B`、2 路。`p[10]` 首址 `0x0`，字段按以下顺序紧排，无额外填充。

```c
struct Node { int x, y, pad[2]; } p[10];
// A：写分配
for (int k=0; k<10; k++) p[k].x=1;
for (int k=0; k<10; k++) sum+=p[k].y;
// B：写分配
for (int k=0; k<10; k++) {
    p[k].x=1;
    sum+=p[k].y;
}
```

求 A、B 的缺失次数；若 B 改为不写分配，又是多少？**必须留下：`sizeof`、两个字段的地址、A 第一遍末状态。**

> [!faq]- 07 核对｜分开两遍不一定全缺，合并也不一定只缺一次
> 1. **定硬件**：`L=8，E=2，S=4`。
> 2. **翻代码**：`sizeof(Node)=16B`，`x` 地址 `16k`、`y` 地址 `16k+4`，同在块 `k`；未访问 pad。三问均 `N=10+10=20`。
> 3. **接状态**：A 首遍写缺 10 次，轮末 `[4,8]｜[5,9]｜[2,6]｜[3,7]`；第二遍同序读，前两组各缺 3 次，后两组全中，再缺 6 次。B 写分配使每次首写把块带入，紧随其后的读命中；改不写分配后，每块先写缺失不装块，后读又缺失，由读装块，两笔都缺。
> 4. **收口**：A **16**；B **10**；B 不写分配 **20**。不要把“总共 10 个块超过 8 行”直接译成“第二遍 10 次全缺”。

## 四、闭卷复测：不再告诉你在哪一步设陷阱

### 08｜错位的二维数组，两种映射

Cache 数据区 `64B`、块 `16B`。`int a[6][4]` 首址 `0x28`。

```c
for (int c=0; c<4; c++)
    for (int r=0; r<6; r++) sum += a[r][c];
```

A：直接映射；B：2 路 LRU。分别求每列缺失次数和总缺失率。**按四步独立做；在块序列变化的那一列，逐笔写 H/M 和状态。**

> [!faq]- 08 核对｜你写的是实际访问前的状态，还是列开始时的状态？
> 1. **定硬件**：`L=4`。A `E=1,S=4`；B `E=2,S=2`；每块 4 个 int。
> 2. **翻代码**：`N=24`；首址 `0x28=2×16+8`，行长 `16B`。`q=⌊(40+16r+4c)/16⌋`。`c=0,1` 每列为 `2,3,4,5,6,7`；`c=2,3` 为 `3,4,5,6,7,8`。
> 3. **接状态 A**：首列缺 6，第二列缺 4。第二列末按行 `0,1,2,3` 为 `[4,5,6,7]`。换段列逐笔是 `3→M、4→H、5→H、6→H、7→M、8→M`：首笔 3 已把 7 踢走，不能把 7 也算命中。列末 `[8,5,6,7]`；末列缺 4。
>    **接状态 B**：首两列各缺 6；第二列末组 0 `[4,6]`、组 1 `[5,7]`。换段列：3 缺失使组 1 成 `[7,3]`；4 命中使组 0 成 `[6,4]`；5 缺失使组 1 成 `[3,5]`；6 命中使组 0 成 `[4,6]`；7 缺失使组 1 成 `[5,7]`；8 缺失使组 0 成 `[6,8]`。故是 `MHMHMM`，缺 4；末列两组各三块抢两路，全缺 6。
> 4. **收口**：A 各列 **`6,4,3,4`**，`M=17`，缺失率 **`17/24`**；B 各列 **`6,6,4,6`**，`M=22`，缺失率 **`11/12`**。总容量固定时，改路数也改组数，不保证这一段访问一定更少缺失。

### 09｜行长不是整数块，还能不能沿用模板

Cache 数据区 `64B`、块 `16B`、直接映射。`int a[5][5]` 首址 `0x0`。

```c
for (int c=0; c<5; c++)
    for (int r=0; r<5; r++) sum += a[r][c];
```

求每列缺失次数和总缺失率。**仍然只写同样四步，但五列都要写真实块号，不能假定前几列序列相同。**

> [!faq]- 09 核对｜公式不变，不能再用“行号就是块号”
> 1. **定硬件**：`L=4，E=1，S=4`，校验 `4×1×16=64B`。
> 2. **翻代码**：`N=25`；每行 `20B`，不是整数块。必须用 `q=⌊(20r+4c)/16⌋=⌊(5r+c)/4⌋`。五列块序列依次为 `0,1,2,3,5`；`0,1,2,4,5`；`0,1,3,4,5`；`0,2,3,4,5`；`1,2,3,4,6`。
> 3. **接状态**：按 Cache 行 `0,1,2,3` 记录。首列 `MMMMM`，末状态 `[0,5,2,3]`。第二列 `HMHMM`，末状态 `[4,5,2,3]`；第三列 `MMHMM`，末状态仍 `[4,5,2,3]`；第四列 `MHHMH`，末状态仍相同；第五列 `MHHHM`，末状态 `[4,1,6,3]`。注意：末状态相同，不代表不同访问序列下的缺失数相同。
> 4. **收口**：各列 **`5,3,4,2,2`**；`M=16`，缺失率 **`16/25`**。实际访问了块 `0…6` 共 7 块，满足 `7≤16≤25`，但这只能检查上下限，不能替代模拟。

## 五、怎样知道这套动作已经熟了

- **① 不漏常数**：容量、块大小、路数一改，能重新算组数并闭环，不沿用上一题。
- **② 不漏访问**：先写 R/W 顺序和分母，再写真实块号，不只盯二维下标。
- **③ 不猜状态**：能指出某块具体在哪一笔被换掉；LRU 命中也会更新顺序；换段不清空。
- **④ 不答错问法**：次数、全部访问缺失率、只写缺失率、命中率分得清。

**对答案时只找“第一处错在哪一步”**。若错在 ②，重写地址与访问串；若错在 ③，从上一轮末状态重新走，不只改最后的分数。下一次可以先不看本页流程，直接拿 08、09 写四步；卡在哪一步，再回前面对应题重做，不另建统计表。
