

# 计网
你前半句的直觉非常接近真相，但里面混杂了一个物理结构上的误区：**主机只要发包（不管是同网段还是跨网段），物理网线上永远是先流经交换机（如设备 3）的！区别不在于“物理上发给谁”，而在于以太网帧首部里的【目的 MAC 地址填谁】！**

为了让你彻底建立起精确的转发逻辑，我把主机、交换机、路由器在处理 **单播、广播、组播（多播）、VLAN** 时的 exact（精确）动作拆解如下：

---

### 一、主机发包的黄金法则（怎么决定目的 MAC 填什么？）

当主机（比如 H3，`192.168.1.66/26`）要发送一个 IP 数据报时，操作系统的 IP 层只做一件事——检查目的 IP 地址 $D$ 的类型，并用自己的子网掩码 $M$（`/26`）去和 $D$ 做**按位与（AND）**运算，然后分以下 **4 种情况** 填写以太网帧的 **目的 MAC 地址**：

#### 情况 1：目的 IP 是受限广播（`255.255.255.255`）或本网段直接广播（`192.168.1.127`）
* **主机动作**：主机一看，这是在自己本网段里喊话！**不需要发给默认网关，也不需要发 ARP 询问**，直接把以太网帧的 **目的 MAC 填全 F（`FF-FF-FF-FF-FF-FF`）**，顺着网线发给交换机。

#### 情况 2：目的 IP 是本网段的单播地址（如 H4 的 `192.168.1.67`）
* **判断依据**：$(D \ \& \ M) == (\text{H3自己的IP} \ \& \ M)$，发现都在 `192.168.1.64/26` 网段，且主机号不是全 1。
* **主机动作**：**不找默认网关（路由器）！** 直接查自己的 ARP 缓存表找 **H4 的 MAC 地址**（没查到就广播发 ARP 问 H4），然后把以太网帧的 **目的 MAC 填成 H4 的 MAC**，发给交换机。

#### 情况 3：目的 IP 不在本网段（不管是外网单播，还是外网段的直接广播 `192.168.1.63`！）
* **判断依据**：$(D \ \& \ M) \neq (\text{H3自己的IP} \ \& \ M)$。
  *(注意你问的关键点：此时哪怕 `192.168.1.63` 是左网段的广播地址，但因为 H3 不知道左网段的掩码是多少，在 H3 眼里它就是一个普通的“外网段 IP”！)*
* **主机动作**：IP 层决定**交给默认网关（`192.168.1.65`，即路由器接口 IF3）**。于是 H3 查 ARP 找**默认网关的 MAC**，把以太网帧的 **目的 MAC 填成默认网关（路由器 IF3）的 MAC**（注意：这是一个**单播以太网帧**！），顺着网线发给交换机。

#### 情况 4：目的 IP 是组播/多播地址（D 类 IP：`224.0.0.0` ～ `239.255.255.255`）
* **主机动作**：组播既不查 ARP，也不找默认网关！TCP/IP 协议栈有一个固定的硬件映射公式：直接把组播 IP 地址的后 23 位，拼接到固定前缀 `01-00-5E` 后面，生成一个 **组播 MAC 地址（以 `01-00-5E` 开头）**，填进目的 MAC，直接发给交换机。

### 二、交换机和路由器收到后，分别怎么处理？（核心对比表）

数据包顺着网线进了交换机（设备 3），随后可能进路由器（设备 1）。它们各自的动作严格遵守以下规则：

| 帧/包的类型 | **以太网交换机（工作在链路层，只看目的 MAC，根本不看 IP！）** | **路由器（工作在网络层，剥掉帧头看目的 IP！）** |
| :--- | :--- | :--- |
| **1. 本网段单播**<br>*(目的 MAC = H4)* | 查 MAC 地址表，精准从连接 H4 的接口（IF3）**单播转发**出去（根本不会发给路由器接口 IF1！）。 | 根本收不到这个帧（被交换机直接转给 H4 了）。 |
| **2. 跨网段单播**<br>*(目的 MAC = 路由器 IF3)* | 查 MAC 表，发现目的 MAC 是路由器，于是精准从 IF1 接口**单播转发给路由器**（H4 根本收不到！）。 | 收到帧，撕掉帧头看目的 IP，查路由表，换上新网段的 MAC 头，从对应接口转发出去。 |
| **3. 本网段广播 / 受限广播**<br>*(目的 MAC = 全 F)* | 看到目的 MAC 是全 F，无脑向**除入端口外的所有端口洪泛（广播）**（H4 和路由器都会收到这个帧）。 | 收到该广播帧，撕掉帧头一看目的 IP 是本网段广播（`.127`）或受限广播（`255.255.255.255`），**直接丢弃（或仅上交本机处理），绝不往其他接口转发**！（这就是“路由器隔离广播域”）。 |
| **4. 外网段的直接广播**<br>*(如 H3 发往 `.63`，此时目的 MAC = 路由器 IF3)* | **注意！** 在右网段里，这个帧的目的 MAC 是路由器 IF3（是**单播帧**！），所以交换机 3 **只把它单播发给路由器**，**H4 收不到**！ | 路由器收到后，查路由表把包转到左接口 IF2；发现 `.63` 是左网段的主机号全 1（广播），于是路由器把目的 MAC 改成**全 F** 从左接口发给左交换机 2 $\rightarrow$ 左交换机 2 全网洪泛 $\rightarrow$ **H1、H2 同时收到**！ |
| **5. 组播（Multicast）**<br>*(目的 MAC = `01-00-5E-...`)* | 普通傻瓜交换机（无 IGMP Snooping）把组播 MAC 当成未知/广播帧，**向所有端口洪泛**；智能交换机只发给订阅了该组的成员端口。 | 普通路由器默认不转发组播；只有运行了**组播路由协议**（如 PIM）并配合 **IGMP** 协议的路由器，才会按组播树跨网段转发。 |

> **💡 重新回味上面表格的第 4 行！**
> 当 H3 发给左网段广播地址 `192.168.1.63` 时：
> * 在右边网段跑的时候，它穿的是**单播 MAC 衣服**（发给路由器），所以同在右边的 **H4 反而收不到**！
> * 过了路由器到了左边网段，路由器给它换上了**广播 MAC 衣服（全 F）**，所以左边的 **H1、H2 全收到了**！
> 把这一条想通，你的网络层+链路层配合机制就达到满分境界了！

### 三、如果引入 VLAN（虚拟局域网），会发生什么变化？

原题特意注明了“以太网交换机（**无 VLAN 功能**）”。如果把题目改成 **“支持 VLAN 的交换机”**（408 真题大题和选择题的另一大常客），规则发生如下质变：

#### 1. VLAN 的核心作用：在物理上同一台交换机内部，强行劈开成多个独立的“广播域”
假设我们把**设备 2** 换成一台支持 VLAN 的交换机，并把 **H1 划入 `VLAN 10`**，把 **H2 划入 `VLAN 20`**：
* **变化 1（广播隔离）**：即便 H1 和 H2 连在同一台交换机上、甚至配了同一个网段的 IP，当 H1 发送一个广播帧（目的 MAC 全 F）时，交换机收到后，会在帧头打上 `VLAN 10` 的标签（802.1Q Tag，占 4 字节），并且**只向同样属于 `VLAN 10` 的端口洪泛**！处在同一台交换机但属于 `VLAN 20` 的 **H2 根本收不到这个广播帧**！
* **变化 2（不同 VLAN 之间不能直接二层通信）**：通常 **一个 VLAN 对应一个独立的 IP 子网**。不同 VLAN 的主机之间要想通信（哪怕插在同一台交换机上），**必须经过路由器（或三层交换机）进行路由转发**！

#### 2. 408 必考的两个 VLAN 细节
1. **802.1Q 帧格式变化**：
   在标准以太网帧的“源 MAC”和“类型（Type）”之间，插入了 **$4\text{ B}$ 的 VLAN 标签（Tag）**。其中包含 **12 位的 VID（VLAN ID）**，因此最多可标识 $2^{12} - 2 = 4094$ 个不同的 VLAN（0 和 4095 保留）。插入后，以太网帧的最大帧长从 $1518\text{ B}$ 变成了 **$1522\text{ B}$**。
2. **谁能看见这个 4 字节的 Tag？**
   * **普通主机（H1～H4）完全看不见 Tag！** 主机发出的永远是不带 Tag 的标准以太网帧。
   * 当帧进入交换机连接主机的接口（Access 端口）时，交换机给它**打上 Tag**；在两台交换机之间的干道链路（Trunk 端口）上传输时，**带着 Tag 跑**；当帧从交换机发往目标主机时，交换机**撕掉 Tag**，还原成普通以太网帧交给主机。

### 四、总结你的判断口诀（考场实战直接套用）

以后做任何 408 拓扑收发题，按这三步走，百发百中：
1. **第一步看源主机**：用【源主机的子网掩码】去套【目的 IP】。
   * 套出来发现是**自己窝里的**（同子网）：单播就直奔目标主机 MAC，广播就直奔全 F（路由器在旁边干瞪眼，不参与转发）。
   * 套出来发现是**外面的**（不同子网）：不管那个目的 IP 是单播还是外网广播，在源主机所在的局域网里，**统统打包成单播帧（目的 MAC 填默认网关）先送进路由器**！
2. **第二步看交换机**：交换机是个瞎子（看不见 IP），它只看帧头的目的 MAC：
   * 目的 MAC 是具体某个人 $\rightarrow$ 只发给那个人对应的接口。
   * 目的 MAC 是全 F $\rightarrow$ 发给**同一个 VLAN 内**除来源口以外的所有接口。
3. **第三步看路由器**：路由器只接收目的 MAC 是自己接口的帧（或者广播帧）。撕掉帧头看目的 IP：
   * 如果是 `255.255.255.255` 或刚进来的那个网段的广播 $\rightarrow$ **掐死，绝不往下传**。
   * 如果是其他网段的 IP $\rightarrow$ 查路由表送过去；送到目标网段门口时，如果发现该 IP 在目标网段里主机号全为 1（直接广播），就换上全 F 的 MAC 头，在目标网段里引爆全场广播！

这一套流程下来，把前面的疑虑都打通了吗？
