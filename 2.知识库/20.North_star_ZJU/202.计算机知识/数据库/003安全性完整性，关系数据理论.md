# 一、数据库安全性：只看“授权/回收、自主/强制”

## 1. 重点：权限是什么？

**权限 = 对什么对象 + 能做什么操作。**  
比如：对 Student 表能不能 `SELECT`，对 Grade 列能不能 `UPDATE`，这就是权限。7

常见对象和操作：

|对象|常见权限|
|---|---|
|表、视图|SELECT、INSERT、UPDATE、DELETE|
|属性列|SELECT、INSERT、UPDATE、REFERENCES|
|数据库对象|CREATE TABLE、CREATE VIEW、CREATE INDEX 等|

SQL 中和权限有关的两个关键词是：


GRANT   -- 授权

REVOKE  -- 回收权限

SQL 的数据控制功能主要就是 `GRANT` 和 `REVOKE`

## 2. 重点：自主存取控制 DAC

**自主存取控制 DAC：谁有权限，谁就能操作；有些权限还可以继续转授权给别人。**

它的特点：

1. 同一用户对不同对象可以有不同权限；
2. 不同用户对同一对象也可以有不同权限；
3. 用户可以把自己拥有的权限再授予别人。12

### 授权语法


```Sql

GRANT 权限

ON 对象

TO 用户;
```


例子：


```Sql

GRANT SELECT

ON Student

TO U1;
```


含义：把 Student 表的查询权限授给用户 U1。

如果允许 U1 再把权限转给别人：


```Sql

GRANT SELECT

ON Student

TO U1

WITH GRANT OPTION;

```

### 回收权限语法


```Sql

REVOKE 权限

ON 对象

FROM 用户;

```

例子：


```Sql

REVOKE SELECT

ON Student

FROM U1;

```

含义：收回 U1 对 Student 表的查询权限。

---

## 3. 重点：强制存取控制 MAC

**强制存取控制 MAC：不是用户自己说了算，而是系统给主体和客体都分安全级别。**

- 主体：用户、进程等主动访问数据的一方；
- 客体：表、视图、文件、数据等被访问的对象；
- 系统根据安全级别决定能不能访问。

课件中说 MAC 的核心是“主体客体分级”。

考试一般只要会区分：

|类型|核心思想|例子|
|---|---|---|
|DAC 自主存取控制|靠授权，用户可被授予/回收权限|GRANT、REVOKE|
|MAC 强制存取控制|靠安全级别，主体客体分级|机密级用户才能访问机密级数据|

---

## 4. 安全性其他内容：跳过

用户标识与鉴别、视图机制、审计、加密、统计数据库安全性都不是你这次重点。  
知道它们是安全控制手段即可：常用方法包括用户标识与鉴别、存取控制、视图、审计、数据加密。8

---

## 典型题 1：简答题

**题目：什么是自主存取控制？SQL 中如何实现授权和回收？**

答案模板：

> 自主存取控制 DAC 是指用户对不同数据库对象可以拥有不同权限，不同用户对同一对象也可以拥有不同权限，并且用户可以把自己拥有的权限转授给其他用户。12  
> SQL 中用 `GRANT` 语句授权，用 `REVOKE` 语句回收权限。12  
> 例如：



```Sql

GRANT SELECT ON Student TO U1;

REVOKE SELECT ON Student FROM U1;
```


---

## 典型题 2：选择题

**题目：SQL 中用于权限授予和回收的语句分别是？**

A. SELECT / UPDATE  
B. CREATE / DROP  
C. GRANT / REVOKE  
D. INSERT / DELETE

答案：**C**

# 二、数据库完整性：只看“实体完整性、参照完整性”

## 1. 重点：完整性 vs 安全性

这个很容易考选择题。

|概念|关注点|防范对象|
|---|---|---|
|数据完整性|数据是否正确、一致|不符合语义、不正确的数据|
|数据安全性|数据能不能被访问|非法用户、非法操作|

完整性关注“数据是否正确和相容”，安全性关注“数据是否被非法访问或破坏”。1

---

## 2. 重点：实体完整性

**实体完整性 = 主码不能为空，主码不能重复。**

在 SQL 中用 `PRIMARY KEY` 定义。6

### 单属性主码


```Sql
可以列级定义：



CREATE TABLE Student (

    Sno CHAR(5) PRIMARY KEY,

    Sname CHAR(20)

);

也可以表级定义：

Sql

CREATE TABLE Student (

    Sno CHAR(5),

    Sname CHAR(20),

    PRIMARY KEY (Sno)

);

```

### 多属性主码

只能表级定义：

```Sql

CREATE TABLE SC (

    Sno CHAR(5),

    Cno CHAR(3),

    Grade INT,

    PRIMARY KEY (Sno, Cno)

);
```


插入或更新主码时，DBMS 会检查两个条件：主码值是否唯一、主码属性是否为空；如果不满足，就拒绝插入或修改

## 3. 重点：参照完整性

**参照完整性 = 外码的值必须在被参照表的主码中存在，或者为空。**

比如选课表 SC 里的 Sno 必须是 Student 表中已经存在的 Sno。

SQL 中用 `FOREIGN KEY ... REFERENCES ...` 定义。6


```Sql
CREATE TABLE SC (

    Sno CHAR(5),

    Cno CHAR(3),

    Grade INT,

    PRIMARY KEY (Sno, Cno),

    FOREIGN KEY (Sno) REFERENCES Student(Sno),

    FOREIGN KEY (Cno) REFERENCES Course(Cno)

);
```


含义：

- SC. Sno 参照 Student. Sno；
- SC. Cno 参照 Course. Cno；
- 插入 SC 记录时，Sno 必须在 Student 表中存在，Cno 必须在 Course 表中存在。

参照完整性被破坏时，DBMS 通常会拒绝相关插入或修改操作。6

---

## 4. 完整性其他内容：跳过

用户定义完整性、触发器、完整性约束命名、域完整性等不是重点，最多知道有 `CHECK`、`NOT NULL`、`UNIQUE` 这些约束即可。6

---

## 典型题 1：简答题

**题目：实体完整性和参照完整性分别是什么？**

答案模板：

> 实体完整性要求关系的主码必须唯一且不能为空，用来保证每个元组可以被唯一标识。6  
> 参照完整性要求外码的取值必须引用另一个关系中已经存在的主码值，或者按规则允许为空，用来保证表与表之间引用关系的正确性。6

---

## 典型题 2：应用题

**题目：建立学生表 Student 和选课表 SC。Student 的主码是 Sno，SC 的主码是 Sno 和 Cno，同时 SC. Sno 参照 Student. Sno。**

答案：


```Sql

CREATE TABLE Student (

    Sno CHAR(5),

    Sname CHAR(20),

    PRIMARY KEY (Sno)

);

CREATE TABLE SC (

    Sno CHAR(5),

    Cno CHAR(3),

    Grade INT,

    PRIMARY KEY (Sno, Cno),

    FOREIGN KEY (Sno) REFERENCES
```

# 三、关系数据理论：重点复习“规范化 + 函数依赖判断”

这一章是三章里最重要的。

---

## 1. 关系模式为什么要规范化？

关系模式设计不好，会产生：

1. 数据冗余；
2. 插入异常；
3. 删除异常；
4. 修改复杂。

规范化的目的就是：**通过分解关系模式，减少冗余和各种异常。**

但分解要满足两个理想要求：

1. **无损连接**：分解后还能还原原来的关系；
2. **保持函数依赖**：原来的约束尽量还能在分解后的表中检查。4

---

## 2. 函数依赖 FD：一定要会判断

### 基本定义

如果在关系 R 中，属性组 X 的值确定后，属性组 Y 的值也唯一确定，那么称：

Text

X → Y

读作：X 函数决定 Y，或者 Y 函数依赖于 X。

课件说，数据依赖是关系内部属性之间的约束关系，函数依赖是最重要的数据依赖之一。3

### 白话判断

看语义：

- 一个学号确定一个学生姓名：
    
    Text
    
    Sno → Sname
    
- 一个学号确定一个系：
    
    Text
    
    Sno → Sdept
    
- 一个系确定一个系主任：
    
    Text
    
    Sdept → Mname
    
- 一个学生选一门课才有一个成绩：
    
    Text
    
    (Sno, Cno) → Grade
    

### 易错点

`Sno → Cno` 一般不成立，因为一个学生可以选多门课。  
`Cno → Sno` 一般不成立，因为一门课可以被多个学生选。


## 3. 码、主属性、非主属性

### 候选码

能唯一确定整个关系全部属性的最小属性组，叫候选码。

例如：

Text

SC (Sno, Cno, Grade)

如果一个学生一门课只有一个成绩，那么：

Text

(Sno, Cno) → Grade

所以 `(Sno, Cno)` 能确定整个元组，是候选码。

### 主属性

包含在任一候选码中的属性，叫主属性。

### 非主属性

不包含在任何候选码中的属性，叫非主属性。

例如：

Text

SC (Sno, Cno, Grade)

候选码是 `(Sno, Cno)`，所以：

- Sno、Cno 是主属性；
- Grade 是非主属性。

# 四、范式关系：必须背清楚，但要理解

课件给出的范式包含关系是：

Text

1NF ⊇ 2NF ⊇ 3NF ⊇ BCNF ⊇ 4NF

也就是说：越往右要求越严格；满足 BCNF 一定满足 3NF，满足 3NF 一定满足 2NF。4

考试通常考到 1NF、2NF、3NF、BCNF。

---

## 1. 第一范式 1NF

**1NF：所有属性都是原子的，不可再分。**

比如：

|学号|姓名|电话|
|---|---|---|
|001|张三|138xxx, 139xxx|

如果“电话”里放了多个号码，就不是原子值，不满足 1NF。

课件说，1NF 是关系模式的最起码要求，不满足 1NF 就不能称为关系数据库。10

---

## 2. 第二范式 2NF

**2NF = 1NF + 非主属性不能部分依赖于码。**

只在“联合码”时特别容易出问题。

### 什么叫部分函数依赖？

如果码是 `(Sno, Cno)`，但有：

Text

Sno → Sdept

那么 Sdept 只依赖联合码的一部分 Sno，而不是完整依赖 `(Sno, Cno)`。

这就叫：**非主属性对码的部分函数依赖。**

2NF 要消除的就是这个问题。4

---

### 例子

关系：

Text

SLC (Sno, Sdept, Sloc, Cno, Grade)

函数依赖：

Text

(Sno, Cno) → Grade

Sno → Sdept

Sdept → Sloc

候选码是：

Text

(Sno, Cno)

非主属性：

Text

Sdept, Sloc, Grade

其中：

Text

Sno → Sdept

说明 Sdept 只依赖码 `(Sno, Cno)` 的一部分 Sno，所以不满足 2NF。10

### 分解到 2NF

Text

SC (Sno, Cno, Grade)

Student (Sno, Sdept, Sloc)

---

## 3. 第三范式 3NF

**3NF = 2NF + 非主属性不能传递依赖于码。**

### 什么叫传递依赖？

如果：

Text

Sno → Sdept

Sdept → Sloc

那么可以推出：

Text

Sno → Sloc

这就是 Sloc 通过 Sdept 间接依赖于 Sno，叫传递依赖。

3NF 要消除的是：**非主属性对码的传递函数依赖。**4

### 例子

关系：

Text

Student (Sno, Sdept, Sloc)

函数依赖：

Text

Sno → Sdept

Sdept → Sloc

候选码是 Sno。

其中 Sloc 通过 Sdept 传递依赖于 Sno，所以不满足 3NF。

### 分解到 3NF

Text

Student (Sno, Sdept)

Dept (Sdept, Sloc)

---

## 4. BCNF

**BCNF：每一个非平凡函数依赖 X → Y 中，X 都必须包含码。**

白话：  
只要某个属性组能决定别人，它自己就必须足够强，至少得是超码。

课件说，BCNF 要求每个非平凡函数依赖的决定因素都包含码。4

### 3NF 和 BCNF 的区别

- 3NF 主要管：非主属性不能部分依赖、传递依赖；
- BCNF 更严格：不管 Y 是主属性还是非主属性，只要 X → Y，X 就必须包含码。

课件总结：BCNF 可以理解为 3NF 之后，还要消除主属性对码的部分或传递依赖


# 五、范式判断公式：考试直接套

## 判断一个关系属于第几范式

### 第一步：找函数依赖

根据题目语义写出：

Text

A → B

AB → C

B → D

---

### 第二步：找候选码

方法：  
看哪个属性组能推出全部属性，而且不能再删属性。

例如：

Text

R (Sno, Cno, Grade, Sdept)

FD:

(Sno, Cno) → Grade

Sno → Sdept

因为：

Text

(Sno, Cno) → Grade

Sno → Sdept

所以 `(Sno, Cno)` 能推出：

Text

Sno, Cno, Grade, Sdept

候选码是：

Text

(Sno, Cno)

---

### 第三步：判断范式

| 判断内容              | 如果存在          | 最高一般到 |
| ----------------- | ------------- | ----- |
| 属性不可原子            | 不满足 1NF       |       |
| 非主属性部分依赖于码        | 只到 1NF，不到 2NF |       |
| 非主属性传递依赖于码        | 到 2NF，不到 3NF  |       |
| 存在 X → Y，但 X 不是超码 | 不满足 BCNF      |       |

| **范式级别** | **必须消除的依赖类型 (阻碍升级的原因)** | **满足该范式的核心条件**   | **考试快速判定口诀 (拦截条件)**                                  |
| -------- | ----------------------- | ---------------- | ---------------------------------------------------- |
| **1NF**  | 属性可再分 (非原子性)            | 所有字段不可再拆分        | 属性不原子 $\rightarrow$ 不满足 1NF                          |
| **2NF**  | 非主属性的部分函数依赖             | 所有非主属性完全依赖于码     | 存在非主属性**部分**依赖于码 $\rightarrow$ 止步 1NF                |
| **3NF**  | 非主属性的传递函数依赖             | 非主属性直接且完全依赖于码    | 存在非主属性**传递**依赖于码 $\rightarrow$ 止步 2NF                |
| **BCNF** | 主属性对码的部分/传递依赖           | 所有函数依赖的决定因素必须是超码 | 存在 $X \rightarrow Y$ 但 $X$ 不是超码 $\rightarrow$ 止步 3NF |
|          |                         |                  |                                                      |
|          |                         |                  |                                                      |
# 六、典型应用题：规范化判断

## 题目

设关系模式：


SLC (Sno, Sdept, Sloc, Cno, Grade)

语义：

1. 一个学生只属于一个系；
2. 一个系的学生住在同一个地方；
3. 一个学生选一门课有一个成绩。

函数依赖：


Sno → Sdept

Sdept → Sloc

(Sno, Cno) → Grade

问：该关系最高属于第几范式？如何分解到 3NF？

---

## 解题

### 第一步：找候选码

因为：



Sno → Sdept

Sdept → Sloc

所以：



Sno → Sdept, Sloc

又有：



(Sno, Cno) → Grade

所以：



(Sno, Cno) → Sno, Cno, Sdept, Sloc, Grade

因此候选码是：



(Sno, Cno)

---

### 第二步：判断 2NF

非主属性是：



Sdept, Sloc, Grade

存在：

Sno → Sdept

Sno 是候选码 `(Sno, Cno)` 的一部分。

所以 Sdept 对候选码存在部分函数依赖。

因此：



SLC 不满足 2NF，只满足 1NF

2NF 要排除非主属性对码的部分函数依赖。

---

### 第三步：分解到 2NF



SC (Sno, Cno, Grade)

Student (Sno, Sdept, Sloc)

---

### 第四步：判断 3NF

在：

Text

Student (Sno, Sdept, Sloc)

中存在：

Text

Sno → Sdept

Sdept → Sloc

所以：

Text

Sno → Sloc

这是传递函数依赖。

3NF 要消除非主属性对码的传递函数依赖。4

继续分解：

Text

Student (Sno, Sdept)

Dept (Sdept, Sloc)

SC (Sno, Cno, Grade)

最终分解到 3NF。

# 七、典型简答题：范式之间的关系

## 题目

简述 1NF、2NF、3NF、BCNF 的区别和联系。

## 答案模板

> 1NF 要求关系中每个属性都是不可再分的原子项，是关系数据库最基本的要求。10  
> 2NF 在 1NF 的基础上，要求每个非主属性都完全函数依赖于码，即不存在非主属性对码的部分函数依赖。4  
> 3NF 在 2NF 的基础上，要求不存在非主属性对码的传递函数依赖。4  
> BCNF 比 3NF 更严格，要求每个非平凡函数依赖的决定因素都包含码。4  
> 它们之间的包含关系是：1NF ⊇ 2NF ⊇ 3NF ⊇ BCNF。4
