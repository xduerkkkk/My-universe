## 一、数据库设计：核心就是“现实世界客观对象的抽象过程”

### 1. 必须掌握的主线

数据库设计就是：**从现实业务出发，把现实世界中的对象、对象属性、对象之间的联系，一步步抽象成数据库中的表、字段、约束、索引等结构**。

一句话流程：

> 现实世界 → 需求分析 → 概念结构设计 E-R 图 → 逻辑结构设计关系模式 → 物理结构设计存储/索引 → 数据库实施 → 运行维护

PPT 中明确说，数据库设计是从实际应用需求出发，逐步构建以数据库为基础的应用管理系统的全过程。1

---

### 2. 数据库设计七个阶段

考试简答题最可能问：**数据库设计的基本步骤有哪些？**

按 PPT 记：

1. **规划阶段**  
    判断有没有必要建数据库，是否可行，确定数据库系统在整个组织信息系统中的位置。3
    
2. **需求分析**  
    全面、准确了解用户实际要求，分析用户需要哪些数据、怎样处理数据。3
    
3. **概念结构设计**  
    把用户需求进行综合、归纳、抽象，形成独立于具体 DBMS 的概念模型，通常就是 E-R 图。3
    
4. **逻辑结构设计**  
    把概念模型转换成具体 DBMS 支持的数据模型，比如关系模型，并进行优化。3
    
5. **物理结构设计**  
    为逻辑数据模型选择合适的物理存储结构和存取方法，比如索引、存储安排等。35
    
6. **数据库实施**  
    用 DBMS 提供的数据语言建立数据库，编写和调试应用程序，组织数据入库，并进行试运行。3
    
7. **数据库运行和维护**  
    数据库投入正式运行后，要不断评价、调整、修改。3

### 3. 需求分析：知道干什么即可

需求分析就是收集用户业务中用到的数据、业务处理流程、数据使用情况，然后整理成数据流图和数据字典。

白话理解：

> 用户说“我要管理学生选课”，你要问清楚：有哪些学生、课程、教师、成绩？谁能选课？成绩怎么录入？需要查什么报表？  
> 然后整理成专业描述。

考试如果问“需求分析的结果是什么”，可以答：

> 需求分析的结果通常包括数据流图、数据字典，以及对数据、数据流、数据存储和处理过程的描述。78

---

### 4. 概念结构设计：重点理解 E-R 图

概念结构设计是把现实世界中的事物抽象成概念模型，常用 E-R 图表示。8

它要求：

1. 能真实反映现实世界中的事物及其联系；
2. 独立于具体机器和 DBMS；
3. 简洁、清晰、容易理解；
4. 容易修改和扩充；
5. 容易转换成关系、层次或网状模型。8

白话理解：

> 概念设计阶段还不急着建表，而是先画清楚：有哪些实体？每个实体有哪些属性？实体之间是什么联系？

例如：

- 学生是实体；
- 课程是实体；
- 学生选修课程是联系；
- 学号、姓名是学生属性；
- 课程号、课程名是课程属性。

---

### 5. 逻辑结构设计：E-R 图转成关系模式

逻辑结构设计就是把概念模型转成 DBMS 支持的数据模型，比如关系数据库中的表，并设计完整性约束。37

白话理解：

> E-R 图中的实体，通常变成表；  
> 属性变成字段；  
> 联系根据 1:1、1: n、m: n 转换成外码或新表。

常见转换套路：

#### 1:1 联系

可以把任意一方的主码放到另一方作为外码。

#### 1: n 联系

把 “1” 端的主码放到 “n” 端作为外码。

例如：

- 一个系有多个学生；
- Department (系号, 系名)
- Student (学号, 姓名, 系号)

这里 Student 表中的“系号”就是外码。

#### m: n 联系

必须单独建一张联系表。

例如：

- 学生选课是多对多；
- Student (Sno, Sname)
- Course (Cno, Cname)
- SC (Sno, Cno, Grade)

其中 SC 表用来表示“学生选课”这个联系。

---

### 6. 物理结构设计：了解即可，不深挖

物理结构设计就是为逻辑模型选择适合应用环境的物理结构，包括存储结构和存取方法。5

重点知道：

- 经常出现在查询条件中的属性，可以考虑建索引；
- 经常作为连接条件的属性，可以考虑建索引；
- 经常用于最大值、最小值等聚集函数的属性，也可以考虑建索引；
- 但索引太多会增加额外开销。6

考试如果简单问“物理设计主要做什么”，答：

> 物理设计主要是为关系模式选择存取方法，并设计关系、索引等数据库文件的物理存储结构。5

---

### 7. 数据库实施和运行维护：简单记

数据库实施主要包括：

1. 用 DDL 定义数据库结构；
2. 组织数据入库；
3. 编制与调试应用程序；
4. 数据库试运行。10

数据库运行维护主要包括：

1. 数据库转储和恢复；
2. 安全性、完整性控制；
3. 性能监督、分析和改进；
4. 数据库重组织和重构造。9

## 二、嵌入式 SQL：知道是什么，如何区分

### 1. 什么是嵌入式 SQL？

嵌入式 SQL 就是：

> 把 SQL 语句嵌入到 C、C++、Java 等高级语言中，由 SQL 负责访问数据库，由高级语言负责流程控制、界面处理、单记录处理、格式化输出等工作。11

为什么需要嵌入式 SQL？

因为普通 SQL 是非过程化语言，不能很好地写 if、while 这类流程控制，也不能完成前台界面开发等工作。11

---

### 2. 如何区分普通语句和嵌入式 SQL？

在主语言中，嵌入式 SQL 语句通常有：

C

EXEC SQL <SQL语句>;

例如：

C

EXEC SQL DROP TABLE Student;

PPT 中明确指出，嵌入式 SQL 的前缀是 `EXEC SQL`，结束标志随主语言不同而不同，例如 C 语言中可以写 `EXEC SQL <SQL语句>`。11

所以考试问“如何识别嵌入式 SQL”，直接答：

> 看有没有 `EXEC SQL` 前缀。

---

### 3. 嵌入式 SQL 的执行过程

嵌入式 SQL 不能直接由 C 编译器识别，要先预编译。

过程：

1. DBMS 预处理程序扫描源程序，识别 SQL 语句；
2. 把 SQL 语句转换成主语言的函数调用语句；
3. 再由主语言编译器编译成目标代码。11

白话：

> 先把 SQL 翻译成 C/C++/Java 能看懂的函数调用，再正常编译。

---

### 4. 数据库连接语句

简单熟悉即可。

建立连接：

Sql

EXEC SQL CONNECT TO target AS connection USER user;

切换连接：

Sql

EXEC SQL SET CONNECTION connection;

关闭连接：

Sql

EXEC SQL DISCONNECT connection;

PPT 中给出的连接数据库语法就是 `EXEC SQL CONNECT TO target AS connection USER user`，关闭连接用 `EXEC SQL DISCONNECT connection`


## 三、嵌入式 SQL：使用游标 vs 不使用游标

### 1. 什么时候不用游标？

如果 SQL 查询结果只有一行，或者是插入、删除、更新操作，通常不用游标。

例如：查询某个学生姓名。

C

EXEC SQL SELECT Sname

INTO :sname

FROM Student

WHERE Sno = : sno;

规律：

> 查询结果是单行，可以直接 `SELECT ... INTO 主变量`。

---

### 2. 什么时候使用游标？

如果查询结果是多行，就需要使用游标。

因为高级语言通常一次处理一条记录，而 SQL 查询可能返回一个集合。游标的作用就是：

> 把 SQL 查询得到的多行结果集，一行一行取出来处理。

典型步骤：

C

EXEC SQL DECLARE C1 CURSOR FOR

SELECT Sno, Sname

FROM Student

WHERE Sdept = 'CS';

EXEC SQL OPEN C1;

while (1) {

    EXEC SQL FETCH C1 INTO :sno, :sname;

    /*

      处理当前这一行

    */

}

EXEC SQL CLOSE C1;

考试记公式：

> 定义游标 `DECLARE` → 打开游标 `OPEN` → 逐行读取 `FETCH` → 关闭游标 `CLOSE`

---

### 3. 简单判断题套路

#### 情况 1：查询某一个学生的姓名

Sql

SELECT Sname

FROM Student

WHERE Sno = '202301';

结果最多一行，**不用游标**。

#### 情况 2：查询计算机系所有学生的学号和姓名

Sql

SELECT Sno, Sname

FROM Student

WHERE Sdept = 'CS';

结果可能多行，**用游标**。

#### 情况 3：更新某个学生年龄

Sql

UPDATE Student

SET Sage = Sage + 1

WHERE Sno = '202301';

这是更新操作，**不用游标**。

## 四、数据库恢复技术：事务基本概念与 ACID

你给的参考材料里，恢复章节内容不完整，只在数据库维护中提到“DBA 要定期备份数据库和日志文件，发生介质故障时利用备份和日志文件把数据库恢复到一致性状态”。9  
下面按数据库考试常规重点补充。

---

### 1. 什么是事务？

事务是数据库中一个逻辑工作单位。

白话：

> 要么全部做完，要么一点都不做。

例如银行转账：

Text

A 账户 -100

B 账户 +100

这两个操作必须作为一个整体，要么都成功，要么都失败，不能只扣 A 的钱但没给 B 加钱。

---

### 2. 事务的 ACID 特性

考试必背。

#### A：原子性 Atomicity

事务中的操作要么全做，要么全不做。

例子：

> 转账时，扣钱和加钱必须一起成功；如果中途失败，已经做的操作要撤销。

#### C：一致性 Consistency

事务执行前后，数据库都必须处于一致状态。

例子：

> 转账前 A+B 总金额是 1000，转账后 A+B 总金额仍然应该是 1000。

#### I：隔离性 Isolation

多个事务并发执行时，互相不能干扰。

例子：

> 两个人同时修改同一个账户余额，不能导致数据错乱。

#### D：持久性 Durability

事务一旦提交，对数据库的修改就是永久的，即使系统故障也不能丢。

例子：

> 转账成功提交后，即使系统断电，恢复后这笔转账也应该还在。

---

### 3. 恢复技术核心

恢复技术的目标：

> 系统故障后，把数据库恢复到某个正确的一致性状态。

常用依据：

1. 数据库备份；
2. 日志文件；
3. 转储记录。

PPT 中第七章运行维护部分提到，DBA 要定期对数据库和日志文件进行备份，发生介质故障时利用数据库备份和日志文件备份，尽快把数据库恢复到一致性状态。9

---

### 4. 简单恢复规则

考试常见说法：

- 已经提交的事务：需要 **REDO 重做**；
- 没有提交的事务：需要 **UNDO 撤销**。

白话：

> 提交了的，必须保住；没提交的，不能算数。


## 五、并发控制：封锁是什么，两种锁怎么申请

### 1. 为什么需要并发控制？

数据库是多用户系统，允许多个事务同时访问数据库。12

但是多个事务同时读写同一数据时，可能破坏事务的隔离性和一致性，导致错误数据。12

并发操作可能带来的问题：

1. 丢失修改；
2. 不可重复读；
3. 读脏数据。

PPT 中明确提到，多个用户并发存取同一数据时，可能存取和存储不正确的数据，破坏事务隔离性和一致性。12

---

### 2. 丢失修改

丢失修改就是：

> 两个事务都读同一个数据并修改，后写回的事务覆盖了先写回事务的结果。

例如：

Text

A = 16

T1 读 A=16

T2 读 A=16

T1: A = A - 1，写回 A=15

T2: A = A - 3，写回 A=13

最终 A=13，T1 的修改丢失了。

PPT 中也用两个事务读入同一数据并修改，后一个提交结果破坏前一个提交结果，说明丢失修改。12

---

### 3. 不可重复读

不可重复读就是：

> 一个事务前后两次读同一数据，中间被另一个事务修改了，导致两次读到的结果不一样。

例如：

Text

T1 第一次读 A=100

T2 修改 A=200 并提交

T1 第二次读 A=200

T1 两次读取结果不同，这就是不可重复读。

PPT 中说，不可重复读是事务 1 读取数据后，事务 2 执行更新操作，使事务 1 无法再现前一次读取结果。12

---

### 4. 封锁是什么？

封锁就是：

> 事务在访问某个数据对象前，先向系统申请锁，获得锁之后才能操作该数据；操作期间其他事务受到限制。

白话：

> 就像上厕所先锁门，别人不能随便进来。

---

### 5. 两种锁：S 锁和 X 锁

#### 共享锁 S 锁 / 读锁

如果事务只想读数据，就申请 S 锁。

特点：

- 加了 S 锁后，自己可以读；
- 其他事务也可以再加 S 锁一起读；
- 但其他事务不能加 X 锁修改。

口诀：

> S 锁允许大家一起读，但不允许别人写。

---

#### 排他锁 X 锁 / 写锁

如果事务要修改数据，就申请 X 锁。

特点：

- 加了 X 锁后，自己可以读和写；
- 其他事务不能再加 S 锁；
- 其他事务也不能再加 X 锁。

口诀：

> X 锁最霸道，别人不能读，也不能写。

---

### 6. 锁相容矩阵：选择题可能考

|已有锁 \ 申请锁|S 锁|X 锁|
|---|---|---|
|S 锁|相容|不相容|
|X 锁|不相容|不相容|

记忆：

> 只有 S 和 S 相容，其余都不相容。

---

### 7. 具体事务执行时如何申请锁

这是你老师强调的“具体事务执行时如何具体申请”，要会写步骤。

#### 规则

1. 读数据前：申请 S 锁；
2. 写数据前：申请 X 锁；
3. 用完数据后：释放锁；
4. 如果申请不到锁，就等待；
5. 如果读后还要写，应该升级为 X 锁。

---

### 8. 典型例题 1：只读数据

事务 T1：

Sql

SELECT A FROM R WHERE id = 1;

加锁过程：

Text

T1 申请 A 的 S 锁

T1 读取 A

T1 释放 A 的 S 锁

---

### 9. 典型例题 2：修改数据

事务 T1：

Sql

UPDATE R SET A = A - 1 WHERE id = 1;

加锁过程：

Text

T1 申请 A 的 X 锁

T1 读取 A

T1 修改 A

T1 写回 A

T1 释放 A 的 X 锁

---

### 10. 典型例题 3：两个事务并发读

Text

T1 读 A

T2 读 A

加锁过程：

Text

T1 申请 A 的 S 锁，成功

T2 申请 A 的 S 锁，成功

T1 读 A

T2 读 A

T1 释放 S 锁

T2 释放 S 锁

原因：

> S 锁和 S 锁相容。

---

### 11. 典型例题 4：一个读，一个写

Text

T1 读 A

T2 修改 A

加锁过程：

Text

T1 申请 A 的 S 锁，成功

T1 读 A

T2 申请 A 的 X 锁，失败，等待

T1 释放 A 的 S 锁

T2 获得 A 的 X 锁

T2 修改 A

T2 释放 A 的 X 锁

原因：

> S 锁和 X 锁不相容。

---

### 12. 典型例题 5：两个事务都修改同一数据

Text

T1 修改 A

T2 修改 A

加锁过程：

Text

T1 申请 A 的 X 锁，成功

T1 修改 A

T2 申请 A 的 X 锁，失败，等待

T1 释放 A 的 X 锁

T2 获得 A 的 X 锁

T2 修改 A

T2 释放 A 的 X 锁

原因：

> X 锁和 X 锁不相容。

## 六、最可能出的简答题整理

### 简答题 1：简述数据库设计的基本步骤。

答案模板：

> 数据库设计一般包括规划、需求分析、概念结构设计、逻辑结构设计、物理结构设计、数据库实施、数据库运行和维护七个阶段。规划阶段进行必要性和可行性分析；需求分析了解用户实际要求；概念结构设计形成独立于 DBMS 的概念模型；逻辑结构设计把概念模型转换为 DBMS 支持的数据模型；物理结构设计选择存储结构和存取方法；实施阶段建立数据库、编写程序、装载数据并试运行；运行维护阶段对数据库进行评价、调整和修改。3

---

### 简答题 2：什么是概念结构设计？

答案模板：

> 概念结构设计是把现实世界中的事物及其联系抽象成独立于具体 DBMS 的概念模型，通常用 E-R 图表示。它建立在需求分析得到的数据流图和数据字典基础上，目的是为计算机存储数据做准备。8

---

### 简答题 3：什么是嵌入式 SQL？如何区分嵌入式 SQL 和主语言语句？

答案模板：

> 嵌入式 SQL 是把 SQL 语句嵌入到 C、C++、Java 等高级语言中，由 SQL 完成数据库操作，由高级语言完成流程控制、界面处理、单记录处理和格式化输出等工作。嵌入式 SQL 通常以前缀 `EXEC SQL` 开头，因此可以通过 `EXEC SQL` 来区分普通主语言语句和嵌入式 SQL 语句。11

---

### 简答题 4：什么时候使用游标？游标的基本步骤是什么？

答案模板：

> 当 SQL 查询结果是多行记录时，需要使用游标，因为 SQL 面向集合操作，而主语言通常需要逐行处理记录。游标的基本步骤是：定义游标 `DECLARE CURSOR`，打开游标 `OPEN`，逐行读取 `FETCH`，最后关闭游标 `CLOSE`。

---

### 简答题 5：什么是事务？事务有哪些特性？

答案模板：

> 事务是数据库中的一个逻辑工作单位，其中的操作要么全部执行，要么全部不执行。事务具有 ACID 特性：原子性表示事务不可分割；一致性表示事务执行前后数据库都保持正确状态；隔离性表示并发事务之间不能相互干扰；持久性表示事务一旦提交，其结果永久保存。

---

### 简答题 6：什么是封锁？S 锁和 X 锁有什么区别？

答案模板：

> 封锁是并发控制的一种方法，事务在访问数据对象前必须先申请锁，获得锁后才能进行相应操作。S 锁又叫共享锁或读锁，允许多个事务同时读取同一数据，但不允许其他事务修改。X 锁又叫排他锁或写锁，一个事务加 X 锁后，其他事务既不能读也不能写该数据。

### 应用题 3：写游标处理多行查询

> 查询 CS 系所有学生的学号和姓名，并逐行处理。

答案模板：

C

EXEC SQL DECLARE C1 CURSOR FOR

SELECT Sno, Sname

FROM Student

WHERE Sdept = 'CS';

EXEC SQL OPEN C1;

while (1) {

    EXEC SQL FETCH C1 INTO :sno, :sname;

    /*

      处理当前学生

    */

}

EXEC SQL CLOSE C1;

### 应用题 4：写事务加锁过程

题目：

Text

T1：读 A

T2：修改 A

答案：

Text

T1 申请 A 的 S 锁，成功

T1 读取 A

T2 申请 A 的 X 锁，因为 S 锁和 X 锁不相容，所以 T2 等待

T1 释放 A 的 S 锁

T2 获得 A 的 X 锁

T2 修改 A

T2 释放 A 的 X 锁

### 应用题 5：判断并发问题

题目：

Text

A = 100

T1 读 A = 100

T2 读 A = 100

T1 A = A - 10，写回 A = 90

T2 A = A - 20，写回 A = 80

问：出现什么问题？

答案：

> 出现丢失修改。T1 和 T2 都读入同一个 A 并修改，T2 后写回的结果覆盖了 T1 的修改，导致 T1 的修改丢失。PPT 中也说明，丢失修改是两个事务读入同一数据并修改，一个事务的提交结果破坏另一个事务提交结果。12
