# 5

![[_attachments/image/04算法重刷-1784626914711.jpeg]]**直接指出：你的逻辑推导完全正确，但你的结论（$O(n)$ 复杂度）正是图片表格里只能拿 11 分的“暴力解法”。**

你所描述的“碰到的第一个比前一个小的数”确实是这道题的物理本质（寻找断崖点）。但正如你所说，最坏情况下（比如最小值在最后一个位置，或者根本没旋转），你要从头走到尾，时间复杂度依然是 $O(n)$。

回到我们之前讲过的**“条件浪费”**原则：
如果你用 $O(n)$ 的线性扫描，哪怕是一个**完全乱序**的数组找最小值，也能在 $O(n)$ 内完成。题目特意强调了它是**“有序数组的旋转结果”**，如果你没有把时间复杂度降到 **$O(\log n)$**，就说明你浪费了这个极其苛刻的前置条件，必然扣分。

下面为你拆解如何利用“局部有序”的特性，使用**二分查找（折半查找）**拿到 13 分满分：

### 1. 底层状态与物理形态分析
旋转数组在物理形态上，必然是由**两个严格升序的子区间**拼接而成的（形如一个断崖）。
*   **左半区**：整体数值较大。
*   **右半区**：整体数值较小。我们要找的最小值，就是右半区的第一个元素。
*   **核心特性**：左半区的所有元素，**绝对大于**右半区的所有元素。

### 2. 状态转移机制（为什么要和右边界比？）
我们设定左指针 `L = 0`，右指针 `R = n - 1`，求出中点 `mid`。
如何判断 `mid` 到底落在了左半区还是右半区？**拿 `A[mid]` 去和绝对处于末尾的 `A[R]` 进行打擂台比较。**

*   **状态 A：`A[mid] > A[R]`**
    *   **物理意义**：中间的数比最右边的数还大，说明 `mid` 踩在了**左边那个较高的断崖**上。
    *   **收缩动作**：真正的最小值一定在 `mid` 的**右边**。因为 `A[mid]` 已经这么大了，它自己绝不可能是最小值。所以毫不犹豫地抛弃左边：**`L = mid + 1`**。
*   **状态 B：`A[mid] < A[R]`**
    *   **物理意义**：中间的数比最右边的数小，说明 `mid` 已经踩在了**右边那个较低的断崖**上。
    *   **收缩动作**：真正的最小值可能在 `mid` 的左边，也**可能恰好就是 `mid` 本身**（比如 `{4, 5, 1, 2, 3}`，`mid` 指向 `1`）。因此，绝对不能写 `R = mid - 1`（会漏解），必须保留 `mid`，将搜索边界收缩为：**`R = mid`**。

### 3. 考场满分代码（完美契合之前的模板）
你仔细看这个逻辑，它完美对应了我们前面讨论过的 **二分查找“模板二：边界夹逼 `while (L < R)`”**。

```c
int findMin(int A[], int n) {
    int L = 0, R = n - 1;
    
    // 使用边界夹逼模板，当 L == R 时，唯一剩下的嫌疑人就是我们要找的最小值
    while (L < R) {
        int mid = (L + R) / 2;
        
        if (A[mid] > A[R]) {
            // mid 在高崖上，最小值必定在右侧，且 mid 绝不是最小值
            L = mid + 1;
        } else {
            // A[mid] < A[R] (题目说了无重复值，不会有 == 的情况)
            // mid 在低崖上，最小值在左侧，或者刚好就是 mid
            R = mid;
        }
    }
    
    // 循环结束时 L == R，定位完成
    return A[L];
}
```

### 总结
你最初的想法（找第一个下降的数）思维非常敏锐，但在 408 考场上，当你看到题目给的数组有**“局部单调递增”**的属性时，大脑的条件反射必须立刻从“从头到尾遍历（$O(n)$）”切换到“砍一半跳着找（$O(\log n)$）”。这就是 11 分和 13 分的底层区别。


# 6 滑动窗口
![[_attachments/image/04算法重刷-1784632919718.jpeg]]



### 正确的满分（15 分）做法：滑动窗口（双指针）

题目强调了序列是**升序**且 $0 \le a_i < n$，这意味着**数组里的元素都是非负整数**。
既然都是非负整数，那么一个连续子序列越长，它的元素之和就越大。这完美契合滑动窗口的单调性原则。

**(1) 算法基本设计思想：**
使用两个指针 `left` 和 `right` 维护一个滑动窗口 `[left, right]`，并用一个变量 `sum` 记录窗口内元素的和。
1. `right` 指针主动向右扩张，每次将 $A[right]$ 加入 `sum`。
2. 如果发现 `sum > k`，说明当前窗口以及包含当前窗口的更大窗口都不满足条件。此时需要 `left` 指针向右收缩，并从 `sum` 中减去 $A[left]$，直到 `sum <= k` 为止。
3. 当 `sum <= k` 时，说明当前窗口 `[left, right]` 满足条件。**关键点来了：如果区间 `[left, right]` 的和 $\le k$，那么以 $A[right]$ 结尾的任何子序列（即 `[left, right]`，`[left+1, right]` ... `[right, right]`）它们的和必定也 $\le k$。** 这样的子序列个数恰好等于窗口的长度，即 `right - left + 1`。将该数值累加到总数中。
4. 重复上述过程，直到 `right` 遍历完整个数组。

**(2) 代码实现 (C/C++)：**

```cpp
#include <iostream>
#include <vector>

using namespace std;

int countSubarrays(vector<int>& A, int n, int k) {
    int left = 0;          // 左指针
    int right = 0;         // 右指针
    int sum = 0;           // 当前滑动窗口内元素的和
    int count = 0;         // 满足条件的子序列总数

    // 右指针遍历整个数组
    for (right = 0; right < n; right++) {
        sum += A[right];   // 将当前元素加入窗口和

        // 如果窗口和大于k，左指针开始收缩，直到和 <= k
        while (sum > k && left <= right) {
            sum -= A[left];
            left++;
        }

        // 此时 [left, right] 区间的和必定 <= k
        // 以 A[right] 结尾的满足条件的子数组个数为 right - left + 1
        count += (right - left + 1); 
    }

    return count;
}
```

**(3) 复杂度分析：**
*   **时间复杂度：$O(n)$。** 虽然代码中有嵌套的 `while` 循环，但是 `left` 和 `right` 指针在整个算法执行过程中，**只进不退**。`right` 最多增加 $n$ 次，`left` 最多也只增加 $n$ 次。因此整体基本操作次数是 $2n$，时间复杂度为 $O(n)$。
*   **空间复杂度：$O(1)$。** 算法运行过程中只使用了常数个额外的变量（`left`, `right`, `sum`, `count`），不需要额外的辅助数组，空间复杂度为 $O(1)$。

---
**总结提醒：**
在考研 408 或者类似笔试中，写双指针/滑动窗口时一定要牢记：**两个指针决不回头！** 如果你写出了 `外层for里套着内层指针重置` 的代码，那基本就是 $O(n^2)$ 暴力解法了。另外考试时一定要仔细看清题目要求的是**“和”**还是**“差”**。

：极限时间优化方案 $O(n)$

题目要求“时间上尽可能高效”，且给出了几个非常关键的条件：**“非负整数”**和上限是固定的 **“$5n$”**。
这意味着：任何大于 $5n$ 的数字都不可能参与组成合法的数对（因为另一个数至少是 0）。这给了我们**空间换时间**的机会，利用“前缀和+数组映射”可以把时间压缩到 $O(n)$。

**基本思路如下：**
1. 申请一个长度为 `5n + 1` 的数组 `countB`，全部初始化为 0。
2. 遍历数组 B：如果 $B[i] \le 5n$，则令 `countB[ B[i] ]++`。（统计 B 中有效数字的出现次数）。
3. 将 `countB` 转化为**前缀和数组**：即 `countB[k]` 存放的是数组 B 中**小于等于 $k$ 的元素总数**。这步遍历数组 `countB` 即可完成，耗时 $O(n)$。
4. 遍历数组 A：对于 A 中的每个元素 $a$，如果 $a \le 5n$，那么 B 中能够与它组合的最大合法值是 $5n - a$。我们直接查表，将 `countB[5n - a]` 累加到总数中即可。

**复杂度：**
*   **时间复杂度：$O(n)$。** 遍历数组、计算前缀和都是一次线性遍历，没有嵌套循环，也没有排序，达到了理论上的时间最优。
*   **空间复杂度：$O(n)$。** 额外申请了一个长度为 $5n+1$ 的数组，用空间换取了时间的极致提升。

# 8 原地重排链表
![[_attachments/image/04算法重刷-1784708110748.jpeg]]

链表排序常用两种思路,先明确前提:假设 L 是**带头结点的单链表**,结点结构 `data` (int)+ `next`。
![[_attachments/image/04算法重刷-1784709528146.jpeg]]
## 方法一:直接插入排序(408最常用,好写)

核心:把原链表拆成两部分——一条"已排序链表"(初始只含第一个结点)和剩下的"待插入结点"。每次从待插入链表取一个结点,在已排序链表里从头扫描找到插入位置,断链+接链插入。

```c
void insertSort(LinkList L) {
    LNode *p = L->next;        // p 指向待处理结点序列的头
    L->next = NULL;            // 把 L 变成空的已排序链表(只剩头结点)
    while (p != NULL) {
        LNode *r = p->next;    // r 保存 p 的后继,防止断链后丢失
        LNode *pre = L;        // pre 从头结点开始找插入位置
        // 在已排序链表中找第一个 data 比 p 大的结点,插到它前面
        while (pre->next != NULL && pre->next->data < p->data)
            pre = pre->next;
        p->next = pre->next;   // 接后
        pre->next = p;         // 接前
        p = r;                 // 处理下一个
    }
}
```

时间复杂度 O(n²),空间 O(1)(只用了几个指针,是**原地**排序,没申请新结点)。

关键点说明:
- `L->next = NULL` 这一步很关键。它把整条链表"清空"成只有一个头结点的空表,然后逐个把结点插回去。不这么做的话,已排序区和待排序区会纠缠在一起,断链丢指针。
- `r = p->next` 必须在改动 `p->next` **之前**保存,否则一旦 `p->next` 被改指向 `pre->next`,原来的后继就找不到了。
- 判断条件用 `pre->next->data < p->data`(严格小于),保证相等元素的相对顺序不变,即**稳定**。

## 方法二:归并排序(要求 O(nlogn) 时用)

链表天生适合归并,不需要像数组那样开辅助空间(不用二分下标随机访问)。分三步:

1. **找中点断开**:快慢指针,快指针走两步、慢指针走一步,快到尾时慢在中点,从中点断成两条链。
2. **递归排序**两条子链。
3. **合并**两条有序链(和合并两个有序链表同一套逻辑)。

```c
// 合并两条有序链表(不带头结点),返回新头
LNode* merge(LNode *a, LNode *b) {
    LNode dummy;               // 临时头结点,简化边界处理
    LNode *tail = &dummy;
    dummy.next = NULL;
    while (a && b) {
        if (a->data <= b->data) { tail->next = a; a = a->next; }
        else                    { tail->next = b; b = b->next; }
        tail = tail->next;
    }
    tail->next = (a != NULL) ? a : b;   // 接上剩余部分
    return dummy.next;
}

// 对不带头结点的链表 head 归并排序,返回新头
LNode* mergeSort(LNode *head) {
    if (head == NULL || head->next == NULL) return head;  // 0 或 1 个结点
    LNode *slow = head, *fast = head->next;   // fast 先走一步保证左半 <= 右半
    while (fast && fast->next) {
        slow = slow->next;
        fast = fast->next->next;
    }
    LNode *mid = slow->next;
    slow->next = NULL;                        // 断开
    LNode *left  = mergeSort(head);
    LNode *right = mergeSort(mid);
    return merge(left, right);
}
```

时间 O(nlogn),空间 O(logn)(递归栈)。

注意归并排序里我用的是**不带头结点**的链表来递归(操作更干净)。如果原题 L 带头结点,外层这样接:

```c
L->next = mergeSort(L->next);
```

## 怎么选

- 题目只说"排序"、数据规模小、要求代码短:写**插入排序**,原地 O(1) 空间,不容易错。
- 题目明确要求 **O(nlogn)** 或强调效率:写**归并排序**。
- 不推荐链表用快排:链表不能 O(1) 随机访问下标,基准划分要额外遍历,代码比归并还啰嗦,考场上没优势。
