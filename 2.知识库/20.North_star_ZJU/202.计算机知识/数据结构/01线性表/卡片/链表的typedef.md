想要彻底搞懂它，你只需要记住一条 C 语言的“黄金法则”：**`typedef` 的语法格式，完全照搬了“变量声明”的格式。**

我们来变个魔术，分三步走，你立刻就能明白为什么是 `typedef LNode *LinkList;`：

### 第一步：先忘掉 `typedef`，只写一个普通的变量声明

假设你现在要定义一个普通的指针变量，名字叫 `p`，让它指向 `LNode` 这个结构体。你会怎么写？ 你会写：

C

```
LNode *p; 
```

（在 C 语言中，`*` 是跟着变量名走的，这代表 `p` 是一个指针）。

### 第二步：把变量名换成你想要的“类型别名”

现在，我们不叫它 `p` 了，我们想给这个类型起个高端的名字，叫 `LinkList`。我们把 `p` 替换掉：

C

```
LNode *LinkList; 
```

注意，如果代码只写到这里，计算机依然会认为 `LinkList` 只是一个**普通的指针变量**。

### 第三步：见证奇迹，加上 `typedef`

我们在整句话的最前面，直接加上 `typedef` 关键字：

C

```
typedef LNode *LinkList;
```

一旦加上了 `typedef`，C 语言编译器就会恍然大悟：“哦！原来你不是要定义一个叫 `LinkList` 的变量，你是想把 `LinkList` 变成一个新的**类型名**啊！”

---

### 为什么不能写成 `typedef *LNode LinkList;` ？

因为在 C 语言的语法规则里，根本不存在 `*LNode LinkList;` 这种声明变量的方式。`*` 必须用来修饰后面的名字。

为了证明这条“黄金法则”有多好用，我们可以看看另一个很容易出错的例子——给**数组**起别名： 假设你想给包含 10 个整数的数组 `int[10]` 起个新名字叫 `TenInts`。

- **人类直觉（错误）：** `typedef int[10] TenInts;`
    
- **C 语言的黄金法则（正确）：**
    
    1. 声明一个数组变量：`int arr[10];`
        
    2. 换成你想要的名字：`int TenInts[10];`
        
    3. 前面加上 typedef：`typedef int TenInts[10];`
        

**总结一下：** `LNode *LinkList` 里面的 `*` 其实是用来修饰 `LinkList` 的。它告诉编译器：被 `typedef` 提拔为类型的 `LinkList`，本质上是一个指向 `LNode` 的指针。
