# 从暴力解到优化解的思路

![[_attachments/image/03大题-1784532748868.jpeg]]


这六道例题是对“条件浪费”和“目标超额”这两个概念的极佳实践。下面直接为你拆解每种暴力解法的具体归属及其底层的优化逻辑：

**例题 2-1**
*   **诊断结果**：**条件浪费**。
*   **底层分析**：题目给出了“升序”条件。暴力枚举（线性查找）的时间复杂度为 $O(n)$，完全没有利用数组有序的特性。利用有序性应直接使用**二分查找**，在每次比较后剔除一半区间，将时间复杂度降至 $O(\log n)$。

**例题 2-2**
*   **诊断结果**：**条件浪费**。
*   **底层分析**：暴力解法是把 B 接在 A 后面然后执行快速排序，时间复杂度为 $O((n+m)\log(n+m))$。这无视了 A 和 B 原本已经局部“升序”的条件。利用该条件，只需使用两个指针分别指向 A 和 B 的首部，比较大小后依次存入 C，即**归并操作**，只需扫描一遍，时间复杂度降至 $O(n+m)$。

**例题 2-3**
*   **诊断结果**：**条件浪费**。
*   **底层分析**：暴力枚举寻找重复值需要双层循环，时间复杂度 $O(n^2)$。这无视了题目中“非负、绝对值 $< n$”这个极强的数据范围限制。由于元素有 $n$ 个且值域为 $[0, n-1]$，元素的值可以直接映射为数组的索引。利用该特性可使用**原地哈希法**（将对应下标的元素加上 $n$ 或取相反数做标记），时间复杂度直接降至 $O(n)$，且空间复杂度为 $O(1)$。

**例题 2-4**
*   **诊断结果**：**目标超额**。
*   **底层分析**：中位数的定义是排序后位于中间位置（奇数长度下索引为 $n/2$）的元素。暴力快排会将整个数组完全排序，时间复杂度 $O(n \log n)$。但我们并不关心比中位数小的元素谁大谁小，也不关心比中位数大的元素内部顺序。只需利用快速排序的 **Partition（划分）操作**，当划分的基准值位置恰好等于 $n/2$ 时即可返回，这使得平均时间复杂度降为 $O(n)$。

**例题 2-5**
*   **诊断结果**：**目标超额**。
*   **底层分析**：与上一题类似。题目只要求将数据分为两坨：$< k$ 的在一边，$\ge k$ 的在另一边，并没有要求这两部分内部有序。暴力快排执行了不必要的内部排序操作，时间复杂度 $O(n \log n)$。只需使用你上一个问题中的**双指针交替扫描法（Partition 划分）**，遍历一次数组即可完成，时间复杂度 $O(n)$。

**例题 2-6**
*   **诊断结果**：**条件浪费**。
*   **底层分析**：题目要求针对不同长度求最大“连续子序列”和。如果暴力枚举所有子序列的起点和终点，再通过内部循环去累加求和，最高会出现 $O(n^3)$ 的复杂度。这里浪费了“连续”特性的重叠子问题关系。
    *   **优化思路**：长度为 $L$ 的区间和，不需要每次从头累加，可以预先计算出**前缀和**数组，利用 $Sum = PreSum[R] - PreSum[L-1]$ 在 $O(1)$ 时间内求出任意区间和；或者利用**滑动窗口**，在计算下一个等长子序列时，只需“减去移出窗口的左端点，加上进入窗口的右端点”。这样能把总体时间复杂度降至 $O(n^2)$。

# 快排

**考场上可以直接默写的“挖坑法”模板：**

codeC

```C
// 标准的划分函数（核心逻辑，建议拆出来写，结构更清晰）
int Partition(int A[], int low, int high) {
    int pivot = A[low];  // 选定基准值，此时 A[low] 视作一个“坑”
    
    while (low < high) {
        // 1. 从右向左找比基准值小的元素
        while (low < high && A[high] >= pivot) {
            high--;
        }
        A[low] = A[high]; // 把找到的较小元素填入左边的“坑” A[low]，此时 A[high] 变成了新“坑”
        
        // 2. 从左向右找比基准值大的元素
        while (low < high && A[low] <= pivot) {
            low++;
        }
        A[high] = A[low]; // 把找到的较大元素填入右边的“坑” A[high]，此时 A[low] 变成了新“坑”
    }
    
    A[low] = pivot; // 循环结束时 low == high，把一开始拿出来的基准值填入最后的“坑”
    return low;     // 返回基准值的最终位置
}

// 快排主函数
void QuickSort(int A[], int low, int high) {
    if (low < high) { // 递归的终止条件：区间内至少有两个元素
        int pivot_pos = Partition(A, low, high); // 划分，获取基准值位置
        QuickSort(A, low, pivot_pos - 1);        // 递归排序左子区间
        QuickSort(A, pivot_pos + 1, high);       // 递归排序右子区间
    }
}
```

### 1. 这就是快排不递归而已吧？
**精确纠正：它不叫“不递归的快排”，它在算法领域有专属名称——快速选择算法（Quick Select）。**

*   **核心区别（状态空间缩减）**：
    *   **快速排序**：每次划分（Partition）后，必须**同时**处理左子区间和右子区间。它的状态树是不断分叉的，平均时间复杂度是 $O(n \log n)$。
    *   **快速选择（例题 2-10）**：每次划分后，基准值会落在一个确定位置 `i`。由于题目只找第 $n/2$ 个元素，你只需要判断 $n/2$ 在 `i` 的左边还是右边，然后**彻底抛弃另一半区间**。
*   **时间复杂度突变**：由于每次只进入一半区间（类似二分查找），它的耗时是 $n + n/2 + n/4 + \dots \approx 2n$。所以快速选择算法的平均时间复杂度是严格的 **$O(n)$**，这正是这道题能拿到满分的时空复杂度要求。

### 2. 考场到底会对 `swap` 扣分吗？
**直接回答：有被扣 1~2 分“代码严谨性”分数的明确风险。**

*   **语言标准**：C 语言标准库中**根本没有** `swap` 函数。C++ 的 `<algorithm>` 库中才有 `std::swap`。
*   **阅卷人视角**：408 允许使用 C/C++。如果你前面写着纯 C 的语法，突然调了一个没定义的 `swap`，严格的阅卷老师会认为你调用了“未定义函数”，扣除 1-2 分的代码细节分；宽容的老师可能算你伪代码放你一马。
*   **防扣分策略**：千万不要把命运交给阅卷人的心情。如果你执意要用图片里的交换法，在卷子上第一行直接写一个宏定义：
    `#define swap(a, b) {int temp = a; a = b; b = temp;}`
    或者老老实实在外面写一个 3 行的 `void swap(int* a, int* b)` 函数。

### 3. 王道给的模板也还行？
**客观评价**：王道的这个模板（双指针交换法）逻辑上没有任何错，如果你已经形成了肌肉记忆，绝对可以放心用。
**隐患提示**：它的代码耦合度太高。在例题 2-10 中，你可以看到它把 `Partition` 的所有内部逻辑，直接硬塞进了一个外层的 `while (true)` 里。在考场高压下，3 层嵌套 `while` 极容易让你把 `i` 和 `j` 的边界写错。

### 4. 如果用我之前给的“挖坑法”模板怎么写？
使用“挖坑法”，最大的好处是**代码极其模块化（解耦）**，并且**完全不需要考虑 `swap` 函数的扣分问题**。

下面是按照挖坑法改写的例题 2-10（寻找 $n/2$ 位置并划分），你看一下逻辑层次有多清晰：

```c
// 模块 1：纯粹的划分函数（与你学过的普通快排一模一样，直接默写）
int Partition(int A[], int low, int high) {
    int pivot = A[low]; 
    while (low < high) {
        while (low < high && A[high] >= pivot) high--;
        A[low] = A[high]; 
        while (low < high && A[low] <= pivot) low++;
        A[high] = A[low]; 
    }
    A[low] = pivot;
    return low; // 返回基准值最终落位所在的下标
}

// 模块 2：快速选择主逻辑（像二分查找一样干净）
void ans(int A[], int n) {
    int L = 0, R = n - 1;
    int target = n / 2;          // 我们要找的目标下标就是 n/2
    
    while (L <= R) {
        int pivot_pos = Partition(A, L, R); // 砍一刀，获取当前基准值落位
        
        if (pivot_pos == target) {
            return;                         // 恰好落在正中间，直接结束
        } else if (pivot_pos < target) {
            L = pivot_pos + 1;              // 目标在右边，彻底抛弃左区间，向右逼近
        } else {
            R = pivot_pos - 1;              // 目标在左边，彻底抛弃右区间，向左逼近
        }
    }
}
```

**对比总结**：
你看模块 2 的主逻辑，完全就是你在前面问我的“二分查找”模板。把复杂的数组交换操作封装在 `Partition` 函数里，你的大脑就不需要同时处理“数组元素怎么换”和“左右区间怎么缩”这两件不同的事。408 考场上，这种低认知负担的代码才是最抗压的。

# 折半
![[_attachments/image/03大题-1784534476180.jpeg]] 这两者的根本区别在于**搜索目标的性质不同**（找单点精确值 vs 找区间边界），并由此引发了**避免死循环**和**防止漏解**的底层状态控制要求。

直接拆解如下：

### 1. 为什么模板一是 `while (L <= R)`？
**适用场景**：精确查找（找特定值 `x`，找到就立刻退出）。
**核心机制**：
*   **搜索区间的语义**：`[L, R]` 代表的是**“尚未被检查过的元素集合”**。
*   **为什么必须是 `<=`**：当搜索进行到 `L == R` 时，意味着整个数组中**还有最后 1 个元素**（即 `A[L]`）没有被检查。你必须进入循环，通过 `A[mid] == x` 去验证它。如果写成 `L < R`，当只剩一个元素时循环会直接终止，这最后一个元素会被漏掉；如果它恰好是你要找的 `x`，函数就会错误地返回 `-1`。
*   **状态转换的保证**：在这个模板中，一旦 `A[mid]` 不是你要找的值，它就会被彻底抛弃。所以指针更新是严格的 `L = mid + 1` 和 `R = mid - 1`。这种每次都 `+1` 或 `-1` 的操作，保证了无论如何区间都在缩小，最终必定会触发 `L > R` 跳出循环，不会死循环。

### 2. 为什么模板二是 `while (L < R)`？
**适用场景**：边界查找（找第一个满足某条件的元素，如找第一个 `>= x` 的位置）。
**核心机制**：
*   **搜索区间的语义**：`[L, R]` 代表的是**“目标答案可能存在的候选区间”**。循环的目的不是“找到就停”，而是不断“夹逼、收缩”这个区间，把绝对不可能是答案的部分砍掉。
*   **为什么必须是 `<`**：当 `L == R` 时，意味着候选区间已经被夹逼到**只剩下最后 1 个元素**。既然只剩一个嫌疑人，那它必然就是最终的结果（或者再单独判断一次即可），不需要再继续“二分”了，所以应当立刻退出循环。
*   **死循环的致命问题**：这是最关键的点。注意模板二中的状态转移 `R = mid`（没有 `-1`）。
    如果在这里写 `while (L <= R)`，假设程序运行到了最后一步，`L == 5` 且 `R == 5`：
    1. 满足 `L <= R`，进入循环。
    2. 计算 `mid = (5 + 5) / 2 = 5`。
    3. 假设此时满足条件 `A[5] >= x`，执行 `R = mid`。
    4. 结果 `R` 依然等于 `5`。
    5. 下一次循环，`L` 和 `R` 还是 `5`，再次执行 `R = mid`，产生**死循环（Dead Loop）**。

### 考场上的固定搭配（硬规则）
为了防止出错，请严格绑定以下两组逻辑，不能混用：
1. **点查找**：循环条件用 `L <= R`，内部一旦不匹配，必须是 `L = mid + 1` 和 `R = mid - 1`，保证越过 `mid`。
2. **边界夹逼**：循环条件用 `L < R`，内部更新必定有一侧是保留 `mid` 的（如 `R = mid`），利用 `L == R` 作为收敛终止条件来防止死循环。


| 循环条件                   | 收缩方式                             | 用途              |
| ---------------------- | -------------------------------- | --------------- |
| `while(left < right)`  | `right = mid` / `left = mid+1`   | 找满足条件的第一个位置(边界) |
| `while(left <= right)` | `right = mid-1` / `left = mid+1` | 找某个确切的值         |
