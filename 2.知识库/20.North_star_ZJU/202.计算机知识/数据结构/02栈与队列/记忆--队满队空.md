### 一、扒开 `rear` 的两副面孔

队尾指针 `rear` 负责**入队（存数据）**。

#### 1. 当 `rear` 指向“下一个空位”时（最常见）

- **动作顺序：** 因为它指的就是空位，所以我们应该**先存数据，再让指针往后挪**。
    
    - 代码：`A[rear] = value; rear = (rear + 1) % M;`
        
- **反推初始化：** 我们希望第一个数据存在 `A[0]`。根据上面的代码，执行 `A[rear] = value` 时，`rear` 必须是 0。
    
- **结论：** 此时初始化必须是 **`rear = 0`**。
    

#### 2. 当 `rear` 指向“真实的队尾元素”时（你问的情况）

- **动作顺序：** 因为它当前指的位置已经有真实数据了（被占用了），所以新来一个元素时，必须**先让指针往后挪找空位，然后再存数据**。
    
    - 代码：`rear = (rear + 1) % M; A[rear] = value;`
        
- **反推初始化：** 我们希望第一个数据存入 `A[0]`。这意味着执行 `rear = (rear + 1) % M` 之后，`rear` 必须变成 0。
    
- **求解方程式：** 什么数加 1 对 M 取模等于 0？显然是 `M - 1`！
    
- **结论：** 此时初始化必须是 **`rear = M - 1`**。

### 二、 扒开 `front` 的两副面孔

队首指针 `front` 负责**出队（取数据）**。

#### 1. 当 `front` 指向“真实的队首元素”时（最常见）

- **动作顺序：** 因为它指着真实数据，所以出队时，我们**先取走数据，再让指针往后挪**。
    
    - 代码：`value = A[front]; front = (front + 1) % M;`
        
- **反推初始化：** 当队列存入了第一个元素（在 `A[0]`）后，我们去取它，`front` 必须刚好指着 0。
    
- **结论：** 此时初始化必须是 **`front = 0`**。
    

#### 2. 当 `front` 指向“真实的队首元素的前一个位置”时

- **动作顺序：** 因为它指着队首前面的空地，所以出队时，必须**先让指针往后挪，才能取到真实数据**。
    
    - 代码：`front = (front + 1) % M; value = A[front];`
        
- **反推初始化：** 要取走 `A[0]` 的数据，必须让 `front` 挪一步之后变成 0。
    
- **求解方程式：** `(front + 1) % M == 0`
    
- **结论：** 此时初始化必须是 **`front = M - 1`**。

### 三、 终极排列组合（四大门派）

既然 `front` 有 2 种定义，`rear` 有 2 种定义，乘起来就是 4 种搭配。

**前排提示：判断队空的万能法则！** 队空条件根本不用死记硬背。**队空的时候，指针的状态一定等于它们初始化的状态！**

#### 搭配 A：`front` 队首，`rear` 下一个空位（绝大多数教材的标准版）

- **动作：** `front` 先取后挪，`rear` 先存后挪。
    
- **初始化：** `front = 0`, `rear = 0`
    
- **队空条件：** `front == rear` (因为初始时 0 == 0)
    

#### 搭配 B：`front` 队首，`rear` 真实队尾（考研最爱出的变体）

- **动作：** `front` 先取后挪，`rear` 先挪后存。
    
- **初始化：** `front = 0`, `rear = M - 1`
    
- **队空条件：** `(rear + 1) % M == front` (因为初始时 `(M-1+1)%M == 0`，即 `0 == 0`)
    

#### 搭配 C：`front` 队首前一个，`rear` 真实队尾

- **动作：** `front` 先挪后取，`rear` 先挪后存。
    
- **初始化：** `front = M - 1`, `rear = M - 1`
    
- **队空条件：** `front == rear` (因为初始时 M-1 == M-1)
    

#### 搭配 D：`front` 队首前一个，`rear` 下一个空位（极少见，纯为恶心人）

- **动作：** `front` 先挪后取，`rear` 先存后挪。
    
- **初始化：** `front = M - 1`, `rear = 0`
    
- **队空条件：** `(front + 1) % M == rear` (因为初始时 `(M-1+1)%M == 0`)

### 四、 队满条件怎么推？

无论上面哪种搭配，如果采用**“牺牲一个存储单元”**的策略，推导队满条件只需记住一句口诀： **队满就是“队尾指针再往前试探着走一步，就会撞上队首指针”。**

比如拿考研最爱出的 **搭配 B** 来举例：

1. `rear` 指向真实队尾，`front` 指向真实队首。
    
2. `rear` 下一次存数据，本该去 `(rear + 1) % M` 这个位置。
    
3. 但是这个位置我们要**故意牺牲掉（留空）**。
    
4. 所以，如果再下一个位置 `(rear + 2) % M` 刚好就是 `front`，说明全满了，再也存不下了。
    
5. **搭配 B 的队满条件：** `(rear + 2) % M == front`。
    

#### 搭配 3：不差钱版（最大容量为 M，引入 size 变量）

_不再牺牲空间，把数组填满。_

- **初始状态：** `front = 0`, `rear = 0`, `size = 0`。
    
- **指针定义：** `rear` 通常指下一个空位（但其实指哪都不重要了）。
    
- **判断策略：** 额外申请一个整型变量 `size`。每次入队 `size++`，出队 `size--`。
    
- **队空条件：** `size == 0` （看，根本不需要管指针了）。
    
- **队满条件：** `size == M`。
    

#### 搭配 4：极致标志版（最大容量为 M，引入 tag 标记）

_也是不牺牲空间，但不用数字统计，用布尔标记。_

- **初始状态：** `front = 0`, `rear = 0`, `tag = 0`。
    
- **判断策略：** 额外申请一个标记变量 `tag`。
    
    - 如果最近一次操作是**入队**导致的，设 `tag = 1`。
        
    - 如果最近一次操作是**出队**导致的，设 `tag = 0`。
        
- **原理解读：** 只有不停入队才会导致队满，只有不停出队才会导致队空。所以当 `front == rear` 发生时，看看最近一次是啥操作就真相大白了。
    
- **队空条件：** `front == rear && tag == 0`
    
- **队满条件：** `front == rear && tag == 1`
