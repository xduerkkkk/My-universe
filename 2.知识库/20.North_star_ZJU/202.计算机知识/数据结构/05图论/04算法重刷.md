### 一、为什么变成了 `->` 而不是 `.`？

这是 C 语言中最基础但也最容易手滑的语法规则。区别仅仅在于**参数是怎么传进来的**：

1. **之前的题（用 `.`）**：
   函数定义是 `int IsConnected(ALGraph G)`。
   这里传入的是 `G` 这个**结构体变量本身**（传值调用）。既然 `G` 是个实体，访问它的成员必须用点操作符：`G.numVertices`。
2. **这道题（用 `->`）**：
   函数定义是 `bool DFS(ALGraph *G, ...)`。
   注意看，这里多了个 `*`。传入的是一个**指向结构体的指针**（传址调用）。既然 `G` 只是个内存地址，访问它指向的成员必须用箭头操作符：`G->numVertices`。

**408 考场建议：**
考试时，如果不要求严格写死函数签名，**强烈建议统一写成 `(ALGraph &G)`（C++ 引用传递）**。这样不仅不用复制庞大的图结构（省内存），而且在函数体里面你可以**全程舒舒服服地用 `G.numVertices`**，完美避开 `->` 和 `.` 混用的灾难。

*顺便指出王道代码里的一个**致命 Bug**（图片第 6 行）：*
代码写着 `ArcNode *p = G->VerticesList[v];`。
这在语法上是完全错误的！`VerticesList[v]` 是一个 `VNode` 结构体，而 `p` 是个边节点指针。
正确的写法必须是：**`ArcNode *p = G->VerticesList[v].firstarc;`**（因为 `VerticesList[v]` 是数组里的实体元素，所以用 `.`，然后取它的 `firstarc` 指针）。

### 二、这里也能用“进门前打标记”的统一模板吗？

**完全可以！而且改写后，判断是否有环的逻辑会变得更加清晰。**

这道题的核心算法是**“无向图找环”**：如果在 DFS 过程中，碰到了一个已经访问过的顶点（`visited[u] == true`），并且这个顶点**不是你刚刚走过来的那个爹（`u != parent`）**，那就说明图里绝对有环。

我们用你总结的**“进门前打标记”**法则来重构这道题，代码会非常工整：

```c
// 统一模板重构版 DFS
bool DFS(ALGraph *G, int v, int parent) {
    // 进来不打标记了
    
    // 修正王道的 Bug，加上 .firstarc
    ArcNode *p = G->VerticesList[v].firstarc; 
    
    while (p != NULL) {
        int u = p->adjvex; // 拿到邻居 u
        
        if (visited[u] == false) {
            // 邻居没去过
            visited[u] = true;           // 【进门前打标记】
            if (DFS(G, u, v) == true) {  // 【进门深入，且告诉 u 它的爹是 v】
                return true;             // 如果子树找到了环，直接向上汇报
            }
        } 
        else {
            // 邻居去过了！检查它是不是回头路
            if (u != parent) {
                return true; // 既去过，又不是爹，绝对是遇到环了！
            }
        }
        p = p->nextarc;
    }
    return false; // 当前节点的所有分支都没环
}
```

这道题正是验证了我们上一轮得出的结论：**408 绝对不会让你从头到尾手写完整的 Kruskal 算法！** 

你看，这道题通过直接给你一个 `FindEdge()` 函数，**把 Kruskal 最耗时、代码最长的“边集数组排序”这一步直接封装屏蔽掉了**。
你在这道题里真正需要写的，仅仅是 Kruskal 算法剩下的核心外壳：**并查集（Union-Find）判环**。

以下是这道题三个小问的精确解答和代码拆解：

### (1) `FindEdge()` 应该使用什么数据结构？为什么？
*   **答案**：**小根堆（Min-Heap）** 或优先级队列。
*   **原因**：`FindEdge()` 的核心操作是“每次从动态集合中取出权值最小的边”。小根堆能够在 $O(1)$ 时间复杂度获取最小边，并在取出后以 $O(\log |E|)$ 的时间复杂度调整维持堆的性质，是处理此类需求时间复杂度最优的数据结构。

### (2) 算法的基本设计思想
本题本质是**简化版的 Kruskal 算法**。
1. 初始化一个并查集，让图中的每个顶点各自成为一个独立的连通分量（集合）。
2. 初始化最小生成树权值之和 `sum = 0`，已加入的边数 `edgeCount = 0`。
3. 循环调用 `FindEdge()` 获取当前权值最小的边。
4. 获取该边的两个端点 `ivex` 和 `jvex`，在并查集中查找它们的根节点。
   * 若根节点不同，说明加入此边**不会构成环**，则将这条边加入最小生成树（累加权值 `sum`，`edgeCount++`），并将两个集合合并。
   * 若根节点相同，说明会构成环，直接丢弃该边。
5. 当 `edgeCount == G.numVertices - 1` 时，生成树构建完成，返回 `sum`。

### (3) 满分 C 语言代码实现

在 408 考场上写并查集，**绝不需要写路径压缩或按秩合并**，用最朴素的一维 `parent` 数组即可拿满分。

```c
// 辅助函数：并查集的 Find 操作（找根节点）
int Find(int parent[], int x) {
    // 只要 parent[x] 不等于自己，说明还没到根，顺着指针往上找
    while (parent[x] != x) {
        x = parent[x];
    }
    return x;
}

// 核心求解函数
int MSTWeight(ALGraph G) {
    int parent[MAXV]; 
    // 1. 初始化并查集：一开始每个顶点的根节点都是它自己（各自独立）
    for (int i = 0; i < G.numVertices; i++) {
        parent[i] = i; 
    }
    
    int sum = 0;       // 记录最小生成树的总权值
    int edgeCount = 0; // 记录已经成功加入的边数
    
    // 最小生成树的边数必定等于 顶点数 - 1
    while (edgeCount < G.numVertices - 1) {
        ArcNode *edge = FindEdge(); // 获取当前全局最小边
        if (edge == NULL) break;    // 防御性编程：图不连通时边取完了
        
        // 2. 查：找到这条边两个端点所属集合的根节点
        int rootI = Find(parent, edge->ivex);
        int rootJ = Find(parent, edge->jvex);
        
        // 3. 判环与并
        if (rootI != rootJ) { 
            // 根节点不同，说明不在同一个集合，加这条边不会形成环
            sum += edge->weight;          // 累加权值
            edgeCount++;                  // 边数 + 1
            parent[rootI] = rootJ;        // 合并集合：让一个根认另一个根做爹
        }
        // 如果 rootI == rootJ，说明在同一个集合，直接无视这条边（进入下一次循环）
    }
    
    return sum;
}
```

### 考场避坑细节提示：

1. **结构体的异常设计**：注意看题目给的 `ArcNode` 结构体，里面同时包含了 `ivex` 和 `jvex`。在标准的邻接表中，边节点一般只有 `adjvex`（指向的终点）。题目这样设计，就是为了让你从 `FindEdge()` 拿到边之后，能立刻知道这条边的两个端点是谁，从而方便你传入并查集。**考试时一定要以题目给定的结构体字段为准，不要凭借记忆瞎写 `edge->adjvex`。**
2. **并查集的初始化**：并查集有两种常见初始化方式。一种是 `parent[i] = -1`（此时找根的条件是 `while(parent[x] >= 0)`）；另一种是我上面写的 `parent[i] = i`。强烈推荐 `parent[i] = i`，因为它非常符合直觉——“我的老大于等于我自己”，逻辑更清晰，不容易出现数组下标越界。
3. **循环终止条件**：`edgeCount < G.numVertices - 1` 是必须的。图中有 $|V|$ 个点，最小生成树恰好只有 $|V|-1$ 条边。找满就立刻停，这是算法的最优停止条件。

这句话在图论和离散数学中的严格定义是：**将图的所有顶点集合 $V$ 划分为两个集合 $V_1$ 和 $V_2$，满足 $V_1 \cup V_2 = V$ 且 $V_1 \cap V_2 = \emptyset$。**

结合二分图的性质，这句话在物理结构和代码实现上的实际含义，我为你拆解如下：

### 1. 物理含义：边只能跨区，不能同区
“分割为两个子集”的核心限制条件在于**图中的边**：
*   **绝对不允许**集合 $V_1$ 内部的两个顶点之间存在边。
*   **绝对不允许**集合 $V_2$ 内部的两个顶点之间存在边。
*   图中**所有的边**，必然是一端连接在 $V_1$ 的某个顶点，另一端连接在 $V_2$ 的某个顶点。

### 2. 算法视角的翻译：染色法 (Graph Coloring)
在计算机内存里，我们不可能物理上把一个数组劈成两半。代码中表达“两个互不相交的子集”的标准机制是**引入一个状态数组（通常命名为 `color` 数组）**。

*   **状态定义**：开辟一个 `int color[MAXV]`，初始化全为 `0`（表示还未划分）。用 `1` 代表该顶点属于子集 $V_1$，用 `2` 代表该顶点属于子集 $V_2$。
*   **划分过程（交替染色）**：如果你把顶点 $u$ 强行分到了集合 1（染成了 1），那么由于同集合不能有边，$u$ 的**所有直接邻居**，必须无条件被分到集合 2（染成 2）。邻居的邻居，又必须分回集合 1。
*   **失败条件（冲突）**：如果在划分过程中，你发现顶点 $u$ 是集合 1，而它的某个邻居 $w$ **已经被提前分配到了集合 1**，说明存在一条边连接了同集合的两个顶点。划分彻底失败，原图**不是**二分图。

### 3. 这道题的考场解题思路
这道题是 408 中非常经典的“图的遍历变体”。只要在普通的 DFS 或 BFS 模板上，把原本的 `visited` 数组替换成 `color` 数组即可。

**以 BFS 为例的核心逻辑推演：**
1.  初始化 `int color[MAXV] = {0}`。
2.  从顶点 0 启动（假设连通），将其标记为属于子集 1：`color[0] = 1;` 并入队。
3.  在队列 `while` 循环中出队一个顶点 `curr`。
4.  遍历 `curr` 的所有邻居 `w`（即在邻接矩阵中找 `Edge[curr][w] == 1`）：
    *   **情况 A**：如果 `color[w] == 0`（还没划分），那就给它分到对立的集合。即 `color[w] = 3 - color[curr];`（利用 `3-1=2`，`3-2=1` 实现快速翻转），然后 `w` 入队。
    *   **情况 B**：如果 `color[w] != 0`（已经划分过了），直接检查 `color[w] == color[curr]`。如果相等，说明发生了同集合内部连边，立刻 `return 0;`（不是二分图）。
5.  如果队列空了都没发生冲突，`return 1;`（是二分图）。

*(注：408 遇到这种题，无论题目里那句“至少包含两个顶点且任何简单回路包含的边数为偶数”看起来多吓人，那只是充要条件的数学废话。在代码层面，**二分图判定 = BFS/DFS 交替染色 + 冲突检测**。)*

以下是这道题的 408 满分标准代码。

这里我们采用 **BFS（广度优先搜索）配合交替染色法**。代码中严格遵守了前面提到的“数组模拟队列”、“边界使用 `numV`” 以及“防范非连通图”的原则。

```c
int IsBipartite(MGraph G) {
    // 状态数组：0 表示未染色（未访问），1 表示分到集合1，2 表示分到集合2
    int color[MAXV] = {0}; 
    
    // 数组模拟队列
    int q[MAXV]; 
    int front = 0, rear = 0;
    
    // 1. 外层循环：防止图是非连通的，必须确保每个孤立的子图都被检查到
    for (int i = 0; i < G.numV; i++) {
        if (color[i] == 0) { 
            // 发现未染色的连通分量起点
            color[i] = 1;      // 【启动前打标记】默认先分到集合 1
            q[rear++] = i;     // 起点入队
            
            // 2. 针对当前连通分量的 BFS
            while (front < rear) {
                int curr = q[front++]; // 出队当前顶点
                
                // 遍历 curr 的所有邻居 w (因为是邻接矩阵，遍历这一行即可)
                for (int w = 0; w < G.numV; w++) {
                    // Edge[curr][w] != 0 表示有边（部分题目无权图用1，带权图用权值，!=0最稳妥）
                    if (G.Edge[curr][w] != 0) { 
                        
                        if (color[w] == 0) {
                            // 情况 A：邻居还没分集合
                            // 【进门前打标记】利用 3 - color 实现 1 和 2 的交替翻转
                            color[w] = 3 - color[curr]; 
                            q[rear++] = w; // 邻居入队
                        } 
                        else if (color[w] == color[curr]) {
                            // 情况 B：邻居已经分过集合，且居然和自己同属一个集合！
                            return 0; // 发生冲突，同集合内部有连边，绝对不是二分图
                        }
                        // 如果 color[w] 已经被染成了相反的颜色，则说明安全，什么都不用做
                    }
                }
            }
        }
    }
    
    // 全图遍历完毕，没有任何冲突，则是二分图
    return 1; 
}
```


### 考场代码细节拆解（核心采分点）

1. **极其巧妙的状态翻转：`color[w] = 3 - color[curr];`**
   这是一个拿高分的数学小技巧。如果当前顶点是 `1`，邻居就变成 `3 - 1 = 2`；如果当前顶点是 `2`，邻居就变成 `3 - 2 = 1`。这比你写一大坨 `if (color == 1) else if (color == 2)` 要清爽得多，阅卷人一眼就能看出你的基本功。
2. **邻接矩阵的边判定：`G.Edge[curr][w] != 0`**
   题目给的结构体定义叫 `Edge[MAXV][MAXV]`，如果是纯粹的无向无权图，通常 `1` 表示有边；如果是带权图，这里存的是权重。在不知道具体约定的情况下，写 `!= 0`（或者针对带权图写 `!= \infty`，但通常 `!= 0` 足以应付二分图判定）是泛用性最强的写法。
3. **外层 `for` 循环（防漏扫机制）**
   这道题如果图不连通（比如两个独立的三角形组成的图），只从 `0` 号顶点出发，你会漏掉另一个三角形，错误地返回 `1`。外层的 `for` 循环确保了即使图被割裂成了几块，每一块都会被拉出来做一次染色检测。

**总结**：这就是 408 图论算法题的真实面貌——没有 Kruskal 那种长篇大论，本质上就是考你**能不能在基础的 BFS 模板里，加一个状态判定逻辑（颜色/连通性）**。这套 BFS 染色模板，你已经在纸上完全可以拿下 15 分了。


# 4 此题用并查集再练一下
![[_attachments/image/04算法重刷-1785482125482.jpeg]]


### 算法基本设计思想

1. **初始化并查集与计数器：** 
   定义辅助数组 `parent[MAXV]`，初始时将每一个顶点看作一个独立的连通分量，令 `parent[i] = i` ($0 \le i < \text{G.numVertices}$)。连通分量计数器 `count` 初始化为图的顶点数 `G.numVertices`。
2. **查操作（`find`）：** 
   实现带路径压缩的查找函数，用于寻找指定顶点所在集合的根节点。
3. **遍历弧结点与合并（`union`）：** 
   遍历邻接表中的所有边 $(i, j)$。利用 `find` 函数分别查找顶点 $i$ 和顶点 $j$ 的根节点 `rootI` 与 `rootJ`：
   * 若 `rootI != rootJ`，说明这两个顶点原本属于不同的连通分量。通过把其中一个根节点的父节点指向另一个根节点（如 `parent[rootI] = rootJ`）将两个集合合并，同时将 `count` 减 1。
   * 若 `rootI == rootJ`，说明两顶点已处于同一连通分量中，不做处理。
4. **返回结果：** 
   遍历完邻接表中的所有边后，`count` 的值即为连通分量的个数。

---

### C 语言代码实现

```c
#include <stdio.h>

#define MAXV 100 // 假设最大顶点数

// 带路径压缩的查找函数
int find(int parent[], int x) {
    if (parent[x] == x)
        return x;
    // 路径压缩：递归查找根节点并将沿途节点的父节点直接指向根节点
    return parent[x] = find(parent, parent[x]);
}

// 计算无向图连通分量个数的函数
int components(ALGraph G) {
    int parent[MAXV];
    int count = G.numVertices; // 初始连通分量数等于顶点数

    // 1. 初始化并查集
    for (int i = 0; i < G.numVertices; i++) {
        parent[i] = i;
    }

    // 2. 遍历邻接表中的所有边
    for (int i = 0; i < G.numVertices; i++) {
        ArcNode *p = G.VerticesList[i].firstarc;
        while (p != NULL) {
            int j = p->adjvex;
            
            // 无向图的一条边 (i, j) 在邻接表中存了两次
            // 通过 i < j 限制只处理一次，避免重复查找（不加此限制逻辑同样正确）
            if (i < j) {
                int rootI = find(parent, i);
                int rootJ = find(parent, j);

                // 两顶点不在同一连通分量，进行合并
                if (rootI != rootJ) {
                    parent[rootI] = rootJ; // 合并集合
                    count--;               // 连通分量数减 1
                }
            }
            p = p->nextarc; // 指向下一条弧
        }
    }

    return count;
}
```

---

### 算法复杂度分析

* **时间复杂度：$O(V + E \cdot \alpha(V))$**
  * 初始化 `parent` 数组需要 $O(V)$ 时间。
  * 邻接表共有 $2E$ 个弧结点，遍历邻接表需要 $O(V + E)$ 时间。
  * 每条边最多触发一次并查集的合并操作。由于采用了带路径压缩的 `find` 函数，单次操作的均摊时间复杂度为 $O(\alpha(V))$（其中 $\alpha$ 为反阿克曼函数，当 $V$ 在实际范围内时 $\alpha(V) \le 4$，可视为常数 $O(1)$）。
  * 综合时间复杂度为 $O(V + E)$。

* **空间复杂度：$O(V)$**
  * 需要一个大小为 $V$ 的辅助数组 `parent` 存储父节点信息。
  * `find` 函数递归调用的栈深度最大为 $O(V)$。
  * 综合空间复杂度为 $O(V)$。

### （1）应该采用哪种数据结构保存？
**答案：十字链表（Orthogonal List）。**
*   **判断依据**：题目明确说是“**有向**完全图”。
*   **核心考点（必须记住的死规则）**：
    *   **十字链表**：专门为**有向图**设计的。它完美解决了有向图邻接表“找入度困难”、逆邻接表“找出度困难”的问题，把出度和入度链表缝合在了一起。
    *   **邻接多重表**：专门为**无向图**设计的。它解决的是无向图邻接表中“一条边被存储了两次，删除某条边时极度麻烦”的问题。

### （2）数据结构定义（十字链表）
十字链表的节点定义比普通邻接表多了一倍的指针。你不需要默写，但必须看懂里面的每一个英文单词是什么意思：

```c
#define MAXV 100

// 1. 弧（边）节点
typedef struct ArcNode {
    int tailvex, headvex;          // tailvex 是起点(弧尾)，headvex 是终点(弧头)
    struct ArcNode *hlink, *tlink; // hlink 指向下一个"同终点"的弧；tlink 指向下一个"同起点"的弧
    // int weight;                 // 如果有权值可以加这个
} ArcNode;

// 2. 顶点节点
typedef struct VNode {
    int data;                      // 顶点信息
    ArcNode *firstin, *firstout;   // firstin 指向第一条入弧，firstout 指向第一条出弧
} VNode;

// 3. 整个十字链表图
typedef struct {
    VNode xlist[MAXV];             // 顶点数组 (xlist 代表十字链表)
    int vexnum, arcnum;            // 顶点数和弧数
} OLGraph;
```
**看懂十字链表的诀窍：** `tailvex` 对应 `tlink`（沿着它走，全是同起点的边，即计算出度）；`headvex` 对应 `hlink`（沿着它走，全是同终点的边，即计算入度）。

### （3）判断有向完全图的代码实现
**算法设计思想：**
在简单有向图（没有自己指自己的环，没有重复的边）中，“有向完全图”在数学上有一个极其严苛的等价条件：
**图中的每一个顶点的出度，必须恰好等于 `vexnum - 1`。** （或者总边数必定等于 $V \times (V-1)$）。
因此，我们只需要遍历十字链表，顺着每个顶点的 `firstout` 和 `tlink` 指针去数它的出度。如果发现任何一个顶点的出度不等于 $V-1$，直接返回 0。

**满分代码实现：**
```c
int IsComplete(OLGraph G) {
    // 快速拦截：有向完全图的总弧数必须严格等于 n*(n-1)
    if (G.arcnum != G.vexnum * (G.vexnum - 1)) {
        return 0; 
    }
    
    // 严谨校验：遍历每一个顶点，检查出度
    for (int i = 0; i < G.vexnum; i++) {
        int outDegree = 0; // 记录当前顶点 i 的出度
        
        // 从顶点 i 的第一条出弧开始找
        ArcNode *p = G.xlist[i].firstout;
        
        // 顺着 tlink (同起点指针) 往下捋，数出度
        while (p != NULL) {
            outDegree++;
            p = p->tlink; // 注意：在十字链表中，找下一个出边必须用 tlink！
        }
        
        // 只要有一个顶点的出边数不等于 顶点总数-1，就不是完全图
        if (outDegree != G.vexnum - 1) {
            return 0;
        }
    }
    
    return 1; // 所有顶点的出度都达标，是有向完全图
}
```
