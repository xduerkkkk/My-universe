# DFS、BFS 

进入图（Graph）的范畴后，图的 DFS 和 BFS 代码结构与树非常相似，但有一个**决定性的物理差异：图有环**。
因此，图的遍历核心是：**必须引入一个 `visited` 数组记录状态，防止死循环**。同时，由于图可能是不连通的（存在多个独立的连通分量），**必须有一个外层的控制函数**来扫描所有顶点。

以下是 408 考场上必须肌肉记忆的图遍历模板（以最常考的**邻接矩阵**为例，并在注释中标注**邻接表**的写法）。

---

### 全局状态定义
```c
#define MAX_VERTEX_NUM 100
bool visited[MAX_VERTEX_NUM]; // 访问标记数组，初始全为 false
```

---

### 一、深度优先搜索 (DFS - Depth-First Search)
**核心机制**：利用**函数调用栈（递归）**。一条路走到黑，碰到死胡同（所有邻接点均已访问）就回溯（Return 到上一层函数）。

#### 1. 外层控制函数（处理非连通图必备）
```c
void DFSTraverse(MGraph G) {
    // 1. 初始化标记数组
    for (int v = 0; v < G.vexnum; ++v) {
        visited[v] = false; 
    }
    
    // 2. 遍历每一个顶点，防止有孤立的连通分量漏扫
    for (int v = 0; v < G.vexnum; ++v) {
        if (!visited[v]) {
            DFS(G, v); // 只要没访问过，就以它为起点发起一次深入遍历
        }
    }
}
```

#### 2. DFS 核心递归函数
```c
void DFS(MGraph G, int v) {
    visit(v);          // 1. 访问当前顶点 v (打印数据等)
    visited[v] = true; // 2. 立即打上已访问标记
    
    // 3. 扫描 v 的所有邻居
    // 【邻接矩阵写法】
    for (int w = 0; w < G.vexnum; ++w) {
        // Edge[v][w] == 1 表示有边，且 w 没被访问过
        if (G.Edge[v][w] == 1 && !visited[w]) { 
            DFS(G, w); // 递归深入下一个顶点 w
        }
    }
    
    /* 
    【邻接表替代写法】(如果题目给的是邻接表 ALGraph)
    for (ArcNode *p = G.vertices[v].firstarc; p != NULL; p = p->nextarc) {
        int w = p->adjvex;
        if (!visited[w]) {
            DFS(G, w);
        }
    }
    */
}
```

### 二、广度优先搜索 (BFS - Breadth-First Search)
**核心机制**：利用**队列**。像水波纹一样，先访问起点，再把起点的所有直接邻居入队，再依次出队访问。

#### 1. 外层控制函数（与 DFS 完全一致，仅替换调用名）
```c
void BFSTraverse(MGraph G) {
    for (int v = 0; v < G.vexnum; ++v) {
        visited[v] = false; 
    }
    for (int v = 0; v < G.vexnum; ++v) {
        if (!visited[v]) {
            BFS(G, v); 
        }
    }
}
```

顶点
#### 2. BFS 核心队列函数（408 高频考点）
```c
void BFS(MGraph G, int v) {
    int q[MAX_VERTEX_NUM];    // 数组模拟队列
    int front = 0, rear = 0;
    
    visit(v);                 // 1. 访问起点
    visited[v] = true;        // 2. 打标记
    q[rear++] = v;            // 3. 起点入队
    
    while (front < rear) {
        int curr = q[front++]; // 出队当前顶点
        
        // 扫描 curr 的所有直接邻居
        // 【邻接矩阵写法】
        for (int w = 0; w < G.vexnum; ++w) {
            if (G.Edge[curr][w] == 1 && !visited[w]) {
                visit(w);          // 先访问
                visited[w] = true; // ★ 致命细节：必须在这里打标记！
                q[rear++] = w;     // 入队
            }
        }
        
        /* 
        【邻接表替代写法】
        for (ArcNode *p = G.vertices[curr].firstarc; p != NULL; p = p->nextarc) {
            int w = p->adjvex;
            if (!visited[w]) {
                visit(w);
                visited[w] = true;
                q[rear++] = w;
            }
        }
        */
    }
}
```

### 1. 能不能用 `bool` 和 ={0}快捷初始化？

**完全可以，而且极其推荐！**

在 408 答题卡上，你为了省时间，绝对可以直接写：
*   `int visited[MAXV] = {0};`
*   或者 `bool visited[MAXV] = {false};`（借用 C++ 特性）

**底层机制**：在 C/C++ 中，当你对数组进行部分初始化时，编译器会自动将剩余的所有元素初始化为 `0`（或 `false`）。所以 =   {0} 完美替代了那个冗长的 `for` 循环，这在考场上能帮你省下宝贵的 1 分钟和几行卷面空间。

---

### 2. 能不能把 DFS 的打标记移到上一行（与 BFS 统一）？

**你的推导极其精准！完全可以，而且这是一个绝妙的“统一记忆法”。**

如果你把 `visited[w] = 1;` 放在 `DFS(w)` 之前，你的 DFS 递归代码就会变成这样：
```c
void DFS(ALGraph G, int v, int visited[]) {
    // 进来就不打标记了
    ArcNode *p = G.VerticesList[v].firstarc;
    while (p != NULL) {
        int w = p->adjvex;
        if (visited[w] == 0) {
            visited[w] = 1;       // 【1. 进去前先打标记】
            DFS(G, w, visited);   // 【2. 再深入】
        }
        p = p->nextarc;
    }
}
```
正如你自己敏锐察觉到的，**代价是：主函数在启动第一步时，必须手动给起点打上标记。** 
主函数必须这样写：
```c
int visited[MAXV] = {0}; // 快捷初始化
visited[0] = 1;          // 【代价：启动前必须手动给起点打标记】
DFS(G, 0, visited);      // 启动！
```

### 3. 确立你的“考场通用模板”

你刚刚自己悟出的这个道理，非常适合作为你个人的考场肌肉记忆。以后无论是 DFS 还是 BFS，你只要死记一条黄金法则：

> **“只要准备进门（入队 / 递归调用），必须在进门前的一瞬间打上 `visited=1` 的标记！启动点也要在启动前打标记！”**

你看，按照你的这个法则，DFS 和 BFS 的核心控制逻辑变得**完全对称**，再也不会搞混了：

**【BFS 的进门前打标记】**
```c
visited[0] = 1; // 启动前打标记
q[rear++] = 0;  // 进门(入队)

// 循环内...
if (visited[w] == 0) {
    visited[w] = 1; // 进门前打标记
    q[rear++] = w;  // 进门(入队)
}
```

**【DFS 的进门前打标记】**
```c
visited[0] = 1;     // 启动前打标记
DFS(G, 0, visited); // 进门(递归)

// 递归函数内...
if (visited[w] == 0) {
    visited[w] = 1;       // 进门前打标记
    DFS(G, w, visited);   // 进门(递归)
}
```

**总结：**
用 `int visited[MAXV] = {0};` 替代 `for` 循环；用“进门前打标记”统领 DFS 和 BFS。你现在的代码认知已经不仅是停留在“看懂”，而是到了“重构”的层面，保持这种自己梳理底层规律的状态，41 题你会做得很顺。
# DIJSKTRA
### 一、 djiskra 算法的 visited 数组是干啥的？能删掉吗？

**结论：绝对不能删。如果删掉，算法会陷入死循环。**

在 408 教材（如严蔚敏版或王道）中，Dijkstra 算法里的 `visited` 数组通常被命名为 `final[]` 或者集合 $S$。它与 DFS/BFS 中的 `visited` **物理含义完全不同**：
*   **DFS/BFS 的 `visited`**：表示“这个顶点我已经**碰过**了（入队/入栈了），别再把它加进来了”。
*   **Dijkstra 的 `visited`（即 `final`）**：表示“这个顶点到起点的最短路径已经被**永久锁定（全局最优）**，以后绝对不会再有更短的路能到它了”。

**为什么删掉会死循环？**
Dijkstra 是一个**贪心算法**。它的核心运转机制是：每一轮都要在“**还没被锁定的顶点（`visited == false`）**”中，挑出一个目前距离起点最近的顶点。
如果你删掉了 `visited` 数组，起点的距离 `dist[start] = 0` 永远是全局最小的。那么算法在每一轮循环中，都会永远挑选 `start` 这个顶点，永远在用 `start` 去更新别人，导致死循环，剩下的顶点根本得不到处理。

### 二、为什么不一开始就把 visited[start] 标记为 true？

你的观察非常准确。在普通的 DFS/BFS 中，我们习惯 `visit(start); visited[start]=true; enqueue(start);`。
但在标准的 Dijkstra 代码中，初始化只有 `dist[start] = 0`，而 `visited[start]` 依然是 `false`。

这是由 Dijkstra 的**代码结构一致性（即统一的松弛逻辑）**决定的。我用底层运行步骤给你拆解：

Dijkstra 的主循环规定了一个严格的“三步曲”动作：
1. **找最小**：在所有 `visited == false` 的顶点中，找 `dist` 最小的顶点 $u$。
2. **上锁**：将 $u$ 标记为锁定，即 `visited[u] = true`。
3. **松弛**：用 $u$ 去更新它所有相邻顶点 $w$ 的距离（`dist[w] = min(dist[w], dist[u] + weight)`）。

**如果你一开始就把 `visited[start] = true`：**
那么主循环的第一轮，在执行“找最小”时，就会跳过 `start`，去从其他顶点里找。可是此时其他顶点的 `dist` 都是 $\infty$，你挑谁都不对。
为了解决这个问题，你就必须在进入主循环**之前**，额外写一段代码，把 `start` 的所有邻居的 `dist` 先更新一遍。这等于把主循环里的“松弛”逻辑在外面又复制了一遍，代码极其冗余。

**标准代码的精妙之处：**
一开始所有顶点的 `visited` 都是 `false`，但给 `dist[start]` 赋予了绝对优势的 `0`。
当进入主循环的第一轮时：
*   **第 1 步找最小**：遍历所有 `false` 的点，必定会把 `dist` 为 0 的 `start` 挑出来作为当前的 $u$。
*   **第 2 步上锁**：此时顺理成章地执行 `visited[start] = true`。
*   **第 3 步松弛**：用 `start` 去更新它所有邻居的距离。

**总结**：
Dijkstra 不提前标记 `visited[start] = true`，是为了**让起点也能顺畅地走一遍主循环的“找最小 -> 上锁 -> 松弛邻居”的标准流程**，从而保证外层循环精确执行 $|V|$ 次，每次锁定一个顶点，代码没有任何冗余。
