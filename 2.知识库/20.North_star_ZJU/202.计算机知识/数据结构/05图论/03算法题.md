# DFS、BFS 

进入图（Graph）的范畴后，图的 DFS 和 BFS 代码结构与树非常相似，但有一个**决定性的物理差异：图有环**。
因此，图的遍历核心是：**必须引入一个 `visited` 数组记录状态，防止死循环**。同时，由于图可能是不连通的（存在多个独立的连通分量），**必须有一个外层的控制函数**来扫描所有顶点。

以下是 408 考场上必须肌肉记忆的图遍历模板（以最常考的**邻接矩阵**为例，并在注释中标注**邻接表**的写法）。

---

### 全局状态定义
```c
#define MAX_VERTEX_NUM 100
bool visited[MAX_VERTEX_NUM]; // 访问标记数组，初始全为 false
```

---

### 一、深度优先搜索 (DFS - Depth-First Search)
**核心机制**：利用**函数调用栈（递归）**。一条路走到黑，碰到死胡同（所有邻接点均已访问）就回溯（Return 到上一层函数）。

#### 1. 外层控制函数（处理非连通图必备）
```c
void DFSTraverse(MGraph G) {
    // 1. 初始化标记数组
    for (int v = 0; v < G.vexnum; ++v) {
        visited[v] = false; 
    }
    
    // 2. 遍历每一个顶点，防止有孤立的连通分量漏扫
    for (int v = 0; v < G.vexnum; ++v) {
        if (!visited[v]) {
            DFS(G, v); // 只要没访问过，就以它为起点发起一次深入遍历
        }
    }
}
```

#### 2. DFS 核心递归函数
```c
void DFS(MGraph G, int v) {
    visit(v);          // 1. 访问当前顶点 v (打印数据等)
    visited[v] = true; // 2. 立即打上已访问标记
    
    // 3. 扫描 v 的所有邻居
    // 【邻接矩阵写法】
    for (int w = 0; w < G.vexnum; ++w) {
        // Edge[v][w] == 1 表示有边，且 w 没被访问过
        if (G.Edge[v][w] == 1 && !visited[w]) { 
            DFS(G, w); // 递归深入下一个顶点 w
        }
    }
    
    /* 
    【邻接表替代写法】(如果题目给的是邻接表 ALGraph)
    for (ArcNode *p = G.vertices[v].firstarc; p != NULL; p = p->nextarc) {
        int w = p->adjvex;
        if (!visited[w]) {
            DFS(G, w);
        }
    }
    */
}
```

### 二、广度优先搜索 (BFS - Breadth-First Search)
**核心机制**：利用**队列**。像水波纹一样，先访问起点，再把起点的所有直接邻居入队，再依次出队访问。

#### 1. 外层控制函数（与 DFS 完全一致，仅替换调用名）
```c
void BFSTraverse(MGraph G) {
    for (int v = 0; v < G.vexnum; ++v) {
        visited[v] = false; 
    }
    for (int v = 0; v < G.vexnum; ++v) {
        if (!visited[v]) {
            BFS(G, v); 
        }
    }
}
```

顶点
#### 2. BFS 核心队列函数（408 高频考点）
```c
void BFS(MGraph G, int v) {
    int q[MAX_VERTEX_NUM];    // 数组模拟队列
    int front = 0, rear = 0;
    
    visit(v);                 // 1. 访问起点
    visited[v] = true;        // 2. 打标记
    q[rear++] = v;            // 3. 起点入队
    
    while (front < rear) {
        int curr = q[front++]; // 出队当前顶点
        
        // 扫描 curr 的所有直接邻居
        // 【邻接矩阵写法】
        for (int w = 0; w < G.vexnum; ++w) {
            if (G.Edge[curr][w] == 1 && !visited[w]) {
                visit(w);          // 先访问
                visited[w] = true; // ★ 致命细节：必须在这里打标记！
                q[rear++] = w;     // 入队
            }
        }
        
        /* 
        【邻接表替代写法】
        for (ArcNode *p = G.vertices[curr].firstarc; p != NULL; p = p->nextarc) {
            int w = p->adjvex;
            if (!visited[w]) {
                visit(w);
                visited[w] = true;
                q[rear++] = w;
            }
        }
        */
    }
}
```

### 三、考场踩坑点精确制导

1. **忘记写外层函数 (`Traverse`)**
   408 题目经常给你一个复杂的图让你求连通分量个数。连通分量的个数就是外层函数里 `if (!visited[v])` 条件成立并调用 `DFS/BFS` 的次数。如果不写外层函数，遇到非连通图就会漏掉孤立节点，直接扣 3-5 分。

2. **BFS 打标记 `visited[w] = true` 的时机错误（极其致命）**
   在 BFS 代码中，对邻接点 `w` 的 `visited[w] = true` 赋值，**必须放在 `w` 入队之前（即与 `visit(w)` 挨着）**。
   *错误写法：*如果你把打标记放到 `w` 出队的时候才打，会导致什么结果？如果 `w` 同时是 `curr1` 和 `curr2` 的邻居，`curr1` 扫描到 `w` 时，因为 `w` 还没出队没被标记，`w` 会被推入队列；随后 `curr2` 扫描到 `w`，发现它还是没被标记，又把 `w` 推入队列。这会导致同一个节点在队列中出现多次，造成内存越界，逻辑彻底崩盘。

3. **时间复杂度与空间复杂度（必考默写点）**
   *   **时间复杂度**：只取决于存储结构，与 DFS/BFS 方法无关。
       *   邻接矩阵：因为双重 `for` 循环遍历矩阵，必须检查每一个 `Edge[v][w]`，复杂度必定为 **$O(|V|^2)$**（$|V|$ 为顶点数）。
       *   邻接表：扫描每个顶点的链表，总共只遍历 $|V|$ 个顶点和 $|E|$ 条边，复杂度为 **$O(|V| + |E|)$**。
   *   **空间复杂度**：DFS 的递归栈深度和 BFS 的队列长度，在最坏情况下（如图退化成一条线/所有点连向同一个点）都可能装入所有的顶点，因此两者空间复杂度均为 **$O(|V|)$**。
