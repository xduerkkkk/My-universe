# 文件内部数据的组织形式
- 流式文件
- 记录式文件
	 记录式文件有多条记录。一条记录，有多个数据项。
	 有一个数据项是关键字，记录长度。同时各个记录，有可能是定长，有可能是可变长。
	 - 链式存储、顺序存储的可变长无法随机存取
		 - 故而引入索引文件，索引文件本身是定长、顺序文件
		     - 进一步，将记录分组，每组只建一个索引项（稀疏索引），索引项记录该组的最大关键字和组起始地址。查找时先在索引表中确定目标在哪一组，再在组内顺序查找。叫索引顺序文件 ![[01视频-1773644524578.jpeg]]
	 - 顺序存储（且是数组而不是链表）的定长记录可随机存取
然后索引文件，就是**顺序存储的记录式文件**，但各个记录的数据项，是键和地址，(而标准的顺序存储记录式文件数据项就是文件内容。)



# 目录
目录也是定长顺序存储的记录式文件，和索引文件长得很像
然后每一条记录，都叫一个文件控制块，也叫目录项
目录文件就是上面说的记录式文件，而文件目录又说是文件控制块的有序集合

为了减小目录文件的大小，改进 FCB，让目录项只有文件名和索引结点指针，内容都放在索引结点中



# 文件在外存是如何存储的 ？
- 连续分配
  文件目录记录着文件的起始块号和长度。我们可以把逻辑地址映射成物理地址，因此，连续分配既支持顺序访问又支持随机访问。
  不适合文件拓展，会产生外存碎片
- 链接分配
  一个目录项会记录起始块号和结束块号，因此只支持顺序访问
  优点就是能弥补连续分配的缺点
	- 显示链接的链接分配：一个磁盘，诞生严格文件分配表，FAT。
	  读这个表不需要访问磁盘，常驻内存
	  ![[01视频-1773664653401.jpeg]]
	  ![[01视频-1773664245466.jpeg]]
	  数组里面存的值 = 同一个文件的“下一块的物理块号”（如果是文件最后一块，就存个特殊标记，比如 -1）
	  你想找这个文件的第 4 块数据？很简单！不需要读磁盘，直接在内存的 FAT 表里查：`FAT[5] = 12`，`FAT[12] = 28`，`FAT[28] = 45`。找到了！第 4 块在物理块 45！然后直接去磁盘读 45 号块。
- 索引分配
	 每个文件都有索引表，存放索引表的块叫索引块 
	![[01视频-1773664637556.jpeg]]
	- 改进：多层索引；混合索引
	![[01视频-1773666192735.jpeg]]![[01视频-1773666181360.jpeg]]

# 文件基本操作

创建文件：
- 外存大小--放到外存
- 文件名、文件存放路径--创建目录项

删除文件：
- 文件名、存放路径--删除目录项，根据目录项的外存地址，回收外存块

打开文件
- 文件名、存放路径--目录项检查是否有权限，讲目录项复制到“打开文件表‘’
- 关闭文件 ：
	- 删除用户打开文件表对应表项（表项序号/索引，也叫文件描述符）。
	- 系统的打开文件表，“打开计数器-1”
		- 如果等于 0 了，就删除对应表表项
- 读文件:索引号、数据、从外存读入内存
- 写文件 ：索引号、数据、写回位置
- 
**表一：进程的“私有打开文件表”（在进程的 PCB 里）**

| 文件描述符 (fd) | 读写指针 (当前读到哪了) | 访问权限 | 指向系统级表的指针                  |
| :--------- | :------------ | :--- | :------------------------- |
| `fd = 3`   | 第 0 字节        | 只读   | $\rightarrow$ 指向系统表里的表项 #1 |

**表二：操作系统的“系统级打开文件表”（全系统唯一）**

| 表项编号 | 打开计数器 (Count)         | 共享锁状态 | 指向内存 Inode 的指针                      |
| :--- | :-------------------- | :---- | :---------------------------------- |
| #1   | **2** (因为 A 和 B 都打开了) | 无锁    | $\rightarrow$ 指向内存中的 `test.c` Inode |

# 文件共享
- 硬链接：多个目录项的索引结点指针指向同一个索引结点，索引结点记录 count
- 软链接：目录项的索引节点，记录想访问文件的存放路径
