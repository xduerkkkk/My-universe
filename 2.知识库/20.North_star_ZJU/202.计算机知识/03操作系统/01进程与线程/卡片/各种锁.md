### 一、 核心痛点：为什么需要硬件指令？

要实现互斥，最直观的逻辑是：
1. **检查锁**：看当前锁是不是空的。
2. **上锁**：如果是空的，立刻把它占有。

如果在纯软件中分两步写：
```c
while (!available);   // 步骤 1：检查
available = false;    // 步骤 2：上锁
```
**致命缺陷**：若进程 A 刚检查完 `available == true`，还没来得及执行 `available = false`，时钟中断发生，进程 B 也来检查，发现也是 `true`。结果 **A 和 B 同时进入了临界区，互斥彻底失效**。

**结论**：**“检查”和“上锁”必须打包成一个不可被打断的原子操作（Atomic Operation）。** 这种原子性必须由 CPU 硬件指令来保证。

### 二、 3 张图的代码逻辑拆解与内在关系

#### 1. 图 1：互斥锁（Mutex Lock）——“概念模型”
* **定位**：这是互斥锁的**抽象语义描述**。
* **核心内容**：定义了 `acquire()`（加锁）和 `release()`（解锁）两个接口。
* **图中的代码是伪代码**：教材在图 1 底部特别注明了——*“acquire() 的执行必须是原子操作，因此互斥锁通常采用硬件机制来实现”*。它引出了图 2 和图 3。

---

#### 2. 图 2：TestAndSet（TS / TSL 指令）——“读并置位”实现方案
* **硬件特性**：CPU 提供了一条原子指令 `TestAndSet(lock)`。在硬件层面（锁总线或缓存一致性协议），**一条指令周期内同时完成两件事**：
  1. 读出 `lock` 的旧值；
  2. 无论旧值是什么，强行把 `lock` 写入 `true`（上锁）。
* **代码逻辑**：
  ```c
  while (TestAndSet(&lock)); // 尝试获取锁
  ```
  * **情况 A（锁空闲，lock 原为 false）**：
    `TestAndSet` 读出旧值 `false`，同时把 `lock` 改为 `true`。函数返回旧值 `false`。`while(false)` 条件不成立，**跳出循环，成功进入临界区**。
  * **情况 B（锁被占，lock 原为 true）**：
    `TestAndSet` 读出旧值 `true`，同时把 `lock` 仍写入 `true`。函数返回旧值 `true`。`while(true)` 成立，**陷入死循环继续尝试（忙等）**。

---

#### 3. 图 3：Swap 指令（XCHG 指令）——“数据交换”实现方案
* **硬件特性**：部分 CPU（如 x86 的 `XCHG`）没有直接的 TestAndSet 指令，而是提供了原子的“交换两个变量值”的指令 `Swap(a, b)`。
* **代码逻辑**：
  每个进程私有一个局部变量 `key = true`（代表我想上锁），全局锁为 `lock`（初始 `false` 表示空闲）。
  ```c
  boolean key = true;
  while (key != false) {
      Swap(&lock, &key); // 原子交换 lock 和 key 的值
  }
  ```
  * **情况 A（锁空闲，lock 原为 false）**：
    交换后，`lock` 变成 `true`（被占有了），局部变量 `key` 变成了 `false`（拿到了旧状态）。此时 `while(key != false)` 不成立，**退出循环，成功进入临界区**。
  * **情况 B（锁被占，lock 原为 true）**：
    交换后，`lock` 保持 `true`，`key` 依然是 `true`。`while(true)` 成立，**继续循环交换重试（忙等）**。

---

### 三、 总结与对比（408 核心考点矩阵）

| 实现方式 | 核心机制 | “检查”与“上锁”如何原子化？ | 优点 | 缺点 |
| :--- | :--- | :--- | :--- | :--- |
| **TestAndSet (TS)** | 读旧值并写 `true` | 一条硬件指令合并完成 | 简单、适用于多核 CPU（SMP） | **违背“让权等待”**（忙等消耗 CPU）；可能产生**饥饿**（无排队机制） |
| **Swap (XCHG)** | 交换全局 `lock` 与局部 `key` | 一条硬件指令合并完成 | 简单、适用于多核 CPU（SMP） | **违背“让权等待”**（忙等消耗 CPU）；可能产生**饥饿**（无排队机制） |

> **一句话理顺关系**：
> 图 1 说明了**要做什么**（互斥锁模型）；图 2 和图 3 是 CPU 分别用**“读写一体指令（TS）”**和**“数据交换指令（Swap）”**在底层**怎么把加锁做成原子操作**的具体手段。它们都属于**自旋锁（忙等锁）**。
