
| 触发类型 | 常见名称（408 标准分类） | 具体机制与实例 |
| :--- | :--- | :--- |
| **1. 程序请求** | **自陷 / 访管中断 (Trap)** | **系统调用（System Call）**。<br>用户程序主动执行特权指令请求（如 x86 的 `int 0x80` 或 `syscall`）。 |
| **2. 内部异常** | **异常 / 故障 (Fault / Exception)** | 程序执行过程中发生了**意料之外的错误或特殊事件**。<br>例如：**缺页中断（Page Fault）**、除零错误（Divide-by-zero）、段错误/非法内存访问（Segmentation Fault）、非法指令。 |
| **3. 外部中断** | **外中断 / 硬件中断 (Interrupt)** | **来自 CPU 芯片外部设备的异步信号**。<br>例如：**时钟中断**（时间片用完，强行剥夺 CPU）、磁盘 I/O 完成中断、键盘/鼠标输入中断。 |

> **关键判定：** 只要 CPU 接收到了上述任意一种信号，硬件就会立即保存当前的 PC 和 PSW，**强制将 CPU 特权级降为内核态（Ring 0）**，并跳转到内核的对应处理程序执行。

408 的选择题非常喜欢在**微观动作的边界**上挖坑。考场上可以用以下 3 个**硬性审查规则**提醒自己：

#### 规则 1：严格区分“微观函数”与“宏观流程”
* **微观动作：** 
  “阻塞进程”（`block`）是一个具体函数，只干一件事：修改 PCB 状态为 `BLOCKED` 并挂入等待队列。它**不包含**后面的调度和切换。
* **宏观流程：** 
  “一个进程因为缺页而被阻塞，直到另一个进程运行”是一个包含了多个微观动作的链条：
  `触发缺页异常` $\rightarrow$ `入内核` $\rightarrow$ `阻塞当前进程(在内核态)` $\rightarrow$ `触发调度(在内核态)` $\rightarrow$ `上下文切换(在内核态)` $\rightarrow$ `特权返回(切到用户态运行新进程)`。
* **做题提醒：** 题目问的是链条上的“某一步”，还是“整个流程”？如果问“阻塞动作完成时”，就只算到 `block()` 函数执行完的那一刻。

#### 规则 2：追踪 CPU 硬件指针（PC 与特权级）
在脑海中画一条 CPU 执行线，问自己两个问题：
1. **当前 CPU 的 PC（程序计数器）指向哪里？** 
   如果是操作系统的代码（如 `0x80000000` 以上的内核空间），那必然在内核态。
2. **CPU 什么时候才会变回用户态？** 
   **只有且仅有** CPU 硬件执行了特权级返回指令（如 `IRET` / `SYSRET`）的那一刷那。在此之前，无论内核代码换了多少个队列、改了多少个状态，CPU 依然停留在内核态。

#### 规则 3：区分“进程的状态”与“CPU 的状态”
* **进程的状态：** 针对 PCB（运行、就绪、阻塞）。被阻塞的进程**已经退出了 CPU 的执行**。
* **CPU 的状态：** 针对当前硬件（内核态、用户态）。当进程 A 被阻塞时，CPU 此时正在执行操作系统的内核调度代码，因此 **CPU 依然处于内核态**。
* **做题提醒：** 不要把“进程没在跑”混淆为“CPU 在用户态”。[1]
