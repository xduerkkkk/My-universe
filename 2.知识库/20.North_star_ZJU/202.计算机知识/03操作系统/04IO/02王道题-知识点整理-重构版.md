> [!abstract] 章节主线
> 进程发出 I/O 请求 → 设备独立层完成逻辑映射与分配 → 驱动设置控制器/DMA → 设备工作并中断 → 内核缓冲与用户区交付 → 调度和 SPOOLing 提升并行性。

## 一、设备、控制器、通道与 DMA

| 层次 | 主要职责 | 不要混淆 |
|---|---|---|
| I/O 设备 | 完成实际输入输出 | 不直接理解系统调用 |
| 设备控制器 | 寄存器、状态、数据缓冲、设备协议 | 不等于整个 OS 驱动 |
| 通道 | 可执行通道程序的专用 I/O 处理硬件 | 不是软件线程 |
| DMA 控制器 | 成批在设备与内存之间传输 | 不负责进程调度 |
| CPU/OS | 发起、配置、异常和调度 | DMA 期间并非固定用户态 |

DMA 时间线：

1. 请求进程系统调用进入内核。
2. 驱动/内核设置控制器和 DMA 参数。
3. 请求进程通常阻塞；DMA 成批传输，CPU 执行其他工作。
4. 设备完成后中断。
5. 中断和驱动完成后处理并唤醒进程。
6. 进程进入就绪态，是否立刻运行由调度器决定。

## 二、I/O 软件层次

1. **用户层 I/O 软件**：库函数、格式转换、用户缓冲。
2. **设备独立性软件**：逻辑设备名映射、保护、缓冲、设备分配、选择驱动、统一错误接口。
3. **设备驱动程序**：具体设备/控制器命令、寄存器、DMA 和中断协作。
4. **中断处理程序**：快速响应硬件事件并安排后续处理。

具体 OS 可能把职责拆成顶半部、底半部、线程化中断、总线驱动和类驱动等；408 题按教材四层模型作答。

## 三、设备分配

### 设备类型

- 独占设备：一个作业使用期间不适合被其他作业交叉占用，如教材中的物理打印机。
- 共享设备：可将多个进程请求排队交错服务，如磁盘。
- 虚拟设备：通过 SPOOLing 等技术把独占设备包装为多个逻辑设备。

### 分配因素

- 设备固有属性；
- 分配算法；
- 分配安全性与死锁；
- 设备独立性。

“及时性”若出现在实时 I/O 设计中当然可能重要，但不应替换教材列举的设备分配核心因素。

## 四、设备名与映射

应区分：

- 物理设备标识：具体硬件、控制器端口、总线地址等实现标识；
- 系统设备号：OS 内部用于定位设备类型和实例的编号；
- 逻辑/符号设备名：用户程序使用的抽象名称；
- fd/句柄：一次打开或 I/O 会话在进程中的引用。

不要把 MAC 地址、端口地址、系统绝对设备号和用户逻辑名合并成一组同义词。

## 五、中断驱动 I/O

1. 设备工作期间，请求进程通常阻塞，CPU 可调度其他进程。
2. 设备准备完成或发生错误后中断。
3. 中断处理读取状态、完成必要搬运/确认并安排后处理。
4. 等待进程转为就绪。
5. 调度器决定接下来运行谁。

“能返回断点”是中断机制提供的恢复能力；“是否继续运行原进程”是 OS 调度决策。

## 六、缓冲

### 缓冲目的

- 缓和 CPU 与设备速度不匹配；
- 减少中断或系统调用频率；
- 提高生产者和消费者并行度；
- 处理传输粒度不一致。

### 单缓冲题

必须根据题图判断：

- 输入阶段是否占用缓冲区；
- 从缓冲区复制到用户区何时释放缓冲；
- CPU 处理能否与下一块输入并行；
- 首块启动和末块收尾时间。

通用做法是画前两块时间线后寻找稳态周期，而不是直接背一个公式。

## 七、SPOOLing

### 组成

- 外存上的输入井、输出井；
- 内存缓冲区；
- 预输入程序、缓输出程序；
- 井管理程序和请求队列。

### 本质

- 用磁盘空间和后台进程换取 CPU、设备和作业之间的并行。
- 把物理独占设备虚拟为多个逻辑设备。
- 不提升设备机械服务速率，提升的是作业提交体验、并行性和系统吞吐。

## 八、键盘等字符设备的数据路径

设备 → 控制器寄存器/缓冲 → 中断与驱动 → 内核输入队列/终端子系统 → 等待的读取请求 → 用户缓冲区。

顶层中断处理通常只做必要的快速工作；进程归属、行规程和唤醒可在后续内核路径完成。

## 九、驱动程序的实现边界

- 可使用 C、C++、Rust、汇编等；语言不是驱动定义。
- 通常依赖特定 OS 驱动模型和内核接口。
- 同一驱动二进制通常不能直接跨 OS 使用。
- 硬件协议、算法和部分源码可以移植，前提是重写或适配 OS 接口。
- 驱动可以检查设备状态和请求合法性；复杂业务数据语义通常由上层协议栈或应用处理，不能绝对说驱动“没有分析能力”。

## 十、磁盘

### 访问时间

$$T_{access}=T_{seek}+T_{rotation}+T_{transfer}+T_{other}$$

题目未给控制器、排队等额外时间时，按给出的三项计算。

### 调度算法

| 算法 | 依据 | 主要特点 |
|---|---|---|
| FCFS | 到达顺序 | 公平但平均寻道可能大 |
| SSTF | 最近请求 | 平均寻道较小，可能饥饿 |
| SCAN | 当前方向扫描 | 类似电梯，动态流下仍需防黏着 |
| C-SCAN | 单向服务后回卷 | 等待较均匀，边界/回卷按题意 |
| N-step-SCAN/FSCAN | 冻结批次或双队列 | 缓解新请求持续造成的黏着 |

### 初始化层次

1. 低级/物理格式化：教材中形成扇区结构。
2. 分区：划分逻辑区域并记录布局。
3. 逻辑格式化：建立文件系统元数据。

## 十一、校正与条件

> [!warning] 旧版：DMA 传输中 CPU 处于用户态
> **校正**：DMA 使 CPU 不必逐字搬运；CPU 可运行用户代码、内核代码或处理中断。  
> **适用条件**：若题目问原请求进程，通常已阻塞；若问 CPU，不能固定其模式。

> [!warning] 旧版：驱动不能用汇编写、绝对不能跨 OS
> **校正**：驱动可以含汇编；二进制通常依赖特定 OS，但源码和硬件逻辑可经适配移植。  
> **适用条件**：区分语言、源码可移植性和二进制兼容性。

> [!warning] 旧版：绝对设备名就是 MAC 地址或端口号
> **校正**：教材设备编号、OS 内部设备号、硬件地址和逻辑设备名是不同层次。  
> **适用条件**：按题目给出的设备表和命名定义判断。

> [!warning] 旧版：C-SCAN 通常忽略回卷
> **校正**：若问磁头总移动量，通常应按题意计入端点和回卷；只有题目明确只计有效服务移动时才能省略。

> [!warning] 旧版：柱面、磁道、扇区、簇号默认都从 0 开始
> **校正**：编号起点依题目和具体格式，计算前必须读取题设。

## 十二、绝对词检查

- “中断后一定返回原进程”：错误，调度器决定。
- “共享设备同时物理服务多个进程”：共享通常是时间上的交错复用。
- “SPOOLing 提高打印机速度”：提高并行性和吞吐，不改变机械速度。
- “驱动唯一懂硬件”：是教材层次化概括，具体内核中总线层、固件和控制器逻辑也参与。


## 十三、控制器、通道与设备表

典型控制链：CPU/OS → 通道（若有）→ 设备控制器 → 设备。驱动向控制器寄存器写命令和参数；通道可执行通道程序，减少 CPU 对一组 I/O 操作的直接干预。

教材设备分配表常按 SDT → DCT → COCT → CHCT 关联。分配检查资源归属和安全，调度决定等待请求的服务顺序，两者不能混为同一动作。

## 十四、缓冲结构对比

| 结构 | 位置/规模 | 主要目的 |
|---|---|---|
| 单/双/循环缓冲 | 内存、固定路径 | 让输入、复制和处理形成流水 |
| 缓冲池 | 内存、系统共享 | 动态复用多块缓冲 |
| 输入井/输出井 | 外存、作业级 | 保存大量排队数据，实现 SPOOLing |
| 控制器缓冲 | 设备控制器 | 匹配设备和总线传输粒度 |

共享缓冲及读写指针属于临界资源，需要互斥和状态同步。

## 十五、设备标识层次

| 层次 | 示例作用 |
|---|---|
| 逻辑/符号设备名 | 用户程序提出设备无关请求 |
| 相对/绝对设备号 | 教材设备表中的类内或系统统一编号 |
| OS 设备号 | 内核定位驱动和实例 |
| 总线/端口/MAC 等硬件标识 | 控制器或网络硬件寻址 |
| fd/句柄 | 进程对一次打开实例的引用 |

这些名称可能在不同教材中略有差异，必须按题目定义映射，不能机械互换。

## 十六、访问方式与介质

- 随机访问：访问时间近似不依赖当前位置，如主存、SSD。
- 直接访问：先定位块，访问时间随位置变化，如机械磁盘。
- 顺序访问：按记录顺序推进，如磁带。

块设备描述传输接口，随机/直接/顺序描述访问特征；同一设备可在不同抽象层得到不同分类表述。

## 十七、SSD 与缓存写策略

- NAND 按页读写、按块擦除；覆盖写依赖异地写、映射表和垃圾回收。
- 静态磨损均衡会搬移长期不变数据，比只处理活跃写入的动态磨损均衡覆盖更全面。
- 提前读利用顺序局部性；延迟写合并修改但扩大未持久化窗口。

## 十八、磁盘大题强制审题项

1. SCAN 还是 LOOK，C-SCAN 还是 C-LOOK。
2. 是否移动到物理端点。
3. 回卷是否计入总磁头移动量。
4. 请求队列是否在服务过程中动态加入。
5. 柱面、磁头、扇区、簇号从 0 还是 1 编号。
6. 题目问机械移动、有效服务距离还是总访问时间。
