





**A. 中断向量表 (Interrupt Vector Table)**

- **创建时机：操作系统初始化时（存在于内存中）。**
    
- **原因：** 计算机在运行过程中，随时需要响应外部硬件信号（如键盘敲击、鼠标移动）或内部软件异常（如系统调用、缺页异常）。操作系统在启动（初始化）时，必须在**内存**中建立一张“中断向量表”（或称为中断描述符表 IDT）。这张表记录了各种中断信号对应的“处理程序入口地址”。只有建立了这张表，系统才能正常接管和处理后续的各种任务。因此它是每次开机初始化时必须创建的。
    

内存存的东西，肯定要每次开机初始化都创建一次。
还有PCB（是在创建进程时动态分配的）、页表

ROM/Flash 中的固件 (BIOS 或 UEFI)

  → 硬盘上的引导扇区 / EFI 分区中的 bootloader (GRUB 等)

    → 硬盘上的内核映像 (vmlinuz 等)

      → 内核的 start_kernel() 完成各种初始化

具体来说：

1. 固件（BIOS/UEFI） — 烧在主板 Flash ROM 里，上电后 CPU 硬件约定从固定地址（x86 是 0xFFFFFFF0）开始执行它。它负责硬件自检和加载 bootloader。
2. Bootloader（GRUB 等） — 存在硬盘的特定位置（MBR 的前 446 字节，或 EFI 系统分区）。固件把它加载到内存并跳转执行。
3. 内核映像 — 存在硬盘文件系统里（如 `/boot/vmlinuz`）。Bootloader 把它加载到内存，内核开始执行，建立中断表、页表、第一个进程等。

### 其他选项是什么时候创建的？

B、C、D 这三个选项都有一个共同点：它们都是**存在于硬盘上**的持久化数据结构。操作系统初始化（开机）时，只是去**读取**它们，而不是**创建**它们。

- **C. 硬盘分区表 (Partition Table)**
    
    - **创建时机：给硬盘分区时。** 比如你刚买了一块新硬盘，使用分区工具（如 DiskGenius、fdisk）将其划分为 C盘、D盘时，分区表就被写入到了硬盘的特定位置（如 MBR 或 GPT 区域）。每次开机，操作系统只是去读取它来识别各个分区。
        
- **B. 文件系统的根目录 (Root Directory)** 和 **D. 文件系统的索引节点表 (Inode Table)**
    
    - **创建时机：格式化分区时（创建文件系统时）。** 当你把一个分区格式化为 NTFS、ext4 等格式时，格式化程序就会在磁盘上划分出索引节点（Inode）区和数据区，并建立好根目录（`/` 或 `C:\`）。每次开机时，操作系统是在“挂载 (mount)”文件系统，也就是把磁盘上已经存在的根目录和 Inode 表读入到内存中来使用，绝不会每次开机都去重新“创建”它们（否则数据就全丢了）。

### 操作系统初始化都创建了什么？

操作系统初始化的核心目的是**在内存中搭建起管理软硬件资源的基础环境**。因此，它创建的绝大多数是**常驻内存的数据结构**，主要包括：

1. **中断与异常管理结构：** 如本题选中的**中断向量表**（IDT）。
    
2. **内存管理结构：** * **页目录表和页表：** 用于建立虚拟内存到物理内存的映射机制。
    
    - **内存分配表/位图：** 用于记录哪些物理内存页是空闲的，哪些已被占用。
        
3. **进程管理结构：**
    
    - 系统初始化的**第一个进程的 PCB（进程控制块）**，例如 Linux 中的 0号进程（idle进程）和 1号进程（init进程）。
        
    - 各种**进程调度队列**（如就绪队列、阻塞队列的头指针）。
        
4. **设备与文件管理相关的内存结构：**
    
    - 初始化**系统调用表**。
        
    - 为加载的设备驱动程序分配内存并建立控制块。
        
    - 建立**系统打开文件表**（注意是在内存中的表，不是硬盘上的文件系统本身）。
        

**总结记忆口诀：** 硬盘上的东西（分区、目录、文件）靠“分区和格式化”创建，内存里的管理表格（中断表、页表、PCB）靠“OS初始化”创建。
