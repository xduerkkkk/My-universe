在 408 考纲中，操作系统引导（Booting）是连接“计算机体系结构（硬件初始化）”与“操作系统（内核加载、文件系统挂载）”的关键环节。

以下基于 408 核心考查的 **BIOS + MBR（Master Boot Record）经典引导架构**进行完整拆解，并在最后与《文件系统》章节做横向联动。

---

### 一、核心概念与英文全称

1. **BIOS**（Basic Input/Output System，基本输入输出系统）：固化在主板 ROM 芯片中的固件程序。
2. **POST**（Power-On Self-Test，加电自检）：BIOS 启动时检查关键硬件（CPU、内存、主板、显卡等）是否正常的检测过程。
3. **MBR**（Master Boot Record，主引导记录）：位于物理磁盘的 **0 柱面、0 磁头、1 扇区**（绝对 0 扇区），固定占用 **512 字节**。
4. **DPT**（Disk Partition Table，磁盘分区表）：MBR 内部用于记录磁盘分区信息的数据结构，占 64 字节（每个主分区项 16 字节，最多支持 4 个主分区）。
5. **PBR / VBR**（Partition Boot Record / Volume Boot Record，分区引导记录 / 卷引导记录）：位于活动分区（Active Partition）的第一个扇区。
6. **Bootloader**（Bootstrap Loader / Boot Loader，引导加载程序）：负责将操作系统内核映像从磁盘读入内存并转交 CPU 控制权的软件（如 GRUB、LILO）。
7. **Rootfs**（Root File System，根文件系统）：内核启动后挂载的第一个文件系统（即 `/` 目录）。

### 二、操作系统引导的 5 个阶段

```text
[加电/复位]
    │
    ▼
【阶段 1: BIOS 初始化】
    ├─ 硬件复位，PC 指向 ROM 入口地址 (如 x86 的 0xFFFF0)
    ├─ 执行 POST (加电自检)
    └─ 根据 BIOS 设置的 Boot Sequence (启动顺序) 选择启动设备 (如 Disk 0)
    │
    ▼
【阶段 2: 读取 MBR】
    ├─ BIOS 将磁盘 0 扇区的 MBR (512 字节) 读入内存 0x7C00 处
    └─ CPU 控制权交由 MBR 中的引导代码 (Boot Code)
    │
    ▼
【阶段 3: 读取活动分区的 PBR】
    ├─ MBR 扫描自身的分区表 (DPT)，找到标志为 "0x80" (活动/激活状态) 的分区
    ├─ MBR 将该活动分区的第一个扇区 (PBR) 读入内存
    └─ CPU 控制权交由 PBR
    │
    ▼
【阶段 4: 执行 Bootloader】
    ├─ PBR 代码加载完整的 Bootloader (如 GRUB Stage 2)
    ├─ Bootloader 解析文件系统，读取 OS 内核映像文件 (如 vmlinuz)
    └─ 将内核装入内存，设置 CPU 运行模式 (实模式 -> 保护模式 / 长模式)，跳转到内核入口
    │
    ▼
【阶段 5: 内核初始化与用户态启动】
    ├─ 初始化中断描述符表 (IDT)、页表、驱动程序、调度器
    ├─ 挂载根文件系统 (Mount Rootfs)
    └─ 创建 1 号用户进程 (如 init / systemd)，进入系统就绪状态
```

### 三、与《文件管理》章节的深度联动

引导过程本质上是**从“硬件无文件系统的绝对物理寻址”，逐步演化为“通过文件系统元数据进行逻辑寻址”的过程**。

#### 1. 磁盘格式化层次的对应关系
408 文件管理中将磁盘初始化分为三个层次，引导过程严格依赖这三层结构：
* **物理格式化 / 低级格式化（Low-level formatting）**：将磁盘划分扇区（包括扇区头、ECC 校验码等）。MBR 的“绝对 0 扇区”在此物理层面确定。
* **磁盘分区（Partitioning）**：在 MBR 中写入 64 字节的 **DPT（分区表）**。每个表项记录了分区的起始扇区号（LBA）、分区大小、文件系统类型标志、以及是否为活动分区（0x80 为激活）。
* **逻辑格式化 / 高级格式化（Logical formatting）**：在某个分区内部创建文件系统元数据（如 Inode 表、空闲空间管理位图、根目录等），并在分区的首扇区写入 **引导控制块（Boot Control Block）**，即 **PBR**。

#### 2. 引导控制块（Boot Control Block）与卷控制块（Volume Control Block）
在 408 文件系统的磁盘数据结构考点中：

| 文件系统结构名称 | 对应引导阶段中的实际概念 | 作用与特点 |
| :--- | :--- | :--- |
| **引导控制块 (BCB)** | **PBR / 引导扇区** | 包含用于从该分区引导操作系统的代码。如果该分区未安装操作系统，该扇区通常为空。 |
| **卷控制块 (VCB)** | **超级块 (Superblock) / 主文件表 (MFT)** | 包含分区的详细信息：块大小、块总数、空闲块指针/位图、Inode 节点总数与空闲数。Bootloader 阶段读取它来解析文件系统。 |

#### 3. 寻址方式的跳跃：从 LBA 扇区号到 Path / Inode
* **BIOS 与 MBR 阶段（无文件系统认知）**：
  * BIOS 和 MBR **完全不知道什么是文件系统**（不认识 ext4、NTFS、FAT32）。
  * 它们只能通过硬件指令向磁盘控制器发送**绝对扇区号（LBA / CHS）**，把特定扇区（如 LBA 0、活动分区起始 LBA）生硬地读取到特定内存物理地址（如 `0x7C00`）。
* **Bootloader 阶段（嵌入简易文件系统驱动）**：
  * Bootloader（如 GRUB）内部编译了常见文件系统的精简只读驱动。
  * 此时可以通过路径（如 `/boot/vmlinuz-x.x.x`）查找文件的 **FCB / Inode**，再通过多级索引结构找到内核文件分散在磁盘中的各个数据块（Data Blocks），将内核拼装读入内存。

#### 4. 根文件系统挂载（Mount）与 VFS 建立
* 内核接管 CPU 后，必须访问硬盘上的应用程序和配置文件。
* 内核首先在内存中建立 **虚拟文件系统（VFS, Virtual File System）** 抽象层。
* 将硬盘分区上的根文件系统挂载（Mount）到 VFS 的根路径 `/`。
* 挂载完成后，内核才能通过文件路径打开可执行文件，启动用户空间的第一个进程（`init` / `systemd`，PID=1），至此操作系统引导完成。
