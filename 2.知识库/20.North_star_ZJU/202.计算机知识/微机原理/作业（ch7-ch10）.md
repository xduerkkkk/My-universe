### **第一组：7.1 - 7.6（简答与概念题）**

这部分主要考查“为什么要用接口”以及“怎么传数据”。

#### **7.1 简述 I/O 接口的基本功能**
*   **答案**：
    1.  **数据缓冲**：解决CPU（快）与外设（慢）之间的速度差异。
    2.  **信号转换**：把外设的信号（如模拟量、串行）转为CPU能懂的信号（数字量、并行）。
    3.  **地址译码**：确保CPU能选中指定的设备。
    4.  **状态监测与控制**：报告设备是忙还是闲，接收CPU命令。

#### **7.2 简述 I/O 接口与 I/O 端口的区别**
*   **答案**：
    *   **I/O 接口**：是指连接CPU和外设的**整个电路板或芯片**（硬件实体）。
    *   **I/O 端口**：是指接口电路中可以被CPU读写的**寄存器**（如数据端口、状态端口、控制端口）。
    *   *人话理解：接口是“房子”，端口是房子里的“房间”。*

#### **7.3 简述 I/O 端口的编址方式及优缺点**
*   **答案**：
    1.  **独立编址（I/O映射）**：
        *   **特点**：I/O地址和内存地址分开，用专门指令（IN/OUT）。**8086就用这个**。
        *   **优**：不占内存空间，程序清晰；**缺**：指令少，操作不便。
    2.  **统一编址（内存映射）**：
        *   **特点**：I/O占用内存地址，当做内存来读写。
        *   **优**：指令丰富，操作灵活；**缺**：占用内存空间。

#### **7.4 简述程序查询、中断和 DMA 三种方式的优缺点**
*   **答案（408简答题必背）**：
    *   **程序查询**：
        *   **优**：硬件简单，程序易懂。
        *   **缺**：CPU要一直询问外设“好了没”，**效率极低**，CPU无法并行工作。
    *   **中断**：
        *   **优**：CPU和外设可以**并行工作**，实时性好。
        *   **缺**：需要保护/恢复现场，频繁中断会消耗CPU时间。
    *   **DMA (直接存储器访问)**：
        *   **优**：数据传输**不经过CPU**（直接在内存和外设间传送），速度最快，适合大数据块。
        *   **缺**：硬件结构复杂（需要DMA控制器）。

#### **7.5 为什么 I/O 设备不能像存储器一样直接连接到系统总线上？**
*   **答案**：
    1.  **速度不匹配**：外设通常很慢，跟不上CPU。
    2.  **信号电平不兼容**：外设可能是模拟信号或高电压，无法直接接总线。
    3.  **数据格式不一致**：外设可能是串行数据，总线是并行数据。
    4.  所以必须通过 **I/O 接口** 这个“翻译官”来连接。

#### **7.6 选择传输方式的主要依据是什么？**
*   **答案**：主要依据是 **外设的工作速度** 和 **系统的实时性要求**。
    *   低速/不频繁：查询或中断。
    *   高速/大数据量：DMA。

### **第二组：7.7 - 7.10（填空题，8086 硬件特性）**

#### **7.7 8086 CPU 地址空间填空（重要！）**
*   **题目解析**：
    *   8086有 **20** 根地址线（$A_0-A_{19}$），内存空间 = $2^{20} = 1MB$。
    *   I/O控制线只用了低 **16** 根（$A_0-A_{15}$），I/O空间 = $2^{16} = 64KB$。
    *   IBM PC 早期设计中只用了 **10** 根线译码（000H~3FFH，1KB）。
*   **答案**：
    *   **20** 条地址总线
    *   形成 **1MB** 的存储器地址空间
    *   寻址范围为 **00000H ~ FFFFFH**
    *   其中的 **16** 条线可用于 I/O 寻址
    *   形成 **64KB** 的输入/输出地址空间
    *   地址范围为 **0000H ~ FFFFH**
    *   PC 中用了 **10** 条地址线
    *   其地址空间为 **1KB**
    *   可寻址范围为 **000H ~ 3FFH**

#### **7.8 外设连接方式**
*   **答案**：最终总是要通过 **I/O 接口电路** 与主机相接。

#### **7.9 接口逻辑的两侧**
*   **答案**：一侧应与 **系统总线（CPU）** 相接，另一侧与 **外设（I/O设备）** 相接。
    *   *解析：接口就是中间人，左手拉CPU，右手拉设备。*

#### **7.10 信息类型与方向**
*   **题目解析**：CPU和接口之间传啥？数据、状态、控制。
*   **答案**：
    *   信息包括：**数据**、**状态**、**控制** 三种类型。
    *   传送方向：
        *   **数据**：**双向**（读/写）。
        *   **状态**：**外设 $\to$ CPU**（单向，告诉CPU我不忙）。
        *   **控制**：**CPU $\to$ 外设**（单向，命令外设干活）。

### **第一组：波形与原理 (9.2, 9.6)**

这部分考察你对 8253 **工作方式** 的物理理解。

#### **9.2 画出波形图**
*   **已知条件**：时钟 $CLK = 1\text{MHz}$ (周期 $1\mu\text{s}$)，计数初值 $N=1000$ (即定时 $1000\mu\text{s} = 1\text{ms}$)。
*   **情况 1：方式 0 (计数结束中断)**
    *   **原理**：写入初值后，OUT 变 **低电平**，开始倒数。数到 0 时，OUT 变 **高电平**（产生上升沿中断）。
    *   **波形描述**：
        1.  写入初值瞬间，OUT 变 **低**。
        2.  维持低电平 **1ms** (1000个周期)。
        3.  之后跳变回 **高**，并一直保持高电平。
*   **情况 2：方式 1 (硬件可重触发单稳态)**
    *   **原理**：平时 OUT 是 **高电平**。当 GATE 信号（触发器）来一个**上升沿**时，OUT 变 **低电平**，开始倒数。数完 N 后，OUT 自动变回 **高电平**。
    *   **波形描述**：
        1.  平时是 **高** 的。
        2.  GATE 触发后，OUT 变 **低**。
        3.  维持低电平 **1ms** (负脉冲宽度)。
        4.  自动变回 **高**。

#### **9.6 GATE 信号的作用 (必考简答)**
GATE 是门控信号（开关），在不同方式下作用不同，重点记下面区别：
*   **方式 0 (中断)** 和 **方式 4 (软件选通)**：
    *   **电平控制**。
    *   GATE = 1 (高)：**允许**计数。
    *   GATE = 0 (低)：**暂停**计数（保持当前值）。
*   **方式 2 (分频)** 和 **方式 3 (方波)**：
    *   **电平 + 边沿控制**。
    *   GATE = 0 (低)：**强制停止**，并且使 OUT 变高电平（复位）。
    *   GATE = 1 (高)：允许计数。
    *   **上升沿 (从0变1)**：**重新装入初值**，重新开始计数（同步/重触发功能）。

#### **9.10 产生方波**
*   **目标**：周期 $5\text{ms}$ 的方波。
*   **条件**：输入时钟 $1\text{MHz}$。
*   **分析**：
    1.  **选方式**：要产生连续的方波，必须选 **方式 3** (方波发生器)。
    2.  **算初值**：
        *   输入周期 $= 1 / 1\text{MHz} = 1\mu\text{s}$。
        *   目标周期 $= 5\text{ms} = 5000\mu\text{s}$。
        *   $N = 5000 / 1 = \mathbf{5000}$。
*   **答案**：工作方式为 **方式3**，计数初值为 **5000**。

#### **9.11 产生延时中断**
*   **目标**：延时 $10\text{ms}$ 后产生中断。
*   **条件**：输入时钟 $2\text{MHz}$。
*   **分析**：
    1.  **选方式**：要产生中断（单次），通常选 **方式 0** (计数结束中断)。
    2.  **算初值**：
        *   输入周期 $= 1 / 2\text{MHz} = 0.5\mu\text{s}$。
        *   目标延时 $= 10\text{ms} = 10000\mu\text{s}$。
        *   $N = 10000 / 0.5 = \mathbf{20000}$。
    *   *(注：图片上你写的 19999 可能是考虑了 N-1 的逻辑，但在 8253 方式0计算中，通常直接用 总时间/时钟周期 即可)*
*   **答案**：工作方式为 **方式0**，计数初值为 **20000**。

#### **9.12 延迟中断产生的时刻**
*   **题目**：方式 0 正在倒数，我想让它晚一点再响铃（产生中断），咋办？
*   **选项分析**：
    *   A. **重置初值**：如果在数到 0 之前，重新写入一个初值（比如从剩 10 重写成 100），它会弃旧图新，按 100 重新倒数。**可以延迟**。
    *   B. **GATE 端加负脉冲**：方式 0 中，GATE=0 会**暂停**计数。给一个负脉冲就是“暂停一会再继续”，总时间自然变长了。**可以延迟**。
    *   C. **降低时钟频率**：时钟慢了，走一步的时间长了，总时间肯定变长。**可以延迟**。
*   **答案**：选 **D (以上全都是)**。

### **第三组：编程逻辑 (9.3)**

这道题是 **编程题**，考察 8253 的初始化和**“读回命令”**。

**题目要求**：
1.  计数器 0，方式 4，初值 10000。
2.  循环查询，直到当前计数值 (CE) $\le$ 1000 后，执行后续程序。

**代码思路**：
1.  **初始化**：写控制字 -> 写初值(低8位) -> 写初值(高8位)。
2.  **读计数**：因为 8253 在计数时数值在变，CPU 不能直接读。必须先发一个**“锁存命令”**，把当前值拍个照，然后再读出来。

**汇编代码实现**：

```assembly
; 假设端口地址：控制口=PORT_CTL, 计数器0=PORT_0

; --- 第一步：初始化 8253 ---
MOV AL, 00111000B   ; 控制字：通道0, 先低后高, 方式4, 二进制
                    ; (00=通道0, 11=16位读写, 100=方式4, 0=二进制)
OUT PORT_CTL, AL    ; 写入控制字

MOV AX, 10000       ; 初值 10000
OUT PORT_0, AL      ; 先写低 8 位
MOV AL, AH
OUT PORT_0, AL      ; 后写高 8 位

; --- 第二步：循环等待 (Wait Loop) ---
CHECK_LOOP:
    ; 1. 发送锁存命令 (这是读数的关键！)
    MOV AL, 00000000B   ; 控制字：通道0, 锁存命令(00)
    OUT PORT_CTL, AL
    
    ; 2. 读取锁存的数值
    IN AL, PORT_0       ; 读低 8 位
    MOV BL, AL          ; 暂存到 BL
    IN AL, PORT_0       ; 读高 8 位
    MOV BH, AL          ; 放到 BH，现在 BX 就是当前计数值
    
    ; 3. 比较
    CMP BX, 1000        ; 看看是不是 <= 1000
    JA CHECK_LOOP       ; 如果 BX > 1000 (Above)，跳回去继续等
    
    ; 4. 满足条件，向下执行
    CALL SUBROUTINE     ; 执行后续程序...
```

### **第一块：N、频率、周期，到底咋算的？**

你疑惑：*“输入频率是Hz，可以和s共同计算吗？”*
**答案：必须可以！因为它们互为倒数。**

想象 8253 是一个**“只会数心跳的傻瓜”**。

1.  **输入频率 ($f_{clk}$)**：就是**心跳速度**。
    *   比如 **1MHz**，意思就是 **1秒钟跳 1,000,000 下**。
    *   那跳一下需要多久？ $T = 1 / 1,000,000 = 0.000001$ 秒 = **1微秒 ($1\mu s$)**。
    *   **结论**：输入周期 = 1 / 输入频率。

2.  **计数初值 ($N$)**：就是**你要它数多少下**。
    *   如果你要它数 **1000** 下。

3.  **输出周期/定时时间 ($T_{out}$)**：就是**数完这么多下用了多久**。
    *   公式：**总时间 = 跳一下的时间 $\times$ 跳的次数**。
    *   即：$T_{out} = T_{clk} \times N$。

4.  **为什么 $N = f_{in} / f_{out}$？**
    *   比如你要产生 **1000Hz** 的输出（1秒钟输出1000次）。
    *   你的输入是 **1MHz**（1秒钟跳1000000次）。
    *   这就像：你有 100万块钱（输入），你要发给 1000 个人（输出），每个人能分多少（N）？
    *   $1,000,000 \div 1,000 = 1,000$。
    *   所以 $N = 1000$。

> **一句话总结**：
> **N (初值)** = **你想要的总时间** / **它数一下的时间**。
> (单位要统一，比如都是毫秒，或者都是赫兹)。

### **第二块：为什么写两遍 OUT？为什么不覆盖？**

你疑惑：*“写完低八位为什么不直接 OUT ... AH？难道不会覆盖吗？”*

**1. 为什么不能 `OUT PORT, AH`？**
*   **这是汇编语法的死规定**：8086 的 `OUT` 指令，源操作数**必须**是 **`AL`** (8位) 或 **`AX`** (16位)。
*   CPU 不允许你写 `OUT DX, AH` 或者 `OUT DX, BL`。
*   所以，必须先把 `AH` 里的数据搬到 `AL` 里，才能发出去。

**2. 为什么不会覆盖？（8253 内部的秘密）**
*   8253 的端口虽然只有一个地址（比如 `PORT_0`），但它门口有个**“看门大爷”**（读写逻辑）。
*   **初值寄存器**其实是 **16位** 的（分高8位盒子、低8位盒子）。
*   当你设置控制字为“先读写低8位，后读写高8位”时，**看门大爷手里有个开关**：
    *   **第 1 次**你送数据来：大爷把开关拨向**“低8位盒子”**，数据存进去。大爷记住了：“低位已填”。
    *   **第 2 次**你送数据来：大爷一看刚才低位填过了，自动把开关拨向**“高8位盒子”**，数据存进去。
*   **结论**：这是硬件自动控制的，**同在一个端口写两次，分别去了不同的地方**，不会覆盖。

### **第三块：怎么读数？（锁存是什么鬼）**

你疑惑：*“后面根本看不懂”*。

想象一下：计数器正在疯狂倒数：`1000, 999, 998 ...` 速度极快。
如果你直接读：
1.  第一次读低8位：读到了 `99`。
2.  （这时候计数器又减了）
3.  第二次读高8位：读到了... 哎呀它变了！
这样拼起来的数是错的（比如 10:59，你先读分59，过一秒读时11，结果变成11:59，实际是11:00）。

**操作流程：**
1.  **锁存（拍照）**：发一个命令 `OUT`，告诉 8253：“**定！**”。8253 就把当前的数复制一份到一个**临时寄存器**里，不动了。
2.  **读低位**：`IN AL, PORT`。从临时寄存器拿走低8位。
3.  **读高位**：`IN AL, PORT`。从临时寄存器拿走高8位。
4.  **拼合**：把低位给 `BL`，高位给 `BH`，这不就拼成一个完整的 16位 `BX` 了吗？

### **第四块：工作方式到底有啥区别？**

你疑惑：*“方式0、1、2、3 到底啥区别？”*

我们用**“炸弹倒计时”**来比喻：

#### **方式 0：计数结束中断（软件启动的炸弹）**
*   **过程**：
    1.  你写入初值 N（比如 10）。
    2.  `OUT` 变成**低电平**（炸弹引信滋滋响）。
    3.  倒数：10, 9, ... 1, 0！
    4.  数到 0：`OUT` 突然变**高电平**（炸弹爆炸！）。
    5.  **一直保持高电平**，直到你下次再重置它。
*   **为什么叫中断？** 因为这个“突然变高”的信号，通常连到 CPU 的中断引脚上，告诉 CPU：“时间到了！”
*   **GATE (暂停键)**：倒数过程中，`GATE=0` 计时暂停；`GATE=1` 继续。**它不能重置倒数，只能暂停。**

#### **方式 1：硬件单稳态（地雷）**
*   **区别**：写入初值后，它**不数**！它在等 `GATE` 信号。
*   **过程**：
    1.  `GATE` 来一个**上升沿**（踩地雷了）。
    2.  `OUT` 变**低**（开始爆炸持续时间）。
    3.  倒数 N 下。
    4.  数完，`OUT` 变**高**（结束）。
*   **核心区别**：方式 0 是**写完数就跑**；方式 1 是**写完数等着，GATE 来了才跑**。

#### **方式 2：分频器（打点计时器）**
*   **波形**：`OUT` 平时一直是**高**的。
*   **动作**：倒数 N 下。数到最后一下（0）时，`OUT` 变成**低电平**（一下下），然后立刻变回高，自动重新装填 N，继续数。
*   **效果**：`高高高...高低高高...`。输出的是**窄脉冲**。

#### **方式 3：方波（闪烁灯）**
*   **区别**：方式 2 是最后一下才变低。方式 3 是 **前一半时间高，后一半时间低**。
*   **效果**：`高高低低高高低低...`。这就是**方波**。

### **总结一下你的疑惑**

1.  **N** = 总时间 / 心跳间隔。
2.  **两次 OUT**：是因为硬件内部有“看门大爷”自动把两次数据分发给高低位，不会覆盖。汇编语法要求必须用 `AL` 中转。
3.  **读数**：先发命令“定身”，然后分两次读出来拼凑。
4.  **方式区别**：
    *   **0**：数完变高（一次性）。适合报时。
    *   **1**：GATE 触发才数（一次性）。适合延时开关。
    *   **2**：输出窄脉冲（自动循环）。适合当节拍器。
    *   **3**：输出方波（自动循环）。适合发声。
