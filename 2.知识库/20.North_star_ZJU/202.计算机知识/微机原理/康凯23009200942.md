### **一、 实验目的**

1. 熟练掌握 8086 汇编语言的源程序格式（段定义、主程序、子程序结构）。
2. 掌握常用的 **寻址方式** 及 **数据传送、算术运算、逻辑运算、转移控制** 等指令的应用。
3. 掌握 **DOS 系统功能调用 (INT 21H)** 的使用方法，包括字符/字符串的输入输出。
4. 理解并应用 **堆栈** 进行数据保护和子程序参数传递。
5. 培养模块化程序设计思想，解决字符串处理、排序、数值转换等综合问题。

### **二、 实验环境**

- **硬件环境**：PC 机
- **软件环境**：Emu8086 汇编模拟器

### **三、 实验内容与要求**

编写一个汇编语言程序，运行后在屏幕上显示由 5 个选项组成的主菜单，用户输入数字键选择功能，执行完毕后返回主菜单。功能如下：

1. **字符串大小写转换**：将内存中指定字符串的小写字母转换为大写。
2. **查找最大值**：在混合了字符和数字的数组中找出最大值，并以十六进制形式显示。
3. **数组排序**：对一组无符号整数进行冒泡排序，并输出排序结果。
4. **显示系统时间**：获取系统当前时间（时:分:秒）并在屏幕上显示。
5. **退出程序**：返回操作系统。



### **四、 算法设计与流程**


本程序采用**模块化结构设计**，主程序负责菜单显示与任务分发，各功能模块独立实现具体逻辑，最后通过通用子程序实现复用。

#### **1. 多分支跳转逻辑**

- **设计思想**：程序启动后进入死循环（MAIN_LOOP）。利用 DOS 功能调用 09H 显示菜单，01H 等待单字符输入。
    
- **流程控制**：输入字符存储在 AL 寄存器中。程序通过连续的 CMP 指令将输入与 ASCII 码 '1' ~ '5' 进行比较。
    
- **长跳转策略**：考虑到 8086 指令集中条件转移指令（如 JE）的跳转范围限制在 -128 到 +127 字节之间，而功能模块代码量较大，无法直接跳转。因此，算法采用了 **“逆向判断 + 无条件长跳转”** 的策略：
    
    - 若 CMP 比较结果不相等（JNE），则跳过下一条指令，继续检查下一个选项；
    - 若结果相等，则执行 JMP FAR_LABEL，利用 JMP 指令的全段寻址能力（64KB）跳转至对应功能模块。
        

#### **2. 功能模块一：字符串大小写转换**

- **算法逻辑**：基于 ASCII 码特性。小写字母 'a'~'z' 的 ASCII 值为 61H~7AH，对应大写字母 'A'~'Z' 为 41H~5AH。两者差值为 20H（32）。
    
- **实现步骤**：
    
    1. 初始化 BX 寄存器作为指针，指向字符串首地址。
        
    2. 循环读取 [BX] 单元内容，判断是否为字符串结束符 $。
        
    3. **范围判定**：利用 CMP 和条件跳转指令（JB, JA）筛选出 ['a', 'z'] 区间内的字符。
        
    4. **位运算处理**：对符合条件的字符执行 SUB AL, 20H 指令，将其转换为大写，并写回内存。非小写字符保持原样。
        

#### **3. 功能模块二：最值查找与十六进制显示**

- **最值查找**：
    
    - 初始化 AL 为数组第一个元素作为“当前最大值”。
    - 遍历数组后续元素，逐一与 AL 进行 CMP 比较。若内存数据 > AL，则更新 AL。

- **十六进制显示算法（难点）**：
    
    - 内存中的数值（如 F1H）是二进制存储的，直接显示会变成乱码。需要将其拆分为高4位（F）和低4位（1）分别转换为 ASCII 码。
        
    - **高4位提取**：利用 MOV CL, 4 和 SHR 逻辑右移指令。
        
    - **低4位提取**：利用 AND 0FH 掩码指令屏蔽高位。
        
    - **ASCII 转换**：
        
        - 若数值在 0~9，直接加 30H。
            
        - 若数值在 A~F（即 >9），需先加 07H，再加 30H（因为 ASCII 表中 '9' 和 'A' 之间间隔了 7 个符号）。
            

#### **4. 功能模块三：冒泡排序（双重循环与堆栈保护）**

- **算法逻辑**：外层循环控制排序轮数，内层循环进行相邻元素比较与交换。
    
- **寄存器冲突处理**：8086 的 LOOP 指令强制使用 CX 寄存器作为计数器。在双重循环中，内层循环会破坏外层循环的 CX 值。
    
- **解决方案**：采用 **堆栈（Stack）** 进行现场保护。
    
    - 进入内层循环前：执行 PUSH CX，将外层计数器压栈保存。
        
    - 内层循环结束后：执行 POP CX，从栈顶恢复外层计数器。
        
- **数据交换**：使用 XCHG 指令直接交换寄存器与内存单元的数据，比传统的中间变量法（TEMP）更高效。
    

#### **5. 功能模块四：系统时间显示（子程序设计）**

- **接口调用**：原计划使用 INT 21H (AH=2CH) 获取系统时间，返回值分别在 CH (时), CL (分), DH (秒) 中。
    
- **BCD 码转换**：时间数值（如 12）是二进制形式，需转换为两个 ASCII 字符（'1' 和 '2'）才能显示。
    
- **子程序封装**：编写 PRINT_TWO_DIGITS 通用子程序。
    
    - 利用 DIV 指令（16位除以8位）计算 AX / 10。
        
    - 商（AL）即为十位数，余数（AH）即为个位数。
        
    - 分别转换为 ASCII 码后调用 DOS 02H 功能输出。

**通用数字打印子程序（模块化设计）：**


```
; 子程序：将AL中的数值打印为两位十进制数
PRINT_TWO_DIGITS PROC
    PUSH AX             ; 保护现场
    PUSH DX
    PUSH CX

    MOV AH, 0           ; 高位清零
    MOV DL, 10
    DIV DL              ; AX / 10 -> AL(商), AH(余数)
    
    MOV BX, AX          ; 暂存结果
    
    ; 打印十位
    MOV DL, BL
    ADD DL, 30H         ; 转ASCII
    MOV AH, 02H
    INT 21H
    
    ; 打印个位
    MOV DL, BH
    ADD DL, 30H
    MOV AH, 02H
    INT 21H

    POP CX              ; 恢复现场
    POP DX
    POP AX
    RET
PRINT_TWO_DIGITS ENDP
```

### 七、 遇到的问题及解决方法

在代码调试过程中，主要遇到并解决了以下三个技术难题：

#### **1. 寄存器资源冲突导致的循环逻辑错误**

- **问题现象**：在调试“冒泡排序”功能时，发现程序只执行了一轮排序就意外退出，未能完成全排序。
- **原因分析**：通过单步调试（Single Step）观察寄存器，发现当内层循环结束时，CX 寄存器的值变为了 0。这是因为外层循环和内层循环都依赖 CX 作为 LOOP 指令的计数器，内层循环执行完毕后，直接覆盖了外层循环原本的计数值。
- **解决方法**：引入堆栈保护机制。在外层循环开始处添加 PUSH CX 指令，将当前计数值入栈备份；在内层循环结束后、外层 LOOP 指令执行前，添加 POP CX 指令恢复计数值。修改后排序功能正常。
    

#### **2. 条件跳转指令的“距离越界”错误**

- **问题现象**：在编写主菜单逻辑时，编译器报错 "Condition Jump out of range"。
    
- **原因分析**：8086 汇编中的条件转移指令（如 JE, JNE）属于“短跳转”（Short Jump），其操作数是 8 位有符号偏移量，跳转范围仅限于当前指令前后的 -128 至 +127 字节。由于本程序集成了 5 个功能模块，代码总长度远超 128 字节，导致无法直接从菜单跳转到后续的功能模块。
    
- **解决方法**：重构控制流逻辑。放弃直接使用 JE label 跳转到功能区

    ```
    CMP AL, '1'
    JNE NEXT_CHECK    ; 若不匹配，则跳转到近处检查下一个
    JMP FUNC_1        ; 若匹配，使用无条件跳转 JMP（支持长距离）
    NEXT_CHECK: ...
    ```
    
    利用 JMP 指令支持段内长跳转（Near Jump, 16位偏移）的特性解决了距离限制问题。

#### **3. 模拟器环境对中断支持的缺失**

- **问题现象**：在实现显示时间功能时，调用 INT 21H 的 AH=2CH 功能号后，Emu8086 模拟器弹出 "Interrupt not supported" 错误提示，导致程序中断。

- **原因分析**：Emu8086 是一款侧重教学的简化版模拟器，并未完整实现 MS-DOS 的所有中断向量表，特别是涉及硬件时钟读取的中断。

- **解决方法**：采用了 **“软件模拟桩”** 的测试策略。在代码中暂时注释掉中断调用指令，手动向 CH, CL, DH 寄存器写入预设的测试数据（如 12:34:56）。通过这种方式，成功验证了后续的“数值转 ASCII 码”算法和“格式化打印”子程序的正确性。此方法证明了代码逻辑在真实环境下是可行的。
