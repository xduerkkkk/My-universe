# 域名解析

1. <font color="#ff0000">A</font>
   多台主机可以映射到同一个域名，一台主机也可以映射到多个域名
   一个域名可以对应多个 IP，用途：负载均衡、CDN、容灾、就近访
   多个域名也可以对应同一个 IP，用途：虚拟主机、反向代理。Web 服务器通过 HTTP 的 `Host` 头或 HTTPS 的 SNI 判断用户到底访问哪个站点。
- **域名与主机/MAC**：主机是物理设备，MAC 是数据链路层硬件标识；而域名是应用层的逻辑名称。一台主机可以拥有成百上千个域名，一个域名也可以对应由数千台主机组成的集群。因此不存在“一一对应”。
2. <font color="#ff0000">B</font>
- **A 错误（符合题意）**：网络层进行路由和转发**只需要 IP 地址**。主机只要配置了公网 IP 就可以提供网络服务（例如通过 http://180.101.50.242 直接访问）。域名只是为了人类记忆在应用层加设的别名，**不是提供网络服务的强制前提**。
- **B 正确**：动态 DNS（DDNS）、CDN 调度或基于地理位置的解析，都会导致同一域名在不同时间/地点返回不同的 IP。
- **C 正确**：即虚拟主机原理，多个域名共享同一 IP。
- **D 正确**：**域名的层次划分与物理子网没有必然联系**。同一个 IP 子网（如 192.168.1.0/24）内的两台主机，完全可以分属于不同的域名（如 a.cs. tsinghua. edu. cn 和 b.math. tsinghua. edu. cn），由各自的管理域服务器维护。

4. D
- 根据 RFC 1034 标准，DNS 系统由三部分构成：
    1. **域名空间（Domain Name Space）**：树状层次命名结构及资源记录（RR）。
        
    2. **域名服务器（Name Servers）**：存储名字空间数据并响应查询的服务器。
        
    3. **解析器与分布式数据库（Distributed Database）**：DNS 在物理上分散、逻辑上统一，本质就是一个**层次化的分布式数据库**。
- **D 选项的本质是 NAT（网络地址转换）**：负责“内部私有 IP 到外部公网 IP 转换”的是运行在路由器/网关上的 **NAT 协议**，属于网络层/传输层功能，与应用层的 DNS 没有任何关系。

   权限域名、代理域名、本地域名服务器的区别
    本地域名服务器，就是主机 H 配置的 DNS 服务器，常见于校园网、公司网、运营商
    权威域名服务器。真正掌握某个域名区域记录的服务器。
    代理域名服务器，它收到你的 DNS 请求后，不自己从根服务器开始查，而是转发给上游 DNS，例如运营商 DNS、公共 DNS。它是个角色，谁都可能是代理域名
    1. **根服务器** 管 **顶级域**；    
	2. **顶级服务器** 管 **二级域/权限域**；
	3. **权限（权威）服务器** 管 **具体主机名与 IP（终点）**；
	4. **本地服务器** 不管域，只管 **代理查询与缓存**。

    时间从 H 发起 TCP 连接开始算


```
H                                              S
|                                              |
|------------------ SYN --------------------->|   0 ~ 0.5RTT
|<--------------- SYN + ACK ------------------|   0.5RTT ~ 1RTT
|---- ACK + HTTP 请求 GET 5KB ---------------->|   第 3 次握手带请求
|                                              |
|<---------------- 1KB 数据 ------------------|   S 初始 cwnd=1KB，只能发 1KB
|                                              |
|---- ACK + FIN ----------------------------->|   H 收到第 1 个数据段后立即发 FIN
|                                              |
|<----------- 1KB 数据 -----------------------|   
|<----------- 1KB 数据 -----------------------|   cwnd 变为 2KB，所以发 2KB
|                                              |
|---- ACK ----------------------------------->|   
|                                              |
|<----------- 1KB 数据 -----------------------|
|<----------- 1KB 数据 + FIN ----------------|   最后 2KB，FIN 挂在最后一个段上
|                                              |
|---- ACK ----------------------------------->|
|                                              |
|        H 等待 2MSL 后进入 CLOSED             |



从 H 发起连接开始：

第 1 个 RTT：完成前两次握手，H 发出第3次握手+HTTP请求  
第 2 个 RTT：H 收到 S 发来的第 1KB 数据  
第 3 个 RTT：H 收到 S 发来的第 2KB + 第 3KB 数据  
第 4 个 RTT：H 收到 S 发来的第 4KB + 第 5KB 数据，以及 FIN
```
