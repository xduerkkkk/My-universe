# 检错纠错
偶校验，数据中有偶数个 1，那异或结果就是 0. 比较方便。
那我异或，奇数个 1 异或结果是 1 。将结果放到第一位。

CRC
1. **直接发 `73` 行不行？**
    
    不行。如果中间信号干扰，`73` 变成了 `75`，我收到 `75` 怎么知道它错了？
    
2. **CRC 的做法：**
    
    - 你要在 `73` 后面**补一个 0**，变成 `730`。（这就相当于图片里的**移位补 0**）。
        
    - 然后你用 `730` 除以我们约定的暗号 `9`：$730 \div 9 = 81 \dots 1$ （余数是 1）。
        
    - 接下来，你把这个**余数 1**，偷偷替换掉刚才补的那个 0，替换的逻辑本质上是**“减去余数也就是把 `730` 变成了 `729`。
        
3. **发送与接收：**
    
    - 你把拼好的 `729` 发给我。
        
    - 我收到 `729` 后，马上用我们约定的暗号 `9` 去除：$729 \div 9 = 81 \dots 0$。
        
    - **重点来了！因为余数是 0（完美整除），我就敢 100%确定，数据在传输过程中没有出错！** 如果信号干扰变成了 `725`，我除以 `9` 余数肯定不是 0，我就知道数据坏了，让你重发。
        

**这就是 CRC 的全部逻辑！** 剩下的，只是把十进制换成了计算机喜欢的“二进制”而已。
![](../../../../../assets/image/01王道视频-1776763370383.jpeg)

- **$G(x) = x^3 + x^2 + 1$** 只是一个纸老虎，它就是用来生成我们刚才说的“暗号”的。

最高次幂是 3（$x^3$），这意味着什么？意味着最后产生的余数**最多只有 3 位**。

- 既然余数有 3 位，我们就得在信息后面**补 3 个 0**，变成 `101001000`。
    
- 这就好比上面例子里把 `73` 变成 `730`，给即将算出来的余数（CRC 码）腾地方
为什么不用普通的加减乘除？因为计算机硬件做普通的除法太慢了（要考虑借位）。所以前人发明了“模 2 除法”（其实就是 **异或运算 XOR**）。

- **异或规则极其简单：相同为 0，不同为 1。** （完全不用管什么借位）。
    
- 用带着 0 的数据 `101001000` 去“除以”暗号 `1101`。
    
- 算到最后，得出余数是 `011`。（这就是那 3 位 CRC 校验码）。
    

#### 第四步：拼接发送

- 把算出来的余数 `011`，填到刚才补 0 的位置上。
    
- 最终发送出去的数据就是：`101001011`

### 为什么“模 2 除法”就是异或？它怎么做到不改变前面数字的？

计算机硬件如果做普通的加减乘除，是非常慢的，因为要一直算进位和借位（比如 9999 + 1，要连进 4 次位，电路会等得不耐烦）。

为了在网络传输中追求极致的计算速度，数学家们引入了“模 2 运算”这种神奇的规则，它的核心法则只有一条：**不进位，不借位**。

在这种规则下，奇迹发生了：**加法、减法、异或，这三者变成了一模一样的东西！**

你来看看“不借位的减法”是什么结果：

- 1 - 1 = 0 （和异或“相同为 0”一样）
    
- 0 - 0 = 0 （和异或“相同为 0”一样）
    
- 1 - 0 = 1 （和异或“不同为 1”一样）
    
- 0 - 1 = **1** （注意这里！普通减法要借位，但模 2 减法不借位，直接等于绝对差值 1。这就和异或“不同为 1”一样！）
    

**既然减法 = 异或，那么除法是什么？** 你小学学过，除法本质上就是**不断地做减法**（比如 10 除以 3，就是 10-3-3-3 剩 1）。所以在模 2 的世界里，**除法就顺理成章地变成了“不断地做异或”**！

### 最终联动：为什么二进制里的“减去余数”像是“偷偷替换”？

刚才我们在十进制里说，要把余数**减掉**（730 - 1）才能完美整除。在二进制 CRC 里，我们同样是把补 0 后的数据，**减去算出来的余数**。

但是，因为**模 2 减法 = 异或**，我们来看看把带有三个 0 的数据 `101001000` 减去余数 `011` 会发生什么：

Plaintext

```
  101001000 (信息码+补的0)
-       011 (余数)
----------- (模2减法，即异或，不借位！)
  101001011
```

你看！因为是异或运算，任何数异或 0 都等于它自己。所以：

- 前面 `101001` 异或 `000000`，完全没变。
    
- 后面补的 `000` 异或 `011`，直接变成了 `011`。
    

它没有产生任何借位，完美保留了前面的信息码，看起来就像是把后面的三个 0 给**“生生替换”**掉了一样。这就是数学之美，也是 CRC 校验能在网卡里以极高速度运行的根本原因！

# 流量控制可靠传输

## 停止等待
滑动窗口，T 和 R 都是 1
确认机制，接受方接受到 i 号帧且没有检测出差错，则返回确认帧
重传机制，若发送方超时未收到确认帧，则重传
帧编号，要求 $W_T +W_R <= 2^n$  （所有都这样，不再赘述。理由是


假设我们用 $n$ 个比特来编号，那么总共可用的序号池大小就是 $2^n$（序号从 $0$ 到 $2^n - 1$）。

**第一步：发送方火力全开**

发送方一口气发送了填满整个发送窗口 $W_T$ 的数据帧。假设序号是从 $0$ 到 $W_T - 1$。

**第二步：接收方完美接收，窗口前移**

接收方运气很好，完美收到了这 $W_T$ 个帧。

此时，接收方会做两件事：

1. 发送确认帧（ACK）。
    
2. 将自己的接收窗口向前滑动 $W_T$ 个位置。
    
    此时，接收方正在**期待接收的新帧**的序号范围变成了：$[W_T, W_T + W_R - 1]$。
    

**第三步：天有不测风云（极端情况发生）**

接收方发出去的所有 ACK，在网络中全部丢失了！发送方一个都没收到。

**第四步：发送方超时重传**

发送方的计时器超时了。它认为自己刚才发的 $0$ 到 $W_T - 1$ 号帧全丢了，于是它开始**重传旧的 $0$ 号帧**。

**第五步：避免灾难的关键判决**

现在，重传的旧 $0$ 号帧到达了接收方。

接收方目前的接收窗口期待的序号范围是 $[W_T, W_T + W_R - 1]$。

如果这个“旧 $0$ 号”的序号，刚好落在了接收方期待的“新序号”范围内，接收方就会把它当成新数据收下，这就造成了极其严重的数据错误！

为了绝对防止这种情况发生，**新接收窗口的最右边界，绝对不能碰到下一轮的序号 $0$（也就是绝对不能超过序号池的总容量 $2^n$）**。

因此，数学表达就是：

接收窗口的上限索引 $< 2^n$

$$W_T + W_R - 1 < 2^n$$

因为窗口大小都是整数，所以得出核心公式：

$$W_T + W_R \le 2^n$$）

## 错误处理的规律
### 规律一：窗口滑动的“唯一通行证”
**规律：发送窗口的左边缘能否右移，只取决于“窗口内最早的那个帧”是否收到了应答。**

*   不论是哪种协议，发送窗口就像一列火车。火车头（窗口右侧）可以不断吃进新数据，但火车尾（窗口左侧，即最早的那个未确认帧）如果不动，整列火车就卡住了。
*   **在“数据帧丢失”或“确认帧丢失”时：** 那个最早的帧会因为等不到 ACK 而超时。只要它不被确认，窗口就**绝对不会移动**。
*   **后果：** 窗口被堵塞，发送端最终会停止发送，直到超时重传。

---

### 规律二：数据丢失 vs. 确认丢失（ sender 的视角）
**规律：对发送方（Sender）来说，数据丢失和确认丢失是“等价”的，最终都会触发超时重传。**

*   **数据帧丢了：** 接收方没收到 $\rightarrow$ 没发 ACK $\rightarrow$ 发送方超时 $\rightarrow$ **重传**。
*   **确认帧（ACK）丢了：** 接收方收到了 $\rightarrow$ 发了 ACK 却丢在半路 $\rightarrow$ 发送方没收到 $\rightarrow$ 发送方超时 $\rightarrow$ **重传**。
*   **共性结论：** 发送方很“多疑”。只要在规定时间内没看到对应的 ACK，它就默认对方没收到，直接重发。重发后，接收方如果发现是重复帧，直接丢弃数据并补发一个 ACK 即可。

---

### 规律三：累积应答（Cumulative ACK）的“掩盖”效应
**规律：在 GBN（以及某些实现的停止-等待）中，后一个 ACK 可以“顺便”确认前一个帧。**

这是理解“确认帧丢失”时最关键的规律。
*   假设发送了帧 1, 2, 3。
*   **场景：** ACK 1 和 ACK 2 都丢了，但 ACK 3 成功到达了。
*   **在 GBN 中：** 发送方收到 ACK 3，会认为“既然 3 都收到了，说明 1 和 2 肯定也收到了”（因为 GBN 接收端只按序接收）。
*   **结果：** 窗口直接越过 1 和 2，猛地向右滑动到 3 之后。**之前的 ACK 丢失被“掩盖”了，不影响传输。**
*   **在 SR（选择重传）中：** 不行。SR 是“点对点应答”，ACK 3 只管帧 3。ACK 1 丢了，帧 1 必须超时重传。

---

### 规律四：接收窗口大小决定了“挑食”程度
**规律：接收窗口 $W_r = 1$（如 SW, GBN）是“完美主义者”，$W_r > 1$（如 SR）是“缓存大师”。**

*   **当数据帧丢失时：**
    *   **$W_r = 1$ 的 GBN：** 非常固执。如果你丢了帧 2，后面来的帧 3, 4, 5 哪怕全到了，它也全部**乱序丢弃**，并一直发 `ACK 1`（告诉你：我要的是 2！）。这导致了 GBN 的“后退 N 帧”现象。
    *   **$W_r > 1$ 的 SR：** 比较包容。丢了帧 2，后面来的帧 3, 4, 5 会先**存在缓存里**。它只发 `ACK 3, 4, 5` 告诉发送方这些到了，等发送方重传帧 2 补上缺口后，窗口才一起滑动。

---

### 综合对比总结表

| 场景 | 规律总结 |
| :--- | :--- |
| **数据帧丢失** | 无论哪种协议，都会导致发送方**超时重传**。区别在于 GBN 浪费带宽（重传一堆），SR 精准补救。 |
| **ACK 丢失** | **GBN 具有鲁棒性**：靠后续的 ACK 能救回来；**SR 比较死板**：丢哪个 ACK 就重传哪个帧。 |
| **窗口移动** | 只有**窗口左界**被确认了，窗口才能右移。这就是为什么“丢帧”会造成“停顿”。 |
| **编号重复** | 为了不让接收方分不清“这是老帧还是新帧”，**窗口总大小必须小于序号范围的一半**（SR 是 $2^{n-1}$，GBN 是 $2^n-1$）。 |

**一句话记住它们的区别：**
*   **停止-等待**：一次只玩一个，简单但慢。
*   **GBN**：发送方大手大脚，接收方极其挑食（只要按序的）。
*   **SR**：发送方精准，接收方带缓存（能容忍乱序）。

### 一、以太网基础 (1980年开始商用)

- **标准：** IEEE 802.3。
    
- **物理层编码：** 早期以太网普遍采用 **曼彻斯特编码 (Manchester Encoding)**。
    
- **核心特性：**
    
    - **10Base5** 中的数字含义：“10”代表带宽 10Mbps，“Base”代表基带传输，“5”代表单段最大传输距离 500米。
        

---

### 二、 早期以太网：同轴电缆 (1980年代)

- **物理介质：** 同轴电缆。
    
- **拓扑结构：** **总线形**。
    
- **MAC层协议：** 必须使用 **CSMA/CD**（载波监听多路访问/冲突检测）。
    
- **特点：** 所有主机共享同一根电缆，属于共享式以太网。由于是共享信道，同一时间只能有一个节点发送数据。
    

---

### 三、 现代以太网的主流：双绞线 (1990年代至今)

这是目前应用最广的形态，经历了从“集线器”到“交换机”的重大演进：

#### 1. 使用集线器 (Hub) 连接 (10BaseT, 1990年)

- **物理特征：** **物理上是星形**（线缆汇聚到Hub），但**逻辑上是总线形**。
    
- **工作模式：** **半双工 (Half-Duplex)**。
    
- **MAC层协议：** 必须使用 **CSMA/CD**。
    
- **本质：** 集线器只是一个物理层设备（多端口中继器），所有端口共享带宽，存在冲突域。
    

#### 2. 使用交换机 (Switch) 连接 (1994年后)

- **物理特征：** **物理和逻辑上都是星形**。
    
- **工作模式：** 支持 **全双工 (Full-Duplex)** 模式（也可兼容半双工）。
    
- **MAC层协议的变化：**
    
    - **在半双工模式下：** 依然采用 **CSMA/CD** 争抢信道。
        
    - **在全双工模式下：** **不需要争抢信道**，因此不需要 CSMA/CD 协议（即图中写的 **NULL**）。
        
- **本质：** 交换机是链路层设备，每个端口是一个独立的冲突域，通过内部背板带宽实现无冲突传输。
    

---

### 四、 远程与高性能扩展：光纤以太网 (1993年)

- **代表标准：** 10BaseF (1993年)。
    
- **用途：** 扩大以太网覆盖范围，长距离传输。
    
- **连接方式：** **点对点**（通常用于连接中继器、集线器或交换机，较少直接连终端）。
    
- **传输特性：**
    
    - 通常使用 **两条光纤** 实现 **全双工通信**（一条发，一条收）。
        
    - 因为是全双工且点对点，所以 **不需要 CSMA/CD 协议 (NULL)**。

### 一、网络适配器（网卡）的核心作用

网卡是连接计算机内部总线和外部网络的“桥梁”，它跨越了物理层和数据链路层。

1. **数据转换**：
    
    - **串行/并行转换**：计算机内部总线进行的是**并行通信**（一次传一堆数据，速度快但距离短），而网络线上进行的是**串行通信**（一个比特一个比特传），网卡负责它们之间的转换。
        
2. **数据缓冲**：
    
    - 网卡自带 **RAM（帧缓冲）**。因为网络上传输速率和计算机 CPU 处理速率不匹配，需要有个“仓库”暂时存放数据帧。
        
3. **封装与解封**：
    
    - 发送时：把 IP 数据报封装成 MAC 帧。
        
    - 接收时：把 MAC 帧拆开，取出 IP 数据报交给 CPU。
        
4. **协议实现**：
    
    - 网卡硬件里固化了以太网协议（如 CSMA/CD）或 WiFi 协议（802.11）。

### 二、 核心考点：MAC 地址 (物理地址)

图中特别标注了 MAC 地址的特性，这是数据链路层的核心知识：

1. **定义与位置**：
    
    - **全称**：介质访问控制地址（Media Access Control Address）。
        
    - **存放位置**：固化在网卡的 **ROM** 中。当你买了一块网卡，它的 MAC 地址就定死了。
        
2. **格式与长度**：
    
    - **长度**：**48 bit（6 字节）**。
        
    - **表现形式**：通常用 12 位十六进制数表示（如 00-0C-29-4F-8B-35）。
        
3. **三大特性**：
    
    - **全球唯一性**：由 IEEE 管理，前 3 个字节是厂家代码（OUI），后 3 个字节由厂家自行指派，确保全球范围内没有两块相同的网卡。
        
    - **物理属性**：它是“硬件地址”，标志着设备本身；而 IP 地址是“逻辑地址”，标志着设备在网络中的位置。
        
    - **不可变性**：通常情况下，MAC 地址伴随硬件一生，不会随网络环境改变（图中对比了 IP 地址“可能会变化”）。

## 无线局域网

![](../../../../../assets/image/01王道视频-1777105763130.jpeg)

![](../../../../../assets/image/01王道视频-1777107196733.jpeg)


![](../../../../../assets/image/01王道视频-1777106671462.jpeg)

这两张图讲的是 **802.11（WiFi）无线局域网的 MAC 层工作机制**。

无线网络和有线以太网最大的区别在于：**无线信号是向四周广播的，且无法边发边听（不能做碰撞检测 CD）**。因此，它必须通过一套更复杂的“点名”和“中转”机制来保证数据不乱。

我们可以把这两张图的内容串联为三个重点：

### 一、为什么 WiFi 帧有 4 个地址？（核心难点）
在有线以太网（802.3）里只有“源地址”和“目的地址”。但 WiFi 里，**移动站之间通常不能直接通信，必须由 AP（基站/路由器）中转**。

这就引入了“中转站”的概念。图中第一张图的重点就是教你如何区分这几个地址：

1.  **地址 1 (Receiver)**：**接收端**。即这根电磁波“现在”要给谁。
2.  **地址 2 (Transmitter)**：**发送端**。即这根电磁波“现在”是谁发出来的。
3.  **地址 3**：**真正的那一头**（源或目的）。

**记忆口诀（对照图中的红字）：**
*   **去往 AP (To DS=1, From DS=0)**：
    *   地址 1 是 **AP**（中转站）；地址 2 是**源站**（起点）；地址 3 是**目的站**（终点）。
    *   *理解：我发给 AP，让它帮我转交给终点。*
*   **来自 AP (To DS=0, From DS=1)**：
    *   地址 1 是**目的站**（终点）；地址 2 是 **AP**（中转站）；地址 3 是**源站**（起点）。
    *   *理解：AP 拿到包后，发给我（终点），包里写着最初是谁（起点）发的。*


当主机 H 发送数据要访问 Internet 时，这个包必须先交给 AP，再由 AP 转交给路由器 R。

- **地址 1 (接收端 RA)：... 9b (AP 的 MAC 地址)**
    
    - 理解： 无线信号是发给谁的？是发给 AP 的。所以地址 1 必须填 AP。
        
- **地址 2 (发送端 TA)：... 9a (主机 H 的 MAC 地址)**
    
    - 理解： 这根电磁波是谁发出来的？是主机 H。
        
- **地址 3 (终点/目的地址 DA)：... 9c (路由器 R 的 MAC 地址)**
    
    - 理解： **这是最关键的一点！** 虽然这个包现在给了 AP，但 AP 只是个“中转站”。AP 拿到包后，需要把它转换成有线以太网帧发给 R。**AP 怎么知道要把这个包转发给谁呢？** 答案就在“地址 3”里。



> **关于地址 4**：它只在两个 AP 之间互连（无线桥接）时才用到，普通手机连路由器时用不到。




### 二、 CSMA/CA：有礼貌的“碰撞避免”
因为无线电无法做到“边发边听”（碰撞检测），所以它采用了 **CSMA/CA**（载波监听多路访问/碰撞**避免**）。


第二张图展示了这种“礼貌”的通信流程，核心是 **RTS/CTS 机制**（主要用于解决“隐蔽站”问题）：

1.  **RTS (请求发送)**：源站想发数据前，先大声喊一句：“AP，我要发数据给你，大概要占多长时间！”
2.  **CTS (允许发送)**：AP 回复一句：“好的，你可以发。**其他人请闭嘴等这段时间！**”
    *   这一步最关键：所有听到 CTS 的其他站都会自觉等待（NAV 机制），从而**避免了碰撞**。
3.  **DATA**：源站开始安全地发送数据。
4.  **ACK**：AP 收到后回一个确认。

**时间间隔 (SIFS/DIFS)**：
*   **SIFS**：短间隔，用于 ACK、RTS、CTS 等高优先级的小帧，抢占先机。
*   **DIFS**：长间隔，普通数据帧发送前必须等这么久，没人在说话才能发。

---

### 三、帧的分类（说人话版）
图二左侧总结了三种帧，它们各司其职：

1.  **数据帧**：真正装载我们要传的文件、网页内容的。
2.  **控制帧**：相当于“交警”，包括 **ACK**（确认）、**RTS/CTS**（清场）。它们不带数据，只负责协调交通。
3.  **管理帧**：相当于“行政”。比如你手机搜到 WiFi（**探测请求/响应**）、输入密码关联 WiFi、心跳包等，都是管理帧在跑。

---

### 💡 总结对比：802.3 (有线) vs 802.11 (无线)

| 特性          | 以太网 (802.3)       | WiFi (802.11)         |
| :---------- | :---------------- | :-------------------- |
| **MAC 地址数** | 2 个               | 3 或 4 个（因为有 AP 中转）    |
| **碰撞处理**    | **CSMA/CD**（碰撞检测） | **CSMA/CA**（碰撞避免）     |
| **核心协议**    | 发现碰撞就停            | 发之前先“预约”（RTS/CTS）     |
| **确认机制**    | 物理层不强制确认          | **必须有 ACK**（因为无线容易丢包） |

**一句话总结这两张图：**
无线局域网通过 **4 地址格式** 标识中转路径，通过 **RTS/CTS 握手** 提前清场，通过 **ACK 确认** 保证可靠性，从而在杂乱的无线空气中实现有序的数据传输。
