- 虚电路服务本身通常**由网络层提供可靠交付**。在虚电路网络（如传统的 X.25、ATM 虚通道）中，网络层节点（交换机/路由器）之间具备确认和差错重传机制，直接由虚电路协议本身保证数据的可靠性与有序性，无需依赖上层（如传输层）协议。
- **对比数据报**：数据报网络（如 IP 网络）的网络层只提供尽最大努力交付（无连接、不可靠），因此**数据报才真正依赖上层协议（如传输层的 TCP）来实现差错控制与可靠传输**。

- 只有在**建立连接阶段**的呼叫请求分组中才需要携带完整的全局目的地址（用于寻路）。连接一旦建立完毕，后续传输的数据分组首部**不再包含全局目的地址，仅携带一个局部的“虚电路号（VCID / VCI）”**（开销极小）。中间节点查表时只需根据 <入端口, 入VCID> -> <出端口, 出VCID> 转发。
- **对比数据报**：数据报方式中，每个分组都是独立的，因此**每个数据报首部都必须包含完整的全局源 IP 和目的 IP 地址**。


1. **电路交换的思想**：通信前先建立逻辑连接，路径预先确定，所有分组沿固定路径传输，天然保证了**按序到达**，无乱序重组时延；
    
2. **分组交换的本质**：物理链路上依然采用统计时分复用（分组传输），不独占物理带宽，利用率高；
    
3. **适合场景**：虽然有建立连接的初期时延，但在长时间、连续传输时，中间节点无需为每个分组重新计算路由（只需匹配 VCID 快速转发），转发时延低且稳定，实时性更好。


**多站点同时使用一段物理链路实行虚电路交换会产生冲突，无法正常通信**

- **错误原因**：虚电路本质上仍然是**分组交换**，采用**统计时分复用（STDM）**。同一条物理链路上可以同时承载成百上千条不同的逻辑虚电路。不同站点的数据分组交替在链路上传输，依靠分组首部不同的**虚电路号（VCID）**相互区分，不会发生冲突。

**引发灾难性后果**：

- 如果要发送 ICMP 报文，路由器必须将 ICMP 报文的目的地址填为该损坏分组的“源 IP 地址”。

**协议硬性规定（408 结论）**：

- 当路由器或主机收到 **首部检验和出错** 的 IP 分组时，**唯一的动作是静默丢弃（Silently Drop）**，**绝不发送任何 ICMP 差错报告**。

    MTU
	- **全称**：Maximum Transmission Unit
	- **含义**：一条链路上能发送的**最大帧或数据报长度**（字节数）。
	- **用途**：如果 IP 数据报比链路 MTU 大，需要**分片**；每个分片的大小不超过 MTU。
	每个 IP 数据报都有唯一标识。当数据报被分片时，所有分片的“标识”都一样，方便目的主机重新组装。
	
	**DF (Don't Fragment，第 2 bit)**：禁止分片

	- DF = 1 → 不能分片，如果数据报超过链路 MTU，会丢弃并返回 ICMP 报文
	  
	  **MF (More Fragments，第 3 bit)**：还有更多分片
当 DF = 1 且报文长度超过链路 MTU 时，路由器丢弃该分组后，**必须向源主机发送 ICMP 差错报文进行报告**

- **默认网关（Default Gateway）**：
    
    - 它是连接当前局域网与外网的**路由器接口的真实 IP**。
        
    - 它必须是当前网段内的一个**合法主机 IP**（工程中习惯配成第 1 个或最后 1 个可用地址，如 192.168.1.1 或 192.168.1.254）。
        
- **默认路由（Default Route）**：
    
    - 它是路由表里的一条规则：当所有具体路由都匹配不上时，走这条兜底路由。
        
    - 它的**目的网络写为全 0**（即 0.0.0.0/0），而它的**下一跳填的就是默认网关的真实 IP**
一、语境 1：在真实发送的 IP 数据报首部中

在网络上跑的每一个真实 IP 数据报中，首部都有【源 IP 地址】和【目的 IP 地址】两个字段：

1. **作为源 IP（合法）**：
    
    - 当一台电脑刚开机，还没有分配到 IP 时（例如向 DHCP 服务器申请 IP），它不知道自己是谁，此时发送的 DHCP Discover 数据报中：
        
        - **源 IP 填 0.0.0.0**（含义：本网络上的本主机，目前暂无 IP）。
            
        - **目的 IP 填 255.255.255.255**（受限广播）。
            
2. **作为目的 IP（绝对非法）**：
    
    - 网络上**绝不可能**出现一个目的 IP 为 0.0.0.0 的数据报。你永远无法把数据发送给 0.0.0.0。
        
    - 所以表格中写的是：**在数据报首部中，0.0.0.0 只能出现在源 IP 字段，绝不能出现在目的 IP 字段。**

 二、 语境 2：在路由器内部的“路由表”中

路由表是路由器用来查路的字典，路由表中的每一行记录有三个主要字段：  
[ 目的网络前缀 | 子网掩码 | 下一跳 ]

在路由表里，**默认路由（Default Route）** 的记录长这样：

- **目的网络前缀**：0.0.0.0
    
- **子网掩码**：0.0.0.0（简写为 0.0.0.0/0）
    
- **下一跳**：192.168.1.1（默认网关 IP）
    

#### 这里的 0.0.0.0/0 是怎么工作的？

它不是指具体某台机器，而是一个**数学上的“万能通配符”**。

根据前面讲过的查表匹配公式：

```
目的 IP & 子网掩码目的网络前缀目的 IP & 子网掩码=?目的网络前缀
```

- 假设来了一个要去往百度的数据报，其真实目的 IP 是 202.108.22.5。
    
- 路由器拿这个目的 IP 与默认路由的掩码相与：  
    
    ```
    202.108.22.5 & 0.0.0.0=0.0.0.0202.108.22.5 & 0.0.0.0=0.0.0.0
    ```
    
- 计算结果是 0.0.0.0，与默认路由记录的目的网络前缀 0.0.0.0 **完全相等**！
    

**结论**：因为任何 32 位二进制数与全 0 相与，结果永远等于全 0。所以，**任何 IP 数据报只要前面的具体路由都没匹配上，都必定会 100% 匹配中这条默认路由**，被送给下一跳（默认网关）。

---



- **数据包首部**里的 0.0.0.0：只能当**源 IP**（表示我还没 IP）。
    
- **路由表条目**里的 0.0.0.0/0：代表**通配所有目的网络**（表示所有未明路径的兜底出口）。

#### 1. 什么叫“重叠（Overlap）”？
* **定义**：两个 CIDR 地址块所覆盖的 IP 范围存在**交集（公共 IP）**。
* **实际含义**：
  * 若地址块 $A$ 包含的某些 IP 同时也属于地址块 $B$（如 $B$ 是 $A$ 的子网），则两者“重叠”。
  * 网络规划中互不隶属的独立子网**绝对不允许重叠**，否则路由器无法判断报文该发往何处。

#### 2. 什么叫“聚合（Aggregation / 路由聚合）”？
* **定义**：将多个连续的、较小的 CIDR 地址块合并为一个**掩码前缀更短的单一 CIDR 地址块（超网）**。
* **规则（伙伴原则）**：
  * 两个等长为 `/n` 的地址块，若前 $n-1$ 位完全相同，且第 $n$ 位**一个是 0、一个是 1**，它们就能刚好合并成一个 `/ (n-1)` 的单一地址块。

#### 3. 什么叫“引入多余地址”？
* **定义**：合并后的新 CIDR 地址块所包含的 IP 总数，**大于**参与合并的各小地址块 IP 数之和。
* **实际含义**：
  * 两个 `/26` 的块各自有 $64$ 个 IP，合起来共 $128$ 个 IP。
  * 如果它们是“相邻且对齐”的伙伴，合并成一个 `/25`（包含 $128$ 个 IP），则 $128 = 64 + 64$，**没有引入多余地址**。
  * 如果它们不相邻（如一个在最开头 `0~63`，一个在最末尾 `192~255`），要用一个单一 CIDR 块把它们包住，就必须用 `/24`（包含 $256$ 个 IP）。此时新块里包含了原本不属于两者的 `64~191`（共 128 个地址），这就叫**“引入了多余地址”**（在路由表中会导致黑洞路由或错误路由）。

* **移动 IP 的 4 个完整阶段**：
  1. **代理发现（Agent Discovery）**：移动节点（MN）监听广播/组播的“代理通告”报文，判断自己是在家（归属网络）还是在外（被访网络）。
  2. **注册（Registration）**：MN 到达外地并获得转交地址（COA）后，**必须向自己的“归属代理（Home Agent, HA）”注册登记**，告知 HA：“我现在在外地，我的新转交地址是 xxx，以后发给我的数据请转寄到这里”。
  3. **分组路由（Packet Routing）**：建立隧道，实现数据的收发（支持单播、广播、多播）。
  4. **注销（Deregistration）**：MN 回到归属网络后，向 HA 注销转交地址，恢复为普通主机模式。
* **选项错误定位（C 项）**：
  * C 项说“通知外部代理”是错的。外部代理（FA）本来就是当地的网关，它早已知道 MN 的存在；**注册的核心对象是远在家乡的“归属代理（HA）”**，这样 HA 才能建立归属地址与转交地址的绑定表项。

---

### 第 02 题：考查移动 IP 的双地址机制（归属地址 vs 转交地址）

* **正确答案**：**C**
* **核心机制解析**：
  移动 IP 为了在主机移动时不中断现有的 TCP 连接，为移动主机分配了**两个 IP 地址**：
  1. **归属地址（Home Address，永久固定）**：
     * 移动主机在原来归属网络中获得的长期静态 IP。
     * **作用**：作为传输层连接（TCP 报文段）的端点标识。无论主机移动到哪里，对外通信的源 IP / 目的 IP 永远是这个归属地址，保证 TCP 连接不掉线。
  2. **转交地址（Care-of Address, COA，动态改变）**：
     * 移动主机漫游到被访网络（外地）时，临时获取的一个在该外地网络合法的 IP 地址。
     * **作用**：作为网络层数据转发隧道的物理终点。**只要主机切换到新的子网，转交地址就必须动态更新**。

---

### 第 03 题：考查移动 IP 的“三角路由（Triangle Routing）”机制

* **正确答案**：**D**
* **核心机制拆解（直接发、间接接）**：

```
                    [ 通信节点 Correspondent Node ]
                     ↗                           ↑
      (1) 直接发送  ／                             │ (2) 传统单播发往归属地址
                  ／                              │
                 ／                               ▼
[ 移动节点 (在被访网络) ] ◀=====[ 隧道中转 ]=====[ 归属代理 Home Agent (归属网络) ]
                            (3) 间接接收
```

1. **发送数据报（可以直接发送）**：
   * 移动节点向通信节点发送数据时，构造普通 IP 报文（源 IP = 自身归属地址 `160.80.40.20`，目的 IP = 通信节点 IP）。
   * 移动节点直接把数据包交给**被访网络的本地默认网关**，网关按照全球单播路由将其**直接转发**给通信节点，不需要绕回原籍网络。
2. **接收数据报（不能直接接收）**：
   * 通信节点发送数据时，目的 IP 填的是移动节点的归属地址 `160.80.40.20`。
   * 全球路由只会把该报文路由到其归属网络 `160.80.0.0/16`。
   * 归属代理（HA）在原籍网络拦截该报文，将原报文作为载荷封装进一个新 IP 报文（目的 IP 填为转交地址 COA），通过 **IP 隧道（IP-in-IP）** 发送给被访网络。
   * 被访网络的代理拆封后，再递交给移动节点。
* **结论**：移动节点**可以直接发送数据报，但不能直接接收数据报**。
