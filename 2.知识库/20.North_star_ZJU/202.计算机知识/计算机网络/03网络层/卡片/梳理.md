一个主机想接互联网，
需要有 IP 地址，也要知道默认网关的 IP 地址，才能发送和接收各种数据报。


那 MAC 地址呢，属于物理地址，数据链路层传递时使用。
但为什么 WIFI 的数据链路局域网和有线的数据链路局域网，是两个网卡，两个 MAC 地址？
就是不同体系要有不同“地址”？

	比如笔记本里可能有：
	
	无线网卡 Wi-Fi adapter  
	有线网卡 Ethernet adapter
	
	它们分别连接不同的数据链路层网络：
	
	Wi-Fi：802.11 无线局域网  
	有线以太网：802.3 以太网
	
	每个接口都要能独立收发链路层帧，所以通常每个接口有自己的 MAC 地址。
	
	Wi-Fi 网卡 MAC：AA-AA-AA-AA-AA-AA  
	有线网卡 MAC：BB-BB-BB-BB-BB-BB
	
	所以更准确的说法是：
	
> 	**一个网络接口通常对应一个链路层地址，也就是一个 MAC 地址。**

首先，主机通过 DHCP 协议，“DORA”四步，
比如 DHCP 分配完后，电脑可能得到：

IP 地址：192.168.1.100  
子网掩码：255.255.255.0  
默认网关：192.168.1.1  
DNS：114.114.114.114 / 8.8.8.8  


IP 地址：说明我是谁  
子网掩码：判断目标和我是不是同一个局域网  
默认网关：如果目标不在本地网段，就交给谁  
DNS：把域名解析成 IP  
MAC 地址：在当前局域网这一跳里真正发给谁


找到了默认网关的 MAC 地址。

一切准备就绪， 
首先把上一层传输层数据报拿来，封装好，就成了 IP 数据报（考点，IP 报首部）
有源 IP 和目的 IP

IP 用于网络层定位，传输层是只有端口定位，数据链路层是具体的物理定位（MAC 地址）

主要学习了 IPV4 这个方法，分配给全球所有设备  

具体划分细节，有子网划分，CIDR 地址块（这和子网划分知识点有什么区别），路由聚合，NAT 表，特殊 IP 含义

CIDR 的核心是：

> 不再死板按照 A/B/C 类默认掩码，而是用 `/n` 表示前 n 位是网络前缀。

设备发送 IP 数据报时，先查看目标 IP 是否与自己相同子网，若相同，ARP 找 Mac 地址，不同，直接抛给默认网关。
默认网关通过路由转发表，决定下一跳 IP  出接口   ARP 表里没有，就发 ARP 请求。


转发口 / 出接口：路由器的某个接口，比如 eth0、eth1、LAN 口、WAN 口  
接口 MAC：这个接口自己的 MAC 地址  
下一跳 MAC：对面设备接口的 MAC 地址
