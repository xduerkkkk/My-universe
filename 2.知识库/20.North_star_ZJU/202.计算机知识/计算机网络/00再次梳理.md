首先，有主机（客户端）与服务器的定义。

客户端是手机，电脑，等设备上的具体进程
服务器也是 google 的 Web 服务器进程，

如何定位这个进程，在本机内是使用“端口”
而本机又如何定位？
- MAC 定位物理地址
  同一个设备，在不同性质的网络有不同的地址，以太网，无线网...【网络的划分】。MAC 是定位链路中的位置 
- IP 地址
  是局域网，互联网中，另一种定位方式【IPv4，v6 】

以有线网卡为例，【只学了有线以太网和无线局域网的数据链路层区别？其他区别呢？】
主机想要访问原在 google 服务器的 html 文件。

首先，主机得有自己的定位方式。
主机发布广播帧，帧是请求报文+外接 UDP 首部+外接 IP首位+MAC 首部尾部，
会发给整个局域网，在家庭里，肯定会发到路由器，只有路由器才承担 DHCP 服务器（全称是？）
其他的手机电脑不鸟这个帧。
Dynamic Host Configuration Protocol


经过 DORA【DHCP 流程】，
主机现在有了
-  IP
- 默认网关的 IP
- 子网掩码
- DNS（全称？） 服务器

路由器连接这个局域网的那个接口，就是默认网关

现在，进入应用层
用户输入www.google.com，
首先客户端会 DNS 解析，
得到服务端的 IP

然后先查看 IP 是否与自己同一个子网，
发现不是，
于是发给默认网关。

但是现在只有默认网关的 IP，于是使用 ARP 协议
