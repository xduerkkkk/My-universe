### 一、硬核解惑：为什么 `[low, high)` 搭配 `high = mid`，最后 `low == high` 必定是答案？

假设数组被分成了两半，左边是不满足条件的（记为 `0`），右边是满足条件的（记为 `1`）。
数组长这样：`0, 0, 0, 1, 1, 1`。我们要找**第一个 `1` 的下标**。

为什么说用左闭右开区间 `[low, high)` 最完美？因为我们给 `low` 和 `high` 定下了两条**从头到尾绝对不会被打破的数学铁律（循环不变量）**：

* **铁律一：区间左边（即所有 `< low` 的下标），已经全部验明正身，100% 全是 `0`。**
* **铁律二：区间右边（即所有 `>= high` 的下标），已经全部验明正身，100% 全是 `1`。**
* **那么中间的 `[low, high)` 是什么？** 就是下标从 `low` 到 `high - 1` 的这群人，他们**还没被检查过，是真是假不知道（未知区）**！

好，现在带着这两条铁律，我们看每一步为什么**只能**那么写：

#### 1. 为什么初始必须是 `low = 0, high = n`？
因为一开始我们一个数都没看！
* 哪些下标 `< 0`？没有。符合铁律一（已知全是 `0` 的集合为空）。
* 哪些下标 `>= n`？没有（假想越界处有个保底的 `1`）。符合铁律二。
* 未知区是 `[0, n)`，也就是下标 `0` 到 `n-1`，刚好是整个数组！

#### 2. 进循环算出了 `mid`，为什么一边是 `mid + 1`，一边是 `mid`？（核心！）
我们的目标是**消灭未知区**，同时**绝对不能打破上面两条铁律**！
* **如果发现 `A[mid]` 是 `0`**：
  既然 `A[mid]` 是 `0`，因为数组有序，它左边的也全是 `0`。也就是说，现在**从 `0` 到 `mid` 全都是 `0` 了**！
  回看【铁律一】：要求 `< low` 的全是 `0`。现在 `<= mid` 的全是 `0`（即 `< mid + 1` 的全是 `0`），所以新的 `low` **必须更新为 `mid + 1`**！
* **如果发现 `A[mid]` 是 `1`**：
  既然 `A[mid]` 是 `1`，那它右边的也全是 `1`。也就是说，现在**从 `mid` 开始往右（即 `>= mid` 的下标）全都是 `1` 了**！
  回看【铁律二】：要求 **`>= high` 的全是 `1`**。你看！现在 **`>= mid` 的全是 `1`**！对照一下这两个式子，`high` 直接变成几？**直接变成 `mid` 啊！**
  这就是为什么“开区间对应 `high = mid`”！因为 `high` 本身就代表“从我开始全是 `1`”，现在 `mid` 证明了“从 `mid` 开始全是 `1`”，所以 `high = mid` 完美维持了铁律二！

#### 3. 为什么退出时 `low == high`，且它一定就是答案？（见证奇迹！）
因为整数除法 `(low + high) / 2` 是向下取整的，只要 `low < high`，算出来的 `mid` 永远满足 `low <= mid < high`。
这意味着：
* 要么 `low` 变成了 `mid + 1`（左边往右缩了至少 1 格）；
* 要么 `high` 变成了 `mid`（因为 `mid < high`，所以右边也往左缩了至少 1 格）。
**未知区 `[low, high)` 的长度每一轮都在严格变小，绝不可能死循环，最终必然缩成空集，即 `low == high`！**

当 **`low == high`** 的那一瞬间（假设停在了下标 `k`，即 `low = high = k`），我们把那两条从未打破的铁律拿出来宣读：
* 根据铁律一：所有 **`< k` 的下标，100% 全是 `0`**（意味着 `k - 1` 是最后一个 `0`）。
* 根据铁律二：所有 **`>= k` 的下标，100% 全是 `1`**（意味着 `k` 本身就是 `1`）。

**你想想！`< k` 的全是 `0`，`>= k` 的全是 `1`，那下标 `k`（也就是此时的 `low` 和 `high`）不是全场第一个 `1` 还能是谁？！**
这就是数学上的严密证明！不是巧合，不是感性认识，是必然结果！

### 二、你的顿悟：二分宇宙的四大形态，一表打尽！

正如你所悟到的：**二分查找的本质，就是寻找 `0` 和 `1` 的分界线！**
在升序数组中，平时题目无非就问你这 4 种问题（找第一个/最后一个 `>`、`>=`、`<`、`<=`），用你的“减 1 转化法”，**全部都能用同一个函数解决**！

你看这张终极转化表（以数组 `A = [1, 3, 3, 5]`，`x = 3` 为例）：

| 题目让你找什么 | 转化为“找第一个满足条件的位置” | 你的模板里 `if (...)` 怎么写 | 最后返回什么 | 用 `[1, 3, 3, 5]` 找 `3` 验证 |
| :--- | :--- | :--- | :--- | :--- |
| **1. 第一个 `>= x`** | 本身就是标准问题 | `if (A[mid] >= x)` | `return low;` | 返回下标 **`1`**（第一个 3） |
| **2. 第一个 `> x`** | 本身就是标准问题 | `if (A[mid] > x)` | `return low;` | 返回下标 **`3`**（元素 5） |
| **3. 最后一个 `< x`** | 就是【第一个 `>= x` 】的前一个！ | `if (A[mid] >= x)` | `return low - 1;` | `1 - 1 =` 下标 **`0`**（元素 1） |
| **4. 最后一个 `<= x`**| 就是【第一个 `> x` 】的前一个！ | `if (A[mid] > x)` | `return low - 1;` | `3 - 1 =` 下标 **`2`**（第二个 3）|

*(注：对于第 3、4 种情况，如果减 1 之后变成了 `-1`，说明数组里连第一个元素都比 `x` 大，不存在小于/小于等于 `x` 的数，返回 `-1` 刚好代表找不到，连边界都完美契合！)*

**你现在再看二分查找：**
以前你觉得它千变万化，一会儿 `<` 一会儿 `<=`，一会儿 `mid - 1` 一会儿 `mid + 1`。
现在你站在上帝视角往下看：全天下所有的二分题，都只是在一条“前半段是 0、后半段是 1”的直线上，用两堵铁律之墙（`< low` 全是 0，`>= high` 全是 1），把未知区夹爆，精准停在**第一个 `1`** 的位置上！

现在，心里那块悬着的石头落地了吗？


完全理解你的痛苦！很多人学二分法，脑子里装的是“数学公式”，一上考场就乱。
今天我们彻底抛弃枯燥的开闭区间概念，换一个**极其直观的物理模型——“筑墙夹逼法”**来解释你说的这句口诀：**`high = n`，配 `low < high`，改动一端 `mid` 一端 `mid + 1`**。

### 一、换个视角：为什么是这套组合拳？

就像你题目里写的，任何找边界的二分题，本质都是把数组变成了左右两个阵营：
**`[ 否, 否, 否, 是, 是, 是 ]`**
我们要找的，永远是**全场第一个“是”**的位置！

现在，请把 `low` 和 `high` 想象成两个向中间推进的侦察兵，他们有**铁律（物理人设）**：
* **`low` 的人设：探路先锋**。它走过的路（`low` 左边）绝对全是“否”。它当前踩的格子，是**还没检查过的嫌疑区起点**。
* **`high` 的人设：保底大本营**。它自己踩的格子以及它右边，绝对全是“是”。**注意：`high` 踩的那个格子本身，就是目前已知最靠左的一个“是”（保底答案）！**

理解了这两个人设，那 4 个疑问瞬间迎刃而解：

#### 1. 为什么一开始 `high = n` 而不是 `n - 1`？
因为一开始我们还没看数组，万一整个数组全是“否”（比如在 `[1, 3, 3, 5]` 里找 `>= 9` 的），一个“是”都没有怎么办？
我们假想在数组最右边（下标 `n` 的越界位置）立了一块免死金牌，假装下标 `n` 是个保底的“是”。所以 `high` 一开始必须站到 `n` 的位置当保底！如果站到 `n - 1`，万一 `A[n-1]` 也是“否”，`high` 的人设就崩了！

#### 2. 为什么一边是 `low = mid + 1`，另一边却是 `high = mid`？
现在我们看中间的 `mid`：
* **情况 A：`A[mid]` 是“否”**。
  既然 `mid` 是“否”，那它绝不可能是我们要找的“第一个是”。`low` 作为探路先锋，直接跨过尸体，去检查下一个：**`low = mid + 1`**。
* **情况 B：`A[mid]` 是“是”**。
  既然 `mid` 是“是”，它**有可能是第一个“是”**，但也可能它左边还有“是”。这时候不能把它扔掉！`high` 作为“保底大本营”，赶紧缩过来踩住这个点：**`high = mid`**（意思是我找到了一个更靠左的保底答案，先踩住它，再去它左边看看还有没有更早的）。
  *(注：如果你写成 `high = mid - 1`，万一 `mid` 就是全场唯一一个“是”，你把它减 1 扔了，就再也找不回来了！)*

#### 3. 为什么是 `while (low < high)`，不能加等号？
* 当 **`low == high`** 时，意味着什么？
  `low` 左边全是“否”，而 `high` 当前踩的就是保底的第一个“是”。现在两人站到了同一个格子上！说明水落石出，**他俩脚下踩的这个格子，就是分界线上的第一个“是”**！大结局了，赶紧退出循环交卷！
* **如果手贱加了等号 `while (low <= high)` 会怎样？**
  当 `low == high`（比如都等于 1）时，进循环算出 `mid = 1`，发现 `A[1]` 是“是”，执行 `high = mid = 1`。下一轮还是 `low = 1, high = 1` ……恭喜你，**死循环（TLE）**，408 直接扣光逻辑分！

### 二、三个经典例题：一套模板通杀！

你会发现，用这套模板，**`while` 框架、初始化、`mid` 更新全都是焊死的！** 唯一要改的，就是 `if (...)` 里面**“什么是【是】”**！

#### 例题 1：找第一个 `> x` 的位置（即 C++ 的 `upper_bound`）
* **408 考点背景**：折半插入排序中，为了保证排序的**稳定性**，当新元素等于中间元素时，必须插在它后面，也就是要找第一个 `> x` 的位置。
* **分析**：把数组看成 `[ <=x (否), <=x (否), >x (是), >x (是) ]`。我们要找第一个满足 **`A[mid] > x`** 的位置。
* **套模板代码**：

```cpp
int FirstGreater(int A[], int n, int x) {
    int low = 0, high = n;              // 焊死不变！
    while (low < high) {                // 焊死不变！
        int mid = low + (high - low) / 2;
        if (A[mid] > x) {               // 【唯一修改点】“是”的条件变成了 > x
            high = mid;                 // 焊死不变！踩住保底答案
        } else {
            low = mid + 1;              // 焊死不变！跨过废品
        }
    }
    return low;                         // 焊死不变！
}
```

#### 例题 2：山脉数组找峰顶（408 选择题高频、LeetCode 852）
* **题目**：数组先严格递增再严格递减，如 `[1, 3, 8, 12, 9, 4, 2]`，找出最大值 `12` 的下标（保证峰顶不在两端）。
* **分析**：怎么变成“否、否、是、是”？看相邻元素的趋势！
  * 在上坡段（1, 3, 8），永远满足 `A[i] < A[i+1]`（还没到顶，记为**否**）。
  * 从峰顶开始及下坡段（12, 9, 4, 2），永远满足 **`A[i] > A[i+1]`**（已经到顶或开始下坡，记为**是**）。
  * **目标**：找全场第一个开始下坡的点（第一个满足 `A[mid] > A[mid+1]` 的点），那就是峰顶！
* **套模板代码**：

```cpp
int PeakIndex(int A[], int n) {
    int low = 0, high = n - 1;          // 注意：因为下面要算 mid+1，为防越界 high 设为 n-1 即可（峰顶必不在 n）
    while (low < high) {                // 焊死不变！
        int mid = low + (high - low) / 2;
        if (A[mid] > A[mid + 1]) {      // 【唯一修改点】它比右边大了，说明它可能是峰顶，或者在峰顶右边（是）
            high = mid;                 // 焊死不变！mid 可能是峰顶，保底留住
        } else {
            low = mid + 1;              // 焊死不变！还在上坡，峰顶肯定在 mid+1 及右边
        }
    }
    return low;                         // 焊死不变！
}
```

#### 例题 3：旋转有序数组找最小值（考研改编题常客）
* **题目**：原本升序的数组 `[0, 1, 2, 4, 5, 6, 7]` 被旋转成了 `[4, 5, 6, 7, 0, 1, 2]`（无重复元素），请用 $O(\log n)$ 找出最小值 `0` 的下标。
* **分析**：数组被分成了两段升序：前半段 `[4, 5, 6, 7]` 都比最后一个元素 `2` 大；后半段 `[0, 1, 2]` 都 `<=` 最后一个元素 `2`。
  * 前半段：`A[i] > A[n-1]` -> **否**
  * 后半段：**`A[i] <= A[n-1]`** -> **是**
  * **目标**：后半段的**第一个元素**就是全场最小值！也就是找第一个满足 `A[mid] <= A[n-1]` 的位置！
* **套模板代码**：

```cpp
int FindMin(int A[], int n) {
    int low = 0, high = n - 1;          // 最小值肯定在 0 ~ n-1 之间，n-1 天然就是保底的“是”
    while (low < high) {                // 焊死不变！
        int mid = low + (high - low) / 2;
        if (A[mid] <= A[n - 1]) {       // 【唯一修改点】落在了右半段（是）
            high = mid;                 // 焊死不变！mid 可能是最小值，踩住保底
        } else {
            low = mid + 1;              // 焊死不变！在左半段，最小值肯定在右边
        }
    }
    return low;                         // 焊死不变！
}
```

### 三、总结：以后做二分题的思考步骤

以后碰到任何二分题，**不要再去想 `low` 和 `high` 怎么加减了**，按下面三步走：
1. **默写骨架**：先把 `while (low < high)`、`high = mid;`、`low = mid + 1;`、`return low;` 这几行死死地默写到卷子上。
2. **找分界条件**：在草稿纸上画个数组，问自己：我要找的目标，是不是某个满足条件 X 的**第一个**元素？把条件 X 填进 `if ( X )` 里（此时 `high = mid` 就顺理成章地保住了它）。
3. **定初始 `high`**：如果题目有可能“无解/越界”（比如找 `>= x`，可能全都不满足），`high` 就写 `n`；如果题目保证数组里一定有解（比如找峰顶、找旋转数组最小值），`high` 写 `n - 1` 即可。

这样记，是不是瞬间清爽了？你可以试着用这个模板想一下：**“如果在一个升序数组里，我想找最后一个 `<= x` 的元素下标，该怎么转化为这个模板？”**（想通了这个，二分你就彻底毕业了！）
