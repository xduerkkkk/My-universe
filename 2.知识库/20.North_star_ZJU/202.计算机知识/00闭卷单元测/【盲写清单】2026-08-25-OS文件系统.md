## 一、概念辨析（5 min）
写出以下概念的**定义 + 决定因素 + 一个易错点**：
- [ ] FCB（文件控制块）vs 目录项 vs inode：  
  - FCB：磁盘上保存文件属性和数据块映射  
  - 目录项：名字→FCB/inode的映射  
  - inode：类Unix系统的FCB实现（文件名不在inode里）
- [ ] 打开文件表：进程级（fd、访问模式）vs 系统级（偏移、打开计数、指向inode）  
  - open()做了什么？（路径解析、权限检查、建立打开实例、返回fd）  
  - close()做了什么？（释放打开实例、更新引用计数，≠fsync）
- [ ] 硬链接 vs 符号链接：  
  - 硬链接：同一inode的另一个目录名，链接计数+1，目标删除后其他硬链接仍有效  
  - 符号链接：独立文件，内容是目标路径，目标删除后悬空
- [ ] 逻辑块号 vs 物理块号：逻辑块号=文件内偏移/块大小，物理块号=磁盘上的实际块地址

## 二、机制流程（8 min）
**完整画出**以下流程：

### 2.1 多级索引寻址流程
以"10个直接块 + 1个一级间接 + 1个二级间接"为例，访问逻辑块号N：
- [ ] 判定N在哪个区间：  
  - N < 10 → 直接块  
  - 10 ≤ N < 10+K → 一级间接（K=每块容纳的索引项数）  
  - 10+K ≤ N < 10+K+K² → 二级间接
- [ ] 一级间接寻址：读一级索引块 → 从中读第(N-10)项 → 得到数据块号
- [ ] 二级间接寻址：  
  1. 读二级索引块根  
  2. 计算一级索引块号 = (N - 10 - K) / K  
  3. 从根读出一级索引块地址  
  4. 读一级索引块  
  5. 计算数据块号 = (N - 10 - K) % K  
  6. 从一级索引块读出数据块号

### 2.2 路径解析流程
解析 `/home/user/file.txt`：
- [ ] 从根目录"/"的inode开始  
- [ ] 读根目录数据块，查找"home"目录项 → 得到home的inode  
- [ ] 读home的inode，读其数据块，查找"user" → 得到user的inode  
- [ ] 读user的inode，读其数据块，查找"file.txt" → 得到file.txt的inode  
- [ ] 每一级都要检查权限（搜索权限x）

### 2.3 磁盘调度算法流程
磁盘请求队列：98, 183, 37, 122, 14, 124, 65, 67，当前磁头位置53，方向向外

- [ ] **FCFS**：按到达顺序 53→98→183→37→122→14→124→65→67
- [ ] **SSTF**（最短寻道时间优先）：每次选最近的 53→65→67→37→14→98→122→124→183（可能饥饿）
- [ ] **SCAN**（电梯算法）：向当前方向走到头，再反向 53→65→67→98→122→124→183→(反向)→37→14
- [ ] **C-SCAN**（循环扫描）：只向一个方向服务，到头后直接返回另一端 53→65→67→98→122→124→183→(直接跳到0)→14→37

## 三、算法套路（6 min）
**列表对比**（文件组织方式）：

| 分配方式 | 随机访问 | 扩展难度 | 典型问题 | 访问逻辑块N需要几次磁盘I/O |
|---------|---------|---------|---------|--------------------------|
| 连续分配 | 快（块号=起始块号+N） | 困难（外部碎片） | 扩展可能需要迁移 | 1次（直接算出物理块号） |
| 隐式链接 | 慢（需逐块遍历） | 容易 | 可靠性差、指针开销 | N次（从头链到第N块） |
| FAT | 较快（查FAT表） | 容易 | FAT表占内存 | 1次（FAT在内存）+ 1次数据块 |
| 索引分配 | 好 | 较好 | 索引块开销 | 多级索引：1-3次索引块 + 1次数据块 |

### 磁盘调度算法对比
| 算法 | 寻道距离 | 公平性 | 特点 |
|------|---------|--------|------|
| FCFS | 可能很大 | 公平 | 简单，可能抖动 |
| SSTF | 较小 | 不公平（边缘饥饿） | 贪心，可能饥饿 |
| SCAN | 中等 | 较公平 | 电梯算法，两端等待时间不均 |
| C-SCAN | 中等 | 更公平 | 循环扫描，等待时间更均匀 |

## 四、计算题检查清单（4 min）
写出计算步骤模板：

### 4.1 多级索引最大文件长度
- [ ] 每块容纳索引项数 K = 盘块大小 / 索引项大小
- [ ] 直接块数 d，一级间接块数 1，二级间接块数 1：  
  最大数据块数 = d + K + K²  
  最大文件大小 = (d + K + K²) × 盘块大小
- [ ] **注意**：索引块本身占用的空间不算在数据容量内

### 4.2 访问逻辑块N需要的磁盘I/O次数
- [ ] 直接块（N < d）：1次（直接读数据块）
- [ ] 一级间接（d ≤ N < d+K）：2次（1次索引块 + 1次数据块）
- [ ] 二级间接（d+K ≤ N < d+K+K²）：3次（1次根索引 + 1次一级索引 + 1次数据块）
- [ ] **假设FCB/inode已在内存**

### 4.3 磁盘调度总寻道距离
- [ ] 按算法模拟磁头移动轨迹
- [ ] 总距离 = Σ|当前位置 - 下一请求位置|

## 五、陷阱识别（2 min）
写出易错点：
- [ ] "找到目录项就得到数据？"（不！还要读inode、读索引块、读数据块）
- [ ] "硬链接各有各的权限？"（不！共享同一inode权限属性）
- [ ] "关闭文件=立即写回磁盘？"（不一定！经过缓存，close≠fsync）
- [ ] "多级索引最大文件大小包括索引块？"（不包括！只算数据块）
- [ ] "SSTF一定比FCFS快？"（总寻道距离小，但可能饥饿边缘请求）
- [ ] "打开文件后就不用文件名了？"（数据读写用fd，但rename/unlink/再次open仍用名字）
