## 一、概念辨析（5 min）
写出以下概念的**定义 + 决定因素 + 一个易错点**：
- [ ] 临界资源 vs 临界区：  
  - 临界资源：一次只允许一个执行流使用的共享资源  
  - 临界区：访问临界资源的代码段
- [ ] 同步 vs 互斥：  
  - 同步：协调执行先后次序（A必须在B之前）  
  - 互斥：限制同时进入（不能同时访问临界资源）
- [ ] 记录型信号量的语义：  
  - P(S)：S--; if (S<0) block当前进程  
  - V(S)：S++; if (S≤0) wakeup一个等待进程  
  - S>0：可用资源数；S<0：-S = 等待进程数
- [ ] 四项原则：空闲让进、忙则等待、有限等待、让权等待（各自含义、违反后果）

## 二、机制流程（8 min）
**完整写出**以下经典问题的PV操作代码：

### 2.1 生产者-消费者（有界缓冲区）
缓冲区大小N，初始为空：
```c
// 信号量定义
semaphore mutex = 1;    // 缓冲区互斥锁
semaphore empty = N;    // 空位数量
semaphore full = 0;     // 产品数量

// 生产者
while (true) {
    生产一个产品;
    P(empty);          // 申请空位
    P(mutex);          // 进入临界区
    放入缓冲区;
    V(mutex);          // 离开临界区
    V(full);           // 产品数+1
}

// 消费者
while (true) {
    P(full);           // 申请产品
    P(mutex);          // 进入临界区
    从缓冲区取出;
    V(mutex);          // 离开临界区
    V(empty);          // 空位数+1
    消费产品;
}
```

**关键点**：
- [ ] P(empty)/P(full)必须在P(mutex)之前（否则死锁）
- [ ] V(mutex)必须在V(full)/V(empty)之前（先退出临界区再通知）
- [ ] "缓冲区不可用"=mutex被占用；"缓冲区空"=full=0（不同维度）

### 2.2 读者-写者问题（读优先）
多个读者可同时读，写者独占访问：
```c
// 信号量定义
semaphore rw = 1;       // 读写互斥锁
semaphore mutex = 1;    // 保护readcount的互斥锁
int readcount = 0;      // 当前读者数

// 读者
P(mutex);
readcount++;
if (readcount == 1)     // 第一个读者
    P(rw);              // 阻止写者
V(mutex);

读文件;

P(mutex);
readcount--;
if (readcount == 0)     // 最后一个读者
    V(rw);              // 允许写者
V(mutex);

// 写者
P(rw);
写文件;
V(rw);
```

**关键点**：
- [ ] 第一个读者P(rw)阻止写者，最后一个读者V(rw)允许写者
- [ ] readcount的修改必须用mutex保护
- [ ] 这是"读优先"版本，写者可能饥饿

### 2.3 读者-写者（写优先）
```c
// 信号量定义
semaphore rw = 1;       // 读写互斥
semaphore r = 1;        // 读者队列互斥
semaphore w = 1;        // 写者队列互斥
int readcount = 0;
int writecount = 0;

// 读者
P(r);                   // 进入读者队列
P(mutex);
readcount++;
if (readcount == 1)
    P(rw);
V(mutex);
V(r);                   // 释放读者队列

读文件;

P(mutex);
readcount--;
if (readcount == 0)
    V(rw);
V(mutex);

// 写者
P(wmutex);
writecount++;
if (writecount == 1)
    P(r);               // 阻止新读者
V(wmutex);

P(rw);
写文件;
V(rw);

P(wmutex);
writecount--;
if (writecount == 0)
    V(r);               // 允许新读者
V(wmutex);
```

**关键点**：
- [ ] 写优先：有写者等待时，新读者不能进入
- [ ] 用writecount控制是否阻止新读者

## 三、算法套路（6 min）
**列表对比**（同步互斥实现方法）：

| 方法 | 互斥安全 | 公平性 | 让权等待 | 核心缺陷 |
|------|---------|--------|---------|---------|
| 单标志法 | 是 | 有轮换限制 | 否 | 违背空闲让进（对方不申请也挡住自己） |
| 双标志先检查 | 否 | — | 否 | 可能同时进入 |
| 双标志后检查 | 是 | 否 | 否 | 可能互等（违背空闲让进） |
| Peterson | 是 | 两进程下是 | 否 | 忙等 |
| TSL/Swap | 是 | 通常不保证 | 否 | 忙等、可能饥饿 |
| 整型信号量 | 可实现 | 取决于协议 | 否 | 忙等 |
| 记录型信号量 | 可实现 | 取决于等待队列 | 是 | 需内核block/wakeup支持 |

### PV操作设计模板
- [ ] **同步**：若A必须先于B，则：  
  - 信号量S初值=0  
  - A后执行V(S)  
  - B前执行P(S)
- [ ] **互斥**：保护临界资源，则：  
  - 信号量mutex初值=1  
  - 临界区前P(mutex)  
  - 临界区后V(mutex)
- [ ] **资源计数**：N个可用资源，则：  
  - 信号量resource初值=N  
  - 申请资源前P(resource)  
  - 释放资源后V(resource)

## 五、陷阱识别（2 min）
写出易错点：
- [ ] "P(mutex)和P(empty)顺序能换吗？"（不能！会死锁：生产者拿着mutex等empty，消费者拿不到mutex）
- [ ] "V(full)和V(mutex)顺序能换吗？"（可以，但最好先V(mutex)再V(full)，早点释放锁）
- [ ] "读者写者的readcount需要mutex保护吗？"（需要！readcount是共享变量）
- [ ] "V(S)后S≤0说明什么？"（说明有或刚好有等待者，不是"出现空闲资源"）
- [ ] "管程的signal和信号量的V一样吗？"（不一样！signal不累计计数，没等待者就丢失）
