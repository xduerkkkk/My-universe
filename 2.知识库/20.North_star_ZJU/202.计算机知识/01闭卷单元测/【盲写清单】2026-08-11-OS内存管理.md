  - 可用物理内存：实际装的内存条容量，再扣掉 OS 内核、页表等占用的部分。
 
  "操作系统位数"是什么
	"32 位/64 位操作系统"这个说法指的是 CPU 一次能处理的数据字长和 CPU 支持的地址位数，OS 是配合这个硬件设计的。它不是一个独立的、能直接决定地址空间的量。408 里你要区分三个东西：
	
	- 机器字长：CPU 一次运算处理的位数（ALU/寄存器宽度）。
	- 逻辑地址位数：决定逻辑地址空间大小。
	- 物理地址位数：决定物理地址空间大小。
	
	这三者在很多机器上恰好相等（比如都 32 位），所以口语里笼统说"32 位系统"。但考题里它们可以不相等，必须分开看。所以我上一轮说"操作系统位数"太模糊，就是因为它把这几个量糊在一起了
	
	物理地址空间的定义就是"CPU 能产生并送出的所有物理地址的集合"。CPU 送地址是通过地址总线送的，地址总线有多少根线，就能表示多少个不同的地址。
	
	- n 位物理地址（n 根地址线）→ 能编码 2^n 个不同地址 → 物理地址空间 = 2^n 个存储单元。
	
	这是一个"能不能表示出这个地址"的编码能力问题，跟你实际插了多少内存条无关：
	
	- 如果物理地址 32 位，物理地址空间就是 4GB，哪怕你只插了 2GB 内存。这时高地址部分寻址不到实际存储，属于"可用物理内存 < 物理地址空间"。
	- 反过来插再多内存，超过 2^n 的部分 CPU 也送不出地址、访问不到。
	
	所以决定因素是位宽（地址线数量），内存容量只决定这 2^n 个地址里有多少个真正对应到内存条。外存更是完全无关——外存不接地址总线，CPU 不能直接寻址外存。

- [ ] 驻留集 vs 工作集（定义、理想关系 vs 现实关系、何时会不匹配）
  <font color="#ff0000">驻留集是理想常驻的页，工作集是现实常驻的页？</font>
  你把两个概念对调了。
	
	- 工作集（working set）：在某个时间窗口 Δ 内，进程**实际访问过**的页面集合。它反映程序的局部性，是"理论上应该驻留内存的页"。决定因素是窗口大小 Δ 和程序的访问行为。
	- 驻留集（resident set）：进程当前**实际在物理内存中**的页面集合。这是"现实中真正驻留的页"。
	
	所以正好和你说的相反：工作集是理论/应该，驻留集是现实/实际。
	
	- 理想关系：驻留集 ⊇ 工作集（把整个工作集装进内存），缺页率低。
	- 现实不匹配：驻留集大小受分配策略限制。当驻留集 < 工作集时，进程频繁缺页，发生抖动（thrashing/颠簸）。

## 二、机制流程（8 min）
**完整画出**以下流程（步骤化，标出每步查什么、判什么）：
- [ ] 存储保护的四步执行链：OS建立→进程切换时装入→硬件检查（MMU/TLB）→异常处理
  MMU 和 TLB 怎么做检查了？如果有异常怎么处理？
	  TLB 是页表项的高速缓存，只加速"虚页号→物理页框号"的查找；真正做访问权限和越界检查的逻辑在 MMU 里（TLB 表项本身也带保护位，所以命中时也能直接查权限）。
	
	一次访存，MMU 做的检查有两类：
	
	- 地址越界检查：界限寄存器方式下，比较逻辑地址与界限寄存器；页式/段式下，检查页号/段号是否超过页表长度寄存器（如页表长度 M，页号 ≥ M 就越界）。
	- 访问权限检查：页表项/段表项里有权限位（可读 R、可写 W、可执行 X）和特权级（用户态/内核态）。当前操作类型与权限位不符（比如对只读页执行写，或用户态访问内核页）就违规。
	
	流程：CPU 发出虚拟地址 → 拆出虚页号查 TLB → 命中就直接拿页框号 + 权限位做检查；未命中则查页表，同样拿到页框号和权限位。检查项：有效位（present）、权限位、越界。任何一项不通过，MMU 拉起异常信号。
	
	异常处理分两种，别混：
	
	- 有效位无效 → 缺页异常（page fault），可恢复。OS 调页后重新执行指令。
	- 权限/越界违规 → 保护异常（如段错误 segmentation fault），通常不可恢复，OS 一般直接终止进程。
	
	关键区别：缺页是"页不在内存，去取"；保护异常是"你没资格访问
- [ ] 动态分区回收后的合并判定：释放的分区变为空闲区→检查前后邻居→三种合并情况 ？为啥三种
	  回收一个分区时，只看它紧邻的前一个物理相邻分区和后一个物理相邻分区是否空闲，组合起来本来有 4 种（前空/前不空 × 后空/后不空）。但通常教材把"前后都空闲"算一种，所以是这样列的：
	
	1. 前邻空闲、后邻占用 → 与前合并，起始地址取前分区的，大小相加。
	2. 前邻占用、后邻空闲 → 与后合并，起始地址取回收区的，大小相加。
	3. 前后都空闲 → 三块合并成一块，起始地址取前分区的，大小三者相加，并从空闲表里删掉后邻那一项。
	
	还有第 4 种：前后都占用 → 不合并，单独插入空闲表作为一个新空闲区。
	
	所以严格讲是 4 种情况，"三种合并"指的是发生合并动作的那三种，第 4 种不产生合并。教材说"三种"时把不合并那种略过了。
- [ ] 多级页表地址转换路径：虚拟地址拆分（页内偏移+虚页号）→逐级查页表→拼接物理地址
	  我忘了顺序了，逐级是从前到后还是从后到前？
	| 一级页号 (页目录号) | 二级页号 | 页内偏移 |
	     高位中间低位
	
	顺序：
	
	1. 页目录基址寄存器（如 x86 的 CR3）+ 一级页号 → 找到页目录项，里面存二级页表的物理基址。
	2. 二级页表基址 + 二级页号 → 找到页表项（PTE），里面存最终页框号。
	3. 页框号 + 页内偏移 → 拼出物理地址。
	
	所以是"从前（高位/顶级）到后（低位/底层）"逐级查。记忆点：高位先用，因为高位定位的是更粗粒度的那一级表。N 级页表就要 N 次访存查表 + 1 次真正访存，共 N+1 次访存（无 TLB 时）
- [ ] 缺页异常处理全流程：访问→有效位检查→触发异常→OS调页/置换→更新页表→重新执行指令
	什么动作会让有效位里标记成无效呢，这里的缺页，TLB 和普通页表，有区别吗，重新执行指令无论什么情况都是先 TLB 后页表吗
	**什么动作把有效位标成无效**
	
	有效位（present/valid）表示该页当前是否在物理内存中。置为无效的情形：
	
	- 进程刚创建/刚加载，页还没调入内存（按需调页，一开始就是无效）。
	- 页被换出（page out）到磁盘交换区——置换算法选中它当牺牲页，OS 把它写回磁盘后清有效位。
	- 内存映射文件、共享页等尚未真正建立映射时。
	
	注意：有效位无效 ≠ 权限非法。前者触发缺页（可恢复），后者触发保护异常。
	
	**这里的"缺页"，TLB 和普通页表有没有区别**
	
	要区分两种"没找到"：
	
	- TLB 缺失（TLB miss）：TLB 里没有这个虚页号的缓存项。这不是缺页异常，只是要去内存查页表。查到页表项后，若有效位有效，把它填进 TLB，继续访问，代价只是多几次访存。
	- 缺页（page fault）：查页表后发现有效位无效，页根本不在内存。这才是真正的异常，要陷入 OS 调页。
	
	关系：TLB 缺失是"缓存没命中"，缺页是"页不在内存"。TLB 缺失后查页表，可能有效（不缺页），也可能无效（才缺页）。所以 TLB 缺失不一定缺页，但缺页时 TLB 必然也没有有效项（因为 TLB 是页表的子集，页不在内存就不会有有效 TLB 项）。
	
	**重新执行指令时，是不是永远先 TLB 后页表**
	
	访存的正常查找顺序确实是先 TLB 后页表（这是硬件固定流程）。但有个细节：缺页处理完、OS 更新页表并重新执行指令时，还是走同一套硬件流程——先查 TLB。
	
	区别在于 OS 调页后有没有顺手更新 TLB：
	
	- 若 OS 在处理缺页时把新的页表项也写入了 TLB，重新执行时 TLB 命中，直接走。
	- 若没写 TLB，重新执行时 TLB 仍缺失，再查页表（此时有效位已改为有效），命中后填 TLB，再访问。
