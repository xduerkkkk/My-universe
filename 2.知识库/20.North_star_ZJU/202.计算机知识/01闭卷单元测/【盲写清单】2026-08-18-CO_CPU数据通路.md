## 一、概念辨析（5 min）
写出**定义 + 决定因素 + 一个易错点**：
- [ ] 状态元件/时序元件 vs 组合逻辑元件（各举 4 个；CPU 基本节奏是哪三步）
  - **CPU 基本节奏的三步：**
    
    1. 在时钟边沿，从**状态元件**读出数据。
        
    2. 信号在**组合逻辑元件**中自由传播并加工运算（耗费一个时钟周期的绝大部分时间）。
        
    3. 在下一个时钟边沿，将运算结果写回**状态元件**保存。
        
  - **易错点：** 误以为 ALU 处理完数据需要“等待时钟节拍”才输出结果。ALU 是组合逻辑，只要输入稳定，输出瞬间就产生了。时钟边沿决定的是**何时将 ALU 的计算结果存入目标寄存器**，而不是决定 ALU 何时出结果。
- [ ] 微操作/RTL vs 控制信号（`PC → MAR` 和 `PCout=1, MARin=1` 是同一层次吗）
	  - **解答疑惑：** PC → MAR 和 PCout=1, MARin=1 **绝对不是**同一层次。前者是微操作（逻辑意图）；后者是控制信号（物理实现）。
	    
	- **易错点：** 在 408 综合大题中，题目让你写“请给出执行该指令所需的**控制信号**”，如果你写了 R1 + R2 → R3 或 PC → MAR，一分不给。必须精准写出物理信号名，如 ALUop=ADD, R1out=1, R2out=1, R3in=1。
	    
- [x] 五个层次链：机器指令 → 微程序 → 微指令 → 微操作 → 控制信号（各层定义）
- [x] 机器级 PC/IR vs 微程序控制器内部 μPC/μIR（别混）
- [ ] PC 位数由什么决定（保存完整字节地址 vs 保存定长指令字地址，两种口径）
	- **决定因素（基于 408 常考的两种口径）：**
	    
	    1. **按字节寻址口径（通常针对变长指令集/CISC）：** 如果题目规定主存按字节编址，且指令长度可变，PC 必须能精确定位到任何一个字节。此时，**PC 的位数必须严格等于 MAR（主存地址寄存器）的位数**。
	        
	    2. **按字寻址口径（通常针对定长指令集/RISC，如 MIPS）：** 如果题干明确规定“指令字长固定为 32 位（4 字节）”，且“PC 存放指令字地址”，这意味着指令总是 4 字节对齐的。PC 的值不需要精确到字节，只需指出是“第几条指令”。此时，PC 的位数由**最大指令条数**决定，它可以比 MAR 少两位（因为最低 2 位永远是 00，硬件设计时可以直接省略，拼地址时再补上）。
	        
	- **易错点：** 做题时无脑套用“PC 位数 = MAR 位数”。如果 2022 年或 2015 年 408 真题中明确说明 CPU 是 MIPS 架构或指令按字寻址（如 PC <- PC + 1 代表跳跃一条指令而非一个字节），此时 PC 内部保存的其实是主存地址的高位部分。必须先看清题目的编址基本单位，再定 PC 位宽

## 三、算法套路（6 min）
**列表对比**：
- [ ] 单周期 / 多周期 / 流水线 CPU：CPI、时钟周期长度、部件是否复用

| 处理器类型   | CPI (每条指令时钟数)    | 时钟周期长度                    | 部件是否复用 (空间逻辑)                             |
| ------- | ---------------- | ------------------------- | ----------------------------------------- |
| **单周期** | **恒为 1**         | **极长** (等于最慢指令的执行时间)      | **否** (必须有独立的指令存和数据存，加法器不能当 ALU 用)        |
| **多周期** | **> 1** (不同指令不同) | **短** (等于最慢的一个数据通路段/节拍)   | **是** (分时复用，比如一个 ALU 既算地址又算数据)            |
| **流水线** | **理想情况为 1**      | **较短** (等于最慢的流水段 + 锁存器延迟) | **否** (同一时刻多个指令在跑，必须部件独立，如指令/数据 Cache 分离) |
- [x] 硬布线 vs 微程序控制器：产生控制信号方式、速度、修改难度
  
- [ ] 三种编码方式：直接编码 / 字段直接编码 / 字段间接编码（字长、并行性、速度）
  
- [ ] 水平型 vs 垂直型微指令：编码程度、字长、并行性、速度
  
	- [ ] 异常与中断分类 + 返回位置（缺页为何重做当前指令？校验错为何常归入终止？）
	#### 1. 分类：
	
	- **异常 (内中断)：** CPU 执行**当前指令本身**引发的。分为故障 (Fault)、自陷 (Trap)、终止 (Abort)。
	    
	- **中断 (外中断)：** 与当前指令无关，由**CPU 外部设备**（键盘、网卡、定时器）引发的。分为可屏蔽、不可屏蔽。
	    
	
	#### 2. 返回位置与推理 (必考！)：
	
	- **故障 (Fault - 例如：缺页、缺段)**
	    
	    - **返回位置：重做当前指令**。
	        
	    - **空间推理：** 这条指令要求拿内存地址 0x0001 的数据，但去查页表发现不在内存里。**这条指令其实根本没有执行完/或者没拿到有效数据**。所以操作系统去把页调入内存后，CPU 必须重新执行一遍这条指令，才能真正拿到数据。
	        
	- **自陷/陷阱 (Trap - 例如：系统调用 (syscall)、断点)**
	    
	    - **返回位置：下一条指令**。
	        
	    - **空间推理：** 这是程序员**故意**埋的雷。比如执行 syscall，指令本身的目的就是“呼叫操作系统”，当呼叫发生时，这条指令的使命**已经圆满完成**。所以处理完返回时，理应接着执行下一条。
	        
	- **终止 (Abort - 例如：控制器出错、校验错)**
	    
	    - **返回位置：不返回（终止该进程）**。
	        
	    - **空间推理：** 校验错（比如奇偶校验失败）意味着物理内存里存储的比特位翻转了。这是**硬件级别的毁灭性灾难**。如果你接着执行，用的就是完全错误的数据，会导致系统全面崩溃。所以根本无法恢复，只能直接把进程杀掉。
	        
	- **外中断 (Interrupt - 例如：I/O 完成)**
	    
	    - **返回位置：下一条指令**。
	        
	    - **空间推理：** 外部事件发生时，CPU 必须**把当前手头这条指令老老实实执行完**，保存好干净的现场，再去处理外部请求。处理完回来，当前指令已经做完了，自然从下一条开始继续干活。
