## 一、I/O 设备与控制

### 1.1 共享设备的特点（原题1）
共享设备必须**可寻址**和**可随机访问**。

块设备必须支持随机寻址：磁盘、U盘、固态硬盘。共享设备允许进程在**逻辑上并发访问**，不一定是真的同一时刻同时访问。

> 🔗 你的卡片：[[卡片/辨析--随机与直接访问]]

### 1.2 虚拟设备（SPOOLing）的本质（原题2）
虚拟设备将一台**独占设备转换为若干逻辑设备**。

**怎么做到的？** 以打印机为例：3 个进程以为自己都独占了一台高速打印机（3 台逻辑设备），实际上底层只有一台慢吞吞的物理打印机在干活。SPOOLing 引入了虚拟设备是为了克服独占设备速度慢、占用率低的特点。

### 1.3 I/O 接口（设备控制器）与命令（原题4）
> 你的困惑：控制命令由设备控制器提供？怎么提供？N 个设备就有 N 个 I/O 接口吗？

**命令如何提供**：CPU 通过总线向设备控制器（I/O 接口）的**控制寄存器**写入命令字（如写入特定位模式表示"启动读操作"或"复位设备"）。命令字的编码格式由设备控制器的硬件规格定义——所以是**控制器提供命令集**。

**N 个设备对应几个 I/O 接口？**
- 通常是 N 个设备对应 N 个设备控制器（各种独立挂在总线上，各有自己的寄存器组和端口地址）
- 但也有例外：一个磁盘控制器可以接多块磁盘，一个 USB 主控制器可以接多个 USB 设备（通过通道号/端口号区分下挂设备）

### 1.4 通道是硬件（原题7）
**通道是硬件技术！** ——不是软件概念。

## 二、DMA 与中断处理

### 2.1 DMA 前后进程的状态变化 ⚡（原题11 · !）
> 你的困惑：怎么区分什么时候内核态什么时候用户态？"负责预处理的进程是请求 I/O 的进程，负责后处理的进程是中断服务例程"什么意思？

**完整时间线**：

| 阶段 | CPU 态 | 进程状态 | 谁在干活 |
|------|--------|----------|---------|
| **预处理**（请求 I/O） | 内核态（系统调用） | 运行态 | 请求 I/O 的进程自己 |
| **DMA 传输中** | 用户态（CPU 干别的去了） | 阻塞态 | DMA 控制器独自搬数据 |
| **DMA 完成中断** | 内核态（硬件自动切） | 仍阻塞态 | 中断服务例程（内核代码） |
| **唤醒进程** | 内核态 | 就绪态 | 中断处理程序标记进程 |

关键区分：
- **预处理由请求 I/O 的进程自己做**（发起系统调用设置 DMA 控制器）
- **后处理由中断服务例程做**（这是内核的代码，不是进程的代码！），此时原进程还在阻塞态
- **进程从阻塞态醒来是在中断处理程序把它标记为就绪态之后**

### 2.2 设备分配考虑的因素 ⚡（原题12 · !）
> 你的困惑：设备分配应考虑及时性吗？

设备分配应考虑：
- **设备固有属性**：独占/共享/虚拟，各有不同分配策略
- **设备分配算法**：FCFS、优先级高者优先
- **设备分配安全性**：安全分配（阻塞式）vs 不安全分配（非阻塞式），涉及死锁
- **设备独立性**：用户程序尽量独立于具体物理设备

**及时性不是设备分配的核心考虑因素**——那属于实时系统调度或 I/O 调度（如磁盘调度算法）的范畴。

### 2.3 绝对号 vs 相对号（原题13）
| | 绝对设备名 | 相对设备名 |
|---|---|---|
| 谁定义的 | 系统统一编号 | 用户自己取名 |
| 例子 | MAC 地址、端口号 0x3F0 | 代码里的 `Printer_1` |
| 本质 | 设备的真实物理身份证 | 逻辑/符号名 |

### 2.4 通道 vs 设备控制器的控制关系（原题14）
**通道控制设备控制器，设备控制器控制设备工作。** 对于一组命令，CPU 要么给通道发命令，要么给设备控制器发命令。

### 2.5 设备独立性软件 vs 驱动程序的分工 ⚠️（原题16 · !!）
> 你的"翻车点"——把翻译过程的"最后一步"当成了全部。

| | 设备独立性软件 | 设备驱动程序 |
|---|---|---|
| **代码范围** | **所有设备共用一套** | **每种设备各一套** |
| **KPI** | 翻译系统调用参数（fd）为设备操作命令 | 把标准命令翻译为硬件寄存器操作 |
| **工作示例** | `fd=3` → "向 U 盘第 10 扇区写入数据" | "写第 10 扇区" → 柱面/磁头/扇区 + 寄存器指令 |
| **查表角色** | 查系统打开文件表，选调哪个驱动程序 | 查设备硬件地址表，发控制信号 |

**核心区分**：
- 凡是涉及 **"fd → 逻辑设备"** 的翻译 → 设备独立性软件
- 凡是涉及 **"逻辑命令 → 硬件寄存器"** 的翻译 → 设备驱动程序
- **"根据设备类型选择调用相应的驱动程序"**——这正是独立性软件的活

### 2.6 中断类型号 ≠ 内中断/外中断分类（原题19）
> 你误以为"中断类型"是分类内中断/外中断。

**中断类型在这里指的是"几号中断"（中断类型号/向量号）**——用于在中断向量表中找到对应入口地址。

获取设备输入是**软件干的**：中断服务程序里写 `IN AX, 0x60`（从端口读数据进寄存器）。

### 2.7 "进程阻塞" ≠ "CPU 阻塞"（原题20）
> 你的困惑核心：程序直接控制方式下进程不阻塞→CPU 空转；DMA/中断下进程阻塞→CPU 不阻塞？

| | 程序直接控制（轮询） | 中断驱动 | DMA |
|---|---|---|---|
| **进程状态** | 运行态（一直占着 CPU 轮询） | 阻塞态（让出 CPU） | 阻塞态（让出 CPU） |
| **CPU 状态** | **空转（做无用功循环检查）** | 有效（去干别的进程） | 有效（去干别的进程） |
| **效率** | 极低 | 中 | 高 |

**"进程阻塞"是软件概念**（让贤行为，提升整体效率），**"CPU 空转"是物理现象**（CPU 满头大汗原地踏步做无用功）。

### 2.8 中断驱动 I/O 的过程 ⚠️（原题21 · !!）
以输入为例：中断处理程序负责将**设备控制器缓冲区中的数据读到内存缓冲区**。

不同设备有不同驱动和不同 ISR。I/O 完成后必须检查状态寄存器确认传输是否出错。

**"一定会返回到被中断的进程"是错误的**：
- 中断由外部硬件引起，与当前运行的进程通常没有因果关系
- 如果新就绪的进程优先级更高，CPU 直接切换到它
- 况且还有多重中断的可能

## 三、I/O 软件层次

### 3.1 设备独立性的主语是"用户程序"（原题1）
**"设备独立性"的主语不是操作系统，而是"用户程序"！** 全称是**"用户程序对物理设备的独立性"**——用户程序使用的设备和实际的设备无关。

> 🧠 **思维误区——"主语搞反"模式**：和内存管理里你把"目录文件"和"普通文件数据"搞混类似，这里你把"谁独立于谁"搞反了。问自己：谁不需要知道具体设备细节？——用户程序。

### 3.2 SPOOLing 的输入/输出井 vs 内存缓冲（原题4）
> 你的困惑：输入井输出井在磁盘，缓冲区在内存，作用一模一样为什么地方不一样？

| | SPOOLing 井 | 内存缓冲 |
|---|---|---|
| **在哪** | **磁盘**（大而慢） | **内存**（小而快） |
| **为什么** | 容量大且便宜，装下整个任务 | 跟上 CPU 速度，平滑数据流 |
| **典型场景** | 打印机——10 个进程的作业都存磁盘 | 磁盘读写——攒够 4KB 再一起写 |
| **本质** | 解决**整批作业级别**的不匹配 + 设备独占问题 | 解决**临时的、短暂的速度**不匹配 |

### 3.3 多缓冲区 vs 缓冲池（原题5）
- **多缓冲区**：**专款专用**。比如双缓冲、循环缓冲，专门服务于特定设备
- **缓冲池**：**公共资源**。任何设备任何进程都可以来申请和释放，极大提高内存利用率

### 3.4 设备分配的本质：修改 DCT 表格（原题8）
> 你的困惑：设备分配为什么会有算法？到底分配了什么？

设备分配的本质是：OS 修改内存里的 **DCT（设备控制表）**——把设备的 `status` 从 `FREE` 改 `BUSY`，把 `owner` 写上进程 ID。这就把设备的**"独占使用权（钥匙）"**交给了你。

只要有"排队"，就必然需要"调度算法"——就两种：**FCFS（公平）** 还是 **优先级调度（VIP 优先）**。

> 🔗 你的卡片：[[卡片/辨析--"查表翻译"和"设备分配"]]

### 3.5 什么时候缓冲区没必要？（原题11）
> 核心逻辑：缓冲区不是"为快的一方服务"或"为慢的一方服务"，而是为了**摊薄昂贵 I/O 的固定成本**和**吸收短期速度抖动**。当 I/O 单次成本趋近于零时，这两个理由都不成立。

（语境通常指 I/O 拿 CPU 数据的场景：I/O 本身很快 → 没必要攒批 → 缓冲区多余。）

### 3.6 缓冲区是临界资源（原题12）
**临界资源** = 一次只允许一个进程访问的共享资源。缓冲区当然是——多个进程不能同时写同一块缓冲区。

### 3.7 哪些活动需要缓冲区？（原题13）
**鼠标移动**：硬件产生高频中断事件，应用程序不一定能立刻消化 → 缓冲区**吸收突发事件 + 解耦中断和应用处理**，防止丢事件。

**磁盘驱动器**：磁盘单次 I/O 开销极大（寻道+等待旋转） → 缓冲区**摊薄固定成本**：攒够一个块（4KB）再写一次。

### 3.8 SDT → DCT → COCT → CHCT 分配链（原题16）
> 你的困惑：怎么记住这个四级审批逻辑？

```
进程喊"要打印机"
  ↓ ① 查 SDT（系统设备总目录）→ 有这号设备吗？找档案放哪
  ↓ ② 查 DCT（设备个人档案）→ 有空吗？FREE→BUSY，写 owner
  ↓ ③ 查 COCT（控制器档案）→ 管这设备的控制器忙不忙？
  ↓ ④ 查 CHCT（通道档案）→ 传输马路空不空？
  ↓ ✅ 全部批过，通路打通
```

### 3.9 磁盘是共享设备，打印机是独占设备 ⚠️（原题17 · !!）
> 你的困惑：为什么磁盘行而打印机不行？

| | 磁盘 | 打印机 |
|---|---|---|
| 访问类型 | **直接存取（DAM）** | 顺序输出 |
| 为何能共享/不能 | 磁头"唰"地飞过去切换服务，A 读扇区 1，B 读扇区 100，交替横跳 | 打印在实体纸张上！A 打一半 B 插队 → 上半段情书下半段辞职信 |
| 本质 | 物理介质允许交替访问 | 物理介质要求连续完整输出 |

**共享设备的定义**：一个时间间隔内，可被多个进程同时访问的设备。

### 3.10 提高单机资源利用率的根本（原题18）
**多道程序设计技术是根**。核心思想：内存里同时放多道程序并发执行。一个程序等 I/O → CPU 切去执行另一个 → CPU 不闲着。

交换技术、虚拟存储：是为多道程序"创造条件"的。SPOOLing：是在多道环境下进一步解决设备独占问题的。

> 🧠 **思维误区——"并列概念搞成层级"**：你把多道程序、虚拟存储、SPOOLing 当成了平级的"都重要"，但它们其实有因果关系——多道程序是根，其他是枝。

### 3.11 "脱机"的含义（原题21）
**"脱机"的"机"特指"主机（主 CPU）"**——SPOOLing 模拟了脱机操作：程序快速把数据丢给磁盘（脱离主 CPU 的参与），后台慢慢输出。

### 3.12 SPOOLing 不需要外围计算机 ⚠️（原题22 · !!）
**SPOOLing 不需要外围计算机**！磁盘就是缓冲区。得益于**多道程序设计**，可以另开进程进行输入输出。

### 3.13 SPOOLing 的三大程序 ⚡（原题23 · !）
SPOOLing 系统由以下组成：
| 程序 | 职责 |
|------|------|
| **预输入程序（缓输入）** | 在程序运行前/中，把数据从输入设备 → 缓冲区 → 输入井 |
| **井管理程序** | 管账的：程序要输入数据 → 从输入井找；程序要输出 → 存到输出井 |
| **缓输出程序** | 把输出井数据 → 缓冲区 → 输出设备 |

流程：[程序产出] →(过内存)→ [输出井(磁盘)] →(过内存输出缓冲区)→ [打印机]

### 3.14 SPOOLing 加快作业执行速度的原因 ⚠️（原题26 · !!）
> 你的困惑：一个打印作业的完成时间应该取决于作业内容和打印机，速度不应变。但宏观来看，SPOOLing 又让整体加快了。

**"作业执行速度"是指程序在 CPU 和内存里驻留的时间！** 程序把数据丢进磁盘的那一刻，"打印"这行代码就已经**执行完毕**了。它被 SPOOLing 后台慢慢打印的时间不算"作业执行"。所以**执行速度被极大地缩短了**。

### 3.15 SPOOLing = 空间换时间（原题27）
- **SPOOLing**：用磁盘空间换 CPU 等待时间 → **空间换时间**
- **虚拟存储、覆盖与交换**：用 CPU 时间换内存空间 → **时间换空间**

### 3.16 SPOOLing 中"虚拟设备"的含义（原题28）
> 你的困惑：磁盘不是物理设备吗？为什么代替打印机的不是物理设备而是虚拟设备？

对进程来说，它感觉自己独占了一台打印机，但实际上根本没有物理打印机参与——它只是**写到了磁盘**。这个"被进程当成打印机来用、实际由磁盘存储区充当"的东西，就是**虚拟设备**。

### 3.17 打印文件的完整流程（原题30 · !）
1. **文件系统**负责：按文件名找到并读取文件内容（从磁盘读）
2. **设备管理程序**负责：把数据送到打印机（SPOOLing 属于设备管理范畴）
3. "打印机启动程序"不是 OS 标准功能模块——它只是初始化打印机

### 3.18 I/O 软件四层的职责划分（原题31）
> 你的困惑：谁最懂底层寄存器？谁做安全检查？printf 里的格式转换谁干的？

| 任务 | 负责层 |
|------|--------|
| 写硬件寄存器 | **设备驱动程序**（唯一懂硬件的） |
| 检查用户权限 | **设备独立性软件**（安检员） |
| printf 的格式转换（二进制→ASCII） | **用户层 I/O 软件**（C 库函数，进内核前就干完了） |
| 缓冲区管理 | **设备独立性软件** |

> 🔗 你的卡片：[[卡片/记忆--IO软件四层作用]]、[[卡片/记忆--IO软件与硬件对照]]

### 3.19 驱动不能用汇编写/不能跨 OS ⚡（原题32 · !）
现在的驱动程序 **95% 用 C 语言**写的（只有极少数时序苛刻的代码才用汇编）。

**驱动程序绝对不能跨 OS**！它要调用 OS 内核接口，与 OS 密切相关——Windows 显卡驱动装不到 Mac 上。

### 3.20 驱动程序不能分析数据内容（原题33）
> 驱动程序是个没感情的搬砖机器！只负责把 0101 搬进内存，**不具备"分析数据内容"的能力**——数据分析是用户态应用程序（播放器、Word）的事。

驱动程序的"检查"是**物理合法性**（你要读第 1000 扇区但硬盘只有 500 扇区→不合法）；独立性软件的"检查"是**权限合法性**（你是谁，能不能用）。

### 3.21 驱动程序与 I/O 控制方式强相关（原题43）
底层控制方式（程序直接控制 vs 中断 vs DMA）不同 → 驱动程序的源代码结构天差地别！**驱动程序与 I/O 控制方式绝对是强相关的。**

设备初次连接主机时，驱动程序负责初始化设备。

### 3.22 键盘输入的数据流转路径 ⚠️（原题45 · !!）

```
键盘敲击 → 键盘控制器数据寄存器（硬件，随时被覆盖）
  → 中断服务例程用 IN 指令救出（CPU 寄存器，马上要被占用）
  → 内核缓冲区（统一大池子，不知道谁在等）
  → (OS 调度发现某进程在等输入)
  → 用户工作区（用户缓冲区）
```

**关键点**：
- 中断程序不知道按键是给 Word 的还是浏览器的——它只负责先统一收进**内核缓冲区**
- 之后 OS 调度发现 Word 在等输入 → 才从内核缓冲区拷贝到 Word 的用户区

### 3.23 键盘输入的大题流程（大题）
正确顺序：②→⑥→④→③→①→⑤

1. **②** 进程 P 执行系统调用要读，缓冲区没字符 → 阻塞，插入阻塞队列
2. **⑥** CPU 切走去跑别的进程，用户敲键盘
3. **④** 敲键盘触发硬件中断 → 启动键盘**中断处理程序**
4. **③** 中断处理程序把字符从键盘控制器读入系统缓冲区
5. **①** 字符有了 → 唤醒 P → 插入就绪队列
6. **⑤** P 被调度上 CPU → 从系统调用返回（真正拿到字符）

> 🧠 **你的思维误区**："我以为中断处理程序先开，才能接收中断信号"——**中断处理程序是来处理中断的，不是来"等着接收"的！** 中断发生→CPU 自动切内核态→跳到 ISR 入口→执行 ISR。ISR 的启动是中断的**结果**，不是前置条件。

## 四、磁盘

### 4.1 随机访问 vs 直接访问 vs 顺序访问（原题3）
> 🔗 你的卡片已完美覆盖：[[卡片/辨析--随机与直接访问]]

一句话总结：**磁盘和光盘是直接访问（DAM），磁带是顺序访问（SAM），其余常见的（内存、SSD、U 盘）都是随机访问。**

### 4.2 寻道时间影响最大（原题7）
对磁盘读写时间影响最大的是**寻道时间**（移动磁头）。

### 4.3 扇区数据的信息是出厂低级格式化创建的 ⚠️（原题9 · !!）
每个扇区里的扇区号等基础信息，是**出厂时商家创建**的，叫**低级格式化（物理格式化）**。

> 🧠 **注意审题**：题目问的是"分扇区后的信息"而不是"分区"的信息——低级格式化是硬件级别的，分区和逻辑格式化是 OS 级别的。

### 4.4 扇区数据处理时间影响传输时间（原题10）
扇区数据的处理时间主要影响**传输时间**。文件的物理结构包括磁道上的存放方式（连续/交替分配）。

### 4.5 寻道时间最影响磁盘 I/O（原题11）
**移动磁头的延迟 = 寻道时间**，是影响磁盘 I/O 最大的因素。

### 4.6 FCFS 不会饥饿，SSTF 会（原题13）
**先来先服务（FCFS）不会出现饥饿现象！** SSTF（最短寻道时间优先）才会——远处的请求可能永远等不到磁头过来。

### 4.7 磁头臂黏着（Arm Stickiness）= 局部极度饥饿 ⚡（原题32 · !）
| 算法 | 会黏着吗？ | 原因 |
|------|:--:|------|
| **FCFS** | ❌ 免疫 | "只看时间不看距离"的铁憨憨——900 道的请求排在前面，即使脚下有 1 万个新请求也得走 |
| **SSTF / SCAN / C-SCAN** | ✅ 会 | "空间（距离）优先"——脚下有请求就先干，结果被源源不断的本地请求黏住 |

### 4.8 固态硬盘（SSD）考点（原题25）
| 考点 | 内容 |
|------|------|
| 读写单位 | **页** |
| 擦除单位 | **块**（一整块擦除） |
| 写时问题 | 不能单独擦一页 → 要把整块其他有用页先读出来 → 擦除整块 → 把老数据+新数据一起写回 → **随机写入速度很慢** |
| 随机访问速度 | **非常快**（纯电子，无机械部件） |
| 静态 vs 动态磨损 | 静态磨损策略更高级——在没有外部动作时自动调整静态数据的位置，让高磨损块以读为主 |

> 🔗 你的卡片：[[卡片/记忆--固态硬盘考点]]

### 4.9 逻辑格式化做的工作（原题30）
分区是在低级初始化之后、逻辑格式化之前进行的独立步骤。

逻辑格式化不负责：划分扇区结构（那是出厂低级格式化的）、不负责分区。

逻辑格式化负责：
- 建立**根目录**（如 Linux `/` 或 Windows `C:\`）
- 初始化**文件分配表（FAT/MFT/Bitmap）**，标记所有数据块为空闲
- 创建**空闲块链表/位示图**

### 4.10 提前读与延迟写（原题31）
> 你的困惑：不知道这两个词的含义

| | 提前读 | 延迟写 |
|---|---|---|
| 怎么做 | 当前块还没读完就把下一块预先读到缓冲区 | 数据先写入缓冲区，不立即写回磁盘 |
| 为何加速 | 程序顺序读时，下一块已经在内存了 | 若程序连续修改同一位置 100 次→前 99 次在内存覆盖→硬盘只写最后 1 次 |

**延迟写的双重加速**：
1. 对程序：误以为写入速度是内存级（纳秒级）
2. 对硬盘：减少 I/O 次数（合并覆盖写入）

### 4.11 磁盘大题：C-SCAN 的边界处理
> 你的困惑：C-SCAN 要移动到最末端，但没给末端磁道号！

**统考真题的标准做法**：只统计有效寻道（服务请求所跨越的磁道），回退那一段不读数据，通常忽略或题目不要求。

### 4.12 簇号→物理地址的约定
**柱面号、磁道号、扇区号、簇号默认都从 0 开始编号！**

例：0~999 簇→柱面 0，1000~1999→柱面 1，100000~100999→柱面 100。100260 落在 100000~100999 内→柱面 100。

柱面号 = 100260 ÷ 1000 = 100 余 260 → 磁道号 = 260 ÷ 100 = 2 余 60 → 扇区 = 60×2 = 120、121。

这个簇号→物理地址的转换由 **I/O 系统中的设备驱动程序**完成。

## 🔗 OS ↔ 计组 对应关系（跨学科联动）

> I/O 在 408 的**操作系统**和**计组**里都考，视角不同：**OS 看"软件层次 + 进程状态 + 调度管理"，计组看"硬件电路 + 时序 + 信号"。** 同一概念两边都讲，串起来一次打通。
> 对应的计组整理见 [[2.知识库/20.North_star_ZJU/202.计算机知识/计组/07io/王道题-知识点整理|计组-IO 王道题知识点整理]]。

| 主题 | OS 视角（本文） | 计组视角（计组整理） |
|------|----------------|------------------|
| **I/O 接口 / 设备控制器** | 控制器提供命令集，CPU 写控制寄存器下命令（1.3） | 接口=适配器/控制器，硬件部件，含数据/状态/控制寄存器 |
| **设备地址命名** | 绝对号 vs 相对号；设备名→fd→驱动链（2.3、卡片） | 逻辑设备名/物理设备名/主从设备号 |
| **通道** | 通道是硬件；通道→控制器→设备的层级（1.4、2.4） | 能独立执行通道程序的"超级 DMA" |
| **DMA** | 进程状态：运行态→阻塞态→中断仍阻塞→就绪（2.1） | 总线请求 HRQ、周期窃取、块/字、Cache 一致性 |
| **中断处理** | 中断驱动 I/O：ISR 把控制器缓冲读到内存缓冲（2.8） | 中断隐指令、保护断点、中断向量、关/开中断位置 |
| **中断 vs 进程** | "进程阻塞"≠"CPU 空转"；不一定返回原进程（2.7、2.8） | 硬件何时检测中断（指令结束时）、多重中断堆栈 |
| **数据传送本质** | 驱动程序把标准命令翻译为硬件寄存器操作（2.5、3.18） | 中断 I/O 实质是 ISR 里 `IN`/`OUT` 指令驱动 |
| **缓冲区** | 内存缓冲 vs SPOOLing 井；缓冲区是临界资源（3.2、3.6） | 普通中断和 DMA 都有硬件缓冲（攒够再发信号） |
| **数据流转** | 键盘：控制器寄存器→CPU 寄存器→内核缓冲→用户区（3.22） | 设备→数据缓冲寄存器→数据线→主存 |

**值得反复咀嚼的主线：**
1. **中断 I/O 的传送是软件还是硬件？** OS（3.18）说驱动程序是唯一懂硬件的层；计组说实质是 ISR 里的 `IN`/`OUT` 指令——其实是 ISR 调用驱动程序、驱动程序里的 `IN`/`OUT` 驱动硬件寄存器，同一件事的两个切片。
2. **DMA 时进程和 CPU 各干嘛？** OS 管进程状态变化（2.1），计组管总线/信号走向，拼成完整生命周期。
3. **中断为何不一定返回原进程？** 计组保证"能正确返回断点"（机制），OS 决定"要不要返回"（调度策略，2.8）。
4. **缓冲区无处不在：** 硬件 FIFO（计组）→ 内存缓冲 → 磁盘 SPOOLing 井（OS 3.2），是"缓冲"从微观到宏观的三级放大。
