    在中断驱动的 I/O 方式中，当 I/O 设备完成数据准备后，中断处理程序负责将设备控制器缓冲区中的数据读取到内存缓冲区中（输入），或者将内存中的数据写入设备控制器（输出）。
    
    由于不同 I/O 设备（如键盘、磁盘、网卡）的硬件结构、数据传输速率和控制逻辑不同，操作系统会为它们配置不同的驱动程序和相应的中断服务程序（ISR）。

    **被中断的进程**是指硬件中断发生那一瞬间，正在 CPU 上运行的进程。该中断是由外部硬件设备（I/O 完成）引起的，与当前正在运行的进程通常没有因果关系。操作系统的进程调度模块会重新评估就绪队列。如果新就绪的进程优先级更高，CPU 将直接切换到该进程执行，而不会返回到先前“被中断的进程”。因此，“一定会返回到被中断的进程”的表述过于绝对。况且还有多重中断的可能！

    你的进程喊着“我要一台打印机”。OS 首先去查全系统的总目录（SDT），看看公司里到底有没有你要的这号设备，并找到这台设备的“个人档案”放在哪。

1. **②** 进程 P 执行系统调用要读一个字符，但此时缓冲区里还没有字符，读不到，于是 P 只能**先阻塞**，被插入阻塞队列。
2. **⑥** CPU 切走去跑别的进程，期间用户在键盘上敲了一个字符。
3. **④** 敲键盘这个动作**触发了硬件中断**，于是启动键盘中断处理程序。
4. **③** 中断处理程序把字符从键盘控制器读入系统缓冲区。
5. **①** 现在字符有了，P 等待的条件满足，把 P 唤醒，插入就绪队列。
6. **⑤** P 被调度上 CPU 后，从系统调用返回（这时它才真正拿到了字符）。
  我以为中断处理程序先开，才能接收到中断信号。中断处理程序是处理中断的！进程从系统调用返回，前提是它得先回到 CPU 上运行
知识点
1. 在 **②**（插入阻塞队列）之后，CPU 一定从 P 切换到其他进程；在 **①**（插入就绪队列）之后，调度程序才可能再选中 P。
2. **③ 和 ④** 的代码属于键盘驱动程序（中断处理程序及其读控制器的部分）。
3. 键盘中断处理程序执行时，P 处于**阻塞态**（它还没被唤醒）；CPU 处于**内核态**（中断处理属于核心态执行）
