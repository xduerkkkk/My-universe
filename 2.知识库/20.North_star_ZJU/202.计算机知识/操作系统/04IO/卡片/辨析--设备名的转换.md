1. 用户调用 `open("/dev/lp0")` 时，系统通过文件系统找到这个设备文件的 inode，从中取出**主设备号 (major) 和次设备号 (minor)**。
2. 系统用 major 号去**设备驱动表（设备开关表 device switch table）**里查，找到对应的驱动程序入口。
3. `open` 成功后返回一个整数 `fd`（比如 3）。从此用户**不再用字符串**，而是用这个 `fd` 来代表设备
4. 当 `write(fd, ...)` 真正执行时，驱动程序再借助 minor 号和系统的**设备配置表**，定位到实际的硬件地址

| 转换步骤                               | 发生在哪一层     | 用到的表            |
| ---------------------------------- | ---------- | --------------- |
| `write(fd,...)` 库函数封装成 `trap` 陷入内核 | 1. 用户层     | —               |
| `"/dev/lp0"` → 主/次设备号              | 2. 设备独立性软件 | 文件系统 inode      |
| 主设备号 → 驱动程序入口                      | 2. 设备独立性软件 | **设备开关表 / DCT** |
| `fd` → 打开文件表 → 设备                  | 2. 设备独立性软件 | 进程打开文件表、系统打开文件表 |
| minor 号 → I/O 端口/IRQ，发命令给硬件        | 3. 设备驱动程序  | **设备配置/控制信息**   |
| 硬件完成 → 发中断 → 唤醒进程                  | 4. 中断处理程序  | —               |

### 第 1 层：用户层 I/O 软件

- `printf`、`fopen`、`write` 这些库函数把用户参数整理好，通过系统调用陷入内核。
- 还包括 **SPOOLing（假脱机）**，比如打印任务先写到磁盘井 (well) 排队，让独占设备变成可共享。

### 第 2 层：设备独立性软件（核心，设备名在这里被解析）

这一层的任务正好是"屏蔽硬件差异"，主要做四件事：

- **设备命名/名字解析**：`/dev/lp0` → 设备号。
- **设备保护**：检查权限（能不能写这台设备）。
- **统一接口与缓冲**：提供与设备无关的块大小、缓冲管理。
- **设备分配与回收**：通过设备表判断设备是否空闲、能否分配。

### 第 3 层：设备驱动程序

- 唯一了解具体硬件细节的代码。
- 把抽象请求（"写这些字节"）翻译成**具体寄存器操作**：往控制寄存器写命令、往数据寄存器送数据、设置中断。
- 完成 minor 号 → 物理 I/O 端口/IRQ 的最后映射。

### 第 4 层：中断处理程序

- 设备完成操作后产生中断，CPU 转到中断处理程序。
- 它唤醒之前因 I/O 而阻塞的进程，告诉上层"干完了"。
