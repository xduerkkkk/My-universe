C 语言的 fwrite (buf, 1, 100, fp);

1. 用户调用接口，
	1. 翻译成汇编语言，writexxx
	2. **库函数发起一次系统调用**, 靠陷入指令切态准备进入内核态
2. 设备独立性软件
	1. 各种检查？（逻辑合法性？是否越界？权限检查、安全检查）
	2. 讲逻辑设备翻译成具体的物理设备及驱动程序入口
	3. :**缓冲管理**(buffer)、**块大小统一**(屏蔽不同磁盘扇区差异,对上层提供统一块)、**设备的分配与回收**、**出错处理**。
3. 设备驱动程序
	1. 检查设备的状态（物理合法性）
	2. 计算出具体的寄存器控制字，写入
4. 中断程序
	- 设备把数据写完 (物理动作完成), 给 CPU 发一个**中断信号** 
	- CPU 暂停当前工作,跳到中断处理程序:检查设备状态 (成功还是出错)、必要时搬运数据、清理现场。
	- 最后**唤醒第 3 层里被阻塞的那个进程**, 告诉它"你的 write 干完了", 结果一层层返回到用户的 `fwrite`。


磁盘调度究竟被分给谁了？
设备驱动程序，只有它接触磁头磁道呀

*   **是只有设备独立性层才翻译吗？** 绝对不是。如你所感悟到的，**全流程都是一层层的“降维翻译”**：
    *   **编译层：** 变量名 `a` 翻译成了栈内存地址 `[rbp-4]`。
    *   **VFS 层：** 文件描述符 `fd` 翻译成了内核的 `struct file`。
    *   **文件系统层：** 逻辑偏移量翻译成了硬盘 LBA 扇区号。
    *   **内存管理层：** 虚拟内存地址 `&a` 翻译成了总线物理 DMA 地址。
    *   **驱动层：** 软件的请求结构体翻译成了硬件设备特定的“命令协议包（控制字）”。
*   **逻辑合法性在哪里？** 主要在 VFS（权限、进程内存安全、文件状态）。
*   **物理合法性在哪里？** 在驱动层和硬件本身（设备在线状态、扇区越界、坏块检测）。
*   **寄存器写入是在哪？** 在驱动层与硬件通信的最后一步（触发门铃），通常只是一条单纯的汇编内存赋值指令 `mov [MMIO地址], 控制字`。
