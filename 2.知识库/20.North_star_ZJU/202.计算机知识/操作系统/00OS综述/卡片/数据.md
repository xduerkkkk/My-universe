所有数据分为
- 只能由特权指令改写
- 在内核态下由 OS 改写
- 硬件自动改写
- 用户态改写




各类数据的改写（也就是修改计算机里的各种变量、寄存器、结构体）确实感觉又多又杂。考试和课本一会儿考进程、一会儿考页表、一会儿考硬件，很容易看晕。

其实，如果你从“谁有权改写”**、**“在哪里改写”**以及**“恶意改写会发生什么”这三个维度去给数据分类，整个知识体系瞬间就会变得清晰无比。

我们可以把计算机里被改写的数据划分为四大阵营：

## 1. 黄金阵营：必须由【特权指令】改写的数据

> **底层逻辑：** 这些数据控制着整个计算机的**底层生死命脉**。如果允许普通程序改写，系统隔离将荡然无存。

- **硬件特殊寄存器：**
    
    - **PSW（程序状态字寄存器）中的特权控制位**：决定 CPU 此时是用户态还是内核态。
        
    - **CR3（页表基址寄存器）**：存放当前进程的多级页表在物理内存中的首地址。
        
    - _谁能改：_ 只有内核态下的操作系统，用专门的特权指令（如 `LCR3`）才能改。
        
- **硬件全局中断配置：**
    
    - **CPU 的中断允许标志位（IF）**：决定要不要响应外中断。
        
    - _谁能改：_ 必须由特权指令 `CLI`（关中断）和 `STI`（开中断）来改。
        
- **外设控制器的寄存器（I/O 端口）：**
    
    - 比如磁盘控制器的“写入扇区”寄存器、显卡控制器的控制寄存器。
        
    - _谁能改：_ 只能用特权指令 `IN` / `OUT` 改写。
        

## 2. 白银阵营：在【内核态下由 OS 软件】改写的数据

> **底层逻辑：** 这些数据本身躺在**物理内存的内核区**。虽然改写它们不需要特殊的硬件特权指令（用普通的普通数据传送指令 `MOV` 就能改），但由于**虚拟内存的物理隔离**，用户态程序根本碰不到这块内存，所以只能由操作系统内核代码去改写。

- **进程的核心控制结构（PCB）：**
    
    - 包含：进程的状态（运行、就绪、阻塞）、进程的优先级、进程的剩余时间片。
        
    - _改写时机：_ 每次时钟中断爆发、或者进程主动阻塞时，由操作系统内核的调度代码改写。
        
- **内核全局管理变量：**
    
    - **系统全局时钟变量（Tick Count）**：记录开机以来跳动了多少毫秒。
        
    - **空闲物理内存链表 / 位图**：记录哪些物理内存是空闲的。
        
    - _改写时机：_ 时钟中断服务程序每次心跳时改写时钟；分配内存时内核代码改写内存链表。
        
- **页表（Page Table）的内容：**
    
    - 页表里的虚拟页到物理页框的映射关系、有效位、保护位。
        
    - _改写时机：_ 发生**缺页中断**时，内核程序把磁盘数据搬进内存，然后改写页表对应的条目。
        

## 3. 青铜阵营：【硬件自动】改写的数据

> **底层逻辑：** 这些数据不需要任何软件代码去操心，是 CPU 芯片里的晶体管根据物理世界的物理信号、或者指令执行的结果，**纯硬件电路自动改写**的。

- **PSW（程序状态字寄存器）中的算术状态位（条件码）：**
    
    - 包含：零标志位（Z）、进位标志位（C）、负数标志位（N）。
        
    - _改写逻辑：_ 普通用户程序执行一条普通的算术指令（如 `SUB A, B`），如果结果等于 0，**CPU 硬件电路自动把 Z 位改成 1**。这在用户态天天发生，完全安全。
        
- **快表（TLB）和高速缓存（Cache）：**
    
    - _改写逻辑：_ CPU 访问内存未命中时，**CPU 硬件内部的 MMU 或缓存控制器**会自动把新的内存映射或数据加载进 TLB / Cache，并自动踢掉旧的数据。软件（OS）不需要干预。
        
- **程序计数器（PC）：**
    
    - _改写逻辑：_ 每执行完一条指令，**硬件自动把 PC 加 4**（指向下一条指令）；或者遇到跳转指令、发生中断时，**硬件自动把目标地址写进 PC**。
        

## 4. 黑铁阵营：在【用户态下由普通程序】改写的数据

> **底层逻辑：** 这就是你平时写 C 语言或任何代码时改写的数据。它被死死限制在当前进程的“一亩三分地（用户态堆栈）”里，随便怎么改，最坏的结果也就是自己的程序崩溃。

- **通用寄存器（GPRs）：**
    
    - 如 `EAX`, `EBX`, `ECX`。
        
    - _改写逻辑：_ 用户程序执行 `MOV EAX, 10`，爱怎么改怎么改。
        
- **用户态内存中的变量：**
    
    - 你的代码里定义的全局变量、局部变量、指针、堆内存。
        
    - _改写逻辑：_ 执行数据传送指令（如 `MOV`）改写。
        

## 💡 终极一张表：看清各类数据的改写本质

|**数据类型**|**存放位置**|**改写它需要什么指令？**|**谁有权改写？**|**为什么限制？**|
|---|---|---|---|---|
|**CR3 / 内核态 PSW**|CPU 内部特殊寄存器|**特权指令**（如 LCR3）|仅限内核态 OS|关乎全系统控权与内存屏障|
|**PCB / 内存页表**|物理内存（内核区）|**非特权指令**（普通的 MOV）|仅限内核态 OS|处于内核地址空间，用户态摸不到|
|**用户态通用寄存器 / 条件码**|CPU 内部通用寄存器|**非特权指令**（普通的 ADD/MOV）|用户程序、内核皆可|只影响当前指令的算术结果或自身逻辑|
|**TLB / Cache / PC**|CPU 内部加速与控制部件|**不需要指令**|**硬件电路自动改写**|属于纯硬件自动化机制|

有了这个框架，以后做题看到任何“数据的改写”，先问自己三个问题：**它在哪里？改它需要特权指令吗？普通程序改了会不会天下大乱？** 答案自然就出来了。
