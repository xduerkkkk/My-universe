| **动作阶段**                   | **执行主体**                                 | **为什么？（底层逻辑）**                                                               |
| -------------------------- | ---------------------------------------- | ---------------------------------------------------------------------------- |
| **1. 关中断、保存断点 (PC/PSW)**   | **硬件自动**<br><br>  <br><br>(又称**中断隐指令**)  | **十万火急！** 中断砸下来的时候，操作系统代码还没登场呢。如果硬件不自动存住 PC 和 PSW，CPU 一旦跳转，原来的程序在哪就彻底丢了。     |
| **2. 识别中断源，寻找中断服务程序入口**    | **硬件自动**                                 | 硬件去查操作系统提前放在内存里的**中断向量表**，找到对应处理程序的地址，然后强行把这个地址送进 PC。这也是硬件电路自动完成的跳转。         |
| **3. 保存通用寄存器 (PUSH GPRs)** | **操作系统（软件）**                             | CPU 已经成功跳转到操作系统的中断服务程序入口了。接下来的第一件事，是由操作系统写一句 `SAVE_ALL`（汇编里的压栈指令），把通用寄存器存起来。 |
| **4. 具体的服务逻辑（如缺页把数据读入内存）** | **操作系统（软件）**                             | 具体的业务逻辑，硬件芯片不可能知道你需要怎么分配内存、怎么读磁盘，这必须由操作系统内核代码去执行。                            |
| **5. 恢复通用寄存器**             | **操作系统（软件）**                             | 事情办完了，操作系统写一段出栈指令（POP），把通用寄存器还给用户程序。                                         |
| **6. 开中断、执行中断返回 (IRET)**   | **操作系统发出指令**<br><br>  <br><br>**硬件执行动作** | 操作系统执行一句 `IRET` 汇编指令，触发 **硬件** 自动把第一步存进去的 PC 和 PSW 弹出来，特权级降回用户态。             |
