# PV 操作

流程
1. 找出题目中所有进程
2. 用中文描述进程所做的事，必须有详细步骤，原子步骤。如：生产 A; 把 A 放到 F1。而不是“在 F1 上放生成的 A”
3. 检查所有进程，看哪里有“P”的需求。每找到一个 P 的需求立刻去补一个 V 的释放。再去看哪里有互斥的需求，顺手 PV 相夹
4. 看自己定义的所有 PV，自己定义信号量名字，初始值
5. 到这就算完成了，现在检查“连续两个 P”的部分，有没有可能发生死锁。如果有，尝试调换顺序
6. 再回顾整个题，检查

## 注意“尽可能少的信号量”


![[_attachments/image/03强化课--PV操作-1780298756457.jpeg]]

🔍 核心本质：为什么这道题不需要 `mutex` 和 `empty`？

### 1. 降维打击：严格的先后顺序，天然自带“互斥”

- **物理现实：** 题目规定了一根铁律——**$P_1$ 执行 $C_1$ 后，$P_2$ 才能执行 $C_2$**（即 $C_1 \rightarrow C_2$）。
    
- **思维扭转：** 既然 $C_2$ 必须在 $C_1$ 彻底结束、发出信号（`signal`）之后才能开始，这就意味着 **$P_1$ 和 $P_2$ 在微观时间轴上是“串行（接力跑）”的，它们绝对不可能同时冲进缓冲区 B 里打架。** * **结论：** 当同步关系极其严格、形成单向顺序流时，**同步本身就已经包含了互斥**。单独加一个 `mutex` 锁，纯属画蛇添足。
    

### 2. 空间折叠：当容量为 1 时，状态互为镜像

- **物理现实：** 缓冲区的大小只有 1。
    
- **思维扭转：** 在标准的生产者-消费者问题中，因为容量很大（比如 1000），我们需要 `empty=1000` 和 `full=0` 两个大箱子来分别计数。但现在容量只有 1，缓冲区的状态变成了纯粹的**二进制**：
    
    - 状态 0：里面是空的（$P_1$ 可以放，$P_2$ 不能取）。
        
    - 状态 1：里面是满的（$P_1$ 不能放，$P_2$ 可以取）。
        
- **结论：** 一个硬币的两面，只需要一个布尔值（或一个初值为 0 的信号量 $S$）就能完美表达。有了 `S` 表达“有没有货”，就不再需要 `empty` 来表达“有没有空位”了。
    
为了彻底戒掉“机械套模板”的习惯，以后拿到任何同步互斥大题，**绝对不要先写信号量**。按下面这个流水线去过滤你的思维：

### 第一步：画出“时序图”，而不是“关系网”

问自己：这两个进程是**任意交替**执行的，还是有**严格的先后接力**关系？

- 如果是任意交替（比如多个人随机抢同一把锤子），必须上 `mutex`。
    
- 如果是 A 没干完，B 绝对动不了（单向箭头 $A \rightarrow B$），那么**只写同步，不写互斥**。
    

### 第二步：检查“容量边界”

看一眼缓冲区的容量。

- 如果容量 $> 1$：老老实实写 `empty` 和 `full`。
    
- 如果容量 $== 1$：高度警惕！尝试只用一个初值为 0 的同步信号量。让先跑的人去 `signal`，后跑的人去 `wait`。
    

### 第三步：审查每一个信号量，玩“精简删减”游戏

代码草稿写完后，对着你定义的每一个信号量进行无情质问：

- “我加的这个 `mutex`，在物理上真的可能发生两个人同时进去的情况吗？”
    
- “我加的这个 `empty`，它的数值在运行过程中，是不是永远和 `full` 刚刚好相反？”
    
    如果答案是肯定的，立刻动手把它们无情地擦掉。

如果我把题目稍微改一下：“缓冲区 B 的容量依然为 1，但 $P_1$ 和 $P_2$ 变成了一个无限循环，要求 $P_1$ 放一个，$P_2$ 取一个，交替进行”，此时你的思维网里，会决定用几个信号量呢？
### 🚨 实验：如果坚持只用 1 个信号量 `S = 0`

既然你觉得没区别，那代码写出来肯定长这样：

C

```
Semaphore S = 0; // 表达“缓冲区里有没有货”

P1() {
    while(TRUE) {
        放一个产品;  // 1. 放入缓冲区 B
        signal(S);  // 2. 喊一句：有货了！
    }
}

P2() {
    while(TRUE) {
        wait(S);    // 1. 等货
        取一个产品;  // 2. 从缓冲区 B 取走
    }
}
```

### 💥 瞬间翻车现场：缓冲区溢出（Overflow）

假设此时 CPU 极度偏心，把所有的算力都分给了 $P_1$，而 $P_2$ 根本没有机会运行。

1. **第一轮循环：** $P_1$ 进场，执行 `放一个产品`。此时缓冲区 B 满了（存了 1 个产品）。接着执行 `signal(S)`，信号量 `S` 变成 1。
    
2. **第二轮循环：** 因为是 `while(TRUE)`，$P_1$ 瞬间转回了开头。此时 $P_2$ 还没来得及运行。$P_1$ 没有任何阻挡，直接往下执行 **`放一个产品`**！
    
3. **物理灾难发生：** 缓冲区 B 的容量**明明只有 1**，里面本来就有一个产品没被取走，$P_1$ 却强行又塞进去了一个！**缓冲区直接溢出，数据被无情覆盖，系统崩溃！**
    

🔍 为什么上一题可以，这一题就不行？

### 1. 上一题（2025 年真题的原型）：单向单次接力跑 🏃‍♂️

上一题的代码里**没有 `while(TRUE)` 循环**。$P_1$ 执行完 $C_1$、发完 `signal(S)` 之后，它的使命就**彻底结束**了，它再也不会回过头来放第二个产品。所以，我们只需要管住 $P_2$、让 $P_2$ 别提前动手就行了。

### 2. 本题（无限循环）：双向连环锁 🔄

一旦加了循环，$P_1$ 就会变成一个不知疲倦的“无情生产机器”。

- 你的 1 个信号量 `S`，**只能管住 $P_2$**（没货时别瞎取）。
    
- 但你**漏掉了管住 $P_1$ 的大闸**！你必须还要有一道关卡，在缓冲区满了的时候，把 $P_1$ 拦在外面，大喊：“等一下！$P_2$ 还没取走呢，你不准放第二个！”
    

## 🛠️ 正确的解法：必须上 2 个信号量

为了让它们俩交替进行，互相牵制，必须引入标准的“双向握手”：

C

```
Semaphore empty = 1; // 空闲位置（一开始有1个空位）
Semaphore full = 0;  // 产品的数量（一开始有0个产品）

P1() {
    while(TRUE) {
        wait(empty); // 先看看有没有空位？(第一次稳稳进去)
        放一个产品;
        signal(full); // 告诉 P2：有货了，你去取吧！
    }
}

P2() {
    while(TRUE) {
        wait(full);  // 先看看有没有货？
        取一个产品;
        signal(empty); // 告诉 P1：我拿走了，空位还给你！
    }
}
```

### 🛡️ 再次用刚才的极端场景测试：

$P_1$ 第一次放完产品后，执行了 `signal(full)`。当它想转回来放第二遍时，会迎头撞上 **`wait(empty)`**。因为此时 `empty` 已经变成 0 了，$P_1$ 会老老实实地在这里**死死卡住、原地睡觉**，绝对没有机会去溢出缓冲区。直到 $P_2$ 跑完一轮发出 `signal(empty)`，把 $P_1$ 叫醒，$P_1$ 才能放下一个。

## 哲学家

### 方法一：限制同时进餐的人数（打破“不剥夺/环路等待”条件）

- **核心思想：** 房间里有 5 个哲学家，但我们只放 4 张椅子（设信号量 `count = 4`）。只要同时想吃的人不超过 4 个，由于资源配置比人数多，就绝对能保证至少有一个人能同时凑齐两根筷子。
    

C

```C
semaphore chopstick[5] = {1, 1, 1, 1, 1}; // 5根筷子
semaphore count = 4;                      // 完美限制：最多允许4人同时出手

void Philosopher(int i) {
    while (TRUE) {
        思考;
        
        P(count);               // 1. 抢夺4个“就餐名额”之一
        P(chopstick[i]);         // 2. 稳稳拿左
        P(chopstick[(i+1)%5]);   // 3. 稳稳拿右
        
        进餐;
        
        V(chopstick[i]);         // 1. 放左
        V(chopstick[(i+1)%5]);   // 2. 放右
        V(count);               // 3. 腾出名额给下一个人
    }
}
```

### 方法二：奇偶号非对称拿筷子（打破“环路等待”条件）

- **核心思想：** 让奇数号哲学家先拿左边再拿右边；偶数号哲学家反过来，先拿右边再拿左边。通过故意制造“方向冲突”，强行让相邻的两个人去死磕同一根筷子，从而破除环形死锁。
    



```C
semaphore chopstick[5] = {1, 1, 1, 1, 1}; // 5根筷子

void Philosopher(int i) {
    while (TRUE) {
        思考;
        
        if (i % 2 == 1) { 
            // 奇数号哲学家：先左后右
            P(chopstick[i]);
            P(chopstick[(i+1)%5]);
        } else { 
            // 偶数号哲学家：先右后左
            P(chopstick[(i+1)%5]);
            P(chopstick[i]);
        }
        
        进餐;
        
        V(chopstick[i]);
        V(chopstick[(i+1)%5]);
    }
}
```

### 方法三：仅当左右两根筷子均空闲时才允许拿起（你的全局锁方案）

- **核心思想：** 也就是你截图里的方案。利用一把全局互斥锁 `mutex`，把“拿左、拿右”这两个动作封装成一个不可分割的**原子宏观整体**。要么你一根都别拿，要么两根一起顺走。
    



```C
semaphore chopstick[5] = {1, 1, 1, 1, 1}; // 5根筷子
semaphore mutex = 1;                      // 全局抓取互斥锁

void Philosopher(int i) {
    while (TRUE) {
        思考;
        
        P(mutex);               // 1. 锁住整个大厅的“抓取权”（所有人不准动！）
        P(chopstick[i]);         // 2. 拿左
        P(chopstick[(i+1)%5]);   // 3. 拿右
        V(mutex);               // 4. 释放抓取权
        
        进餐;
        
        V(chopstick[i]);         // 放筷子不需要抢大门锁
        V(chopstick[(i+1)%5]);
    }
}
```


你现在的并发思维已经非常硬核了。回头看这三种方法：

- **方法一** 走的是 **“控人数”** 路线；
    
- **方法二** 走的是 **“反向走位”** 路线；
    
- **方法三（也就是你敏锐捕捉到的方案）** 走的是 **“野蛮原子大包围”** 路线。



![[_attachments/image/03强化课--PV操作-1780296901245.jpeg]]


- 如果题目**没有**硬性规定并发度，只想图省事 $\rightarrow$ 可以用一把全局 `mutex` 粗暴大包围（锁粒度粗）。
    
- 如果题目**强行要求“尽可能高的并发度”** $\rightarrow$ 必须把公共资源（碗）和边界冲突（筷子）拆开。用 `count = n-1` 这种“只限制总人数、不限制具体动作”的精细化机制，去给并发度彻底松绑。


既然不能一刀切，我们就把资源拆开治理：

- **关于碗：** 它是放在圆桌中心的公共资源，谁先来谁拿，用最纯粹的 **资源信号量** 即可。
    
- **关于死锁：** 我们采用我们通关表里的 **“限制最多 $n-1$ 个人同时出手”** 策略。只要限制了出手人数，就绝对不会形成环路等待，连一把大门锁都不需要！
    

### 📝 满分代码实现与信号量定义

C

```
semaphore chopstick[n] = {1, 1, 1, ..., 1}; // n根筷子的信号量，初值全为1
semaphore bowl = m;                         // m个碗的资源信号量，初值为m
semaphore count = n - 1;                    // 完美限制：最多允许 n-1 个人同时尝试进餐
```

**哲学家 $i$ 的进程流（$i = 0, 1, ..., n-1$）：**

C

```
void Philosopher(int i) {
    while (TRUE) {
        思考;
        
        P(count);               // 1. 核心防死锁：限制同时出手的人数不超过 n-1
        P(bowl);                // 2. 正常申请一个碗
        
        P(chopstick[i]);         // 3. 拿左手边筷子
        P(chopstick[(i+1)%n]);   // 4. 拿右手边筷子（注意题目是n个哲学家，所以模n）
        
        进餐;
        
        V(chopstick[i]);         // 1. 放回左手筷子
        V(chopstick[(i+1)%n]);   // 2. 放回右手筷子
        V(bowl);                // 3. 把碗放回原位
        
        V(count);               // 4. 腾出一个出手名额给别人
    }
}
```
## 理发师

![[_attachments/image/03强化课--PV操作-1780218380265.jpeg]]


![[_attachments/image/03强化课--PV操作-1780211354579.jpeg]]

一旦题目中出现了“如果满/空了，就直接离开/丢弃”**这种分支剧情，你必须在纯 P/V 操作之外，引入一个**普通的整型变量（共享计数器）**来记录当前的状态，并且用一个专门的**互斥信号量（Mutex）来保护它。

我们用升级后的“五步法”来秒杀这道题：

#### 第一步：找出所有进程，描述原子步骤

- **理发师：** 睡觉（等顾客） $\rightarrow$ 叫一个顾客过来 $\rightarrow$ 理发。
    
- **顾客：** 进门看椅子 $\rightarrow$ 有空位就坐下并叫醒理发师 / 没空位就走人 $\rightarrow$ 等待理发 $\rightarrow$ 被理发。
    

#### 第二步：引入核心变量与信号量（寻找 P/V 需求）

既然要判断有没有空椅子，我们就设一个普通变量 `waiting = 0` 表示正在等待的顾客数。

- `int waiting = 0;` （普通变量，记录等待人数）
    
- `Semaphore mutex = 1;` （互斥信号量，谁想看/修改 `waiting`，谁就得先 P 这个门锁）
    
- `Semaphore customers = 0;` （同步信号量，顾客用来叫醒理发师，“生产”了一个待理发的顾客）
    
- `Semaphore barbers = 0;` （同步信号量，理发师用来叫顾客理发，“生产”了一个准备好的理发师）
    

#### 第三步：写出带条件的伪代码（套入 PV）

**理发师进程（Barber）：**

C

```
while (TRUE) {
    P(customers);   // 1. 等待顾客上门。没顾客就一直在这睡觉 (阻塞)
    
    P(mutex);       // 2. 准备叫顾客，先锁门看一眼等待人数
    waiting--;      // 3. 叫走了一个顾客，等待人数减 1
    V(barbers);     // 4. 告诉顾客：理发师准备好了，来坐理发椅吧
    V(mutex);       // 5. 解锁大门
    
    理发();         // 6. 开始剪头发 (耗时操作，放在锁外面！)
}
```

**顾客进程（Customer）：**

C

```
    P(mutex);       // 1. 进门，锁门，准备数椅子
    if (waiting < n) {  // 2. 椅子没坐满
        waiting++;      // 3. 找个椅子坐下，等待人数加 1
        V(customers);   // 4. 按铃！通知理发师有顾客来了 (如果理发师在睡觉，这会叫醒他)
        V(mutex);       // 5. 坐好了，解锁大门，让后面的顾客可以进来看椅子
        
        P(barbers);     // 6. 坐在椅子上等待理发师叫我
        被理发();       // 7. 享受理发
    } else {
        V(mutex);       // 2.1 椅子满了，解锁大门 (这步极容易忘！)
        离开();         // 2.2 走人
    }
```

#### 第四步：执行你的“第五步（死锁检查）”

你总结的“检查连续两个 P”在这里极其关键！我们来看看理发师的代码：

C

```
P(customers);
P(mutex);
```

**如果把这两个 P 换个顺序会怎样？**

假设理发师先 `P(mutex)`（把大门锁了），然后 `P(customers)`（发现没顾客，于是抱着大门的钥匙直接睡着了）。

这时顾客来了，想进门看椅子，执行 `P(mutex)`，发现大门被理发师从里面反锁了，进不去。

**结果：** 理发师在等顾客，顾客在门外进不来等理发师开门，死锁！

所以，你的死锁检查步骤非常灵验，**必须先等顾客（P (customers)），再拿大门锁（P (mutex)）。**

### 💡 核心总结

以后做统考题，只要看到：

1. **必须按顺序一环扣一环的** $\rightarrow$ 用传统的“同步互斥 P/V 夹击法”（如生产者消费者）。
    
2. **遇到“满了就走”、“空了就不干”这种傲娇条件的** $\rightarrow$ 立刻条件反射：**设一个全局整数变量（如 `count` 或 `waiting`），加一个 `mutex` 保护它，用 `if-else` 分支来决定是执行后续的 P/V 还是直接离开。**
