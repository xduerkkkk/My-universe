> [!abstract] 章节主线
> **进程提供资源容器，线程提供执行流；调度决定谁占用 CPU；同步互斥约束并发次序；死锁分析资源等待环。** 解题时始终区分“资源归谁、谁被调度、是否已定位/已阻塞、题目采用哪种实现模型”。

## 1. 程序、进程与线程

| 概念 | 性质 | 主要拥有内容 | 典型考点 |
|---|---|---|---|
| 程序 | 静态 | 指令与初始数据 | 同一程序可产生多个进程 |
| 进程 | 动态资源与控制实体 | 地址空间、资源、PCB | 状态转换、资源分配、隔离 |
| 线程 | 进程内执行流 | TCB、PC、寄存器、栈 | CPU 调度、并发执行 |

- 单处理器任一时刻普通进程运行态数量为 0 或 1；多处理器才可能有多个进程真正并行运行。
- 一个进程可通过装入/替换程序顺序执行不同程序；一个程序也可同时对应多个进程。
- 线程必须依附进程资源存在，但“线程是特殊进程”只在某些实现语境成立。

## 2. PCB、创建、终止与父子关系

### PCB 的核心内容

- **标识信息**：PID、父进程、用户标识。
- **处理机状态**：PC、PSW、通用寄存器、SP 等现场。
- **调度信息**：状态、优先级、队列指针、时间统计。
- **资源信息**：地址空间、打开文件、I/O 与会计信息。

### 创建与调度分工

**创建原语：建立进程并放入就绪队列；调度程序：从就绪队列选择并分配 CPU。**

创建常见来源：用户登录、作业/程序启动、OS 服务需要、现有进程请求创建子进程。

### 父子、孤儿与僵尸

- 子进程有独立 PCB/PID；fork 类语义通常以写时复制建立逻辑上独立的地址空间，并继承部分资源引用。
- 父子进程创建后独立调度。父先退出时，子进程在类 Unix 系统中通常被 PID 1 或子收割进程接管。
- 子进程已退出但父尚未读取退出状态时形成僵尸；孤儿仍可能继续运行，二者不同。

> [!warning] 校正
> - 正常终止不是“最后一行必然是 kill”，而是返回 main、调用 exit 或由运行时完成退出，最终由内核回收资源。
> - 最大进程数受 PID 空间、内核参数、用户限制和 PCB/内存资源共同约束，不能只写“主要由内存大小决定”。

## 3. 地址空间与线程资源

| 区域/状态 | 内容 | 同进程线程关系 |
|---|---|---|
| 代码段/只读区 | 指令、只读常量 | 共享 |
| 数据段/BSS | 全局、静态变量 | 共享 |
| 堆 | 动态分配对象 | 共享 |
| 用户栈 | 局部变量、参数、返回地址 | 每线程私有 |
| PC、通用寄存器、SP | 当前执行现场 | 每线程私有 |
| 页表/地址空间 | 虚拟到物理映射 | 同进程共享 |
| 打开文件等进程资源 | 内核资源引用 | 通常共享 |

- 同进程线程通信可直接读写共享内存，但必须同步；不同进程默认隔离，需要 IPC。
- 线程切换通常不更换页表基址，因此比跨进程切换轻；KLT 切换仍需内核调度。

### ULT 与 KLT

| 模型 | 谁维护线程 | 阻塞影响 | 多核并行 |
|---|---|---|---|
| 多对一 ULT | 用户态线程库 | 一个阻塞系统调用可能阻塞整个进程 | 不能让多个 ULT 同时占多个核 |
| 一对一 KLT | 内核 | 一个线程阻塞不必阻塞同进程其他线程 | 可以 |
| 多对多 | 用户线程映射到多个 KLT | 取决于映射与运行时 | 可以 |

TCB 的位置取决于模型：ULT 控制块由用户态运行时维护，KLT 控制块由内核维护。

## 4. 阻塞、挂起与进程通信

### 阻塞 vs 挂起

- **阻塞**：进程因等待事件不能运行，通常仍驻留内存。
- **挂起**：进程被剥夺内存驻留资格，相关内容可能换出外存；可与就绪/阻塞组合成挂起就绪、挂起阻塞。

### IPC 对比

| 方式 | 数据路径/特点 | 易错点 |
|---|---|---|
| 共享内存 | 建立共同映射后直接读写，数据交换通常最快 | 必须另行同步 |
| 消息传递 | 内核维护消息；可直接命名对方或通过信箱间接通信 | “直接/间接”通常特指消息传递 |
| 管道 | 内核缓冲的字节流，教材常按半双工 | 容量实现相关，不是固定一页；可有多个端点持有者 |
| 信号 | 传递事件/通知，信息量小 | 不是大数据通信方式 |

- 信号的实际递送常发生在内核准备返回用户态或调度目标进程运行时；默认动作可由内核完成，不能简化成“内核态绝不处理信号”。
- 低级通信原语强调同步控制和少量状态，高级 IPC 强调数据交换。

## 5. 调度基础与上下文

### 调度层次

- **高级调度**：作业接纳，决定哪些作业进入内存。
- **中级调度**：挂起与激活，调节内存中的多道程序度。
- **低级调度**：进程/线程调度，决定谁占用 CPU。

### 上下文

进程上下文不仅是 PC、SP 和页表基址，还包括全部必要寄存器、内核栈、地址空间、调度及资源控制信息。中断向量表是系统级结构，不属于某个进程上下文。

普通用户临界区中的进程可以被抢占，只是其他进程不能同时进入同一临界区；内核在修改关键调度数据结构时可能暂时禁止抢占或使用自旋锁。

## 6. 调度算法对比

| 算法   | 抢占性     | 主要目标/优点        | 主要问题               |
| ---- | ------- | -------------- | ------------------ |
| FCFS | 非抢占     | 简单、按到达顺序、通常不饥饿 | 护航效应，短作业响应差        |
| SJF  | 非抢占     | 已知服务时间时平均等待较小  | 长作业可能饥饿，需估计时间      |
| SRTF | 抢占      | SJF 的抢占版本      | 切换多，长作业可能饥饿        |
| 优先级  | 可抢占或非抢占 | 体现重要性/实时需求     | 低优先级饥饿，可用老化        |
| RR   | 抢占      | 公平、交互响应好       | 时间片过小开销大，过大趋近 FCFS |
| HRRN | 通常非抢占   | 兼顾短作业与等待时间     | 需计算响应比             |
| MLFQ | 通常抢占    | 自适应短任务与交互任务    | 结构复杂、切换开销大；需防低层饥饿  |

### 三个常见边界

- I/O 型常有短 CPU 脉冲，但不等于定义上的短作业。
- 实时系统常用抢占式优先级/截止期调度，但是否“必然”抢占取决于题目模型。
- 作业是用户任务单位，进程是执行实体；进程并不只属于分时系统。

### 甘特图计算模板

1. 写到达时间、服务时间、优先级和时间片。
2. 标明抢占规则及相同时的决胜规则。
3. 每个事件点更新就绪队列：到达、完成、时间片用完、被抢占。
4. 画运行区间，再算完成、周转、带权周转和等待时间。
5. 把题目给出的调度/切换开销单独插入时间轴，不能漏算。

## 7. 同步、互斥与临界区

- **临界资源**：一次只允许一个执行流使用的共享资源。
- **临界区**：访问临界资源的代码段。
- **同步**：协调执行先后次序；**互斥**：限制同时进入。

### 四项原则

| 原则   | 含义               | 违反后的典型问题  |
| ---- | ---------------- | --------- |
| 空闲让进 | 空闲且有人申请时允许一个进入   | 无故阻塞、可能死锁 |
| 忙则等待 | 已有人进入时其他人不能进入    | 互斥失效      |
| 有限等待 | 等待有上界            | 饥饿        |
| 让权等待 | 获得资格但不能进入者让出 CPU | 否则忙等、效率低  |

### 经典实现

| 方法 | 互斥安全 | 公平/有限等待 | 让权等待 | 核心缺陷 |
|---|---|---|---|---|
| 单标志法 | 是 | 有轮换限制 | 否 | 对方不申请时仍挡住自己，违背空闲让进 |
| 双标志先检查 | 否 | — | 否 | 可能同时进入 |
| 双标志后检查 | 是 | 否 | 否 | 双方都声明后互等，违背空闲让进并可能无限等待 |
| Peterson | 是 | 两进程模型下是 | 否 | 忙等 |
| TSL/Swap | 是 | 通常不保证 | 否 | 自旋且可能饥饿 |
| 整型信号量 | 可实现 | 取决于协议 | 否 | 忙等 |
| 记录型信号量 | 可实现 | 取决于等待队列 | 是 | 需内核 block/wakeup 支持 |

## 8. 信号量与生产者—消费者

### 记录型信号量语义

- P(S)：S--；若 S < 0，则把进程加入等待队列并 block。
- V(S)：S++；若 S ≤ 0，则从等待队列唤醒一个进程。
- S > 0 表示可用资源数；S < 0 时 -S 通常表示等待者数量。

### 同步模板

若 A 必须先于 B：S 初值 0，A 后 V(S)，B 前 P(S)。

### 有界缓冲区

容量为 N：

- mutex = 1：缓冲区互斥锁。
- empty = N：空位数量。
- full = 0：产品数量。

生产者：P(empty) → P(mutex) → 放入 → V(mutex) → V(full)。  
消费者：P(full) → P(mutex) → 取出 → V(mutex) → V(empty)。

- “缓冲区不可用”通常指互斥锁被占用；“缓冲区空”指 full = 0，是不同维度。
- V(full)/V(empty)负责异类同步唤醒；V(mutex)可唤醒任何等待该锁的生产者或消费者。

## 9. 管程与可重入代码

### 管程

管程把共享数据、操作过程和初始化封装在模块中，并自动保证管程过程互斥执行；条件变量负责等待特定条件。

- condition wait：释放管程互斥并阻塞。
- condition signal：唤醒已在该条件上等待的执行流；没有等待者时通常不累计计数。
- 被唤醒者立即运行还是进入就绪队列，取决于 Hoare/Mesa 等语义。

### 可重入代码

可被多个执行流同时或嵌套调用而互不干扰。通常只使用参数、局部自动变量和受保护/只读共享状态，不依赖未同步的共享可写全局或静态变量。

## 10. 死锁

### 四个必要条件

1. 互斥使用。
2. 请求并保持。
3. 不可剥夺。
4. 循环等待。

预防死锁必须破坏至少一个条件；提高优先级不等于破坏条件。

> [!warning] 校正
> 系统资源不足会增加争用并可能促成死锁，但它既不是死锁的充分条件，也不能只归为“饥饿原因”。是否死锁还取决于分配与等待结构。

### 处理方法

| 方法 | 核心思想 |
|---|---|
| 预防 | 静态破坏四条件之一 |
| 避免 | 每次分配前检查是否保持安全状态，如银行家算法 |
| 检测与解除 | 允许进入不安全状态，周期检测并撤销/剥夺 |
| 忽略 | 假设概率低，由人工或重启处理 |

### 两个公式/判定

- 单类资源，m 个进程、每个最多需 n 个：**m(n-1)+1** 个实例可保证至少有一个进程完成。仅适用于该经典模型。
- 死锁定理：不断消去当前可满足并完成的进程；若最终仍有进程不可消去，则剩余集合构成死锁。

## 11. 易混概念与绝对词检查

- **孤儿 vs 僵尸**：父先退出仍运行 vs 子已退出未回收。
- **阻塞 vs 挂起**：等待事件 vs 被换出/暂停驻留。
- **ULT 阻塞 vs KLT 阻塞**：内核不可见的多对一模型才容易“一阻塞全阻塞”。
- **SJF vs I/O 型**：服务时间短 vs CPU 脉冲通常短。
- **临界资源 vs 临界区**：共享对象 vs 访问它的代码。
- **互斥 vs 同步**：不能同时做 vs 必须按顺序做。
- **V 后 S ≤ 0**：说明仍有或刚好有等待者，并不表示出现空闲资源。
- **管程 signal vs 信号量 V**：条件通知通常不累计，资源计数会累计。
- **“一定不饥饿/一定抢占/固定一页/只能一个读者”**：均需检查算法和实现条件。
