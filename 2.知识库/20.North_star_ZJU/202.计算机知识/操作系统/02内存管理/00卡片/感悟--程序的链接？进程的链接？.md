先有 PCB（内核登记），操作系统才会允许把程序和数据装入内存（用户区）。

编译是将程序和数据，翻译成机器语言，此时各个模块仍然独立，每个独立的模块都有从 0 开始的逻辑地址。

接着链接，链接是把一堆散装的目标模块，以及它们调用的库函数（比如 `printf`）拼接在一起，编排成一个统一的、连续的**逻辑地址空间**。

对于<span style="background:#b1ffff">静态链接</span>，到“链接”结束为止，你的程序都还静静地躺在**磁盘（外存）**里，和内存、CPU、进程没有半毛钱关系。
然后再看装入时，以什么方式把这一整坨装入进去


若采用<span style="background:#b1ffff">装入时动态链接</span>，就是编译后的各程序模块还躺在磁盘，装入时碰到哪个模块链接哪个模块（难道装入不是全部装入吗？这不是要形成一个完整进程吗），然后再装入。
此时也不一定有程序运行
它的实际工作流程是这样的：

1. **编译链接阶段（静态）**：编译时，你的主程序发现需要用到 `liba.dll`。静态链接器不会把 `liba.dll` 的代码拷进你的可执行文件，而只是在可执行文件里写了一句标记：“我启动时需要 `liba.dll`，里面有个函数叫 `foo`”。此时它躺在磁盘里。
    
2. **装入阶段（动态）**：当你运行程序时，操作系统的装入器（Loader）出场：
    
    - 先把你的**主程序模块**装入内存。
        
    - 接着装入器检查主程序，发现上面写着需要 `liba.dll`。
        
    - 装入器立刻去磁盘上把 `liba.dll` 找出来，也**装入到内存**中。
        
    - **关键的链接发生在这里**：装入器把主程序里所有调用 `foo` 的虚地址，修改为 `liba.dll` 在内存中的实际地址。
它是“全部”装入的。在**程序正式运行之前**，主程序和它依赖的动态链接库都已经躺在内存里了，链接也完成了。此时，它已经是一个**完整的进程**了。
**那它和静态链接有什么区别？** 区别在于**磁盘空间的节省和共享**。如果有 10 个程序都用到了 `liba.dll`，静态链接会导致磁盘上有 10 份重复的代码；而装入时动态链接，磁盘上只有 1 份，只是在每个程序**各自装入内存时**，才分别去和这同一份库对接。



<span style="background:#b1ffff">运行时链接</span>，是程序运行时再链接+装入
如果用户一辈子不点那个功能，那个模块就**永远不会被链接，也永远不会被装入内存**。

| **链接方式**    | **谁来负责链接**     | **什么时候链接**      | **什么时候装入物理内存**    | **优点**         |
| ----------- | -------------- | --------------- | ----------------- | -------------- |
| **静态链接**    | 静态链接器 (Linker) | 程序运行前（在磁盘上就搞定了） | 程序启动时，整体一次性装入     | 运行速度最快，不依赖外部环境 |
| **装入时动态链接** | 装入器 (Loader)   | 程序启动时（运行前）      | 程序启动时，主程序和依赖库一起装入 | 节省磁盘空间，方便库的升级  |
| **运行时动态链接** | 运行中的程序+操作系统    | 程序运行中（用到时才链接）   | 运行中用到某行代码时，才动态装入  | 极大地节省内存，支持插件扩展 |
|             |                |                 |                   |                |




那现在我就在想，装入有三种方式，链接有三种方式，程序要链接+装入，那是不是简短的 3×3 种搭配？似乎不是，要根据含义。
绝对装入，是要求编译后的逻辑地址就是物理地址，然后直接装入... 好像三种链接都可以配啊。可重定位装入.. 装入时确定物理地址，而且装入一定是在一片连续的内存空间。额我感觉和绝对装入可以说几乎没区别了，只是说绝对装入因为单道程序，逻辑地址和物理地址一样罢了。所以叫静态装入比较合适吧，不知道为啥叫可重定位。动态重定位是，编译后的东西已经装入了，但不管地址是多少。运行时使用重定位寄存器当场算物理地址

- **绝对装入**：在**编译时**物理地址就定死了，换个内存位置就无法运行。
    
- **可重定位装入**：在**编译时**是未知的，在**装入时**可以根据内存空闲情况，**重新确定（定位）**它的物理起点。只是因为装入后所有代码都被改写死了，所以它叫“静态”重定位。 

### 1. 绝对装入：只能配“静态链接”

- **为什么？** 绝对装入要求在编译/链接阶段就必须把所有的物理地址锁死。如果你用动态链接（不管是装入时还是运行时），意味着有些代码还在别的 DLL 里，地址根本没法锁死。
    
- **结论**：绝对装入只能和静态编译/链接玩。在现代通用操作系统中，这种方式已经绝迹，只有在极简单的嵌入式单片机里还能看到。
    

### 2. 静态可重定位装入：能配“静态链接”和“装入时动态链接”

- **配静态链接**：最经典的传统组合。打包好的完整 exe 整体塞进内存一片连续区域，装入时批量修改地址。
    
- **配装入时动态链接**：这就是你上一轮提到的场景。主程序和依赖的 `a.dll` 在装入内存时，装入器把它们一股脑全塞进内存，并在这个时候**一边做链接，一边静态修改地址**。
    
- **不能配运行时动态链接**：因为静态可重定位要求“装入时地址就必须全部改好且定死”。如果运行时突然冒出来一个新模块，这个老实的装入器根本没办法在运行中动态给它挪地方和改地址。
    

### 3. 动态重定位装入：天生海王，全都能配（现代操作系统的基石）

动态重定位引入了**硬件（重定位寄存器 / MMU）**。程序在内存里爱怎么躺怎么躺，地址不用在装入时修改，而是 CPU 执行到哪一行，当场用寄存器去加。

- **配静态链接**：没问题，整坨程序塞进内存，寄存器存个基地址就能跑。
    
- **配装入时动态链接**：没问题。
    
- **配运行时动态链接（绝配！）**：这才是现代操作系统的王道组合（比如 Linux 运行 ELF 文件）。程序跑着跑着，动态加载了一个库，MMU 只需要在页表里为这个新库划一片虚拟地址映射，CPU 就能无缝访问，不需要停下来改写之前的任何代码。


| **链接 \ 装入方式** | **绝对装入 (Compile-time)** | **静态可重定位装入 (Load-time)** | **动态重定位装入 (Execution-time)** |
| ------------- | ----------------------- | ------------------------ | ---------------------------- |
| **静态链接**      | ✅ 可以（古代单道程序）            | ✅ 可以（早期多道程序）             | ✅ 可以（现代运行纯静态编译程序）            |
| **装入时动态链接**   | ❌ 冲突（地址无法预先锁死）          | ✅ 可以（启动时打包加载）            | ✅ 可以                         |
| **运行时动态链接**   | ❌ 冲突                    | ❌ 冲突（装入后无法再动地址）          | ✅ **最优解（现代操作系统的标准形态）**       |


| **分配方式 \ 装入方式**                            | **绝对装入**                           | **静态可重定位装入**                               | **动态重定位装入**                               |
| ------------------------------------------ | ---------------------------------- | ------------------------------------------ | ----------------------------------------- |
| **连续分配**<br><br>  <br><br>（单一连续/固定分区/动态分区） | ✅ 可以<br><br>  <br><br>（古代单板机/单道程序） | ✅ 可以<br><br>  <br><br>（多道程序早期，如早期的 IBM 系统） | ✅ 可以<br><br>  <br><br>（通过基址/限长寄存器实现紧凑和移动） |
| **非连续分配**<br><br>  <br><br>（页式 / 段式 / 段页式） | ❌ **绝对冲突**                         | ❌ **绝对冲突**                                 | ✅ **天作之合**<br><br>  <br><br>（现代操作系统的标准配置） |


我们可以把这堆乱七八糟的概念，划分为三个时代。每个时代都包含了一套【分配 + 链接 + 装入 + 硬件】的专属全家桶：

### 阶段一：古代——绝对僵硬的单道程序时代

- **内存分配**：**单一连续分配**（整个内存只有你和操作系统，你独占全场）。
    
- **链接方式**：**静态链接**（把所有模块死死打包成一个文件）。
    
- **装入方式**：**绝对装入**（在编译链接时，连具体的物理地址都写死了）。
    
- **硬件工具**：**无**（不需要任何地址转换机构，因为代码里的地址就是真实的物理地址）。
    

### 阶段二：近代——整体平移的多道程序时代

- **内存分配**：**连续分配（固定分区 / 动态分区）**（内存可以跑多个程序了，但每个程序必须分到一整块连续的空间）。
    
- **链接方式**：静态链接或 **装入时动态链接**。
    
- **装入方式**：**静态可重定位装入**（编译时不知道住哪，装入内存的一瞬间，把地址整体加一个基准值，然后写死）。
    
- **硬件工具**：**重定位寄存器（Relocation Register，也叫基址寄存器）**。
    
    - _它在这里怎么用？_ 此时如果操作系统要支持“内存紧凑”（把程序在内存里整体挪个位置），就需要这个寄存器。挪动后，寄存器换个新开头，程序就能继续跑。
        

### 阶段三：现代——粉碎多变的虚拟内存时代（王道）

- **内存分配**：**非连续分配（页式 / 段式 / 段页式）**（程序被操作系统撕得粉碎，离散地塞进内存的各个角落）。
    
- **链接方式**：**运行时动态链接**（程序跑着跑着，用到哪个库再去拿哪个库）。
    
- **装入方式**：**动态重定位装入**（装入时地址完全不改，纯靠运行时当场算）。
    
- **硬件工具**：**地址转换机构（MMU + 页表/段表硬件）**。
    
    - _它在这里怎么用？_ 此时单靠一个“重定位寄存器”已经搞不定了，因为程序是不连续的！必须升级为复杂的“地址转换机构”，每次 CPU 发出逻辑地址，硬件自动去查页表/段表，当场算出被撕碎的每一页在物理内存的什么地方。
        

## 🛠️ 核心关键词的“岗位职责”

你提到的那几个硬件关键词，它们不是孤立的，而是根据上面的时代需求诞生出来的**工具**：

### 1. 重定位寄存器（Base Register）

- **段位**：初级硬件。
    
- **职责**：只负责“一整坨连续代码的整体平移”。
    
- **工作原理**：里面只存一个数（物理起始地址）。
    
- **公式**：$\text{物理地址} = \text{重定位寄存器} + \text{逻辑地址}$。
    

### 2. 地址转换机构（Address Translation Mechanism / MMU）

- **段位**：高级硬件。
    
- **职责**：负责“被扯碎的代码（非连续分配）的动态拼装”。
    
- **工作原理**：它不再只存一个数字，它包含了查页表、查快表（TLB）、处理缺页异常等一系列复杂的硬件电路。
    
- **公式**：$\text{逻辑地址} \xrightarrow{\text{拆分为页号+偏移}} \text{硬件自动查页表} \rightarrow \text{拼接出物理地址}$。
-
