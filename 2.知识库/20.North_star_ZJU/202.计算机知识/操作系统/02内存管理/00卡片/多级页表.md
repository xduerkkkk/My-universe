
# 1. 二级页表具体例子

设定：32 位虚拟地址，页大小 4KB，每个页表项 4B。

先算拆分：

- 页大小 4KB = 2^12，所以**页内偏移 12 位**。
- 剩下 32 − 12 = 20 位给页号。
- 一页能装多少个页表项？4KB / 4B = 1024 = 2^10 项，所以每级页号占 **10 位**。
- 20 位页号拆成：一级页号 10 位 + 二级页号 10 位。

Text

| 一级页号 (10 位) | 二级页号 (10 位) | 页内偏移 (12 位) |

     31~22           21~12            11~0

具体转换，假设虚拟地址 = `0x00403008`：

先写成二进制并按 10/10/12 切分：

Text

0x00403008 = 0000 0000 0100 0000 0011 0000 0000 1000

一级页号 = 0000000001 = 1

二级页号 = 0000000011 = 3

页内偏移 = 000000001000 = 8 (0x008)

查找过程：

1. 页目录基址在 CR3，设 CR3 = 0x1000。取第 1 项：访问物理地址 `0x1000 + 1×4 = 0x1004`，读出内容假设 = 0x5000（这是二级页表的物理基址）。
2. 到二级页表 0x5000，取第 3 项：访问 `0x5000 + 3×4 = 0x500C`，读出内容假设 = 0x8000（这是最终页框的物理基址，页框号对应）。
3. 拼接：物理地址 = 页框基址 + 页内偏移 = `0x8000 + 0x008 = 0x8008`。

整个过程 2 次查表访存 + 1 次真正访存 = 3 次访存（无 TLB 命中时）。

为什么要二级：单级页表要 2^20 = 1M 个表项，占 4MB 连续内存，且不管进程用不用都得建。二级页表下，只有实际用到的二级页表才分配，没用到的页目录项置空，节省空间——代价是多一次访存。

沿用之前的例子：32 位虚拟地址，页大小 4KB，页表项 4B。

# 单级页表的空间问题

单级页表就是一张表，用虚页号直接做下标去查。

虚页号有多少个？32 位地址，页内偏移 12 位，剩 20 位是页号，所以共 2^20 = 1M 个虚页，对应页表**必须有 1M 个表项**。

每项 4B，整张表 = 1M × 4B = **4MB**。

三个关键约束：

1. **必须连续存放**。因为查表是"页表基址 + 虚页号 × 项大小"直接算偏移定位的，这要求所有表项在物理内存里连续排列。于是要一块 4MB 的连续物理内存。

2. **必须全部建立**。虽然表项内容可以先标成无效（有效位=0），但这 1M 个表项的**存储空间**得先占着——因为你不知道进程将来会访问哪个虚页，硬件按下标定位时，任何一个下标都得有对应的物理位置存在。不能"用到再插进去"，因为下标定位不允许中间有空洞。

3. **每个进程一张**。多进程时 4MB × 进程数，开销叠加。

核心矛盾：一个进程通常只用地址空间的一小部分（比如几 MB 代码 + 几 MB 数据 + 栈），可能只涉及几百个虚页，但页表却要为全部 1M 个虚页预留空间，绝大部分表项是无效的，纯浪费。

# 二级页表怎么省

把 20 位页号拆成 10 位一级页号 + 10 位二级页号：

- 页目录（一级）：2^10 = 1024 项，每项 4B，共 4KB，正好一页。
- 每张二级页表：2^10 = 1024 项，每项 4B，共 4KB，也是一页。
- 一个进程理论上最多 1024 张二级页表（覆盖满则 1024 × 4KB = 4MB，加页目录 4KB，比单级还多一点——所以二级是**最坏情况不省，常见情况才省**）。

省在哪：**二级页表按需分配**。

关键机制：页目录项里有个有效位。如果某个页目录项对应的那 1024 个虚页进程**一个都没用到**，这个页目录项就置无效，**根本不分配对应的二级页表**，那 4KB 内存不占。

具体算笔账。假设一个进程实际只用：
- 代码 + 数据：低地址区，约 8MB
- 栈：高地址区，约几百 KB

8MB / 4KB = 2048 个虚页，跨 2048/1024 = 2 张二级页表。
栈那块再算 1 张二级页表。

那么这个进程需要的页表内存：
```
页目录：        1 × 4KB = 4KB
二级页表：      3 × 4KB = 12KB
合计：          16KB
```

对比单级页表固定的 4MB，二级只用了 16KB。省的原因是：地址空间里**大片没用到的连续区域**，对应的页目录项直接置空，那些二级页表压根不建。单级页表做不到这点，因为它是一整块连续数组，中间不能留空洞。

# 代价

1. **多一次访存**。单级查表 1 次访存，二级要先查页目录（1 次）再查二级页表（1 次），共 2 次，加上最终数据访问，无 TLB 时总共 3 次访存。级数越多访存越多，N 级就是 N+1 次。这就是为什么要 TLB——命中时直接跳过所有查表。

2. **最坏情况不省反增**。如果进程把整个地址空间铺满都用到，二级需要 4KB (页目录) + 1024×4KB (全部二级表) = 4MB + 4KB，比单级的 4MB 还多出一个页目录。二级页表的收益完全来自"稀疏使用"——地址空间大片空着。

# 一句话总结机制差异

单级页表是"一整块连续数组，下标直达，必须全建"；二级页表是"目录 + 按需分配的子表，允许目录项为空从而跳过大片未用空间"。省空间的本质是把"必须连续、必须全建"的约束，通过分级打散成"每级一页、子表可缺省"。


# 页表项内容
我们继续以题目中 **32 位系统、4KB 页大小、4 字节（32 bit）页表项** 的经典架构（即经典的 x86 32 位架构）为例。

正如前面所说，这 32 个 bit 被分成了两部分：**高 20 位**用于存放物理页框号（PFN），**低 12 位**用于存放控制标志。

下面是这 32 位（bit 31 到 bit 0）的具体剖析图：

```text
31                                              12 11  9 8 7 6 5 4 3 2 1 0
+-------------------------------------------------+-----+-+-+-+-+-+-+-+-+-+
|           物理页框号 (PFN) / 基地址的高20位           | OS用|G|P|D|A|C|W|U|R|P|
+-------------------------------------------------+-----+-+-+-+-+-+-+-+-+-+
                                                          | | | | | | | | |
               操作系统自定义使用 (Avail) ------------------+ | | | | | | | |
                                全局页位 (Global) ----------+ | | | | | | |
                                  页大小 (Page Size) ---------+ | | | | | |
                                      脏位 (Dirty) -------------+ | | | | |
                                    访问位 (Accessed) ------------+ | | | |
                               禁止缓存位 (Cache Disable) ----------+ | | |
                             直写策略位 (Write-Through) --------------+ | |
                            用户/内核位 (User/Supervisor) --------------+ |
                                读/写位 (Read/Write) -------------------+ |
                                  存在位 (Present/Valid) -----------------+
```

对于学习操作系统来说，不需要死记硬背每一个，但有 **5 个核心标志位** 是极其重要的，它们是操作系统实现虚拟内存、内存保护和页面置换的“基石”：

### 🌟 最核心的 5 个标志位

#### 1. Bit 0: P (Present / Valid) - 存在位 / 有效位
*   **含义：** 标记这个页表项指向的物理页（或二级页表）**当前是否真正在物理内存中**。
*   **1 = 在内存中：** CPU 可以直接去读写。
*   **0 = 不在内存中：** 可能是这个虚拟地址还没被分配，也可能是内存不够，操作系统把这一页数据**“踢”到了硬盘上（Swap / 虚拟内存）**。
*   **魔法效果：** 如果 CPU 查表时发现 P=0，就会触发一个鼎鼎大名的硬件异常——**缺页中断（Page Fault）**。这时，操作系统会暂停当前程序，去硬盘把这页数据调入内存，把 P 改为 1，然后让程序继续执行。程序对此毫无察觉。

#### 2. Bit 1: R/W (Read / Write) - 读写位
*   **含义：** 决定这一页内存的访问权限。
*   **0 = 只读（Read-Only）：** 只能读不能写。
*   **1 = 可读写（Read/Write）：** 既能读也能写。
*   **魔法效果：** 你的代码段（存放程序指令的地方）通常会被标记为 0（只读）。如果程序里有 Bug，或者黑客试图篡改你的代码，CPU 一看 R/W 是 0，直接触发异常（段错误 Segfault），把程序杀掉，保护了系统安全。

#### 3. Bit 2: U/S (User / Supervisor) - 用户/特权位
*   **含义：** 决定谁有资格访问这一页。
*   **1 = 用户态（User）：** 普通应用程序（如浏览器、微信）可以访问。
*   **0 = 内核态（Supervisor）：** 只有操作系统内核（特权级）才能访问。
*   **魔法效果：** 为什么你的普通程序不能直接去读取操作系统的密码表或直接控制硬件？因为那些关键内存页的 U/S 位都被设为了 0。普通程序一碰，CPU 就报警。

#### 4. Bit 5: A (Accessed) - 访问位
*   **含义：** 记录这一页最近**有没有被 CPU 读过或写过**。
*   **机制：** 只要 CPU 访问了这页内存，硬件就会自动把这个位设为 `1`。
*   **魔法效果：** 当物理内存快满了，操作系统需要挑选一页踢到硬盘上（页面置换）。踢谁呢？操作系统会定期去扫这些 A 位，如果发现某页 A=0，说明好久没人用了，就优先把它踢走（这就是 **LRU 页面置换算法** 的底层硬件支持）。

#### 5. Bit 6: D (Dirty) - 脏位 (主要在二级页表项中生效)
*   **含义：** 记录这一页自从加载到内存后，**有没有被修改过（写过）**。
*   **0 = 干净：** 内存里的数据和硬盘上的一模一样。
*   **1 = 脏的：** 程序往这一页写了新数据，和硬盘上的不一致了。
*   **魔法效果：** 还是在内存满了要踢人的时候。如果一页是“干净”的（D=0），操作系统直接把它丢弃就行，因为硬盘上有一份一样的。但如果是“脏”的（D=1），操作系统在丢弃前，**必须先把它写回硬盘**。D 位极大地优化了磁盘 I/O 性能。

---

### 其他几个辅助位（简单了解即可）

*   **Bit 3 (PWT) & Bit 4 (PCD)：** 和 CPU 内部的高速缓存（Cache）有关。决定这页数据是不是不允许被缓存到 L1/L2 Cache 中，或者决定缓存的写入策略。常用于操作系统控制显存等特殊硬件映射的内存。
*   **Bit 7 (PS - Page Size)：** 在一级页表项里，如果设为 1，表示这个表项不指向二级页表了，而是直接指向一个 **4MB 的超大物理页（Huge Page）**。这在大型数据库等需要连续大内存的场景非常有用。
*   **Bit 8 (G - Global)：** 全局位。表示这个页是所有进程共享的（比如操作系统内核代码）。切换不同进程时，不需要把这个页的缓存（TLB）清空，提高效率。
*   **Bit 9~11 (Available)：** 留白。硬件不去管这 3 个 bit，操作系统想拿它们存什么就存什么，通常用来记录一些页面置换的自定义状态。

**总结：**
这 12 个 bit 就像是这 4KB 物理内存的**“电子身份证”和“门禁卡”**。CPU 里的 MMU 每次访问内存，不仅要翻译地址，还要同时检查这些标志位，一旦发现违规（没权限、越界、不在内存），立刻阻止并向操作系统报告。这就是现代操作系统能做到多任务互不干扰、安全稳定的根本硬件保证。
