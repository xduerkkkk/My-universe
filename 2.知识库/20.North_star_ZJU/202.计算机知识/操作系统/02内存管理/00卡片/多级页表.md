
# 1. 二级页表具体例子

设定：32 位虚拟地址，页大小 4KB，每个页表项 4B。

先算拆分：

- 页大小 4KB = 2^12，所以**页内偏移 12 位**。
- 剩下 32 − 12 = 20 位给页号。
- 一页能装多少个页表项？4KB / 4B = 1024 = 2^10 项，所以每级页号占 **10 位**。
- 20 位页号拆成：一级页号 10 位 + 二级页号 10 位。

Text

| 一级页号 (10 位) | 二级页号 (10 位) | 页内偏移 (12 位) |

     31~22           21~12            11~0

具体转换，假设虚拟地址 = `0x00403008`：

先写成二进制并按 10/10/12 切分：

Text

0x00403008 = 0000 0000 0100 0000 0011 0000 0000 1000

一级页号 = 0000000001 = 1

二级页号 = 0000000011 = 3

页内偏移 = 000000001000 = 8 (0x008)

查找过程：

1. 页目录基址在 CR3，设 CR3 = 0x1000。取第 1 项：访问物理地址 `0x1000 + 1×4 = 0x1004`，读出内容假设 = 0x5000（这是二级页表的物理基址）。
2. 到二级页表 0x5000，取第 3 项：访问 `0x5000 + 3×4 = 0x500C`，读出内容假设 = 0x8000（这是最终页框的物理基址，页框号对应）。
3. 拼接：物理地址 = 页框基址 + 页内偏移 = `0x8000 + 0x008 = 0x8008`。

整个过程 2 次查表访存 + 1 次真正访存 = 3 次访存（无 TLB 命中时）。

为什么要二级：单级页表要 2^20 = 1M 个表项，占 4MB 连续内存，且不管进程用不用都得建。二级页表下，只有实际用到的二级页表才分配，没用到的页目录项置空，节省空间——代价是多一次访存。

沿用之前的例子：32 位虚拟地址，页大小 4KB，页表项 4B。

# 单级页表的空间问题

单级页表就是一张表，用虚页号直接做下标去查。

虚页号有多少个？32 位地址，页内偏移 12 位，剩 20 位是页号，所以共 2^20 = 1M 个虚页，对应页表**必须有 1M 个表项**。

每项 4B，整张表 = 1M × 4B = **4MB**。

三个关键约束：

1. **必须连续存放**。因为查表是"页表基址 + 虚页号 × 项大小"直接算偏移定位的，这要求所有表项在物理内存里连续排列。于是要一块 4MB 的连续物理内存。

2. **必须全部建立**。虽然表项内容可以先标成无效（有效位=0），但这 1M 个表项的**存储空间**得先占着——因为你不知道进程将来会访问哪个虚页，硬件按下标定位时，任何一个下标都得有对应的物理位置存在。不能"用到再插进去"，因为下标定位不允许中间有空洞。

3. **每个进程一张**。多进程时 4MB × 进程数，开销叠加。

核心矛盾：一个进程通常只用地址空间的一小部分（比如几 MB 代码 + 几 MB 数据 + 栈），可能只涉及几百个虚页，但页表却要为全部 1M 个虚页预留空间，绝大部分表项是无效的，纯浪费。

# 二级页表怎么省

把 20 位页号拆成 10 位一级页号 + 10 位二级页号：

- 页目录（一级）：2^10 = 1024 项，每项 4B，共 4KB，正好一页。
- 每张二级页表：2^10 = 1024 项，每项 4B，共 4KB，也是一页。
- 一个进程理论上最多 1024 张二级页表（覆盖满则 1024 × 4KB = 4MB，加页目录 4KB，比单级还多一点——所以二级是**最坏情况不省，常见情况才省**）。

省在哪：**二级页表按需分配**。

关键机制：页目录项里有个有效位。如果某个页目录项对应的那 1024 个虚页进程**一个都没用到**，这个页目录项就置无效，**根本不分配对应的二级页表**，那 4KB 内存不占。

具体算笔账。假设一个进程实际只用：
- 代码 + 数据：低地址区，约 8MB
- 栈：高地址区，约几百 KB

8MB / 4KB = 2048 个虚页，跨 2048/1024 = 2 张二级页表。
栈那块再算 1 张二级页表。

那么这个进程需要的页表内存：
```
页目录：        1 × 4KB = 4KB
二级页表：      3 × 4KB = 12KB
合计：          16KB
```

对比单级页表固定的 4MB，二级只用了 16KB。省的原因是：地址空间里**大片没用到的连续区域**，对应的页目录项直接置空，那些二级页表压根不建。单级页表做不到这点，因为它是一整块连续数组，中间不能留空洞。

# 代价

1. **多一次访存**。单级查表 1 次访存，二级要先查页目录（1 次）再查二级页表（1 次），共 2 次，加上最终数据访问，无 TLB 时总共 3 次访存。级数越多访存越多，N 级就是 N+1 次。这就是为什么要 TLB——命中时直接跳过所有查表。

2. **最坏情况不省反增**。如果进程把整个地址空间铺满都用到，二级需要 4KB (页目录) + 1024×4KB (全部二级表) = 4MB + 4KB，比单级的 4MB 还多出一个页目录。二级页表的收益完全来自"稀疏使用"——地址空间大片空着。

# 一句话总结机制差异

单级页表是"一整块连续数组，下标直达，必须全建"；二级页表是"目录 + 按需分配的子表，允许目录项为空从而跳过大片未用空间"。省空间的本质是把"必须连续、必须全建"的约束，通过分级打散成"每级一页、子表可缺省"。
