> [!decision] 2026-11-02：KK 已决定选择记忆方向

> **指导教师：张旭**
> 选择动机：意识到记忆可以作为 personalized agent（个性化智能体）的研究入口；对“Agent 如何持续理解用户”有明确兴趣，而不只是因为已有经验、比较稳妥。
> 这是 KK 的选题决定；学校选题系统登记、导师确认与最终研究方案仍待落实。

**兴趣主线：个性化智能体。毕设切口：记忆写入阶段的信息筛选。**

不必把毕设扩成完整个人助理，也不必以“个性化”替换任务书规定的长对话问答实验。

一个可与导师讨论的问题是：

> **在有限记忆预算下，怎样过滤重复交互，同时保留用户偏好、事实和决定的变化，使后续问答更符合用户当前状态？**

这是研究假设与范围建议，不是已验证的方法，也不是已确认创新点。

> 记忆机制能够帮助大语言模型智能体保存历史交互中的事实、偏好和任务经验，并通过检索为后续决策提供支持，是实现连续交互的重要基础。随着交互过程持续进行，记忆数量不断增加，其中可能出现重复、过时或与后续任务关联较弱的信息。直接保留全部记忆不仅增加存储和检索开销，还可能引入无关内容，影响回答质量。因此，需要在信息保留与资源消耗之间进行合理权衡。本课题旨在复现典型的智能体记忆管理方法，改进记忆写入阶段的筛选策略，研究记忆规模、检索效率与问答表现之间的关系。

> （2）复现典型的智能体记忆管理方法，并在公开长对话数据集上完成问答实验；
> （3）改进记忆写入阶段的筛选策略，分析记忆规模、检索效率与问答表现之间的关系。

## 四、为什么这条兴趣线与写入筛选有关

PersonaMem（COLM 2025）直接围绕用户画像与偏好的动态变化，以及基于当前状态的个性化响应进行评测，说明“用户信息会变化”可以成为明确研究对象，而不仅是一个产品口号。[^personamem]

LongMemEval（ICLR 2025）包含时间推理、知识更新等能力，能为检查筛选是否误删变化提供评测思路，但不能等同于完整个性化评测。[^longmemeval]

### 用今天的真实对话理解问题

今天较早时，KK 说记忆做过、有一点乏味，正在比较错误恢复与性能优化。中午又明确表示：想到 personalized agent 后产生兴趣，并决定选择记忆。

如果只保存“KK 觉得记忆乏味”，会错过新决定；如果把后一句当成与旧讨论相近的重复内容而过滤，也会出错。

建议区分：

| 记录 | 在当前决策中的地位 |
| --- | --- |
| 做过 Agent / LLM 相关项目 | 背景经历 |
| 早先对重复做记忆题感到乏味 | 决策过程中的历史感受，不应固定为长期标签 |
| 因 personalized agent 产生新兴趣 | 新动机 |
| 决定选记忆方向 | 当前明确决定；与学校是否登记是两回事 |

这是一个说明任务的案例，不是正式测试样本，也不能仅靠这一个例子证明方法有效。

### 拟优先研究的一个区别

**内容相似，不一定意味着没有新增信息。** 建议重点区分：

1. 同一信息的重复表达。
2. 状态或偏好的明确更新。
3. 只有在特定场景生效的临时要求。

不要自动把“今天想看简短回答”覆盖成“用户永远只喜欢简短回答”；也不要让旧偏好覆盖当前明确要求。将这些作为待测试的设计要求，而非预先声称系统已经具备的能力。

## 五、建议的最小研究方案

### 1. 主任务只做一条

固定一个公开长对话问答主基准，在已有记忆框架中改进写入筛选。优先复现基线，再提出改动。

A-Mem 已包含记忆构建、关联与演化，不能把它误当成空向量库。先理解原有写入过程，再选择插入点。[^amem]

其系统仓库明确将论文复现实验指向另一仓库，所以需确认版本与实验入口，而不是随便安装一个同名项目。[^amem-code]

### 2. 最小对照组

| 组别 | 用途 |
| --- | --- |
| 原始复现方法，不增加筛选 | 主基线 |
| 朴素相似度去重 | 检查简单办法能省多少、会误删什么 |
| 去重 + 一种信息变化保护机制 | 候选改进；具体机制待调研 |
| 去掉保护机制的消融 | 检验额外机制是否真正带来收益 |

后两者的设计需避免重复：如果去掉全部保护就等于朴素去重，应直接复用该组，不为凑实验增加同一配置。

建议从保守规则或轻量判断开始，不同时引入画像图谱、强化学习、多 Agent、情绪识别和复杂产品界面。

### 3. 指标与实验口径

- **问答表现**：使用主基准的官方评分；有相应标注时单列时间、更新类问题。
- **记忆规模**：条数之外，同时报告可比的 Token、字节或实际存储口径。
- **检索效率**：同配置下记录时延并重复测量；检索耗时与回答生成耗时分开。
- **维护与调用开销**：去重判断、记忆构建、检索、问答分别记录，再合计。
- **误删与失败分析**：对可人工核查的子集检查新事实、偏好更新是否被过滤；报告标注规则与范围。

存储上限与检索上下文上限分开讨论；不把“相同条数”直接视为“相同存储”。压缩率、正确率和时延未必同时改善，分析取舍而不是承诺全胜。

阈值等选择在开发集完成；按基准规定隔离用户历史、问题与答案，禁止为记忆写入偷看测试答案。

### 4. 保留对强基模的检验，但不过度扩张

资源允许时增加简单检索 / 摘要基线，并比较第二个能力不同的模型。目的不是承诺跨模型普遍提升，而是检查改进是否只对某个弱基模有用。

完整历史能放入上下文时，可另报告直接读历史的参考结果；若上下文预算不同，明确标成不同成本条件下的参考，不与等预算实验混为一谈。

### 5. 个性化只做可控扩展

第一步：使用主基准中确实具有更新、时间或用户信息的样本做分组分析。没有明确类别标注时，先定义规则，不自行伪造标签。

第二步（主实验完成且导师同意后）：考虑 PersonaMem 的小规模附加评测，直接检查用户偏好变化与响应选择。它包含模拟交互，结果不能等同于真实用户满意度或完整行动型 Agent 能力。[^personamem]

第三步（时间允许）：做少量可回放、标明为演示的交互案例。个人经历可以帮助构思案例，但不把 KK 的私密对话作为默认上传或公开数据。

## 八、复试叙事与研究边界

当前可以真实表达的动机：

> 我已有 Agent 实践经验，对长期个性化助手产生了兴趣。我希望通过记忆写入筛选研究：在节省资源时，怎样不丢失用户不断变化的事实和偏好。

以后只有在实验完成后，才能进一步讲“我发现了什么失败模式、做了什么改进、在哪些条件下有效”。不提前声称已经实现或验证个性化能力。

**研究方向可以宽：个性化智能体。毕设问题要窄：写入筛选时保护有用的信息变化。**
